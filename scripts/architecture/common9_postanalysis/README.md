# Closed-block reporting helper

This helper only arranges recorded evidence for independent Astra review under frozen19 section5. It creates no endpoint, metric, semantic success numerator, paired aggregate, oracle or model input. It imports no evaluator and runs no candidate, model, parser, build, network request or subprocess. Primary common9 and supplement6 remain separate.

## Scope and input

Root must explicitly name one already closed seven-configuration population/episode/repetition block. V2 supports only the initial COMMON9/S02/rep1 ABI: the exact status FIRST_FIXED7_CONFIGURATION_BLOCK_CLOSED_NOT_CAMPAIGN_COMPLETE at root/FIRST-BLOCK-S02-SUMMARY-v1.json, closed_episodes7, planned_joint_episodes441 and a rows list. Substrings such as NOT_CLOSED and unsupported manually named summaries are rejected. Other closure ABIs need separate review before support is added. The immutable freeze must name all seven planned identities. The supplied closure summary supplies only explicit run IDs. No recursive scan or whole runs.jsonl read occurs. A duplicate identity/run, mixed phase/configuration/binary, wrong-root path, changed frozen source or oversized input is rejected. A missing listed run/trace retains every declared response/goal obligation as missing evidence and UNREVIEWED; absence alone is not evidence that a run never executed.

The freeze contains absolute frozen_path references. Those must resolve exactly under the supplied root's frozen/source tree; active source files or relocated snapshots cannot substitute. The helper checks only explicitly relevant frozen oracle/evaluator/analyze_joint/contract files, never all runtime files or large dependencies. Supplement functional-oracles is additionally referenced when that population is explicitly selected. An unknown functional-oracle shape is retained as an unresolved reference, without normalization.

The CLI requires root, closure, population, episode, rep, freeze-sha256 and a new output path. It must not be launched against actual evidence until root approves a bounded extraction. V2 rejects any saved-evaluations input as UNSUPPORTED_SAVED_EVALUATION_PROVENANCE, including newer envelopes not implemented here. Matching identity and saved-file hashes do not establish trace/evaluator provenance. Initial extraction omits that option and explicitly supplies no certified selected endpoint, primary eligibility or deadline-audit result. The helper never executes an evaluator to fill missing results. No same-stimulus replacement eligibility rule is implemented: frozen BG newer same-Task RESULT behavior is not reinterpreted by this helper.

## Resource bounds

Each trace is read and hashed sequentially with a16MiB per-file cap and128MiB total-input cap. No parallel workers or corpus scan is used. Large memory sample arrays are not copied into the readable evidence. Only event records, source/input context, actual host receipts and explicitly recorded model request/response file references are retained. Referenced model files are hashed without copying their content. The output accumulates projected plain-text evidence, not all raw traces. Other strings above65,536 characters, arrays above256 items and image/binary/base64 payloads become explicit omission records containing unchanged raw file/hash/JSON-pointer references. No image decoding occurs. The relevant body remains UNREVIEWED if an omission prevents judgment.

This bounds work; it does not establish that reporting creates no host-load interference. Actual extraction scheduling remains root's decision while measurements run.

## Outputs and association

- `manifest.json`: exact input/source/tool hashes, explicit planned7 identities, declared oracle response/goal counts, separate observed handoff/control event count, missing/omitted records and byte limits.
- `evidence.json`: recorded events in unchanged raw index order with ID/ns/data and exact JSON pointers; source/revision/extent/read/authority facts stay in these records. The candidate_input_file is a single initial JSON object, not the full streamed runtime ingress. Later input/source/deadline/cancel/ACK facts remain in trace events and raw records. Initial user input, recorded model request/prompt references and frozen oracle conditions stay distinct; no literal oracle difference automatically establishes an actual-request failure. Base64/images are reference-only.
- `worklist.json`: stable population/configuration/episode/rep/run_id/obligation_kind/obligation_id keys, frozen expectations and raw evidence links. Expected oracle obligations and observed ingress events have distinct origins. Automatic QA02 binding obligations are not a new manual denominator.
- `review.md`: readable frozen expectation, explicit unavailable selected endpoint, all matching actual callback bodies, adopted plans and typed stimulus-linked timeline; run-level failure/effect/rejection/cancellation facts and full preceding/following context remain visible. Its exact UTF-8 SHA/bytes are in manifest.outputs alongside evidence.json and worklist.json.

Association uses only exact recorded stimulus_id/origin_event_id/request.stimulus_id and two known typed fields: WORKFLOW_FAILED.data.event_id and STATE_EFFECT_COMMIT.data.data.stimulus_id. Failure/effect/control kinds have explicit run-level references. Rows expose exact matched typed references plus unmatched run-context event indexes. Unmatched facts are not assigned inferred causal relations; absence from a row timeline cannot establish absence from the full trace. All raw events remain available, including prior/later Task/revision, source/permission changes, control, approval, actual ingress/receipt/result and rejection/late-effect facts. Unknown wire formats are not reconstructed from the oracle. The helper makes no claim that a linked event or recorded source is semantically correct.

The raw first matching display is ordered by actual observed_ns only if every matching display has a usable integer clock. Any missing/non-integer/boolean clock, earliest tie or duplicate earliest event ID makes raw-first ambiguous; the helper does not sort an unknown clock after known clocks and claim a first event. The raw-first field is never a QA01 selected endpoint. No saved result is accepted in v2. Missing output is distinct from missing execution/technical evidence; none produces a new automatic semantic FAIL.

All four new review dimensions—body, Task/revision, approval/authority and handoff—are UNREVIEWED. Subsequent Astra PASS/FAIL/UNREVIEWED judgments belong to separate versioned artifacts that bind this bundle's hashes. Existing frozen diagnostic statuses, if present in the saved artifact, are evidence rather than new judgments. Partial semantic review never changes QA01's original timestamp or denominator.

`bundle-schema-v2.json` defines the current manifest and named evidence/worklist schemas. The CLI requires source-checkpoint-v2.json to bind the unchanged helper. A generated manifest references that v2 checkpoint and schema; the synthetic pre-checkpoint write is explicitly labeled as such. Output files use exclusive creation, with the manifest written last. An existing output directory is never overwritten. A failed write may leave an incomplete new directory, which must be preserved and replaced by a fresh output name. Root JSON Pointer is the empty string; slash is not used as a substitute.

Exact v1 source, schema, README, tests,14-check result and checkpoint remain under preparation/source-v1/, bound by its immutable manifest. V1's NOT READY findings and the six v2 repairs are recorded in source-checkpoint-v2.json and v2-review-handoff.md. The original bundle-schema-v1.json remains historical.

## Synthetic checks

`test_extract_closed_block.py` constructs only temporary tiny synthetic roots and checks wrong root/phase/configuration, duplicate/missing runs, ambiguous or partially unclocked callbacks, exact closure ABI, oversize rejection, payload omission, immutable output, absent/unsupported saved evaluation, no-output distinction, empty JSON Pointer, review.md hash, and typed failure/effect links without invented association. It never opens actual campaign evidence. The authorized synthetic-only result is recorded immutably in synthetic-check-v2.json; v1's14-check record is preserved.
