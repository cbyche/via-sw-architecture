# DP01 / DP05 finite PoC implementation

These are authored synthetic source documents and event sequences for a mechanism PoC, not recordings or a user study. Runtime/model configuration, the global cost ledger, timing and RAM collection are shared with the other DPs. No source contains an evaluator answer list, and fixture files never load the physically separate oracle directory.

DP01 has four episodes and 12 referent judgments: same-source follow-up (3), topic changes (4), partial delivery and source correction (2), old-source relation reuse in a new conversation (3). A retains previously read source passages for the same conversation and resets the full view on revision/access invalidation. B selects and reads a fresh bounded bundle using metadata and recent conversation. C actually invokes a purpose-neutral relationship producer on observed source activities, atomically replaces its in-process published revision with source vector/coverage, and lets current requests select records or fall back to the original sources. Production never receives later request events. Unused publication calls remain in usage. The producer/store are deliberately in-process; no durable restart or independent fault-isolation claim follows.

The common DP01 first semantic call selects evidence or directly answers when actual valid evidence already suffices. A receives its rolling evidence, C its published source-backed relations, and every design receives the same bounded recent delivered answers. A host guard requires available actual evidence and current source provenance for each directly adopted target; metadata alone cannot authorize the shortcut. Otherwise bounded reads precede the final real interpretation call. This avoids forcing a second call when state reuse already supplied sufficient evidence. Source access uses actual files, one-based inclusive lines, and current source descriptors owned by the module. Prepared response lines outside `delivered_lines` are cut before any model input; full raw files remain in frozen fixtures. Every selected passage, reuse, query, branch, adoption and publication is traced. First-adoption target sets are source IDs in this small fixture; the two partial-delivery judgments additionally require the intended quote/source revisions. Coarse source-level targets do not establish arbitrary sub-object or pixel grounding accuracy.

DP05 has four episodes and six delegation opportunities: no delegation (0), one delegation (1), changed purposes (3), large source with correction and access revocation (2). Adopted request/condition/action state is common input because this DP begins after semantic adoption. Mandatory fields are copied and source access is checked in code. A selects actual source ranges and composes the purpose-specific capsule when delegation happens. B actually builds source-backed reusable explanation blocks whenever sources/adopted state/access change, then extracts matching blocks and reads missing original passages. C constructs the mandatory contract and current manifest and assigns original-detail selection to the receiver. The identical real receiver model/read tool is available to all three; A/B may provide references and request extra reads too.

N-H checks mandatory goal/conditions/exclusions/action/access/revision fields at admission, required original-source availability/currentness, and capsule source-span access/revision. The scorer separately excludes the receiver's domain draft quality. Receiver calls and their cost are external and separately recorded. Actual VIA file serving between receiver calls remains VIA processing. File reads currently materialize full UTF-8 files before slicing; returned range size does not imply RAM or I/O savings. Revoked sources are absent from later manifests, cannot be served, and cannot be revived by a prior B record. Source/access changes invalidate the previous B record before any new model input. Publication drops ungrounded/stale/out-of-scope blocks with rejection diagnostics; invalid generated capsule provenance blocks admission and records the failure rather than transmitting the capsule.

Focused checks completed: `cargo check` and static fixture/oracle ID/source-file/range validation. No independent model calls or campaign runs were made by this worker. Final campaign results must be generated by the shared runtime under its single budget ledger.

Potential selected-design tactics, only after basic measurements: DP01 A2 invalidate dependent fragments only (versus baseline whole-view invalidation), B1 valid range cache, or C1 declared activity-based selective production with source fallback; DP05 B1 batch activity-window production, A1 capsule cache with exact purpose/condition/source/access matching, or C2 valid receiver-read cache. Fixed workloads may produce cache misses or tied values; those outcomes must remain visible.
