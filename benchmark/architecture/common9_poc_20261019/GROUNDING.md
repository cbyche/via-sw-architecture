# Common9 grounding integration

`grounding::ground(Context, variant, GroundingInput)` returns actual bindings and provenance to the shared workflow. It does not capture input, adopt meaning, publish responses or complete goals. All7 configurations receive the same observed frames/cues and source permissions. The same evaluator judges all15 referent sets; no answer key enters this module.

GroundingInput carries a unique finalized capture event ID and its **capture record version**, currently1 for each distinct finalized transcript. A subsequent input such as S08-U02 is a new event with capture version1. Its interpreted Task correction/request revision is decided later by the shared runtime and is not prefilled from expected Task associations. Source revision is independently derived from the actual frame, such as DOC-A v1. Output `input_revision` is capture provenance; it is not the current Task revision. Shared adoption/publication owns the latter's authority checks. Component-only tests also exercise a capture version2 to ensure source revision1 is not confused with input version2.

## Actual paths

- No actual frame: return no screen bindings and make no grounding model call. The shared meaning/evidence workflow still handles non-screen historical references. All9 cases remain in every QA population.
- A: Qwen joint grounding receives original permitted PNGs, transcript, actual cues/native selection and actually delivered prior state. A bounded reread repairs actual output-contract violations. It returns normalized whole extents which are converted to the original frame's pixel space.
- B with an actual native selection and no pointer/path/drag: native selected objects can satisfy the visual production requirement. The speech producer still interprets the expression. No dedicated parser or screen model is forced merely to add latency/cost. This applies to the authored S15 selection-only path.
- B when native selection cannot cover actual pointing: the actual task-local detector/OCR/caption stack runs on the original PNG. A Qwen Screen Target Producer receives its fallible output plus the original PNG and actual cues, without speech, and owns whole-item candidates. The additional Qwen visual production call is real and charged; OmniParser alone is not claimed to have produced perfect whole table/paragraph extents. A separate Qwen speech producer receives speech/cue metadata and prior state without pixels or screen candidates. Typed observed cue relations are used when all references can be resolved; otherwise a semantic binder receives actual raw cues, candidate pixel extents, speech meanings and delivered prior, without pixels. It may select producer-owned targets, not create or repair geometry. A bounded owner expansion rereads actual sources.

The local helper is cold on first actual need in each episode and warm/reusable within that episode for identical frame ID/source revision/PNG SHA. Initialization and first parsing remain on the stimulus-to-result path. No helper precomputation is excluded to make B faster. There is one helper instance/cache per episode and all resident weights/PIDs are sampled. Its deployment is local CPU while Qwen inference is remote; this experiment does not measure the originally proposed remote parser service or establish a deployment-independent structural latency/RSS ranking.

## Actual authored observations

S08 and S15 use the same visible five-line DOC-A source content rendered at2880×1800. `assets/observations.json` contains actual authored raw pointer events and only selected-object native metadata. It does not expose a complete native scene map. The image visibly contains T1/T2/T3/P1/P2 labels; source IDs are not inferred from evaluator answers. A source's line extents are actual raw-document metadata. Unselected object boxes are not injected into the live candidate or parser adapter.

The offline semantic/vision double reads the authored SVG only as a disclosed deterministic fixture producer. It is not invoked in formal model mode. The candidate binder double now consumes the same actual candidates/cues/prior as the real binder, without fetching missing cue context from the asset catalog. Its prior-order choice sorts the actually delivered preserved extents; no hardcoded prior target ID is supplied.
