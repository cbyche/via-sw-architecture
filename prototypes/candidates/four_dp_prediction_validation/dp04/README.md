# DP04 new prediction validation candidate

This is a new source generation derived from the prior shared normalized-wire candidate. A retains joint target-extent/binding authority. B calls the task-local real dedicated detector/OCR/caption dependency before Screen Target Producer interpretation, separately produces speech references, then resolves only producer-owned candidates. A4 supplies the identical dedicated parser output directly to joint interpretation; it does not invoke screen semantic production first. B4 overlaps independent speech production with the screen dependency chain under the same two cloud slots. BQ is an explicitly parser-free separated-producer diagnostic.

The parser communicates through the existing wire at `dp04.local_screen_parser`; the bridge classifies it separately from cloud model calls, registers its PID for simultaneous RSS, and records initialization/inference separately. No candidate path reads an oracle or SVG authoring source. The common normalized output adapter validates declared units and rejects malformed coordinates without clamping.

The original design proposed a cloud parser. The actual local CPU deployment used here has different latency/resource placement; its results cannot establish the original cloud service's price, delay or local-memory use. The source does not implement the full VIA product or a Windows native selection adapter.

See [plan](../../../../benchmark/architecture/four_dp_prediction_validation/dp04/PLAN.md) and the new campaign's immutable freeze/results. Previous generations remain unchanged. No commit/push is performed by this experiment owner.
