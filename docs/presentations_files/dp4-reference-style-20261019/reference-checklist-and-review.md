# DP4 레퍼런스 제작 원칙과 평가

2026-10-19

DP2 v2와 DP3의 R01~R16 체크리스트를 이어받았다. 발표용 DP4는 **Agent 간 업무 인계**이며 저장소 분석 번호 05에 해당한다. 배경, 설계 방안 비교, 선택 및 보완, 보완 효과 상세의 4장으로 구성했다.

## 근거에 따른 적용 범위

완료된 발표 캠페인의 최신 결과 기록에 따라 **읽기 지원 수신자에 조건부 C 선택, C1 제한 적용**을 표현했다. 수신자가 범위 읽기, 판본, 권한, 철회 검사를 실제로 지원해야 한다. 초기 설계 문서의 A 권고를 최신 결론으로 사용하지 않았다.

C의 적용 QA에서 상대적 열세는 확인되지 않았다. C1은 인계 본문에서 채택 조건의 전제가 빠지는 위험을 보완한다. 이 본문 진단을 QA02 지칭 집합 정확도로 바꾸지 않았다. QA01의 우열도 미확정으로 유지했다.

2·3장의 전체 기본 비교와 C1의 별도 E3 실험은 모집단이 다르다. 3장에서는 기본 C 수치를 유지한 채 **별도 E3** 전후 값을 추가했다. 4장은 별도 E3의 C와 C1만 비교한다. C1의 모든 개선을 사전 읽기의 인과 효과로 단정하지 않으며, 새 common9 캠페인의 부분 결과를 섞지 않았다.

## 레퍼런스에서 확인한 원칙

- **23 DP04 방안과 24 DP04 채택:** 비교 장의 대안 순서, 표 위치, 행 높이와 비선택 대안을 유지한다. 선택 열 전체에 파란 외곽선과 빨간 체크를 붙인다. 내부 보완 경로, 단점 아래 보완 문구, 전후 수치를 파란색으로 연결한다.
- **18 DP02 채택:** 보완의 효과와 함께 증가하는 시간·자원 비용을 남긴다.
- **DP1·DP2의 후속 수정:** 배경은 문제상황과 설계 질문을 시각화한다. Component 경계, 내부 처리, 중간 상태를 구분하고 실제 실행·저장·읽기 책임의 차이가 보이도록 한다.
- 참조 이미지의 수치나 점수를 VIA에 옮기지 않는다. 2·3장은 같은 비교표를 쓰고 보완의 상세 메커니즘과 해석 범위는 4장에 둔다.

## 구조와 검토 수정

1. A는 위임 요청에서 목적별 자료 선택·구성을 수행하고 임시 capsule을 만들어 전송한다. 기확보 원문·유효 참조 재사용을 허용하며 전체 대화 덤프로 표현하지 않았다.
2. B는 공개 결과·정정 사건에서 업무 설명과 관계를 생산·갱신한다. 지속 기록을 목적별 추출기가 읽는 경로를 명시했다. 위임 요청은 생산 사건과 다른 트리거다.
3. C는 VIA가 필수 목표·조건·제외·수행 범위를 명시한다. 수신자가 상세 범위를 고르고 Agent Gateway를 통해 Context Manager에 요청한다. scope와 revision, 권한·철회 검사를 표시했다.
4. C1은 다음 위임 목적을 알기 전에 기존 condition_source_refs로 조건 원문 1~2행을 확보한다. 3장은 기확보 원문 첨부를 표시하고 4장에서 시점을 설명했다. 첫 해석 호출 입력을 바꾼 것으로 표현하지 않았다.
5. 두 독립 검토자가 build03 네 장을 사실·구조 관점과 시각·레퍼런스 관점에서 재검토했다. B 기록 소비 경로와 3장 QA03 분모 표시를 수정한 후 남은 P1/P2를 발견하지 못했다.
6. build04에서는 내용과 구조를 그대로 유지하고 native 표의 행 높이만 재배분했다. 주 검토자가 최종 선택 장을 다시 확인했다. native 객체·표 보존과 재가져오기, 패키지·레이아웃 검사가 통과했다.
