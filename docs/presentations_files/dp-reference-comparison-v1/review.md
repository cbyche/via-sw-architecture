# 레퍼런스 대조와 보완 기록

2026-10-15 / 작성자 검토 / A/B 미선정 / 성능 측정 없음

사용자 레퍼런스 네 장과 최종 PPTX 네 장을 이미지로 대조했다. 구조와 수치의 기준은 README에 고정한 커밋이다. 독립 외부 리뷰나 실제 PowerPoint 실행 검증을 했다는 뜻은 아니다.

## 반복 검토에서 보완한 항목

| 확인한 문제 | 반영한 보완 |
| --- | --- |
| 모듈 이름 위로 단계 설명이 겹침 | 42의 K1 설명과 입력 번호를 빈 띠 영역으로 이동하고 47의 후보 배정 설명을 Registry 아래로 이동 |
| 44의 실제 전달선이 업무 사실 설명을 가림 | 반환선을 별도 통로로 이동하고 실제 전달 원장의 Mailbox 반환을 표시 |
| 44 B의 단계 산출물이 소비자의 내부 실행으로 직결될 위험 | 채택 의미와 Notice가 Response Composer의 입력 큐에 도착하도록 원문 보완 커밋과 대조 |
| 47의 원본과 모델 선 끝이 불명확 | R/M 포트와 대상 Component를 명시하고 각 worker의 포트 사용을 표시 |
| 47의 후보 저장소가 결합 작업을 직접 시작하는 것으로 보임 | 후보 snapshot을 Coordinator가 확인한 뒤 Binding Work Queue에 배정하는 경로로 수정 |
| 47 B의 완료 반환과 결합 상태가 빠짐 | 생산자 완료 Inbox, Binding Revision State와 재판단 Inbox 경로 추가 |
| 47 B에서 결합부가 원본으로 최종 지칭을 직접 생산할 수 있는 것으로 읽힐 위험 | 원본 재확장은 원 생산자가 수행하고 결합부는 게시 후보와 M을 사용한다고 명시 |
| 45의 현재 사용 조건과 원본 확인이 약함 | A의 Use Guard, B의 source 반환과 Origin Verifier의 원본 확인 경로 보완 |
| 42의 상태 소유와 전송 복구가 불명확 | 업무 저장 경로, 전송 복구기와 같은 C1/R1~R3/P1/T1/X1,X2/Q1/K1 예시를 해당 저장소에 표시 |
| 레퍼런스의 수치 근거와 강조가 부족 | QA 영향 괄호를 붉게 표시하고 각 수치 옆에 짧은 구조 원인 메모 추가 |
| draw.io 줄바꿈과 레이어 순서 | 줄바꿈을 XML 문자 참조로 보존하고 연결선 뒤에 Module과 라벨을 배치 |
| SVG 원통 윗면이 짧은 상태 라벨에 걸침 | 윗면 높이를 도형 높이에 맞춰 줄이고 네 SVG를 별도로 렌더링해 확인 |

## 최종 구성 확인

네 장 모두 제목, 단계 표시, 기능 요구, 관련 QA, A/B 설계안, 범례, 큰 구조도, 단계 번호와 흐름, 장점, 단점, Trade-off를 포함한다. 44의 관련 QA와 수치 행은 점수 동점 제외 규칙으로 비우고 그 이유를 표시했다. 47은 세 QA, 45는 네 QA, 42는 두 QA를 표시한다. QA07~09를 대체로 넣지 않았다.

모듈과 저장소 이름은 해당 도형의 text body다. 네 장에 네 개의 네이티브 표가 있으며 스크린샷이나 이미지로 구조도를 대체하지 않았다. 원형은 0~6점의 같은 규칙을 사용하고 합산 승자나 새 배점을 만들지 않았다. B44의 국소 실행, B47의 후보 관리와 B42의 독립 운영 이점은 조건부 설명으로 유지한다.

## 검증 범위

- 최종 패키지의 4장 모두 렌더링하고 검토했다. 마지막 수명 ID 보완은 42에만 적용했고 나머지 세 장의 렌더는 직전 검토본과 동일하다.
- 패키지 관계, 첫 번째 도구 재수입, 슬라이드 수, 표 소유와 명시 글꼴 검사 통과. 모든 선언 글꼴은 Calibri, 정수 pt, 언어는 ko-KR이다.
- QA 원값과 점수는 고정한 `predictions.json`에서 가져왔고 포함 및 제외 집합과 표시 반올림을 대조했다. [콘텐츠 검사 결과](./content-validation.json)에 최종 파일 해시, QA 목록, 네이티브 객체 수와 이미지 객체 0건을 기록했다.
- 활성 Markdown 447개 파일의 로컬 링크, 활성 용어와 정식 Component 이름, DP-47 원본 생성기 `--check`, Git 공백 검사와 두 JS 생성기의 문법 검사에 통과했다.
- 배치 검사기의 `native_table_overflow` 경고 네 건은 Trade-off 셀 안의 수치 텍스트를 footer로 추정한 것이다. 표의 실제 끝은 y=1048이고 footer는 y=1052 이후다. 네 장 렌더에서 표 밖으로 넘친 셀이나 가려진 footer가 없는 것을 확인했다. 경고 원문은 `validation.json`에 보존한다.
- 로컬 렌더는 네이티브 Windows PowerPoint 검증이 아니다. Windows Open XML SDK 검사는 게시 후 별도 CI로 실행한다. SDK 성공도 실제 PowerPoint의 글꼴 대체, 화면 배치와 실행을 보증하지 않는다.
