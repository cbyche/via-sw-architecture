# DP3 레퍼런스 제작 원칙과 평가

2026-10-19

DP2 v2의 R01~R16 체크리스트와 레퍼런스 표 구성을 이어받았다. 발표용 DP3는 화면과 발화의 지칭 결합이며, 저장소 분석 번호 04와 DP-47에 해당한다. 배경, 설계 방안 비교, 선택 및 보완, 보완 효과 상세의 4장으로 구성했다.

## 근거에 따른 적용 범위

완료된 발표 캠페인의 공통 정규화 좌표 계약에서는 기본 A를 선택하며 추가 보완은 채택하지 않았다. 이번 비교에서 선택 A의 QA 열세는 확인되지 않았다. 따라서 열세나 보완 성과를 새로 만들지 않았다.

3장에는 정규화 기본 A의 선택과 별도 pixel 계약에서 확인한 A2+A5 복구 대안을 함께 표시했다. 복구 상자에 **미적용**, QA02 전후 값에 **별도 pixel 복구**를 붙였다. 4장은 동일 pixel 계약의 기본 A와 A2+A5만 비교한다. **정규화 A+A2+A5 조합은 미실행**이다. 선택된 정규화 A에 보완을 적용한 전후 수치로 읽어서는 안 된다.

## 레퍼런스에서 확인한 원칙

- **23 DP04 방안과 24 DP04 채택:** 대안 순서, 표 위치, 행 높이, 비선택 대안을 유지한다. 선택 열 전체를 파란색으로 감싸고 빨간 체크를 붙인다. 내부 보완 경로, 단점 아래 보완 문구, QA 전후 값을 파란색으로 연결한다.
- **18 DP02 채택:** 개선 효과뿐 아니라 보완으로 늘어나는 자원 비용도 남긴다.
- **DP1과 DP2의 후속 수정:** 배경은 문제상황과 설계 질문을 시각화한다. Component와 Module, 중간 상태와 실행 의존관계를 구분한다. 구조 차이가 이름이나 색만으로 표현되지 않게 한다.
- 참조 이미지의 수치와 점수는 VIA에 옮기지 않는다. 2·3장은 비교를 위한 같은 표를 사용하고, 상세한 복구 설명은 4장에 둔다.

R07과 R09는 별도 복구 실험으로만 충족한다. 이 기록은 선택안의 열세를 보완한 검증이 완료됐다는 판정이 아니다. 제작 과정에서 새 구현, 모델 호출, 성능 측정을 수행하지 않았다.

## SW 구조와 검토 수정

1. A에는 Joint Grounding Interpreter와 Joint Grounding State를 크게 배치했다. 원본 입력 두 갈래가 하나의 판단으로 모이고, TryApply 검증 뒤에 상태를 게시한 다음 Request Controller가 최종 채택하도록 했다.
2. B에는 Speech Reference Producer와 Screen Target Producer, 각각의 Candidate Revisions, Multimodal Binding Resolver, Binding Revision State를 따로 배치했다. Grounding Coordinator의 제어와 화면 후보 확장 경로도 표시했다.
3. B의 후보 게시 전 현재성 검사와 검증 후 binding 상태를 명시했다. 이번 PoC의 화면 생산자는 Qwen이며 실제 OmniParser 실행 결과로 표시하지 않았다. B4 병렬화는 기본 B와 별도이다.
4. A2 복구는 영향 표현만 다시 판단하고 비영향 표현의 binding을 유지한다고 수정했다. 기존 상태 전체를 무조건 유지하는 것으로 표현하지 않았다.
5. 배경의 포인터 라벨과 원형 지시선 겹침, 정정 귀환선과 말풍선 교차를 해소했다. 2·3장 검증 단계의 숫자 배지를 앞으로 배치하고, B의 검증 주석을 화살표에서 분리했다.
6. 두 독립 검토자가 최종 build03 네 장을 다시 확인했다. 사실·구조 검토와 시각·레퍼런스 검토에서 남은 P1/P2는 발견하지 못했다. 이는 제품 구현이나 PowerPoint 앱 자체 실행을 확인한 결과가 아니다.

## 수치와 해석 범위

### 공통 정규화 계약의 기본 비교

| 지표 | A | B |
| --- | --- | --- |
| QA01 첫 응답 | 7.716초 (15/15) | 18.774초 (12/15) |
| QA02 지칭 집합 | 24/24 (100%) | 18/24 (75.0%) |
| QA03 처리 | 9.646초 (12/12) | 25.033초 (9/12) |
| QA04 변경 | 미측정 | 미측정 |
| QA05 모델 비용 | $0.0254572 | $0.0650212 |
| QA06 최고 동시 RSS | 40.141MB | 41.894MB |

안별 네 작성 사례×3회, 전체 24episode이다. QA05는 안별 12episode 합계이다. QA01·03의 시간은 관측된 endpoint 평균이며 미관측을 숨기거나 0초로 바꾸지 않았다. 관측 모집단이 달라 단순 속도 개선율을 주장하지 않았다. QA04의 이전 판본 2.50개는 이전 판본으로 표시했으며 이번 계약 측정값으로 이월하지 않았다.

### 별도 pixel 계약의 복구 비교

| 지표 | 기본 A | A2+A5 | 해석 |
| --- | --- | --- | --- |
| QA01 첫 응답 | 9.268초 (12/15) | 11.036초 (15/15) | 미관측 3건 회복 |
| 같은 관측 12건의 QA01 | 9.268초 | 10.875초 | +1.607초, +17.33% |
| QA02 지칭 집합 | 19/24 | 24/24 | 정답 5건 증가 |
| QA03 처리 | 12.559초 (10/12) | 13.795초 (12/12) | 미완료 2건 회복 |
| QA04 변경 | 미측정 | 미측정 | 이전 값 적용 안 함 |
| QA05 확정 비용 | $0.0339156 + 사용량 미확정 1회 | $0.0413400 | 총비용 증감 미확정 |
| QA06 최고 동시 RSS | 41.452MB | 50.037MB | +8.585MB |
| 실제 모델 요청 | 22회 | 23회 | 거절·복구 포함 |

- 비용 미확정 1회의 예약 상한 $0.0729404는 실제 청구액이 아니다.
- A2와 A5의 개별 효과를 분리한 실험이 아니다. 정답 bbox를 제공하지 않았고, 좌표 오류와 공급자 오류를 포함한 기본 실패도 보존했다.
- QA06은 로컬 Python+Rust 실행기 RSS이다. 원격 모델 weights/KV나 VIA 제품 전체 RAM이 아니다.
- 현재 진행 중인 공통 대표 평가의 부분 결과를 이 완료된 캠페인에 합치지 않았다. 발표 선택은 승인된 ADR 변경을 뜻하지 않는다.
