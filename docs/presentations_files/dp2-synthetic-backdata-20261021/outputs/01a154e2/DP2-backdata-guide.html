QA01 = 접수 + 별도 관계 판단 + 선행 대기 + 첫 내용 판단 + 표시. QA03 = 정정 전 원래 목표 처리 + QA01 + 이후 결합/준비/전달/결과/음성 경로. 실제 식은 실행단계 DAG에서 외부 업무 노드 시간을 0으로 만든 완료경로로 검산했다. 조회와 관계 판단의 겹친 시간을 두 번 더하지 않는다.

G1/G2는 원래 목표 t=-0.6부터 QA03를 계산한다. G3/G4는 새 목표 t=0부터 계산한다. 원래 목표의 유지와 경합은 별도 기존목표진단 표에 남겼다. 주표는 사전 지정한 200개 목표만의 합성 평균이며 전체 시스템의 모든 목표 평균이 아니다.

각 그룹의 시간은 이전 가상 평균에 대칭 오프셋을 더한 것이다. QA01 오프셋=(j−24.5)×0.004초, QA03는 그 1.5배다. 이 변형을 실제 반복 측정의 분산처럼 해석하면 안 된다. 모든 외부 처리와 completion 역시 설정값이다.

QA03의 추가 가정: 독립 질문 G4의 첫 표시 이후 전체 설명 생성은 A 2.35초, B 1.15초로 설정했다. 큰 공통 문맥과 좁은 문맥의 후속 생성 차이를 가정한 것으로, 기존 step 대기만으로 설명되는 차이가 아니다. 이 1.20초 차이를 제거하면 G4의 A는 3.20초, 전체 A는 4.70초가 되고 B는 4.40초를 유지한다. 실측에서는 이 별도 가정을 검증해야 한다.

DP5 및 향후 DP 통합

참고 채팅: DP5 = DP4+1+45. 사례→원본→최초 응답/의미→시간→비용 연결 방식을 참고했다. DP5 파일은 변경하지 않았다.

DP5의 비용은 정규화 단위이고 수신 Agent 비용을 포함한다. DP2는 가상 USD 명목묶음에서 VIA만 포함하므로 숫자를 직접 비교할 수 없다. 두 자료의 입력 수나 적용 표현 수도 다르다. 공통 스키마 DP-BACKDATA-0.1에 evidence_kind, DP/대안, 사례/요청/revision/목표/표현 ID, oracle/최초 채택, DAG, 비용 범위, 프로필을 두고 통합 전에 판본과 분모를 검토하도록 했다.

확인한 범위

평균·분모·오류 건수·정답/채택 비교·근거 참조·DAG 경로·가상 비용·시점별 메모리 합계와 스프레드시트 수식의 재계산을 확인했다. 모델/제품 실행이나 실측 결과의 유효성을 확인한 것은 아니다. 실제 데이터는 별도 dataset_id와 evidence_kind로 수집해야 한다.
