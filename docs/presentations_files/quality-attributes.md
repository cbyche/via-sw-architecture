# VIA 품질 요구사항 발표자료

> 작성일: 2026-10-06 / 발표 문안 및 측정 방법 초안 / 구현·측정 결과 없음
> 원문: [03-00 품질 시나리오 §2·§2.1](../architecture/12-decisions/decision-packages/03-00-quality-scenarios.md)

## 작성 계획과 구성

1. V-01~13의 이름, 의미와 공동 순위를 원문에 대조한다.
2. 각 행을 한 문장 설명, 목표, 측정 방법으로 작성하고 묶인 부특성의 차이를 유지한다.
3. 참고 페이지처럼 표를 사용하되 13개를 읽을 수 있도록 1~5순위 8개와 공동 6순위 5개를 두 장으로 나눈다.
4. Markdown과 PowerPoint를 같은 원문 데이터로 생성하고 13개 누락 여부, 동순위, 편집 가능한 표, 렌더링과 링크를 검증한다.

참고 이미지의 표 구성과 설명·목표·측정 기준의 표현을 적용했다. 참고 제품의 숫자, H/M/L 난이도, 상위 5개 ASR 선정은 VIA에 옮기지 않았다. V 표식은 현재 품질 검토 관점이며 확정 QA ID 또는 최종 ASR 선정이 아니다.

## 목표 수치의 상태

현재 V 원문은 목표 수치, 시험 모집단과 정확한 지표·집계를 동결하지 않았다. 따라서 미확정 수치는 **미정**으로 표시했다. 기존 요구에 있는 **다른 업무 오실행·중복 실행·무단 사용 0건**은 금지 행위에 대한 조건이며 전체 정확성·복구율 목표를 뜻하지 않는다. 과거 QA의 95%, 1,500ms, 3-element, 5,000ms 제안을 V에 자동 적용하지 않았다.

아래 측정 방법은 발표를 위한 구체화 초안이다. 실제 측정 전에 모든 DP에 공통인 정의·지표·절차·모집단·집계·실패 처리를 확정해야 한다. 기준선이나 기존 측정 계약을 변경하지 않았다.

공동 순위 안에 추가 우열을 부여하지 않는다. 6순위도 필수 검토 관점으로 모두 유지하며 높은 순위의 이익으로 권한 위반이나 다른 품질 손실을 상쇄하지 않는다. 한 사건의 효과를 여러 관점에 설명하더라도 독립 표본처럼 중복 합산하거나 가중 총점으로 합치지 않는다.

## 측정 시 빠뜨리면 안 되는 내용

### V-01 기능 정확성

- 측정 초안: 목표·대상·요청 관계·업무 연결·실행 상태·실제 전달 사실을 사전 작성한 정답 기준과 대조한다; 전체 적용 판정을 모두 만족한 실행 수/전체 시험 실행 수와 항목별 오류를 함께 보고하며 누락·오답·시간 초과를 성공 표본에서 제외하지 않는다.
- 목표 상태: 정확 처리율은 V 기준에서 미확정이며 오실행·중복 실행 0건은 기존 action/access 규칙을 보존한다.
- 책임 경계: Downstream Agent 내부의 도메인 추론·계획·도구 실행 품질은 제외한다. VIA의 잘못된 대상 연결, 상태 판단과 전달은 포함한다.
- 품질 분류: Functional suitability → Functional correctness

### V-02 기능 적절성

- 측정 초안: 사용자 여정별 목표 달성 여부와 재설명·재선택·수동 연결의 횟수 및 능동 작업시간을 기록한다; 권한 확인이나 근거 부족으로 필요한 질문은 불필요한 단계와 분리하고 기능 축소가 만든 수동 우회도 포함한다.
- 목표 상태: 사용자 단계 수와 작업시간의 허용 상한은 미확정이다.
- 책임 경계: V-01의 의미 오류율이나 V-03의 기능 지원률로 대체하지 않는다. 사용자 수고는 V-05의 VIA 귀속 시간과 구분한다.
- 품질 분류: Functional suitability → Functional appropriateness

### V-03 기능 완전성

- 측정 초안: 공통 R/B와 고정 UC·필수 변형을 지원, 부분 지원, 미지원, 미확인의 네 상태로 기록하고 각 상태의 건수와 분모를 공개한다; 제한 조건, 포기한 목표, 수동 우회와 사용자 영향을 적으며 설계상의 지원 주장과 구현 시험 결과를 구분한다.
- 목표 상태: 허용 가능한 부분 지원과 미지원 범위는 미확정이며 모든 대안에 100% 지원을 진입 조건으로 강제하지 않는다.
- 책임 경계: 대안에 맞춰 공통 요구 목록을 줄이지 않는다. 미지원 안내를 원래 사용자 목표의 완료로 세지 않는다.
- 품질 분류: Functional suitability → Functional completeness

### V-04 상호작용 반응성

- 측정 초안: 발화 종료/텍스트 제출, 외부 상태의 source availability, barge-in onset 등 실제 사건과 유효한 표시·의미 있는 발화·마지막 중단 음성 sample을 연결한다; 응답·상태 전달·Task 제어·음성 중단을 구분해 지연 분포와 실패·시간 초과를 보고한다.
- 목표 상태: V-04의 종류별 지연 상한과 집계 방식은 미확정이며 기존 QA 평균 목표를 자동 적용하지 않는다.
- 책임 경계: 접수 인사·spinner·enqueue는 유효한 종료점이 아니다. 음성 출력 중단과 업무 취소는 구분하며 Agent 내부 실행 시간은 제외한다.
- 품질 분류: Performance efficiency → Time behaviour

### V-05 VIA 귀속 요청 완료 시간

- 측정 초안: 같은 요청과 외부 실행 profile에서 자료 준비·내부 queue·경합·인계·후속 요청 해제·결과 검증·실제 최종 전달의 사건과 의존 관계를 기록한다; 병렬 및 겹친 구간을 구분해 VIA 귀속 완료 지연을 산출하는 공통 귀속·집계 규칙을 측정 전에 정한다.
- 목표 상태: 완료시간 상한과 병렬·중첩 구간의 정확한 귀속 산식은 미확정이다.
- 책임 경계: Agent 내부 대기·추론·계획·업무 실행 및 사람의 답변 대기는 제외한다. 전체 경과시간에서 외부 시간 합을 단순 차감하거나 병렬 VIA 구간을 무조건 합산하지 않는다.
- 품질 분류: Performance efficiency → Time behaviour

### V-08 변경 용이성과 모듈성

- 측정 초안: Agent 계약, 모델 인터페이스, Context source, 상태 형식과 시험·로그 변화에 동일한 변경 과제를 적용한다; 같은 추상화 깊이로 변경 요소·인터페이스·상태·런타임을 기록하고 수정 난이도·공수·검증 부담·회귀 실패를 함께 보고한다.
- 목표 상태: 허용 변경 범위와 공수는 미확정이며 기존 QA의 3-element 목표를 자동 적용하지 않는다.
- 책임 경계: 파일 수나 Component 수만으로 모듈성 또는 변경 용이성을 판정하지 않는다. 기능을 제거해 변경 비용을 줄였다면 V-03에도 기록한다.
- 품질 분류: Maintainability → Modifiability / Modularity

### V-06 자원 활용성과 수용량

- 측정 초안: 대상 PC·모델 profile·기능·입력률·동시 업무 수를 맞추고 전체 committed memory, CPU/GPU, 에너지, 저장공간을 기록한다; idle·정상·경합·background·폐기·재구성 비용을 포함하며 자원별 사용량과 정상 기능을 유지할 수 있는 부하 한계를 별도로 보고한다.
- 목표 상태: 자원별 예산과 수용량 목표는 미확정이며 참고 슬라이드의 32MB·12.8GB 수치를 가져오지 않는다.
- 책임 경계: 하나의 공유 Omni 가중치와 역할별 KV·Context를 구분하고 Streaming ASR 및 모든 추가 helper 비용을 포함한다. 자원 감소가 기능 축소 때문이면 함께 공개한다.
- 품질 분류: Performance efficiency → Resource utilization / Capacity

### V-07 결함 허용성과 복구성

- 측정 초안: 단절·process 종료·실패·중복/역순 event를 같은 의미 시점에 주입한다; 사전에 정한 필요 의존 범위 밖의 기능 영향과 전체 영향 업무의 올바른 identity·state·result·control 복원 여부 및 시간을 각각 기록하고 실패·시간 초과도 남긴다.
- 목표 상태: 유지·복구율과 deadline은 미확정이며 오실행·중복 실행 0건은 기존 규칙을 보존한다.
- 책임 경계: process 재기동만으로 복구 성공을 판정하지 않는다. 외부 실행이 확인 불가이면 unknown을 유지하며 완료나 취소를 만들어내지 않는다.
- 품질 분류: Reliability → Fault tolerance / Recoverability

### V-09 분석 및 시험 용이성

- 측정 초안: 같은 숨겨진 원인 사례의 최소 보호된 기록으로 원인 구분 정확도와 진단 시간을 확인한다; 별도로 사건·장애의 통제 가능 여부, fixture/정답 기준 준비 공수, 기대 결과 판정 가능 여부와 저장 근거의 재계산 가능성을 확인한다.
- 목표 상태: 진단 성공률·시간, 시험 공수와 재현 범위 목표는 미확정이다.
- 책임 경계: trace 완전성이나 반복 재계산 성공만으로 원인 분석이 쉽다고 결론 내리지 않는다. 보호정보 원문을 더 기록해 품질을 높이지 않는다.
- 품질 분류: Maintainability → Analysability / Testability

### V-10 기밀성

- 측정 초안: 자료·대상·목적·시점별 허용 기준과 실제 접근/전달 기록을 대조한다; 권한 철회·삭제 경계의 경쟁 조건, 파생 자료, cache, 역할별 KV 및 외부 Agent 제공을 포함해 무단 사용 건수를 집계한다.
- 목표 상태: 허용 대상·목적 및 철회/삭제 뒤 신규 사용 금지라는 기존 요구를 0건 목표로 표현한다; 집행 경계와 시험 모집단은 미확정이다.
- 책임 경계: 허용된 Downstream Agent Context 제공을 모두 위반으로 세지 않는다. 외부 통신 0회나 모든 데이터 외부 반출 금지로 바꾸지 않는다.
- 품질 분류: Security → Confidentiality

### V-11 상호운용성과 공존성

- 측정 초안: 같은 Agent/source capability에 대해 요청·질문·결과·취소·오류의 의미와 identity 보존을 시험한다; 별도 공존 시험에서는 타 앱의 고정 부하와 CPU·메모리·장치를 공유하며 VIA와 타 앱 각각의 기능 실패 및 반응/처리시간 변화를 기록한다.
- 목표 상태: 연동 성공률과 공존 시 허용 저하 한도는 미확정이다.
- 책임 경계: 상호운용성과 공존성을 한 점수로 합치지 않는다. 외부 제품의 미지원 기능을 VIA의 성공으로 가정하지 않는다.
- 품질 분류: Compatibility → Interoperability / Co-existence

### V-12 조작 용이성과 사용자 오류 방지

- 측정 초안: 같은 사용자 시나리오에서 실제로 제시된 질문/대상, 현재 상태 이해, 원하는 동작의 성공과 단계 수를 확인한다; 잘못된 대상 선택이나 모호한 제어를 주입해 방지/확인 여부와 실제 다른 업무에 미친 영향을 별도로 기록한다.
- 목표 상태: 조작 성공률·단계 수는 미확정이며 다른 업무 오실행 0건은 기존 action/access 규칙을 보존한다.
- 책임 경계: 음성 출력 중단과 업무 취소를 구분한다. pending을 완료로 표시하지 않고 숨겨진 내부 focus를 사용자에게 제시된 질문으로 간주하지 않는다.
- 품질 분류: Interaction capability → Operability / User error protection

### V-13 설치 용이성

- 측정 초안: 동일 PC/profile에서 신규 설치·갱신·제거와 단계별 부분 실패를 시험한다; runtime/helper/weights 의존성, 상태/schema migration, 사용자 절차·시간, 실패 식별과 복구/정리 결과 및 의도하지 않은 잔여 실행체·자료를 기록한다.
- 목표 상태: 성공률·절차·시간과 잔여물 판정 기준은 미확정이다.
- 책임 경계: 내려받는 크기만으로 설치 용이성을 판단하지 않는다. 사용자가 의도적으로 보존한 자료와 제거 실패의 잔여물을 구분한다.
- 품질 분류: Flexibility → Installability

## 공통 측정 조건과 목표 확정 항목

- 사용자 목표, 완료 조건, 공통 요구 목록과 외부 capability/profile을 같게 유지한다. 각 DP의 영향 경로와 비적용 근거를 기록하고 특정 DP에만 지표나 의미를 바꾸지 않는다.
- PC·OS·전력 조건, Omni/ASR/helper 구성, warm/cold 조건, 입력률, 동시 업무 수, 자료 크기, background 작업 및 타 앱 부하를 기록한다. 실제 수치는 이 조건을 정한 뒤 설정한다.
- 시간 지표는 실제 사용자/source 사건과 유효한 결과·제어 효과를 연결한다. 물리적 위치가 달라도 VIA 책임 비용은 포함하고 Agent 내부 업무 및 사람의 답변 대기를 구분한다.
- 정답 기준, 사례·변형·장애·변경 목록, 적용 판정, 반복 수, 지연 분포·집계, timeout과 실패 처리를 결과 전에 확정한다. 미확인·누락·실패를 성공 표본에서 제거하지 않는다.
- 묶인 부특성은 자원/수용량, 결함 허용/복구, 변경/모듈성, 분석/시험, 상호운용/공존, 조작/오류 방지를 각각 확인한다.
- 정량 목표가 미정인 항목은 단위·상한/하한·근거·적용 조건을 채운 뒤 발표 확정본에 반영한다. 실제 model/제품을 실행하지 않은 자료를 실측 결과로 표시하지 않는다.
