# 과제 소개 v9 검수 기록

검수일: 2026-10-14

## 대상과 범위

- [통합본 v9](../VIA-architecture-presentation_v9.pptx): 63장 중 관련 동향과 필요성인 실제 1~2장 교체
- [두 장 전용 PPTX](../VIA-project-introduction_v9.pptx): 같은 두 장과 발표자 노트
- [출처 및 편집 원본 안내](../project-introduction-v9/README.md)
- [슬라이드 목록](./manifest-v9.json)과 [보존 검사](./preservation-v9.json)

사용자가 언급한 3~4페이지 대신 슬라이드 제목으로 편집 대상 식별. 실제 v8의 3~4장은 VIA 역할과 시스템 구조이며 변경 없음. Bixby, Galaxy Book 생산성 자료와 Copilot Vision 제외. 주요 기업 사례는 Google, Amazon, Apple, OpenAI. CTO 메시지는 사용자 제공 문구의 인용으로 발표자 노트에 출처 구분. 필요성 페이지에 구체적인 대화나 업무 예시 없음.

## 로컬 검사

- Artifact Tool 기반 편집 가능한 텍스트, 역할 도형 및 시장 차트 작성
- 시장의 2026 추정과 2031 전망, 십억 달러 단위, 0 기준선 및 원자료 값 확인
- 신규 시장 데이터의 내장 workbook 생성 및 차트 참조 일치 검사
- 파일 무결성, 슬라이드 수, native 표 및 차트, 도형 경계와 글자 정책 검사
- Calibri, 정수 pt, 한국어 기본값 위반 0건
- 63장 전체 렌더링 및 변경 두 장의 원본 크기 확인, 전체 슬라이드 흐름 점검
- 슬라이드 3~63의 본문 XML, 관계 파일 및 노트의 v8 대비 바이트 동일성 확인
- 원본 media, 마스터, 레이아웃 및 테마 보존
- 두 GIF의 바이트와 68/128프레임 애니메이션 데이터 보존
- 새 본문 문구의 명사형, 중간점 미사용 및 제외 대상 서비스 미포함 확인

GIF 프레임 데이터 보존과 렌더러의 정지 미리보기는 PowerPoint 자체 애니메이션 재생 검증과 별개. 기존 FR, QA 및 DP 상세 페이지는 v8 상태 보존이며 최신 Architecture 논의와의 전면 동기화는 이번 범위 밖. 구현, 모델 실행, 성능 측정 및 DP 선정 없음.

## Windows 검증

두 파일 모두 Calibri가 설치된 Windows Server 2022의 Microsoft Open XML SDK 3.3.0 검사 통과. Office2021 스키마 오류 0건, 파일 열기 성공. Windows에서 검사한 SHA-256과 최종 로컬 파일의 해시 일치.

| 대상 | Windows 실행 | 슬라이드 수 | 스키마 오류 |
| --- | --- | --- | --- |
| 두 장 전용본 | [검사 통과](https://github.com/cbyche/via-sw-architecture/actions/runs/38576295510) | 2 | 0 |
| 통합 v9 | [검사 통과](https://github.com/cbyche/via-sw-architecture/actions/runs/38576297414) | 63 | 0 |

PPTX 배포 commit `62617e68a`의 [Architecture CI](https://github.com/cbyche/via-sw-architecture/actions/runs/38576237978) 통과. 상세 해시와 Windows 환경은 보존 검사 JSON에 기록.

Windows cloud에 PowerPoint 미설치. 프로그램 자체에서의 글꼴 배치, 차트 편집과 GIF 재생은 미검증. SDK 검사와 로컬 렌더링의 범위로 한정.
