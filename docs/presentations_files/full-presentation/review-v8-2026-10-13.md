# v8 문제 소개·그림·통합 발표자료 검수

## 작업 범위

최신 입력인 [v7](../VIA-architecture-presentation_v7.pptx)의 사본에서 [v8](../VIA-architecture-presentation_v8.pptx)을 작성했다. 이전 버전과 개별 발표자료는 보존한다. 부모 세션의 Architecture 본문, AGENTS.md와 공용 workplan, 04-50 및 제안서 DOCX/JSON/그림/생성기는 이 작업에서 편집하지 않았다. 제안서 파일에는 작업 중 다른 세션의 변경이 관찰되었으며 되돌리거나 덮어쓰지 않았다.

사용자가 요청한 문제 소개를 사용자 장면 → 피해 → SW 어려움 → 설계 질문으로 다듬고, 그림과 PPTX의 편집 가능한 도형에 같은 장면 정의를 적용했다. 새 구조를 선정하거나 기존 A/B의 실행·저장 기제를 바꾸지 않았다.

## 그림과 생성 원본

[장면 정의](../../../scripts/architecture/via_problem_intro_scenes.py)가 아래 6개 장면의 SVG·draw.io, [현재 통합 draw.io](../dp-background/VIA-problem-intros-v8.drawio), [HTML 모아 보기](../dp-background/index.html)와 PPTX native 도형의 공통 내용이다. [그림 목록](../dp-background/README.md)의 PNG는 해당 SVG의 1920×1080 렌더링이다.

- `via-common-request-background`
- `dp44-background`
- `dp45-background`
- `dp45-basic-structures`
- `dp42-background`
- `screen-voice-grounding-background`

44·45·42의 현재 개별 SVG/draw.io와 기존 연결 경로의 PNG를 함께 갱신했다. 다른 DP의 배경·MAIN·수명·사건 그림과 이전 통합 draw.io/PPTX는 보존했다. 이전 통합 draw.io는 당시 구성이며 현재 모아 보기는 v8만 주요 흐름으로 표시한다.

[PPTX 작성](../../../scripts/presentations/update_problem_intros_v8.mjs)은 Artifact Tool JS API를 사용한다. [패키저](../../../scripts/presentations/package_problem_intros_v8.py)는 새 native 도형과 지정한 문구·셀·노트만 최신 package에 반영하고 원래 마스터·레이아웃·테마·미디어를 보존한다. SVG를 슬라이드 전체 이미지로 붙이지 않았다. 상자 라벨은 각 도형 자체의 `p:txBody`에 있다.

bundled Node/Python과 package 경로를 설정하고, private build에 `node_modules`를 연결해 실행한다. `RUNTIME_NODE_MODULES`, `VIA_RUNTIME_PYTHON`, `VIA_PRESENTATION_SKILL_DIR`는 `load_workspace_dependencies`가 반환하는 현재 경로를 사용한다. 새 build에는 `via_problem_intro_scenes.py --scene-json BUILD/scenes.json`으로 장면 JSON을 쓰고 작성 `.mjs`의 사본에 저장소·build의 절대 경로를 전달한다. 발표 skill의 시작 marker를 성공적으로 한 번 호출한 뒤 작성했다. 파일을 수정할 때마다 새 private output 경로를 사용했으며 최종 검증 파일을 bytes 그대로 저장소에 복사했다.

## 검증과 한계

검증 기록은 [manifest-v8.json](./manifest-v8.json)과 [preservation-v8.json](./preservation-v8.json)에 남겼다.

- 총 63장, 기존 20×11.25in / 16:9 유지. 전체 최종 파일을 Artifact Tool로 다시 열고 렌더링했다.
- 파일 구조·관계, geometry·머리글·native 표 검사에서 오류와 경고 0건. native 표 44개를 유지한다. 이 검사에 품질 목표의 실측은 포함되지 않는다.
- Calibri, 정수 pt, `ko-KR` 및 새 텍스트 기본값 정책 위반 0건. 새 6개 페이지의 모든 문구와 명시된 pt 크기를 장면 정의와 대조했다.
- 변경 페이지를 개별 렌더링으로 확인했다. 작은 글자 크기 적용 오류와 24장의 긴 셀 문장을 수정한 뒤 최종 파일을 다시 검증·렌더링했다. 배경 SVG 6개의 텍스트 폭·캔버스·텍스트 겹침 검사 0건이며 시각적으로 연결선 위치도 확인했다.
- v7의 비대상 52개 슬라이드 본문과 노트가 보존된다. 페이지 번호와 이동한 41의 상단 탐색 표시를 제외한 본문 렌더링은 픽셀까지 동일하다. 44·45·42의 기존 A/B 그림과 평가표도 이 보존 집합에 포함된다.
- v7의 모든 26개 media part, 마스터·레이아웃·테마를 bytes 그대로 보존한다. Claude 브라우저 GIF와 기존 시연의 애니메이션 데이터를 변경하지 않았다.
- SVG/draw.io 생성기 검사, 활성 링크·용어·QA catalog 검사 및 42·44·45의 기존 MAIN/계약 검사를 실행했다. 새 품질 측정이나 모델 호출은 실행하지 않았다.

**Windows Open XML SDK와 PowerPoint 자체 실행·native 글꼴 배치·GIF 재생은 v8에서 미검증**이다. v7의 cloud 검사 결과를 v8의 결과로 옮겨 주장하지 않는다. Artifact Tool의 로컬 렌더링과 파일 구조 검사는 PowerPoint 직접 실행을 대신하지 않는다.

모델 실행, 품질 측정, A/B 최종 선정 및 새 DP 번호 부여는 하지 않았다. 독립 agent review는 이 작업에서 요청·수행하지 않았으며 자체 검수 결과다. 작성·검수 후 사용자가 commit/push를 요청했으며, 발표자료와 관련 그림·생성 원본만 그 대상으로 지정했다.

## 부모 세션에 남긴 설계 논의

42의 B가 강한 A에 비해 어떤 정상 사용자 장면에서 충분히 중요한 차이를 만드는지, 새 화면·음성 지칭 문제에 어떤 구조와 강한 대안을 둘지는 부모 세션의 검토 범위다. 이번 그림에서 답이나 우위를 추가하지 않았다. 공통 요구·배경과 최신 발표자료의 동기화는 완료했으며, 그 논의가 기존 A/B MAIN이나 Architecture 본문을 바꾸면 이후 별도 버전에서 반영한다.
