# 주요 DP 네 개의 최소 PoC 계획

2026-10-18 / 사용자 검토용 실행 계획 / 구현과 모델 실행 전

## 1. 목표와 권고 범위

**공통 실행기 하나에서 각 DP의 A/B 기제만 교체하고, 작은 사건 묶음으로 시간과 비용 및 오류의 원인을 확인한다.** 외부 Agent의 업무는 고정된 사건으로 재생한다. 비교의 핵심인 문맥 생산, 요청 해석, 화면 후보 생산과 인계 구성은 실제로 실행한다.

이 PoC의 목표는 **어떤 사용 조건에서 어느 기본안을 선택할지 결정할 실측 근거**다. 네 DP의 모든 QA에서 반드시 차이가 나온다는 보장은 없다. 범위 안에서 차이가 없거나 한 안이 모든 관측 축에서 좋으면 그 결과로 설계를 정리한다.

최소 범위에서 먼저 확인할 것은 다음과 같다.

| DP | 첫 비교 | 확인할 상충 | 이번 구현에 필수인 부분 |
| --- | --- | --- | --- |
| 01 근거 공급 | A 유지 문맥 / B 요청별 구성 | 후속 질문의 조회와 구성 대기 ↔ 유지 입력과 갱신 비용 | 실제 view 생산/압축, 원본 읽기, 요청별 구성, 공통 후속 해석과 지칭 채택 |
| 02 의미 판단 실행 | A 한 대화 실행 / B 공통 대화와 요청별 실행 | 새 입력의 선행 step 대기 ↔ 실행별 문맥과 반환 비용, 원래 목표의 지연 | 비동기 수신, 두 실행 전략, 같은 전역 호출 한도, 관계 판단과 현재성 검사 |
| 04 화면 지칭 | A 원본 결합 / B 후보 생산 후 결합 | 지칭 오류와 재처리 감소 가능성 ↔ parser/producer/결합 비용 | 같은 원본 replay, 실제 화면/발화 생산, 코드 또는 모델 결합, 원본 확장과 채택 |
| 05 업무 인계 | A 위임 때 구성 / B 지속 업무 기록 | 반복 인계의 준비 대기 ↔ 미사용 선생산과 갱신 비용 | 공통 Task 이후 실제 남는 인계 설명 생산, 목적별 구성, 외부 허가 계약과 수신 |

첫 비교는 A/B 두 안으로 한정한다. 01 C의 관계 선생산과 05 C의 수신자 자료 선택은 별도 가치가 남을 때 한 쌍씩 추가한다. 다른 DP의 모든 A/B 조합이나 모든 tactic을 구현하지 않는다.

## 2. 공통 실행기에서 만들 것

기본 구조는 한 프로세스의 함수와 자료형으로 충분하다. 그림의 각 상자를 별도 서비스로 만들 필요는 없다. QA04까지 이어갈 가능성을 고려하면 공통 실행기와 후보 정책을 Rust로 작성하고, 자료 정리와 분석만 별도 스크립트로 처리하는 구성을 권고한다. 언어 선택 자체의 성능 비교는 하지 않는다.

```text
사건 원장과 원본 저장소
  → 공통 입력 수신 및 revision 기록
  → 이번 DP의 A 또는 B 처리
  → 공통 채택 검사와 응답/위임
  → 작은 Request/Task 표시창 또는 진단 출력

모든 처리 → 같은 모델 adapter와 전역 호출 한도
모든 처리 → 시각, 의존 관계, 실제 usage와 결과 원장
평가자만  → 별도 정답 파일
```

| 공통 기능 | 최소 구현 |
| --- | --- |
| 입력 | Text, 녹화한 발화/전사/화면/포인터 사건과 Agent 통지의 JSONL replay |
| 원본 | 파일과 metadata. source ID, 시각, 판본, 접근 범위와 실제 전달 구간 |
| 호출 | 고정된 실제 의미/vision 모델 adapter, 필요한 실제 parser adapter, 같은 호출 admission |
| 상태 | 요청 revision, Task 관계, 미해결 입력, 사용 중인 원본 참조, 최초 채택/외부 허가 기록 |
| 출력 | 응답 ID별 내용과 표시 기록. 첫 단계는 CLI 진단도 가능하고 QA01 실측 단계에는 작은 공통 표시창 추가 |
| 계측 | monotonic 시각, 호출 시작/종료, source 시각, parent와 자원 의존, input/output/cache usage, 취소 이후 청구 |
| 판정 | 지칭 집합 정답, 요청/질문 관계, 인계 계약의 필수 조건을 별도 원장과 비교 |

화면 수집용 Windows 제품 연동, 음성 인식 엔진 개발, 외부 업무 앱 조작, 일반 Agent 플랫폼, 전체 제품 UI와 서비스 재시작 복구는 이 첫 구현에 포함하지 않는다. 실제 화면 수집을 생략해도 화면 원본과 시각, pointer/selection 자료 자체를 만들어 주거나 삭제하지는 않는다.

### 실제 처리와 대역의 경계

- **실제 실행:** 요약/압축, 필요한 의미 검색과 요청 해석, 화면 후보와 binding, 자유문 결과의 인계 설명 생산. 필요한 모델 호출과 원본 읽기 횟수는 후보가 결정한다.
- **코드로 처리:** 명시 ID 조회, 판본/권한 검사, typed 관계의 일의적인 결합, queue와 저장. 차이를 만들려고 모든 단계에 모델을 강제하지 않는다.
- **재생 가능:** 사용자 입력, 이미 발생한 공개 Agent 결과와 질문, 화면/포인터 관측. 원래 요청에 의존하는 결과는 유효한 ingress 뒤에만 공급한다.
- **채점기 전용:** 정답 Task/관계, 지칭 집합, 필수 인계 조건. 완성 view나 정답 후보를 A/B 입력으로 제공하지 않는다.

실제 모델 전에 명시적 barrier로 정정/늦은 결과/철회 순서만 한 번씩 확인한다. 이때의 고정 응답과 대기시간은 기능 경로 확인용이며 성능 자료에 섞지 않는다. 실제 cloud 동시성이 지원되지 않으면 02 B의 이익을 synthetic sleep으로 대신 입증하지 않는다.

## 3. 적은 실행으로 판별하는 시나리오

### 3.1 근거 공급

원본, 실제 전달 기록과 현재 요청의 해석기를 양안에 공통으로 제공한다. A는 자기 view를 실제로 만들고, B는 공통 최소 문맥에서 필요한 원본을 실제로 구성한다. B의 유효한 최근 상태와 코드 조회를 제거하지 않는다.

| 묶음 | 입력과 비교 이유 |
| --- | --- |
| E1 같은 자료의 연속 질문 | 설명 뒤 세부 질문, 두 항목 관계, 요약을 이어 묻는다. 재사용 대기와 반복 입력 비용 관찰 |
| E2 서로 다른 주제 | 같은 길이의 활동에서 이전 자료를 재사용하지 않는다. 유지 문맥의 미소비 비용 관찰 |
| E3 일부 전달과 원본 변경 | 실제 표시/청취 범위를 일부로 두고 정정, v1/v2 및 철회를 재생. 과거 설명과 최신 자료를 구별하고 원본 보완 확인 |

**결과:** 요청별 첫 응답/완료와 전체 활동의 모델 비용, 실제 조회/압축/재시도, 채택 지칭 집합을 비교한다. E1과 E2에서 비용 방향이 바뀔 때만 재사용이 중간인 활동을 하나 더 준비한다. 그때도 미래 질문을 view 생산자에게 미리 주지 않는다.

### 3.2 의미 판단 실행

원본 두 개, 대화 하나, 최대 요청 세 개와 고정 Agent 통지 하나면 시작할 수 있다. 근거 공급 정책은 고정한다. A/B 모두 같은 전체 호출 한도 K를 받는다.

| 조건 | 입력과 비교 이유 |
| --- | --- |
| X1 겹치지 않는 후속 질문, K=2 | 문맥 재사용과 B의 불필요한 추가 호출 여부 |
| X2 긴 VIA 판단 중 짧은 독립 질문, K=2 | 현재 의미 step 뒤에 기다리는 시간과 공통 짧은 답 경로 |
| X3 긴 VIA 판단 중 다른 자료 요청, K=2 | 요청별 실제 병행, 문맥과 반환 비용, 두 목표의 완료 |
| X4 정정과 Agent 질문, K=2 | “비용만 비교” 정정, 실제 표시된 Agent 질문에 대한 답, 늦은 구버전 반환 |
| X5 X3의 포화 대조, K=1 | 같은 총 자원에 여유가 없으면 실행 분리의 이익이 사라지는가 |

A를 전체 요청 완료까지 대기시키지 않는다. A도 step 경계에서 새 입력을 처리하고 외부 Agent 대기 동안 입력을 받는다. B의 짧은 답에 worker를 강제하지 않는다. 새 질문의 이익과 원래 목표의 손해를 함께 보고한다.

후속 입력은 사전에 정한 동일한 trigger 규칙으로 재생한다. 논리적 주요 호출의 송신 후 상대 시각을 쓰면 그 조건을 밝히고 실제 송신/도착 절대 시각도 기록한다. 호출이 이미 끝난 반복을 버리거나 응답을 붙잡아 겹침을 만들지 않는다. Agent 질문의 사용자 답은 각 안에서 질문이 실제 표시된 뒤에 제공한다.

### 3.3 화면 지칭

작은 녹화 장면 여섯 개를 사용한다. 각 장면은 최대 두 완성 발화, 보존 frame 여섯 개, 지칭 표현 네 개 정도로 제한하되 원래 범위를 처리하는 데 필요한 근거는 보존한다. 이 크기는 비용을 줄이기 위한 PoC 범위이며 제품의 입력 제한이 아니다.

| 장면 | 확인할 경로 |
| --- | --- |
| G1 사전 선택 후 foreground 변경 | 선택 근거와 현재 화면의 구별, native 경로 대조 |
| G2 밀집 화면의 작은 반복 요소 | 별도 screen parser 표현의 이익 가능성 |
| G3 그래프 안의 자유로운 범위 | 언어가 범위를 정할 때 후보 누락과 원본 확장 |
| G4 click 없는 원형 지정과 페이지 이동 | 복수 집합과 과거 frame 보존 및 시점 결합 |
| G5 부분 정정과 늦은 결과 | 유지할 대상과 바꿀 대상, revision gate |
| G6 실제 관측 공백 또는 철회 | 없는 근거를 만들어 확정하지 않는 공통 기능 |

B에는 실제 parser와 Speech/Screen Producer, 후보 계약과 Binding Resolver가 있어야 한다. 이미 정답인 후보를 손으로 넣지 않는다. 충분한 typed 관계는 코드로 결합하며 후보 밖의 대상은 원 생산자가 원본에서 확장한다. A는 같은 원본/native 근거로 한 호출에서 여러 지칭을 처리할 수 있다.

정답 원장은 장면 제작 때 만들고 후보에게 숨긴다. 지칭 표현과 입력 revision별 **채택된 대상 집합의 완전 일치**를 사용한다. 내부 후보 수정은 허용하지만 오답을 채택한 뒤 고쳐 최초 실패를 지우지는 않는다. 실제 모호함은 사전에 분모에서 제외하고 기능 검사에 남긴다.

**추가 비교는 필요한 경우에만 한다.** B가 정확도에서 좋아 producer 구조를 추천하려면 A4에 같은 parser를 붙여 효과의 원인을 구별한다. B가 느려서 제외하려면 B4의 독립 생산 병행으로 같은 호출 예산에서 비용이 줄어드는지 확인한다. 기본 B와 A4/B4는 별도 열로 남긴다.

### 3.4 업무 인계

선택 Agent, 이미 채택한 목적/조건, 현재 Task와 01에서 얻은 유효 근거는 공통 입력으로 고정한다. A가 가진 근거를 숨기거나 B에 완성된 인계 설명을 무료로 주지 않는다.

| 묶음 | 입력과 비교 이유 |
| --- | --- |
| H1 공개 결과가 있지만 후속 인계 없음 | 전체 관측 창 동안 B의 미소비 생산 비용 확인 |
| H2 다른 Agent로 한 번 인계 | 목적에 맞춘 A 구성과 B 추출/보완, 실제 전달 범위 및 known/unknown 보존 |
| H3 같은 업무를 세 번 인계하며 중간 정정 | 발표자료, 메일, 회의 메모처럼 목적이 달라지는 재사용. 정정/철회 뒤 조건과 판본 유지 |

H1/H2/H3는 동일 원본에서 시작하는 별도 가지다. 생산자는 어느 미래 가지인지 미리 알지 못한다. H3 안에서는 첫 번째와 세 번째 인계까지의 누적 비용도 읽는다. H1의 미소비 비용은 단지 H3 시작 전 짧은 구간으로 대체하지 않는다.

외부 Agent 대역은 실제 인계 계약을 받아 정해진 공개 결과를 돌려준다. N-H는 외부 실행 허가 시 목표, 필수 조건, 제외 범위, 유효한 근거 참조와 접근, 허용 실행 범위가 맞는지를 별도 채점한다. 대역이 결과를 반환했다고 잘못된 인계가 성공으로 바뀌지 않는다.

```text
A 전체 비용 = 각 인계의 실제 구성/보완 비용 합
B 전체 비용 = 모든 기록 생산/갱신 비용 + 각 인계의 추출/보완 비용 합
```

B가 위임 때 줄이는 양이 양수일 때만 반복 횟수의 손익분기를 추정한다. H3에서도 선생산을 회수하지 못했다면 그 결과를 남긴다. B가 공통 Task/01 근거를 복제할 뿐 실제 재구성을 줄이지 못하면 그 별도 생산 계층을 권고하지 않는다.

## 4. 최소 실험 규모와 순서

아래 수는 통계적 최소 표본 수가 아니라 **예산을 제한한 계획 상한**이다. episode 하나에 모델 호출이 여러 번 있을 수 있으므로 실행 수를 API 호출 수나 비용으로 읽지 않는다.

| DP | 예비 실험 | 새 자료의 확인 실험 상한 |
| --- | ---: | ---: |
| 01 | 3묶음 × 2안 × 3회 = 18 | 3묶음 × 2안 × 5회 = 30 |
| 02 | 5조건 × 2안 × 3회 = 30 | 5조건 × 2안 × 5회 = 50 |
| 04 | 6장면 × 2안 × 2회 = 24 | 새 6장면 × 2안 × 5회 = 60 |
| 05 | 3묶음 × 2안 × 3회 = 18 | 3묶음 × 2안 × 5회 = 30 |
| 합계 | **최대 90 episode 실행** | 모든 DP가 계속되면 **최대 170 추가 실행** |

1. **준비:** 입력/정답 분리, 후보의 필수 기능, 관측 구간과 조건을 문서로 고정한다. 실제 API의 요청/응답과 필요한 동시성/parser 지원을 작은 접속 확인으로 점검한다. 이 확인을 성능 본시험으로 세지 않는다.
2. **기능 경로:** 정정/늦은 결과/철회 및 외부 중복 방지의 필요한 순서만 deterministic 대역으로 확인한다. 제품 전체 회귀 suite를 만들지 않는다.
3. **예비 실험:** 실제 호출을 써서 차이가 어느 단계에서 생기는지, 모델 변동이 얼마나 큰지 확인한다. 조정한 prompt/schema의 버전을 남긴다.
4. **확인 실험:** 구조와 설정을 고정한 뒤 원본/표현을 바꾼 미사용 자료에서 수행한다. 주장하는 오류 경로에는 서로 다른 원본 사례를 최소 두 개 두고, 반대안에 유리한 조건과 쉬운 동점 조건도 남긴다. 적은 장면 안에 담기지 않으면 확인 범위를 줄여 명시하거나 필요한 장면만 추가한다.
5. **선택 후 보완:** 선택안을 실제로 방해한 약점에 tactic 하나를 적용하고 같은 확인 자료에서 전후를 비교한다. A1/A2 전부와 모든 조합은 만들지 않는다.

예비 실험을 본시험과 합쳐 유리한 평균으로 만들지 않는다. 확인 실험의 모든 사례와 반복을 마친 뒤 결론을 낸다. 결과를 보며 원하는 방향이 나올 때까지 반복하지 않는다. 기능 오류, 계측 불능 또는 정한 비용 한도에 도달하면 실패/미관측을 보존하고 중단한다. 수정 후에는 새 판본으로 영향을 받은 A/B 양쪽을 다시 비교한다.

**작업 순서:** 공통 실행기 이후 02와 04의 작동 가능성을 먼저 병렬 확인한다. 02는 실행 의존을 빨리 확인할 수 있고 04는 parser/정답 자료의 불확실성이 크다. 01을 구현한 공통 원본/usage 경로를 05에 재사용한다. 최종 조합 전체의 시험은 각 DP 비교 뒤의 작은 통합 확인으로 남긴다.

## 5. QA를 어디까지 확정할 수 있는가

| QA | 작은 PoC에서 가능한 결론 | 공식 값 또는 목표 판정을 위한 추가 경계 |
| --- | --- | --- |
| QA01 첫 응답 | 같은 입력에 대한 내용 준비 대기와 작은 UI의 표시 차이 | 실제 UI 프레임을 확인해야 QA01. API 반환/렌더 callback만 있으면 준비 구간 proxy. 오답도 실제 시간을 기록 |
| QA02 지칭 집합 | 같은 oracle에서의 일치율과 최초 채택 오류, 사례별 A만 정답/B만 정답 | 독립 원본 사례를 늘려야 넓은 정확도 주장 가능. 좁은 사례의 100%로 93% 제품 목표 달성을 주장하지 않음 |
| QA03 VIA 처리 | Text/Voice OFF의 정한 목표까지 실제 상세 표시를 연결하면 해당 경로의 귀속시간 | Voice ON을 주장하려면 실제 전사와 필요한 전체 음성 요약 준비까지 포함. CLI 종료나 binding 완료는 부분구간 |
| QA05 모델 비용 | 같은 PoC 활동 창의 모든 실제 호출 비용과 재사용 손익분기 | 기존 단위는 COMMON-28 전체 묶음이다. 부분 semantic 비용을 $2.55 목표/0~6점으로 직접 환산하지 않음 |
| QA04 변경 범위 | 최초 기능 구현만으로 차이 판정 불가 | 같은 실제 변경 과제를 운영 Rust 모듈에 적용해야 함. 그림/파일/함수 개수는 대체 지표가 아님 |
| QA06 최대 RAM | PoC 상태/버퍼의 크기와 수명, 부분 프로세스 관측 | 전체 로컬 VIA의 실제 상주 RAM과 공유 중복 제거, Windows 계측 필요. commit은 보조이며 512 MB 제품 합격 판정 불가 |

**처음부터 결과물에 QA01/03 원값이 필요하면 작은 공통 UI까지 구현하는 안을 권고한다.** 01/02/05는 우선 Text와 Voice OFF의 명시적 범위로 진행할 수 있다. 04는 원음/전사 timing을 재생해 binding을 비교하되 실제 음성 응답 경로가 없으면 grounding 구간과 QA02만 먼저 판정한다. 기존 Voice ON 시나리오의 음성을 몰래 꺼 같은 결과로 표기하지 않는다.

시간은 산술평균, 원값과 미관측 건수를 함께 제공한다. QA03은 실제 의존 그래프에서 외부 Agent와 사용자 대기만 0으로 바꾼 경로 길이다. 병렬 시간을 모두 더하거나 실제 전체 시간에서 외부 시간을 단순 차감하지 않는다. QA01과 QA03을 합산한 종합 점수를 만들지 않는다.

준비/미사용/재시도/폐기/취소 후 청구를 비용에 넣는다. 원본을 재사용하더라도 해당 안의 파생 상태 생산은 실제로 수행한다. provider cache는 지원과 적중을 기록하며 한쪽에만 무료 warm 상태를 주지 않는다. 동일 비용을 01과 05에서 중복 합산하지 않는다.

COMMON-28과 DP-RELATED-v2의 기존 모집단 및 점수표는 보존한다. 이번 일곱 문제의 새 A/B에 옛 DP의 분모/예상 점수를 그대로 옮기지 않는다. 공식 점수가 필요하면 새 관련 사건/목표 매핑을 결과 전에 고정하고 동일 endpoint로 실행해야 한다. QA05는 전체 묶음 비용을 실제로 확보해야 한다. 부분집합 결과를 선형 확대해 전체 금액을 만들지 않는다.

## 6. 차이를 확인했다고 말하는 기준

### 실험 전에 정할 것

- 자료와 oracle, 모델/parser 판본, 출력 요구, 호출/원본 한도, 가격과 비용 상한.
- 입력 trigger, 전처리/초기 준비, 비교 순서, 관측 종료와 늦은 청구 수집.
- 선택을 바꿀 **실용 차이 기준 δ**와 허용할 기능 상태. 이는 기존 QA 점수 구간을 바꾸는 것이 아니다.

δ의 출발 제안은 표시/처리 시간에 `상대 10%와 절대 100ms 중 큰 값`, 활동 비용에 `10%`다. 이는 연구에서 입증된 사용자 한계가 아니라 작은 차이에 개발 비용을 쓰지 않기 위한 **계획 제안**이다. 계측 오차와 예비 실험 변동이 더 크면 작은 차이를 인정하지 않는다. 확인 결과를 보기 전에 기준을 고정한다. 정확도에는 임의 1~2건 우세를 합격선으로 두지 않는다.

### 결과 분류

| 결과 | 판정 |
| --- | --- |
| 서로 다른 QA에서 반대 방향의 실용 차이가 재현되고 trace로 원인을 확인 | **해당 조건의 trade-off 확인**. 사용 빈도/우선순위를 적어 기본안 결정 |
| 한 안이 관측한 모든 주요 QA에서 유리하고 기능도 유지 | **해당 범위에서 우세**. 반대 비용을 만들어내지 않음 |
| 한 축 차이만 확인 | 그 개선만 확정. 나머지 가설은 미확인 |
| 차이가 기준보다 작고 변동 안에 있음 | 판별되지 않음. 단순한 구조를 고르는 공학적 결정은 가능하지만 동등성 입증이라고 부르지 않음 |
| 반복/새 자료에 따라 방향이 바뀜 | 조건 의존 또는 미결. 조건별 원값을 공개하고 일반 승자를 선언하지 않음 |
| 잘못된 정정/인계/채택, 목표 소실, 정답 누출 또는 계측 불능 | 현재 구현/실험의 수정 필요. 빠른 오류를 성공으로 선정하지 않으며 시간 원값은 보존 |

5회 반복은 같은 고정 자료의 변동 관측이다. 다른 자료 다섯 개나 사용자 다섯 명으로 세지 않는다. 평균의 불확실성을 계산할 때도 같은 episode 안의 여러 응답을 독립 반복처럼 부풀리지 않는다. 짝지은 차이에 대한 추론은 가정과 반복 단위를 명시한다. 작은 표본의 성공률은 특히 주의해야 하며 독립성 없는 반복에 단순 이항 신뢰구간을 적용하지 않는다. [NIST 짝지은 평균 차이](https://itl.nist.gov/div898/handbook/prc/section3/prc312.htm), [NIST 작은 표본의 비율 구간](https://itl.nist.gov/div898/software/dataplot/refman2/auxillar/exacbici.htm)

**화면 정확도의 작은 차이는 이 계획의 상한 안에서 확정하지 못할 수 있다.** 그때는 자료를 추가할 가치가 있는지 결정하거나 정확도 우위 미확인으로 종료한다. 05도 QA03/05 외의 세 번째 차이가 나오지 않으면 기존 과정 coverage 빈칸을 유지한다. 추가 시험을 했다는 사실은 새 QA 차이가 있다는 증거가 아니다.

## 7. 조건부 추가와 최종 결과물

| 추가 | 수행 조건과 최소 범위 |
| --- | --- |
| 01 C | 여러 대화에서 같은 과거 관계를 반복 소비하는 일이 주요 사용에 남을 때 B/C. 실제 선생산, 미소비와 미지원 관계 포함 |
| 05 C | 수신자가 상세 자료를 직접 고르는 이익을 평가할 때 실제 읽기 지원 Agent 하나로 A/C. A도 유효 artifact 참조 허용. 고정 read 대역만으로 수신자 선택 품질을 주장하지 않음 |
| 04 A4/B4 | 위 §3.3의 원인 구분 또는 강한 반대안 확인에 필요할 때. 기본과 분리해 보고 |
| 선택안 tactic 하나 | 관측된 가장 큰 약점을 줄일 때. 예: 01 A1 prefix cache, 02 B2 호출 여유 예약, 04 A1 crop/cache, 05 A1 인계 묶음 cache |
| QA04/06 | 실제 중요한 차이의 근거가 있을 때 별도 변경 과제/Windows 전체 계측. 세 번째 QA 칸을 채우기 위한 형식적 실험은 하지 않음 |

실험 후 각 DP에 다음 한 묶음을 남긴다.

1. 최소 A/B 코드와 입력/정답 및 실행 manifest.
2. 같은 사건별 실제 시간/비용/정확도, 실패와 미관측, 단계별 원인 trace.
3. 기본안 선택 또는 미결, 그 결론이 성립하는 재사용/입력 겹침/대상/인계 조건.
4. 선택한 tactic 하나의 전후 결과와 남은 손해.
5. 새 QA×DP 표의 `차이 확인 / 미확인 / 범위 밖` 상태. 실제로 확보하지 못한 QA는 채우지 않음.
