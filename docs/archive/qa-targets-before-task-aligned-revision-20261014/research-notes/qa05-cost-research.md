# QA05 조사 기록: 모델 사용 비용

> 조사 확인일: 2026-10-14 / 발표 설명 페이지를 위한 근거 보존 / 가격과 견적은 해당 확인일 기준
> 정의와 측정 및 점수의 기준은 [QA05 상세안](../qa05-model-cost.md)이다. 이 부록은 새 모델 선정이나 API 호출 및 비용 측정을 수행하지 않는다. [조사 목록](./README.md)

## 1. 이번 조사에서 답하려던 질문

사용자는 월 구독료 $20과 월 20일 및 하루 40요청을 가정해 요청당 비용을 나누는 방식을 거부했다. 소비자가 낼 금액과 실제 이용량이 확인되지 않았고 원하는 상한을 정한 다음 나누는 것으로는 제품 원가의 적정성을 설명할 수 없었기 때문이다.

이번 요구안은 **동일한 음성 대화와 화면 및 문맥 처리를 기성 API로 구성하는 공개 견적보다 VIA의 모델 원가가 커지지 않아야 한다**는 비교다. CTO/담당임원과 과제 책임자 관점에서 구성한 제품 요구안이며 승인된 예산이나 실제 발언이 아니다. 모델 원가 경쟁력의 참조점이고 출시 서비스 전체의 손익분기점은 아니다.

## 2. 출처별 확인 내용과 적용 범위

| 출처 | 확인한 사실 | VIA에 적용하는 부분 | 적용하지 않는 주장 |
| --- | --- | --- | --- |
| [GPT-Live 1 공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-live-1) | 음성 세션 $0.05/분과 초 단위 청구. 백엔드는 별도 | 5분 음성 프런트 견적 $0.25 | 음성 요금에 의미 해석 백엔드까지 포함된다는 주장 |
| [GPT-5.6 Luna 공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-5.6-luna) | 100만 토큰당 입력 $0.20와 출력 $1.20. cache write는 입력의 1.25배 | 참조 입력에는 높은 쓰기 단가 $0.25를 적용 | 모든 실제 API 입력이 반드시 쓰기 단가로 청구된다는 주장 |
| [이미지 입력 공식 가이드](https://developers.openai.com/api/docs/guides/images-vision) | 해당 모델의 high 입력은 최대 2,500패치와 1.2배 배율 | 한 장의 입력 견적을 최대 3,000토큰으로 계산 | 2880×1800 화면의 실제 tokenizer 결과가 정확히 3,000이라는 주장 |
| [음성 지연과 비용 공식 가이드](https://developers.openai.com/api/docs/guides/voice-latency-cost?voice-api=realtime) | 세션 시간에 발화 외 무음과 백엔드 대기도 포함 | 5분은 사용자와 모델의 발화 길이만 더한 값이 아님 | 후보가 5분 뒤 처리한 작업을 무료로 제외하는 주장 |
| [Groq 모델 표](https://console.groq.com/docs/models)와 [청구 FAQ](https://console.groq.com/docs/billing-faqs) | 모델과 입력 및 출력과 음성에 따라 요금 단위가 다름 | 모든 모델 사용을 통화 단위로 합치는 원장 필요 | 모델 호출 수만으로 비용 우열을 결정하는 주장 |

출처의 모델과 단가 및 기능 지원은 바뀔 수 있다. 향후 실행에서는 provider와 모델 버전 및 지역과 서비스 등급 및 확인일을 하나의 단가 manifest에 고정한다. 과거 결과를 새 단가의 실측 결과로 이름만 바꾸지 않는다.

## 3. 견적을 재현하는 계산

참조 활동은 `COST-20-v2`다. 20개 사용자 요청과 Agent 사건 6개를 5분 음성 세션에 배치하고 각 사건에 의미 처리 한 번을 배정하는 **미실행 견적 규격**이다. 고객의 하루 이용량이나 후보 구현의 호출 정책을 관측한 값이 아니다.

| 항목 | 산출 과정 | 금액 |
| --- | --- | ---: |
| 음성 | 5분 × $0.05/분 | $0.2500 |
| 텍스트 입력 | 26회 × 20,000토큰 × $0.25/100만 토큰 | $0.1300 |
| 총 청구 출력 | 26회 × 500토큰 × $1.20/100만 토큰 | $0.0156 |
| 화면 입력 | 6개 요청 × 15장 × 3,000토큰 × $0.25/100만 토큰 | $0.0675 |
| 합계 | 위 네 항목의 합 | **$0.4631** |
| 제품 상한 | 합계를 센트 단위로 올림 | **$0.47** |

500토큰은 화면에 보이는 응답만이 아니라 **청구되는 추론을 포함한 총 출력**이다. 필요한 추론과 출력이 이를 넘으면 참조 구성의 기능을 이 견적으로 달성했다고 말할 수 없다. 텍스트와 화면은 같은 input bucket에 포함될 수 있으므로 실제 원장에서는 provider가 보고한 청구량을 분리해 한 번씩만 센다.

초기 계산은 입력 $0.20를 적용해 텍스트 $0.104와 이미지 $0.054 및 음성 $0.25와 출력 $0.0156의 합인 $0.4236을 얻었다. 공식 cache write 조건을 검토한 후 참조 입력 전체에 더 높은 $0.25를 적용해 **$0.4631로 보완**했다. $0.43과 $0.47을 서로 다른 목표 후보로 병기하지 않고 현재 목표에는 후자를 사용한다.

요청당 텍스트 20,000과 이미지 최대 45,000토큰은 합쳐도 272,000토큰 미만이므로 이 견적에는 해당 긴 입력 할증을 적용하지 않는다. 세금과 지역 추가 요금 및 무료 크레딧과 프로모션은 반영하지 않는다. 실제 적용에 필요한 변경은 양안에 같은 manifest로 반영한다.

## 4. 표준 활동의 숫자가 의미하는 것

| 조건 | 선정 목적과 한계 |
| --- | --- |
| 20요청 | 화면 6과 과거 조회 6 및 업무 제어 4와 직접 질의 4를 한 활동에서 포함. 사용자 빈도의 통계가 아님 |
| 정정 4건 | 20요청 안에서 정정을 포함. 별도 목표로 분모를 늘리지 않음 |
| Agent 사건 6개 | 질문 2와 진행 2 및 결과 2를 포함. 사용자 요청 수와 별개 |
| 과거 조회 6개 | 재조회 3개와 새로운 관계 조회 3개를 포함해 생산과 재사용 양쪽 비용을 관측 |
| 이력 | 원본 200턴과 완료 Task 20개 및 진행 Task 5개. 파생 상태는 후보가 준비하고 비용 부담 |
| 원본 변경 2개 | 이미 만든 파생 상태의 갱신과 무효화 비용 포함 |
| 5분 | 짧고 반복 가능한 견적 활동 길이. 일일 사용량과 월간 과금 추정에 사용하지 않음 |
| 회당 20,000텍스트 토큰 | 지시문과 원본 이력 및 현재 요청을 담을 견적용 payload 규격. 실측 tokenizer 값 아님 |
| 화면 15장 | QA06과 같은 보존 대상 원본을 참조 구성에 제공하는 견적. 모든 후보에 15장 전송을 강제하지 않음 |
| 5회 반복 | 같은 초기 원본에서 시작하는 비용 비교. 반복 안의 정상적인 cache 재사용은 허용 |

아직 표준 WAV와 화면 자료 및 토큰 수를 확인한 견적 payload를 만들지 않았다. 실행 전 필요한 정보를 실제로 담을 수 있는지 확인해야 한다. 담을 수 없다면 후보 결과를 보기 전에 활동 규격과 참조 견적을 함께 개정한다. 필요한 내용을 잘라 현재 비용에 맞추지 않는다.

## 5. 실제 비용에서 빠뜨리기 쉬운 부분

1. **준비 비용:** 파생 이력과 후보 및 cache를 미리 만드는 시간부터 원장을 연다. B에 완성된 파생 상태를 무료로 주지 않는다.
2. **재사용:** A의 cache를 매 요청 삭제하지 않는다. B에 모든 가능한 관계를 무조건 생산하도록 강제하지 않는다.
3. **폐기와 실패:** 재시도와 취소 전 생성 및 잘못된 결과와 사용되지 않은 준비도 청구되면 포함한다.
4. **출력과 추론:** 화면에 표시한 token 수만 세지 않는다. 실제 청구 출력 bucket을 사용한다.
5. **중복:** cached input이 총 input에 이미 포함됐다면 두 번 더하지 않는다. 이미지와 음성의 별도 bucket도 provider 정의를 따른다.
6. **활동 이후 처리:** 5분 후 생긴 해당 활동의 청구도 포함한다. 30초 drain과 10초 idle 및 최종 usage 확인 규칙은 [QA05 §4](../qa05-model-cost.md#4-대표-활동-cost-20-v2-제안)를 따른다.
7. **기능 실패:** 필요한 응답을 생략한 실행은 저비용 성공으로 채점하지 않는다. usage 누락은 $0가 아니라 `INCOMPLETE_COST`다.

직렬화 payload와 tokenizer로 계산한 값은 `ESTIMATED_COST`이고 공식 요금의 참조 견적은 `REFERENCE_QUOTE`다. 실제 provider usage와 재시도 및 음성 청구가 있어야 실측이라고 부른다. 현재 조사에는 모델 실행과 비용 실측이 없다.

## 6. 채택하지 않은 근거와 이유

| 검토했던 방식 | 채택하지 않은 이유 |
| --- | --- |
| 월 $20 ÷ 20일 ÷ 40요청 | 구독료와 업무일 및 사용량이 제품 자료로 확인되지 않음. 일반 소비자 이용을 설명하지 못함 |
| 호출 1회 대 3회 | 입력 길이와 출력 및 음성 단가와 cache가 다르면 실제 비용의 대소가 뒤집힘 |
| 조회 요청의 비용만 집계 | 선행 생산과 원본 변경 및 미사용 상태의 비용이 누락됨 |
| 참조 API가 같은 기능을 성공한다고 전제 | 가격 문서는 정확도와 품질 달성을 검증하지 않음 |
| 500토큰을 화면 출력으로만 해석 | 청구 추론이 누락되어 총액을 낮게 산정할 수 있음 |
| 5분에 원장 강제 종료 | 늦게 실행된 응답과 취소 및 청구가 사라져 느린 후보에 유리함 |

## 7. 발표 페이지와 예상 질문에 사용할 내용

- **핵심 문장:** “같은 20요청 활동의 공개 API 견적이 $0.4631이므로 VIA 모델 원가의 제품 상한을 $0.47로 제안했습니다.”
- **작은 도식:** 음성 $0.25 + 텍스트 $0.13 + 출력 $0.0156 + 화면 $0.0675 → $0.4631 → $0.47.
- **측정 예시:** 각 활동의 준비 $0.02 + 요청 $0.10 + 음성 $0.20 + 갱신과 재시도 $0.02 = $0.34. 가상으로 5회 활동 모두 같다면 평균 $0.34로 현재 점수표의 3점이다. 단일 활동만으로 전체 점수를 정하지 않는다.
- **각주:** 2026-10-14 공개 단가와 COST-20-v2 견적 규격. 미실행 견적이며 실제 청구와 기능 달성 확인은 별도.

| 심사 질문 | 답변의 핵심 |
| --- | --- |
| 왜 하필 $0.47인가 | 같은 활동을 범용 음성과 의미 API로 구성한 견적 $0.4631의 센트 단위 상한이다 |
| 왜 20요청인가 | 기능 유형과 재사용 및 갱신을 담은 동일 비교 단위다. 고객의 일일 이용량으로 가정하지 않았다 |
| 참조 API와 성능이 같은가 | 아직 확인하지 않았다. 가격 기반 제품 원가 요구안이고 기능 동등성의 실측 증거가 아니다 |
| 준비 비용이 비싼 구조는 불리하지 않은가 | 초기 준비와 반복 재사용을 모두 같은 활동에서 포함한다. 무료 준비도 강제 전량 생산도 하지 않는다 |
| 6점의 절반 비용은 근거가 있는가 | 같은 예산으로 두 배의 활동을 처리한다는 원가 의미를 가진 점수 규칙이다. 외부 연구의 임계값은 아니다 |

점수와 DP 예상 및 반증 조건은 [QA05 §6~8](../qa05-model-cost.md#6-06점-구간--cost-v2-제안)를 따른다. 발표 편집 시 [아홉 QA 페이지 구성안](../slide-page-plan.md)을 함께 사용한다.
