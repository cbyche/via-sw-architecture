# QA05와 QA06의 공통 사용자 활동 20건

> **후속 평가 구성 정정:** QA별로 따로 정한 사례 수는 [공통 시나리오 구성 방안](./common-evaluation-population-plan.md)에 따라 통합할 초안이다. 20요청과 Agent 사건 6건은 독립 시나리오 26개가 아니다. 공통 N과 QA별 관측 건수 확정 전이며 기존 $0.71 견적은 이전 20요청 활동에만 적용된다.

> 2026-10-14 / `ACTIVITY-20-v3` / 평가 입력 제안 / 녹음과 화면 파일 및 정답 자료는 아직 제작하지 않음

QA05의 비용과 QA06의 RAM을 **어떤 일을 하는 동안 측정할지** 정의한다. 실제 고객의 하루 이용량이나 통계로 만든 활동이 아니다. 아래 요청과 자료를 두 비교안에 동일하게 제공한다. 특정 구조의 호출 수나 저장 방식을 강제하지 않는다.

## 1. 발표에 쓸 측정 조건

**화면 지칭 6건과 과거 조회 6건 및 업무 제어 4건과 직접 질의 4건을 수행하며 Agent 사건 6건을 함께 처리하는 활동을 5회 반복한다.**

20건 안에 정정 4건이 포함된다. Agent 사건은 질문 2건과 진행 2건 및 결과 2건이다. 비용은 5회 평균 총액을 쓰고 RAM은 시작부터 후속 처리 종료까지 5회 전체의 관측 최고량을 쓴다.

## 2. 사용자 요청과 확인할 내용

아래 발화는 제작할 입력의 내용 명세다. 임의의 대명사만 넣고 정답을 사후 결정하지 않는다. 화면과 과거 자료에 대상 ID와 범위 및 버전을 지정하고 정답을 만든 뒤 비교를 시작한다.

| 번호 | 종류 | 사용자 발화 예시 | 동일하게 준비할 근거와 기대 처리 |
| --- | --- | --- | --- |
| R01 | 화면 | “지금 선택한 표의 내용을 요약해 줘.” | 선택 범위가 있는 표를 식별 |
| R02 | 화면 | “여기 가리킨 그래프의 추세를 알려 줘.” | 클릭하지 않은 포인터 위치와 해당 그래프 식별 |
| R03 | 화면 | “동그라미 친 이 두 항목을 비교해 줘.” | 원으로 둘러싼 두 항목을 한 집합으로 식별 |
| R04 | 화면 정정 1 | “아니 왼쪽은 빼고 오른쪽 항목만 설명해 줘.” | R03의 대상 중 하나를 제거한 정정 채택 |
| R05 | 화면 | “페이지 넘기기 전에 봤던 표에서 단위가 뭐였어?” | 화면 전환 전의 표와 버전을 조회 |
| R06 | 화면 | “선택한 문단을 쉽게 풀어서 설명해 줘.” | 문서의 선택 범위 식별 |
| R07 | 과거 조회 | “아까 찾아본 호텔 이름을 다시 알려 줘.” | 앞서 조회한 호텔과 해당 대화 연결 |
| R08 | 과거 조회 | “그 호텔의 취소 조건도 다시 보여 줘.” | R07의 호텔과 앞서 제공한 취소 조건 연결 |
| R09 | 과거 정정 2 | “아니 마지막 호텔 말고 처음 봤던 호텔 말이야.” | R08의 호텔을 첫 호텔로 정정하고 기존 조건 조회 |
| R10 | 과거 조회 | “지난주 여행 계획에서 이동 시간이 가장 긴 날은 언제야?” | 초기 이력의 날짜별 이동 자료로 처음 묻는 관계 계산 |
| R11 | 과거 조회 | “이번 사진 정리에서 빠진 사진들은 어떤 조건 때문이야?” | 사진 정리 결과와 제외 조건을 처음 연결 |
| R12 | 과거 정정 3 | “아니 이번 정리 말고 지난번 정리 결과를 말한 거야.” | R11의 업무 버전을 바꾸어 제외 결과와 조건 연결 |
| R13 | 업무 시작 | “선택한 사진을 날짜별로 묶는 작업을 시작해 줘.” | 외부 Agent에 맡길 새 업무와 대화 연결 |
| R14 | 업무 조회 | “진행 중인 보고서 요약은 어디까지 됐어?” | 초기 진행 업무의 최신 상태 조회 |
| R15 | 업무 변경 | “여행 계획에서 첫 번째 숙소는 제외해 줘.” | 진행 중인 여행 계획의 제외 조건 변경 |
| R16 | 업무 정정 4 | “아니 첫 번째는 유지하고 두 번째 숙소를 제외해 줘.” | R15의 변경 범위를 정정하여 같은 업무로 전달 |
| R17 | 직접 질의 | “파일 압축을 하면 무엇이 달라지는지 알려 줘.” | 외부 실행 없이 설명 |
| R18 | 직접 질의 | “블루투스와 와이파이의 차이를 쉽게 설명해 줘.” | 외부 실행 없이 설명 |
| R19 | 직접 질의 | “사진의 해상도와 파일 크기는 어떻게 달라?” | 외부 실행 없이 설명 |
| R20 | 직접 질의 | “문서 확대와 글자 크기 변경의 차이를 알려 줘.” | 외부 실행 없이 설명 |

과거 조회는 기존 내용을 다시 묻는 R07~09와 새로운 관계를 묻는 R10~12로 나눈다. 화면 요청과 업무 요청은 업무용 문서뿐 아니라 개인 여행과 사진 이용을 포함한다.

## 3. 입력과 동시 사건

- 사용자 음성 입력 창은 5분이다. R01은 0초에 시작하고 이후 15초 간격으로 R20까지 입력한다. 각 입력 음성은 견적상 6초로 잡아 총 120초다. 녹음 제작 후 발화 내용을 줄이지 않고 이 규격을 만족할 수 있는지 먼저 검증한다.
- R04와 R12의 발화 종료 시각에 각각 서로 다른 초기 Task의 질문 1건과 진행 1건 및 결과 1건을 제공한다. 두 구간의 질문은 각각 보고서 형식 확인과 사진 보존 범위 확인이다. 진행은 자료 수집률과 분류 진행률이며 결과는 완료된 일정 정리와 문서 변환 결과다. Agent 사건의 실제 텍스트와 Task ID는 실행 자료에 고정한다.
- 질문 사건은 해당 Task의 답변 대기로 표시하는 데까지가 이 활동의 의무다. 질문에 대한 추가 사용자 답변을 20건 외부에 숨겨 넣지 않는다. 진행과 결과도 해당 Task 화면에 반영하고 음성 요약을 제공한다.
- 초기 200턴 이력과 완료 Task 20개 및 진행 Task 5개를 제공한다. 파생 요약과 관계 자료는 후보가 생성하며 그 비용과 RAM을 포함한다.
- R10 직전과 R13 직전에 원본 자료를 각각 한 번 변경한다. 변경 내용과 원본 버전을 양안에 동일하게 제공한다. R10은 날짜가 지정된 과거 기록을 찾아야 하므로 최신 자료로 덮어쓰면 실패다.
- 동시에 활성화할 Task는 최대 10개이며 클라우드 호출은 최대 4개다. 원본 화면은 2880×1800이며 보존 대상은 최대 15장이다. 압축과 필요한 부분 추출 및 공유 참조를 허용한다.
- 입력과 출력의 로컬 음성 자료 조건은 각각 48kHz와 16bit 및 mono이며 최대 60초 분량이다. API 전송 형식 변환이 필요하면 그 비용과 로컬 버퍼도 포함한다.

## 4. 응답과 관측 범위

20요청과 6개 사건 각각에 상세 텍스트와 음성 요약을 제공한다. 견적은 요약 26개를 각각 5초로 잡아 총 130초다. 실제 재생은 사용자 발화와 앞선 응답 때문에 뒤로 밀릴 수 있다. **5분이 됐다는 이유로 필요한 응답을 자르지 않는다.** 이 수치는 견적용 길이이며 고객 관측 평균이 아니다.

관측은 앱 시작과 파생 상태 준비 전부터 시작한다. **`t_last`는 R20의 실제 발화 종료 시각**이다. `t_last+30초`까지 후속 처리를 관측하고 `t_last+30~40초`에는 완료 여부와 완료 후 대기 상태를 추가로 확인한다. 모든 활동 유래 작업과 필요한 응답이 끝났으면 `t_last+40초`에 관측을 마친다. 그때까지 끝나지 않았다면 `t_last+40초`에 미완료 작업의 취소를 요청하고 정리 종료까지 계속 관측한다. **`t_last+120초`에도 정리가 끝나지 않으면 미완료**다. 필요한 응답이나 처리를 취소한 실행도 기능 미완료로 남기며 낮은 비용이나 RAM으로 합격시키지 않는다.

비용은 취소 전에 발생한 사용량을 보존하고 늦게 도착한 최종 청구도 원장에 추가한다. 늦은 청구 정산으로 실행의 미완료 판정을 성공으로 바꾸지 않는다. RAM은 정의한 관측 종료까지 수집하되 미완료 실행의 값을 완결된 활동의 합격 수치로 사용하지 않는다.

반복마다 같은 초기 원본으로 복원하고 5회 수행한다. 반복 내부에서는 생성한 캐시를 유지한다. 입력 파일과 정답 및 타임라인과 모델 견적용 직렬화 자료가 아직 없으므로 **실행 준비 완료나 측정 동결을 의미하지 않는다.** 자료를 제작한 후 내용과 길이를 확인하고 변경이 필요하면 A/B 결과를 보기 전에 규격과 견적을 함께 개정한다.
