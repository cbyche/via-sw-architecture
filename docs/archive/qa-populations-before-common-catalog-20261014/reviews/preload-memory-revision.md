# 삼성 기본 탑재 관점의 QA06 독립 검토

> 2026-10-14 / MEM-v2 당시 검토 기록 / 이후 사용자 지적으로 목표와 점수 철회 / Windows 실행 없음

최신 판단은 [RAM 최고량과 변경 목표 재검토](./ram-peak-and-change-target-review.md)를 따른다. 아래 검토는 산술과 문서 일치 확인에 치우쳐 목표 자체의 정당성을 충분히 확인하지 못했다.

## 검토 요청

사용자가 기존 32GiB 분할 근거를 거부하고 삼성 노트북 기본 탑재 앱의 관점에서 목표를 도출하도록 요청했다. 내부 허용량은 없다고 명시했다. 통합 작성자와 별개의 `review_preload_memory` 에이전트가 공식 근거의 범위와 새 목표의 논리 및 최종 문서 일치를 검토했다.

## 1차 검토와 반영

| 검토 의견 | 반영 |
| --- | --- |
| Microsoft 공개 자료에 모든 OEM 기본 탑재 앱에 동일한 GiB를 허용하는 기준은 확인되지 않음 | 공통 허용량처럼 쓰지 않고 제품별 목표와 설치 전후 영향 확인의 근거로 사용 |
| 원본 크기 산술만으로 나머지 UI와 실행 환경의 허용량이 입증되지는 않음 | 공식 삼성 해상도와 산술 및 작성자가 정한 내부 상한을 구분 |
| 확보량은 실제 RAM과 다르며 물리 RAM 합산도 공유와 페이지 이동의 문제가 있음 | 단일 확보량 지표 유지. 출하 장치의 실제 RAM과 업무 반응은 별도 확인 |
| 원본 복사 수를 A와 B에 강제하면 비교를 왜곡할 수 있음 | 용량 예산과 실제 할당을 구분하고 양안의 압축과 부분 추출 및 참조 공유 허용 |
| 화면 입력과 목표 변경은 비용 조건과 점수에도 영향을 줌 | MEM-v2로 버전을 남기고 QA05 공통 입력과 새 점수 및 예시를 함께 수정 |

## 최종 재검토

검토 대상은 QA06 상세 명세와 QA04 및 QA06 요구사항 표, 패키지 README, 03-03 중심 문서, QA05 공통 입력이다. 검토자는 삼성 공식 사양과 Microsoft PowerToys의 공개 수치도 다시 확인했다.

- 화면 `296.63MiB`와 음성 `10.99MiB` 및 `912 + 112 = 1,024MiB` 산술 확인
- MEM-v2 구간과 예시의 `900MiB → 1점` 일치 확인
- 15장과 동시 4개 및 클라우드 모델 조건의 문서 간 일치 확인
- 공식 자료와 자체 설계 예산의 구분 확인
- 확보량과 실제 RAM의 구분 및 제품 공존 확인의 한계 확인
- 남은 P1/P2는 발견하지 못함

경미한 문구 권고는 Microsoft 지침을 “요구”가 아닌 “권고”로 표현하는 것이었으며 상세 표에 반영했다.

## 검증 한계

이 검토는 1GiB가 Windows의 공식 허용량이거나 삼성에서 승인한 값이라는 증거가 아니다. 실제 VIA의 할당과 목표 달성 여부 및 제품 공존성과 DP 우열은 측정하지 않았다. 내부 상한은 구현하고 검증할 설계 제안이다.

당시 근거와 공식 출처는 [보관한 QA06](../../../../../archive/qa04-qa06-before-ram-peak-20261014/qa06-local-memory.md)에 보존한다.
