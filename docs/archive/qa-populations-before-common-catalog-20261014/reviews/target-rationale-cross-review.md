## 1. 검토 결론

**P1은 발견하지 않았다. P2 한 건을 발견했다.** QA06의 개별 메모리 참조값은 확인되지만 이를 통합한 공개 기능군이 약 0.5GB라는 표현은 원자료가 뒷받침하지 않는다. 512MiB 목표를 철회할 필요는 없으나 독립 참조 사례와 작성자가 선택한 제품 상한을 분리해야 한다.

QA02의 98.7%와 QA04의 실제 변경 1개 및 3개 그리고 QA05의 가격과 $0.4631 계산은 확인했다. 이들이 VIA의 성능 달성이나 사용자 만족을 증명하지 않는다는 한계도 상세안에 기록되어 있다. 아래 한계를 유지하는 조건에서 제품 요구 제안으로 제시할 수 있다. 정책 선택이 유일하게 필연적인 수치라는 뜻은 아니다.

## 2. P2 발견 원문

### XREV-01: 개별 메모리 사례를 통합 기능군의 공개 규모로 표현

- 심각도: **P2**
- 위치: [QA06](../qa06-local-memory.md) 도입부 / §1 목표 근거 / §5 외부 참조 연결 / §10, [목표 도출 요약](../target-rationale.md) §1 / §7, [발표 표](../quality-requirements-table.md)의 QA06 목표 근거
- 발견한 표현: `공개 자원 규모인 약 0.5GB`, `기성 음성 UI 기능군 수준인 약 0.5GB`, `공개 기능군이 약 0.5GB 규모`

**문제:** 원자료가 보고한 것은 Windows 명령 UI의 시작 피크, 소형 음성인식의 대략적인 실행 자원, TTS 엔진의 합성 중 자원이다. 서로 다른 프로그램과 환경 및 관측 범위를 함께 실행한 측정이 없다. 따라서 세 독립 사례를 근거로 통합 음성 UI 기능군이 약 0.5GB라고 표현하면 원자료에 존재하지 않는 비교 기준을 만든다. 뒤에 합산 실측이 아니라는 단서를 적어도 앞의 공개 규모 주장과 충돌한다.

**확인한 사실:** Command Palette의 171MB, Vosk의 약 300MB, Orca의 41MB는 각 원자료에서 확인했다. 그 값들을 더한 숫자는 동일 RAM 카운터의 동시 최고량도 아니며 VIA의 예상 사용량도 아니다. MB와 MiB 역시 그대로 교환할 수 없다.

**구체적인 수정안:** 목표 512MiB는 유지하고 근거 문장을 다음처럼 바꾼다.

> Windows 명령 UI의 시작 피크 171MB와 소형 음성 기능의 41~300MB 독립 사례를 참고해 기본 탑재 VIA의 제품 상한을 512MiB로 제안한다.

512MiB라는 정확한 값은 0.5GiB 단위의 제품 예산 선택임을 밝힌다. 세 참조에서 산출된 합계나 기성 통합 제품의 실측값 또는 Windows의 공통 할당 규정이라고 설명하지 않는다. 전체 VIA가 이 상한을 달성하는지와 다른 앱에 미치는 영향은 동일한 계측 범위에서 별도로 확인한다.

## 4. 발표에서 남겨야 하는 한계

### QA02

99%는 수동 선택 실험을 참조한 대상 지정 목표다. 연구가 VIA의 의미 해석에 동일 성공률을 요구하거나 사용자 만족을 증명한 것으로 설명하지 않는다. 20개 원본을 5회 반복한 100판정은 100개의 독립적인 실사용 상황이 아니다. 상세안의 100판정에서는 합격 점수가 1점과 6점만 나오는 해상도 한계를 숨기지 않는다.

### QA04

기존 VIA의 독립 수정 두 건은 실제 선례지만 일반 변경의 대표 표본은 아니다. 평균 3개는 그 국소성을 유지하려는 개발 요구이며 현재 C01~C06을 실행한 결과도 아니다. 발표 문장에서 단순히 기존 변경의 상단이라고만 쓰기보다는 확인한 두 독립 수정 중 큰 값이라고 범위를 남기는 편이 정확하다. 모듈 크기를 달리하여 숫자를 맞추지 않는 규칙도 유지해야 한다.

### QA05

$0.47은 공개 가격과 명시한 활동 규격으로 만든 미실행 참조 견적의 상한이다. 기성 API 구성이 VIA의 정확도와 기능을 같은 비용으로 실제 달성했다는 경쟁 실험이 아니다. 출력 500토큰에는 청구되는 추론량도 포함해야 하며 활동 자료가 그 규격을 충족하는지는 실행 전에 확인해야 한다. 이 범위가 남아 있는 한 원가 요구 제안으로 설명할 수 있지만 실증된 가격 경쟁력이라고 요약해서는 안 된다.

### QA06

512MiB는 기본 탑재 제품의 로컬 부담을 제한하려는 정책 제안이다. 자료가 정확히 512MiB를 요구하거나 삼성과 Windows가 해당 한도를 정했다고 설명하지 않는다. 현재 계측 정의는 전체 물리 RAM의 공유 중복과 그래픽 귀속을 포함하므로 private working set만으로 달성했다고 판정할 수 없다. 측정 방법과 제품 공존 실측이 남아 있다는 상태를 유지한다.
