# 독립 심사 리뷰와 보강 기록

2026-10-06. Senior SW Architect 심사위원 역할의 독립 sub-agent가 목표와 측정 정의를 읽고 검토했다. 구현, 품질 실측 또는 실제 심사위원의 평가 결과는 아니다.

| 지적 | 반영한 보강 | 확인 위치 |
| --- | --- | --- |
| 문장 분류 결과를 전체 요청 정확도에 전이 | NexusRaven의 검색 보조 도구 사용 95%를 참조 수준으로 선택. 다른 모집단과 장치의 성능 예측이라는 주장 제거 | 측정 설계 §3 |
| 시간 집계가 숨은 성공률 기준을 강화 | 산술평균 사용. 오답도 실제 endpoint 계측. 정확성과 시간 별도 판정 | §2.5, §6~7 |
| 실패를 무한대 시간으로 바꿈 | 실제 처리 및 관측 종료시간과 미전달 상태 기록. 미관측 endpoint의 충족 판정 보류 | §2.5 |
| 사용자 전체 대기와 VIA 처리시간 혼동 | 외부 대기만 있는 실제 구간을 제외. 중첩 구간 계산 예제 및 전체 wall time 별도 공개 | §7 |
| 긴 음성 출력만으로 시간 목표 초과 | 짧은 출력 계약과 긴 설명 조건을 시험 전에 구별. 긴 설명을 기능 평가에서 삭제하지 않음 | §2.3, §7 |
| 기능 회귀만으로 DP 효과를 식별 | 비교별 8개 구체 상황, 3개 조건, 4반복. 직접 품질 경로와 반증 조건, 회귀 경로 명시 | §13, evaluation-plan.json |
| 타 앱 RAM을 임의 예약 | VIA 자체 weights와 KV 및 runtime와 buffer의 예산 합계로 16GB 계산 | §9.1~2 |
| RAM과 VRAM을 같은 용량처럼 해석 | 고유 물리 bytes 합계와 장치별 capacity 구별. 예시 배치와 offload 및 반응시간 동시 검증 | §9.3 |
| background 상태와 loading 비용 누락 | 8시간 세션 3회, startup과 idle 및 반복, burst와 회수 구간. 임시 복제와 모든 helper 포함 | §9.4 |
| Module 크기에 따른 변경 count 편향 | 기존 C/I/S/D 책임 단위와 후보 대응표 적용. 큰 통합 Module도 독립 책임은 따로 셈 | §8 |
| count를 노력으로 곧바로 환산 | 실제 과제의 MH로 a+bN을 보정하고 조직 월 표준시간으로 MM 환산 | §8 |
| 실패와 조기 중단으로 개입 수가 낮아짐 | 동일 사용자 재요청과 수동 마무리 script, 미완료 포함, 완료 여부가 다른 pair 분리 | §4 |
| 단 한 번의 성공을 기능 지원으로 인정 | 구현 경로, 개별 capability 계약 시험과 다섯 구체 상황 witness 요구 | §5 |
| 안전 보류와 정상 복구 혼동 | RECOVERED와 DEGRADED/PENDING 구분. 입력과 상태 및 다음 처리 probe로 정상 복구 확인 | §10 |
| trace 존재를 분석 용이성으로 주장 | 독립 분석자의 동일 5분 세션에서 다섯 처리 경위 질문을 oracle과 대조 | §11 |
| 삭제 후 로그가 원문 재구성을 요구 | 삭제 후 분석은 ID와 epoch 및 차단 경위만 확인. 삭제한 원문 복원 금지 | §11 |
| 0건 목표의 시험 내용 불명확 | 금지 144회와 허용 144회, 12개 상황, prompt injection과 race, 실제 접근 계측 | §12 |
| 추가 질문으로 응답 평균 희석 | 사전 고정 event ledger 사용. 후보가 만든 추가 질문과 retry는 진단만 기록 | §6 |
| 올바른 오류 안내까지 정확성 실패로 분류 | 안내의 시간은 실제 값, 정확성은 정답 manifest에 따라 별도 판정 | §2.5 |
| 45의 순수 B와 B+ 혼동 | 지원 관계 미게시 범위의 backfill만 순수 B. schema 미지원과 source fan-out B+는 별도 | §13, DP45-S03 |

재검토에서 새 P1은 없었고 마지막 두 P2가 보고되었다. 위의 오류 안내와 순수 B 경계를 수정한 뒤 독립 검토자가 현재 파일을 다시 읽어 두 건의 해결을 확인했다. **독립 문서 검토 범위에서 미해결 P1/P2는 없다고 회신했다.** 이는 목표 달성 또는 실행 가능성을 검증한 결과가 아니다.

심사 답변에서 지켜야 할 경계는 다음과 같다. 95%는 외부 구현의 공개 결과를 참조한 연구 목표이며 VIA 실적은 직접 시험해야 한다. 16GB는 전체 비용을 배정한 설계 예산이며 선정 모델의 실제 inventory와 장치 배치로 검증해야 한다. 1초와 10초는 사용자 반응 기준을 참고한 평균 시간 예산이다. 구체 모델 hash와 exact fixture가 아직 미정이므로 이 문서를 이미 실행한 benchmark 또는 동결된 계약으로 설명하지 않는다.
