## 1. 판단 요약

**VIA는 현재 발화의 의미를 정하기 위해 최근 대화, 실제 전달 범위, 화면 관측과 과거 업무 결과를 함께 사용한다. 이 자료에서 모델이 읽을 근거를 언제, 어떤 수명의 상태로 만드는가가 문제다.** 관련 UC는 01~07, 10~11, 14~15, 17~18이다.

이번에는 기존 A/B 외에 **출처가 있는 기억을 미리 생산하고 게시하는 C**를 명시적인 탐색안으로 남긴다.

| 안 | 지속해서 유지하는 주된 파생물 | 요청이 들어왔을 때 기본 경로 | 정상 사용에서 선택할 이유 |
| --- | --- | --- | --- |
| **E-A 대화 작업 문맥 유지** | 대화별 rolling view | 최근 관측을 더해 바로 의미 판단. 부족하면 원본 조회 | 같은 주제가 이어지고 이미 읽은 근거를 반복 사용하는 대화 |
| **E-B 요청별 원본 근거 구성** | 원본 index, 최근 anchor와 범위별 cache | 최소 문맥에서 판단하고 필요한 원본을 읽어 요청별 view 구성 | 주제가 자주 바뀌며 실제 읽을 범위는 작은 사용 |
| **E-C 출처 있는 기억 게시와 회상** | 원본에서 가공한 재사용 기억 및 출처 관계 | 최근 anchor와 관련 기억을 회상하고 부족한 부분은 원본 확장 | 긴 이력의 여러 대화에서 같은 사실과 결과를 반복 사용 |

세 안은 구현을 전혀 공유하지 않는 제품 분류가 아니다. 기본 공급 경로와 지속 파생 상태가 다른 구조다. E-A에 E-C를 조합할 수도 있다. 그 혼합의 추가 비용도 보존하며 대안 수를 맞추기 위해 제거하지 않는다.

**권고:** 세 구조와 혼합을 비교 후보로 유지하되, E-A 대 E-B는 저비용 cache / pinning으로 차이가 줄어드는지 우선 검토한다. E-C는 기존 DP-45의 기억 생산 문제와 직접 연결되므로 별도 새 DP로 중복 등록하지 않는다. QA01/03/05의 손익은 설명할 수 있으나 QA02의 최종 정확도 차이와 QA04의 독립적인 이익은 아직 확인되지 않았다.

## 2. 같은 일을 수행하는 조건

모든 안은 같은 원본과 권한, 모델, 동시 실행 예산으로 시작한다. 근거가 충분한 쉬운 입력을 일부러 검색하게 만들지 않는다. 현재 선택, 최근 원문, 채택된 대상과 조건의 작은 상태는 공통으로 유지할 수 있다.

| 정보 | 공통 권위와 사용 규칙 |
| --- | --- |
| 사용자 입력과 시점별 화면 관측 | Interaction Manager가 확보한 범위와 누락을 보존. 마지막 화면으로 지난 관측을 대체하지 않음 |
| 현재 요청과 업무 조건 | Request Controller가 채택한 revision 및 Task Manager의 확인된 업무 상태. 요약이 이를 덮어쓰지 않음 |
| 실제 사용자 전달 | Response Manager의 표시와 실제 음성 전달 범위. 생성 예정 문장은 전달 사실이 아님 |
| 원본 결과와 첨부 | Agent Gateway가 관측한 결과와 접근 가능한 자료. native revision이 없으면 관측 복사본의 로컬 식별자를 구별하고 native revision을 만들지 않음 |
| 파생 view / 기억 / index | Context Manager가 생산하고 원본, revision, 범위와 의존 관계를 유지. 확정된 업무 상태의 권위가 아님 |
| User Memory | 사용자가 허용한 지속 선호와 사실. 현재 대화의 일시적 조건이나 Agent의 주장과 구별 |

Request Interpreter는 근거로 지칭과 Task 연관성을 제안하고 Request Controller가 현재 revision에 채택한다. 정답 Task를 미리 지정하지 않는다. 구체적인 처리 의도가 확정되면 상세 자료 읽기나 Agent 접수 전에 첫 내용을 표시할 수 있다. 단순 접수 문장은 첫 응답 완료가 아니다.

### 공통 기록과 파생 상태의 흐름

`입력 / 전달 / 업무 사건 → 각 소유자의 원본 기록 → 근거 공급 구조 → Request Interpreter → 현재 revision 채택 → 실제 표시`

각 소유자는 자신이 관측한 사실만 기록한다. 이 비교는 원본 사건의 기록 여부를 선택하는 비교가 아니다. 외부 업무 계획이나 범용 탐색을 VIA에 추가하지 않고 현재 요청 이해를 위한 bounded read / search를 다룬다.

## 4. 세 안의 구체 구조

### E-A. 대화별 작업 문맥을 계속 유지

1. Context Manager는 새 사용자 원문, 최근 채택 상태와 실제 전달 anchor를 대화 view에 반영한다. 큰 자료는 출처 있는 참조와 필요한 구절만 남긴다.
2. Request Interpreter는 그 view와 현재 관측으로 판단한다. 충분하면 추가 읽기 없이 채택 제안을 반환한다.
3. 부족하면 원본을 읽고 판단을 이어 간다. 조회 결과를 다음 입력에서도 쓸 수 있게 view에 유지한다.
4. token 예산을 넘으면 조건부 condensation한다. 안정 prefix cache, 최근 원문 pinning과 부분 갱신을 허용한다.

**상태 수명:** view는 대화 수명, 원본과 채택 조건은 각 보존 정책, 읽기 cache는 원본 revision 및 권한 유효기간에 따른다. 대화가 바뀌어도 원본을 조회할 수 있지만 모든 view를 자동 합치지는 않는다.

**정정과 실패:** 정정된 source / 조건을 참조하는 view 조각을 무효화하고 필요한 범위만 재생산한다. condensation 실패 시 유효한 bounded view와 원본 조회로 진행한다. 낡은 요약을 최신 조건으로 쓰는 fallback은 허용하지 않는다.

**이익과 비용:** 이미 들어 있는 복합 근거를 쓰는 후속 질문에서 왕복을 줄인다. 반대로 관련 없는 과거를 반복 입력하고, 아직 쓰지 않을 view를 갱신하거나 요약할 수 있다. view를 유지한다는 이유만으로 local RAM에 전체 이력을 상주시킬 필요는 없다.

### E-B. 현재 요청에 필요한 원본에서 문맥 구성

1. 최근 대화, 현재 선택과 채택 anchor의 공통 최소 문맥으로 판단한다.
2. 필요한 근거가 없으면 Request Interpreter가 현재 요청에 맞춰 범위 조회를 선택한다. Context Manager는 원본의 권한과 revision을 확인해 반환한다.
3. 여러 독립 자료는 같은 예산 안에서 병렬로 읽는다. 반환 자료를 요청별 임시 view에서 결합하고 추가 읽기를 제한한다.
4. 채택 후 원본 cache와 유효한 채택 상태는 남기고 탐색 중간 문맥은 종료한다. 반복 질의는 cache hit를 허용한다.

**상태 수명:** 요청별 view는 해당 revision의 판단 또는 폐기까지다. index와 cache는 별도 수명이다. 의미 검색을 위해 embedding을 생산한다면 준비 비용도 포함한다.

**정정과 실패:** 정정은 관련 요청 view와 source cache를 무효화한다. 원본 일부가 읽히지 않으면 ‘해당 자료가 없다’와 ‘지금 읽을 수 없다’를 구별한다. 이미 충분한 근거가 있으면 유효 범위에서 답하고, 필수 근거가 없으면 보완을 요청한다.

**이익과 비용:** 오래된 여러 주제 중 작은 범위를 읽는 요청에서 입력량을 제한한다. 어떤 자료가 필요한지 판단한 뒤 조회해야 하면 모델 → 조회 → 모델 대기가 생긴다. 최초 질의가 잘못되면 원본이 있어도 놓칠 수 있다.

### E-C. 출처 있는 기억을 먼저 생산하고 회상

1. Context Manager 내부의 기억 생산 역할이 새 업무 결과, 실제 전달 범위와 채택된 사용자 수정을 읽는다. 범위가 제한된 후보 기억을 만든다.
2. 후보에는 원본과 의존 revision을 붙인다. 현재 조건과 출처를 검사한 뒤 기억 저장소에 게시한다. 원본 전체를 덮어쓰지 않는다.
3. 새 요청은 최근 원문과 anchor에서 시작하고 관련 기억을 조회한다. 현재 요청과 맞는지 확인한 뒤 원본의 필요한 구절 / 관측으로 확장할 수 있다.
4. 충분한 후보가 없으면 E-B와 같은 원본 읽기로 진행한다. 별도 recall worker를 선택했다면 query 구성, 회상, 반환 가공과 주 해석기의 재판단을 모두 센다.

**상태 수명:** 기억은 특정 대화 view와 별개로 여러 대화와 요청에서 재사용한다. 임시 업무 기억과 허용 User Memory는 다른 종류다. source별 계보와 게시 generation을 지속해서 관리한다.

**정정과 실패:** 오래된 생산 작업이 늦게 끝나면 source revision과 admission generation을 다시 확인해 게시를 막는다. 일부 원본이 철회된 혼합 기억은 영향 구절을 분리할 근거가 있으면 부분 재생산하고, 없으면 해당 기억을 사용 보류한다. 생산 실패를 원래 업무 실패로 바꾸지 않고 원본 fallback을 남긴다.

**이익과 비용:** 과거 자료 여러 개에서 반복해서 필요한 의미를 읽어야 할 때 매번 같은 조합을 줄일 수 있다. 아직 쓰지 않을 기억의 생성과 embedding, 갱신, 삭제 및 계보 저장 비용이 든다. 요약의 잘못된 일반화나 누락 때문에 원본 재확인이 늘면 이익이 줄어든다.

| **EX08 이동 지칭:** 차트 A 다음 B를 가리키고 빈 곳 이동 후 전사 | 발화 구간 관측을 view에 넣어 해석 | 같은 관측을 공통 기본 입력 또는 제한 읽기로 취득 | 최근 관측을 그대로 사용. 기억 생산을 기다리지 않음 | 관측 기본 공급을 허용하면 공급 구조 차이가 작음. 관측 자체의 결합은 문제 3 |
| **EX09 부분 정정:** T1/T2 보존과 P2 수정에서 T2만 T3로 변경 | 관련 view 조각 무효화, P2 유지 | 현재 채택 상태와 새 근거로 해당 부분 판단 | 해당 조건 기억과 의존 기억을 수정하고 필요하면 원본 판단 | E-C의 수정 전파가 추가. E-A/B도 stale cache 차단 필요 |
| **EX10 모호 / 누락:** 두 대상 가능 또는 관측 일부 누락 | view의 불확실성과 부족 범위 보존 | 검색 확대 또는 질문 | 경쟁 기억 / unknown과 원본 확장 또는 질문 | 원본에도 없는 의도를 만들어내지 않음. 불필요한 질문을 정확도 성공으로 세지 않음 |
| **EX16 자료 철회:** 과거 결과 일부 사용 철회 | view와 cache에서 관련 부분 사용 차단 | 조회 admission 차단, cache 제거 | 기억의 source 계보를 따라 사용 차단 및 재생산 | 파생 상태가 많을수록 무효화 부담. 세 안 모두 철회 적용이 기능 조건 |
| **EX17 재접속:** 원본 revision 변경, 이전 cache 잔존 | 복구 view의 의존 revision 대조 | 필요한 범위의 cache validity 재확인 | 게시된 기억 generation과 원본 변경 대조 | 저장돼 있다는 사실을 현재 유효성으로 해석하지 않음 |

### EX03에서 첫 응답의 실제 경계

1. ‘들려준 부분’이라는 지칭에서 실제 음성 A를 채택해야 한다.
2. A가 확인되면 ‘앞서 들려드린 첫 부분을 다시 보여드릴게요’처럼 구체적인 처리 의도를 표시할 수 있다.
3. 상세 본문 재구성과 음성 준비는 이후에도 이어질 수 있다. 그 비용은 QA03에 남고 첫 표시 이후의 비용을 QA01에 다시 넣지 않는다.
4. 다음 ‘화면의 두 번째 항목’은 B를 새로 채택한다. 이전 A의 anchor만 반복 사용하면 실패다.

따라서 입력량이 작다는 이유로 자동 QA01 이익을 부여할 수 없다. 채택을 위한 근거가 이미 공통 anchor에 있다면 세 안의 첫 응답은 같고 상세 준비에서만 차이가 생긴다.

## 8. 반증 조건과 다음 DP 판단

- **E-A의 정상 사용 이익 반증:** 관련 대화가 계속돼도 유효 view를 준비하는 비용이 원본 / cache 조회 절약보다 크거나, 최소 anchor만으로 충분해서 왕복 차이가 없다.
- **E-B의 입력 / 비용 이익 반증:** 필요한 자료를 찾는 판단과 반복 조회가 많아 E-A의 bounded view보다 전체 입력과 호출이 늘어난다.
- **E-C의 재사용 이익 반증:** 게시된 기억의 hit가 낮거나 원본 확인이 대부분 필요하고, 정정과 미사용 생산 비용이 반복 결합 절약을 넘는다.
- **정확도 차이 가설 반증:** 원본 확장과 동일 관측을 허용하자 채택 대상 집합이 대부분 같아진다. 정확도라는 이름으로 검색 중간 품질만 비교하지 않는다.

이 후보는 ‘문맥을 더 많이 주면 정확하다’라는 일반 주장에서 벗어나 VIA의 실제 전달 범위와 긴 업무 이력을 다룬다. 그래도 현재 확인한 정상 사용 손익은 주로 지연과 비용이다. QA04를 추가 우위로 제조하거나 문제 4의 인계 정확도를 QA02에 넣어 주요 DP 요건을 맞추지 않는다. 문제 4와 공통 생산물을 공유한다면 하나의 DP에서 서로 다른 사용 장면으로 비교하거나, 같은 비용을 한 번만 세는 결합 비교가 필요하다.
