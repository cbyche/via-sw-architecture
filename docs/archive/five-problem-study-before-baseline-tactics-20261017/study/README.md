# 다섯 VIA 설계 문제의 심화 조사 결과

2026-10-16 / 사용자 승인에 따른 조사 / 구조 비교와 DP 후보 권고 / 미선정, 미측정

## 1. 결론

**다섯 문제 모두에서 실제 구현을 바탕으로 비교할 구조를 도출했다. 그중 동시 사건 처리와 화면 지칭은 우선 심화할 후보이며, Agent 간 업무 기억 / 인계는 VIA의 제품 가치를 설명하는 중요한 추가 후보다.** 근거 공급은 기존 DP-45와 중복을 정리해야 하고, Agent 선택은 필수 기능이지만 현재 비교안의 주요 DP 자격은 더 약하다.

이 판단은 작성자의 권고다. 기존 DP-44/45/47/42의 교체, 새 DP 번호 부여, core QA와 A/B 승자를 결정하지 않았다. reference Architecture도 변경하지 않았다.

| VIA 문제 | 실제로 남긴 구조와 혼합안 | 가장 분명한 trade-off 가설 | DP에 대한 권고 |
| --- | --- | --- | --- |
| **1. 현재 요청의 근거 공급** | E-A 대화 작업 문맥 유지 / E-B 요청별 원본 조회 / E-C 출처 있는 기억의 사전 생산과 회상 | 이미 준비된 근거의 빠른 재사용과 미사용 생산 / 반복 입력 비용. 원본 조회는 필요한 범위를 줄이지만 조회 왕복과 검색 누락 가능 | 세 방향을 보존. E-A/B의 작은 cache 보완과 기존45와의 중복부터 검토 |
| **2. 정정, 새 질문과 Agent 사건 처리** | A 현재 대화 해석 실행에 합류 / B 요청별 지속 해석 실행과 대화 채택 분리 / C A에 제한된 별도 질문 경로 | 현재 잠정 문맥 재사용과 실행 경계 대기 대 독립 질문 반응성과 추가 문맥 / 합류 / 폐기 비용 | **우선 심화.** C까지 허용한 강한 A와 B 비교. 단순 event bus 대 Stage 연결보다 실제 사용자 대기를 직접 다룸 |
| **3. 발화 중 화면 지칭** | A 원음 / 전사와 화면 원본 공동 해석 / B 생산자 소유 부분 후보의 교환과 결합. 증분 갱신은 양쪽에 조합 | 원본 공동 단서 사용과 입력량 대 후보 재사용과 생산 / 확장 왕복. 정확도 우위는 강한 확장 후 미확인 | **우선 심화.** 기존47과 같은 문제 / 생산 축이므로 새 DP로 중복 등록하지 않음 |
| **4. Agent가 바뀌어도 이어지는 업무** | H-A 위임 시 인계 묶음 / H-B 계속 갱신하는 공통 업무 기록 / H-C 필수 manifest와 수신자의 범위 읽기 | 필요할 때만 가공하는 비용 대 반복 인계의 준비 이익. 수신자 읽기는 VIA의 선행 가공을 줄이지만 지원 계약과 실행 중 왕복 필요 | **추가 핵심 후보로 유지.** 가공 시점과 push / pull은 두 축. 문제1과 같은 producer라면 하나의 선택으로 통합 |
| **5. 적합한 Agent 선택과 전환** | A 요청 판단과 선택을 결합 / B 요청 계약을 받아 별도 선택. 후보 필터와 worker handoff 제안은 공통 보완 | 요청 맥락을 그대로 사용하는 이익 대 선택 전용 정보 / 상태의 분리. 별도 왕복과 계약 누락 / stale 선택 비용 | 필수 설계와 신규 QA 후보 유지. **현재 두 안만으로 주요 DP 승격은 보류** |

‘차이가 있을 수 있다’와 ‘course의 3~4개 QA에서 실질적 trade-off가 확보됐다’는 다른 판단이다. 지금 네 개 DP의 조건을 모두 충족했다고 보고할 근거는 없다. 다만 부족한 원인을 각 안의 정상 / 반복 / 정정 경로까지 좁혔다.

## 2. 이번에 수행한 조사

- 공통 기능과 QA 경계를 먼저 정하고 **17개 EX 장면 및 문제별 변형**에서 같은 입력과 완료 조건을 비교했다. 쉬운 입력, 반복 / cache hit, 독립 질문, 부분 정정, Agent 교체, 자료 만료와 실행 불명 상태를 포함했다. 기존 COMMON-28이나 점수표는 변경하지 않았다.
- 보조 Agent 세 명은 문제 1/4, 문제 2, 문제 3을 나누고 주 담당자는 문제 5와 QA 통합을 맡았다. 초안 이후 담당을 바꾸어 교차 검토했다. 상세 기록과 확인 범위는 [리뷰 종합](reviews/README.md)에 남긴다.
- OpenClaw, OpenHands, LangChain Deep Agents, AutoGen Magentic-One, CrewAI의 공식 소스에서 입력, 호출 경계, 상태와 수명, 수정 / 실패 경로를 확인했다. 화면 지칭은 인접한 실제 시스템으로 조사 범위를 넓혔다. [소스 원장](../../../../../references/five-problem-study/README.md).
- 구현 사실, VIA에 필요한 추가 설계와 품질 가설을 구별했다. harness 설치 / 실행, 모델 호출, 성능 측정이나 수치 예측은 수행하지 않았다.

## 3. 세 가지 중요한 수정

### 3.1 같은 제품에서도 여러 구조를 가져올 수 있다

Deep Agents는 원본 offload뿐 아니라 별도 thread / run과 도구 없는 side 질문도 제공한다. OpenHands는 유지 문맥뿐 아니라 child conversation 재사용과 실행 교체 경로를 제공한다. 따라서 ‘OpenHands 대 Deep Agents’를 대안 이름으로 두지 않고 **VIA에서 근거, 실행 또는 인계가 어떻게 달라지는지**로 이름을 붙였다. 세부 근거는 각 문제와 소스 원장에 연결했다.

### 3.2 조합 가능한 선택을 억지로 A/B/C로 만들지 않는다

- 문제 2의 steer / interrupt / followup은 A/B 내부에서도 선택할 수 있는 정책이다. C는 A의 실용적인 보완이므로 B의 상대 안에 허용한다.
- 문제 3의 증분 가설 추가 / 철회 / 확정은 A/B 모두에 붙는다. 새 C를 발견했다고 부풀리지 않는다.
- 문제 4의 가공 시점과 수신자 pull은 별도 축이다. H-A/B + 제한 pull 같은 구성을 남긴다.
- 문제 5의 적격 후보 필터와 현재 Agent의 다음 후보 제안은 A/B의 공통 입력이 될 수 있다.

### 3.3 VIA가 기억한다는 약속을 구체적인 계약으로 바꾼다

VIA가 보존할 것은 실제 관측한 목표와 수정, 위임 입력, 확인된 진행과 결과, 사용자가 채택한 내용, 실제 전달 범위, 접근 가능한 원본과 revision이다. 이를 새로운 Agent에 전달해야 사용자가 같은 설명을 반복하지 않는다. **외부 Agent의 비공개 memory와 실행 중 내부 상태를 자동 이전하는 것은 이 약속에 포함하지 않는다.**

업무별 ‘최고 Agent’를 고르려면 기능 선언 외에 선택 목적과 독립 품질 근거가 필요하다. card의 기능 선언과 취소 / 상태 확인 같은 프로토콜 계약은 그 기반이지만, 성능 우열의 증거는 아니다. 관련 공식 명세의 범위는 [A2A 1.0.0](https://a2a-protocol.org/v1.0.0/specification/)에서 확인했다.

## 4. QA에서 새로 드러난 빈칸

[QA 후보와 적용 범위](06-qa-candidates-and-coverage.md)에 고정된 관찰 경계를 제안했다.

| 신규 후보 | 같은 뜻으로 평가할 것 | 주 관련 문제 |
| --- | --- | --- |
| **N-S Downstream Agent 선택 정확도** | 채택한 Agent 또는 정당한 보류가 독립 근거로 정한 허용 집합에 속하는가 | 5. 현재 두 DP의 실제 차이를 확보한 것은 아님 |
| **N-H 업무 인계 정확도** | 외부 위임 시 확정한 계약에 유효 목표 / 조건 / 근거 / revision / 실행 범위가 빠짐없이 보존되는가 | 4와 2의 위임 정정. 1/3은 최종 인계까지 오류가 남을 때 조건부 |
| **N-R 요청 관계 연결 정확도** | 최초로 채택한 새 요청 / 정정 / 질문 답변 / 취소 관계가 맞는가 | 2. 1/3의 근거와 부분 정정도 조건부 |

세 후보는 서로 다른 실패를 다룬다. Agent를 맞게 골라도 조건을 잘못 넘길 수 있고, 자료 대상을 맞혀도 답을 다른 Task 질문에 연결할 수 있다. 기존 QA02 지칭 정확도에 이 실패를 모두 넣지 않았다. 다만 같은 오류가 여러 지표에 남을 수 있어 합산 점수나 독립 이익으로 포장하지 않는다. 신규 후보의 core 채택, 목표와 점수는 미정이다.

기존 QA에서는 다음 한계가 특히 중요하다.

- **QA01:** 문제 4/5의 인계 / 선택 처리가 첫 구체적 의도 표시 뒤에 가능하면 첫 응답 차이는 작거나 없다.
- **QA02:** 문제 1/3 모두 강한 원본 확장을 허용하면 최종 정확도는 동점일 수 있다. 중간 검색 / 후보 손실을 최종 오류로 자동 계산하지 않는다.
- **QA04:** 공통 adapter와 안정 계약이 변화 파급을 흡수하면 동점이다. 상자가 나뉜다는 이유로 적은 Rust 모듈 변경을 주장하지 않는다.
- **QA05:** 미사용 기억과 후보 생산, 재시도와 폐기도 포함한다. 수신 Agent가 원본을 읽는 구조의 비용 이동을 전체 업무 비용 절약이라고 하지 않는다.

## 5. 문제 사이의 중복을 다루는 방법

| 연결 | 구별되는 책임 | 통합 또는 분리 판단 |
| --- | --- | --- |
| 1 ↔ 4 | VIA 해석 입력 대 외부 업무 인계 입력 | 독립 조합 가능. 동일 기억 producer의 생성 / 갱신 정책만 비교한다면 한 DP의 여러 사용 장면으로 통합 |
| 2 ↔ 3 | 어느 해석 실행이 새 입력을 다루는가 대 그 실행이 어떤 원본 / 후보로 지칭을 판단하는가 | 실행 정책을 고정한 뒤 의미 생산 구조를 비교. 증분 효과를 양쪽의 별도 우위로 중복 계산하지 않음 |
| 4 ↔ 5 | 무엇을 넘기는가 대 누구에게 맡기는가 | 같은 장면으로 검토하되 선택과 인계의 관찰 경계를 유지. H-C의 read 지원 여부는 적격성 입력 |
| 기존42 ↔ 2/4/5 | 서비스 / 상태 수명 경계 대 실행 문맥, 인계와 선택 메커니즘 | 이번 조사로42를 자동 대체 / 강등하지 않음. 다른 서비스가 있다는 이유만으로 이번 메커니즘이 성립하지 않음 |

## 6. 다음 공동 검토에서 결정할 내용

작성자 권고는 **문제 2와3을 우선 비교 대상으로 상세화하고, 문제 4를 새 주요 후보로 검토하며, 문제 1과4의 중복을 정리하는 것**이다. 문제 5는 실제 연결할 Agent의 capability와 선택 목적을 더 구체화한 뒤 별도 선택 실행의 이익이 남는지 판단한다.

다음 산출물은 제품별 요약을 더 늘리는 것보다 각 후보의 **강한 보완 뒤에도 남는 실행 의존과 실패 경로, 조건별 유리한 안, 정확한 QA 관찰 지점**을 압축한 비교안이어야 한다. 지금 확보한 근거로도 문서상 설계 비교는 가능하다. 실제 정확도 / 지연 / 비용 우열을 확인하려면 이후 별도 승인된 구현과 평가가 필요하다.
