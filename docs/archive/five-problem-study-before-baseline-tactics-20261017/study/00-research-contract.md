# 다섯 VIA 문제의 공동 조사 기준

2026-10-16 / 사용자 승인에 따른 병렬 조사 시작 / 설계 탐색 문서

## 1. 목적과 범위

사용자가 승인한 탐색은 QA와 VIA 사용 장면에서 중요한 기능 설계 문제를 찾고, 실제 Agent harness의 메커니즘으로 복수의 강한 대안을 구성하는 것이다. 아래 다섯 문제를 한 조사 주기에서 다룬다. 문제 번호는 탐색 식별자이며 DP 번호가 아니다.

1. 현재 요청을 이해하는 데 필요한 근거 공급
2. 정정, 새 질문과 Agent 사건의 동시 처리
3. 발화 중 바뀌는 화면과 지칭의 보존 및 결합
4. Agent가 바뀌어도 이어지는 업무 기억과 인계
5. 적절한 Downstream Agent의 선택과 전환

대안 수는 제한하지 않는다. 구현 근거, 실제 다른 처리와 상태, 선택할 조건과 비용이 남는 대안과 혼합안을 보존한다. 조합 가능한 선택 축을 독립적인 경쟁안처럼 취급하지 않는다. 이 조사에서 구현, 모델 호출, 측정 freeze, 성능 측정, 기존 DP의 교체나 최종 A/B 선정, commit/push는 수행하지 않는다.

## 2. 공통 기능 및 품질 계약

공식 출발점은 [현재 QA 논의](../../03-03-qa-dp-evaluation-plan.md), [고정 기능](../../../../03-fixed-architecture-scope.md), [대표 UC](../../../../05-representative-use-cases.md), [공통 실행 계약](../../04-40-common-execution-contract.md)이다. 기존 target는 검토한 reference Architecture이며 모든 대안의 정답 구조가 아니다. 기존 source와 설계를 그대로 요약하는 것으로 탐색을 끝내지 않는다.

- VIA는 대화와 화면 interaction, bounded read / search / understand, 요청 해석과 채택, 위임과 결과 재연결을 소유한다. 업무 내부 계획, domain reasoning과 외부 Action은 Downstream Agent 책임이다.
- 현재 비교 캠페인의 로컬 VIA와 cloud 음성 / 의미 모델 조건을 사용한다. 각 비교 안에서는 모델과 사용 가능한 원본, 권한과 자원 예산을 동일하게 둔다. 모델 차이를 구조 우위로 바꾸지 않는다.
- 원본 사건, 현재 업무 조건, 파생 요약 / index, 사용자가 명시적으로 허용한 User Memory를 구별한다. 외부 Agent의 비공개 내부 추론이나 내부 memory를 자동 수집할 수 있다고 전제하지 않는다.
- 최종 의미 채택, 입력 revision, 실제 표시 / 음성 전달 사실과 업무 실행의 확인 사실을 구별한다. Task 연관성은 해석의 출력이며 정답 ID를 사전 제공하지 않는다.
- 양안 모두 cache, bounded read, 병렬 읽기, 부분 갱신과 적법한 fallback을 사용할 수 있다. 쉬운 정상 입력과 cache hit도 비교 장면에 포함한다.
- [ADR-001](../../../../../../docs/adr/ADR-001-agent-integration-contract-boundary.md)의 integration edge 정규화와 미지원 기능의 명시 원칙을 보존한다. 내부 API 추상화만 바꾸는 제안을 새 주요 DP로 만들지 않는다.

| QA | 같은 뜻으로 유지할 경계 |
| --- | --- |
| QA01 첫 응답 | 첫 완결된 내용의 실제 Request/Task UI 표시. 구체적인 채택 의도는 위임 전에 표시 가능. 오답도 실제 시간 보존, 미응답은 임의 벌점 시간으로 대체하지 않음 |
| QA02 지칭 대상 정확도 | 지정 표현과 revision에 대해 채택한 대상 집합의 완전 일치. routing / 이력 일관성 / 인계 정확도와 혼합하지 않음 |
| QA03 VIA 처리시간 | 외부 업무, 사용자 발화와 대기를 제거한 실제 인과 경로. VIA 모델 / 검색 / 조정과 상세 표시 및 전체 음성 요약 준비 포함 |
| QA04 변경 범위 | 같은 관련 변경 요구를 완료하는 실제 운영 Rust 모듈 수. 소스가 없는 현 단계에는 영향 경로만 예측하고 숫자를 만들지 않음 |
| QA05 모델 비용 | COMMON-28의 전체 VIA 음성 / 의미 비용 단위를 보존. 준비, 미사용 생산, 재시도, 폐기와 tail 포함. 외부 Agent 내부 모델 / tool 비용 별도 |
| QA06 최대 RAM | 사용자 지정 512 MB 요구를 유지. 로컬 상태 / buffer / worker의 기여를 구별하고 cloud 메모리를 로컬 RAM으로 세지 않음 |

QA07~09는 사용자 평가대로 이번 핵심 후보 탐색에서 우선도가 낮다. 기존 정의와 필수 기능 검증은 보존한다. 새로운 QA 후보는 문제와 대안에서 도출할 수 있다. 지표 의미와 판정 근거, 여러 DP에 적용할 경로를 제안하고 신규 목표 / 점수 / 번호를 확정하지 않는다. 특히 Downstream Agent 선택 정확도는 capability 충족과 실제 업무 적합성, 복수 적합 후보와 정당한 보류를 구별한다.

## 3. 공동 사용 장면의 출발 목록

아래 `EX`는 문서상 사고 실험 식별자다. 기존 COMMON-28이나 QA 평가 모집단을 대체하지 않는다. 각 담당자는 관련 장면의 입력, 같은 완료 조건과 상태를 구체화하고 필요하면 추가 장면을 표시한다. 평가기에만 줄 정답은 후보의 실행 입력에 넣지 않는다.

| 장면 | 같은 사용자 입력과 조건 | 공통 완료 조건 | 주 관련 문제 |
| --- | --- | --- | --- |
| EX01 최근 대화 | TCP 다음 UDP 설명 후 ‘방금 두 번째 방식은 언제 써?’ | UDP를 대상으로 답함. 필요 없는 검색을 강제하지 않음 | 1 |
| EX02 명시 선택 | 선택한 문단 / 셀 범위에 대한 지정된 요청 | 실제 선택과 source revision을 사용. 상세 읽기 전 구체적 처리 안내가 가능하면 허용 | 1, 3 |
| EX03 실제 전달 범위 | 텍스트 A/B/C 표시, 음성 A만 재생. ‘아까 들려준 부분’ 뒤 ‘화면의 두 번째 항목’ | 첫 대상 A, 다음 대상 B. 취소된 음성을 실제 전달로 취급하지 않음 | 1, 4 |
| EX04 과거 복수 결과와 반복 | 과거 비용 비교를 다시 조회하고 반복한 뒤 일정 결과와 연결 | 동일한 원본과 실제 version을 사용. 두 번째 요청의 cache 허용 | 1, 4 |
| EX05 처리 중 독립 질문 | 긴 근거 조회 중 관계없는 짧은 새 질문 | 새 질문에 응답하면서 이전 유효 업무도 연결. 새 질문을 정정으로 오인하지 않음 | 2 |
| EX06 정정과 Agent 질문 | 응답 준비 중 조건 정정, 다른 업무의 질문 도착, 사용자의 짧은 답변 | 정정 범위만 갱신. 실제 제시한 질문에 답을 연결. 다른 업무의 유효 결과 보존 | 2, 4 |
| EX07 취소와 늦은 결과 | 특정 Task 취소 후 진행 / 완료 도착. 다른 Task는 계속 실행 | 취소 요청과 확인된 종료 구별. 늦은 결과로 옛 조건을 되살리지 않음 | 2, 5 |
| EX08 이동하는 지칭 | 말하면서 차트 A 다음 B를 가리킨 뒤 빈 곳으로 이동, 화면 전환 후 전사 도착 | 발화 구간 관측으로 두 대상을 구별. 마지막 화면으로 당시 근거를 대체하지 않음 | 3, 1 |
| EX09 부분 지칭 정정 | 표 T1/T2 보존, 문단 P2 수정 후 ‘표는 T1과 이 표로 바꾸고 문단은 유지’와 T3 지칭 | T1/T3와 P2 조건 유지. 전체 요청을 다시 시작하도록 강제하지 않음 | 3, 2, 4 |
| EX10 관측 부족과 모호성 | 관측 누락 또는 두 대상 모두 가능한 발화. 명확한 대조 입력도 포함 | 근거 부족을 보존하고 적절히 보완 / 질문. 충분한 근거에서 불필요한 질문을 성공으로 세지 않음 | 1, 3 |
| EX11 Agent 간 후속 위임 | A의 비교 결과를 사용자가 수정한 뒤 B에게 그 결과로 발표자료 요청 | 수정 조건, 실제 결과 version과 접근 가능한 자료를 인계. 사용자에게 같은 조건 재입력 요구 없이 완료 경로 확보 | 4, 5 |
| EX12 같은 Agent에서 후속 수정 | 이전 Agent와 실행 맥락을 재사용할 수 있는 간단한 수정 요청 | 공통 이력을 보존하며 재사용 가능 경로 허용. 교체를 강제하지 않음 | 4, 5 |
| EX13 후보 변화 | 새 Agent 등록, 기능 정보 변경, 기존 후보 접속 실패, 적합 후보 없음의 각 변형 | 기능 / 권한 / 사용자 지정 조건을 만족하는 후보 선택 또는 정당한 보류. 부적합 후보의 자동 실행 금지 | 5 |
| EX14 실행 중 전환 | 기존 Agent의 실행 상태가 확인된 경우와 접수 / 수행 여부가 불명인 경우 | 확인된 진행 범위와 새 실행 연결. 불명 상태에서 중복 외부 Action을 시작하지 않음 | 4, 5, 2 |
| EX15 복수 적합 후보 | 둘 이상의 Agent가 필수 기능을 충족하고 업무별 품질 근거 / 지연 / 비용 조건이 다름 | 합의한 선택 목적과 독립 근거에 따라 후보 또는 보류 선택. 정답 Agent를 하나로 임의 고정하지 않음 | 5 |
| EX16 자료 철회와 만료 | 다음 위임 전에 원본 일부 사용 철회 또는 결과 locator 만료 | 유효한 허용 자료만 인계. 부족함과 실제 복구 범위 표시 | 4, 1, 5 |
| EX17 재접속과 기록 갱신 | 연결 중단 뒤 복귀. 원본 결과 revision이 바뀌고 이전 cache가 남음 | 기록과 현재 상태를 대조해 복원. 낡은 파생 자료를 확정 사실로 채택하지 않음 | 1, 2, 4 |

정상 사용을 어려운 예외보다 먼저 설명한다. Agent 내부 업무 성공과 VIA의 올바른 위임 / 인계가 다른 결과임을 기록한다. 외부 시스템의 기능을 사용할 수 있는지 확인하지 않은 장면은 해당 dependency가 필요한 설계 조건으로 표시한다.

## 4. 소스 조사 방식

기존 [고정 source 원장](../../../../../references/agent-harness-20261015.md)과 [근거 공급 조사](../../../../../references/qa-first-evidence-supply-20261016.md)를 재사용할 수 있다. 다시 확인한 경로와 새로 조사한 경로를 구별한다. GitHub 검색은 경로 발견용이고 중요한 주장은 고정 commit의 실제 코드를 읽는다. 도구명은 functions의 ALL_TOOLS에서 GitHub fetch / search를 찾을 수 있다. 공개 웹은 공식 docs / 논문 / 원 저자 구현을 사용한다.

각 source 기록에는 저장소 / commit / 파일과 위치, 정상 실행, 상태와 수명, 강한 보완 기능, 실패 / 정정 경로, VIA에 직접 옮길 수 없는 부분을 남긴다. 제품별 소개 문단만으로 충분한 조사라고 보지 않는다. 동일 구조를 다른 이름으로 반복한 자료와 새로운 대안을 제공한 자료를 구별한다.

다섯 프로젝트 모두 조사 범위에 포함하되 모든 문제에 모든 제품을 억지로 배정하지 않는다. 근거가 없는 기능은 ‘이번 확인 범위에서 미확인’으로 쓰고 저장소 전체의 기능 부재로 단정하지 않는다. 다른 종류의 실제 SW를 참고했다면 그 이유를 기록한다.

## 5. 결과 문서의 필수 내용

1. VIA의 사용자 가치와 기능 실패, 관련 UC와 여러 구체 장면
2. 구조와 무관한 공통 완료 조건, 가정과 dependency
3. 조사 범위, 확인한 source와 탐색에서 남긴 / 제외한 메커니즘
4. 복수의 강한 대안: 데이터, 호출 의존, 상태 소유 / 수명, 정정과 실패, 필요한 공통 / 추가 모듈
5. 같은 장면의 단계별 대안 비교. 단순 요청, cache hit와 대안이 불리한 장면 포함
6. QA01~06과 신규 후보의 인과: 차이 → 처리 / 상태 비용 → 지표 → 방향을 바꾸는 조건
7. 최소 비용 보완과 혼합안, 대안별 유리한 조건, 반증 조건
8. DP 후보로 더 발전시킬지, 다른 문제와 통합할지, 상세 설계로 둘지에 대한 작성자 권고
9. 품질 우위, 기능 지원과 조사 근거의 미확인 범위

숫자 예측, 점수, 순위를 소스 없이 만들지 않는다. 과거 DP의 결과나 수치를 새 후보의 성과로 옮기지 않는다. 구조도는 필요하면 paired SVG / draw.io로 만들고 같은 문서에 표시한다. 문서의 ASCII 흐름과 표로 충분한 부분은 그림을 억지로 늘리지 않는다. 새 prose와 그림에 middle-dot 문자를 쓰지 않는다.
