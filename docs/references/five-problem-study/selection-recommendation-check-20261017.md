[기존 고정 소스 원장](agent-selection.md)의 commit 근거를 유지한다. 아래 현재 문서는 조회일의 공개 설명이며 고정 commit을 대체하지 않는다.

## 2. 이번 권고

**현재는 문제 5를 별도 주요 DP로 승격하지 않고 A를 상세 설계의 출발점으로 추천한다.** 실제로 쓸 수 있는 A/B는 확보했다. 부족한 것은 VIA의 정상 사용에서 별도 선택 문맥을 유지해야 할 만큼 후보만 바뀌는 재선택이 있는지, 그 선택의 정답을 판정할 독립 자료가 있는지다.

후보 종류와 업무 품질 목적이 고정되기 전에는 B가 더 정확하다는 주장도, A가 많은 후보를 다루지 못한다는 주장도 성립하지 않는다. 사용자가 지정한 Agent 또는 적격 후보 하나가 분명하면 양안 모두 같은 공통 경로로 처리한다.

### 연결할 Agent의 최소 등록 자료

- 호출 가능한 endpoint와 인증 및 사용자 허용 범위.
- 실제 확인한 입력 및 출력 형식, 자료 접근 방식, 상태 조회와 취소 지원.
- 지원 업무의 선언과 별도로, 어떤 업무 표본과 조건에서 확인한 성공 / 실패인지 표시한 성과 근거.
- 기능 확인일, protocol 및 capability revision, 연결 상태, native session의 재사용 조건.
- 사용자가 명시한 품질, 시간, 비용 목적과 우선 조건. 알려지지 않은 성능을 임의 점수로 채우지 않는다.

이는 VIA용 등록 계약 제안이다. 현재 GPT, Gemini, Claude 등의 사용자 앱이 모두 같은 방식으로 호출 및 제어 가능하다고 확인한 목록이 아니다.

## 3. 선택 정답을 만들 때의 제안

예를 들어 같은 발표자료 요청이라도 ‘편집 가능한 파일 필수’, ‘확인된 자료에 없는 내용 금지’, ‘초안 우선’의 조건에 따라 허용 후보 집합은 다를 수 있다. 앱 이름을 미리 정답으로 정하지 않는다. 실제 연동 확인과 동일 업무 표본의 독립 성과 자료로 허용 집합을 만들고, 자료가 부족하면 사용자 지정 또는 보류가 허용되는 조건을 먼저 기록한다.

여러 후보를 임의 실행해보는 정책은 이번 기본안에 넣지 않는다. 실험으로 얻은 자료를 실제 제품 성과로 부르지 않으며, 후보 card에 적힌 자기 설명을 독립 정답의 근거로 사용하지 않는다. 구체적인 권고와 재검토 조건은 [문제 5의 권고](../../architecture/12-decisions/decision-packages/qa-first-exploration/five-problem-study/05-agent-selection-and-transition.md#8-2026-10-17-설계-권고)에 있다.
