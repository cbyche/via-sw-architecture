## 1. 이번 재검토의 기준

사용자는 QA01 → QA02 → QA03 → QA04 → QA05 → QA06 순서를 유지하고, 구조적으로 영향을 주지 않는 QA는 동점으로 판단하도록 요청했다. 필요한 구현·추가 실험과 편집 가능한 발표자료 제작도 승인했다. [16 실행 전 계약](16-presentation-selection-contract.md)에 따라 기존 기본안과 보완을 분리하고 실패를 보존한다.

기존 [15 결과](15-corrected-poc-results.md)의 수치와 실행 이력은 유지한다. 당시의 화면 ‘정확도 우선’ 설명이나 인계 ‘조건 보존 우선 B’ 권고를 현재 고정 우선순위의 승리로 바꾸지 않는다. 이번의 선택은 해당 근거와 적용 조건을 명시한 설계 권고이며 accepted ADR이나 참조 Architecture의 사용자 채택 상태를 바꾸지 않는다.

| 발표 DP | 최종 설계 권고 | 보완 적용과 보류 |
| --- | --- | --- |
| DP1 현재 요청의 근거 공급 | 후속 자료 재사용 조건의 A. QA01 전체 우열 미확정 | A2는 정정 재조회 감소에 한정. 공통 첫 채택 안내 분리는 E3 설계 방향으로 권고. A3 보류 |
| DP2 후속 입력의 의미 판단 실행 | 입력 겹침과 호출 여유가 있는 B | B1 불변 입력 공유를 작은 로컬 중복 감소에 한정 적용 |
| DP3 화면과 발화 지칭 결합 | 공통 정규화 출력 계약의 A | 추가 tactic 없는 기본 권고. pixel A2+A5는 별도 복구 실험으로 보존 |
| DP4 Agent 간 업무 인계 | 읽기 지원 수신자를 전제로 C. QA01 우열 미확정 | C1은 기채택 조건 provenance가 있을 때 한정 적용. C2 보류 |

DP1과 DP4의 조건부 권고는 최고 우선순위 QA01의 엄격한 승자 판정과 구별한다. 네 안을 통합한 전체 제품이나 위 보완을 모두 합친 조합은 실행하지 않았다.

### 동점, 미확정, 미관측의 차이

| 판정 | 의미 | 다음 판단 |
| --- | --- | --- |
| 구조적 동점 | 비교 구조가 해당 측정 경로를 바꾸지 않음 | 원값을 함께 보존하고 다음 QA를 비교 |
| 관측상 같은 값 | 이번 유한 표본의 점수가 같음 | 구조적 영향 가능성과 반복 수의 한계를 함께 기록 |
| 우열 미확정 | 영향 경로는 있지만 방향·크기가 확인되지 않음 | 원하는 선택을 위해 동점으로 바꾸지 않음. 조건부 권고와 불확실성 공개 |
| 미관측 | 응답/완료가 발생하지 않아 해당 시간 없음 | 예정 분모와 실패 보존. 성공 사례 평균을 전체 속도 우위로 쓰지 않음 |
| 비적용 | 이 DP가 해당 QA의 측정 대상을 다루지 않음 | 별도 진단을 같은 QA 이름으로 바꾸지 않음 |

필수 기능·권한·최소 기기 조건을 만족하는 대안 사이에서 QA 우선순위를 적용한다는 전제는 기존 [QA 후보 묶음](../qa-candidate-package/README.md)에 있다. 이를 이유로 사후 정확도 점수 문턱이나 임의의 벌점 시간을 추가하지 않았다. 한 번의 미완료만으로 일반적인 구조 실패를 확정하지 않으며, 기능 관측 범위와 완료된 같은 목표의 비교를 함께 제시한다.

## 2. 기본 비교의 원값

> **이전 캠페인의 보존 표다.** 모든 DP에 같은 시험을 적용하는 새 공통 비교의 사례와 분모는 §10, 완주 결과와 예측 대조는 §13에서 확인한다. 아래 원값은 새441회와 합산하지 않는다.

### 2.1 비교 범위와 공통 실행 조건

**이 절은 DP마다 서로 다른 시험 사례를 사용한 네 비교 실험의 결과다. 같은 DP의 A/B/C에 같은 입력·원본·평가 기준을 적용했으며, DP 사이의 초 단위 값을 같은 업무의 속도 순위로 비교하지 않는다.** 대안이 유지한 상태와 실제 모델에 보내는 입력, 실행 단계와 호출 수는 구조에 따라 달라진다.

기존 보완 캠페인의 기본10개 안에 각각 **네 시나리오×세 번 반복=12episode**를 적용한 총120회다. episode는 여러 질문·정정·통지를 포함할 수 있는 한 시나리오의 실행이며, 세 번 반복한 것을 세 개의 다른 사용자 사례로 세지 않는다. 최종 표는 저장소01/02/04의 기본84회와 기확보 근거 연결을 교정한 저장소05의36회로 구성된다. 이후의 첫 안내 분리, 화면 pixel48회·정규화24회, C1과 응답 재생은 각 후속 절의 별도 결과다.

작성한 전사 텍스트와 관측 사건을 재생하고, 화면은 렌더링한 PNG로 제공했다. 의미·이미지 판단과 인계 수신자는 고정 원격 모델 `qwen3.7-plus-2026-05-26`을 실제 호출했다. ASR/TTS, 전체 VIA UI, 상용 Agent 제품과 로컬 Omni 가중치는 이 시험 범위에 포함하지 않았다. 후보에는 실제 입력과 허용 원본을 주고 평가용 정답은 분리했다. 공통 조건과 사건 계약은 [14 실행 전 계약](14-corrected-poc-contract.md), 기존 사례 설명은 [15 측정 범위](15-corrected-poc-results.md#측정한-기능과-비교-범위)를 따른다.

## 3. DP1: 현재 요청의 근거 공급

### 기본안의 구조적 예상과 재검토

A는 이전에 읽은 source-backed 문맥을 유지한다. B는 이번 요청에 필요한 원본을 구성한다. C는 원본의 관계와 설명을 미리 생산·게시하고 요청 때 조회한다. A/B의 문맥 수명과 C의 게시 생산은 서로 다른 축이며 A+C 조합도 가능하다.

첫 의미 호출의 위치가 같아도 입력은 A의 유지 view, B의 최소 문맥, C의 게시 record로 다르다. 같은 `select-or-complete` 스키마에서 본문을 첫 호출에 완성하는 분기와 조회를 선택하는 분기도 다르다. 따라서 **A/B QA01의 0.342초 차이를 확정 우위로 보지도, 첫 호출 위치만을 이유로 구조적 동점으로 지우지도 않는다.** C의 긴 첫 반환도 관계 생산 자체의 필연적인 비용과 출력 분기·길이의 영향을 구별해야 한다.

기존 첫 의미 호출을 추적하면 A/B/C 각각 36회에서 평균 입력 token은 1,088/961/3,533, 평균 출력 token은 325/307/644였다. A는 첫 호출에서 본문 완성을 9회 제안했고 B는 3회, C는 36회 제안했다. C의 실제 직접 채택은 34회였다. A가 읽기를 생략한 일부 경로에서는 첫 반환 전에 더 긴 본문을 생성한다. 이 때문에 QA03의 재사용 이익과 QA01의 짧은 안내 반환이 같은 방향으로 움직인다고 가정할 수 없다. 이 분기별 집계는 서로 다른 사례 분포의 관찰이며 인과 효과의 분해가 아니다. [첫 호출 원값](../../../../../results/architecture-evaluation/current/four-dp-presentation-20261019/dp01/old-first-call-paths.json)을 보존했다.

기존 비교에서 A는 B보다 동일 자료의 답변 호출을 6회 줄였고, A/B 모두 host 종료가 관측된 같은 35목표의 QA03은 A 13.730초, B 14.242초였다. 전체 host 종료는 A 36/36, B 35/36이다. C는 전체 36/36 종료 관측에서 QA03이 12.364초로 A의 13.617초보다 짧았고, 별도 본문 의미 진단도 C 34/36, A/B 각각 30/36이었다. A/B의 본문 조건 누락 각 6건은 그대로 남는다. C의 첫 반환 전에 답변을 많이 완성한 분기와 게시 기록이 작용한 결과이며 QA02와 구별한다. 사전 생산을 포함한 C 비용은 A의 2.42배였다. 후속 자료 재사용이 있는 환경에서 A를 조건부로 추천하지만, 최고 우선순위 QA01에서 엄격한 전체 승자를 입증했거나 A만 필수 기능을 완벽하게 충족했다는 뜻은 아니다.

### 출력 정책 민감도와 보존 보완

추가 실행은 E3의 ABC×3회에서 기존 정책과 공통 adoption-only 첫 안내 정책을 비교한 총18회다. 추가 후속 호출까지 비용에 포함했다. E3은 첫 질문에 유지 view가 없고 후속 질문 직전 원문 정정으로 이전 view가 무효화된다. 실제 A/B 첫 요청 payload는 같은 정책·반복·질문으로 짝지은 12쌍 모두 같았다. 이 결과를 전체 네 사례의 A/B QA01 순위나 A의 유효 문맥 재사용 효과로 일반화하지 않는다.

**이 E3 범위에서는 QA01을 우선해 공통 첫 채택 안내를 분리하는 설계 방향을 권고한다.** QA03 증가와 추가6호출/안의 대가를 함께 부담하는 선택이다. A/B 문맥 구조를 선택한 효과나 모든 사례에 대한 검증 완료로 바꾸지 않는다. 정책을 바꿔도 본문 진단은 A/B 각각3/6, C6/6으로 같았다. A/B의 후속 납기 조건 누락 각3건은 유지된다.

실제 [첫 표시 예시](../../../../../results/architecture-evaluation/current/four-dp-presentation-20261019/dp01/first-handling-examples.json)는 평가 기준의 전달 기록과 Aster A 견적이라는 source 및 현재 revision의 요약 처리 채택을 표시했다. 완료를 주장하거나 질문의 사실 답변을 먼저 제공한 것은 아니다. ## 5. DP3: 화면과 발화의 지칭 결합

## 6. DP4: Agent 간 업무 인계

발표의 DP4는 저장소05다. A는 위임 때 목적별 자료를 구성하고 B는 공개 사건에서 업무 기록을 미리 생산한다. C는 필수 목표·조건·수행 범위를 VIA가 전달하고, 상세 자료의 선택 읽기를 실제 지원하는 수신자에게 맡긴다. 비공개 Agent 기억의 이동은 어느 안의 기능도 아니다.

**QA01의 우열은 미확정이며, 읽기를 지원하는 수신자 조건에서 QA03·비용의 관측 이익을 근거로 C를 조건부 추천한다.** 같은20개 첫 callback 평균은 A4.307/B4.409/C4.327초다. 처음에는 공통 채택 함수를 이유로 구조적 동점이라고 판단했으나 실제 요청을 대조하면서 정정했다. 첫21호출의 입력 token 합계는 A15,318/B41,002/C13,722, 출력은3,720/3,828/3,690이었다. B의 유효 업무 기록 원문과 A의 이전 읽기 원문이 첫 해석에도 들어가므로 C와 입력 경로가 다르다. 작은 관측 차이를 확정 우위나 구조적 동점으로 바꾸지 않는다. 이 권고는 최고 우선순위 QA01에서 승자를 입증한 결과가 아니다. QA02는 비적용이다.

[실제 첫 요청63개 대조](../../../../../results/architecture-evaluation/current/four-dp-presentation-20261019/dp05/basic-prefix-boundary-audit.md)에서 같은 목표의 A/C 요청은15/21쌍 같았지만 A/B와 B/C는 각각0/21쌍이었다. 공통 코드 위치와 동일한 모델 입력은 서로 다른 조건이다.

모든 안이 완료한16목표에서 VIA 시간은 A10.565/B12.299/C4.213초, 전체 경과시간은31.372/31.406/23.532초였다. 수신자 시간을 제외해서만 생긴 이익으로 설명하지 않는다. 전체21목표의 완료20/19/19와 실패도 유지하므로 전체 성공률 우위는 주장하지 않는다.

B의 본문 충족15/18은 C12/18보다 높았지만 별도 내용 진단이며 QA02가 아니다. 고정 QA 순서의 승리로 바꾸지 않는다. 전체 비용은 A $0.1018408/B $0.2886828/C $0.0757928이며 B의 준비51호출을 포함한다. C는 읽기 도구와 접근 계약을 지원하는 수신자라는 조건이 있고 세 안 모두 본문 오류가 남았다.

C는 적용 QA에서 상대적 열세가 입증되지 않아 약점을 만들어내지 않는다. C1은 이미 채택된 필수 조건의 provenance 원문을 미리 제공하는 기능 취약점 보완이다. C2는 정확히 같은 권한·판본·범위의 실제 읽기 기록을 재생하여 반복 I/O와 보존 상태를 비교한다. 독립 보완이며 C1+C2 실행 결과로 합치지 않는다.

### C1: 채택된 조건 원문을 최초 인계에 제공

### C2: 반복 읽기 cache는 기본 적용 보류

[C2 실제 응답 재생](../../../../../results/architecture-evaluation/current/four-dp-presentation-20261019/dp05/replay-summary.json)의 12쌍에서 모델 payload와 최종 본문은 모두 같았다. 실제 `read_to_string`은 34→22회로 줄고 cache hit 12회를 확인했다. 그러나 전체 원문 제공 구간의 합은 7.602→8.784ms로 늘었다. E3 반복 읽기만 줄었으며 다른 사례에는 hit가 없었다. cache 직렬화 상태는 최대 14,790 byte가 추가됐다. 전체 Python+Rust 최고 RSS 51.429→51.298MB의 작은 변동을 cache가 메모리를 줄인 효과로 해석하지 않는다. **C2는 이번 입력에서 지연 개선 근거가 없어 기본 적용을 보류한다.** 큰 원문이나 비싼 저장소 접근이 반복되는 조건에서 재검토할 수 있다.

### 9.1 데이터 구성 결정

**주 결과는 새 측정만으로 구성한다. 이전 결과와 합쳐 모수를 늘리지 않는다.** 공통 첫 응답 정책, 작성 사례, 구현 세대와 화면 생산 의존성이 바뀌었다. 이 자료들을 합산하면 표본 수는 커져도 어떤 조건에서 나온 수치인지 불분명해진다. §2와 §3~6의 기존 원값, 실패와 보완 실험은 그대로 남기고 새 결과와 구별한다.

같은 사례를 반복 실행한 것은 모델 변동의 반복 관측이다. 서로 다른 사용자 사례가 추가된 것으로 세지 않는다. 이전 조건 진단은 세 반복이고 새 공통9는 다섯 반복이다. 이전 DP별 전체 평균은 해당 고정 모집단 안에서만 비교한다. 새 공통9에서는 같은 주변 구조에서 해당 DP만 바꾼 값을 비교하되, 다른 DP를 동시에 바꾼 조합이나 구조 자체의 보편적 속도 순위로 확대하지 않는다.

QA01은 실제 채택된 구체적 첫 callback, QA03은 현재 revision의 host 완료를 측정한다. 이것만으로 상세 응답의 모든 의미 조건이 올바르다는 뜻은 아니다. 지칭 집합 QA02, N-R/N-H, 본문 조건과 실제 출력의 오류는 각각 별도로 보고한다. 미관측 시간은 임의 벌점 시간으로 바꾸지 않고 예정분모에 남긴다.

### 9.3 사용자 지적에 따른 공통 대표 평가와 조건 진단의 구분

### 9.5 첫 정식 세대의 실제 실패와 공통 계약 보완

`formal-v1`의 첫 AAAA/S02 실행에서 API12회는 정상 반환됐지만 사용자6개 요청 모두 `segment not declared by source`로 거절됐다. 실제 원본 읽기 뒤 모델이 이미 허용된 일반 조회에도 `permission_operations`를 제안했고, 선언된 권한 구간 이름 대신 `1-2` 또는 `[1,3]` 같은 행 번호 표현을 넣었다. `source_revisions`에도 실제 source ID 대신 예시의 `source_id` 키를 그대로 반환한 사례가 확인됐다.

**이는 모델의 유효하지 않은 제안이며, 권한 검증기의 거절은 올바른 동작이었다.** 사실과 맞는 답변 문자열이 모델 원시에 있더라도 실제 게시되지 않았으므로 첫 응답과 목표 완료는 각각0/6이다. API 성공을 기능 성공으로 세거나 답변 원문을 사후 표시 성공으로 바꾸지 않는다. [독립 원인 검토](../../../../../results/architecture-evaluation/current/common9-poc-20261019/independent-formal-audit/AAAA-S02-r1-acd5e6-cause-review.json)에 원시 근거를 남겼다.

동일 오류로 전체 실행을 계속 소비하지 않도록 다음 episode dispatch를 보류했다. 이미 시작한 BAAA/S02도 취소하지 않고 끝까지 수집했으며 같은6개 검증 거절과 첫 응답, 완료0/6을 확인했다. 이 세대는 **2/315episode 수행, 313개 미실행**, 실제 API24회와 고정 단가 비용$0.0420392, 미확정 사용량0으로 종료했다. [보류 종료 원장](../../../../../results/architecture-evaluation/current/common9-poc-20261019/formal-v1/METHOD-HOLD-CLOSURE.json)에 기존315개 계획과 실제 수행 및 미실행을 그대로 보존하며, 완성한 대표표나 A/B 우열 근거로 쓰지 않는다.

새 공통 구현은 일반 조회와 권한 변경의 출력을 구분하고 실제 source ID를 쓰는 형식을 명확히 한다. 권한을 변경하기 전에 전체 제안의 형식과 실제 catalog를 순수 검증하고, 오류가 있으면 관측된 오류와 같은 원본을 모델에 돌려주는 제한된 재판단을 모든 구성에 동일하게 적용한다. 한 workflow의 의미 호출은 최초 호출과 권한 적용 후 재조회 및 오류 재판단을 모두 합쳐 최대3회다. 잘못된 제안의 자동 삭제, 권한 구간 자동 확대, 정답 주입은 하지 않는다. 재판단 시간과 비용도 측정한다.

### 9.8 진행 통지의 첫 응답 판정에 대한 별도 교정

실행 중 정적 검토에서 동결 집계기의 QA01 대체 종료점 조건 두 가지를 발견했다. S11-A01, S18-A03, S19-A01의 진행 통지는 같은 Task의 더 최신 완료 카드로 충족할 수 있는데, 기존 코드는 같은 Task와 표시 시각 및 `완료`라는 단어만 확인했다. 실제 완료 사건이 없는 처리 의도 문장도 대체 카드로 인정할 가능성이 있었다. 또한 자체 진행 표시가 있으면 더 먼저 표시한 유효 완료 카드를 확인하지 않았다. 발견 당시 종료된 실행은 S02뿐이므로 실제 오집계를 확인한 결과는 아니다.

[교정 부록](reviews/common9-newer-completion-endpoint-addendum-20261019.md)에 이후 BG 결과를 관측하기 전에 기준과14개 경계 사례를 기록하고 독립 정적 검토를 완료했다. 실제 제공, 수신한 RESULT, 같은 Task, 원천, 수신, 표시 시각, 실제 결과 표시 단계와 원문 연결을 확인한다. 현재 구현은 수신 결과의 바깥 공백만 제거해 표시하므로 그 범위에서 본문 일치도 확인한다. `완료`라는 단어 자체는 필요조건도 충분조건도 아니다. 자체 진행 표시와 유효한 최신 완료 카드 중 가장 이른 시각을 사용한다.

최신 사건이 실제로 먼저 제공됐는지 입증할 시각 정보가 부족하면 첫 시각을 임의 확정하지 않는다. `UNRESOLVED_EARLIEST_BOUNDARY`와 가능한 하한, 확정 가능한 상한을 별도로 표시하고 정확 지연은 비워 둔다. 실제 게시 사실, 첫 종료점 확정 수와 예정215건을 구별한다. 승인 당시 교정 코드는 실행하지 않았으며 측정 보류 후 별도 `evaluation_v3`에서 구현했다. [초안 검사 원장](../../../../../results/architecture-evaluation/current/common9-poc-20261019/development/evaluator-v3-draft-04/manifest.json)의 승인14개와 추가35개, 총49개 유한 검사는 통과했다. 유료 호출은0이며 실제 host 수신 확인과 최종 원시 trace의 통합 수용은 아직 진행 중이다. 초안 검사 통과를 새 정식 측정 완료로 표시하지 않는다.

후보, 입력, 동결19 계약, 원시 callback, 비용, 인과 경로는 유지한다. 동결 집계기와 원래 출력도 보존하고, 별도 버전의 교정 집계기를 같은315개 계획의 원시에 모든 구성 동일하게 적용한다. 영향을 받은 행마다 원래 판정과 교정 판정, 선택한 카드와 이유 및 시간 차이를 공개한다. 이 QA01 종료점 교정으로 유료 모델을 재실행하거나 QA02~06의 정의를 바꾸지 않는다.

### 9.9 종료, 취소 계약 결함에 따른 두 번째 세대 보류

§9.8과 별개로 실행기, 후보, 집계기의 종료 계약 불일치를 확인했다. 실행기는 실제 `RESPONSE_FINAL`과30초 응답 anchor 대체를 같은 `finalseen`에 넣어 모두 응답했다고 판단할 수 있었다. `end_input`은 입력 종료와 worker join만 수행하며 작업 취소가 아니었다. 집계기에도 마지막 의무 source+60초 뒤의 callback, 완료를 제외하는 상한 조건이 없었다. [원시 시각과 실행기 대조](../../../../../results/architecture-evaluation/current/common9-poc-20261019/formal-v2/S02-SOURCE-TIMELINE-AND-DEADLINE-REVIEW.json), [독립 정적 검토](../../../../../results/architecture-evaluation/current/common9-poc-20261019/independent-formal-audit/formal-v2/final-source-deadline-static-review.json)에 근거를 남겼다.

첫 S02의6개 발화는 각각6초였고 후속 입력 간격은30초 실패 대기+2초 시작 대기+6초 발화로 계약과 맞았다. 문제는 마지막 source 후 약30초에 종료했다는 것이다. 당시 모든 workflow는 그 전에 실패했고 게시, 목표 완료가0이므로 실제 늦은 성공을 오채점했다고 주장하지 않는다. 그러나 다른 실행에서는60초 뒤의 권한 변경, 인계, 게시와 호출 및 비용이 남을 수 있어 결과 집계만 고쳐 취소했을 때의 상태, 비용, 메모리를 복원할 수 없다.

### 11.1 이번 공통9에서 검증할 수 없는 예측 조건

독립 검토에서 세 가지 범위 한계를 확인했다. S11/S18/S19의 BG 사건은 이미 해석된 Agent 사실을 공통 코드로 표시하며, 일반 사용자 후속 질문은 이전 상세 응답 이후에 발생한다. 따라서 **긴 의미 판단 중 독립된 새 의미 요청을 처리하는 DP2의 이익은 이9개로 확인하거나 반증할 수 없다.** S08의 동일 목표 정정은 다른 조건이며 실제 모델 실행이 겹쳤는지 원시 경로로 따로 판단해야 한다.

이번 화면 fixture는 큰 고유 라벨을 가진 정적 요소 중심이다. 화면 파서와 실제 지칭 경로는 실행하더라도 **작고 밀집된 요소에서 별도 후보가 정확도를 높인다는 DP3 가설은 검증하지 않는다.** 또한 B의 Qwen screen producer에도 원본PNG를 제공하므로, local parser가 모든 Qwen 이미지 입력을 제거하는 구조의 비용 효과를 측정한 것이 아니다. 실제 native 선택만으로 충분한 S15 경로와 구별한다.

이 한계를 숨기거나 원하는 차이를 만들기 위해 동결 사례의 난도와 입력 시점을 사후 변경하지 않는다. 모든 구성에 같은 시험을 적용한다는 공정성과 모든 구조 가설의 성립 조건을 포함한다는 충분성은 각각 확인해야 한다. 이번 대표표는 공정한 공통9 비교이며, 모든 이익 조건을 포괄하는 반증 실험이라는 주장은 하지 않는다.

**따라서 새315회만 끝났다고 ‘모든 구조 예측 검증 완료’로 표시하지 않는다.** DP2의 독립 의미 목표 병행과 DP3의 작은 밀집 요소 처리 가설은 대표 9개만으로는 미검증이다. 해당 조건이 없는 표본의 동점이나 역전으로 이 가설을 반증했다고 해석하지 않는다. [Astra Ultra의 실험 목적 검토](reviews/common9-method-v3-astra-review-20261019.md#fitness-of-the-nine-case-experiment)도 동일하게 판정했다.

사용자는 이 한계를 보완하기 위해 **별도의 공통 6조건×7구성×3회, 총126회**를 추가 승인했다. [20 공통 보완 계약](20-common-supplement-evaluation-contract.md)에 정확한 요청과 원본, 화면 배치, 입력 시점, 분모와 실행 순서를 사전 등록했다. DP2는 독립 요청의 중첩, 순차 입력, 동일 목표 정정을 비교하고 DP3는 밀집 화면, 같은 내용의 넓은 배치, 실제 native 선택 정보를 비교한다. 모든 조건을 모든7구성에 동일하게 적용한다. 보완 시험의 승인과 실제 메커니즘 발동 또는 가설 지지는 서로 다르다. 실제 fixture와 소스를 동결하고 구현 및 독립 검토를 마친 뒤 대표315회와 보완126회를 사전 등록한 순서로 함께 실행하기 시작했다. 각 모집단의 집계는 계속 분리한다.

보완 구성별 분모는18episode에 QA01 응답36개, QA02 지칭 집합18개, QA03 목표24개다. QA04는 같은 여섯 변경 과제의 실제 변경 측정을 참조하고 새 사례의 회귀 검사를 추가한다. QA05는6episode 묶음의3회 평균 비용, QA06은18episode의 최고 동시 RSS다. 대표9와 QA의 의미는 같고 새 조건의 예정 수량만 다르다. [20 계약 §7](20-common-supplement-evaluation-contract.md#7-동일한-여섯-qa의-보충-집계)에 동일한 계산식과 실패 처리를 명시한다.

대표315회와 보완126회는 각각 집계한다. 기존 결과, 개발 호환성 점검, 대표9와 보완6을 합쳐 하나의 평균이나 표본 수로 만들지 않는다. 전체 비용은 이전 실패와 개발 점검을 포함해$40로 제한한다. 실행 전 두 모집단의 비용을 함께 계산하며, 실제 비용과 예약 합계가 상한에 닿으면 예정 분모와 미실행 항목을 보존한다.

첫 [441회 공동 비용 계획](../../../../../results/architecture-evaluation/current/common-supplement6-20261019/preflight/joint441-cost-projection-v1.json)은 이전 확정 환산 비용$0.7150616을 포함해 보통 호출 경로 약$30.36, 모든 의미 판단이 최대 복구 횟수를 사용하는 경우 약$47.73으로 추산했다. 입력은 UTF-8 약3byte/token, 출력은 설정 상한, 이미지는 byte 기반의 계획용 proxy를 사용하며 실제 provider token 측정이나 청구액 보장이 아니다. 예약용 byte 가정의 더 보수적인 합계는 약$100.77이며, 각 호출의 예약이 실제 usage 정산 후 풀리는 점과 구분한다. [독립 비용 판단](reviews/common-supplement6-astra-review-20261019.md)에 따라 같은441회, 모델, 복구 정책과$40 상한을 유지한다. 보통 가정의 여유 약$9.64는 가장 큰7구성 block의 보수적 계획액 약$3.36보다 크지만 완주를 보장하지 않는다. 최종 동결 자료로 계획을 다시 연결하고 각 block 전 잔액을 확인한다. 상한에 따른 중단은 `INCOMPLETE`로 보고하며 저비용 구성만 골라 완주하거나 반복 수를 줄이지 않는다.

[24개 예측의 검증 범위 검토](reviews/common9-prediction-coverage-review-20261019.md)에 각 셀의 실제 구현 조건과 필요한 실행 근거를 남겼다. 공통9 유료 실행 전의 범위 검토이며, 결과를 본 뒤 불리한 셀을 제외한 판단이 아니다.

기존 수치와 새 수치를 합쳐 표본 수를 늘리지 않는다. 입력 모집단, 연결 구현과 측정 방식이 달라 이전 독립 PoC의 성공 행을 추가하면 비교 조건이 다시 달라지기 때문이다. 새 대표표는 공통9의 새 측정만 사용하고 이전 결과와 DP별 조건 진단은 별도 근거로 남긴다.

### 11.2 실측 후 판정 규칙

먼저 같은 고정 모집단의 전체 값과 실패 수를 표시한다. 이어서 예측한 조건이 입력에 있었는지, 실제 실행에서 해당 경로가 사용됐는지, 그 경로의 수치 방향과 전체 값이 어떻게 연결되는지를 확인한다. 예측에 원래 승자가 없던 셀의 수치 순위를 사후에 ‘예측 적중’으로 부르지 않는다.

이번 QA01의 정확한 측정명은 **첫 구체적 응답의 실제 host callback 지연**이다. callback의 계측·게시가 유효하다는 사실만으로 본문이 정확하다고 판정하지 않는다. [최종 보고 및 의미 진단 계획](../../../../../results/architecture-evaluation/current/common-supplement6-20261019/joint-formal-v1/postanalysis/planning/astra-final-report-plan-v1.md)에 따라 본문, Task·정정 관계, 승인·권한 및 인계 조건을 별도로 검토하고 `PASS / FAIL / UNREVIEWED`와 각각의 검토 분모를 공개한다. 전체 예정 응답 의무는 대표 1,505개와 보완 252개, 목표 관계는 각각 805개와 168개다. 이 진단으로 이미 고정한 QA01의 시각이나 분모를 다시 필터링하지 않으며, 미검토한 내용을 정답으로 간주하지 않는다.

[AAAA/S02 첫 반복 한 건의 원시 의미 검토](../../../../../results/architecture-evaluation/current/common-supplement6-20261019/joint-formal-v1/postanalysis/semantic-reviews/manual-reference-AAAA-S02-r1-v1.md)에서는 실제 요청에 대한 여섯 본문과 여섯 목표 연결을 확인했다. 별도 기대 문구 RU02의 발송 시각과 RU05의 본문 출처 표시는 실제 발화나 공통 출력 계약에 추가로 요구되지 않았다. 해당 문구의 불충족은 `ORACLE_INPUT_MISMATCH` 및 요구조건 미확정으로 남기며 모델 오답으로 바꾸지 않는다. 원래 기대 문구와 실제 입력, 구조화된 출처 근거는 모두 보존한다. 이 한 건의 수용을 전체 441회의 정확성 수용으로 확대하지 않는다.

#### S20: 모호한 승인, 실제 Task 연결과 공통 수신자의 한계

실제 열린 질문은 “TA: PDF로 만들까요?”와 승인 종류인 “TB: 민수에게 보낼까요?”였다. 이를 수신자 선택 질문으로 부른 기대 라벨과 구분한다. 네 구성은 확인 질문 없이 첫 “응”을 TB 승인으로 채택했고, 이후 “보고서는 PDF로 만들어줘. 메일은 보내지 마”를 기존 Task 제어 대신 새 `TASK-5` 위임으로 처리했다. 모델이 원시 제안에서 TA를 적은 것과 실제 채택된 Task는 다르며, 위임 제안에 담긴 TB 거부가 실제 제어로 실행된 것도 아니다. 목표 관계는4건 FAIL,3건 UNREVIEWED다.

S02의 준비 실패는 실제 모델 출력이 길이 제한으로 잘려 JSON이 완성되지 않은 경우다. 여섯 직접 응답이 모두 맞았더라도 사용되지 않은 준비의 실패와 비용을 없애지 않는다. S81의 ABAA/AABA/AAAA는 공개를 막는 일부 조건은 설명했지만, 요청한 여덟 항목 중 배포 지원 가능 시간과 일정 조정 조건을 누락했다. `월요일12시`라는 문구의 부재만으로 실패를 부여한 것은 아니다. AABA/AAAB/AAAC는 첫 응답을 기다리던 중30초 대체 규칙으로 U02를 제공했고 실제 표시도 U02가 먼저였다. 늦게 도착한 U01 응답을 이용해 이 세 사례를 정상 순차 조건으로 바꾸지 않는다.

두 사례의 보조 binding 필드는 발화의 정확한 부분 문자열을 요구했지만 원문 문장이나 해석한 값을 기록한 경우가 있었다. 이를 별도 지시 불일치로 보존한다. S02/S81에는 동결된 QA02 지칭 집합 의무가 없으므로, 사후에 QA02 분모나 QA01의 정확성 필터를 추가하지 않는다.

S08에서는 실제 선택 목록이 계속 T1/T2이고 정정 발화의 현재 포인터는 T3를 가리켰다. AAAA는 기존 목표의 정정으로 연결했지만 보존 대상을 T1/T2로 유지했고, AABA는 T1/T3를 맞혔지만 별도 목표로 채택해 기존 요청의 정정 관계를 놓쳤다. 나머지5구성은 실제 선택 전체와 다른 집합을 완전한 선택으로 주장해 동결 검증에서 거절됐다. 최초 A01 누락 플래그는7건이지만 이후 실제 결과가 제공되고 표시된 것은2건이다. 최초 실패 플래그와 최종 제공 상태를 함께 보존한다. 두 결과를 충실히 전달했다는 판정은 문단 수정이나 올바른 보존 대상의 실제 완료를 뜻하지 않는다.

S84의 두 번째 반복도 전체7구성에서 응답과 채택 관계가 없었다. 여섯 joint 경로의 실제 제안24건은 B03/B04에서 B03/B05로 바뀐 현재 지칭 대신 B01/B02를 선택했고, 두 원형 경로를 단일 점 관계로 주장했다. AAAB의 마지막 정정 제안에는 정규화 좌표 범위 오류도 있었다. AABA의 정정 대상 ID B03/B05는 맞았지만 관계와 중간 영역이 부정확해 확장 후 관측 종료에 취소됐다. raw ID 일치, 늦은 생산 출력, 실제 채택과 사용자 전달을 구분하며 QA02 성공이나 완료로 바꾸지 않는다. 버튼 크기와 행 간격이 함께 바뀐 작성 조건이라는 범위를 유지한다.

S11의 두 번째 반복에서는7구성 모두 H10의 비용 비교를 두 번 정확히 보여줬다. AAAB와 CAAA는 실제로 공급된 H10과 H11의 개별 원본에 근거해 비용과 완료일의 관계도 설명했다. 나머지5구성은 대화 기록 안의 일정 문구를 읽었으나 실제로 공급되지 않은 개별 H11 source를 claim으로 작성했고, AAAA의 후속 수정도 source와 판본 목록을 맞추지 못했다. 표시되지 않은 초안을 본문 오답으로 세거나, BG의 완료 통지를 사용자 관계 설명의 완료로 세지 않는다. 같은 원문이 입력에 다시 나타난 사실만으로 선택 호출 생략이나 비용 절약을 주장하지 않는다.

S82의 두 번째 반복에서 현재 내부 링크 목적의7답변은 기존 권한의 내부 검토자에게 링크 공유가 가능하고 외부 발송과 새 외부 권한 부여 및 실제 실행은 포함하지 않음을 설명했다. CAAA의 추가적인 초안 직접 배포 금지는 더 넓은 범위가 미확정이므로 현재 링크 가능성에 한정해 수용한다. 앞선 외부 공개 목적의7행은 대체되어 미검토이며, 같은 U02 callback을 두 번 세지 않는다. AABA, AAAB, AAAC, BAAA는 그 뒤 오래된 U01 작업을 새 정정으로 채택해 마지막 입력 ID를 U01로 되돌리고 같은 본문을 다시 표시했다. 본문이 현재 목적에 맞아도 이 최신성 실패는 남는다. ABAA, AAAA, CAAA의 최종 입력은 U02이지만, ABAA의 앞선 자기 정정 오류와 CAAA의 준비 취소 등 실제 실패와 비용도 보존한다. [독립 Sol 감사](../../../../../results/architecture-evaluation/current/common-supplement6-20261019/joint-formal-v1/postanalysis/planning/sol-semantic-audit-S82-r2-v1.md)는 이 범위의 판정과 수량을 확인했으며 계측 인증이나 새로운 중단 규칙을 추가하지 않았다.

S12의 두 번째 반복에서는 모든 구성이 이전10개 파일을 보여줬고, 원본 갱신 뒤6구성이 현재12개를 답했다. AAAB의 현재 원본도 해석 입력에 도착했으나, 모델이 DOC-A의 v1과 v2를 함께 claim하고 source별 판본 map에는 v2만 기록해 채택되지 않았다. source ID마다 숫자 판본 하나를 두는 PoC 표현 계약의 제한과 실제 모델 출력 형식을 함께 기록한다. 다른6구성은 현재 판본만 claim했고, 그중4구성은 실제 전달 이력의 옛 값과도 올바르게 비교했다. 이 한 실패를 두 판본 비교 기능 전체의 불가능이나 구조 고유 열위로 확대하지 않는다. 원본 판본2와 별도 요청 목표의 revision1도 구분한다.

S85의 두 번째 반복에서는 실제 native 선택이 모든 구성에서 B03/B04에서 B03/B05로 갱신됐다. 첫 답변7건과 정정 답변6건은 행 이름을 정확히 전달했다. AABA의 speech 해석과 두 binder 출력만 이전 집합을 선택해 현재 producer 후보 검증에 실패했으며, 정확한 native 입력 자체의 결함으로 돌리지 않는다. AABA의 실제 native 후보 경로와 관측된 event 및 linked request 범위에서 parser와 screen producer dispatch가 없었던 점을 확인했지만, 전체 helper lifecycle과 call-level spawn/parse admission을 사용하는 정식 skip 진단은 아직 미확정이다. 메타데이터가 있다는 사실만으로 helper 비용과 지연이 사라졌다고 주장하지 않는다.

S15의 두 번째 반복은 실제28본문이 모두 표시됐고21목표의 Task와 최신 요청 연결은 맞았다. 그러나 AAAB는 TCP가 오류 검사 없이 신뢰성 있게 전달한다고 실제로 표시했고, CAAA는 사용자가 가리킨 기존 P1 문단 설명에 없던 비용·일정·자원 표까지 작업 범위를 넓혔다. 올바른 내부 의도나 충실한 Agent 결과 전달로 이 두 본문 오류를 없애지 않는다. 실제 A01 결과7건은 모두 입력되고 표시됐으나 물리 발표자료 파일의 완성은7건 모두 미검토다. AAAB의 선택된 REC-005는 실제 ingress와 수신자 입력에서 앞선 producer 세대와 일치했으며, 같은 ID로 나중에 다시 생산한 기록과 구별했다. 자유문 요약의 P4 표기 오류와 실제 P1 원본 전달, 준비 응답의 길이 제한 실패 및 폐기 비용도 각각 보존한다. 기록 노출을 원문 읽기 생략이나 반복 생산 비용 회수로 해석하지 않는다.

### 12.5 보존, 복원과 다음 결정

작은 결과와 계약은 직접 읽고, Git에 직접 넣기 큰 원시·실패·동결 source·이전 세대는 [분할 evidence 패키지](../../../../../results/architecture-evaluation/current/common-supplement6-20261019/preservation-final-stopped258-v1/README.md)에 보존한다. 실제 생성·해시·새 경로 복원 상태와 명령은 같은 폴더의 [검증 기록](../../../../../results/architecture-evaluation/current/common-supplement6-20261019/preservation-final-stopped258-v1/VERIFICATION.json)을 따른다. 원본을 덮어쓰지 않으며 weights, 환경, secrets와 compiled binary는 패키지에서 제외한다. 기록된 binary hash와 source 및 dependency inventory는 유지한다.

원래 경로에서의 동결 분석은 실제 통과했지만 **다른 경로에서 API 없이 분석을 다시 수행하는 절차는 미검증**이다. accepted analyzer와 reader는 저장된 절대 경로와 비symlink 조상을 검사한다. 단순히 새 `--root`를 주거나 symlink를 만드는 명령을 검증된 재분석 절차로 제시하지 않는다. 이미 있는 격리 runtime으로 복원본을 원래 논리 경로에 읽기 전용으로 연결할 수 없으므로 새 가상화 환경을 만들지 않았다. 패키지 byte 복원 검증과 분석 재실행, 실제 모델 실험 재현은 서로 다른 주장이다. [수용된 복원·재분석 계획](../../../../../scripts/architecture/common9_postanalysis/clean-restore-reanalysis-plan-v1.md)에 한계와 조건을 남겼다.

의미 검토는 대표 응답441/1,505행과 목표 관계266/805행, 보완140/252행과91/168행까지만 수행했다. 미관측·대체 목적·미검토와 실제 본문 오류를 §11.2에 각각 보존했으며 다른 반복에 PASS를 상속하지 않는다. 추출255행의 범위 내 COMPLETE도 이 의미 검토 범위를 늘리지 않는다. 원래441회 완료라는 목적은 달성되지 않았고 이번 부분 자료만으로 새 최종 방안을 선택하지 않는다. §1~8의 이전 권고는 당시 증거로 유지되며 새 공통 결과로 소급 인증하지 않는다.

재개 전에 필요한 결정은 종료 handshake의 수정·검증과 새 source/binary provenance 및 freeze 처리, 실패 slot과 남은183회를 어떤 모집단으로 새로 평가할지다. 기존 실패를 인증으로 바꾸거나 멈춘 controller를 그대로 재시작하지 않는다. 관측·admission cutoff와 settlement, 입력·정답·복구 한도와 예정 분모는 결과에 맞춰 완화할 수 없다. **이번에는 추가 API 호출·후보 수정·재실행을 하지 않았다.** 후속 구현·검증·유료 재측정은 그 범위가 명시된 별도 승인을 받아야 한다.

게시 검증의 한계도 별도로 남긴다. 첫 게시 커밋의 자동 `architecture-ci`는 링크426건으로 실패했으며, [정확한 CI 원인 기록](../../../../../results/architecture-evaluation/current/common-supplement6-20261019/preservation-final-stopped258-v1/CI-FAILURE-DIAGNOSIS.json)에서 이전 커밋에도 있던14건과 이번에 추가된412건을 분리했다. 추가 오류에는 추출하지 않은 보존 파일과 원래 절대 경로의 링크가 포함됐다. 정확한 package manifest·inventory·분할 파일과 전체 archive hash, 원래 root 및 Markdown hash를 검증하는 제한적 locator 지원을 추가했다. 임의 파일명이나 result tree 전체를 예외로 만들지 않으며 누락·손상·미결합 경로와 symlink alias는 실패한다. [독립 Sol 검토](../../../../../results/architecture-evaluation/current/common-supplement6-20261019/preservation-final-stopped258-v1/CI-LINK-INDEPENDENT-REVIEW.md)에서 발견한 P2도 수정하고11개 synthetic 검사를 보존했다. [게시 대상884파일 확인](../../../../../results/architecture-evaluation/current/common-supplement6-20261019/preservation-final-stopped258-v1/CI-TARGETED-CHECK-RESULT-v4.json)에는 새 오류0건과 기존14건이 남았다. 기존 동결 복사 문서의 상대 탐색 링크14건은 고치거나 제외하지 않았다. 전체 CI 통과와 이후 단계 검사를 통과했다고 주장하지 않는다. 이 게시 검사와 메타데이터는 archive 밖에 있으며 측정·동결 증거 byte와 지표는 바꾸지 않았다.

## 13. 종료 처리 수정 후의 공통 재측정 완주

### 13.1 수정, 별도 동결과 기술 인증

2026-10-20 KST에 §12의 종료 경합을 수정했다. 두 모집단의 harness는 `cancel_work`를 한 번 보내고 중복된 `end_input` 쓰기를 제거한다. 후보 Rust 입력 loop에서 `cancel_work`가 종료 신호이므로, 뒤따르던 쓰기는 정상 종료된 pipe와 경합했다. 취소 신호 **자체**가 `BROKEN_PIPE`로 실패하면 이전과 같이 기술 실패로 기록한다. 자식 종료 뒤 Python writer를 닫을 때의 pipe 예외만 로컬 정리로 처리한다. 대표와 보완의 오프라인 종료 점검은 각4호출·2원천을 처리하고 취소 ACK, 결과, stdout 종료를 한 번씩 확인했다. 유료 정식 실행의184회도 모두 `returncode=0`, 기술 실패0, 예산 중단0으로 종료했고 controller lock을 반환했다.

원래 `joint-formal-v1`의 **258개 trace와 실패1개는 그대로 보존**했다. 별도 `joint-recovery184-v1`은 원래 미인증 `ABAA-S12-r3`의 새 실행1개와 시작되지 않았던183개만 원래 순서대로 실행한다. 복구 세대의 freeze SHA-256은 `ff92a5609f4d40b5303ec9ec7d120f55b22fc5520645197ca8c52001f5c42c87`이며, 기존 freeze는 `0753a648e97dbb831c70c127bce383de747333ee0737f1d5b75010cc1f510ebd`다. 후보 binary SHA-256 `5aea60533c5b2a46c0e22cf8a7e4d86d51b4ba2c3860f6006341f0f073dd2e1d`와 외부 dependency, fixture, oracle, 평가 기준, 모델·단가는 같고, 동결 source 차이는 두 harness의 종료 처리와 새 recovery controller뿐이다. 재측정 실행은 기존 $40 전역 원장을 사용했고 각 block의 보수적 비용을 남은 한도와 대조했다.

[결합 분석기](../../../../../scripts/architecture/common9_postanalysis/analyze_recovery_pool.py)는 기존258개 원시 trace의 해시, 새184개 원시 trace·입력·실행 순서, 종료 ACK와 결과, 두 freeze·binary·dependency, 기술 인증과 원장 잔액을 대조했다. 기존 인증257개에 새 인증184개를 넣고 **기존 미인증 결과는 대표 QA 표본에서 제외**한다. 그 실패의 trace·호출 비용은 삭제하거나 새 실행으로 덮지 않는다. 따라서 대표는7구성×9사례×5회=315, 별도 보완은7구성×6사례×3회=126으로 예정된 신원441개가 정확히 한 번씩 집계된다. 이 인증은 실행·관측 절차의 인증이며 응답 본문의 의미 정확성을 자동 승인하지 않는다. 원시 자료, 결합 분석 JSON과 [작은 집계 JSON](../../../../../results/architecture-evaluation/current/common-supplement6-20261019/preservation-recovery184-v1/summary.json)은 [검증된 복구 세대 패키지](../../../../../results/architecture-evaluation/current/common-supplement6-20261019/preservation-recovery184-v1/README.md)에 보존한다.

### 13.3 합산 결정, 비용과 비교 한계

**같은 공통 모집단 안에서는 조건부로 합산한다.** 기존 인증257개와 새 인증184개는 동일한 예정 신원441개를 겹치지 않게 채운다. 원본·oracle·후보 binary·모델·가격·평가식이 같고, 수정은 중복 종료 쓰기 제거로 제한된다. 따라서 전체 예정 분모, QA02의 정확 집합 비율과 QA05의 완료 묶음 비용을 구성별로 계산할 수 있다. 다만 두 세대는 다른 시각에 실행됐으며 provider/network 지연과 host 부하를 통제한 batch 교차 실험이 아니다. QA01·QA03은 endpoint 누락이 남아 관측 부분 평균만 보조로 쓴다. QA06 대표 CAAA는 불완전 sample이고 다른 구성도 기기 전체 메모리보다 좁은 관측이다. 시간과 RSS의 작은 차이를 세대에 불변인 순수 구조 효과로 확정하지 않는다. **대표9와 보완6은 서로 다른 별도 모집단이므로 합산 점수·평균을 만들지 않는다.** §2의 이전 DP별 상이한 시험도 이441회와 합산하지 않는다.

### 13.5 재현 범위와 보존

새 복구 root의 freeze, authorization,184개 controller 진행·trace·원시 호출, 결합 분석과 요약은 SHA-256 manifest로 검증한 분할 archive에 넣었다. [패키지 검증·복원 기록](../../../../../results/architecture-evaluation/current/common-supplement6-20261019/preservation-recovery184-v1/VERIFICATION.json)은 archive 전체와 구성 파일의 해시 및 빈 경로 복원 여부를 남긴다. 기존 중단 세대의 별도 패키지는 §12.5에 그대로 있다. 복원 byte 동일성과 분석기의 원래 절대 경로 제약, 모델 API의 실제 재실행 가능성은 다른 주장이다. 새 패키지의 byte 복원은 모델을 다시 호출하지 않는다.
