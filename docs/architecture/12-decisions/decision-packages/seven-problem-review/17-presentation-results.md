# QA 우선순위에 따른 네 DP의 발표용 재검토

2026-10-19 / 추가 실험과 30장 발표자료의 시각 검토 완료

## 1. 이번 재검토의 기준

사용자는 QA01 → QA02 → QA03 → QA04 → QA05 → QA06 순서를 유지하고, 구조적으로 영향을 주지 않는 QA는 동점으로 판단하도록 요청했다. 필요한 구현·추가 실험과 편집 가능한 발표자료 제작도 승인했다. [16 실행 전 계약](16-presentation-selection-contract.md)에 따라 기존 기본안과 보완을 분리하고 실패를 보존한다.

기존 [15 결과](15-corrected-poc-results.md)의 수치와 실행 이력은 유지한다. 당시의 화면 ‘정확도 우선’ 설명이나 인계 ‘조건 보존 우선 B’ 권고를 현재 고정 우선순위의 승리로 바꾸지 않는다. 이번의 선택은 해당 근거와 적용 조건을 명시한 설계 권고이며 accepted ADR이나 참조 Architecture의 사용자 채택 상태를 바꾸지 않는다.

## 3. DP1: 현재 요청의 근거 공급

### 기본안의 구조적 예상과 재검토

A는 이전에 읽은 source-backed 문맥을 유지한다. B는 이번 요청에 필요한 원본을 구성한다. C는 원본의 관계와 설명을 미리 생산·게시하고 요청 때 조회한다. A/B의 문맥 수명과 C의 게시 생산은 서로 다른 축이며 A+C 조합도 가능하다.

첫 의미 호출의 위치가 같아도 입력은 A의 유지 view, B의 최소 문맥, C의 게시 record로 다르다. 같은 `select-or-complete` 스키마에서 본문을 첫 호출에 완성하는 분기와 조회를 선택하는 분기도 다르다. 따라서 **A/B QA01의 0.342초 차이를 확정 우위로 보지도, 첫 호출 위치만을 이유로 구조적 동점으로 지우지도 않는다.** C의 긴 첫 반환도 관계 생산 자체의 필연적인 비용과 출력 분기·길이의 영향을 구별해야 한다.

기존 첫 의미 호출을 추적하면 A/B/C 각각 36회에서 평균 입력 token은 1,088/961/3,533, 평균 출력 token은 325/307/644였다. A는 첫 호출에서 본문 완성을 9회 제안했고 B는 3회, C는 36회 제안했다. C의 실제 직접 채택은 34회였다. A가 읽기를 생략한 일부 경로에서는 첫 반환 전에 더 긴 본문을 생성한다. 이 때문에 QA03의 재사용 이익과 QA01의 짧은 안내 반환이 같은 방향으로 움직인다고 가정할 수 없다. 이 분기별 집계는 서로 다른 사례 분포의 관찰이며 인과 효과의 분해가 아니다. [첫 호출 원값](../../../../../results/architecture-evaluation/current/four-dp-presentation-20261019/dp01/old-first-call-paths.json)을 보존했다.

기존 비교에서 A는 B보다 동일 자료의 답변 호출을 6회 줄였고, A/B 모두 host 종료가 관측된 같은 35목표의 QA03은 A 13.730초, B 14.242초였다. 전체 host 종료는 A 36/36, B 35/36이다. C는 전체 36/36 종료 관측에서 QA03이 12.364초로 A의 13.617초보다 짧았고, 별도 본문 의미 진단도 C 34/36, A/B 각각 30/36이었다. A/B의 본문 조건 누락 각 6건은 그대로 남는다. C의 첫 반환 전에 답변을 많이 완성한 분기와 게시 기록이 작용한 결과이며 QA02와 구별한다. 사전 생산을 포함한 C 비용은 A의 2.42배였다. 후속 자료 재사용이 있는 환경에서 A를 조건부로 추천하지만, 최고 우선순위 QA01에서 엄격한 전체 승자를 입증했거나 A만 필수 기능을 완벽하게 충족했다는 뜻은 아니다.

### 출력 정책 민감도와 보존 보완

추가 실행은 E3의 ABC×3회에서 기존 정책과 공통 adoption-only 첫 안내 정책을 비교한 총18회다. 추가 후속 호출까지 비용에 포함했다. E3은 첫 질문에 유지 view가 없고 후속 질문 직전 원문 정정으로 이전 view가 무효화된다. 실제 A/B 첫 요청 payload는 같은 정책·반복·질문으로 짝지은 12쌍 모두 같았다. 이 결과를 전체 네 사례의 A/B QA01 순위나 A의 유효 문맥 재사용 효과로 일반화하지 않는다.

각 행의 각 정책은 첫 응답6/6, host 종료6/6, QA02 6/6이며 API 오류는 없었다. 원값과 RSS는 [fresh 집계](../../../../../results/architecture-evaluation/current/four-dp-presentation-20261019/dp01/fresh-summary.json), 호출별 입력·출력은 [첫 반환 분석](../../../../../results/architecture-evaluation/current/four-dp-presentation-20261019/dp01/first-call-policy-breakdown.json)을 따른다. 첫 안내 분리는 구체적인 채택 의도를 반환하는 별도 호출이며, 뒤의 상세 처리와 본문 생성 비용을 없애지 않는다. A/B의 첫 안내 출력은 각각6호출270 token, C는6호출310 token이었다. 기존 C의 첫 출력6호출6,175 token보다 짧았다. C의 사전 관계 생산도 정책별로 독립 실행되어 그 변동이 비용·결과에 포함되므로 모든 차이를 응답 정책 하나의 순수 인과 효과로 계산하지 않는다.

**이 E3 범위에서는 QA01을 우선해 공통 첫 채택 안내를 분리하는 설계 방향을 권고한다.** QA03 증가와 추가6호출/안의 대가를 함께 부담하는 선택이다. A/B 문맥 구조를 선택한 효과나 모든 사례에 대한 검증 완료로 바꾸지 않는다. 정책을 바꿔도 본문 진단은 A/B 각각3/6, C6/6으로 같았다. A/B의 후속 납기 조건 누락 각3건은 유지된다.

실제 [첫 표시 예시](../../../../../results/architecture-evaluation/current/four-dp-presentation-20261019/dp01/first-handling-examples.json)는 평가 기준의 전달 기록과 Aster A 견적이라는 source 및 현재 revision의 요약 처리 채택을 표시했다. 완료를 주장하거나 질문의 사실 답변을 먼저 제공한 것은 아니다. A/B에는 `summarize`, C에는 더 긴 내부 intent 라벨이 그대로 노출됐다. 따라서 현재 callback 결과를 자연스러운 제품 UI 문장으로 부르지 않으며, 그 문장을 다듬은 이후의 끝단 지연도 이번에 측정하지 않았다.

이 판본의 QA04는 다시 측정하지 않았다. QA06 최고 동시 RSS는 A 41.189→40.124MB, B 39.993→40.157MB, C 42.254→43.074MB였다. 작은 관측 변동으로 유지 문맥이나 출력 분리의 일반적인 메모리 우위를 확정하지 않는다.

[저자 원문 대조](../../../../../results/architecture-evaluation/current/four-dp-presentation-20261019/dp01/content-review.md)는 고정36본문을 검토했다. C의 원래 literal 채점은 기존3/6·첫 안내 분리2/6이며 raw에 보존한다. 기존 날짜·단위 동등표현 판정과 원문 대조는 각6/6이었다. literal 점수, 동등표현 점수와 저자 판정을 하나의 숫자로 덮어쓰거나 QA02로 옮기지 않는다.

기존 A2 변경 조각 갱신은 정정 사례3회에서 원문 읽기12→9회, 모델 호출12→12회, QA03 21.822→21.433초, 비용 $0.0148424→$0.0145860이었다. 본문 충족3/6은 개선되지 않았다. 원문 재조회를 줄였지만 큰 모델 지연·비용 이익은 확인하지 못했다.

**A를 쓰는 경우 A2는 정정 때 원문 재조회량을 줄이는 보완으로 한정 적용한다.** 정정 의존성을 확인하고 변경 조각을 읽은 뒤 전체 근거의 현재성을 다시 검증하는 비용을 포함한다. 본문 누락을 해결한 보완으로 소개하지 않는다.

A의 단일 passage가14KB 예산을 넘는 구현 누락은 필수 기본 수정으로 분리한다. 선택적8KiB 보존과 locator인 A3는 교정된14KB 기준과의 자원 교환으로만 비교한다. native 경계·실제 응답 재생 결과를 새 모델 정확도·지연 개선으로 쓰지 않는다.

정본은 [A3 재생](../../../../../results/architecture-evaluation/current/four-dp-presentation-20261019/dp01/replay-summary.json)과 [native](../../../../../results/architecture-evaluation/current/four-dp-presentation-20261019/dp01/native/summary.json)다. **이번 짧은 문맥에서는 A3를 기본 보완으로 적용할 근거가 부족하다.** 더 큰 유효 문맥의 유지 비용이 실제 문제가 될 때 선택할 수 있는 절충안으로 남긴다.

큰 view를 locator로 바꾸면 다음 의미 호출에서 원문을 바로 활용하지 못해 직접 완료 대신 READ와 답변 호출이 추가될 가능성도 있다. 큰 범위의 검사는 native 검사였으므로 그때의 실제 모델 호출·QA03·QA05는 미측정이다. 보존 상태가 감소했다는 사실을 전체 모델 실행 경로의 최적화로 확대하지 않는다.

## 4. DP2: 후속 입력의 의미 판단 실행

A도 입력을 비동기로 보존한다. 새 의미 판단이 현재 VIA step 경계를 기다린다는 점이 B와 다르며, 외부 Agent 업무 전체가 끝날 때까지 기다리는 안이 아니다. B는 공통 대화 해석과 요청별 실행이 같은 모델 호출 예산을 경쟁한다.

호출 한도 2의 독립 질문에서 QA01은 A 13.388초, B 6.270초였고 B의 실제 API 구간 6.261초 중첩이 확인됐다. 한도 1에서 같은 질문의 완료는 13.429/13.087초였다. **호출 여유가 있고 입력이 겹치는 VIA에는 B를 선택한다.** 최상위 QA01의 관측 차이를 우선한 선택이다.

새 B1은 공통 input/source의 불변 참조와 빌린 payload 직렬화를 사용하고 요청별 mutable 상태·기록·revision 검사를 유지했다. 실제 기존 B 응답을 사용해 N=1/2/4, 네 사례×세 응답 기록, B/B1 총 72회를 재생했다. 첫 재생에서는 최종 결과·callback이 같았지만 E4 B1의 4개 session에서 U3가 먼저 채택되어 R1 상세 호출의 mutable snapshot이 달라졌다. ## 5. DP3: 화면과 발화의 지칭 결합

발표의 DP3은 저장소04다. A는 원본을 함께 읽어 대상 범위와 binding을 직접 생산한다. B는 화면·발화 후보를 별도로 생산하고 충분한 관계는 코드로, 모호한 관계는 의미 모델로 결합한다. 대상 범위가 부족하면 원 생산자가 원본을 확장한다.

기존 A의 첫 callback10/15, 목표 완료9/12, QA02 17/24와 B의15/15,12/12,24/24를 함께 제시한다. A의 빠른 관측 평균을 전체 속도 우위로 사용하지 않는다. 과거 ‘정확도를 먼저 선택했다’는 설명은 현재 고정 우선순위와 다르므로, 필수 응답·완료 관측 범위와 최고 QA의 미관측을 먼저 검토한다.

새 같은 실행 창의 기본 A/B 24회와 A2+A5/B4 보완 24회를 별도로 비교한다. 새 기본에서 A는 첫 응답 12/15, 목표 완료 10/12, QA02 19/24였다. B는 각각 14/15, 11/12, 22/24였다. 관측된 첫 응답의 평균은 A 9.268초, B 18.922초이며 양쪽 모두 미응답이 있다. 따라서 기존 B의 24/24를 구조의 보장으로 확대하거나 이번의 성공 평균만으로 A를 전체 속도 승자로 판정하지 않는다.

A의 미완료는 밀집 화면의 지시점이 주장한 범위 밖에 있는 좌표 오류와 페이지 복구 중 공급자의 HTTP 400 오류였다. 공급자 오류는 실패와 사용량 미확정을 남기고 예정된 미실행 항목만 이어서 수행했다. B의 정정 실패는 올바른 대상을 선택한 뒤에도 화면 생산자가 높이 650인 frame에 하단 794의 bbox를 반복 반환한 경우였다. 후보 소유권 분리만으로 좌표 계약의 정확성이 보장되지는 않았다.

## 6. DP4: Agent 간 업무 인계

발표의 DP4는 저장소05다. A는 위임 때 목적별 자료를 구성하고 B는 공개 사건에서 업무 기록을 미리 생산한다. C는 필수 목표·조건·수행 범위를 VIA가 전달하고, 상세 자료의 선택 읽기를 실제 지원하는 수신자에게 맡긴다. 비공개 Agent 기억의 이동은 어느 안의 기능도 아니다.

**QA01의 우열은 미확정이며, 읽기를 지원하는 수신자 조건에서 QA03·비용의 관측 이익을 근거로 C를 조건부 추천한다.** 같은20개 첫 callback 평균은 A4.307/B4.409/C4.327초다. 처음에는 공통 채택 함수를 이유로 구조적 동점이라고 판단했으나 실제 요청을 대조하면서 정정했다. 첫21호출의 입력 token 합계는 A15,318/B41,002/C13,722, 출력은3,720/3,828/3,690이었다. B의 유효 업무 기록 원문과 A의 이전 읽기 원문이 첫 해석에도 들어가므로 C와 입력 경로가 다르다. 작은 관측 차이를 확정 우위나 구조적 동점으로 바꾸지 않는다. 이 권고는 최고 우선순위 QA01에서 승자를 입증한 결과가 아니다. QA02는 비적용이다.

[실제 첫 요청63개 대조](../../../../../results/architecture-evaluation/current/four-dp-presentation-20261019/dp05/basic-prefix-boundary-audit.md)에서 같은 목표의 A/C 요청은15/21쌍 같았지만 A/B와 B/C는 각각0/21쌍이었다. 공통 코드 위치와 동일한 모델 입력은 서로 다른 조건이다.

모든 안이 완료한16목표에서 VIA 시간은 A10.565/B12.299/C4.213초, 전체 경과시간은31.372/31.406/23.532초였다. 수신자 시간을 제외해서만 생긴 이익으로 설명하지 않는다. 전체21목표의 완료20/19/19와 실패도 유지하므로 전체 성공률 우위는 주장하지 않는다.

B의 본문 충족15/18은 C12/18보다 높았지만 별도 내용 진단이며 QA02가 아니다. 고정 QA 순서의 승리로 바꾸지 않는다. 전체 비용은 A $0.1018408/B $0.2886828/C $0.0757928이며 B의 준비51호출을 포함한다. C는 읽기 도구와 접근 계약을 지원하는 수신자라는 조건이 있고 세 안 모두 본문 오류가 남았다.

C는 적용 QA에서 상대적 열세가 입증되지 않아 약점을 만들어내지 않는다. C1은 이미 채택된 필수 조건의 provenance 원문을 미리 제공하는 기능 취약점 보완이다. C2는 정확히 같은 권한·판본·범위의 실제 읽기 기록을 재생하여 반복 I/O와 보존 상태를 비교한다. 독립 보완이며 C1+C2 실행 결과로 합치지 않는다.

### C1: 채택된 조건 원문을 최초 인계에 제공

새 C/C1 비교는 E3×3회, 각9개 인계다. 양쪽에 같은 `condition_source_refs`가 있으며 C1만 다음 위임 목적을 알기 전에 현재 조건 원문 1~2행을 읽어 최초 인계에 붙였다. 정답 제품이나 미래 목적의 요약을 추가한 것이 아니다. **조건 provenance가 이미 있다는 전제**이며 upstream에서 그 연결을 새로 만드는 비용은 미측정이다. 기존 전체 C 기본 비교를 다시 실행한 결과로 바꾸지 않는다.

QA04는 이번에 새로 측정하지 않았다. raw literal/기존 동등표현 점수는 각각 C4/9, C1 7/9로 저자 본문 대조와 다르다. [별도 집계](../../../../../results/architecture-evaluation/current/four-dp-presentation-20261019/dp05/fresh-summary.json), [메커니즘 분석](../../../../../results/architecture-evaluation/current/four-dp-presentation-20261019/dp05/mechanism-breakdown.json), [본문 대조](../../../../../results/architecture-evaluation/current/four-dp-presentation-20261019/dp05/content-review.json)를 유지한다. 독립 담당자가 저자 판정을 미리 받지 않고 실제 메일6개를 대조한 결과는 C 충족1/모호2, C1 충족3으로 일치했다. 18개 전체의 독립 검토는 아니다.

C1의 입력 전 읽기는3회, 전체 파일 읽기 요청1,848byte, 로컬 읽기 구간 합계0.201ms, 첨부 상태 최대 직렬화323byte였다. 수신자의 조건 원문 읽기는2→0회지만 prefetch를 합친 전체 원문 읽기는20→21회다. 양쪽 모두 모든 인계가 수신자 READ→result 경로였고 호출 생략은 없었다. C의 복구1호출을 포함하면 전체 비용이 감소하지만, 그 호출을 별도 제외하면 C1 비용이 더 크다. 전체 경과도 같은8목표에서 약0.987초 늘었다. 따라서 본문 개선 관측을 시간·모델 비용 최적화로 설명하지 않는다.

C의 미표시1건은 원문을 읽고 만든 초기/복구 결과 모두 fact15개로 공통 host 상한14를 넘긴 사례다. 동결된 수신자 프롬프트에는 숫자14가 안내되지 않았다. 실제 실패 원인은 이 수량 계약 불일치이며 원문 부족이나 의미 오답으로 분류하지 않는다. 사후 수정·재실행 없이 실패와 복구 비용을 보존했다.

첫 해석의 실제 API 요청9쌍은 같았지만 출력은 달랐다. C의 두 번째 반복 메일 첫 안내는 ‘가격이 같을 때’ 조건을 유지보수 우선으로 강화했다. **callback9/9은 올바른 첫 구체내용9/9을 확정하지 않으며, 잘못된 첫 안내1건이 확인됐다.** C1의 원문은 이 첫 안내 호출에 들어가지 않는다. 뒤의 본문 차이도 모두 prefetch의 고립된 인과 효과로 계산할 수 없다. [첫 안내 대조](../../../../../results/architecture-evaluation/current/four-dp-presentation-20261019/dp05/prefix-review.json)를 함께 읽는다.

**C1은 기존 조건 provenance가 있고 인계에서 그 조건을 잃을 위험을 줄여야 하는 경우에 한정 적용한다.** 이번 본문에서는 가격 동률 전제를 더 명확히 유지했다. 전체 제품의 정확성, 새 provenance 생성 비용 또는 지연 개선을 입증한 선택은 아니다.

### C2: 반복 읽기 cache는 기본 적용 보류

[C2 실제 응답 재생](../../../../../results/architecture-evaluation/current/four-dp-presentation-20261019/dp05/replay-summary.json)의 12쌍에서 모델 payload와 최종 본문은 모두 같았다. 실제 `read_to_string`은 34→22회로 줄고 cache hit 12회를 확인했다. 그러나 전체 원문 제공 구간의 합은 7.602→8.784ms로 늘었다. E3 반복 읽기만 줄었으며 다른 사례에는 hit가 없었다. cache 직렬화 상태는 최대 14,790 byte가 추가됐다. 전체 Python+Rust 최고 RSS 51.429→51.298MB의 작은 변동을 cache가 메모리를 줄인 효과로 해석하지 않는다. **C2는 이번 입력에서 지연 개선 근거가 없어 기본 적용을 보류한다.** 큰 원문이나 비싼 저장소 접근이 반복되는 조건에서 재검토할 수 있다.

## 7. 대안을 다시 선택할 조건

| 발표 DP | 현재 권고의 적용 조건 | 다른 안을 검토할 조건 |
| --- | --- | --- |
| DP1 근거 공급 | 유효 원본에 대한 후속 질문이 반복돼 A의 상태를 실제 재사용함. QA01 우열은 미확정 | 독립 요청·주제 전환으로 재사용이 적으면 B. 여러 요청이 같은 관계를 반복 소비해 생산 비용을 회수할 수 있으면 C 또는 별도의 A+C 비교 |
| DP2 의미 판단 실행 | 독립 입력이 앞선 VIA 판단과 겹치고 공통 호출 한도에 여유가 있음 | 한도1·짧은 순차 상호작용에서는 B의 중첩 이익이 사라지므로 A의 단순한 실행 경로를 다시 비교 |

이 조건표는 관측된 방향과 구조가 작동하는 전제를 연결한 판단이다. 측정하지 않은 A+C 조합, 읽기 미지원 수신자 또는 전체 제품의 성능을 새 실험 결과로 표시하지 않는다.
