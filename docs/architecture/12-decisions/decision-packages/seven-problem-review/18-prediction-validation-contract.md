# 구조 예측의 성립 조건과 반대 조건 재검증

2026-10-19 / 사용자 승인에 따른 새 구현, 시험과 측정 계약

상태: DP별 조건 진단의 사전 계획과 부분 실행 보존. 사용자가 QA별 공통 시험의 공정성을 지적하여 DP2의48/72회 이후 추가 호출을 보류했다. [17 발표 결과 §9](17-presentation-results.md#93-사용자-지적에-따른-공통-대표-평가와-조건-진단의-구분)의 방법론 검토를 따른다. 아래 사전 가설과 동결 이력은 그대로 보존하며 모든 DP에 같은 입력을 적용한 공통 대표 결과로 승격하지 않는다. 기존 14, 15, 16, 17의 수치와 원시 결과는 보존한다.

## 1. 요청과 비교 범위

사용자는 전체 DP와 방안에 대해 예측이 성립하는 조건과 성립하지 않는 조건을 명확히 하고, 필요한 테스트와 구현을 보완해 다시 측정하도록 승인했다. 사전에 기대한 순위를 만들기 위한 입력 선별이나 실패 제외는 하지 않는다. 예측의 미지지와 미확정도 결과다.

발표 DP1은 저장소01의 A/B/C, DP2는 저장소02의 A/B, DP3는 저장소04의 A/B, DP4는 저장소05의 A/B/C다. 기본 10개 방안을 같은 DP 안의 같은 외부 조건에서 비교한다. 선택 후 tactic과 화면 생산 의존성의 교차 구성은 별도 표시한다. 기본안의 실제 기능 누락을 고치는 일은 tactic의 성과로 세지 않는다.

QA01 첫 응답, QA02 지칭 집합 정확도, QA03 VIA 처리시간, QA04 실제 변경 Rust 모듈 수, QA05 전체 모델 비용, QA06 로컬 메모리의 의미와 우선순위를 유지한다. 이전 Core-ASR QA-09/19/29/39로 재명명하지 않는다. N-R, N-H와 본문 조건 충족은 별도 기능 진단이다. accepted ADR과 Reference Architecture의 채택 상태는 바꾸지 않는다.

## 2. 기존 데이터와 합치지 않는 결정

**이번 주 비교표는 새 동결 계약으로 실행한 데이터만 사용한다.** 기존 데이터는 독립된 역사 비교와 재현성 참고로 남긴다.

| 판단 요소 | 현재 차이 | 처리 |
| --- | --- | --- |
| 첫 응답 정책 | DP1의 공통 채택 안내와 기존 select-or-complete 분기가 다름 | 기존 QA01/03을 새 표본에 합치지 않음 |
| 시험 모집단 | 유효 재사용, 정정, 무재사용, 동시성, 생산 비용 회수 조건을 명시한 새 사례 | 기존 사례 반복을 새 독립 사례처럼 세지 않음 |
| 구현 | 발견한 공통 기능 누락 수정과 계측 보완, 화면 생산 의존성 구체화 | source 및 binary hash가 다른 세대는 별도 |
| 화면 계약 | 기존 pixel, 정규화, 새 helper 구성을 구분해야 함 | 같은 이름의 A/B라는 이유로 결과를 합치지 않음 |
| 외부 서비스와 기기 상태 | 실행 창, 원격 서비스 지연과 로컬 helper 배치가 다를 수 있음 | 같은 창의 방안 교차 실행과 조건별 비교를 사용 |
| QA04 | 새 소스에 실제 독립 변경 과제를 다시 적용 | 기존 모듈 수를 새 측정으로 복사하지 않음 |

같은 옛 사례를 새 실행기로 재실행하면 그 행은 `BRIDGE`로 표시한다. 그것은 구현 세대 간 설명용 비교이며 주 모집단에 추가하지 않는다. 기존 응답 재생은 `REPLAY`, 자료 구조 검사는 `NATIVE`로 구분한다. 서로 다른 증거 종류를 실제 모델 호출 횟수, 정확도 또는 지연 표본에 합치지 않는다.

향후 통합을 검토하려면 후보와 dependency 버전, 정책, fixture/oracle, endpoint, timeout과 repair, 자원 한도 및 표본 가중이 동등하고 실행 창의 교환 가능성을 설명할 수 있어야 한다. 이번에는 이 조건을 충족하지 않는다. 단순히 n을 키우기 위한 합산은 채택하지 않는다.

## 3. 방안별 이익이 성립할 조건과 반대 조건

| DP와 기본안 | 이익이 성립할 조건 | 이익이 사라지거나 손해가 될 조건 | 반드시 확인할 실제 경로 |
| --- | --- | --- | --- |
| DP1 A 유지 근거 | 실제 읽은 유효 원문이 후속 질문에 다시 필요하고 추가 탐색을 대체 | 최초 질문, 다른 주제, 원문 정정 또는 철회, 유지 입력이 불필요하게 큼 | 유효 view 사용, 생략한 READ와 답변 호출, 첫 호출 입력과 출력 |
| DP1 B 요청별 구성 | 필요한 근거가 좁고 요청 사이 재사용이 적음 | 같은 자료를 계속 다시 읽거나 관계를 재구성해야 함 | 요청별 구성 범위와 반복 읽기, 과거 전달 출처 연결 |
| DP1 C 선생산 근거 | 같은 기록을 여러 질문이 실제 소비하고 생산이 유효한 원본에 근거 | 미사용 생산, 짧은 소비 수명, 정정 후 재생산, 원문 보완이 계속 필요 | 준비 비용, 기록 소비와 직접 완료, 교체 전에 미사용된 기록 |
| DP2 A 진행 경계 대기 | 새 독립 입력이 없거나 호출 슬롯이 하나이고 앞 판단의 재사용이 큼 | 긴 VIA 판단 도중 무관한 새 입력 도착 | 경계 대기, 현재 revision과 완료 처리, 실제 재사용 |
| DP2 B 요청별 실행 | 독립 입력이 겹치고 동일 총 호출 한도 안에 여유가 있음 | 슬롯 포화, 짧거나 없는 앞선 작업, 의존 정정의 재결합 비용 | 실제 API 중첩, 독립/정정 관계, 원래 목표와 새 목표의 완료 |
| DP3 A 원본 공동 판단 | 원본과 발화를 직접 결합할 수 있고 별도 생산이 필요하지 않음 | 작은 반복 요소, 복잡한 공간 관계와 공동 판단의 기하 오류 | 처음 채택한 집합, 위치 근거, 재판단과 실제 표시 |
| DP3 B 후보 생산 후 결합 | 충분하고 올바른 화면 후보가 혼동을 줄이거나 같은 판단에서 재사용 | 후보 누락, 잘못된 범위, 자유 영역 표현 한계, 생산과 확장 비용 | 원본 보존, 후보 품질과 coverage, 확장, code/model 결합 |
| DP4 A 목적별 전달 | 위임이 드물고 필요한 원문이 이미 확보됐거나 목적에 좁게 구성 가능 | 매 인계마다 같은 자료를 다시 가공 | 실제 확보 원문의 직접 사용, 구성/재조회/추출 비용 |
| DP4 B 업무 기록 선생산 | 같은 유효 기록을 여러 인계가 소비해 준비 비용을 회수 | 인계 없음, 단발 위임, 잦은 갱신, 긴 기록 추출이 계속 필요 | 생산/갱신/미사용 비용, DIRECT 사용, 남은 추출 호출 |
| DP4 C 목록과 원문 접근 | 수신자가 범위 읽기와 권한/판본 계약을 지원하고 필요한 자료를 선택 | 읽기 미지원, 반복 원격 읽기, 누락 조건 또는 큰 serving 부담 | 수신자 읽기와 전체 비용, VIA serving, 실제 본문과 조건 출처 |

모든 방안에 같은 허용 원본과 권한, 같은 사용자 목표를 준다. 준비가 끝난 warm 조건은 명시적으로 구분한다. 특정 producer가 끝날 때까지 사용자 입력을 몰래 지연시켜 비용을 감추지 않는다. 수신자 읽기 미지원은 C의 적용 제약으로 남기며, 지원하지 않는 실행을 성공한 시간 표본으로 만들지 않는다.

## 5. 측정과 판정 규칙

- 같은 DP의 모든 기본안에 같은 사례와 반복을 적용하고 방안 순서를 교차한다. 최초 계획은 조건당 세 반복이며 사례별 정확한 수량과 순서를 실행 전에 plan에 고정한다. 같은 사례 세 반복을 서로 다른 사용자 사례 세 개라고 하지 않는다.
- QA01/03은 기존의 실제 callback/host 완료를 관측한 개별 입력/목표 평균과 관측/예정 분모를 유지한다. 실패를 제거한 속도 승자나 임의 벌점 시간을 만들지 않는다. 같은 성공 교집합은 사후 메커니즘 설명으로만 추가한다.
- QA02는 해당 표현/revision의 최초 채택 집합과 필요한 판본의 exact match다. DP1과 DP3에 적용한다. 본문 조건과 채택 gate 통과는 별도다.
- QA04는 C01, C03과 각 DP의 기존 기능 과제 두 개를 새 동결 소스의 독립 복사본에 각각 실제 구현하고 수용 검사한다. 모듈 수 평균과 과제별 diff를 공개한다. 새 과제를 추가한다면 기존 네 과제 점수와 합치기 전에 새 분모를 명시한다.
- QA05는 실제 usage와 고정 비교 단가를 적용하며 준비, 미사용, 폐기, 실패/복구, 수신자 호출을 포함한다. 사용량 미확정은 0이 아니며 보수적 예약 상한을 별도 공개한다. 이전12episode 합계와 새 모집단 합계는 크기가 다르므로 직접 절감률을 계산하지 않는다.
- QA06은 동일 시각의 지정 로컬 프로세스 RSS를 표본 관측하며 실제 local helper도 포함한다. 상태 byte, 소유 할당, 저장 파일, cloud 가중치, 실제 제품 전체 RAM을 구분한다. 작은 차이는 allocator와 표본 변동을 넘는 구조 이익으로 확정하지 않는다.
- 각 조건의 paired 원값과 범위를 제공한다. 세 반복은 작은 유한 사례의 메커니즘 검증이며 일반 사용자 분포나 통계적 우월성 입증이 아니다. 조건을 합친 전체 평균과 조건별 해석을 모두 남기고 유리한 조건만 전체 대표로 바꾸지 않는다.
- 조건부 지지는 예상 방향과 관련 실행 경로가 함께 확인된 경우다. 반대 관측, 메커니즘 미발동, 상쇄, 사전 순위 없음, 관측 동점, 미확정, N/A, 미측정을 구별한다. 합격 비율을 만들기 위해 모호한 예측을 사후 확정 순위로 바꾸지 않는다.
- 한 DP의 실제 시간 측정 창에 다른 DP의 모델 실행이나 대규모 local helper 계산을 겹치지 않는다. 공통 총 호출 한도는 각 plan대로 유지한다.

코드 개발과 실행은 사용자 지정 GPT-6.1 Sol High 담당이 수행한다. 주 담당은 계약, 범위 검토, 결과 통합과 독립 대조를 맡는다. 관리 예산은 우선 전체 $4이며 DP1+DP4 $1.60, DP2 $0.80, DP3 $1.40, 미배정 $0.20으로 둔다. provider usage와 미확정 예약을 함께 관리한다. 이것은 이번 유한 캠페인의 실행 한도이며 과거 예산과 결과를 덮어쓰지 않는다.

원시 입력과 모델 응답, 실패, source/fixture/oracle/binary hash, 실행 명령, 관측 환경, 조건별 모집단과 모델 호출 원장을 보존한다. 결과가 예상과 달라 재구현이 필요하면 현재 phase를 보존하고 변경 이유와 새 freeze를 먼저 남긴다. 관련 없는 AGENTS, workplan, 04-50과 work/ 변경은 포함하지 않는다.

## 7. DP4 formal 동결 전의 조건 추가

DP2 formal 실행 중, DP1/DP4의 formal 호출 전에 읽기 전용 검토를 했다. DP4의 기존 낮은/높은 재사용 조건은 모든 안이 같은 원문을 실제 확보한 상태다. 이는 A의 직접 재사용도 가능한 강한 대조 조건이다. 반면 B의 준비 기록을 최초로 소비할 때의 반복 경로는 단발 조건만으로 충분히 분리되지 않았다.

따라서 **공통 사전 원문 획득이 없는 준비 기록 반복 소비** 조건을 여섯째로 추가한다. 기존 높은 재사용 조건과 원본, 세 인계 목적 및 요청 사실을 같게 하고 공통 acquire 사건만 제거한다. A가 첫 인계에서 실제 읽어 확보한 원문은 이후 재사용할 수 있다. A의 후속 재사용을 차단하지 않는다. B의 추출 호출이나 비용이 계속 남아 이익이 나타나지 않아도 그대로 보존한다.

이 추가로 DP1은 5조건×3안×3회=45trajectory, DP4는 6조건×3안×3회=54trajectory다. 합계99회이며 같은 $1.60 상한을 유지한다. 이전 다섯 조건과 모든 예정 분모를 유지한다. DP2의 72회 계약, 코드 및 입력 동결은 바꾸지 않는다. 추가 이유는 아직 미측정인 DP4의 조건 범위를 보강하는 것이며 실제 결과를 본 뒤 유리한 모집단으로 교체하는 것이 아니다.
