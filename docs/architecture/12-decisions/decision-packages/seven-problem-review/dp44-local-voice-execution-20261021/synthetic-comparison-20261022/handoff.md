## 이번 자료의 핵심

- A는 응답별 생성 실행과 오디오를 독립 유지하고, B는 현재 발화의 생성 실행을 소유한다. 두 안 모두 유효한 기존 오디오를 재사용한다.
- Agent가 문안을 만든다. DP2 해석, 같은 입력 처리, 판본과 권한 검사, UI, 로컬 감지 및 중단 경로는 공통이다. 화면과 음성은 독립이다.
- 8사례군, 유형별 10개 작성 변형이다. 평가 입력 80개, 지칭 표현 120개, QA03 목표 90개다. 원래 보고서 목표 10개와 새 전달 목표 80개를 구별한다.
- 준비 활동 80개와 미사용 구판, 취소 후 생성, 재개 문맥을 비용 및 메모리에 포함한다. 준비 활동을 평가 입력 분모에 더하지 않는다.
- 기본 권고는 A다. 음성 QA01을 우선하면 선행 준비가 근거다. 기존 화면 QA01을 유지해도 화면과 고정 정확도는 동점이고 QA03에서 A가 유리하므로 이번 작성 범위에서는 A를 권고한다. 사용자 채택이나 ADR 변경은 아니다.
- B의 이익은 폐기될 음성 생성비와 예상 변경 범위다. RAM 차이는 약 0.15 MB로 작다. S05에서 B가 다시 준비할 때는 미생성 후반만 요청하며 A가 소액의 재개 문맥 비용을 절약한다.

## 통합 시 반드시 유지할 경계

| 필드 | 의미와 통합 처리 |
| --- | --- |
| `qa01_display_s` | 기존 공통 v2 QA01과 같은 화면 종료점. 80개 새 입력의 첫 구체적 표시 |
| `qa01_voice_s` | 같은 시작에서 실제 음성 출력에 대응하는 가상 사건. 추가 종료점으로 별도 열을 유지. 화면 값과 평균하지 않음 |
| `deliveries` | Agent source 발생부터 전달까지의 별도 진단. 사용자 입력 80개에 섞지 않음 |
| `qa02`, `qa07` | 같은 올바른 DP2 결과를 고정한 제어 fixture. 100%를 실제 모델 성능 또는 다른 DP보다 높은 정확도로 해석하지 않음 |
| `goals` | 원래 목표 시작과 terminal 목록. 정정 목표를 현재 입력 시점으로 잘라내지 않음 |
| `nodes` | 실제 경과시간 가정과 VIA 포함 여부. 외부 duration을 0으로 투영하되 의존 관계 유지 |
| `changes` | 같은 C01~C06 완료 조건, 예상 concept 모듈. B도 Turn Execution과 Turn Audio Buffer를 별도 모듈로 셈 |
| `usage` | VIA 가상 사용량과 공통 v2 가상 요율. 수신 Agent 내부 비용은 이 자료에서 미모델링 |
| `memory` | 동일 시점 base, audio, metadata 합계. 원격 가중치와 KV 제외 |

profile은 `VOICE-DELIVERY-CLOUD-SYN-1.0`이다. 공통 기반 RAM 560 MB와 일부 시간식, 요율을 공유해도 DP3 Voice/Screen profile과 동일한 제품 구성이 아니다. DP2/DP3/DP5는 고정 주변 기능이며 기존 A/B에 자동 매핑하지 않는다. 현재 자료를 별도 전달 층으로 통합하거나, 공통 workload로 다시 작성한다면 모든 해당 DP와 비교 구성을 그 조건에서 다시 계산한다. 개별 이익, peak, 비용을 합산해 결합 성능을 만들지 않는다.

QA03의 S08은 외부 도착을 기다리는 50ms 선행 여유 사례다. 물리 음성 이익은 50ms지만 외부 대기를 0으로 투영한 QA03에서는 생성과 의미 채택의 병행/직렬 차이가 더 크게 보인다. 계산 의미를 실제 wall-clock 단축으로 바꾸지 않는다.

공통 v2를 덮어쓰지 말고 새 dataset/registry 판본을 만든다. 같은 정의의 화면 QA01을 먼저 연결하고 음성 열은 별도 유지한다. QA01 공식 종료점을 바꾸는 결정이 있다면 다른 DP에도 같은 정의와 판본을 적용해야 한다. 기존 COMMON-28의 목표나 점수표를 이 묶음에 재사용하지 않는다.

## 검토와 남은 범위

오프라인 재산출로 DAG와 목표별 시간, 사용량, 분모, 동시 RAM, 음성 중첩과 구판 미재생, 같은 의미 fixture를 확인했다. Excel은 집계 수식과 요율 변경 시 재계산 및 원복을 확인하고 9개 시트를 렌더 검토했다. 실제 모델, 마이크, 장치와 제품은 실행하지 않았다. 네이티브 Windows Excel 검증과 별도 독립 검토는 수행하지 않았다.

통합 세션에서 인과와 분모, QA04의 일반화된 인터페이스 대안, 고정 정확도 fixture의 표시, 공통판과의 호환성을 독립 검토한다. 특히 QA04의 두 추가 변경을 공통 계약으로 흡수하면 A도 2.00으로 동점이 되는 민감도를 보존한다. HTML과 저장소 검사의 최종 상태는 산출물 안내와 발행 검증 기록을 함께 확인한다.
