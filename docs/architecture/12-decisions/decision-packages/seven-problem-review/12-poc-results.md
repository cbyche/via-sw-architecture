# 주요 DP 네 개의 초기 PoC 결과와 잠정 선택

2026-10-18 / 기본 120회와 보완·진단 15회 실행 완료 / 사용자 리뷰 후 측정·기능 계약 보완 필요

> **최신 해석은 [13 사용자 리뷰와 최소 재실험](13-poc-user-review-and-remeasurement.md)을 먼저 읽는다.** 재검토에서 QA01/03의 사실상 같은 표시·완료 사건, DP02의 Agent 알림 목표 모집단 오류, DP01의 근거 부족 뒤 필수 재조회 누락, DP05의 후채택 시작 경계를 확인했다. 아래 원시 수치와 초기 선택은 이력으로 보존한다. A/A/A/C와 A1을 네 DP의 최종 QA trade-off 결론으로 확정하지 않는다. 기존 32 PASS는 증거 정합성 검사이며 이 기능·측정 적합성 검토를 대신하지 않는다.

## 1. 비교 범위

현재 요청의 근거 공급 A/B/C, 후속 입력의 의미 판단 실행 A/B, 화면과 발화의 지칭 결합 A/B, Agent 간 업무 인계 A/B/C를 비교한다. 각 안에 같은 네 episode를 세 번 적용하는 총 120회 기본 비교다. 코드 개발, 코드 실행과 실제 모델 호출은 사용자가 지정한 GPT-6.1 Sol High 담당들이 수행했다. 의미 판단에 호출하는 모델은 별개인 `qwen3.7-plus-2026-05-26`이다.

이 문서의 선택은 작성한 입력과 아래 측정 범위에서의 초기 PoC 판단이다. 기존 참조 Architecture와 accepted ADR의 채택 상태는 유지한다. **10개 기본안의 120회와 선택안 보완 12회 및 시간 원인 진단 3회를 완료했다. 초기 선택은 01 A, 02 A, 04 A, 05 C 및 02 A1이었다. 사용자 리뷰 후 공통 완료 계약과 측정 경계를 보완하기 전 최종 선택을 유보한다.** 실제 호출·비용 기록과 기능·QA 비교의 완결성을 구별한다.

실제 Qwen 호출은 접속 확인과 smoke를 포함해 **579회**, 공개 정가 환산 비용은 **$0.7207640**이다. 모든 호출의 usage를 확보했고 초기 $5 상한 이내다. 코딩 담당 모델의 이용료나 실제 Alibaba 청구서 금액을 합친 값은 아니다. BASIC에는 실행기/JSON 오류가 없지만 의미 판단 B의 미응답 6건과 근거 공급의 별도 내용 조건 실패 9건이 있다. 보완 A4에는 JSON 출력 잘림 실패 2건이 있다. 이 실패를 결과에서 제외하지 않았다.

QA04의 동일 값은 이 PoC의 두 변경이 공통 adapter에 모였다는 결과다. 실제 Rust diff와 컴파일을 확인했고 호환 경로는 고정 계약 응답기로 검사했다. 모델 의미 정확도 재시험은 아니다. QA06에는 브라우저, 외부 실행 controller, 원격 모델 weight/KV가 들어 있지 않다. 작은 RSS 차이를 전체 VIA 제품의 메모리 우위나 Windows 512MB 요구 충족으로 해석하지 않는다. 모델 비용은 공개 정가에 따른 계산이며 실제 청구서 금액은 아니다.

기본 비교에서 DP05 A의 2회와 C의 3회는 짧은 실행 동안 두 프로세스 RSS의 동시 관측이 불완전했다. 나머지 기본안에는 이 누락이 없다. 표의 최대값은 확보된 표본의 최대 관측이며 누락된 순간의 peak를 추정한 값이 아니다.

음성 입력은 작성한 전사와 사건 시각으로 재생했다. 실제 ASR/TTS는 실행하지 않았다. 화면 지칭은 작성한 합성 PNG와 pointer/selection 기록을 실제 모델에 보냈다. 실사용 앱에서 수집한 화면은 아니다. 네 episode를 세 번 반복한 결과이며 서로 다른 사용자 12명의 시험은 아니다.

## 3. 근거 공급

### 기본 비교 36회

| 안 | QA01 ms | QA02 | QA03 ms | QA04 모듈 | QA05 USD | QA06 MB |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| A 대화별 유지 문맥 | 7,226.13 | 36/36, 100% | 7,226.17 | 1.5 | 0.0368480 | 39.240 |
| B 요청별 근거 구성 | 7,589.08 | 36/36, 100% | 7,589.14 | 1.5 | 0.0355520 | 39.174 |
| C 관계 근거 생산과 게시 | 6,957.52 | 32/36, 88.89% | 6,957.59 | 1.5 | 0.1224032 | 39.977 |

**초기 PoC에서는 A를 선택했으나 현재 최종 선택은 유보한다.** A/B 모두 지칭 36건이 맞았고 A의 평균 표시 proxy는 B보다 362.95ms 낮았다. 그 대신 사건 창 전체 모델 비용은 B보다 $0.001296, 약 3.65% 높았다. QA04는 동점이다. 추가 감사에서 A/B의 본문 재조회와 응답 완료 결함을 확인했으므로 아래 식별 성공을 완결 기능 정확도로 확대하지 않는다.

전체 평균의 원인은 사례마다 다르다. 같은 자료의 후속 질문 E1에서 A는 5,200.07ms, B는 6,876.41ms였다. 새 주제로 전환하는 E2에서는 A 6,816.44ms와 B 6,850.82ms로 가까웠고, 비용은 A $0.014858와 B $0.012272였다. 따라서 같은 근거의 후속 사용이 많은 조건에서 A를, 주제 전환과 좁은 일회성 요청이 많은 조건에서 B를 선택할 이유가 남는다.

**대상·판본 식별 성공이 요청한 요약 내용의 성공은 아니다.** 독립 검토에서 E3 q2의 사전 oracle에 별도 `semantic_checks`가 있었지만 처음 계산기에 집계되지 않았음을 발견했다. 실제 표시 답변에는 금액 1,180,000, 36개월과 11월 1일의 필수 사실이 모두 빠졌다. 기본 ABC의 9회와 A2의 3회 모두 이 내용 조건을 충족하지 못했다. 전체 36개 필수 marker의 관측은 0개이며, 다른 사례에는 같은 사전 내용 조건이 없어 성공 분모에 넣지 않았다. 정확 문자열 검사는 표기 차이를 놓칠 수 있지만 이번 원문은 지칭 표현을 반복하며 세 사실 자체를 제시하지 않았다. 새 모델 평가를 한 것은 아니다. QA02 대상·판본 점수와 기록된 시간은 유지하지만, **이 출력 시각은 올바른 요약이 전달된 시각이 아니며 근거 공급의 전체 요약 기능이 완성됐다고 결론내리지 않는다.** [내용 조건과 실제 답변](../../../../../results/architecture-evaluation/current/four-dp-qwen37-20261018/semantic-conditions.md).

C는 준비된 상태의 요청 지연이 A보다 268.61ms 낮았지만 전체 모델 비용은 A의 약 3.32배였고 E4에서 4건 틀렸다. 실제로 참조한 두 원본 대신 그 원본에 관한 과거 설명을 추가하거나 대체하는 오류였다. 출처와 revision이 유효하다는 검사가 사용자가 지칭한 대상의 정확성까지 보장하지는 않았다. [실패 원문](../../../../../results/architecture-evaluation/current/four-dp-qwen37-20261018/referent-failures.md).

C의 생산은 다음 요청이 들어오기 전에 완료되는 시험 조건이다. 따라서 위 요청 지연에 준비 시간을 무료로 숨기지 않도록 요청 전 생산 시간과 전체 비용을 함께 읽어야 한다. 생산 중 즉시 새 요청이 도착하는 경우의 응답 지연은 이번 표에서 측정하지 않았다.

### 선택 후 보완

기존 **A2 변경 조각 갱신**을 E3에 적용한다. 원본이 바뀌면 유지한 작업 근거 view를 비우던 A에 대해, 변경 원본에 의존하는 조각만 무효화하고 다른 유효 근거는 유지한다. 기본 A도 최근 실제 전달 이력은 보존하므로 대화 이력 전체의 삭제를 고치는 변경은 아니다. 별도 scratch 구현과 freeze를 사용하며 기본 E3의 세 반복과 보완 E3의 세 반복만 비교한다. 재조회가 줄어도 입력 token이나 모델 시간이 늘 수 있으므로 보완 효과는 실제 결과로 판정한다.

## 4. 후속 입력의 의미 판단 실행

### 기본 비교 24회

| 안 | QA01 ms | 내용 있는 응답 / 예정 응답 | QA03 ms | QA04 모듈 | QA05 USD | QA06 MB |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| A 한 대화 실행과 step 경계 반영 | 11,791.96 | 30/30 | 11,792.04 | 1.5 | 0.0528276 | 39.092 |
| B 공통 대화와 요청별 해석 실행 | 9,383.16 | 24/30 | 9,383.29 | 1.5 | 0.0535072 | 39.191 |

**초기 PoC에서는 A를 선택했으나 현재 최종 선택은 유보한다.** 초기 설계 권고는 B였지만 B는 세 번의 정정 episode마다 정정 입력 U2와 수정된 원래 요청 R1에 `answer:null`을 반환했다. 미응답과 미완료가 각각 6건이고 A는 0건이었다. B의 전체 지연 평균은 응답이 있는 24건만의 값이므로 A보다 약 2.41초 빨리 모두 완료했다고 해석할 수 없다. 기본 정정 처리·복구를 보완해 B의 시간·비용을 다시 비교할 필요가 있다. 또한 위 QA03에는 새 사용자 목표가 아닌 Agent 질문 표시 3건이 포함된 모집단 오류가 있어 정식 완료시간으로 확정하지 않는다.

응답 누락이 없는 사례에서는 실행 조건에 따른 손익이 관측됐다. 긴 판단 도중 별도 입력이 들어오고 동시 호출 한도가 2인 E2의 평균 첫 응답은 A 11,738.60ms, B 6,069.71ms였다. 같은 입력에서 한도가 1인 E3는 A 14,168.68ms, B 20,344.88ms로 방향이 바뀌었다. 호출 여유가 없을 때 실행 분리만으로 실제 모델 대기를 없앨 수는 없다. 다만 관측 차이에는 달라진 문맥과 실제 출력 길이 및 서비스 지연이 함께 들어 있다.

겹침 없는 E1은 A 5,888.99ms, B 8,804.75ms였지만 이 구현에서는 양쪽이 같은 직렬 처리와 문맥 구성 방식을 사용한다. 최초 요청은 같지만 뒤 문맥에 들어가는 앞 모델의 실제 반환 내용은 달라질 수 있다. 이 차이를 구조적 이익으로 세지 않는다. B의 빈 응답 역시 이 구현과 모델 계약에서 관측한 실패이며, 요청별 실행 구조 자체가 정정을 처리할 수 없다는 결론은 아니다.

겹치는 입력에서 A는 완료된 앞 step의 아직 게시하지 않은 판단까지 후속 문맥에 전달하고, B는 공통 상태를 전달하며 앞 판단을 요청 실행에 남긴다. 양쪽 모두 같은 전체 원본 문서에 접근한다. 원본을 B에서 숨겨 만든 비교는 아니다.

추가 진단 N-R은 입력과 기존 Request/Task/Agent 질문의 연결을 검사한다. 고정 E2/E3 발화는 “기존 작업은 계속하고, 별도로 TCP와 UDP 차이를 설명해 달라”는 두 의도를 갖지만 고정 정답은 발화 전체에 단일 `NEW` 관계를 요구한다. `FOLLOWUP` 판단은 앞 절의 의미와도 연결되므로 이 N-R 점수 전체를 순수 모델 오판이나 구조의 정확도 차이로 단정하지 않는다. 고정 점수는 유지하고, 실제 별도 질문 답변 누락과 빈 응답을 따로 기록한다.

고정 N-R은 양쪽 **21/27, 77.78%**다. 혼합 발화 여섯 건을 제외한 사후 진단은 양쪽 **21/21**이지만 원래 점수를 대체하지 않는다. 전체 답변을 확인한 결과 TCP/UDP 설명 누락은 양쪽 0/6이었다. B의 빈 정정 답변은 별개의 실제 실패다. [진단 원문과 입력별 시간](../../../../../results/architecture-evaluation/current/four-dp-qwen37-20261018/dp02-diagnostics.md).

### 선택 후 보완

기존 **A1 제한된 별도 질문**을 E2에 적용한다. 모델이 도구 없는 짧은 독립 질문으로 처리할 수 있다고 판단할 때 제한된 side 답변을 만들고 실제 전달 이력에 반영한다. 그렇지 않으면 기본 대화 실행으로 돌려보낸다. 전체 호출 한도는 2로 유지하고 원래 요청의 완료 지연도 함께 계산한다. 별도 실행을 장기 요청 worker로 확대하는 변경은 이번 A1에 포함하지 않는다.

기본 24회에서 A/B 모두 **15/24, 62.5%**였다. 세 반복 모두 밀집 화면은 0/2, 그래프 자유 범위는 0/1, 페이지 이동은 1/1, 부분 정정은 4/4의 같은 결과였다. 당시 화면을 보존한 페이지 이동과 이전 결과의 유효성을 검사하는 정정 경로는 성공했으나, 작은 시각 요소와 자유 범위를 해석하는 정확도는 부족했다.

**이번 구현의 작업 기준으로 A를 선택한다.** 같은 정확도에서 후보 생산과 결합을 추가한 B의 비용과 지연을 감수할 이익이 확인되지 않았다. 이는 A의 62.5% 정확도가 제품 요구에 충분하다는 뜻은 아니다. B의 화면 후보 생산자는 이번 PoC에서 같은 Qwen vision 모델이다. OmniParser를 실제 실행한 결과나 모든 parser 구성의 일반 결론으로 확대하지 않는다.

실제 전송 PNG의 크기와 해시는 고정 원본과 같았고 bridge 단계의 이미지 변형은 없었다. provider 내부의 이미지 처리나 좌표 해석까지 검증한 것은 아니다. A는 밀집 화면에서 다른 카드를 선택했고, B는 생산한 후보의 위치와 pointer를 잘못 연결했다. 자유 범위에서는 A가 루프 밖 점을 포함했고 B는 요구된 세 점보다 많은 점을 선택했다. 이 오류는 그대로 남겼다.

늦은 결과의 차단 검사는 이전 revision에서 실제 모델이 만든 proposal을 보관했다가 재생해 현재 revision 관문이 거절하는지 확인한 것이다. 실제 provider 응답이 늦게 도착하거나 취소되는 시간까지 측정한 비동기 지연 실험은 아니다.

반면 `A2`와 `A2 / Conversion chart`, 실제 producer의 `chart_c1_baseline`과 출처 label `C1 / Baseline`처럼 동일성이 명백한 대상을 다른 문자열이라는 이유로 오답 처리하던 계산기 오류는 수정했다. 원시 대상과 이전 계산기는 보존했으며, 정답에 맞춘 추측이나 모호한 label을 성공으로 바꾸지 않았다. 정규화된 ID와 실제 출처 연결을 별도 기록했고 관련 14개 확인이 통과했다.

### 선택 후 보완과 시간 원인 확인

- **A4 동일 화면 생산자의 보조 정보:** 밀집 화면 세 반복에서 A의 최종 공동 판단에 B와 같은 화면 생산 결과를 제공한다. 최종 binding 작성 책임은 A에 남긴다. QA02 개선과 추가 지연/비용을 확인한다.
- **B4 초기 생산 병행:** 같은 밀집 화면 세 반복에서 독립 화면/발화 생산을 같은 호출 한도 안에서 병행한다. B의 초기 순차 실행 정책이 만든 시간과 이후 결합 의존을 구별한다. 기본 B 열을 덮어쓰거나 이 결과를 선택된 A의 보완으로 합치지 않는다.

반복 인계 E3의 실제 전체 완료시간은 A 24,175.92ms, B 28,580.94ms, C 15,659.28ms다. B는 실제로 유지 기록을 읽었다. 그러나 18번 모두 기록과 함께 원본 읽기를 요청했고 목적별 묶음 구성 호출도 수행했다. **기록 재사용이 있었지만 이번 표본에서는 요청별 구성 단계를 제거하지 못했다.** B의 선행 생산만 51회, $0.117164였으며, 인계하지 않는 E1에도 9회와 $0.0131528이 들었다. 생산한 기록이 후속 목적의 원본 선택/구성을 실제로 대체하는 조건에서 B를 다시 평가할 이유는 남는다.

현재 A는 원본 선택 18회와 인계 묶음 구성 18회를 VIA 모델 호출로 나눈 구현이다. B는 선행 생산에 더해 기록 추출 18회와 구성 18회를 실행했다. 수신자는 실제 제공 근거가 충분하면 즉시 완료했고 A는 14/18건, B는 17/18건이 이 경로였다. C는 18번 모두 수신자 자료 선택과 결과 생성 두 단계를 거쳤다. A/B의 두 VIA 호출을 모든 가능한 A/B 구조의 필수 하한으로 일반화하지 않는다.

E4의 철회 자료는 manifest와 제공 근거에서 제외됐고 실제 수신자의 금지 자료 읽기 시도는 없었다. 따라서 실행 결과와 별도 접근 거부 guard 검사를 구별한다. B의 한 반복에서 실제 문서 범위를 벗어난 출처 블록 두 개는 출처 검사로 폐기됐고 유효 원본 보완 후 N-H를 통과했다. 폐기 생산 비용도 위 표에 남아 있다.

### 공통 조건과 선택 후 보완

C의 수신자는 실제 자료 읽기를 지원한다. 이 지원이 없는 임의의 외부 Agent에 C의 결과를 적용하지 않는다.

시작점은 목표와 필수 조건이 이미 채택된 공통 상태다. 그 앞의 사용자 요청 해석을 C만 무료로 생략한 비교는 아니다. A/B/C 모두 같은 Qwen 기반의 최소 수신자를 사용하고 위임 목적별로 실제 자료와 결과를 주고받는다. 서로 다른 상용 Agent 제품의 API 호환성이나 native session 이전을 시험한 것은 아니다. N-H는 18개 인계 기회의 필수 조건/원본 판본/허용 범위 계약을 검사하며, 자유문 초안의 모든 사실 정확도를 검사하는 점수가 아니다.

DP05 첫 BASIC 실행 전에 공통 수신자 계약을 별도 v2로 고정했다. 이미 유효한 근거가 있는 A/B에도 자료 선택과 결과 생성의 두 모델 호출을 강제하던 하한을 제거했다. A/B/C 모두 첫 호출에서 충분한 실제 근거가 있으면 완료하고, 부족하면 원본을 선택해 읽은 뒤 결과를 만든다. manifest 메타데이터만으로 내용 근거가 충분하다고 처리하지 않는다. DP01/02/04의 원래 freeze와 DP05의 v2 freeze를 각각 보존하며, 이 수정 전 smoke는 기본 비교에 섞지 않는다.

선택 후 **C2 정확한 범위 읽기 cache**를 E3 세 반복에 적용한다. 수신자, 원본, 판본, 범위와 접근 epoch가 같은 유효 읽기를 재사용하고 hit마다 권한을 확인한다. 모델의 자료 선택과 수신자 계약은 유지한다. 실제 파일 읽기 호출 수와 공통 `receiver-select → receipt` 구간을 비교한다. 모델 호출 절약이나 물리 disk I/O 감소를 자동으로 주장하지 않는다.

**C2의 기능 효과와 QA 효과를 구별한다.** 실제 원본 파일 읽기는 18 → 6회로 줄고 cache hit 12회가 발생했다. 그러나 수신자 모델 호출은 18회로 같았다. 공통 자료 선택부터 읽기 receipt까지의 구간을 episode별 합산한 평균은 1.591 → 1.466ms로 약 0.124ms 줄었다. 물리 disk I/O를 직접 측정한 값은 아니며, 초 단위 모델 대기를 줄인 효과도 아니다. 수신자 비용의 작은 차이를 cache의 모델 비용 절약으로 해석하지 않는다.

### 별도 B4 병행 진단

화면 B의 같은 dense 사례에서 독립 초기 생산을 병행했다. 첫 응답 평균은 **27,812.93 → 22,965.19ms**, 비용은 양쪽 **$0.0096588**, 모델 호출 수는 매회 2회로 같았다. 실제 두 생산자의 겹침은 0에서 각 반복 5,001.96 / 5,466.84 / 5,341.47ms로 늘었다. 이 진단은 기본 B의 순차 정책에 시간 비용이 있었음을 보여 준다.

QA02는 0/6 → 2/6이었다. 병행 자체가 의미 정확도를 높였다고 단정하지 않는다. 동일 사례의 출력 변동이 함께 있으며, 별도 진단의 결과를 기본 B의 15/24에 합치지 않는다. 병행 후에도 A의 같은 dense 기본 응답 시간 6,854.31ms보다 길었다.

## 8. 변경 확인과 재현 경계

코드, 입력, 별도 정답과 실제 모델 설정은 결과 디렉터리의 freeze에 기록한다. 기본안의 결과를 본 뒤 프롬프트나 정답을 고쳐 실패를 지우지 않는다. 지표 계산 오류를 수정한 경우 원시 trace는 보존하고 계산기 이전 버전과 수정 이유를 남긴다. 전후 계산기 검증은 모델 정확도 재시험과 구별한다.

계산기 검토에서는 조기 종료 시 아직 처리하지 않은 입력의 분모 보존, 마지막 결과가 없어져도 앞서 실제 채택한 결과 보존, 독립 작업 중 사용자 대기를 잘못 차감하지 않는 처리, null/잘못된 형태의 응답 처리와 화면 대상 동일성을 확인했다. 처음 보고한 값을 숨기고 결과가 좋아지도록 입력을 바꾼 작업과 구별하여 변경 이력을 남겼다. [독립 지표 검토](../../../../../results/architecture-evaluation/current/four-dp-qwen37-20261018/metric-review.md).

선택 후 tactic은 기본안과 별도 source, binary, freeze 및 phase로 기록한다. 제한된 사례의 보완 효과를 전체 기본 비교의 평균과 직접 비교하지 않는다. 개선이 없거나 악화되면 그대로 결론에 반영한다.
