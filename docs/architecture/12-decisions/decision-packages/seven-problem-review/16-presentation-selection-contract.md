# 발표용 기본안 재검토와 추가 실험 계약

2026-10-19 / 사용자 승인에 따른 추가 실험과 발표자료 제작

## 1. 이번 요청

사용자는 QA 우선순위를 유지하고 구조적 차이가 없는 QA는 동점으로 두며, 기본안을 다시 검토하고 선택안의 약점을 tactic으로 보완하도록 요청했다. 필요한 추가 구현·실험과 편집 가능한 발표자료 제작까지 승인했다. 이전 권고를 유지하는 것을 목표로 삼지 않는다.

발표 순서는 **구조적 예상 → 같은 조건의 실측 → 우선순위에 따른 기본안 선택 → 선택안의 보완 구조와 전후 수치**다. 첨부한 다른 과제의 비교/채택 슬라이드는 구성과 강조 방식의 참고이며 VIA의 QA 정의나 실험 결과를 제공하지 않는다.

코드 개발, 실행, 모델 호출과 발표 생성 프로그램은 사용자 지정 GPT-6.1 Sol High 담당들이 수행한다. 원시 증거, 동결된 기존 소스, 과거 실패와 보고서는 보존한다. accepted ADR과 참조 Architecture의 채택 상태를 변경하지 않는다.

## 2. 고정할 평가와 선택 규칙

1. QA01 첫 응답, QA02 지칭 집합 정확도, QA03 VIA 처리시간, QA04 변경 모듈 수, QA05 전체 사용 비용, QA06 로컬 메모리 순서를 유지한다. 번호와 의미를 변경하지 않는다.
2. 구조가 실제로 바꾸지 않는 경로는 **구조적 동점**이다. 실측 원값은 그대로 함께 표시한다. 작은 관측 차이를 지워 동일한 숫자로 만들지 않는다.
3. 구조적 차이는 있으나 우열이 입증되지 않은 경우는 **우열 미확정**이다. 이를 구조적 동점과 구별한다. 동점은 다음 우선순위 QA로 진행할 근거지만, 불명확한 결과를 원하는 선택을 위해 동점 처리하지 않는다.
4. 완료되지 않은 입력·목표의 시간은 존재하지 않는다. 기존 14번 계약대로 미관측 분모를 표시하고 관측 평균을 전체 속도 승자 근거로 사용하지 않는다. 임의 벌점 시간이나 성공 사례만의 평균으로 대체하지 않는다.
5. 공통 필수 응답과 완료 계약을 확인할 수 있는 안을 현재 사용 가능한 구성으로 선택한다. 미완료 기본안의 빠른 관측 경로와 다른 QA 수치도 전부 비교한다. 기능 미충족으로 한정한 선택과 전체 모집단에서 더 빠르다는 주장을 구별한다. 정확도 QA의 순서를 바꾸기 위한 사후 점수 문턱을 만들지 않는다.
6. 기본안과 tactic을 분리한다. 필수 기능 누락 수정은 새 기본 구현 판본이며 보완 성과로 위장하지 않는다. 조합은 A2+A5처럼 모두 적는다. 새 번호는 처리 방식과 추가 비용을 먼저 정의한다.
7. 선택안이 적용 QA에서 상대적 열세를 보이지 않으면 약점을 만들지 않는다. 기능 취약점·절대 부담의 보완과 상대적 QA 열세의 보완을 구분한다. N-R/N-H/본문 충족을 QA02로 바꾸지 않는다.
8. 같은 사례의 전후 비교를 사용하고, 기본 전체 평균과 일부 tactic 평균을 섞지 않는다. 작은 반복 수의 결과는 그 모델·입력·실행 조건에 한정한다.

## 4. 실행 전 작업별 예상

### DP1 현재 요청의 근거 공급

유지 근거가 줄이는 실제 조회·답변 단계와 첫 안내 시점을 분리한다. A/B의 기존 작은 QA01 차이는 구조 우위로 확정하지 않는다. C의 긴 첫 반환에는 출력 정책이 관여하므로 관계 생산 자체의 필연적 비용으로 일반화하지 않는다. 최우선 차별 QA를 확인한 뒤 선택안의 유지 비용·반복 구성 비용 등 실제 부담에 맞는 tactic을 검증한다. 기존 A2의 작은 효과를 큰 성과로 확대하지 않는다.

코드 경로 재검토에서 첫 호출 위치가 같아도 A의 유지 view, B의 최소 입력, C의 게시 record와 `select-or-complete` 출력 분기가 첫 반환에 영향을 줄 수 있음을 확인했다. 따라서 A/B QA01을 자동으로 구조적 동점으로 분류하지 않는다. E3에서 기존 출력 정책과 공통 adoption-only 안내 정책을 ABC 각각 세 번 비교하는 18회 민감도를 추가한다. 이는 별도의 공통 응답 정책 변경이며 기존 기본안 결과를 대체하거나 구조 단독 효과를 확정하지 않는다. 추가된 후속 호출과 전체 비용을 모두 센다.

기존 A의 14KB 유지 예산에서 마지막 단일 passage가 상한을 넘을 수 있는 구현은 설계의 hard limit 계약과 다른 누락이다. 이 누락 수정은 필수 기본 구현 교정으로 기록한다. 별도의 8KiB 보존 예산과 locator를 쓰는 A3를 비교한다면 교정된 14KB 기준과 비교하고, 보존 감소와 재읽기 증가를 함께 공개한다. 기존 실제 응답 재생과 native 경계 검사는 새 의미 정확도나 실제 모델 지연의 증거가 아니다.

### DP2 후속 입력의 의미 판단 실행

기존 B의 QA01 이익은 K=2 실제 중첩과 K=1 반대 조건으로 설명한다. B1 불변 문맥 공유는 실행별 공통 입력 복제를 줄이지만, 원본이 작으면 RSS 차이가 작거나 없을 수 있다. 실제 공통 입력, 별도 요청 상태, 직렬화 버퍼의 소유를 분리한다. N=1/2/4의 범위는 자원 진단이며 새 실제 모델 지연 실험으로 합산하지 않는다.

### DP3 화면과 발화의 지칭 결합

A의 직접 경로와 B의 생산·결합 경로를 유지한다. 동일 시점의 기본 A/B와 B4를 다시 확인하고, 실패 때만 좌표 표현과 영향 부분을 재판단하는 A2+A5를 별도 검증한다. 조건부 복구가 A4의 항상 생산 비용을 줄일 수 있다는 가설이며 성공을 보장하지 않는다. B4는 독립 생산 대기를 겹쳐 QA01/03을 줄이고 동시 버퍼 비용을 늘릴 수 있다. 모든 화면 사례와 실패 분모를 보존한다.

**좌표 표현 민감도 추가, 실행 전 기록:** 새 48회에서 A와 B 모두 frame 범위를 벗어나는 좌표를 반환했다. 공식 [Qwen grounding 구현](https://github.com/QwenLM/Qwen-MM-Plugins/blob/main/src/capabilities/api/qwen_mm_plugins_api/vl/grounding.py)은 기본 `qwen3.7-plus`에 0~1000 정규화 좌표를 요청하고 원본 pixel로 변환한다. 현재 후보는 pixel을 명시했으므로 변환 누락이라는 필수 기능 결함으로 단정하지 않는다. 원인은 모델의 pixel 지시 불이행 또는 표현 혼동일 수 있으며, 공식 예시가 해당 고정 snapshot의 보장을 제공하는 것도 아니다.

이 가설을 확인하기 위해 A/B 양쪽에 같은 정규화 출력 계약과 원본 pixel 변환을 적용한 **전체 네 사례×세 번×두 안, 24회**를 별도 동결한다. 예산 상한은 $0.20이며 DP3 담당의 기존 $0.55와 전체 $1.50 안에 포함한다. A2/A5/B4를 혼입하지 않고 원본, oracle, 기능 gate와 평가 정의를 유지한다. raw cue의 단위, frame/view 식별, rounding과 범위 검사를 실행 전에 정한다. 정답 좌표나 사후 clamp를 사용하지 않는다. 기존 48회는 재채점하지 않는다. 이 결과는 공통 좌표 표현을 바꾼 비교이며, 기본 구조 자체를 고친 효과나 특정 tactic의 성과로 바꾸지 않는다. 여기서도 기능 완료가 불안정하면 그 한계를 최종 자료에 남긴다.

### DP4 Agent 간 업무 인계

공통 목적 채택 경로의 QA01은 구조적 동점으로 둔다. QA02 비적용을 유지하며 다음 차별 QA인 QA03에서 C의 가공 생략 경로를 검토한다. 수신자 구간을 제외한 값과 전체 wall time을 함께 제시한다. 반복 자료 읽기·조건 원문 보존의 보완은 실제 수신자 지원 범위를 유지한다. 기존 B의 본문 충족 이익을 QA01~06 우선순위 승리로 바꾸지 않는다.

> **결과 대조 후 해석 정정:** 위 문단은 실행 전 예상이다. 실제 첫 요청에는 A의 이전 원문 읽기와 B의 업무 기록 원문이 들어가 C와 입력이 달랐다. [17 결과 §6](17-presentation-results.md#6-dp4-agent-간-업무-인계)은 QA01을 구조적 동점이 아닌 우열 미확정으로 정정한다. 기존 동결 입력·실행·수치·우선순위는 바꾸지 않는다. C는 QA03·비용과 수신자 읽기 지원 전제를 근거로 한 조건부 권고다.

C1은 이미 채택한 필수 조건의 provenance 원문만 미리 제공하는 경로이며 새로운 의미 요약을 생산하지 않는다. E3의 C/C1 각각 세 번을 같은 창에서 비교한다. C2는 같은 권한·판본·범위의 읽기 재사용을 실제 수신자 읽기 선택 기록으로 재생한다. C1과 C2는 독립 tactic이며 결합 실행 결과로 표시하지 않는다.

## 5. 발표 산출물

- 네 DP의 모든 기본안에 대해 입력, 주요 처리, 유지 상태, 원본 보완과 출력 경로를 비교하는 편집 가능한 설계 그림.
- 각 안의 장점·단점에서 해당 QA와 구조적 원인을 명시한 비교 페이지.
- 선택한 열 또는 구조를 강조하고 새 tactic 요소와 전후 수치를 별도 색으로 표시한 채택 페이지.
- QA01~06 원값·관측 분모·단위, 구조적 동점과 비적용, 실패 해석을 포함한 근거 표.
- 구조적 예상과 일치한 결과, 예상과 달랐던 결과, 적용 조건을 설명하는 발표자 노트.

기존 10번 발표 원고와 15번 결과는 이전 권고의 기록으로 보존하고 새 통합 보고서로 연결한다. 추가 실험이 특정 가설을 지지하지 않으면 그 한계를 자료에 남긴다.
