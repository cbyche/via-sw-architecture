# DP2 + DP44 통합 탐색: 겹친 사건의 해석과 확정 단위

> **후속 사용자 검토로 방향 변경:** 이 문서는 이전 제안 이력이다. 순차 사건 처리와 비동기 작업으로 가능한 범위를 넘어 별도 의미 조정이 필요한 이유를 충분히 제시하지 못했다. 이후 대화/업무 분리 비교도 정확성 이점의 근거가 부족했다. [현재 방향](via-operating-architecture-reset-20261020.md)은 기존 Component 구성을 고정하지 않고 단일 정상 요청부터 VIA의 전체 동작 구조를 탐색하는 것이다. 아래 A/B를 현재 주 비교 후보로 재사용하지 않는다.

2026-10-20 / 사용자 요청에 따른 설계 비교 / 새 번호·기본안 미선정 / 새 구현·측정 없음

## 1. 문제와 이번 제안

사용자는 DP2와 DP44를 하나로 통합해도 좋으므로, 발화·정정·Agent 통지가 겹치는 VIA의 중요한 구조 결정을 찾으라고 요청했다. 특히 QA01/03의 속도 대 QA02/새 QA07의 정확성, 또는 QA01 대 QA03의 상충이 드러나는 대안을 원했다. 원하는 손익의 형태는 탐색 방향이며, 특정 안의 우위를 미리 확정하는 조건은 아니다.

**이번 결정 질문은 “여러 사건의 해석 결과를 어떤 실행과 중간 상태에서 만들고, 무엇을 검토한 결과를 현재 대화·요청 상태로 확정하여 후속 처리를 시작할 것인가?”다.**

| 안 | 기본 메커니즘 | 선택할 이유 | 주된 비용 |
| --- | --- | --- | --- |
| **A 사건별 해석과 직접 확정** | 사건별 해석 실행이 완성한 의미 변경안을 공통 코드 검사 후 채택. 독립 사건은 다른 해석 완료를 기다리지 않음 | 같은 자원 여유에서 첫 응답과 독립 목표 진행을 앞당김 | 서로 영향을 주는 해석의 재검토·재입력, 조기에 시작한 후속 처리의 폐기 가능성 |
| **B 잠정 제안과 대화 의미 조정 분리** | 사건별 해석 결과는 잠정 보관. 별도 의미 조정 실행이 관련 제안·원문·현재 대화를 대조한 변경안을 만들어 채택 | 첫 채택 전에 대상·정정 범위·다른 업무의 유지 조건을 교차 검토 | 조정 단계의 모델 호출·대기·문맥 전달, 제안 수명과 재검토 상태 |
| **C 하나의 지속 대화 실행에서 통합 갱신** | 하나의 의미 실행이 판단 경계마다 들어온 사건들을 같은 문맥에서 함께 해석하고 채택 | 문맥·중간 판단 재사용, 관련 사건의 처리와 변경을 한 번에 구성 | 새 입력이 진행 중인 의미 단계 뒤로 밀릴 수 있음. 큰 문맥의 간섭과 입력 비용 |

A/B를 속도 대 최초 의미 정확성의 주 비교 후보로, C를 **별도 조정 단계 없이 같은 문맥에서 풀 수 있는가**를 확인하는 강한 대안으로 둔다. 세 안의 우열을 측정하거나 사용자 선택을 받은 것은 아니다. 기존 DP2/44 A/B와 다른 탐색 기호이며 이전 결과를 재명명하지 않는다.

## 2. 공통 기능과 자원 조건

- 입력·Agent 사실·실제 전달 이력을 공통 원장에 보존한다. 같은 화면/음성/원본/대화와 Task 기록, 같은 접근 권한과 근거 조회 능력을 제공한다. A에 이력을 숨기거나 B에 정답 Task·정정 범위를 미리 주지 않는다.
- 같은 모델 가중치·총 동시 실행 한도·기본 scheduler·source cache·출력 정책을 사용한다. 세션은 역할별로 분리하되 가중치를 복제하지 않는다. runtime 예약·선제 취소는 별도 보완으로 비교할 수 있다.
- 모든 안에서 사용자 발화 수신·ASR과 즉시 로컬 음성 stop이 계속된다. 관계가 미해결인 관련 미전송 효과는 공통 hold로 보호한다. 이미 무관함이 확인된 사실 처리는 계속 가능하다.
- Task Manager는 확인된 외부 업무 사실을 보존하고 Request Controller는 요청 의미·관계를 채택한다. 의미 모델은 제안자이며, B에서도 원본 확정 권한이 모델로 넘어가지 않는다.
- Response Manager의 게시 허가·내구 전달 기록과 Interaction Manager의 실제 receipt를 유지한다. 실제 제시하지 않은 질문을 짧은 답변의 기본 대상으로 삼지 않는다.
- 코드 검사는 권한, source/Request revision, 실행 세대, 필수 필드, 명시적 의존과 중복 실행을 확인한다. **코드 검사 통과가 자연어 의미의 정답 증명은 아니다.** 세 안 모두 알려진 충돌을 무시하거나 명백히 오래된 결과를 채택할 수 없다.
- A도 한 사용자 입력의 필수 의미 전체를 해결한 뒤 채택한다. 한 발화의 대상만 먼저 확정하고 조건·업무 관계는 나중에 정해 QA01을 줄이지 않는다. B의 첫 단계는 이와 달리 명시적인 미채택 제안이다.
- 이미 확정된 Task 상태와 명시적 질문을 코드로 바로 표시할 수 있으면 세 안 모두 같은 경로를 쓴다. 모든 Agent 통지에 모델 호출이나 B의 두 단계를 강제하지 않는다.
- 세 안 모두 부족한 근거를 추가 조회하고 필요한 확인 질문을 할 수 있다. 명백한 의미 충돌/불명 항목을 해결하는 필수 재판단은 A에서도 허용한다. B만이 다시 생각할 수 있는 구조가 아니다.
- VIA는 대화·요청·업무 연결을 조정한다. 보고서 작성·메일 수정 등의 domain planning과 실행은 Downstream Agent에 남긴다.

## 3. 실제 SW 책임·상태·계약의 차이

세 안은 정식 Component 책임을 유지하고 그 내부 실행과 반환 계약을 다르게 구성한다. 추가 Module 명칭이나 process 분리로 구조 차이를 대신하지 않는다.

| 비교 항목 | A 사건별 직접 확정 | B 제안 후 대화 의미 조정 | C 지속 대화 실행 |
| --- | --- | --- | --- |
| Request Interpreter의 실행 단위 | 사건/입력별 독립 실행. 필요 근거와 현재 대화 snapshot을 조회 | 사건별 제안 실행 + 별도 대화 의미 조정 실행 | 대화별 지속 의미 실행. 경계마다 수신 사건 반영 |
| 반환의 의미 | 공통 검사 후 채택 가능한 완성 의미 변경안 | 첫 반환은 채택 불가. 조정 결과만 채택 후보 | 현재 경계에 포함된 사건별 의미와 관련 상태 변경안 |
| Request Controller가 유지할 차등 상태 | 사건별 base revision·의존 참조·채택/재검토 상태 | 제안 ID·base revision·관련 사건 집합·조정 세대·미해결 충돌·조정 결과 참조 | 소비한 사건 위치·현재 의미 단계·대기 사건·지속 문맥 재구성 참조 |
| 의미 확정의 범위 | 한 입력의 필수 의미와 영향을 주는 요청들. 독립 입력은 따로 채택 가능 | 관련 입력/제안 사이의 관계까지 조정한 묶음. 입력별 의미 기록은 따로 보존 | 현재 판단에서 함께 처리한 사건의 변경안. 입력별 의미 기록은 따로 보존 |
| 후속 작업의 시작 | 해당 변경안 채택 직후 | 해당 조정 결과 채택 뒤 | 현재 통합 판단 채택 뒤 |
| 새 정정의 영향 | 관련 실행과 아직 게시하지 않은 효과만 hold/무효화. 필요 의미만 재판단 | 관련 제안을 superseded 처리하고 조정 집합을 갱신. 무관한 제안 재사용 | 같은 의미 실행의 다음 경계에서 반영. 유효한 이전 근거/판단 재사용 |
| 실패 뒤 재개 | 공통 원본과 사건별 완료 단계에서 재시도 | 제안이 유효하면 재생산 없이 조정만 재시도 가능 | 공통 원본·소비 위치·유효 문맥에서 재구성 |

Request Controller의 의미 상태와 변경 명령을 일관되게 반영하는 것이며, 외부 Agent 실행이나 다른 시스템의 상태까지 하나의 DB transaction으로 확정한다는 뜻은 아니다. 외부 전송의 현재성·중복 방지·접수 확인은 공통 계약이다.

### A: 독립 결과가 채택 자격을 갖는 구조

1. 입력과 통지의 사실을 기록한다. 정답 요청 ID를 붙이지 않은 사용자 입력은 Request Interpreter가 관계까지 판단한다.
2. 사건별 실행은 현재 대화, 실제 질문/전달, 관련 Task와 원본을 읽어 완성된 의미 변경안을 만든다. 필요하면 같은 실행에서 추가 읽기·수정·확인 질문을 수행한다.
3. Request Controller가 공통 검사를 통과한 변경안을 채택한다. 충돌하는 상태가 바뀌었으면 재검토하며, 독립적인 변경까지 단일 전역 revision 불일치로 모두 버리지 않는다.
4. 채택 직후 같은 응답 정책으로 첫 내용과 후속 작업을 시작한다. 다른 독립 사건의 해석 결과는 기다리지 않는다.

A의 이점은 **짧은 경로와 독립 진행**이다. 비용은 서로 영향을 주는 사건을 각각 해석해 중복 문맥·재검토가 생길 수 있고, 필수 코드 검사로 드러나지 않는 잘못된 의미 결합은 첫 채택까지 통과할 수 있다는 것이다. 후자는 A가 일부러 검증을 생략해서 만드는 오류가 아니라 한 번의 사건 중심 판단에 남는 모델 오류 가능성이다.

### B: 관련 제안을 조정하기 전에는 확정할 수 없는 구조

1. 사건별 실행은 원문·근거 참조, 가능한 대상/정정 범위, 유지할 조건, 미해결 항목을 포함한 의미 제안을 생산한다. 외부에 확정 응답을 내거나 업무 변경을 시작할 자격은 없다.
2. Request Controller가 해당 입력과 관련된 제안·원문·현재 대화/Task 사실·실제 전달 기록을 묶어 Request Interpreter의 별도 의미 조정 실행에 제공한다.
3. 의미 조정은 **어떤 대상인가, 무엇을 바꾸는가, 어느 조건은 유지하는가, 어떤 요청/질문과 연결되는가, 지금 어떤 후속 처리가 허용되는가**를 함께 검토한다. 첫 제안에 동의하는 yes/no 평가가 아니라 수정 가능한 완성 변경안을 반환한다.
4. Request Controller가 같은 코드 검사를 수행하고 채택한다. 그 뒤에 첫 확정 안내와 후속 작업을 시작한다.

B는 의미가 필요한 관련 사건에서 조정 단계를 기본으로 갖는다. 같은 모델을 다른 역할·문맥으로 호출할 수 있으나 독립 정답 검증기나 새로운 원본 증거라고 부르지 않는다. **동일 오류를 반복하거나, 맞던 제안을 잘못 고칠 수도 있다.**

조정 대상은 현재 입력과 실제 의존 후보가 있는 bounded 집합이다. 판별이 안 된 관계는 unresolved로 남기고 활성 대화의 필요한 범위를 함께 본다. 이미 독립임이 확인된 Task까지 기다리지 않으며, 미래 통지를 더 모으기 위한 고정 sleep도 넣지 않는다. 현재 처리할 집합의 사건 위치와 revision을 기록하고, 실행 중 들어온 관련 사건은 공통 hold 후 다음 조정으로 연결한다. 늦은 제안은 기한 내 재시도/필수 확인으로 처리하고 무한 join으로 숨기지 않는다.

B가 A와 다른 것은 모델 호출 횟수뿐이 아니다. **미채택 제안이 지속되는 상태, 사건 간 조정 의존, 조정 결과만 채택할 수 있는 계약, 후속 실행 시작 경계**가 필요하다. 반대로 A에 선택적인 사후 확인 한 번만 붙인 구현을 B라고 하지 않는다. 첫 채택 뒤 확인은 QA02/07의 첫 실패를 지우지 못한다.

### C: 한 문맥에서 모인 사건을 함께 해석하는 구조

1. 입력·통지는 계속 기록하고 공통 hold/stop을 적용한다.
2. 현재 의미 단계가 끝나거나 공통 중단 계약의 경계에 도달하면, 그동안 도착한 사건과 현재 상태를 같은 대화 문맥에 반영한다.
3. 요청 간 관계·지칭·정정·질문 연결을 함께 판단하고, 입력별 의미와 상태 변경안을 반환한다. Request Controller가 검사·채택한다.
4. 다음 의미 단계는 갱신된 문맥과 유효한 근거를 이어 사용한다. 외부 업무와 사용자 답변 대기 동안에는 모델 자원을 반환한다.

C는 앞선 사용자 목표 전체를 끝내고 다음 입력을 받는 구조가 아니다. 다른 owner의 사실 수신·응답 전달도 멈추지 않는다. 다만 **새 의미 판단은 하나의 지속 실행의 다음 판단 경계에 의존**한다. 짧은 관련 후속 발화에는 문맥 재사용과 한 번의 통합 판단이 유리할 수 있지만, 긴 의미 호출 중 독립 질문에는 불리하다. 모든 입력을 두 번 판단하지 않고도 B 수준의 정확성을 얻는다면 C가 더 효율적일 수 있다.

## 4. 동일한 겹침 장면

### 공통 초기 상태와 사건

- 보고서 업무 R은 두 표를 포함한 수정본을 준비 중이다. 메일 **초안** 업무 M은 앞서 확인한 첨부 D0와 수신인을 사용한다. 실제 발송을 요청한 장면이 아니다.
- 사용자에게 메일 첨부를 확인하는 질문 Q1이 이미 표시됐다. 화면에는 보고서의 위 표 T1과 아래 표 T2가 있으며 D0의 과거 확인·전달 기록도 있다.
- **U1:** “보고서는 위 표만 남겨. 메일은 아까 확인한 그 파일로 계속하고, 받는 사람은 바꾸지 마.”
- U1 해석 중 보고서 Agent의 **이전 조건으로 만든 결과 D1**과 메일 Agent의 **새 질문 Q2**가 도착한다. Q2가 아직 표시되지 않았다면 U1을 그 질문의 답으로 취급할 수 없다.
- 뒤이어 **U2:** “표 제목은 그대로 두고, 본문만 줄여줘.”라는 추가 정정이 들어온다.

입력 사건의 원래 시각과 source 내용은 같은 비교 계약으로 제공한다. 실제 질문에 대한 답변은 각 안의 실제 제시 뒤 같은 사용자 반응 규칙으로 제공한다. 아직 제시하지 않은 질문에 미리 답을 주거나, B에만 더 많은 원본을 주지 않는다. 먼저 도착한 원본·사실은 세 안 모두 읽을 수 있으며 B의 추가 제안은 같은 원본의 파생 해석이다.

### 같은 사건을 처리하는 차이

| 사건 | A | B | C |
| --- | --- | --- | --- |
| U1 수신 | 별도 실행에서 보고서·첨부·수신인 관계까지 판단 | U1 해석은 잠정 제안으로 생산 | 현재 의미 단계 뒤 U1과 수신 사건을 같은 문맥에 반영 |
| D1·Q2 도착 | Task 사실은 즉시 보존. 필요한 대화 연결은 독립 해석. U1에 영향을 주는 상태 변화면 재검토 | 같은 사실을 보존하고 필요한 제안·관계를 조정 집합에 반영 | 사실은 즉시 보존하고 다음 판단에 반영 |
| 최초 의미 채택 | U1의 완성 변경안이 유효하면 다른 독립 제안 완료 전 채택 | 조정 실행이 T1/D0/수신인 유지·R 정정·M 유지·Q1/Q2 관계를 함께 검토한 뒤 채택 | 통합 판단이 같은 의미를 반환한 뒤 채택 |
| 첫 구체적 안내 | 채택 직후 “보고서는 위 표만 남기고, 메일 초안은 기존 첨부와 수신인을 유지하겠습니다” 표시 가능 | 같은 내용을 조정 후 표시 | 같은 내용을 다음 통합 판단 후 표시 |
| U2 도착 | 관련 후속 준비가 이미 시작됐을 수 있음. 유효 범위는 재사용하고 영향받은 준비만 변경 | 아직 조정 중이면 U2를 후속 조정에 반영해 오래된 후속 작업 시작을 피할 가능성. 이미 채택했다면 A와 같은 비용 가능 | 다음 판단에서 반영. 이전 문맥의 유효 범위 재사용, 이미 시작한 작업은 동일하게 제어 |
| 늦은 D1 처리 | 이전 조건의 사실로 보존하되 현재 요청 완료로 게시하지 않음 | 동일 | 동일 |
| 완료 | 최종 보고서 변경과 메일 유지 관계, 모든 의무 응답·상세·음성 준비 확인 | 동일 | 동일 |

이 표는 각 안이 달성해야 하는 정상 처리를 설명한다. A가 반드시 T1이나 D0를 틀리고 B가 맞는다는 예측이 아니다. 이전 결과의 단순 revision 거부와 미제시 질문의 기계적 제외는 공통 기능이며 B의 정확도 효과로 세지 않는다.

## 5. QA01 대 QA02·새 QA07: 어떤 정확성 차이를 기대하는가

**주 가설은 A의 짧은 채택 경로 대 B의 채택 전 교차 의미 검토다.** A도 같은 필수 근거를 모두 볼 수 있고 자연어 관계를 판단한다. B는 한 번 더 원문·제안·현재 대화를 대조하는 비용을 내며, 제안 단계에서 빠진 관계/조건을 최초 확정 전에 고칠 기회를 얻는다.

| 품질 | 이 장면에서 보는 것 | B의 개선 경로 | 한계/반증 |
| --- | --- | --- | --- |
| **QA01** | U1 끝부터 실제 첫 내용 표시까지 | 개선을 기대하는 축이 아님. A는 별도 조정 단계를 기다리지 않음 | A의 충돌 재검토나 자원 대기가 크면 B가 더 빠를 수도 있음. 모든 사건 평균을 확인 |
| **QA02** | “위 표”가 T1인지, “아까 확인한 그 파일”이 D0인지 | 화면·실제 확인 이력·새 결과의 지칭 관계를 제안과 원문으로 다시 대조 | 화면 인식/원본이 잘못됐거나 A가 이미 맞으면 이익 없음. 일반적인 QA02 우위는 미확보 |
| **새 QA07** | T1 유지, 보고서 변경, M 유지, D0 첨부, 수신인 유지라는 최초 필수 의미 전체 | 지칭은 맞지만 R의 정정을 M에도 적용하거나 유지 조건을 놓친 제안을 채택 전에 수정 | 같은 모델의 오류가 반복되거나 조정이 새 오류를 만들면 이익 없음. QA02보다 직접적인 가설 |

“R과 M을 혼동했다”는 설명만으로 QA02 실패라고 하지 않는다. 실제 지정된 지칭 대상 집합을 틀렸는지 따로 본다. 대상은 맞고 유지 조건만 놓쳤으면 QA02 성공/QA07 실패가 가능하다. 반대로 같은 대상 오류가 둘 다 실패하게 할 수 있지만 두 독립 정확성 효과로 부풀리지 않는다.

B의 중간 제안에는 채택 권한이 없으며 외부 확정 안내/명령으로 사용하지 않는다. QA02/07은 세 안 모두 **처음 의미를 확정한 시점**에 평가한다. A의 채택 뒤 정정을 B의 채택 전 수정과 같은 성공으로 처리하지 않는다. C도 같은 평가 경계를 적용한다.

정확성의 현재 판단은 **B의 QA07 개선 가설은 구체적, QA02는 해당 지칭 장면에 한정된 가설, 둘 다 실증 전**이다. “빠른 A 대 정확한 B”라는 확정 우열이나 새 QA07 우선순위·목표를 만들지 않는다.

## 6. QA01은 A, QA03은 B/C가 유리할 수 있는가

가능하지만 **첫 응답을 늦추면 전체 완료가 빨라진다**는 일반 법칙은 아니다. 다음 두 경로를 구별한다.

### 반복 정정과 교차 상태 변경: A 대 B

A는 U1을 빨리 채택하고 R의 후속 준비를 시작할 수 있다. 그 뒤 U2가 오면 이미 시작한 관련 준비를 수정·폐기·재시도한다. B가 아직 제안/조정 단계에 있다면 U1과 U2의 관계를 정리한 뒤 최종 유효 조건의 후속 준비만 시작할 수 있다. 어느 안도 미래 U2를 기다리기 위해 고정 지연을 삽입하지 않는다.

B의 QA03이 짧아질 조건은 **실제 완료 경로에서 피한 재처리·재검토 대기가 추가 조정 대기보다 큰 경우**다. 병렬로 숨겨진 계산량을 완료시간 절약으로 바꾸지 않는다. A도 준비된 유효 상태와 원본을 재사용하며, 취소한 외부 업무를 다시 수행하는 가상 비용을 억지로 더하지 않는다. B가 이미 U1을 채택한 뒤 U2를 받았으면 같은 재처리 비용을 낼 수 있다.

U1/U2의 입력별 의미 기록과 대체 관계는 보존한다. U2로 바뀐 최종 의미를 U1의 최초 정답으로 소급하지 않는다. 병합한 응답이 여러 의무 사건을 처리하면 각 원래 시작 시각을 보존한다. QA03은 공통 계약의 최종 revision 완료를 사용하고 Agent 통지를 새 사용자 목표로 늘리지 않는다.

### 같은 주제의 짧은 연속 수정: A 대 C

A의 별도 실행들은 같은 자료·조건을 다시 입력하고 변경 충돌을 재판단할 수 있다. C는 같은 의미 문맥과 유효 중간 판단을 이어 쓰고, 현재 판단 경계 전에 모인 관련 사건을 한 번에 반영할 수 있다. 이 경우 C의 첫 입력 반영은 늦어도 전체 VIA 호출·재결합이 줄 수 있다.

반대로 **긴 판단 중 무관한 새 질문**에서는 A의 독립 진행이 QA01/03 모두 유리할 수 있다. C에 이미 모인 사건이 없거나 재사용 효과가 작으면 대기만 늘 수 있다. C의 정확도가 B와 같고 처리·비용이 더 좋다면 추가 조정 구조 B를 선택할 이유가 약해진다.

## 7. 세 안의 QA 비교와 우선순위

| QA | A | B | C | 근거 상태 |
| --- | --- | --- | --- | --- |
| **QA01 첫 응답** | 독립 실행과 추가 조정 없는 경로가 유리 | 제안 이후 조정이 첫 확정 앞에 추가됨 | 기존 의미 단계 경계를 기다릴 수 있음 | A 우위의 구체 가설. 짧은 공통 코드 응답은 동점 가능 |
| **QA02 지칭 정확도** | 한 사건의 완성 해석을 검사 후 채택 | 지칭·확인 이력·새 결과 사이 의미 관계 재검토 | 공유 문맥에서 지칭 연속성을 판단 | B/C의 일반 우위 미확정. 정확한 근거와 실제 오류 개선이 필요 |
| **QA03 VIA 처리** | 독립 목표 병행에 유리. 관련 사건 재입력/충돌 비용 가능 | 조정 비용. 반복 정정의 불필요 후속 작업을 피하면 역전 가능 | 관련 입력 문맥 재사용·통합 갱신에 유리. 독립 입력은 지연 | workload에 따른 반대편 이익이 구체적, 크기 미측정 |
| **QA04 변경 범위** | 사건별 의미 계약·공통 채택·재검토의 파급 | 제안과 조정 계약·미확정 상태의 변경 파급 | 지속 문맥·사건 소비·통합 변경의 파급 | 같은 Rust 변경 과제 전에는 순위 없음 |
| **QA05 모델 비용** | 사건별 입력과 충돌/재시도 비용 | 추가 조정 입력/출력·제안 유지/갱신. 피한 후속 작업과 함께 계산 | 문맥 재사용과 반복 입력 길이, 단일 실행 재구성 비용 | 단순/독립 장면은 B 추가 부담 예상. 전체 비용 순위는 미확정 |
| **QA06 로컬 RAM** | 여러 실행의 동시에 살아 있는 상태 | 제안 원장·조정 입력·동시 실행 상태 | 지속 문맥과 수신 대기 사건 | B의 논리 상태 증가 경로 있음. 실제 RAM 순위·원격 KV 혼동 금지 |
| **새 QA07 요청 의미 정확도** | 사건별 한 번의 완성 의미 판단 | 채택 전 관계·조건 보존을 별도 교차 조정 | 한 문맥에서 연속 상태를 판단 | B를 정확성 지향 후보로 탐색. C/A보다 낫다는 실측 없음 |

QA01→QA02→QA03→QA04→QA05→QA06의 기존 평가 순서는 유지한다. 새 QA07의 우선순위와 점수는 별도 합의 대상이다. 이번 요청의 “정확성 우선 B”는 설계가 지향하는 이점이며 기존 선택 순서를 몰래 바꾸는 의미가 아니다. QA01/03은 오답의 실제 관측 시간도 보존하며 최초 정답까지의 시간으로 바꾸지 않는다.

## 8. 반드시 같이 비교할 장면과 반증

| 장면 | 실행 전 예상 | 예상이 틀렸다고 볼 조건 |
| --- | --- | --- |
| 긴 VIA 판단 중 독립 새 질문 | A의 QA01/03 유리, B는 추가 조정 부담 | 같은 자원에서 독립 진행이 없거나 A의 재결합 대기가 더 큼 |
| 보고서 정정·메일 유지·Agent 질문의 교차 | B의 QA07 개선 가능, A는 빠른 첫 채택 | B가 오류를 고치지 못하거나 C/A가 같은 정확도를 더 낮은 비용에 달성 |
| 새 결과 도착과 과거에 확인한 파일 지칭 | B/C가 최초 지칭 결합에 도움을 줄 가능성 | 개선이 공통 revision 검사나 A에 누락한 원본 때문이면 구조 효과로 인정 안 함 |
| 짧은 연속 정정·동일 자료 재사용 | C의 QA03/05, 조건부 B의 재처리 회피 이익 | C의 긴 문맥 비용/B의 조정 대기가 절약보다 큼 |
| 하나의 짧고 명확한 요청 | A/C가 짧은 경로, B는 추가 비용 | B가 정확성·재처리 이익 없이 비용만 더하면 해당 장면의 열위 인정 |
| 확인된 상태·코드로 표시 가능한 질문 | 세 안의 첫 응답은 공통 경로 | 특정 안에만 모델을 강제했다면 비교 결함 |
| 의미 근거 부족·실제 모호함 | 세 안 모두 필요한 확인 | 질문을 많이 해서 QA02/07을 좋아 보이게 만들지 않음. 불필요 질문 실패 포함 |
| 중단·재시작·늦은 결과 | 모든 안 같은 유효 목표/효과 보존 | B 제안이나 C 문맥을 원본으로 잘못 취급, 중복 실행 또는 미완료 누락 |

원하는 정확도 구도를 얻기 위해 교차 정정만 모집단에 넣지 않는다. 간단·독립·관련·모호·실패 장면의 분모와 입력 시점은 이후 계약에서 고정한다. 이번 문서는 새 평가 freeze가 아니다.

## 10. 구조 비교와 보완을 섞지 않는 방법

이 세 구성은 두 선택을 드러낸다. **의미 실행 문맥을 사건별로 나눌지 지속 대화로 둘지**, **각 완성 해석을 직접 채택할지 별도 의미 조정을 선행할지**다. A/B는 같은 사건별 생산을 사용해 채택 전 조정의 효과를 주로 비교하고, A/C는 직접 채택을 사용해 문맥/실행 단위의 효과를 비교한다. B/C는 여러 요소가 함께 달라지므로 결과의 원인을 하나로 단정하지 않는다.

지속 대화 실행에도 별도 조정을 붙이는 조합은 가능하다. 필요하면 추가 구성으로 비교하되 지금 임의의 네 번째 안을 만들어 coverage를 늘리지 않는다. 추가 판단이 있다는 이유만으로 보완이라고 고정하지 않으며, 채택 자격과 의존 계약이 바뀌면 구조 변경으로 표시한다.

기본안의 조건부 선택 이후 검토할 보완 예시는 다음과 같다.

- **A1:** 명시적 불확실성/교차 의존이 큰 경우에만 추가 의미 조정. 필요한 충돌 해결을 처음 넣는 것이 아니라 기본 기능 밖의 추가 검토를 뜻한다. 미탐/과탐과 조정비용을 함께 비교한다.
- **B1:** 원본·상태 의존이 변하지 않은 제안/조정 결과의 제한적 재사용. 무효 제안을 재사용하거나 필수 최초 조정을 생략하지 않는다.
- **C1:** 필수 원문 참조를 유지한 문맥 정리와 갱신 범위 제한. 독립 의미 실행을 새로 추가하면 A 계열의 구조 변경으로 다시 분류한다.

우선순위 설정·자원 예약·취소 지원은 세 안의 실행 조건으로 공개하고 필요 시 별도 보완한다. 해당 설정 효과를 의미 조정의 정확도나 실행 분리의 속도로 중복 계산하지 않는다.

## 12. 현재 결론과 증거 수준

**주 비교는 A 사건별 직접 확정 대 B 잠정 제안 후 대화 의미 조정이다.** 사용자가 원한 QA01 대 정확성의 방향을 실제 채택 의존과 중간 상태에 연결할 수 있다. B의 정확도 우위는 아직 가설이며, 특히 QA07보다 QA02의 일반적인 개선 근거가 약하다.

**C 지속 대화 실행은 남겨야 할 강한 대안이다.** A보다 첫 반응이 늦어도 관련 사건의 재사용·통합으로 QA03/05가 유리할 수 있고, B의 추가 조정 없이도 정확성을 유지할 가능성을 검증한다. A가 단순/독립 장면에서 더 빠르고 B/C가 관련/반복 장면에서 더 유리한 조건을 같이 설명한다.

기존 DP2의 병행 관측은 실행 분리의 참고이며 새 B의 조정 효과나 QA07 결과가 아니다. 최신 [17 결과 §12](17-presentation-results.md#12-기술-중단-후의-최종-부분-집계)는 부분 실행·미확정 의미 검토를 포함하므로 과거 일부 수치로 새 세 안의 우열을 확정하지 않는다.

이번 문서는 통합 문제의 기본 구조 후보와 예상 손익이다. 기존 QA 정의·점수·모집단·참조 Architecture·ADR을 수정하지 않았고, 새 모델 호출·코드 구현·측정·commit/push를 수행하지 않았다. DP 통합의 공식 번호와 최종 기본안, 새 QA07의 우선순위는 정하지 않았다.
