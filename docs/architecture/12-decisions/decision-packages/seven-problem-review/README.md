# VIA 일곱 설계 문제의 최종 분석

> **2026-10-22 DP44 합성 비교와 인계:** [80입력과 QA01~07 백데이터](dp44-local-voice-execution-20261021/synthetic-comparison-20261022/README.md)에 화면과 음성 첫 응답, 원래 목표별 시간, 폐기와 재개 비용, 동시 RAM 및 변경 요구를 연결했다. 이번 가정의 조건부 권고는 A이며 고정 정확도는 동점이다. 합성 계산이고 실제 성능 검증이나 사용자 채택이 아니다. 공통 QA v2를 보존하며 [통합 인계 경계](dp44-local-voice-execution-20261021/synthetic-comparison-20261022/handoff.md)를 별도로 제공한다.

> **2026-10-21 DP44 로컬 음성 실행 상세:** [A/B Component와 S2S 호출 및 사용자 개입의 전체 흐름](dp44-local-voice-execution-20261021/README.md)을 구체화했다. 사용자 발화 감지부터 재생 중단, 정정, 재개, 실제 전달 이력까지 같은 시나리오를 추적한다. 음성 QA01과 과금형 QA05의 직접 교환, QA03의 실제 실행 의존, QA06 크기, 피크 조건, 반복 재개 반례를 구분하고 공통 입력 및 A/B 구조, 흐름의 편집 가능한 그림을 제공한다. 미구현, 미측정, 미선정이며 아래 기록은 각 정의와 시점의 탐색 이력이다.

> **2026-10-21 최신 DP44 조건부 재평가:** 사용자는 QA01을 실제 첫 음성 시작까지로 보면 손익이 생기는지 검토하도록 요청했다. [음성 QA01 아래 비용·실행 비교](dp44-conversation-delivery-reset-20261021.md#02-qa01을-실제-첫-음성까지로-보는-조건부-재평가)는 화면·음성 독립을 유지하고 응답별 독립 준비 A와 현재 발화 소유 준비 B를 비교한다. 대기 중 유효 음성을 준비할 수 있으면 A는 실제 첫 음성 대기를 줄이고, B는 전달 전에 정정된 구판의 생성 비용을 피한다. 이전 음성 준비 축의 새 조건 아래 재평가이며 특정 S2S capability 검증·공식 QA 변경·실측·선정은 아니다. 아래 UI QA01을 전제로 한 폐기 판단은 이력으로 보존한다.

> **2026-10-21 DP44 핵심 범위 재확정:** 사용자는 화면·음성 결합 비교를 기각했다. 두 채널은 독립이라는 공통 전제 아래 [현재 발화·중단 응답·대기 질문의 전달 제어](dp44-conversation-delivery-reset-20261021.md#0-지금까지의-결론과-dp44를-이어갈-방향)를 구체화했다. 이전 통합 생명주기 탐색 권고도 철회하며, 핵심 기능 설계와 아직 확보하지 못한 주요 QA 교환을 구별한다.

> **2026-10-21 DP44 논의 정리:** [현재 결론과 재탐색 경계](dp44-conversation-delivery-reset-20261021.md#0-지금까지의-결론과-dp44를-이어갈-방향)에 합의 범위, 폐기한 비교와 QA 관측의 한계를 모았다. 음성 선행 준비 A/B는 주요 DP44 대안에서 폐기했다. 대화·채널 전달 생명주기의 소유와 실제 게시 선행 의존을 탐색하되 새 강한 A/B 확보나 QA 변경을 선언하지 않는다.

> **2026-10-21 DP44 음성 비교의 추가 전제 확인:** Agent의 완성 텍스트가 S2S 입력이다. 아래 음성 선행 준비 비교는 S2S의 출력 오디오를 미리 받아 보관한다는 추가 가정이며, LiveKit의 고정 문구 TTS cache 예제로 VIA의 해당 S2S 계약이나 주요 DP 적합성을 확인한 것은 아니다. [음성 비교 상단의 한계](dp44-audio-preparation-tradeoff-20261021.md)를 먼저 읽는다.

> **2026-10-21 최신 DP44 QA 교환:** 사용자가 구조의 차이만으로는 부족하다고 다시 지적했다. [음성 선행 준비 A와 발화 시점 준비 B](dp44-audio-preparation-tradeoff-20261021.md)는 독립 음성 artifact 생산·보관 대 현재 발화 소유 producer를 비교한다. A는 겹친 응답의 QA03 준비 경로를 단축하고, B는 대기 판본이 대체될 때 QA05의 미사용 음성 생성 비용을 줄인다. 기본 RAM 보관은 QA06 비용도 만들지만 QA01은 동점이다. 아래 Workflow/Reconciler pair의 주 비교 권고는 철회한다. 새 후보는 미구현·미측정·미선정이다.

> **2026-10-21 현재 DP44 구현 대안:** [응답별 전달 절차 A와 출력 상태 대조 B](dp44-workflow-and-reconciliation-20261021.md)를 실제 상태·명령·정정·복구 계약으로 구체화했다. A는 응답별 진행에서 명령을 직접 결정하고, B는 원하는 출력 의무와 실제 전달·실행 중 작업의 차이에서 명령을 만든다. 응답 재작성 LLM 없이 같은 내용을 전달한다. 정상 경로의 직접성 대 부분 변경의 공통 처리라는 선택 이유를 제시하되, QA01의 큰 차이·QA04 실제 변경 수·3~4축 coverage는 아직 확정하지 않았다. 기존 A/B, Reference Architecture와 QA 정의를 변경하거나 새 안을 선정한 결과가 아니다.

> **2026-10-21 현재 DP44 재정립:** [준비된 응답을 실제 대화로 전달하는 구조](dp44-conversation-delivery-reset-20261021.md)에서 시작한다. 사용자는 DP44를 VIA의 핵심 대화 설계로 다시 깊게 검토하도록 요청했다. 응답 생성·묶음 생성 비교는 현재 대안에서 철회했다. 내용 준비, 게시 조건 충족, 실제 표시·발화를 구별하고 전달 상태·후속 답변 연결까지 구조 탐색 범위로 다시 연다. QA01은 실제 첫 UI 표시 정의를 유지한다. 아래 생성 탐색과 상세 설계 유지 권고는 이전 이력이며 새 A/B·실측·최종 선택은 아직 없다.

> **2026-10-21 가정 기반 DP44 수치 예시:** [개별 응답 생성 대 묶음 생성](dp44-batched-response-synthetic-example-20261021.md)은 사용자의 새 대안·수치 요청에 대한 **synthetic design example**이다. QA03/QA05는 명시한 지연·사용량·가상 단가로 계산했고 다른 축의 가정/미검증을 구별했다. 실측·기존 PoC·QA 점수·주요 DP 선정 근거로 사용하지 않는다.

> **2026-10-20 현재 요청 — 원래 DP44 A/B 재평가:** [중앙 비동기 Dispatcher 대 Stage 연결의 설득력](dp44-original-alternatives-reassessment-20261020.md)을 다시 평가했다. 실행권/상태 소유 차이는 실재하지만 A도 독립 준비를 병행하므로 B의 QA01/03 이익은 중앙의 실제 잔여 대기에서만 나온다. QA04의 부분 정정/철회 변경과 QA06도 자동 우위를 지지하지 않는다. A를 구현 출발점으로 권고하고 주요 DP로서의 강한 QA 교환은 미확립으로 판정했다. 사용자 채택·실측 승자가 아니다.

> **2026-10-20 현재 QA 기반 DP44 재탐색:** 자연스러움을 별도 QA로 추가하지 않는 사용자 기준에 따라 [응답 문안 경유 대 채널별 직접 생성](dp44-output-generation-tradeoffs-20261020.md)을 검토했다. 일반 LLM의 문안 이후 음성을 만드는 A와 확정 자료에서 텍스트/음성을 독립 생산하는 B의 QA03/QA05 손익을 식과 반증 조건으로 구분한다. QA01 차별화나 주요 DP 선정은 주장하지 않는다. 별도 RAM/spool 축은 조합 가능한 상세 설계로 남긴다.

> **2026-10-20 최신 DP44 범위 정정:** 사용자는 의미 해석 실행을 DP2에서 다루고 DP44를 여러 응답과 Agent 통지의 전달 구조로 한정했다. [사건별 응답 산출물과 현재 전달 상태 기반 생성](dp44-response-delivery-structure-20261020.md)을 비교했다. 확정 사실의 즉시 표시를 공통으로 허용하면 QA01 차이가 약하고, 생성량 감소가 QA03 임계 경로 개선을 보장하지 않아 요청한 교차 우위는 미확립이다. 아래 의미 상태 동시성 탐색은 DP2 검토 입력이며 현재 DP44 권고가 아니다.

> **2026-10-20 현재 DP44 재구성:** [대화 의미 상태의 직렬 갱신과 낙관적 병행 갱신](dp44-state-concurrency-reconstruction-20261020.md)을 새 비교 후보로 기록했다. 원래의 발화·정정·Agent 사건을 유지하며 상태 사본·확정·재해석 계약에서 구조를 도출한다. QA01 대 충돌 시 QA03/05의 예측이며 정확성 우위·실측 승자·새 DP 채택이 아니다.

> **2026-10-20 최신 방향 정정:** [VIA 기본 동작 구조 재탐색](via-operating-architecture-reset-20261020.md)이 현재 사용자 방향이다. 기존 Component 구성을 공통 골격으로 삼지 않고 단일 정상 요청의 전체 동작부터 비교한다. 화면 근거 구조는 DP3에서 다루고 겹침·스케줄링은 주된 문제에서 내려놓는다. 아래 통합 탐색과 이후 대화/업무 분리 가설은 주요 대안의 필요성·정확성 이점을 충분히 설명하지 못했다. 이전 본문·결과는 보존하며 새 구조를 선정한 것은 아니다.

> **2026-10-20 최신 통합 탐색:** [DP2+DP44: 겹친 사건의 해석과 확정 단위](dp2-dp44-integrated-interpretation-and-commit-20261020.md)는 A 사건별 직접 확정, B 제안 후 대화 의미 조정, C 지속 대화 실행을 비교한다. 같은 사건의 처리와 최초 의미 채택, QA01 대 QA07 정확성 가설·QA03 재처리/재사용 손익을 구체화했다. 새 대안의 구현·실측·최종 선택은 아니며 아래 이전 선정·탐색은 이력으로 보존한다.

> **2026-10-20 문제 중심 통합 탐색:** [최신 사용자 방향](dp44-overlapping-events-exploration-20261020.md#13-dp-경계보다-via의-구조적-결정을-우선)은 DP2/DP44의 개수와 경계 보존보다 의미 있는 VIA 구조 결정을 우선하는 것이다. 두 영역을 함께 검토하고 통합 DP 가능성을 열어 둔다. 아래 경계 검토는 분석 이력이며 DP2와 겹친다는 이유로 새 대안을 제외하지 않는다.

> **2026-10-20 DP44 구조성 재검토:** [DP2와의 경계 및 B/C 재판정](dp44-overlapping-events-exploration-20261020.md#12-dp2와의-경계와-bc의-구조성-재판정)이 최신이다. 중단/재시도와 자원 예약의 구현 계약은 구별되지만 조합 가능하며, 독립 의미 실행 추가는 DP2와 겹친다. B/C를 배타적 주요 DP44 대안으로 제시한 권고를 철회하고 상세 설계/보완 후보로 남긴다. 아래 탐색은 이 검토에 이르는 이력이다.

> **이전 보완 캠페인:** [15 보완 결과 보고서](15-corrected-poc-results.md)와 [10 발표 원고](10-presentation-outline.md). 기본10개 안120회, A2/A4/B4 보완27회와 공통 원문 표현 진단9회를 완료했다. 모든 QA의 구조적 예상과 실제 호출·시간·비용·변경 모듈·메모리를 연결하며 실패·교정 이력을 보존한다. 당시 권고는01A/02B/04B+B4이고 05는 조건 보존 우선B 또는 수신자 읽기·시간·비용 우선C였다. 아래 초기 결과와 설계 판단도 각각의 이력이다.

## 결론

**최종 주요 DP 세트는 네 개다. 현재 요청의 근거 공급, 후속 입력의 의미 판단 실행, 화면과 발화의 지칭 결합, Agent 간 업무 인계다.** 네 개로 맞춘 결과가 아니라 일곱 문제의 구조와 정상 사용의 품질 선택을 각각 판정한 결과다. DP-44, Agent 선택과 DP-42는 독립 상세 설계로 남기고 기본안과 재검토 조건을 정했다.

| --- | --- | --- | --- |
| [01 근거 공급](01-evidence-supply.md) | 이미 읽은 근거를 대화 문맥에 유지할지, 요청 때 구성할지 | **주요 DP**. 문제 1 + DP-45 통합 | **A** 유지 작업 문맥과 필요한 원본 보완 |

## 이번에 완성한 것과 확인하지 않은 것

일곱 문제 모두에 기능 완료 조건, 복수 시나리오, 실제 구현에 근거한 대안, 상태와 오류/복구, QA01~06 인과, 추천과 반대안 선택 조건, 선택 후 보완을 작성했다. 비교 그림은 각각 SVG, 편집 가능한 draw.io, PNG를 제공한다. OpenClaw, OpenHands, Deep Agents, AutoGen Magentic-One, CrewAI와 관련 원 논문/실행 SW의 근거를 연결했다.

**설계 분석과 수치 산출이 과정의 모든 QA×DP 차별화 조건 충족을 뜻하지는 않는다.** 이전 캠페인의 측정에서는 QA04의 별도 생산 경로 수정 차이가 확인됐지만, QA02의 두 번째 강한 DP와 전체 제품의 QA06 우위는 여전히 신중하게 구별해야 한다. [09](09-qa-tradeoffs.md)는 실행 전 판단과 현재 확인 범위를 나누고 [15](15-corrected-poc-results.md)는 실제로 확인한 메커니즘과 조건을 제공한다.

위 설계 분석 이후 사용자 승인으로 실제 Qwen 비교를 수행했다. 전체 Windows 제품 검증, 기존 0~6 점수의 재산정과 최종 사용자 채택은 이번 PoC로 자동 성립하지 않는다. 기존 QA 정의/점수/COMMON-28과 참조 Architecture, ADR은 유지한다.
