## 1. 판정 방법

이 표는 QA 관련성 목록이나 측정된 우열표가 아니다. **기본 구조가 실제로 바꾸는 처리에서 품질 차이로 이어지는 경로**를 기록한다. 좋은 안을 찾는 이유와 그 안을 선택할 때 지불하는 비용을 함께 본다.

- **주:** 기본안 비교의 중요한 차이 가설이다. 사용 조건과 반증이 있다. 실제 차이 크기나 통계적 검증은 없다.
- **조건:** 실패/비용 경로는 있지만 정상 사용의 반대편 이익 또는 차이 방향 근거가 약하다. 과정의 차별화 coverage에 자동 산입하지 않는다.
- **공통:** 필수 검증 대상이나 이 비교축의 기본 차이 근거가 없다.

값이 없다는 이유로 모든 칸을 같은 의미의 “미확인”으로 취급하지 않는다. 반대로 source가 있다고 가설을 실측 coverage로 승격하지 않는다. QA01과 QA03에 겹친 시간을 두 개의 독립 절약량으로 더하지 않는다.

## 3. 주요 DP별 trade-off를 한 문장으로

| DP | 선택에 영향을 주는 상충 | 더 작은 구조를 선택할 조건 | 더 많은 상태/실행을 선택할 조건 |
| --- | --- | --- | --- |
| **01** | 유효 근거를 미리 유지해 응답/완료의 조회 대기를 줄일 가능성 ↔ 쓰지 않는 자료까지 문맥에 넣고 갱신하는 비용 | 주제 전환이 많고 재사용이 낮으면 B | 짧은 후속 질문이 많으면 A. 여러 대화의 반복 관계 소비가 크면 C 또는 A+C |
| **02** | 새 입력의 앞선 VIA 판단 대기를 줄일 가능성 ↔ 분리 문맥/반환과 활성 상태의 비용 | 호출 여유가 없거나 대부분 짧은 판단이면 A | 독립 입력이 긴 VIA 판단과 자주 겹치고 호출 여유가 있으면 B |
| **04** | 밀집 화면의 대상을 명시적으로 구별할 가능성 ↔ 선행 화면/발화 생산, 추가 모델과 후보 손실/확장 비용 | 자유로운 범위/관계가 많고 공동 판단으로 충분하면 A | parser의 실제 지원 범위에 많은 지칭이 있고 구별 이익이 추가 비용보다 중요하면 B |
| **05** | 반복 인계의 준비 대기 절감 ↔ 지속 기록의 생산/갱신 및 끝내 사용하지 않는 비용 | 반복 인계가 드물거나 목적이 자주 달라지면 A | 같은 관계/조건을 여러 후속 Agent가 읽으면 B. 상세 자료 선택을 지원하는 수신자이면 C 가능 |

특정 장면에서 한 안이 여러 축 모두 유리할 수 있다. 그 장면만 전체 모집단으로 만들지는 않는다. 유지/재사용에 유리한 반복, 반대편에 유리한 주제/목적 변경, 공통 동점, 실패/철회를 각 본문에 같이 두었다.

## 4. 과정의 QA×DP 조건은 얼마나 충족되는가

기존 과정 계약은 DP별 3~4개 QA 차이, 각 핵심 QA의 두 DP 이상 차이, 최우선 QA의 전체 또는 최소 세 DP 차이를 요구한다. 이번 사용자 요청은 DP 개수 제한을 풀었지만 같은 QA의 의미를 유지하는 조건은 그대로다.

| 조건 | 설계 단계 판정 | 부족한 이유 |
| --- | --- | --- |
| DP별 중요한 반대편 이익과 비용 | 네 주요 DP에 있음 | 실제 크기/빈도는 미측정 |
| 각 DP의 3~4 QA 차별화 | 01/02/04는 주요 가설이 3개 이상. **05는 2개** | N-H나 RAM 차이를 이름만 추가해 세 번째로 만들 수 없음 |
| QA01이 최우선 DP의 주 목표 | **02가 직접 담당** | QA01 1초 달성이나 B 우위를 측정한 것은 아님 |
| QA01이 네 DP 모두, 차선으로 세 DP 차별화 | **01/02/04에 설계 경로 3개** | 05의 후속 위임 준비를 이미 표시한 첫 안내의 지연에 추가할 수 없음 |
| QA02가 두 DP 이상 차별화 | **04에 지칭 식별과 관련된 외부 간접 근거가 있음** | VIA의 temporal binding/producer 소유권 우위를 직접 검증한 근거는 아님. 01의 압축/탐색 오류 방향은 아직 미확보. 02의 관계 연결과 05의 인계 정확도를 대체 지표로 쓸 수 없음 |
| QA03이 두 DP 이상 차별화 | 네 주요 DP에 실제 경로 | QA01과 겹치는 시간은 독립 시간 절약으로 더하지 않음 |
| QA04가 두 DP 이상 차별화 | **충족 근거 없음** | 코드가 없고 동일 C01~C06 변경이 공통 adapter에서 끝날 수 있음. 상자 수로 판정 불가 |
| QA05가 두 DP 이상 차별화 | 네 주요 DP에 실제 호출/선생산 경로 | 금액과 어느 쪽이 더 싼지는 workload와 실제 비용에 의존 |
| QA06이 두 DP 이상 차별화 | **구체 상태 경로는 있으나 coverage 판정 보류** | 공유 중복을 뺀 전체 로컬 실제 상주 RAM 최고량이 같을 수 있음. 512 MB 요구는 모든 안에 유지. commit은 보조 진단 |

**따라서 “과정 평가 조건까지 모두 만족하는 최종 제출물”로 주장할 수는 없다.** 현재 분석으로 의미 있는 네 주제를 선정하는 것과 전체 coverage를 충족하는 것은 다르다. 이 한계를 없애려고 QA02를 일반 정확도로 넓히거나 실제 차이가 약한 03/07을 주요 DP로 재포함하지 않는다.

발표의 중심 축으로는 **QA01/02/03/05**를 우선 설명하고 QA04/06은 같은 정의의 회귀/조건부 차이로 공개하는 구성이 가장 정직하다. 이는 공식 QA 삭제/우선순위 재승인이 아니라 이번 자료의 설명 순서다. QA02의 두 번째 DP와 인계의 세 번째 축은 이 구성에서도 미충족이다.

## 5. 새 정확도 지표의 명확한 위치

| 후보 | 관측 단위와 성공 | 이 지표가 아닌 것 | 현재 결론 |

## 6. 이후 실행이 허용될 때 확인할 구체 항목

이번에는 실행하지 않았다. 사용자가 요청한 [네 주요 DP의 수치 산출 PoC 계획](11-minimal-poc-plan.md)은 음성 모델을 생략하고 모든 기본안의 실제 동작과 수치표를 내는 범위다. 이전의 A/B 우선과 별도 예비/확인 단계는 축소하고 총 10개 기본안 전체를 비교한다. 상세 실패 계약은 각 문제 본문의 마지막 절을 함께 따른다.

| 문제 | 먼저 확인할 좁은 메커니즘 | 같은 조건과 관측 | 결론을 바꾸는 결과 |
| --- | --- | --- | --- |
| 01 | A/B의 동일 과거 입력에서 문맥 유지와 요청별 구성, 이어 B/C 게시 비교 | 같은 원본/실제 전달/권한, 실제 첫 채택과 완료, 전체 생산 비용 | 유지 문맥이 쓸모 없이 커지면 B. C가 대부분 원본 재구성을 요구하면 생산 계층 제외 |
| 02 | 긴 VIA 판단 중 독립 입력, 동일 총 호출 한도에서 겹침과 포화 | 실제 새 답 표시와 원래 목표 지연, 전체 호출/문맥/RAM | B가 대기를 줄이지 못하고 반환 비용만 늘면 A |
| 04 | A/B, B4 병행, A4 동일 parser, parser 없는 B의 교차 비교 | 동일 관측/최종 모델/native. 밀집 UI와 자유 범위/페이지 변화 모두 포함 | A4로 같은 구별 이익을 얻으면 후보 소유 구조의 추가 근거 약화. B 생산 비용만 늘면 A 유지 |
| 05 | 반복 인계와 미사용 기록을 함께 주고 A/B 준비 비교. C는 실제 읽기 지원 구분 | 실제 위임 계약과 N-H, QA03의 기존 목표 경로, COMMON-28 전체 비용 | B가 공통 Task/01 기록 복제만 하면 제외. 지속 기록이 반복 조합을 대체하면 B 선택 조건 확인 |
| 03/06/07 | 각각 코드 활성화, 후보만 바뀐 재선택, 실제 writer 경합 | 정상/포화 분리. 다른 DP의 이익을 빌리지 않음 | 정상 중요 차이가 생길 때 주요 DP 지위 재검토 |

작은 메커니즘 확인을 COMMON-28 전체 점수로 환산하지 않는다. 제품 비교를 실행할 때 QA01/03의 새 관련 사건/목표 집합을 이 대안에 맞게 사전 명시해야 한다. 기존 DP의 v2 모집단과 예상값은 그대로 재사용할 수 없다. QA05의 전체28 비용 단위, QA02의 공통 지칭 판정과 QA04의 같은 변경 과제는 유지한다.

## 7. 이미 확인한 문서 품질

공식 source 사실과 VIA 설계 추론을 분리했고, 기본 기능/보완과 추가 dependency를 구분했다. 다른 담당자의 교차 검토 및 주 담당자의 통합 수정을 [검토 기록](reviews/README.md)에 남겼다. 정적 링크/그림/공백 확인은 문서의 일관성 확인이며 제품 성능 시험이 아니다.
