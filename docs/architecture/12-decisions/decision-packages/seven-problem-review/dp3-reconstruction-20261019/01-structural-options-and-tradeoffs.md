# DP3의 구조 후보와 실제 사용 조건

2026-10-19 / 구조 분석 및 작성자 제안 / 미구현·미측정·미선정

## 1. 이번에 바꾸는 질문

사용자는 기존 B가 어느 QA에서 유리한지 분명하지 않다면 장점을 만들어 넣지 말고 다른 구조를 찾도록 요청했다. 화면·발화 지칭이라는 DP3 주제는 유지한다. 종전 A/B의 이름이나 Module 배치만 바꾸지 않고, 실제 입력 획득·실행 의존·중간 상태·채택·복구가 달라지는지 검토한다.

현재 여섯 QA는 발표의 QA01 첫 응답 지연시간 → QA02 지칭 집합 정확도 → QA03 VIA 처리시간 → QA04 실제 Rust 변경 모듈 수 → QA05 전체 모델 비용 → QA06 로컬 RAM이다. 기존 core QA-09/19/29/39와 재번호하거나 혼합하지 않는다. 목표값·점수·COMMON-28을 변경하지 않는다.

이 문서의 ‘유리’는 조건을 갖춘 실행 전 예상이다. 기존 실측은 종전 구조의 관측으로만 인용한다. 새 후보의 미측정을 옛 수치로 채우지 않는다.

## 2. 공통 기능과 비교 경계

고정 UC-03·04의 사전 선택, 클릭 없는 포인터 지칭, 복수 지칭, 원형 집합, drag, 페이지·창 이동, 전사 지연·수정, 일부 정정을 모두 지원한다. 실제 모호함과 근거 누락을 유지하며 필요하면 확인한다. 사용자에게 모든 대상을 명시적으로 클릭하게 만드는 안은 같은 요구를 푸는 대안이 아니다.

다음은 어느 후보에도 허용하거나 요구하는 공통 기능이다.

- 허용된 원음/전사, 실제 pointer·selection, 당시 frame과 source identity/revision을 보존한다. 현재 화면으로 사라진 원본을 대체하지 않는다.
- raw 기록의 보존과 의미상 시간 대응을 구별한다. 원래 시각·도착 시각·시간 오차·gap을 기록하고, 필요한 source가 해당 구간을 처리했거나 gap을 선언하는 경계를 둔다. 시간 일치만으로 지칭 의도를 확정하지 않는다.
- native 선택이 실제로 충분하면 같은 코드 경로를 양쪽에 허용한다. 기존 A도 필요한 원본 범위를 읽고 같은 판단에서 얻은 결과를 재사용할 수 있다.
- 정책·source·input revision 검증과 중복 실행 방지는 공통이다. 채택 전 잠정 결과를 실제 업무 실행의 권한으로 쓰지 않는다.
- 같은 모델 capability, 원본 권한, 공통 Model Access 호출/연산 예산을 적용한다. 한 공유 Omni의 세션·KV를 분리하며 가중치를 역할별로 복제하지 않는다. 추가 helper는 별도 의존과 비용으로 명시한다.
- 음성 capture와 Streaming ASR은 계속 동작해야 한다. 추론 전체를 잡는 mutex로 발화 수신·인식을 막지 않는다.
- 명백한 native fast path, 원본 crop/범위 확대, 부분 갱신 같은 기능을 한쪽에서 금지해 상대의 이익을 만들지 않는다. 선택 후 보완은 개별 번호와 비용으로 구분한다.

## 3. 검토한 선택과 선별

| 검토한 선택 | 실제 구조 차이 | 반대편 이익 | 판정 |
| --- | --- | --- | --- |
| 완성 입력 후 공동 판단 ↔ 발화 중 잠정 관계 유지 | job 수명, 입력 단위, 의미 의존 상태, 무효화·최종 채택 | 후자는 긴 안정 발화의 잔여 대기, 전자는 정정·철회 때의 폐기 계산과 상태 부담 | **우선 상세 검토할 축**. 기존 A3/B3의 독립 재검토임을 명시 |
| 전체 관계 공동 판단 ↔ 발화로 지칭 질의를 만들고 source별 판단 | 발화 결과를 실제 선행 의존으로 둠. 질의와 표현별 결과를 저장·결합 | 후자는 작은 모델·다수 화면의 추론 범위 축소 가능성, 전자는 선행 질의/결합 생략 | **조건부 후보**. 현재 정확도 이익 미확보 |
| 넓은 원본 이력 보존 ↔ 이벤트·참조 중심 선택 보존 | 어떤 시점에 원본을 복사하고 무엇을 남기거나 해제하는지 | 후자는 원본 보존 자원, 전자는 사후 범위 확대와 근거 복구 | **범위 보류**. 같은 기능 유지와 실제 RAM 차이가 먼저 필요 |
| 모델 공동 판단 ↔ native 우선/시각 fallback | source adapter와 경로 선택 | native가 충분하면 모델 호출 감소 | **새 주요 대안으로 제외**. 같은 native 사용은 기존 A에도 허용 |
| 단일 판단 ↔ 별도 의미 검증자 | 추가 추론과 채택 전 합의 | 정확도 개선 가능성 대 추가 지연·비용 | **보완 후보**. 같은 모델의 상관 오류와 잘못된 거절이 있어 개선 미확보 |
| 큰 모델 공동 판단 ↔ 작은 모델의 다단계 판단 | 모델 portfolio와 역할별 capability | 자원 대 정확도 가능성 | **이번 구조 비교에서 제외**. 모델 크기·분해 효과가 섞이며 새 모델 근거가 필요 |
| 지칭마다 확인·명시 선택 요구 | interaction과 완료 경로 | 잘못된 자동 채택 감소 가능성 | **기본 대안으로 제외**. 명백한 장면까지 사용자 행동을 강제하거나 QA02 분모를 바꾸지 않음 |

선별은 주제를 늘리기 위한 목록이 아니다. 여러 선택을 하나의 안에 묶고 장점만 합산하지 않는다. 특히 첫 두 축은 조합 가능하지만 각각 따로 비교한다. 기존 B의 독립 화면 후보 생산은 어느 축의 필수 전제도 아니다.

## 4. 우선 검토: 완성 입력 후 공동 판단과 발화 중 잠정 관계 유지

### 4.1 두 구조의 기본 동작

| 항목 | 완성 입력 후 공동 판단 | 발화 중 잠정 관계 유지 |
| --- | --- | --- |
| 수집 | 발화 중 실제 근거를 계속 기록 | 동일하게 기록 |
| 최초 의미 실행 | 완성 입력 revision 뒤 시작 | partial 발화와 실제 지정 근거가 충분해지면 시작 |
| 의미 입력 | 완성 발화, 관련 원본, 이전 채택 결과 | 그때까지의 발화와 관련 원본을 **함께** 사용. 화면만 무차별 선생산하지 않음 |
| 실행 수명 | 완성 입력별 유한 attempt | 발화 안의 잠정 관계들이 수정·철회되는 동안 유지하는 attempt |
| 중간 상태 | 현재 proposal과 실제 read-set | 표현별 잠정 binding, 근거·단어 구간·revision 의존, pending job과 폐기 상태 |
| 새 정보 | 완성 입력 후 정정이면 현재 attempt의 정책에 따라 재판단 | 부분 전사·지정 동작이 바뀌면 의존 결과를 무효화하고 새 입력으로 재판단 |
| 채택 | 완성 입력·source의 현재성 확인 뒤 Request Controller가 채택 | 입력이 닫힌 뒤 같은 조건으로 채택. 이전 job의 revision을 임의로 승격하지 않음 |
| 실패 | 같은 원본에서 유한 복구, 필요 시 보류·확인 | 영향 판단 불명확·budget 초과·부분 결과 재사용 불가 시 전체 공동 재판단 또는 같은 보류·확인 |

발화 중 유지하는 관계는 최종 목표/Task를 미리 확정하는 권한이 없다. Request Controller의 채택, Task Manager와 Agent Gateway의 외부 업무 실행은 공통 확정 경계를 유지한다. Interaction Manager가 raw 근거를, Context Manager가 허용된 evidence 구성을, Request Interpreter가 의미 제안과 잠정 의존 상태를 소유한다. Model Access가 공통 자원을 배정한다.

### 4.2 같은 Excel → PDF → 메일 장면

1. Excel 범위를 선택하고 “이 매출과…”라고 말한다. 양쪽 모두 실제 선택과 발화를 보존한다.
2. PDF의 두 그래프를 가리키며 “이 두 그래프를 비교해줘”라고 이어 말한다. 완성 입력 후 구조는 원본을 기록한다. 발화 중 구조는 관측한 말과 화면으로 잠정 대상 관계를 계산할 수 있다.
3. 메일로 옮기며 “아니, 오른쪽 것만”이라고 같은 발화 안에서 고친다. 발화 중 구조는 그래프 집합과 그 관계에 의존한 결과를 철회한다. Excel 범위의 유지가 의미상 확인되지 않으면 관련 결과 전체를 재검토한다. 코드가 문구만 보고 정정 범위를 추측해 고정하지 않는다.
4. 입력이 닫히면 전자는 이제 최종 말과 보존 원본을 공동 판단한다. 후자는 남은 잠정 결과와 최종 말의 정합성을 확인하고 필요 부분을 재판단한다. 이 확인에 의미 호출이 필요하면 그 비용도 남는다.
5. 두 구조 모두 동일한 source/input/policy 조건을 통과한 결과만 채택한다. 최종 요청은 Excel 범위 유지와 PDF 오른쪽 그래프로 정리된다. 잠정 제안이 만들어졌다는 사실은 QA02의 정답 채택이나 업무 완료가 아니다.

정정이 없다면 3의 폐기가 발생하지 않아 발화 중 계산을 더 많이 활용할 수 있다. “아니, 그래프 말고 표 전체”처럼 후반부에 의미 범위가 크게 바뀌면, 전자는 처음부터 최종 의미만 계산하고 후자는 기존 계산을 버릴 수 있다. 두 조건 모두 UC-04·11의 실제 사용 범위다.

### 4.3 시작·갱신·보류의 최소 계약

- 모든 단어마다 호출하지 않는다. partial 발화 구간과 실제 selection/pointing/frame 묶음이 주어지고 지칭 처리가 가능한 시점에 유한 job을 시작한다. trigger는 현재까지 관측한 정보만 사용한다.
- 아직 말하지 않은 최종 대상·정정 여부를 알고 trigger를 고르지 않는다. 안정성 판단이 미래 정정을 막아주지는 않는다.
- job은 읽은 utterance span/revision, source snapshot, 관계 버전과 policy epoch를 기록한다. 오래된 반환은 그대로 채택하지 않는다.
- 이미 충분한 native 정보라면 양쪽 모두 같은 코드 처리를 한다. 증분 구조에만 code fast path를 주지 않는다.
- 변경은 누적 대기 중 coalesce할 수 있다. 동시 job, 보존 상태, speculative usage에 유한 예산을 둔다. 우선권이 높은 voice/foreground 일을 밀어내 얻은 시간을 이익으로 세지 않는다.
- 미결 job을 논리적으로 무효화해도 provider가 실제 실행을 멈췄는지는 별개다. 발생한 토큰·비용과 미확정 사용량, 취소·폐기 사실을 남긴다.
- ‘최종 확인’은 공짜가 아니다. 유지할 의미가 불명확하면 전체 공동 판단으로 돌아간다. 기존 후보를 항상 재사용할 수 있다고 가정하지 않는다.
- WAIT_USER·권한 철회·attempt 만료에는 잠정 session과 pin을 해제한다. 발화 중 상태가 영구 대화 기억이 되는 것은 아니다.

모델 내부의 새 학습이나 토큰 단위 수정 기능을 전제하지 않는다. 부분 입력 snapshot별 일반 호출로도 구성할 수 있지만, 그런 구현의 재전송·반복 추론 비용을 포함해야 한다. append 가능한 session이나 KV 재사용을 쓰려면 실제 runtime 지원과 동일 모델·prefix·권한 조건을 별도로 확인한다. 기존 KV를 임의로 고쳐 정정 비용을 없애는 기능은 가정하지 않는다.

### 4.4 무엇이 구조 차이이고 무엇이 단순 보완인가

기존 A3/B3가 같은 발화의 일부를 미리 보내고 add/revoke/coalesce하는 경로를 이미 제안했다. 이 문서는 그 선행 작업을 밝힌다. 주요 비교축으로 볼 수 있는 것은 **완성 입력별 attempt를 기본 단위로 삼을지, 수정 가능한 지칭 관계와 그 의존 수명을 기본 단위로 삼을지**다.

다음 중 하나라면 ‘새 주요 구조’라는 설명을 낮춰야 한다.

1. 실행 시작 시각 한 줄 외에는 상태·권한·복구가 같고, 의미 의존이나 새 무효화 계약이 필요하지 않다.
2. 기존 A의 저비용 한 번 선행 호출만으로 같은 대기·비용·기능을 얻는다.
3. 복잡한 관계 graph를 만들었지만 최종 입력 뒤 매번 전체 공동 판단을 다시 하여 잠정 결과가 실제 일을 대체하지 않는다.

이 경우 유용한 tactic일 수는 있어도 주요 DP의 강한 경쟁 구조라고 포장하지 않는다.

## 5. 이 축의 QA별 trade-off

| QA | 완성 입력 후 구조가 유리한 조건 | 발화 중 구조가 유리한 조건 | 현재 판정 |
| --- | --- | --- | --- |
| QA01 첫 응답 | 짧은 발화, 늦은 의미 변경, 공통 모델 포화로 선행 판단이 무효화·경합됨 | 지칭 가능한 내용이 발화 중 일찍 주어지고, 유효한 계산이 종료 전 완료되며 최종 확인이 작음 | **주된 반대 방향 가설**. 최종 유효 표시까지 비교 |
| QA02 지칭 집합 | 최종 말 전체를 함께 읽어 섣부른 부분 해석을 피할 가능성 | 수정·의존 경로를 명시해 부분 정정을 보존할 가능성 | **우열 미확정**. 둘 다 같은 최종 입력·원본을 사용할 수 있음. 구조만으로 정확도 승자 지정 금지 |
| QA03 VIA 처리 | 폐기 계산·최종 재판단과 자원 대기가 큰 조건 | 최종 완료에 필요한 계산을 실제 선행 수행해 남은 경로를 줄이는 조건 | **조건부 가설**. QA01과 겹친 절감량을 더하지 않음 |
| QA04 변경 모듈 수 | 단순한 attempt와 한 공동 판단 계약 안에서 변화가 끝나는 경우 | 특정 표현·의존 처리 변경이 국소화되는 경우 | **미확보**. Module 수나 ‘분리’만으로 우위 부여 금지 |
| QA05 전체 모델 비용 | 후반 정정·중단·해석 불필요 입력에서 미사용 호출을 하지 않음 | 실제 후행 재판단을 대체하고 총 토큰·호출도 줄일 때만 이익 가능 | **완성 입력 후 구조의 비용 이익 가설이 구체적**. 발화 중 구조가 항상 더 비싼 것은 아님 |
| QA06 로컬 RAM | raw 공통 보존 외 잠정 job·의존 graph·활성 KV/출력 상태가 적음 | 선행 처리로 실제 peak의 다른 사본·작업 상태까지 줄이는 경우에만 가능 | **추가 상태 경로는 명확하나 실제 peak 우열 미확정**. 가중치 복제나 cloud KV를 local RAM에 넣지 않음 |

강한 가설은 **긴 안정 발화의 잔여 대기 감소 ↔ 뒤늦은 수정·중단 때의 폐기 계산/비용**이다. 아직 여섯 QA가 모두 차별화됐다는 뜻이 아니다. 특히 QA02는 공통 정확성 요구로 두고, 새로운 정확도 비교축을 확보했다고 주장하지 않는다.

### 같은 의미의 계산과 관찰

```text
완성 입력 후의 잔여 대기
  = 완성 입력 준비 이후의 실제 공동 판단 + 검증/표시 경로

발화 중 구조의 잔여 대기
  = 종료 시점에 남은 유효 job의 실제 대기
    + 필요한 의미 재검토/재실행 + 검증/표시 경로

전체 모델 비용
  = 사용·폐기·확장·최종 확인·복구를 포함한 모든 실제 사용량

로컬 peak RAM
  = max_t(공통 보존 + 그때 살아 있는 사본/실행/상태/session 메모리)
```

이 식은 예측 시간을 계산한 모델이 아니다. 실제 timestamp·usage·메모리 기록으로 채울 경로 설명이다. 입력 종료 시각을 전사 확정 시각으로 옮겨 이익을 만들지 않는다. QA01/03의 원래 시작·종료와 인과 규칙을 유지하며, 종료 전 계산도 비용/메모리 원장과 선행 작업 진단에 남긴다. 잠정 UI나 spinner를 첫 내용 응답으로 세지 않는다. 같은 입력을 후보마다 새 Request로 쪼개 분모를 바꾸지 않는다.

## 6. 조건부 후보: 발화 질의 분해 후 source별 판단

### 동작과 실질 의존

이 구조에서는 발화를 먼저 읽어 지칭 표현별 질의를 만든다. 질의에는 원문 span, 지시 시각 후보, 대상 종류/개수, 상대 관계, 제외 범위, 유지/교체 관계와 미해결 값을 둔다. source별 판단은 이 질의를 입력으로 원본을 읽고 필요한 대상/범위를 생산한다. 같은 source에 대한 질의는 묶을 수 있고 서로 독립적인 source별 작업은 공통 한도에서 병렬화한다. 전역 집합·정정 관계 검사를 통과한 결과만 채택한다.

이는 종전 B의 독립 화면 생산과 다르다. 발화 결과가 화면 작업의 실제 선행 입력이므로, 화면은 ‘그 안의 선 부분만’ 같은 언어 조건으로 범위를 좁힐 수 있다. 그 대신 발화 질의 생산을 먼저 기다린다.

원문과 competing/unknown을 남기며 불완전한 질의를 정답처럼 확정하지 않는다. source 선택이 틀렸거나 화면·발화가 서로 영향을 주는 상황에는 질의를 수정하거나 원본 공동 재판단으로 돌아간다. 그 fallback을 비용 없는 pure 분해 성공으로 세지 않는다. 질의 결과, source read-set, 표현별 결과와 최종 제안이 중간 상태다.

### 유리할 수 있는 실제 조건과 한계

- 여러 창·페이지의 복합 지칭에서, 같은 작은 모델이 전체 관계를 한 번에 유지하는 데 실패하지만 개별 질의와 source별 판단은 수행할 수 있다면 QA02 이익 가능성이 있다. 이는 확인할 모델 조건이며 일반적 사실로 확정하지 않는다.
- 한 화면의 단순 지칭에서는 공동 판단이 선행 질의·source별 반환·전역 결합을 생략하므로 QA01/03과 QA05에 유리할 수 있다.
- 질의 입력이 작다고 전체 비용이 줄었다고 하지 않는다. 원본 인코딩·반복 원문·모든 질의와 반환·결합/복구를 포함한다.
- 기존 A도 bounded read와 여러 지칭의 한 번 판단을 할 수 있다. A의 원본을 인위적으로 크게 만들거나 똑같은 원본을 표현마다 재전송하도록 제한하지 않는다.
- A의 한 공동 책임 안에서 같은 source 질의를 사용해 동등한 결과를 얻으면, 이 비교는 별도 Architecture보다 실행 전략/보완으로 수렴할 수 있다. 최종 writer와 필수 단계 의존이 실제 달라지는지 확인해야 한다.

**판정:** 언어가 화면 생산 범위를 좁히는 구조적 차이는 있으나, 현재 VIA/모델 조건에서 반대편 QA 이익은 아직 약하다. 우선 후보보다 낮은 순위의 조건부 탐색으로 유지한다. 작은 모델이라는 말만으로 새 B의 QA02 이익을 확정하지 않는다.

## 7. 보류: 원본 이력 보존과 이벤트·참조 중심 선택 보존

전자는 허용된 시간/메모리 예산 안에서 넓은 raw 구간을 남겨 최종 발화로 필요한 장면을 선택한다. 후자는 실제 selection·pointing·source 변화 같은 사건을 인덱스화하고 당시 참조와 필요한 원본 snapshot을 고정한다. 해석에는 양쪽 모두 같은 발화와 실제 원본을 쓴다. 단순한 파일 offload, 공통 raw ring 크기 조정이나 crop cache와 구별해야 한다.

선택 보존은 원본 보존량·decode 부담을 줄일 수 있지만, 발화가 뒤에서 정한 범위가 보존 snapshot 밖이면 사라진 화면을 복구하지 못할 수 있다. 반대로 넓은 이력은 capture/보관/조회 부담을 치른다. 이 방향은 UC-03의 사전 선택과 UC-04의 창·페이지 이동 때문에 VIA에 실제 의미가 있다.

그러나 다음이 해결되지 않아 지금 강한 비교로 채택하지 않는다.

1. 양쪽에 필요한 pre-roll과 원본 보존을 제공하면서도 실제 획득·저장 authority가 얼마나 다른가.
2. native를 얻지 못하는 PDF 내부·그래프·클릭 없는 동작까지 같은 기능을 유지할 수 있는가.
3. ‘나중에 필요하다고 판명된 frame’을 oracle로 미리 고르지 않고 source gap과 범위 확대를 처리할 수 있는가.
4. 파일 크기나 보존 frame 수의 차이가 실제 QA06 peak RAM 차이인가. 공통 decode/upload 사본 정책으로 차이가 사라지지는 않는가.

필수 장면을 놓치는 선택 보존을 메모리 우승자로 만드는 비교는 하지 않는다. 당장은 공통 evidence capture/수명 상세 설계로 남긴다.

## 9. 작성자 권고와 종료 조건

1. 기존 화면/발화 독립 생산 B에 정확도 장점을 붙여 주요 DP를 유지하지 않는다. 종전 실측과 실패는 그대로 남긴다.
2. **우선 상세 검토할 질문을 ‘화면·발화의 지칭을 완성 입력별로 재구성할지, 발화 중 수정 가능한 관계로 유지할지’로 제안한다.** 이 주제는 VIA의 연속 입력과 정정에 직접 연결되고, 잔여 대기와 폐기 계산이라는 반대편 이익이 명확하다.
3. 이 제안은 구조적 trade-off의 가설을 구체화한 것이다. 실제 성능·QA02 우위·과정 coverage·최종 주요 DP 선정·참조 Architecture 변경을 완료한 것으로 보지 않는다.
4. 실질 차이가 호출 시작 시점이나 작은 cache에 그치거나, 저비용 보완이 모든 이익을 대체하면 주요 DP 승격을 보류한다. 주제가 중요하다는 이유로 비교의 강도를 과장하지 않는다.
5. 언어 질의 분해는 작은 모델·복합 지칭에서 검증할 수 있는 조건부 후보로, evidence 보존 방식은 공통 기능 유지가 확인돼야 하는 보류 후보로 남긴다.

실행하지 않은 영역의 QA 셀을 좋은 점수로 채우지 않는다. 새로운 구조를 설명하기 전에 기존 PPT의 B열이나 과거 수치를 새 후보의 결과로 바꾸지 않는다.
