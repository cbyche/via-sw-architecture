# 조건별 예측 재검증의 검토 기록

2026-10-19. [18 사전 계약](../18-prediction-validation-contract.md)에 따른 새 캠페인 검토다. 결과와 판정은 [17 발표 결과](../17-presentation-results.md)에 통합한다. 이 기록은 진행 중이며 최종 검사 완료 선언이 아니다.

> **방법론 검토로 추가 실행 보류:** 사용자가 같은 QA에 DP별로 다른 시험을 쓰는 공정성 문제를 제기했다. DP2는48/72회에서 경계 종료 후 보존했고 다른DP의 새 formal 호출은0이다. 아래 검토는 DP별 조건 진단의 내부 정합성에 관한 것으로, 공통 대표 모집단의 타당성을 확인했다는 뜻이 아니다. 초기 COMMON-28 뒤에 2026-10-15 DP-RELATED-v2가 당시 비교 방식으로 적용된 이력이 있다. COMMON-28 전체가 항상 현행 대표 계약이었다는 초기 검토 발언은 정정한다. 새 공통 평가의 범위와 연결 구현은 별도 동결이 필요하다.

## 실행 전과 진행 중 독립 검토

| 검토 대상 | 확인한 사항 | 발견과 처리 |
| --- | --- | --- |
| DP1과 DP4의 PLAN, fixture, oracle, 실행 연결 | 낮은 재사용과 높은 재사용의 최초 원본 및 획득 사건이 동일함. 후속 질문의 내용이 같고 횟수를 달리함. oracle은 평가기에만 제공됨 | 읽기 전용 교차 검토에서 새로운 P1/P2 미발견. 최초 소비 조건은 준비가 끝난 상태이며 cold startup을 검증하지 않음 |
| DP4의 기확보 원문 사용 | 모든 방안에 같은 실제 원문 획득 경로를 주고 A의 직접 사용과 B의 기록 직접 사용을 허용함. 파생 설명과 수신자 내부 상태는 VIA의 실제 획득 원문으로 승격하지 않음 | 담당자 사전 감사에서 active 참조 소스와 이전 effective source의 차이를 발견. formal freeze 전에 교정된 effective DP05 소스를 복사하고 이전 offline probe는 임시 검사로 보존 |
| DP2의 목표와 분모 | 방안별 QA01 72입력, QA03 54목표. 정정은 원래 입력 시점의 같은 목표 revision 2로 완료해야 함. 실제 capture는 대기 전에 기록됨 | 구현 사전 검사에서 겹침 없는 정정의 새 revision 완료 누락을 공통 수정. 새 source로 동결하고 기존 결과는 보존 |
| DP2의 실행과 비용 | A 경계 대기, B pending 입력 확인, 현재 revision 재판단, 공유 K 제한, 실제 API 중첩, 모든 비용과 실패 보존 | 읽기 전용 교차 검토에서 현재 시험을 무효화하는 계약 오류 미발견. 현재성 검사와 완료 게시가 단일 원자 연산은 아니므로 임의 시점의 revision race를 일반적으로 보장하지 않음 |
| DP2의 실패 집계 | U2 capture 전 host 실패도 예정분모에 남아야 함 | 분석기의 필수 U2 검색이 예외를 일으킬 수 있음을 지적. candidate와 fixture 동결을 유지하면서 분석기 별도 버전에서 미관측 처리 보강 요청 |
| 본문 정확성과 시간 경계 | 실제 채택 callback과 host 완료를 시간 끝점으로 사용함. 본문 표식, N-R, N-H는 별도 진단 | DP2 초기 실제 응답에 요구한 세 절 형식 누락과 수치 관계 오류 관측. DP4의 단어 표식만으로 부정 조건 정확성을 증명할 수 없음. 빠른 callback을 의미적으로 올바른 전체 응답의 증거로 사용하지 않음 |
| 측정 창 간 간섭 | 실제 지연 측정 중 다른 DP의 API와 무거운 로컬 실행을 중지함 | DP2 첫 trial 시작 직후 DP3 parser probe 중지 확인. 첫 trial은 삭제하지 않고 잠재 간섭 표시 및 제외 민감도를 별도로 요청. 이후 측정 창을 직렬화 |

## 검토 한계

읽기 전용 검토는 실제 원시 결과 대조와 실행 검사를 대신하지 않는다. 세 반복은 유한 작성 사례의 반복이며 실제 사용자 분포의 독립 표본 수가 아니다. QA04 실제 patch 수용 검사, QA06 동시 RSS 및 원자료 재집계, 최종 문서 연결 검사는 수행 결과와 함께 후속 기록한다.
