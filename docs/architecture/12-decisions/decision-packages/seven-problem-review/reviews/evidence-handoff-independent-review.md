## 1. 현재 판정

열린 P1/P2는 발견하지 않았다. P3 두 건은 원저자 보완을 재확인하여 모두 닫았다. 현재 확인 범위에 열린 P1/P2/P3는 없다. 원문을 직접 수정하지 않았다.

## 2. 발견

### EH18-R1 / P3 / 업무 인계의 두 비교축과 B+C를 명시

**상태: 수정 후 닫힘.** 원저자가 05 §2.3을 추가했다. A/B와 A/C에서 고정하는 조건, B/C의 두 축 변경, B+C 교차 구성과 최초 주 비교 A/B를 명시한 것을 재확인했다.

- 위치: 05 §1 기본안 표, §4.3 마지막 두 문단, §10.1.
- 관찰: A/B는 VIA가 세부를 고르는 조건에서 준비 수명이 다르다. A/C는 실제 위임 시 준비하는 조건에서 세부 선택 책임이 다르다. §4.3은 일반적인 수신자 읽기를 A/B에 붙이는 조합을 허용하지만, 01 §2와 같은 비교축/교차 구성 설명은 없다.
- 영향: A/B/C가 같은 하나의 배타적 선택으로 읽히면 지속 업무 기록과 수신자 읽기를 함께 쓰는 B+C가 배제되거나 C의 이익을 준비 수명 때문이라고 오해할 수 있다.
- 제안: 주 비교 A/B와 보조 비교 A/C를 구분하고, B+C는 지속 기록으로 필수 manifest/자료 목록을 준비하면서 수신자가 세부를 선택하는 교차 구성이라고 짧게 명시한다. 기본 record 참조 전달을 새 tactic으로 만들지 않는다.

### EH18-R2 / P3 / 공통 근거 뒤에 남는 인계 생산을 한 사례로 보이기

**상태: 수정 후 닫힘.** 원저자가 05 §4.2 끝에 공통 Task 필드, 01 C의 기존 근거와 아직 없는 공개 결과 설명 블록을 구분하는 예를 추가했다. ID/조건 복사는 새 모델 생산이 아니며, 구조화된 설명은 코드로 읽고, 동일 블록이 이미 제공되면 A도 재사용하여 B의 추가 생산/절약을 0으로 처리한다고 명시했다. 새 domain 평가/계획을 추가하지 않은 것도 확인했다.

- 위치: 05 §2.2의 B 추가 상태, §4.2, §7 H2.
- 관찰: 공통 Task/01 기록 복제만이면 B 차이가 소멸한다는 반증과 비용 중복 금지는 명확하다. 다만 현재 예에서 ‘업무 설명, 적용/대체 관계, 미해결 범위’가 01 C의 relation/coverage와 얼마나 겹치는지 독자가 직접 대조해야 한다.
- 영향: 독립 DP 선정은 소비자 이름만 바뀐 기억 생산이 아니라 실제로 다음 인계 구성을 대체하는 잔여 생산이 있다는 조건에 달려 있다. 이 조건을 명시한 현재 결론은 타당하지만 설명이 추상적이다.
- 제안: H2에서 이미 제공되는 공통 Task 필드와 01 근거, 그 뒤 A가 목적별로 만드는 부분, B가 미리 생산해 재사용하는 부분을 한 행씩 예시한다. 남는 일이 단순 ID 복사이면 모델 비용을 붙이지 않고 B 이익도 없는 사례로 둔다. domain 계획을 새 생산 내용으로 만들 필요는 없다.

## 3. 확인한 경계

| 검토 사항 | 판정 |
| --- | --- |
| 01 A/B/C의 축 | A/B는 작업 문맥 수명, B/C는 게시 근거 생산으로 구분되고 A+C가 공개됨. A 대 C에서 두 축의 원인을 단정하지 않음 |
| 01 C의 필수 기능 | 원본 보완, 파생 오류 신고, 게시 coverage와 권한/원본 판본 확인이 기본에 남음. unsupported relation을 무조건 게시 대기로 강제하지 않음 |
| 기본 상태와 tactic | A 유지 view와 B/C의 지속 기록 재사용은 기본. prefix cache, 부분 갱신, 인계 capsule cache와 native session 재사용은 별도 보완 |
| 근거와 인계의 경계 | 현재 의미 판단 입력과 외부 실행 허가 계약을 구별. 공통 생산은 실제 job/call ID로 한 번 계상하고 A에도 유효 근거를 허용 |
| QA02와 N-H | 지칭 채택 후 인계만 바꾸면 QA02 동점. source/조건 인계 오류는 고정 tuple과 execution authorization의 N-H로 판정. 후속 수정이 최초 오류를 지우지 않음 |
| QA01/03 | 첫 구체 내용 이후 인계를 QA01에 붙이지 않음. QA03은 기존 endpoint 내 VIA 인과 경로만 포함하고 이후 serving과 외부 판단은 별도 진단 |
| QA05/06 | 미소비 선생산, 재시도와 취소 후 청구 포함. 외부 비용 이동을 총비용 절약으로 세지 않고 범위 read가 backend RAM 절감이라는 가정도 하지 않음 |
| 실제 API 범위 | ACP 연결/버전, resume/load/fresh, 원본/공개 transcript의 실제 접근과 누락을 구별. 임의 Agent 내부 상태의 이전을 가정하지 않음 |
| 주요 DP와 과정 coverage | 05의 QA03 대 QA05 설계 손익을 인정하면서 세 번째 중요 차이와 N-H 우열의 미확인을 공개. 그 부족을 임의 정확도 이익으로 채우지 않음 |

## 4. 검토 범위와 한계

두 설계 문서 전체, 공통 규칙과 연결된 새 source 원장의 구현/추론 구분을 대조했다. 이번 검토에서 모든 외부 repository를 다시 checkout하거나 source link 전부를 직접 재열람하지 않았다. source 원장의 직접 확인 주장은 원저자의 조사 범위이며, 이전 독립 검토에서 확인한 일부 경로와 이번 문서의 사용 범위가 충돌하는지 살폈다.

문서 링크/표기 검사는 의미 성능 검증이 아니다. 실제 API 지원, 외부 Agent의 자료 선택, 모델 품질/요금, Windows RAM, 운영 Rust 변경 수와 PoC는 실행하지 않았다. 주요 DP 권고를 사용자 승인이나 측정 우위로 간주하지 않는다.
