# 종합 결론과 QA 표의 화면 지칭 검토

대상: [08 최종 DP 세트](../08-final-dp-set.md), [09 QA trade-off](../09-qa-tradeoffs.md)의 화면 지칭 판정. 대조 문서는 [04 통합 설계](../04-screen-speech-grounding.md)와 [공식 근거 원장](../../../../../references/seven-problem-review/screen-grounding.md)이다.

## 1. 현재 판정

화면 지칭의 주요 DP 포함, 초기 기본 A 권고와 B의 반대편 이익 설명에서 P1/P2는 발견하지 않았다. P3 한 건은 주 담당자의 수정을 재확인하여 닫았다. 현재 확인 범위에서 열린 P1/P2/P3는 없다. 08/09 원문은 직접 수정하지 않았다.

### SG-F1 / P3 / 외부 간접 근거를 직접 근거라고 줄이지 않기

**상태: 수정 후 닫힘.** 09 §4의 해당 행을 다시 읽었다. `04에 지칭 식별과 관련된 외부 간접 근거가 있음`으로 수정되었고, VIA의 temporal binding/producer 소유권 우위를 직접 검증한 근거가 아니라는 한계를 같은 행에 명시했다.

- 위치: 09 §4 과정 coverage 표, `QA02가 두 DP 이상 차별화` 행의 `04의 직접 근거만 상대적으로 강함`.
- 관찰: 08 §2.3과 04 §8.4는 OmniParser의 정지 UI 대상 연결 실험을 VIA 시간 지칭의 간접 근거로 제한한다. 이 표의 `직접 근거`만 읽으면 실제 VIA QA02를 직접 검증한 것으로 읽힐 여지가 있다.
- 수정 제안: `04에 지칭 식별과 관련된 외부 간접 근거가 있음`으로 쓰고, VIA QA02 실측이나 producer ownership 검증이 아니라는 범위를 유지한다.
- 영향: 주요 DP 포함이나 기본 A 권고를 바꾸는 발견은 아니다. 인접 시스템의 실험을 현재 제품의 직접 근거로 승격하지 않기 위한 표현 정밀화다.

## 2. 확인한 일관성

| 항목 | 확인 |
| --- | --- |
| 포함 근거 | B의 후보 재사용만으로 총비용 절약을 약속하지 않는다. 별도 화면 표현의 QA02 가능 이익과 QA03/05 생산 비용을 비교한다 |
| 원본과 공통 기능 | 당시 원본 보존과 시각 대응은 공통이다. B의 raw 확장을 기본으로 남기며 A의 한 번 다수 지칭을 제한하지 않는다 |
| 결합과 소유권 | QuickSet은 typed 결합의 근거이며 자유 지칭 전체의 코드 해결 증거가 아니다. 의미가 부족하면 원 producer가 확장한다 |
| 외부 실험의 범위 | 08 §2.3은 동일 최종 모델의 시각 표현 비교와 VIA temporal binding/producer ownership을 명확히 구별한다 |
| 추가 의존의 비용 | B의 parser와 producer 비용 및 영역 분할/crop 손실을 남긴다. 공짜 helper나 로컬 RAM 절감으로 설명하지 않는다 |
| 기본과 tactic | 초기 기본 A와 A1/A2 보완을 구분한다. 09 §6은 A4 동일 parser와 parser 없는 B의 교차 구성으로 효과 귀속을 확인한다 |
| 순차 실행 | 09 §2와 §6은 B4 병행 가능성을 명시한다. 기본 순차 정책만으로 B 전체의 필연적 지연을 주장하지 않는다 |
| QA coverage | QA01/03의 중복 시간을 합산하지 않는다. QA04/06의 차이는 조건부이며 전체 과정 조건 충족으로 과장하지 않는다 |

## 3. 상세 그림 확인

[A 상세 PNG](../diagrams/dp47-seven-A-detail.png)와 [B 상세 PNG](../diagrams/dp47-seven-B-detail.png)를 각각 열어 확인했다. 입력/원본, 실행 역할, 상태, 조건부 cloud 의존, 정정/실패와 보완을 같은 위치에 배치했다. 본문 25 px와 35 px 행 간격을 유지하고 renderer의 글자 축소에 기대지 않도록 생성기에서 폭/높이를 확인했다.

기본 B의 두 생산 화살표는 의존 경로이며 동시 실행을 뜻하지 않는다. 순차 dispatch가 기본 정책이라는 문장과 B4의 별도 위치를 그림에 명시했다. candidate 생성만으로 raw를 해제하지 않고, cloud helper 가중치와 local 상태를 구분했다.

## 4. 검토 한계

종합 문서와 담당 상세/근거 문서를 대조한 빠른 검토다. 이 단계에서 외부 source 전부를 다시 읽거나 실제 API, 모델, Windows capture, 메모리와 요금을 실행하지 않았다. 그림의 픽셀 확인과 정적 폭/링크 검사는 문서 품질 확인이며 제품 성능 시험이 아니다.
