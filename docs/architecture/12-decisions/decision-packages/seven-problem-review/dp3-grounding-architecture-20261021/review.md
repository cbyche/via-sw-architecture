# DP3 A/B 상세 설계 검토 기록

2026-10-21 / 문서와 구조 검토 / 구현·모델 실행·성능 평가 아님

## 검토 범위

두 독립 검토자가 [설계 문서](README.md)를 각각 검토했다. 첫 검토는 A의 기능 대등성, QA01/03 경계와 시간식, QA02/07의 중첩과 비용 계상을 확인했다. 둘째 검토는 B의 A+α 여부, 시각 생산과 의도 해석의 구분, 기존 DP47 계열과의 관계, 공식 구현 근거의 적용 범위를 확인했다.

## 발견 및 수정

| 중요도 | 발견 | 반영 |
| --- | --- | --- |
| P2 | 정확한 timestamp만으로 desktop pointer와 확대/crop frame 좌표를 연결할 수 없음 | 공통 좌표계 계약과 `coordinate_frames`를 추가. frame 크기, monitor/DPI, desktop/window 변환, crop offset/scale과 불확실성을 보존하며 불명확한 변환은 unknown 처리. |
| P2 | B 초기 생산 시간과 확장 경로에 같은 재생산 구간이 중복될 수 있음 | `P_B`는 첫 후보 revision까지, `G_B`는 이후 결합과 추가 조회·재생산·재결합으로 구분. 병렬 구간은 실제 의존 그래프를 따름. |
| P2 | QA03 제외 설명에서 후속 사용자 발화와 순수 청취·재생 차례가 빠짐 | 기존 QA03의 제외 항목과 VIA 포함 항목을 명시. 확인 질문 생성 및 답변 이후 재해석은 포함. |

검토에서 A의 원본 확대·재조회·복수 추론·native 정보·재사용을 제한한 문제는 보고되지 않았다. B의 후보 누락·경계 오류·identity drift를 공개하고, QA07 개선을 QA02와 독립 효과로 부풀리지 않은 점도 확인했다. 동일 시각 생산을 A의 보완으로 추가했을 때 B의 전체 계약이 실제로 필요한지 반증할 조건을 유지한다.

두 검토자가 각자 제기한 수정부를 다시 확인했으며, 위 세 P2의 해소를 보고했다. 해당 검토 범위에서 남은 P1/P2는 없다. 구조의 실제 성능을 확인한 리뷰는 아니다.

## 로컬 생산기 판본의 추가 검토

사용자가 B의 시각 생산을 local로 지정한 뒤 [local 판본](local-producer.md)을 별도로 검토했다. 이전 cloud 본문·그림은 보존하고 README 첫머리에서 현재 판본을 안내했다.

- QA 독립 검토: 강한 A, 조건부 모델 호출, SAM2 capability의 한계, cold-load와 요청 내 재사용/해제, QA05 청구액과 local 운영비의 구분, QA06 512 MB 목표와 동시 물리 RAM peak, QA02/07 중첩, 실패와 권한 처리를 확인했다. 해당 범위에서 P1/P2는 보고되지 않았다. “ASR·시각 생산”이 vision으로 오해될 수 있다는 표현 의견을 반영해 본문은 “ASR·단어 timestamp 생산”, 그림은 “ASR·단어 시각”으로 명확히 했다.
- 별도 공식 라이선스 조사: OmniParser root CC BY 4.0, 원래 detector AGPL-3.0, 새 v3 detector와 caption MIT, SAM2 코드/체크포인트 Apache-2.0와 cctorch BSD-3-Clause를 확인했다. 새 detector 경로에 불필요한 Ultralytics runtime이 원래 requirements를 통해 들어올 수 있는 점을 문서에 반영했다. 실제 제품 전체 의존성 감사를 수행한 것은 아니다.
- 새 local SVG/draw.io의 생성 동기화, XML·ID·경계·직교 경로·노드 관통 검사와 local 문서 링크 검사가 통과했다. 그림 작성자와 주 검토자가 AppKit PNG 렌더를 확인했다. QA 검토자의 그림 검토 범위는 텍스트·구조였다.

이 검토는 local 모델의 실행 성공, 가속기 호환성, 512 MB 달성이나 실제 QA 우열을 확인한 측정이 아니다.

## 소형 CPU 구성과 합성 예산의 추가 검토

[CPU 구성](cpu-small-synthetic-budget.md)은 별도 두 관점으로 검토했다. 공식 모델 조사에서는 caption 생략 경로, 기존 작은 AGPL detector와 MIT v3의 차이, SAM2.1 Tiny 38.9M과 기본 1024 입력을 확인했다. 예산 검토자는 전체 VIA RAM·load/회수 overlap·지속 ASR·실제 실행 RAM과 weight-only의 구별, 단일 요청 시간과 정확도 모집단의 분리를 확인했다.

독립 재검토에서 문서 범위의 P1/P2는 보고되지 않았다. 300+16+180=496 MB, 남는 16 MB, 시간 차이 3.6초와 가상 정확도 분수의 산술이 일치한다. local 링크와 diff whitespace 검사도 통과했다. **180 MB stage 예산의 실제 구현 가능성, CPU 속도나 정확도를 검증한 것은 아니다.** 이 값은 설계 가정이며 기존 결과와 점수에 반영하지 않았다.

## CPU runtime과 상주·회수 구조의 추가 검토

사용자가 이번 검토에서 512 MB 상한을 제외한 뒤 [CPU runtime 설계](cpu-runtime-architecture.md)를 별도로 작성했다. 앞선 합성 예산은 보존하되 현재 구성의 실행 RAM·지연·정확도로 계승하지 않았다.

- 공식 구현 검토자는 OmniParser v3의 CPU TorchScript 경로, SAM2의 CPU builder, checkpoint 파일 크기와 실행 RAM의 구분, CPU thread 설정과 코어 예약의 차이, CUDA 후처리 생략 조건, 영상 frame 배열 산술을 확인했다. 해당 범위에서 P1/P2는 보고되지 않았다. 작은 명료화 의견에 따라 패키징 트리의 SAM2 config 위치를 설명 코드와 일치시켰다.
- 구조 검토자는 P2 한 건을 지적했다. 모델 상주가 줄이는 load/session 초기화 비용과 episode 보존이 줄이는 embedding/추적 상태 재계산 비용이 일부 섞여 있었다. 표·실행 순서·시간 설명·메모리 식·QA03을 수정했고, residency 자체의 비교에서는 R1/R2의 episode 보존 조건을 동일하게 명시했다. 검토자는 수정부를 재확인하여 해당 P2 해소를 보고했다. 활성 작업·참조의 종료와 session 유휴 정책도 명시했다.
- 새 runtime SVG/draw.io는 생성 동기화, XML·ID·경계·직교 경로·노드 관통 검사를 통과했다. 작성자와 주 검토자가 오프라인 PNG 렌더를 확인했다. 마지막 문구 수정으로 R2의 최초 필요 시 로딩 정책을 본문과 일치시켰고 생성 검사를 다시 통과했다.

위 검토 범위에서 미해결 P1/P2는 없다. 실제 모델 설치·추론·export·native Windows 패키징·성능 측정은 수행하지 않았다. CPU API 지원과 제품 성능 검증을 구별한다.

## 네 완성 대안 비교의 후속 검토

사용자의 제안으로 [runtime 설계 §11](cpu-runtime-architecture.md#11-a와-b-r1b-r2b-r3의-네-대안-비교)에 A / B-R1 / B-R2 / B-R3의 QA01~07 비교를 추가했다. 독립 검토자는 해당 절을 읽고 P1/P2 또는 사실과 다른 단정이 없음을 보고했다. 정확도·모델 상주·병렬 실행·process 격리의 효과 분리, R3의 조건부 이익과 R2 제한 병렬 교차 조합, QA04의 Rust 변경 모듈 수 유지, 전체 RAM 및 cloud 청구 비용의 비교 조건을 확인했다. 이는 네 안의 설계 비교 검토이며 모델 실행·측정·승자 채택을 뜻하지 않는다.

## 네 대안 합성 수치의 검토

사용자 요청에 따라 [가상 QA 평가](synthetic-comparison/README.md)를 별도 Voice+Screen profile로 작성했다. DP2/DP5의 기존 Text 공통판과 BASE는 보존했다. 120개 평가 입력·표현·목표와 60개 준비 활동을 네 구성에 적용하고 응답, 시간 단계, 비용, RAM과 C01~06 목록에서 집계했다. 모델 실행 기록은 아니다.

두 독립 검토에서 중복 제거 후 P2 두 건을 수정했다.

| 발견 | 수정과 재검토 |
| --- | --- |
| 비동기 모델 회수와 Agent 전달이 같은 0.15초 동안 서로 다른 weight 생존 상태를 기록 | 회수 종료까지 두 경로에 같은 weight를 유지하고 이후에 제거했다. 검토자가 겹치는 구간의 동일 상태를 확인했다. |
| S2/S4의 직사각형 포함 관계와 준비 목록 확인에 불필요한 SAM을 추가했으며 S3의 과거 단일 지칭에도 추적 이유가 약함 | S2/S4와 해당 준비의 SAM을 제거하고 재집계했다. S3는 두 시점의 지칭을 중복 제거하는 요청으로 구체화했고 native ID·고유 OCR·content transform 없는 시각 대응을 명시했다. SAM을 준비한 이전 요청도 독립된 과거 clip의 중복 제거로 연결했다. 두 검토자가 호출 근거와 재산출 수치를 확인했다. |

최종 QA01은 A 3.4667 / R1 5.7833 / R2 5.2833 / R3 5.3233초, QA03은 5.9833 / 8.3000 / 7.8000 / 7.8400초다. 정확도 분수, 비용, RAM peak, S5 재사용 비중 임계 91.7%도 독립 재계산과 일치했다. 해당 검토 범위에서 미해결 P1/P2는 없다. 이 확인은 작성한 구조와 산술의 일관성에 한정되며 모델 정확도·CPU 성능·물리 RAM의 현실성을 측정한 검증은 아니다.

## 검증의 한계

문서의 로컬 링크, 그림의 XML·ID·좌표와 SVG/draw.io 생성물 동기화를 확인했다. macOS AppKit으로 SVG를 오프라인 PNG로 렌더하여 실제 그림을 확인하고, 여러 줄 텍스트와 화살촉의 렌더 호환성을 수정했다. 이러한 검사는 모델 capability, 실제 QA 우열, 제품 구현의 현재성이나 측정 결과를 입증하지 않는다. 기존 DP47 실측과 이번 제안 구성의 결과를 혼합하지 않았다.

## 발표 SW 구조 그림 v7 재작성

[발표 구조 계약](presentation-architecture-contract.md)으로 소유권·실행·상태 수명을 먼저 고정하고, DP1·DP2·DP4의 도형 문법에 맞춰 발표 10~12쪽을 재작성했다. 독립 검토자는 v6의 UI/SAM fanout, 후보/episode 소유권 혼합, 최종 채택 주체 누락, model session 실행 주체 표현을 지적했다. 수정 렌더를 검토하며 발견한 RAM 귀속·라벨 넘침·IPC 출발점까지 수정하고 재확인했다. 최종 범위와 한계는 [v7 검토 기록](../../../../../presentations_files/dp1-dp4-reference-style-20261019/dp3-v7-review.md)에 있다. QA 수치는 기존 합성 원장을 유지한다.
