# 주요 DP 네 개의 수치 산출 PoC 계획

2026-10-18 / 사용자 정정 반영 / 승인된 구현과 실제 실행 완료

> **완료 결과:** [12 실제 수치와 선택](12-poc-results.md). 기본 120회, 선택 후 보완 12회와 화면 병행 B4 진단 3회를 완료했다. 실제 호출 579회, 정가 환산 $0.7207640. 원래 기본 freeze와 DP05 공통 수신자 v2, 보완별 freeze 및 원시 실패를 각각 보존한다. 아래는 실행 전 계획과 계약의 이력이다. PoC 수치 산출 완료를 모든 기능 조건의 통과로 해석하지 않는다.

## 현재 수행 지시

사용자는 네 주요 DP의 10개 기본안을 실제 구현하고 실행하여 QA trade-off 분석을 수치로 끝내도록 지시했다. 계획과 결과 검토는 주 세션이 맡고, **코드 개발과 코드 실행은 명시적으로 GPT-6.1 Sol / High로 생성한 세 sub-agent가 담당**한다. 이는 PoC 내부의 의미 모델과 별개다. PoC 의미 모델은 §3.1의 Alibaba Qwen3.7-Plus다.

- 공통 실행기, 계측, UI, 02 구현 및 전체 실행 통합 담당
- 01 근거 공급과 05 업무 인계의 여섯 기본안 및 입력 자료 담당
- 04 화면 지칭의 두 기본안 및 동일 화면 입력 자료 담당

신규 후보는 `prototypes/candidates/four_dp_poc/`, 실행기와 입력/정답은 `benchmark/architecture/four_dp_poc/`, 신규 결과는 `results/architecture-evaluation/current/four-dp-qwen37-20261018/`에 둔다. 기존 DP41 코드와 결과는 보존한다. 실행 직전에 후보 코드, 입력, 별도 정답, 모델 설정, 가격과 지표의 버전을 남긴다. 기능 실패와 모든 청구 호출을 보존하며 기본 결과와 선택 후 tactic 결과를 구별한다. 초기 전체 API 지출 상한은 $5로 두고 준비/재시도/본 실행/보완 실행이 하나의 예산 원장을 공유한다.

이 승인은 현재 네 DP PoC의 구현, 필요한 확인 실행, 실제 모델 호출과 측정 및 결과 분석을 포함한다. 아래의 실행 전 설명은 계획 수립 이력으로 읽으며 현재 수행을 막는 미승인 조건으로 해석하지 않는다. 최종 결과와 실제 완료 건수는 실행 결과 보고서에 기록한다.

## 1. 이번 PoC의 완료 조건

사용자는 실제 동작을 볼 수 있는 최소 구현과 QA의 수치 및 관측 우열을 원한다. **제시한 기본안 전부의 실행, 같은 시나리오의 측정값, 차이와 선택 이유를 반드시 결과로 낸다.** 근거 공급 A/B/C, 의미 판단 실행 A/B, 화면 지칭 A/B, 업무 인계 A/B/C의 총 10개 대안을 평가한다. C를 조건부 후속 작업으로 미루지 않는다. 별도 예비 실험과 새 자료 확인 실험을 필수로 두었던 이전 계획을 축소한다.

- 시나리오와 A/B 또는 A/B/C를 선택하면 입력과 처리 및 결과를 화면에서 볼 수 있다.
- 각 QA에 모든 기본안의 값, 차이, 관측 방향과 오류 건수를 표시한다.
- 원시 시간, 모델 usage, 채택 대상과 위임 내용, 실행 환경을 CSV/JSON으로 저장한다.
- 기본안을 선택한 뒤 tactic 하나의 전후 숫자를 추가한다.

표 제목은 **이번 PoC 조건의 기본안별 측정 결과**다. 통계적 유의성이나 제품 전체 검증을 첫 결과의 선행조건으로 삼지 않는다. 값은 실제 관측하거나 명시한 계산으로 산출한다. 같은 값이면 동점, 다른 값이면 이번 표본에서의 방향을 표시한다. 구조에 대한 설명은 그 숫자와 실제 처리 기록에 연결한다.

[이전 상세 계획 보존](../../../../archive/seven-problem-poc-plan-before-numeric-first-20261018/11-minimal-poc-plan.md). 이전의 90회 예비/170회 확인, 5회 확인 반복과 10%/100ms 선택 문턱은 현재 필수 계획이 아니다.

## 2. 음성 모델은 실행하지 않는다

사용자 발화는 미리 작성한 전사 문장과 입력/정정 시각으로 재생한다. 화면 지칭에는 같은 screenshot, pointer/selection 기록과 지칭 표현의 시점 정보를 제공한다. 모든 A/B에 같은 입력을 사용한다. 녹화 대신 작성한 사건 원장을 쓰면 작성한 시험 입력이라고 표시한다.

음성 인식, 음성 합성, 실제 마이크/스피커 입출력과 외부 업무 앱 조작은 생략한다. PoC의 입력은 전사 근거가 준비된 Text 사건이고 출력은 **Voice OFF의 실제 텍스트 표시**다. 음성 인식/합성 지연을 임의 상수로 더해 전체 음성 응답시간처럼 보이지 않는다. 업무 인계 C의 자료 선택을 평가하기 위한 작은 실제 LLM 수신자는 A/B/C 공통으로 사용한다.

이렇게 해도 근거 공급, 의미 실행 분리, 화면과 표현의 결합, 업무 인계의 처리 차이는 실행할 수 있다. 음성 인식 오류에 대한 견고성은 이번 결과의 범위에 포함하지 않는다.

## 3. 의미 LLM은 필요한 단계에서 실제 호출한다

**권고 구성은 음성 모델 0개 실행, 실제 의미/vision LLM 호출, 고정 외부 사건과 필요한 최소 수신자다.** 다섯 harness를 모두 설치하거나 각각의 전체 제품을 실행할 필요는 없다. 참고한 구조의 핵심 처리만 구현한다.

| 부분 | 처리 |
| --- | --- |
| 문맥 요약/압축과 요청 해석 | 실제 LLM. 필요한 시점에만 호출 |
| 원본 ID/범위 조회, revision/권한 검사 | 코드와 실제 파일 읽기 |
| 화면/발화 후보 생산과 지칭 해석 | 실제 모델 또는 선택한 parser. 정답 후보를 미리 주지 않음 |
| 관계가 충분한 후보 결합 | 코드. 애매하거나 후보 확장이 필요할 때 실제 모델 |
| 인계 설명의 생산/갱신과 목적별 구성 | 의미 가공이 필요한 부분만 실제 LLM |
| 01 C의 게시 관계 생산과 조회 | 동일 원본에서 실제 관계를 생산/갱신하고 요청 시 읽음. 미소비 생산 비용도 포함 |
| 05 C의 수신자 자료 선택 | 작은 LLM 수신자가 허용된 자료 읽기 도구로 필요한 범위를 골라 읽고 구조화된 결과 반환. 같은 수신자와 도구를 A/B에도 제공 |
| 그 밖의 외부 업무, Agent 질문과 결과 | 인계 수신을 확인하는 대역과 공통 사건 원장 |

모델을 전부 고정 응답으로 바꿔도 동작 시연과 코드 실행 측정은 가능하다. 다만 그때의 의미 정확도와 모델 시간은 설정한 대역을 평가하는 값이다. 실제 의미 정확도와 모델 비용을 얻는 이번 결과본에는 실제 호출을 사용한다.

LLM의 모델/설정, 출력 요구, 전체 호출 한도와 원본은 모든 기본안에 공통이다. 각 구조가 실제로 요구하는 호출 횟수와 입력량은 달라도 된다. 준비, 미사용 생산, 재시도 및 폐기 호출까지 usage에 포함한다. 같은 model adapter를 재사용해 구현량을 줄인다.

### 3.1 Qwen 계열과 기존 Alibaba API를 사용하는 구성

2026-10-18 사용자는 고가 최상위 GPT 제안을 거절하고 **기존 Qwen3-30B보다 나은 수준의 Qwen 계열 모델을 적정 비용으로 사용**하라고 정정했다. Alibaba API는 보유하고 있다. 앞선 GPT-6 Astra/high 제안은 철회한다.

이번 PoC의 기본 모델은 **Qwen3.7-Plus의 고정 버전 `qwen3.7-plus-2026-05-26`, `enable_thinking=false`**로 정한다. Plus 계열의 텍스트 및 이미지 처리와 공개 단가를 고려한 교체 선택이다. 기존 모델보다 VIA 사례의 정확도가 높다는 실측 결론은 아직 아니다. Alibaba의 [시각 입력 문서](https://www.alibabacloud.com/help/en/model-studio/vision)와 [thinking 설정 문서](https://www.alibabacloud.com/help/en/model-studio/deep-thinking)를 근거로 사용한다.

- 기존 Alibaba 연결 경로를 사용한다. 과거 코드의 기본 endpoint는 Singapore/International이다. 2026-10-18 기본 샌드박스에서는 보이지 않았지만 샌드박스 밖의 항목 조회에서 기존 Keychain의 `via-dashscope-api-key`와 `via-dashscope-workspace-id` 존재를 확인했다. 비밀번호를 읽거나 출력하지 않았으며 사용자에게 재등록을 요구할 필요가 없다. 이전 설정 세션에는 Qwen 실제 호출 HTTP 200 성공 기록도 있다. 새 모델 버전의 실제 접근 가능 여부는 호출 준비 시 확인한다.
- 처음에는 thinking을 명시적으로 끈다. 요청 해석과 구조화된 짧은 출력에 필요한 비용과 지연으로 시작한다. 기본 의미 과제에 반복 실패하면 프롬프트, 원본 전달, 출력 계약과 잘림을 먼저 확인하고 필요한 경우에만 제한된 thinking 설정을 검토한다.
- 네 DP의 A/B/C에 같은 모델, thinking 설정과 단계별 출력 계약을 적용한다. 데이터 구성, 호출 의존 관계와 횟수는 각 구조를 따른다. 설정 변경 후에는 같은 최종 설정으로 모든 기본안을 실행한다.
- 초기 연결 확인은 DP별 대표 사례 하나씩으로 진행한다. 실제 이미지 content 전달과 JSON 출력 계약도 확인한다. 별도의 대규모 모델 비교를 선행 과제로 만들지 않는다.
- 2026-10-18 공식 가격표의 Singapore/International, 요청 입력 256K 이하, 고정 버전 정가는 **입력 100만 token당 $0.40, 출력 100만 token당 $1.60**이다. 예를 들어 입력 100만 및 출력 10만 token의 단순 합계는 $0.56이다. 이는 120회 전체 실행의 예상 총액이 아니다. 실제 usage, 캐시 할인, 문맥 구간과 실행 시점 요율로 비용을 산출한다. [공식 가격표](https://www.alibabacloud.com/help/en/model-studio/model-pricing).
- 시간과 비용은 이 모델/API 환경에서 관측한 수치다. 로컬 Omni의 절대 지연으로 일반화하거나 로컬 RAM에 원격 weight/KV가 포함됐다고 쓰지 않는다. 기존 공유 로컬 Omni 참조 Architecture의 모델 결정을 바꾸는 것은 아니다.

이 절은 변경된 PoC 구성 계획이다. 사용자 실행 승인 이후 `qwen3.7-plus-2026-05-26`의 실제 HTTP 200 호출과 이미지 입력 및 JSON 반환을 확인했고 본 비교를 실행하고 있다. 과거 실행 증거와 provider 기본값은 새 비교 결과로 재해석하거나 덮어쓰지 않는다.

## 4. 최소 구현과 보이는 화면

한 실행기에서 각 DP의 A/B 또는 A/B/C 정책을 교체한다. 기본 구조는 한 프로세스의 함수와 상태로 만들고 일반 서비스 플랫폼이나 메시지 브로커는 만들지 않는다. QA04 수치를 실제 변경으로 얻기 위해 운영 후보 코드는 Rust 모듈로 작성한다. 자료/결과 분석은 작은 스크립트를 사용해도 된다.

```text
시나리오 선택 → 같은 입력/원본 재생 → 선택한 기본안 처리
                                  → 실제 내용 표시 또는 위임 대역
                                  → 시간/usage/정답/메모리 기록
                                  → 전체 기본안 수치표와 실행 타임라인
```

화면에는 입력, 채택된 대상/조건, 현재 단계, Request/Task별 결과, 모든 기본안의 측정표를 보여준다. 모든 내부 자료를 제품 UI처럼 꾸밀 필요는 없다. 정답 파일은 채점기만 읽는다. 외부 결과는 유효한 요청을 받았을 때만 반환한다.

작은 공통 표시창은 첫 결과부터 포함한다. 표시 직전 callback을 쓰는 최소 계측이면 그 값을 **표시 proxy**로 적고, 화면 기록으로 실제 표시와의 차이를 확인한 경우 실제 표시 관측값으로 구별한다. 두 경우 모두 ms 단위 숫자를 내되 관측 방법을 숨기지 않는다.

## 5. 네 DP의 고정 시험

각 DP에 네 개의 짧은 episode를 고정하고 모든 기본안을 각각 세 번 실행한다. 예비/확인 세트를 따로 만들지 않는다. 기능 구현 중 고친 실패는 버전을 남기며 최종 표에는 같은 최종 버전의 전체 고정 시험을 사용한다.

| DP | 네 episode | 비교 기제 |
| --- | --- | --- |
| 01 근거 공급 | 같은 자료 후속 질문 / 주제 전환 / 일부 전달과 원본 정정 / 새 대화에서 오래된 두 자료의 관계 재조회 | A 유지 문맥, B 요청별 구성, C 게시 관계 조회. 실제 파생 상태 생산과 요청 해석까지 실행 |
| 02 의미 판단 실행 | 겹침 없는 후속 질문 / 긴 판단 중 새 요청 K=2 / 같은 사건 K=1 / 정정과 Agent 질문에 대한 답변 | A step 경계 반영과 B 공통/요청별 실행. 두 목표 모두 완료하며 전체 K는 동일 |
| 04 화면 지칭 | 유사 항목이 많은 화면 / 그래프의 자유 범위 / 포인터 지정 중 페이지 이동 / 대상 일부 정정과 늦은 결과 | A 원본 결합과 B 실제 후보 생산/결합/원본 확장 |
| 05 업무 인계 | 후속 위임 없음 / 한 번 위임 / 목적을 바꿔 세 번 위임 / 큰 자료에서 일부 범위 읽기와 조건 정정·접근 철회 | A 위임 시 구성, B 지속 인계 기록, C 필수 계약과 manifest 후 수신자 읽기. 미래 위임/읽기 정답은 입력하지 않음 |

**(3 + 2 + 2 + 3)개 대안 × 4 episode × 3회 = 120 episode 실행**이다. 근거 공급 36회, 의미 판단 실행 24회, 화면 지칭 24회, 업무 인계 36회다. API 호출 수는 실제 분기에 따라 정한다. 호출 수를 같게 강제하지 않는다. QA02의 분모는 입력에 사전 지정한 실제 지칭 표현 수이며 target 개수를 낱개 정답으로 늘리지 않는다. 세 번의 실행을 서로 다른 사용자 사례라고 표현하지 않는다.

두 안의 순서는 AB/BA/AB, 세 안의 순서는 ABC/BCA/CAB로 교차한다. 원본 준비와 파생 상태의 생성 비용도 기록한다. 현재 사례에 필요한 기본 원본 보완/재사용은 허용하되 A1/B1/C1 등 선택 후 tactic은 기본 결과와 분리한다. 쉬운 native 선택과 근거 부재/철회의 코드 경로는 작은 공통 기능 확인에 남긴다.

01 C에는 같은 원본 활동에서 관계를 생산해 게시하는 경로와 요청별 조회/원본 보완을 실제로 구현한다. A/B/C 모두 같은 관계 재조회와 정정 사건을 받는다. C에만 유리한 평가 묶음을 따로 만들어 순위를 내지 않는다.

05의 공통 최소 수신자는 같은 목표와 유효 참조를 받아 자료를 읽고 작은 결과를 반환한다. A/B도 artifact 참조와 읽기 도구를 사용할 수 있다. C의 차이는 필수 조건을 보낸 뒤 상세 선택을 수신자에게 맡기는 책임과 실행 순서다. 수신자 자체의 모델/업무 시간과 비용은 외부 항목으로 따로 표시하며 VIA의 자료 제공 처리만 해당 목표의 VIA 경로에 넣는다. 이렇게 해야 C가 단지 비용을 외부로 옮겼는지도 볼 수 있다. 전체 Agent 플랫폼이나 실제 문서 편집을 구현하지 않는다.

02의 A는 전체 업무나 외부 Agent를 기다리지 않는다. B의 일반 짧은 답에 불필요한 worker를 강제하지 않는다. 04의 B가 parser 덕분에 좋아지면 A4의 같은 parser 보조 입력을, 단순 순차 실행 때문에 느리면 B4의 병행 생산을 필요한 사례에만 추가해 원인을 설명한다. 추가 열 때문에 기본 수치표 완성을 미루지는 않는다.

## 6. 실제로 산출할 QA 수치

| 항목 | 산출 값 | 이번 표의 범위 |
| --- | --- | --- |
| QA01 첫 응답 지연 | 내용 표시 시각 − 입력 제출/Agent 사건 시각의 평균, ms | 전사 준비가 끝난 입력에서 표시까지. 실제/표시 proxy 구분. 오답도 시간은 그대로 포함 |
| QA02 지칭 정확도 | 최초 확정 채택이 정답 집합과 같은 건수 / 지정 지칭 판단 수, % | 01/04 중심. 같은 입력 revision의 내부 후보 수정은 허용하되 오채택 후 정정으로 최초 실패를 지우지 않음 |
| QA03 VIA 처리시간 | 정한 목표의 상세 표시까지 VIA 인과 경로 평균, ms | Voice OFF. Agent 업무와 사용자 대기만 제외하고 VIA의 모델/조회/queue/반환은 포함 |
| QA04 변경 범위 | 같은 변경 두 건을 완료하며 수정한 운영 Rust 모듈 수의 평균, 개 | 작은 PoC 구현 범위의 실제 diff. 본래 전체 변경 과제 모집단 결과와 구별 |
| QA05 모델 비용 | 전체 PoC 사건 창의 실제 usage × 기록한 단가, 달러 | 준비/미사용/폐기 포함. 이 활동 묶음의 의미 모델 비용. 기존 COMMON-28의 $2.55 단위로 환산하지 않음 |
| QA06 메모리 | PoC 프로세스의 동시 관측 RAM 최고량, MB | 실제 실행 OS, 대상 프로세스와 RSS/working-set 등 카운터 명시. UI/helper 별도 관측 및 공유 중복 여부 표시 |

QA04는 우선 기존 C01 모델 요청/응답/usage 형식 변경과 C03 원본 좌표/시각/판본 형식 변경을 실제 적용한다. 같은 변경을 양안에 적용하고 수정한 모듈 목록과 diff를 남긴다. 공통 adapter 하나에서 끝나 양안이 같으면 같은 숫자를 쓴다. 모듈 수를 달리 만들기 위한 불필요한 분할/합병을 하지 않는다.

QA06은 얻을 수 있는 실제 RAM 수치를 먼저 제공한다. backend만 잰 경우 backend로 표시하고 전체 PoC라고 이름 붙이지 않는다. 공유 메모리 중복 제거가 확인되지 않은 합계는 추정 합계로 표시한다. 작은 PoC의 RSS/working-set 값은 전체 VIA의 Windows 512 MB 요구를 검증한 값이 아니다. commit과 디스크 저장 크기를 실제 RAM으로 바꾸어 쓰지 않는다.

인계에서는 별도로 **N-H 인계 계약 일치율**도 산출한다. 목적, 필수 조건과 제외, 원본 판본과 접근 범위, 허용 실행을 실제 외부 허가 계약에서 검사한다. 이것을 QA02 지칭 정확도로 바꾸지는 않는다. 02의 요청/질문 연결 오류도 별도 건수로 표시한다.

시간과 정확도는 따로 센다. 빨리 나온 오답의 실제 시간은 보존하고 오류를 별도 열에 둔다. 응답이 없으면 실제 시간 대신 임의 timeout 숫자를 넣지 않고 미응답 건수와 관측된 시간 평균을 보여준다. 기능 실패의 낮은 비용을 정상 성공으로 선정하지 않는다.

## 7. 수치에서 우열과 선택까지

첫 결과표는 다음 형태로 만든다. 데이터가 없을 때 예시 숫자를 측정값처럼 채우지 않는다.

| DP / QA | A 평균 또는 비율 | B 평균 또는 비율 | C 평균 또는 비율 | 안별 차이와 이번 시험의 방향 | 오류/측정 방식 |
| --- | --- | --- | --- | --- | --- |
| 각 적용 항목 | 실제 값 | 실제 값 | C가 있는 DP는 실제 값 | 같은 단위의 차이 / 관측 순위 / 동점 | 실제 실행 기록 |

- 지연/비용/변경 범위/RAM은 작은 값, 지칭/인계 정확도는 큰 값을 관측 우세로 적는다.
- 세 번의 개별 값도 보여줘 평균 뒤의 흔들림을 확인할 수 있게 한다. 확률적 우위나 제품 전체 보장이라는 표현은 붙이지 않는다.
- QA별 관측 우열을 먼저 낸 다음 중요 QA와 실제 오류를 근거로 기본안을 선택한다. 가중합 점수를 만들어 서로 다른 손해를 숨기지 않는다.
- 선택안의 가장 큰 약점 하나에 tactic 하나를 적용하고 같은 입력을 세 번 재실행해 전후 값을 보여준다.
- 같은 측정값이면 동점이다. 여러 QA에서 같은 안이 좋으면 그 결과를 그대로 제시한다. 반대편 이익을 숫자로 만들어 넣지 않는다.

이전 계획의 별도 실용 차이 문턱, 통계적 유의성, 독립 확인 세트는 첫 수치표의 완료 조건에서 뺀다. 작은 차이도 원값과 함께 공개하고 이번 관측에서의 방향을 표시한다. 세 번째 QA 차이가 약한 업무 인계도 수치표를 완성하되 동점인 항목을 차별화 coverage로 세지는 않는다.

## 8. 실행 순서와 최종 산출물

1. 공통 실행기, 작은 UI, 실제 LLM adapter와 원시 계측을 만든다.
2. 각 DP의 모든 기본안과 네 episode를 넣고 수치가 끝까지 출력되는지 확인한다.
3. 동일 최종 버전에서 세 번의 고정 비교를 수행해 120 episode의 수치표를 낸다. 필요한 호출 수와 비용은 별도 기록한다.
4. 두 실제 변경의 diff로 QA04 표를, 같은 실행에서 RAM 관측표를 완성한다.
5. 기본안과 선택 이유, tactic 하나의 전후 숫자, 남은 오류를 정리한다.

최종 결과는 **모든 기본안을 볼 수 있는 데모 + QA 원값/차이 표 + 기본안 선택 이유 + tactic 전후 표 + 재생 가능한 입력과 raw 기록**이다. 실제 모델은 의미 비교와 최소 수신자에만 사용하고 음성 제품 통합은 하지 않는다.
