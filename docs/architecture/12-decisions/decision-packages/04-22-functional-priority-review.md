## 1. 이번 판단

**VIA 특화 기능의 다음 심화 대상은 M-2, F-01, F-02다. F-03은 중요한 전형적 비교로 함께 검토하되 기존 음성 안과의 중복을 먼저 확인한다.** 복구/격리의 구조적 차이가 더 설명하기 쉽다는 이유로 이 기능 문제들을 뒤로 미루지 않는다.

세 추가 주제에 각 두 안을 만들었다. 기능상 중요한 문제라는 판단, 두 메커니즘의 설계 가능성, 실제 모델/기기에서의 지원 입증 및 최종 DP 선정은 다르다. 이번에 앞의 두 가지를 구체화했다. 완성되지 않은 부분은 아래와 개별 문서에 남긴다.

| 주제 | 실제 바뀌는 구조 | 가장 큰 반론 | 작성자 판단 |
| --- | --- | --- | --- |
| F-01 | 관측 구간을 요청마다 해석하는 흐름과, 지속 객체/관계 상태가 요청에 대상을 제공하는 흐름 | 객체 cache를 기존 raw 해석에 추가한 정도라면 이전 S-02 반복 | 우선 심화. B가 담당할 대상 표현/동일성 수정과 raw fallback 경계를 분명히 해야 함 |
| F-02 | Conversation 전체의 질문/의미 연결과, 업무별 대화 owner 및 입력 배정/교차 참조 | Task별 Context 필터로 충분하면 별도 owner가 불필요 | 우선 심화. 실제 업무별 대화가 상태와 처리를 소유하는 경우만 B로 봄 |
| F-03 | 원음 중심의 이해/응답 연결과, Text 확정 후 이해/음성화하는 공통 경로 | audio payload 설정이나 ASR/TTS 추가만 다르면 약한 선택 | 기능 주제 유지, 구조 자격은 앞의 둘보다 조심스럽게 판단. 기존 S-05/06과 통합 가능. 순수 B의 native S2S 미지원도 공개 |

## 2. 13개 공통 관점으로 본 두 안의 손익

## 3. 선택을 가를 구체 사례와 반증

다음은 후속 비교에 반드시 함께 넣을 상황이며 유리한 것만 고를 수 없다. 실제 데이터/정답/집계/목표 수치는 이번에 고정하지 않는다.

| 주제 | A를 살리는 사례 | B를 살리는 사례 | 두 안 모두 어려운 사례와 반증 |
| --- | --- | --- | --- |
| F-01 | 객체 모델에 없던 새 도형의 부분을 말로 지정 | 같은 객체를 여러 창/scroll 변화 뒤 반복 지칭 | 비슷한 도형 교환, 늦은 전사, 관측 gap. A의 작은 cache로 B 이익을 얻거나 B가 대부분 raw 재해석에 의존하면 큰 구조 비교가 약해짐 |
| F-02 | 두 업무의 결과와 앞 대화를 한 발화로 연결 | 한 업무의 길고 미완성인 질문/제약을 여러 날 이어가기 | 여러 채널의 질문이 동시에 노출된 “응”. B의 로컬 상태가 단순 검색 최적화보다 이익이 없거나 배정 질문이 늘면 선택 가치 저하 |
| F-03 | 부정/자기 정정이 전사에서 잘못 표현됐으나 원음에는 남음 | Text로 고쳐 쓴 요청과 정확한 수치의 음성 전달 | 중단된 항목을 지칭, 전사/원음 충돌, 모델 backlog. ASR의 정보가 충분하거나 native 통제 비용이 이익을 상쇄하면 B 유리. Text 경로의 손실이 잦으면 A 가치 증가 |

같은 목적과 완료 조건을 유지한다. 새 화면/긴 대화/음성 정정의 실제 발생 비율은 알지 못하므로 “대부분”, “몇 배”, 별점이나 가중 총점으로 결론내리지 않는다. 독립적으로 지원하지 못하는 기능을 `0 ms 성공`으로 계산하지 않는다.

## 4. 적용 가능성에 대한 판단

| 후보 | SW로 구체화할 수 있는 부분 | 아직 실제 지원을 주장할 수 없는 부분 |
| --- | --- | --- |
| F-01 A/B | 같은 관측/시각 수집, 유한 buffer, source ID, snapshot, 후보/gap/정정 계약. B의 tracker와 의존 무효화는 새 구현 | 구조 없는 화면에서의 객체 대응/관계 정확성, 지속 갱신의 PC 비용. 소프트웨어 schema만으로 해결된다고 하지 않음 |
| F-02 A/B | 기존 Task/질문/실제 전달 기록을 이용한 중앙 또는 업무별 대화 상태, 배정 revision, 교차 참조와 공통 command guard | 암묵적 업무 전환의 배정 정확성, 긴 대화의 정보 유지, 모델 Context/시간 부담 |
| F-03 A/B | 동일 ASR/Omni 연동 경계의 원음/전사/의미/응답 기록, Text 확정과 실제 전달 연결 | 목표 build의 native 계약, 임의 발화문의 충실한 음성화, 충분한 전달 구간 대응. 공개 기능 소개는 해당 제품/장비 검증이 아님 |

양안 모두 실제로 만들 수 있는 SW 책임과 자료 흐름을 제시했지만 **구현 성공이 입증된 두 안**이라고 하지 않는다. capability가 없는 부분은 사용자 질문/부분 지원으로 공개하거나 해당 조합의 선택을 보류해야 한다. 사용자가 허용한 미완성 탐색을 근거 없는 기능 약속으로 해석하지 않는다.

## 5. 자기 반론 및 수정

- 참조 구조를 방안 A로 다시 고정하지 않았다. 실제 ref와 닮은 부분은 재사용하지만 A/B를 별도로 정의했다. 기존 내용을 새로 승인된 product target으로 바꾸지 않았다.
- 질문 focus, 관련 Task 선별, 화면의 시간 buffer, 원음 재확인, streaming 음성화는 한쪽만의 독점 이익으로 세지 않았다.
- F-01 B의 지속 모델은 새 독립 source evidence가 아니다. 파생 해석의 오류와 삭제/갱신 비용을 포함했다.
- F-02 B는 여러 Agent나 모델 복제안이 아니다. 초점만으로 “응”을 임의 승인하는 안도 아니다. 한 발화의 여러 Task 제어를 위한 조합과 검증 경로를 넣었다.
- F-03의 입력 방식과 출력 방식은 독립 선택이며 혼합안도 성립한다. 양 끝의 두 조합만으로 입력/출력의 이익이 필연적으로 묶인다고 주장하지 않고, 후속 비교에서 분리하거나 혼합안을 포함한다.
- F-03 A에 즉시/무검사 음성 게시를 허용하지 않았고 B를 무조건 비streaming으로 만들지 않았다. B의 native S2S 미지원과 TTS/정렬 capability 한계를 공개했다.
- 핵심 기능 주제의 가치를 판단한 것과 전환 난이도에 대한 최종 입증을 구분했다. 작게 구현 가능한 반례가 나오면 통합/축소하며, 세 새 주제를 반드시 세 DP로 유지하지 않는다.

## 6. 현재 보고 범위

사용자가 요청한 **상위 기능 품질의 추가 주제 세 개와 각 두 대안**, 구체 사건, 양안 선택 조건/손실, 전체 품질 및 중복/전환 반론까지 작성했다. M-2를 포함한 기능 주제의 우선순위를 회복했고 복구/격리는 조건부 후순위로 남겼다. 구조 이름만 나열하거나 실제 지원의 판단을 사용자에게 떠넘긴 보고는 피했다.

본문과 세 비교 그림을 대조하고 SVG/draw.io 및 렌더를 검수했다. 문서/그림 검사, diff와 GitHub CI의 최종 기록은 [WORKPLAN](./00-workplan.md)에 따른다. 그림/링크 검사가 구조의 품질 우위를 입증하지 않는다. 독립 리뷰나 모델/성능 실행은 하지 않았다. 정식 Stage 5 및 DP 선정은 이번 탐색의 다음 단계이며 자동 진행하지 않는다.
