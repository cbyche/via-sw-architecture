# 기존 합성 자료의 이관과 후속 DP 확장

2026-10-21 / `QA-COMMON-SYN-MIGRATION-v1` / 근거 종류 `SYNTHETIC_AUTHORED_NOT_MEASURED`

**기존 DP2와 DP5 숫자는 보존하고, 같은 계약과 활동에 맞춰 새 판본의 값을 다시 구성한다.** 기존 평균을 유지하도록 새 사례의 정답이나 지연을 조정하지 않는다. 새 값이 달라지면 구조가 실제 개선됐다고 해석하지 않고, 모집단, 경계와 가정을 바꾼 결과로 설명한다. 공통 정의와 산식은 [01 공통 계약](01-common-contract.md)에 있다.

## 1. 보존할 원본과 새 자료의 관계

| 원본 | 보존하는 내용 | 새 자료에서 사용하는 방법 |
| --- | --- | --- |
| `dp2-synthetic-backdata-20261021/synthetic-data.json` | 200입력, 표현별 정답, 최초 채택 의미, 시간 DAG, 명목 COMMON-28 비용, 변경과 RAM 가정 | 정정과 독립 질문의 기제, 입력과 의미 필드, 오류 예시를 재검토해 새 공통 원장에 연결 |
| `DP2-backdata-guide.html` | 기존 수치의 의미와 추가 가정 및 한계 | 이전 결과를 설명하는 출처로 유지 |
| `dp5-synthetic-backdata-20261021/synthetic-data.json` | 100입력, 원본 표시와 피드백 관계, 최초 응답, 정규화 비용과 시간 | 과거 관계의 종류, 정정과 미생산 조건, 원본과 관계의 추적 방식을 재사용 |
| `build_dp2_synthetic_backdata.mjs` / `build_dp5_synthetic_backdata.mjs` | 합계에 맞춰 작성한 규칙과 원본 파일의 재생성 방식 | 수정하지 않고 이전 세대의 작성 방법을 확인하는 근거로 보존 |

기존 파일을 새 값으로 덮어쓰거나 기존 dataset ID를 재사용하지 않는다. 원본 세션의 최종 수치와 기존 xlsx도 이전 범위의 자료다. 새 통합 요약은 새 dataset과 계약의 ID를 표시한다. 기존 PoC나 모델 실측 경로에 합성 파일을 넣지 않는다.

이전 원본 경로는 로컬 출처 식별자다. 다른 작업의 미발행 파일을 이번 변경에 포함하지 않으며 공통판은 자체 원본과 생성기만으로 재생성한다.

## 2. 반드시 기록할 변경 이유

| 항목 | 기존 차이 또는 가정 | 이번 공통화 |
| --- | --- | --- |
| DP의 의미 | DP2는 실행 연결, 최신 DP5는 과거 의미 관계 생산 시점의 비교 | DP 이름과 A/B 설명을 구성 registry에 기록. 과거 DP5 업무 인계 비교와 구별 |
| 입력 구성 | DP2 네 유형 각 50입력, DP5 열 유형 각 10입력 | 같은 12사례군, 120에피소드, 240입력을 BASE/EXEC/REL에 적용 |
| 공통 기준 | 서로 다른 A를 별도 표로 작성 | BASE=2A5A 한 벌을 DP2 A와 DP5 A에서 같은 ID로 참조 |
| QA01 | 과거 설명에 첫 올바른 응답과 첫 내용 표시가 혼재 | 오답 여부와 분리한 첫 구체적 내용 표시. 이번 Text 제출 profile 명시 |
| QA02 | DP2는 입력당 0~2표현, DP5는 입력당 1표현 | 표현과 revision의 정답 원장을 공통 입력에서 정의. 입력 수에 분모를 맞추지 않음 |
| QA03 목표 | DP2는 G1/G2 원래 목표와 G3/G4 새 목표만 headline으로 선택. DP5는 각각의 후속 요청 중심 | 두 입력의 목표 관계와 완료 조건을 공통 원장에서 먼저 지정. 기존 목표를 숨기지 않음 |
| DP2 시간 | 독립 질문에서 A의 후속 설명에 추가 1.2초를 설정. 제거하면 이전 전체 A 값이 5.00초에서 4.70초가 되는 민감도 존재 | 1.2초의 대안별 고정 차이를 계승하지 않고 같은 단계, 사용량과 의존 가정으로 설명 생성 비용을 계산 |
| DP5 시간 | 첫 응답 뒤의 준비 시간에도 A/B의 별도 차이가 설정됨. 이전 전체 QA03 차이 중 0.4초가 이 후속 구간에서 발생 | 0.4초를 고정 이익으로 넣지 않고 현재 목적 적용, 자료 준비와 전달 단계의 실제로 작성한 작업량에서 계산 |
| QA04 | 가상 모듈 수와 변경 설명의 상세 수준이 서로 다름 | 동일 C01~C06과 설계 예상 운영 모듈 목록, 과제별 수정 이유 및 동일 수용 조건으로 비교. `concept::...`는 실제 Rust 경로가 아닌 임시 식별자 |
| QA05 단위 | DP2는 VIA만 포함한 별도 명목 COMMON-28 USD, DP5는 수신 Agent까지 포함한 정규화 비용 | USD/새 공통 활동 묶음. VIA를 headline으로 하고 수신 Agent와 전체 합을 별도 열로 제공 |
| QA05 산출 | 기존 총액에서 비용과 사용량을 배분한 작성 규칙 | 단계별 사용량과 공통 가상 요율에서 합산. 기존 총액에 맞추는 역산을 제거 |
| QA06 | 서로 다른 사례 구성과 동시 상태의 가정. DP2 네 snapshot은 특정 에피소드와 직접 연결되지 않음 | 같은 입력과 부하 profile에서 소유 상태와 생존 구간을 연결해 같은 시점 합계의 최고값 계산 |
| QA07 | 의미 필드와 별도 대상 필드의 표현 방식이 다름 | 대상 포함 필수 의미 전체의 입력별 판정. QA02와 중복 오류의 연결 ID를 유지 |
| 점수와 목표 | COMMON-28 묶음과 이전 profile의 목표가 존재 | 새 합성 원값을 제공. 모집단과 profile이 다른 기존 점수를 그대로 부여하지 않음 |

DP2의 1.2초와 DP5의 0.4초 차이를 없앤다고 양안의 후속 시간이 반드시 같아지는 것은 아니다. 입력 문맥, 원본 재판단이나 갱신 작업량이 다르면 공통 규칙으로 계산한 차이는 남을 수 있다. 제거하는 것은 구조 이름에 붙인 고정 이익이며, 작업량의 실제 차이를 숨기는 것이 아니다.

기존 수치와 새 수치는 별도 열에 표시한다. 이전값, 새값, 단위, 분모, 경계 판본과 변경 이유를 한 행에서 확인할 수 있어야 한다. 과거 값에서 새 값으로 얼마나 개선됐다는 백분율은 성능 개선 수치로 사용하지 않는다.

## 3. 원장과 추적 필드

JSON을 재계산 가능한 원본으로 관리하고 xlsx와 HTML은 그 자료에서 생성한다. [시나리오 원본](../../../../../scripts/presentations/common_qa_synthetic_scenarios.mjs)과 [생성기](../../../../../scripts/presentations/build_common_qa_synthetic.mjs)에서 [새 JSON](../../../../presentations_files/qa-common-synthetic-20261021/synthetic-data.json) 및 [집계](../../../../presentations_files/qa-common-synthetic-20261021/summary.json)를 만든다. 표시용 문장이나 반올림 값에서 원래 수치를 역산하지 않는다. 구현의 필드명은 schema에 고정하되 다음 의미를 보존한다.

| 원장 | 필수 식별과 내용 |
| --- | --- |
| dataset manifest | dataset/schema/contract 버전, 근거 종류, 생성기 버전과 hash, 생성 시각, 부모 dataset, 공통 profile과 tariff, 사례 및 정답 hash |
| 구성 registry | 구성 ID, 각 DP의 대안 ID와 의미, 고정된 다른 축, 기본안 또는 tactic 여부, 공유 원본 구성 |
| 시나리오 | 사례군, episode, 작성 변형, 두 입력과 사건 시각, 초기 상태, 공개 원본, 기존 COMMON-28/common9 주제 매핑과 호환 상태 |
| 목표 | goal ID, 시작 입력, revision 연결, 기존 목표 유지 또는 교체 관계, 공통 완료 조건, 예정 포함 여부 |
| 지칭 | expression ID, 입력과 revision, 표현, 정답 집합, 필요한 판본과 범위, 채점 여부와 사전 제외 이유 |
| 요청 의미 | 입력 ID, 필수 필드와 정답, 최초 확정 의미, 최초 확정 사건, 성공 여부, 오류 필드 및 QA02와의 공통 오류 ID |
| 응답 | 최초 내용, 전체 상세 내용, 채택한 처리 의도, 표시 시각, 전체 출력 및 음성 요약 준비의 완료 사건 |
| 단계 | 사건 ID, 작업 종류, 소유 역할, 선행 사건, 시작과 끝, 사용 자원, VIA 포함 여부, 적용한 가정 ID |
| 사용량 | call 또는 operation ID, episode, 생산 및 갱신 원인, 역할, 중복 없는 bucket과 양, tariff ID, 사용/미사용/폐기 상태 |
| 메모리 | episode, 시각 또는 생존 구간, 소유 역할, 상태 종류, 공유와 복사 관계, bytes, 동시 합계 및 peak 근거 |
| 변경 | C-ID, 같은 변경 전 구성, 완료 조건, 설계 예상 모듈 목록, `concept::...` 임시 ID와 수정 이유, 검토 상태. 실측 전환 시 실제 모듈 경로와 diff를 별도 대응 |
| 집계 | QA ID와 이름 및 의미 판본, 구성 ID, 포함 ID 목록, 분모, 관측과 실패 수, 산식, 반올림 전 값 |
| 이관 | 원본 dataset/행 ID, 새 행 ID, 재사용/재작성/비호환, 변경 이유, 이전값과 새값 |

합성 자료는 모든 파생물에 `SYNTHETIC_AUTHORED_NOT_MEASURED`를 유지한다. 나중에 실제 실행을 하더라도 이 필드를 실측으로 바꾸지 않는다. 실측은 새 dataset에서 같은 시나리오 ID를 참조하고 별도의 실행 ID, 원시 관측과 근거 종류를 갖는다.

## 4. 재계산과 검토

검증은 다음 관계를 확인한다. 검사 통과와 실제 성능 검증을 구별해 보고한다.

1. 120개 에피소드와 240개 사용자 입력이 모든 구성에서 같은 원본과 외부 사건 trigger 규칙을 사용한다. 사건 상대 입력의 절대 시각이 달라지는 경우 해당 선행 사건을 명시한다.
2. BASE가 두 DP 요약에서 같은 행과 같은 집계값으로 연결되며 중복 표본으로 추가되지 않는다.
3. QA02는 250개 표현, QA07은 240개 입력, QA03은 180개 목표 원장에서 분모를 가져온다. 후보가 생성한 출력 수로 분모를 정하지 않는다.
4. 정정의 기존 목표 연결, 최초 채택과 첫 표시, 원본의 이용 가능 시각이 시간상 모순되지 않는다.
5. 정답 집합 정규화와 입력별 필수 의미 전체 판정이 결과와 일치한다. 같은 대상 오류의 중복 반영 관계를 보존한다.
6. 시간 그래프에 순환이 없고, 외부 구간 및 공유 자원 의존을 한 번만 반영한다. 첫 응답과 완료 조건을 혼동하지 않는다.
7. 모든 모델 작업은 해당 사용량 원장에 연결되며, 생산, 갱신과 미사용 비용이 누락되거나 중복되지 않는다. VIA와 수신 Agent 합계가 전체 비용과 맞는다.
8. 메모리 최고값은 같은 시점의 소유 상태에서 재계산할 수 있다. 개별 peak의 합이나 디스크 크기를 RAM으로 사용하지 않는다.
9. C01~C06은 같은 완료 조건을 갖고 예상 모듈 목록과 개수가 일치한다. `concept::...`를 실제 Rust 경로로 표시하지 않으며 실제 변경 완료와 가상 변경 검토를 구별한다.
10. JSON, 표, 설명서와 workbook의 단위, 분모, 판본과 반올림 전 합계가 일치한다. 새 자료의 링크는 기존 자료를 대체한 실측 출처로 표시하지 않는다.

오류 수를 작성했으므로 통계적 신뢰구간이나 유의성 검정을 만들지 않는다. 변형 수를 늘려 가정의 신뢰도가 높아졌다고 주장하지 않는다. 민감도 분석은 호출 슬롯, 과거 관계 재사용, 정정 빈도와 상태 생존 기간 같은 가정을 바꾼 별도 profile로 작성하며, 기본 표와 섞지 않는다.

## 5. 후속 DP의 등록 절차

다른 DP가 정리되면 기존 합성 표에 열만 붙이지 않고 다음 순서로 등록한다.

1. **구조 축을 등록한다.** A/B가 바꾸는 책임, 실행, 데이터 생산과 상태를 적고, 기존 DP2/DP5 축과 중복되거나 독립적으로 조합 가능한지 확인한다. 대안의 이름이 같아도 같은 구현이라고 간주하지 않는다.
2. **고정할 구성과 비교 쌍을 적는다.** 기존 BASE와 같은 조건으로 비교할 수 있으면 그 BASE를 공유한다. 기본 조건이 달라지면 별도 context ID를 만들고 기존 값을 같은 기준인 것처럼 연결하지 않는다.
3. **공통 QA와 사건에 연결한다.** 내부 단계가 달라도 최초 표시, 최초 의미 확정, 목표 완료와 역할별 비용 경계를 같은 의미에 매핑한다. 추가 진단은 공통 QA를 대체하지 않는다.
4. **모집단의 기능 범위를 확인한다.** 현재 12사례군이 새 DP의 실제 선택을 드러내는지 확인한다. 부족하면 어느 기능과 반대 조건이 빠졌는지 근거를 적어 공통 시나리오의 새 판본을 만든다. 새 DP만 유리한 사례를 평균에 조용히 추가하지 않는다.
5. **같은 모집단으로 기존 비교를 다시 작성한다.** 공통 입력, 정답, 비중, model/resource profile 또는 의미 경계를 바꾸면 DP2와 DP5도 같은 새 판본으로 재집계 또는 재작성한다. 이전 판본의 표는 유지한다.
6. **기제와 수치의 연결을 검토한다.** 새 안에만 불필요한 직렬 처리, 추가 호출이나 미리 주어진 정답이 없는지 확인한다. 공통 필수 기능과 구조에 내재한 재사용을 유지하고 tactic은 별도 구성으로 둔다.
7. **전체 파생물을 다시 생성한다.** manifest와 hash를 갱신하고 모든 표에 같은 계약 및 dataset 버전을 표시한다. 변경 이유와 비호환 범위를 이관 원장에 남긴다.

각 DP×QA 셀은 `차이 가설`, `구조적 동점`, `우열 미확정`, `비적용`을 구별한다. 합성 수치를 작성했다는 이유로 `실측 차이 확인`으로 바꾸지 않는다. 모든 QA에 적용 가능한 값을 제공해도 모든 QA가 그 DP의 강한 차별화 축이 되는 것은 아니다.

## 6. 판본과 변경의 범위

| 변경 | 필요한 처리 |
| --- | --- |
| 오타, 표시 자릿수, 설명 보완 | 표시 판본을 갱신. 원값과 산식은 유지하고 보고서 hash 변경을 기록 |
| 합계 또는 판정 코드 오류 수정 | 새 dataset 판본과 수정 사유. 이전 원본 및 잘못된 파생값도 보존하고 영향받는 모든 구성을 재계산 |
| 입력, 원본, 정답, 사례 비중, 목표 연결 변경 | 새 corpus/contract 판본. 기존 수치와 비호환 범위를 밝히고 모든 관련 비교를 같은 조건으로 재작성 |
| 단가만 변경 | 새 tariff와 비용 파생 판본. 동일 사용량의 재가격 계산임을 명시하고 시간 및 정확도 변화로 해석하지 않음 |
| 작업별 시간, 호출 슬롯, 메모리 생존 규칙 변경 | 새 execution/resource profile과 dataset 판본. 해당 시간, 비용과 메모리의 연쇄 영향을 함께 재계산 |
| 새 DP 또는 기본안 추가 | 새 구성 registry와 dataset 판본. 같은 공통 조건의 BASE만 출처를 명시해 재사용 |
| tactic 또는 두 DP의 동시 변경 | 기본안과 구별한 구성 ID. A1은 A에 단일 tactic, A1+A2는 결합안으로 명시. 개별 개선량을 합산하지 않음 |
| 실제 후보 또는 모델 실행 추가 | 별도 측정 계약과 새 실행 dataset. 합성 행을 실측 행으로 변환하지 않음 |

해시는 원본 파일, 공개 fixture, 평가자 정답, 가정 profile, generator와 결과의 재현 관계를 식별하는 데 사용한다. 해시가 있다는 이유로 값의 사실성이 입증되는 것은 아니다. 생성 시각은 실제 실험 시각으로 표시하지 않는다.

이번 공통화는 후속 DP가 들어와도 같은 QA 의미와 비교 조건을 유지할 수 있는 작성 기반이다. 참조 Architecture, accepted ADR, 기존 QA 목표와 점수 또는 실제 실험 결과를 수정하지 않는다.
