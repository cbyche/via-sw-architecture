# 새 DP의 공통 QA 평가를 이어가는 세션 지침

2026-10-21 / 인계 기준 `COMMON-QA-SYN-1.0`

## 새 세션에 전달할 요청

> 이 저장소의 INTENT.md와 AGENTS.md를 읽고, docs/architecture/12-decisions/decision-packages/qa-common-synthetic-20261021/06-session-handoff.md를 기준으로 DP 공통 QA 평가 작업을 이어가줘. 먼저 현재 공통판을 파악하고 준비 상태만 요약해줘. 내가 정리된 새 DP의 문서나 세션을 지정하면 최신 A/B를 확인하고, 같은 QA 정의와 공통 시나리오로 가상 수치와 근거를 구성해 기존 DP들과 일관성을 맞춰줘. 관련 문서, JSON, Excel, HTML을 갱신하고 검토 후 해당 작업의 변경만 commit/push해줘.

사용자는 다른 세션에서 새 DP를 정리한 뒤 이 작업을 이어갈 예정이다. 새 DP의 대상과 준비 완료 여부를 임의로 확정하지 않는다. 파일명이나 미추적 문서가 존재한다는 이유로 초안을 채택된 비교안으로 해석하지 않는다. 첫 응답에서는 기존 작업을 이해한 상태와 이어갈 절차를 간단히 알리고, 새 DP 지정을 기다린다. 자동 감시나 예약 작업은 만들지 않는다.

## 작업 목적과 현재 결과

사용자가 원하는 것은 구체적인 가상 시나리오와 그럴듯한 수치 및 설명 근거다. 수치를 제시하는 것까지 작업에 포함한다. 실제 측정이 없다는 이유로 수치 작성 자체를 중단하지 않는다. 원자료, 정답, 가능한 오답, 처리 단계와 자원 가정을 먼저 구성해 서로 맞는 값을 계산하고, 산출물의 근거 종류는 `SYNTHETIC_AUTHORED_NOT_MEASURED`로 유지한다. 실제 실행 기록이나 모델 실측 결과와 섞지 않는다.

기존 공통판은 `e8c10995062fa45a5c361325e9c0e7928f6ea6f2`에서 발행했다. 기준은 다음과 같다.

- DP2: 후속 입력을 기존 대화 실행의 다음 step에서 해석하는 A와 별도 실행에서 해석한 뒤 기존 또는 새 목표에 연결하는 B.
- DP5: 요청 시 과거 사건의 관계를 해석하는 A와 관계를 미리 생산하고 관리하며 요청 때 조회와 보완을 하는 B.
- 공통 구성은 `BASE=2A5A`, `EXEC=2B5A`, `REL=2A5B`다. DP2 A와 DP5 A는 같은 BASE 행을 참조한다.
- 12개 사례군과 유형별 10개 변형으로 120개 에피소드, 240개 입력, 250개 지칭 표현, 180개 목표를 구성했다.
- 기본 profile은 Text 입력과 동일 가상 cloud 모델이다. 입력 이전 관계 생산과 종료 후 유휴 갱신의 비용 및 로컬 메모리를 포함한다.
- Excel 13개 시트, HTML 사례 탐색기, 계약과 상세 해설 및 JSON 원장이 있다. 기존 DP2의 200입력과 DP5의 100입력 자료는 별도 선행 세대로 보존한다.

현재 대표값은 [결과와 사례 해설](04-results-and-walkthrough.md)의 표를 읽는다. 채팅에서 옮긴 반올림 값보다 [summary.json](../../../../presentations_files/qa-common-synthetic-20261021/summary.json)의 원값을 기준으로 한다.

## 모든 DP에서 유지할 QA 경계

| QA | 공통 의미 |
| --- | --- |
| QA01 | 입력 제출에서 첫 구체적인 채택 내용의 표시까지. 오답도 최초 표시 시간을 남기며 접수 인사는 제외 |
| QA02 | 표현과 revision별 최초 채택 대상 집합의 완전 일치율 |
| QA03 | 원래 목표부터 최종 revision 처리 종료까지의 VIA 인과 경로. 외부 Agent 업무와 사용자 대기는 제외하고 정정 전 VIA 처리 및 필요한 출력 준비는 포함 |
| QA04 | 같은 C01~C06 변경 요구의 예상 운영 Rust 모듈 수 평균. 현재 concept:: 목록은 설계 가정이며 실제 diff가 아님 |
| QA05 | 공통 활동 전체의 VIA 모델 비용. 준비, 미사용 생산, 갱신까지 포함하고 수신 Agent 비용과 전체 합계는 별도 열 |
| QA06 | 같은 시각에 생존하는 로컬 상태의 합계 중 최고값. 개별 peak를 더하지 않고 모델 배치 profile을 동일하게 유지 |
| QA07 | 입력과 revision별 최초 확정한 필수 요청 의미 전체의 일치율. 대상, 조건, 기존 목표 관계 등을 포함 |

QA02와 QA07의 같은 대상 오류는 중복될 수 있다. 이후 인계 누락이나 외부 Agent의 업무 실패를 첫 의미 해석 오류로 재분류하지 않는다. 새 QA07은 예전 부하 추가 지연과 다른 정의이며 우선순위, 목표와 점수는 별도 합의 없이 만들지 않는다. 기존 COMMON-28의 비용 목표나 점수를 새 모집단에 그대로 적용하지 않는다.

## 새 DP가 준비됐을 때의 절차

1. 최신 기본안의 책임, 실행, 데이터 생산과 보존 및 상태 수명을 정리한다. 기본안과 tactic을 분리한다.
2. 기존 DP2/DP5와 독립된 선택 축인지 확인하고 비교 쌍과 고정할 주변 구성을 등록한다. 공통 조건이 같은 경우만 BASE를 공유한다.
3. 기존 12개 사례군으로 새 구조의 이익, 비용과 반대 조건을 설명할 수 있는지 확인한다. 부족한 기능은 새 사례로 보완하되 같은 QA의 의미를 DP마다 바꾸지 않는다.
4. 입력, 원자료, 정답과 목표를 먼저 확정하고 모든 비교안에 동일 적용한다. 구성별 처리 DAG, 사용량, 동시 상태 및 구체적인 채택 오류를 작성한다.
5. 사례, 비중, profile 또는 QA 경계가 달라지면 새 corpus와 dataset 판본 및 새 출력 디렉터리를 만든다. 사례와 profile이 같더라도 새 DP나 기본안을 추가하면 구성 registry와 dataset 판본을 올린다. 기존 v1 파일을 덮어쓰지 않는다. DP2와 DP5도 같은 새 조건으로 다시 계산한다.
6. 개별 수치에서 요약표까지 생성하고, 변경 전후 차이의 이유와 호환 여부를 남긴다. 구조의 실제 영향이 없는 QA는 동점이나 비적용으로 두고 차이를 억지로 만들지 않는다.
7. 독립 검토로 QA 의미, 공통 입력, 처리 인과, 비용 및 메모리 누락을 확인하고 수정한다. Excel 수식과 내보낸 값 및 HTML 표시를 검증한다.
8. 완성된 해당 작업의 파일만 commit/push하고 커밋과 CI 상태를 알린다. 다른 세션에서 진행 중인 문서나 발표자료는 섞지 않는다.

`2B5B` 같은 결합안은 별도 구성으로 작성한다. DP2 B와 DP5 B의 개선량을 더해 조합 결과를 만들지 않는다. 새 profile은 원본 재사용, 현재 상태, 호출 슬롯과 생산 경합이 실제로 서로 영향을 주는 경로를 다시 작성한다.

## 구현과 검증 시 주의할 지점

생성기는 [build_common_qa_synthetic.mjs](../../../../../scripts/presentations/build_common_qa_synthetic.mjs), 시나리오는 [common_qa_synthetic_scenarios.mjs](../../../../../scripts/presentations/common_qa_synthetic_scenarios.mjs), 설명서는 [render_common_qa_synthetic_report.mjs](../../../../../scripts/presentations/render_common_qa_synthetic_report.mjs)다. 개발 변경 과제는 [change-spec.json](change-spec.json)이다.

현재 생성기에는 v1의 출력 경로, 판본 및 분모 assertion이 고정돼 있다. 확장 전 이를 새 판본에 맞게 일반화하거나 새 생성 진입점을 만든다. `--data-only`도 기존 JSON과 문서를 쓰므로 원본 보존 전 실행하지 않는다. workbook 생성에는 `@oai/artifact-tool`이 필요하며 현재 세션의 런타임 경로를 확인해 `VIA_ARTIFACT_MODULE_BASE`를 설정한다. 과거 세션의 `/private/tmp` 경로가 계속 존재한다고 가정하지 않는다.

검토에서 실제로 발견했던 다음 오류가 재발하지 않도록 확인한다.

- 관계 생산과 갱신은 비용 행뿐 아니라 시간 및 메모리 상태에도 연결한다.
- 직접 답변과 외부 위임을 입력별로 구별한다. 완전한 첫 답변에 불필요한 상세 호출을 추가하지 않는다.
- 부분 첫 안내는 채택한 구체적 의도를 포함하고, 전체 의미 확정 및 최종 답변 표시와 구별한다.
- 실행 상태의 수는 목표 수와 다를 수 있다. 정정 중 실행이 겹치는 경우도 상태 생존 구간으로 계산한다.
- 작성한 오답의 내용, 오류 설명과 후속 경로를 맞춘다. 처리 종료와 의미상 성공을 별도 기록한다.
- 준비 이후 도착한 정정이나 원본 갱신은 후보가 미리 읽을 수 없도록 원자료 이용 가능 시점을 명시한다.
- 전체 호출은 사용량 행과 연결하고 동시 호출 상한, DAG 의존, 시간 및 메모리 합계를 확인한다.
- 모든 파생물에서 같은 계약 판본, 단위, 분모와 원값을 유지한다.

공통판의 수식과 렌더 검사는 [발행 확인](../../../../presentations_files/qa-common-synthetic-20261021/publication-validation.json)에 있다. 2026-10-21 인계 점검에서 이 작업의 Markdown 10개 링크, 활성 용어와 생성기 문법 검사는 통과했다. 전체 링크 검사는 기존 `four-dp-presentation-20261019`의 보존 복사본에서 누락 링크 14건으로 실패했으며, 공통판 최초 발행의 [CI 실패](https://github.com/cbyche/via-sw-architecture/actions/runs/39565859207)도 같은 원인이다. 새 세션에서는 현재 상태를 다시 확인하고 저장소 전체 검사와 해당 변경 범위의 검사를 구분해 보고한다.
