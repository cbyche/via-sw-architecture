# DP2와 DP5의 공통 QA 결과와 사례 해설

> **설명용 합성 비교 / COMMON-QA-SYN-1.0.** 모든 사례, 채택 결과, 시간, 사용량과 상태 크기는 작성 가정이다. 실제 후보 또는 모델 실행 결과가 아니며 실제 시험을 수행했다는 근거로 제시하지 않는다.

공통 QA를 같은 사용자 활동에 적용한 결과다. **DP2 A와 DP5 A는 동일한 BASE 기록**을 사용한다. [대화형 설명서](../../../../presentations_files/qa-common-synthetic-20261021/outputs/01a15d51/VIA-QA-common-guide.html)에서 사례와 구성별 오류를 살펴보고, [워크북](../../../../presentations_files/qa-common-synthetic-20261021/outputs/01a15d51/VIA-QA-common-synthetic.xlsx)에서 계산 원장을 확인할 수 있다. 정의는 [공통 계약](01-common-contract.md), 변경과 자원 가정은 [설계 근거](02-change-and-resource-rationale.md), 이전 자료와의 관계는 [이관 및 확장 규칙](03-migration-and-extension.md)을 따른다.

## 1. 같은 기준으로 읽는 대표값

| QA | 단위 | DP2 A / BASE | DP2 B / EXEC | DP5 A / BASE | DP5 B / REL | 방향 |
| --- | --- | --- | --- | --- | --- | --- |
| QA01 첫 응답 지연시간 | 초 | 2.457 | 2.132 | 2.457 | 1.988 | 낮을수록 좋음 |
| QA02 지칭 대상 식별 정확도 | % | 95.20% | 93.60% | 95.20% | 97.20% | 높을수록 좋음 |
| QA03 VIA 처리시간 | 초 | 6.650 | 5.804 | 6.650 | 5.875 | 낮을수록 좋음 |
| QA04 변경 모듈 수 | 개/과제 | 1.833 | 1.833 | 1.833 | 2.000 | 낮을수록 좋음 |
| QA05 VIA 모델 사용 비용 | USD/묶음 | $2.451601 | $2.573512 | $2.451601 | $3.355791 | 낮을수록 좋음 |
| QA06 최대 로컬 RAM | MB | 278.79 | 306.08 | 278.79 | 329.68 | 낮을수록 좋음 |
| QA07 요청 의미 해석 정확도 | % | 93.33% | 88.75% | 93.33% | 90.42% | 높을수록 좋음 |

한 구성은 120개 episode와 240개 입력이다. QA02는 250개 지칭 표현, QA03은 180개 목표, QA04는 6개 변경 과제를 사용한다. 비용은 같은 120개 episode의 준비부터 종료 후 처리까지를 합산한다. BASE를 두 번 합산하지 않으므로 고유 구성은 3개다.

- DP2 B는 BASE 대비 QA01이 0.326초, QA03이 0.845초 짧다. 이 묶음에서는 별도 판단과 진행 중 읽기의 겹침이 시간을 줄인다. QA07은 93.33%에서 88.75%로 달라지고 VIA 비용은 $0.121911, 최고 RAM은 27.29MB 증가한다.
- DP5 B는 BASE 대비 QA01이 0.469초, QA03이 0.775초 짧다. 준비된 관계의 조회가 원문 재구성을 줄이는 가정이다. QA02는 95.20%에서 97.20%로 바뀌지만 QA07은 93.33%에서 90.42%로 낮아진다. 대상 연결과 현재 목적 적용을 같은 정확성으로 취급하지 않는다.
- QA04는 DP2에서 1.833개와 1.833개로 같고, DP5 B는 2.000개다. 차이는 구간 철회 때 관계 의존성을 바꾸는 C06 가정에서 발생한다. 공통 모듈로 해결할 수 있으면 이 차이는 없어질 수 있다.

오류율은 처리 구조에서 자동으로 도출된 값이 아니라 작성한 채택 사례의 집계다. 이 결과로 구조의 필연적 정확도 우위나 통계적 유의성을 주장하지 않는다. 기존 우선순위와 새 QA07의 미합의 상태를 유지하며, 여기서 새 대안 채택이나 점수를 부여하지 않는다.

## 2. 무엇을 평가했는가

| QA | 단위와 경계 |
| --- | --- |
| QA01 첫 응답 지연시간 | 입력 제출부터 첫 구체적 내용 표시까지. 오답의 첫 표시시간도 유지한다. |
| QA02 지칭 대상 식별 정확도 | 표현과 revision별 최초 채택 집합의 완전 일치율이다. |
| QA03 VIA 처리시간 | 원래 목표 시작부터 최종 revision 완료까지의 VIA 경로다. 외부 업무와 사용자 대기 구간을 제거한다. |
| QA04 변경 모듈 수 | 공통 C01~C06을 적용할 때 수정할 것으로 설정한 운영 모듈 수의 평균이다. |
| QA05 VIA 모델 사용 비용 | 같은 활동 묶음의 VIA 사용량에 공통 단가를 적용한다. 준비와 미사용 생산 및 갱신도 포함한다. |
| QA06 최대 로컬 RAM | 같은 순간의 로컬 상태 합계 중 최고값이다. 원격 모델 가중치는 이 profile에 없다. |
| QA07 요청 의미 해석 정확도 | 입력과 revision별 최초 확정 의미의 필수 항목 전체 일치율이다. |

QA02와 QA07은 같은 대상 오류를 함께 반영할 수 있다. 이를 독립적인 두 번의 정확성 개선으로 합산하지 않는다. 첫 구체적 안내, 전체 의미 최초 확정과 최종 목표 완료는 서로 다른 사건이다. QA01의 빠른 안내가 QA07 성공이나 QA03 완료를 대신하지 않는다.

## 4. 세 가지 입력을 따라가기

### SYN-F06-01: 과거 대상 유지와 현재 목적 변경

**U01** “전에 서비스 운영위원회용으로 구성이 좋았던 자료를 써서 전환 검토 발표자료를 5장 이내로 만들어줘. 월 운영비 240만원 이하, 첫 12개월 조건이고 외부 발송은 하지 마.”

**U02** “같은 자료는 쓰되 이번에는 상담팀 실무회의용으로 바꿔. 장점보다 위험과 야간 상담 배정의 미확인 사항을 먼저 보여줘. 나머지 조건은 유지해.”

대상 집합이 같더라도 현재 목적과 기존 목표의 정정 관계는 별도 필수 의미다. QA02의 성공을 QA07의 성공으로 바꿔 읽을 수 없다.

| 의미 모델 | 공통 가상 cloud 의미 모델 | 특정 실제 모델의 성능이나 가격을 대표하지 않음 |
| 동시 호출 슬롯 | 2 | 대기 중인 읽기와 새 해석의 겹침을 허용하는 공통 자원 |
| 대화 실행 직렬 구간 | BASE와 REL의 대화형 의미 판단 및 상세 준비 호출은 같은 실행 순서를 유지 | EXEC는 입력별 실행 상태와 공통 호출 슬롯을 함께 사용 |
| REL 요청 전 준비 | episode 시작 -8초부터 첫 입력 0초 전까지 | 이 준비 여유를 갖는 profile이며 생산 비용과 동시 RAM은 포함 |
| REL 갱신 시점 | 관계 갱신은 두 입력의 모든 목표 처리 종료 후 유휴 구간에서 실행. 준비와 갱신의 비용 및 RAM은 포함. | 현재 요청 지연을 줄이는 대신 종료 후 비용과 RAM을 함께 부담 |
| 모델 호출 시간 | 0.16초 + 입력/3500 + 출력/160 | 같은 작업량에는 같은 계산식 |
| 입력과 출력 단가 | 입력 $1/M, 출력 $4/M | 비용 원장의 입력 및 출력 토큰에 적용 |
| 음성 요약 생성 | $0.002/초 | 음성 준비 비용이며 실제 듣기 시작시간이 아님 |
| 후속 입력 trigger | 진행 중 첫 표시 +0.35초 / 완료 후 +1.5초 | 같은 상대 trigger이고 구성별 절대 시각은 다를 수 있음 |
| 외부 Agent 업무 | 8초 | QA03에서 외부 구간만 0으로 투영하고 비용은 별도 열 |
| 처리 경로 | initial/correction은 Agent 위임, addition/independent는 VIA 직접 답변 | 추가 조회와 일반 질문에 존재하지 않는 외부 Agent 업무를 넣지 않음 |
| EXEC 요청 상태 RAM | 실행 상태당 11MB | 동시에 살아 있는 실행 상태 수를 반영하며 입력 수를 일괄 최고값으로 더하지 않음 |
| 정확도 오류 배정 | 66개 구성별 오류 규칙 | 자료와 잘못된 채택 내용을 연결한 작성 가정이며 빈도의 실증 근거는 아님 |

시간의 인과는 입력량과 읽기, 모델 호출, 의존 및 자원 순서에 있다. DP2 B는 새 의미 판단을 먼저 시작해도 최종 대상에 필요한 조회 반환을 기다린다. DP5 B는 준비된 관계를 쓸 수 있는 경우 재구성을 줄이지만 갱신과 미사용 생산을 부담한다. 독립 설명 생성에 대안 이름만으로 고정 시간을 더하거나 빼지 않는다.

U01에서 오답을 채택한 뒤 U02가 정답으로 작성된 경우는 같은 접근 가능 원본을 다시 판단한 가정이다. 이전 오답은 최초 판정에 그대로 남고 이후 정답으로 소급 삭제하지 않는다.

정확도 차이의 가정은 오류 원장에 별도로 공개한다. TARGET은 대상 연결 오류로 QA02와 QA07에 함께 영향을 줄 수 있고, MEANING_ONLY는 대상이 맞아도 조건 또는 기존 목표 관계가 달라 QA07만 실패하는 경우다. 인계 이후 누락이나 외부 Agent의 업무 품질을 이 두 QA에 넣지 않는다.

원래 DP2와 DP5 자료는 보존한다. 이번 결과는 이전 수치에 비율을 곱해 맞춘 보정이 아니라 공통 입력, 목표, 사용량과 계산 경계로 다시 작성한 세대다. 두 세대의 차이를 성능 개선으로 표시하지 않는다.

## 8. 다른 DP를 추가하는 방법

1. 새 DP의 A/B가 바꾸는 책임과 상태 및 실행 의존을 구성 registry에 등록한다. 기존 DP와 독립적인 축인지 확인한다.
2. 같은 BASE를 쓸 수 있으면 원본 행을 공유한다. 주변 구조가 달라지면 별도 context와 비교 쌍을 둔다.
3. 기존 QA의 의미와 사건 경계를 유지하며 내부 단계를 연결한다. 부가 진단이 QA를 대체하지 않는다.
4. 새 기능을 다룰 시나리오가 필요하면 corpus 판본을 올리고 기존 DP도 동일 새 묶음으로 다시 산출한다. 새 DP만 사례를 추가해 평균을 바꾸지 않는다.
5. 기본안과 tactic 및 복수 DP 조합은 별도 구성으로 둔다. 두 개별 개선량을 더해 2B5B 결과를 만들지 않는다.
6. 시나리오, 정답, 가정과 계산 원장을 함께 버전 관리하고 JSON, 워크북과 설명서를 다시 생성한다. 실제 실행 자료는 별도 근거 종류와 dataset으로 추가한다.
