# DP2와 DP5의 공통 QA 합성 비교 계약

2026-10-21 / `QA-COMMON-SYN-CONTRACT-v1` / 근거 종류 `SYNTHETIC_AUTHORED_NOT_MEASURED`

**같은 사용자 활동과 정답에 세 가지 구조를 적용하고, 같은 관측 경계와 산식으로 QA01~07을 계산한다.** 이 자료는 구조의 이익과 부담을 설명하기 위해 작성한 가상 사례와 수치다. 후보 실행, 모델 호출, 실제 화면 표시, RAM 계측이나 사용자 시험 결과가 아니다. 계산 검증은 합성 자료의 연결과 산식이 맞는지를 확인한다.

판단 원칙은 [INTENT.md](../../../../../INTENT.md), QA의 상세 의미는 [현재 QA 후보 명세](../qa-candidate-package/README.md)와 [보완 PoC 계약](../seven-problem-review/14-corrected-poc-contract.md)을 따른다. 기존 정의와 점수표를 덮어쓰지 않고, 이번의 공통 합성 모집단과 관측 가정을 별도 판본으로 기록한다. 새 QA07 요청 의미 해석 정확도는 INTENT.md의 정의를 사용하며, 예전 QA07 부하 추가 지연과 구별한다.

## 1. 바꾸는 구조와 고정하는 구조

DP2는 새 입력의 의미를 **어느 실행에서 판단하는가**, DP5는 과거 사건의 의미 관계를 **언제 생산해 사용하는가**를 비교한다. DP5를 과거의 목적별 인계 묶음과 지속 업무 기록 비교로 되돌리지 않는다.

| DP | A | B |
| --- | --- | --- |
| DP2 의미 판단 실행 | 진행 중인 대화 해석 실행의 다음 step 경계에서 새 입력을 기존 문맥과 함께 판단한다. | 기존 요청 실행과 별도로 새 입력을 판단하고, 관계에 따라 기존 요청 또는 새 목표에 연결한다. |
| DP5 위임 이력과 관계 해석 | 현재 요청에 필요한 과거 표시, 피드백, 결과, 정정 원본을 읽어 관계를 판단한다. 이미 확정한 관계는 재사용한다. | 과거 사건에서 대상, 평가 측면, 적용 상황 등의 관계를 미리 생산하고 관리한다. 요청 시 조회하되 현재 조건을 별도로 적용하고, 무효하거나 아직 생산되지 않은 부분은 원본으로 보완한다. |

DP2 A는 원래 업무 전체의 완료를 기다리는 안이 아니다. DP2 B는 모든 입력에 새 실행이나 추가 모델 호출을 강제하는 안이 아니다. DP5 B의 파생 관계는 원본과 별개인 새로운 증거가 아니며, `valid` 표시는 의미가 정답이라는 보증이 아니다. 양안에 필요한 원본 접근과 이미 확정한 상태의 재사용을 허용한다.

| 구성 ID | DP2 | DP5 | 비교에서의 역할 |
| --- | --- | --- | --- |
| `BASE` | A | A | 두 비교가 공유하는 조건부 기준 구성 |
| `EXEC` | B | A | BASE와 비교해 DP2 축만 바꿈 |
| `REL` | A | B | BASE와 비교해 DP5 축만 바꿈 |

따라서 DP2의 A/B는 BASE/EXEC, DP5의 A/B는 BASE/REL이다. BASE의 입력, 판단, 시간, 비용과 메모리 행은 한 번 작성해 두 비교에서 같은 출처 ID로 참조한다. BASE를 두 번 세어 독립 표본 수를 늘리지 않는다. 이 공통 기준은 사용자에게 채택된 설계나 accepted ADR가 아니다.

재계산 원본은 [synthetic-data.json](../../../../presentations_files/qa-common-synthetic-20261021/synthetic-data.json), 집계는 [summary.json](../../../../presentations_files/qa-common-synthetic-20261021/summary.json), 검토용 산출물은 [워크북](../../../../presentations_files/qa-common-synthetic-20261021/outputs/01a15d51/VIA-QA-common-synthetic.xlsx)과 [설명서](../../../../presentations_files/qa-common-synthetic-20261021/outputs/01a15d51/VIA-QA-common-guide.html)다.

`2B5B` 조합은 이번 세 구성에 포함하지 않는다. EXEC와 REL의 개선량을 더해 그 조합의 결과를 만들지 않는다. 두 구조가 같은 관계 판단, 문맥과 자원을 사용하는 상호작용은 별도 조합 자료가 있어야 설명할 수 있다.

## 2. 공통 활동과 서로 다른 QA 단위

공통 모집단은 **12개 사례군 × 작성한 변형 10개 = 120개 에피소드**다. 각 에피소드에 사용자 입력 두 개를 두므로 입력은 240개다. 정정, 추가 목표, 독립 질문과 과거 관계의 재참조 조건을 함께 포함한다. 사례군의 동일 비중은 비교를 위한 구성 규칙이며 실제 사용 빈도 조사 결과가 아니다. 열 개 변형을 열 번의 모델 반복 실행이나 독립 사용자 시험이라고 부르지 않는다.

에피소드는 원본과 초기 상태, 사용자 입력, 사건 시각, 정답과 완료 조건을 묶는 단위다. 같은 에피소드라도 지칭 표현 수, 요청 revision 수와 완료 목표 수는 다를 수 있다. 이번 원장은 구성당 **지칭 표현 250개와 완료 목표 180개**다. 이 개수는 입력에서 먼저 지정한 고유 ID를 세어 생성한다. 요약값을 맞추기 위해 후보별로 분모를 바꾸지 않는다.

| QA | 추출하는 단위 | 공통 집계 |
| --- | --- | --- |
| QA01 첫 응답 지연시간 | 사용자 입력별 지정 첫 내용 표시 사건 | 240개 입력의 지연 산술평균 |
| QA02 지칭 대상 식별 정확도 | 채점 가능한 지칭 표현과 입력 revision | 처음 채택한 대상 집합의 완전 일치 수 / 250개 표현 |
| QA03 VIA 처리시간 | 사전에 지정한 사용자 완료 목표 | 외부 구간을 제거한 180개 목표별 완료 경로 길이의 산술평균 |
| QA04 변경 범위 | 공통 C01~C06 변경 과제 | 과제별 가상 변경 운영 Rust 모듈 수의 산술평균 |
| QA05 모델 사용 비용 | 초기 준비와 종료 후 처리를 포함한 공통 활동 묶음 | VIA의 가상 사용량 × 공통 가상 단가의 총합, USD/120 에피소드 묶음 |
| QA06 최대 로컬 RAM 사용량 | 같은 활동의 같은 시각에 함께 유지되는 VIA 메모리 | 전체 관측 구간에서 동시 합계의 최고값, MB |
| QA07 요청 의미 해석 정확도 | 사용자 입력 하나와 그 revision | 필수 의미 전체가 처음 확정 때 맞은 입력 수 / 240개 입력 |

QA02의 분모가 240과 같아야 할 이유는 없다. 한 입력이 두 표현을 포함하거나 지칭을 포함하지 않을 수 있다. 정정은 기존 목표의 revision일 수 있으므로 QA03 목표 수도 입력 수와 같게 만들지 않는다. 에피소드별 평균의 평균이 아니라 각 QA의 정해진 관측 단위로 집계한다. 사례군별 값과 분모를 함께 제공해 구성 비중에 따른 결과를 확인할 수 있게 한다.

[COMMON-28](../qa-candidate-package/common-scenarios.md)과 기존 common9의 ID는 기능과 장면의 주제 연결에 사용한다. 이번의 새 원본, 입력과 사건 배열은 그 실험의 재실행이 아니다. 매핑에는 `THEMATIC_ONLY_NOT_EQUIVALENT_EXECUTION`을 기록하며 기존 실행 건수, 반복 수, 점수와 결과를 계승하지 않는다.

## 3. 공통 환경과 작성 규칙

| 항목 | 이번 합성 자료의 조건 |
| --- | --- |
| 입력 | 같은 Text 입력 두 개와 같은 과거 원본. 입력 제출을 관측 시작점으로 하며, 후속 입력은 공통의 사건 상대 trigger를 적용 |
| 출력 | 첫 구체적 Text, 전체 상세 Text, 목표에 필요한 음성 요약의 준비. 실제 오디오 재생은 관측하지 않음 |
| 모델 | 동일한 가상 cloud 모델 profile. 실제 provider, 현재 가격이나 특정 모델의 실측 성능을 나타내지 않음 |
| 모델 자원 | 구성 간 같은 호출 슬롯과 서비스 가정. 선행 실행과 새 입력의 겹침 및 준비 작업의 자원 사용을 원장에 기록 |
| 원본과 권한 | 같은 접근 가능 원본, 판본, 사용 범위와 조회 조건. 평가용 정답은 후보가 읽는 근거와 분리 |
| 외부 Agent | 같은 접수 및 결과 조건과 8초의 가상 업무 구간. 내부 업무 시간과 비용은 VIA와 역할별로 분리 |
| 메모리 | 같은 cloud 모델 및 로컬 VIA profile. 공통 기반, 입력과 원본, 실행 문맥, 결과 및 관계 상태를 동일 경계로 계상 |
| 준비와 종료 | 최초 평가 입력 전의 준비부터 마지막 입력 때문에 발생한 후속 처리까지 비용과 메모리에 포함 |

겹침 사례의 두 번째 입력은 해당 구성의 첫 번째 내용 표시 후 0.35초, 순차 사례는 첫 목표 완료 후 1.5초에 도착하도록 작성한다. 사용자 자극의 동등성은 같은 문장, 상태와 trigger 규칙으로 정의한다. 구성의 첫 표시나 완료 시각이 다르면 두 번째 입력의 절대 시각도 달라질 수 있다. 같은 절대 타임라인을 재생한 실험이라고 설명하지 않는다. 첫 응답은 각 입력의 실제로 설정한 제출 시각부터, 기존 목표의 정정은 그 목표의 원래 시작 시각부터 계산한다.

공통 가상 단가는 입력 **$1/백만 토큰**, 출력 **$4/백만 토큰**, 음성 생성 **$0.002/초**다. 시장 가격이나 특정 provider 요금이 아니다. 모델 시간은 같은 가상 시작 비용, 입력 처리와 출력 생성 속도를 호출별 사용량에 적용해 계산하며, 정확한 값과 단위는 원본의 공통 가정 원장에 둔다. VIA가 원본을 읽는 시간은 포함하고 외부 수신 Agent의 8초 업무 구간만 QA03에서 제외한다.

새로운 별도 관계를 만드는 비용은 DP5 B의 준비 또는 갱신 원장에 남긴다. 사용되지 않은 관계도 생산했다면 비용과 보존 상태를 기록한다. 현재 요청에 필요하지 않은 과거 준비를 QA01의 입력 이후 시간에 임의로 더하지는 않는다. 반대로 관계 생산이 끝나지 않았거나 자원을 점유해 요청을 늦추면 실제로 설정한 의존과 자원 순서를 시간 경로에 포함한다.

단계 시간과 사용량은 작업 종류, 읽을 원본, 입력과 출력량, 관계의 준비 상태, 실행 의존 및 자원 조건으로 설명한다. 같은 종류와 양의 작업에는 같은 계산 규칙을 적용한다. `DP2 B이므로 1초 감산`과 같은 대안 이름별 보너스는 두지 않는다. 합성 정확도 오류에는 잘못 채택한 내용과 원본 근거, 가능한 원인을 명시한다. 그 오류 빈도가 구조에서 수학적으로 도출되거나 모델에서 관측됐다고 설명하지 않는다.

## 4. QA별 관측 경계

### QA01: 첫 구체적 내용 표시

`입력 제출 → 첫 구체적 내용 표시`를 사용한다. 단순 접수 인사, 미해결 지칭을 그대로 반복한 문장, 내부 제안은 종료점이 아니다. 실제로 채택한 대상이나 구체적 처리 의도를 알리는 문장은 전체 작업 완료 전에도 첫 내용이 될 수 있다.

틀린 구체적 내용도 최초 표시시간을 유지하고 정확도를 별도 판정한다. 나중 정답으로 고친 시각으로 최초 오답을 지우지 않는다. 이번 시각은 작성한 가상 표시 사건이며 화면 계측값이나 callback 실측값이 아니다. Text profile이므로 음성 종료 판정과 전사 지연은 포함하지 않는다. 이후 Voice profile을 추가할 때는 그 구간을 포함한 별도 공통 판본을 사용한다.

### QA02: 최초 채택한 지칭 집합

표현별로 원본 식별자, 필요한 판본, 항목 또는 범위의 정답 집합과 최초 채택 집합을 비교한다. 순서만 다른 같은 집합은 성공이며 누락, 추가, 다른 대상이나 필요한 판본의 혼동은 실패다. 표현별 역할을 합쳐 하나의 큰 집합으로 채점하지 않는다.

제공한 근거로 단일 정답 집합을 정할 수 없는 표현은 사전 등록한 이유와 함께 정량 분모에서 제외하고 필요한 확인 행동을 별도 기록한다. 후보가 틀렸다는 이유로 사후 제외하지 않는다. 첫 확정 전의 내부 후보 수정과, 첫 확정 뒤의 정정은 구별한다. 인계 이후의 누락과 외부 Agent의 업무 정확도는 이 QA가 아니다.

### QA03: 사용자 목표의 VIA 완료 경로

새 요청은 새 목표에, 정정은 관련 기존 목표와 revision에 연결한다. 정정의 시작점을 정정 입력 시각으로 당겨 앞선 처리를 지우지 않는다. 서로 다른 새 목표는 별도 ID로 관리한다. 기존 목표 유지 여부와 결과도 원장에 남기고, 빠른 새 목표만 선택해 전체 평균으로 제시하지 않는다.

완료점은 목표에 요구된 상세 Text와 실제 확인에 해당하는 상태 연결, 자료 참조와 전체 음성 요약 준비가 끝난 시점이다. 첫 안내나 위임 명령 전송만으로 최종 목표를 완료 처리하지 않는다. 외부 Agent의 내용 생산은 공통 합성 결과로 제공하고 그 내부 처리 구간은 제외한다.

```text
d'(node) = 0                       외부 Agent 업무, 사용자 답변 대기, 순수 오디오 재생 대기
           작성한 duration         VIA 판단, 모델, 읽기, queue, 연동, 상태, 출력 준비
finish(node) = d'(node) + max(finish(parent))
QA03(goal) = 공통 완료점의 finish - 공통 목표 시작점
```

선행 결과와 자원 순서를 보존한 인과 그래프를 사용한다. 병렬 작업의 시간을 모두 더하거나, wall time에서 겹치는 외부 시간을 두 번 빼지 않는다. 경합은 선행 자원 edge 또는 추가 정책 대기로 한 번만 표현한다. 전체 wall time과 제외한 역할별 구간은 보조 열로 남긴다.

### QA04: 같은 변경 과제의 모듈 영향

[C01~C06](../qa-candidate-package/qa04-change-scope.md)의 형식 변경 세 가지와 기능 확장 세 가지를 같은 완료 조건으로 비교한다. 각 과제는 동일한 변경 전 구성에서 독립적으로 적용한다. C01의 변경 결과를 C02에 누적하지 않는다.

실제 QA04의 모듈 고유 ID는 `package / crate-target / fully-qualified-module-path`다. 파일 수나 Component 수로 바꾸지 않는다. prompt, schema와 설정 변경은 사전 지정한 소유 모듈에 귀속하고, 하위 모듈 변경만으로 조상을 자동 추가하지 않는다. 테스트와 포맷만의 변경은 운영 모듈 수에서 제외한다.

이번 원장의 `concept::model_wire` 같은 이름은 **설계에서 예상한 운영 모듈의 임시 식별자**다. 실제 Rust crate나 소스에 존재하는 경로가 아니며, 완성된 Rust 모듈 registry를 뜻하지 않는다. 변경 과제마다 어떤 운영 모듈을 수정할 것으로 보는지와 그 이유를 적고 해당 목록의 수를 계산한다. 이 값의 근거 상태는 `SYNTHETIC_DESIGN_CHANGE_REVIEW`이며 실제 Rust diff나 변경 완료의 증거가 아니다. 같은 수이면 합성 설계상 동점으로 기록하고, 변경 완료 조건이 다른 과제의 수를 비교하지 않는다.

이후 실제 QA04를 측정할 때는 임시 이름을 구현의 고유 모듈 경로와 대응시키고, 과제를 수행한 diff와 수용 결과로 수를 다시 확인한다. 임시 설계 목록에 있는 수를 구현 결과로 그대로 옮기거나 임시 이름을 실제 경로처럼 표시하지 않는다.

### QA05: VIA 모델 사용 비용

요청 처리뿐 아니라 준비, 생산, 갱신, 재판단, 폐기와 마지막 요청 이후의 관련 작업을 모두 사용량 원장에 넣는다. 같은 작업을 두 DP가 이용하면 한 구성에서 한 번만 계상한다. 총액에서 목표 수치를 먼저 정해 토큰을 역산하지 않고, 단계별 가상 사용량과 공통 가상 요율에서 비용을 계산한다.

```text
QA05 = sum(VIA 역할의 중복 없는 usage bucket × 공통 tariff)
보조 비용 = 수신 Agent 비용
전체 비용 = QA05 + 보조 비용
```

외부 Agent 내부 비용을 QA05에 섞지 않는다. 입력, 출력, 캐시와 음성 등 사용한 bucket을 서로 중복 없이 기록한다. 음성 요약을 준비했다면 실제 재생 여부와 관계없이 그 준비 비용을 포함한다. 비용이 없는 것이 아니라 자료가 없는 경우에는 `INCOMPLETE_COST`로 구별한다.

이번 단위는 **USD/120 에피소드 묶음**이다. 기존 **USD/COMMON-28 묶음**과 활동량 및 입력 profile이 다르므로 $2.55 목표나 기존 비용 점수를 직접 적용하지 않는다. 에피소드당 비용은 보조 진단으로 제공할 수 있지만 두 묶음을 단순 개수 비례로 같은 평가로 바꾸지 않는다.

### QA06: 같은 시점의 로컬 RAM 최고량

모든 로컬 VIA 역할이 같은 순간에 차지한다고 설정한 RAM을 합한 뒤 전체 구간의 최고값을 취한다. 서로 다른 시점의 문맥 peak, 결과 peak와 관계 peak를 더하지 않는다. 공유 데이터는 실제 복사본 수에 해당하는 가정만큼 한 번씩 세며 모델 가중치를 실행별로 복제하지 않는다.

cloud 모델과 외부 Agent의 RAM은 제외한다. 공통 로컬 기반, 입력 버퍼, 보존 원본, 실행 문맥, 대기 결과, 생산된 관계와 준비 중인 버퍼는 포함한다. `MB = 1,000,000 bytes`를 사용한다. 단계와 소유 역할 및 관련 에피소드가 없는 임의 최종 RAM 숫자는 두지 않는다.

이 합계는 가상 RAM 구성 예시다. 실제 working set, RSS, commit 또는 전체 물리 페이지를 측정한 값이 아니며, 기존 512 MB 제품 요구의 달성 증거로 사용하지 않는다.

### QA07: 최초 확정한 요청 의미 전체

입력별 정답은 필요한 목표, 대상, 사용 범위와 조건, 기존 요청 관계, 유지할 목표 및 필요한 전달 범위를 담는다. 해당 입력에 필수인 모든 항목이 최초 확정 때 맞아야 성공이다. 항목별 성공률의 평균으로 바꾸지 않는다.

대상이 틀리면 QA02와 QA07이 함께 실패할 수 있다. 같은 대상 개선을 독립적인 두 효과로 합산하지 않는다. 대상은 맞지만 새 목적이나 제외 조건을 놓쳤다면 QA02 성공과 QA07 실패가 가능하다. 처음 의미를 올바르게 확정한 뒤 인계에서 빠뜨린 조건은 별도 인계 진단이며 QA07 오답으로 바꾸지 않는다.

QA07의 새 우선순위, 목표와 0~6점은 이 자료에서 정하지 않는다. 기존 QA01~06 우선순위 사이에 임의로 삽입하거나 QA02를 대체하지 않는다.

## 5. 실패와 해석 규칙

각 QA는 예정 관측 수, 관측된 수, 성공 또는 정확성, 미완료 수를 함께 제시한다. 틀린 응답의 시간과 비용은 남긴다. 첫 내용이나 완료가 없는 행에는 임의 벌점 시간을 만들지 않으며, 관측된 일부의 평균을 전체 속도 우위로 제시하지 않는다. 빠르게 실패한 목표를 성공 완료로 바꾸지 않는다. 이번 산출물은 숫자 점수를 부여하지 않는다.

합성 시나리오에서 모든 terminal이 작성돼 있어도 그것이 제품의 성공률 100%를 뜻하지 않는다. 정확도 오류, 의미는 맞지만 후속 처리가 실패한 경우, 정당한 보류와 미관측을 구분할 수 있는 원장을 유지한다. 비적용은 0점이나 동점과 다르다.

전체 표에는 공통 모집단의 값과 함께 유형별 반대 조건을 남긴다. DP2의 실행 겹침이 적거나 관계 의존이 큰 경우, DP5의 관계가 미생산이거나 정정돼 재사용할 수 없는 경우를 전체 이익의 예외로 설명한다. 이 값은 합성 가정 아래의 계산 결과다. 실제 우열, 통계적 유의성, 추천안 채택과 구별한다.

후속 DP 등록과 기존 자료의 이동 규칙은 [이관과 확장 계약](03-migration-and-extension.md)을 따른다.
