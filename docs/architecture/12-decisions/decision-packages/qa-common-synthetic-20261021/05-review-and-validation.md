# 검토와 확인 기록

## 공통 계약, 인과 계산의 독립 재감사

2026-10-21. 주 작성자와 별도의 검토 담당이 공통 QA 계약, 시나리오 원본, 합성 생성기와 생성된 JSON을 읽고 인과 시간, 비용, 상태 계산을 확인했다. **합성 계산과 문서의 내부 일관성 감사**이며, 실제 VIA 실행, 모델 성능, Rust 변경 diff, Windows RAM을 검증한 결과가 아니다.

검토 대상은 [공통 계약](01-common-contract.md), [자원 가정](02-change-and-resource-rationale.md), [합성 생성기](../../../../../scripts/presentations/build_common_qa_synthetic.mjs), [시나리오 원본](../../../../../scripts/presentations/common_qa_synthetic_scenarios.mjs), [합성 JSON](../../../../presentations_files/qa-common-synthetic-20261021/synthetic-data.json)이다. QA04의 가상 모듈 분석은 이 검토 담당이 작성했으므로 자신의 변경 수 가정을 독립 검증했다고 주장하지 않는다.

| 발견 사항 | 반영과 재확인 |
| --- | --- |
| REL 생산, 갱신 비용에 대응하는 시간, 메모리 node가 없었음 | 요청 전 생산과 종료 후 유휴 갱신을 DAG에 넣고 모든 비용을 node에 연결. warm, 유휴 조건을 문서에 명시 |
| 제한된 자료 설명, 요약을 외부 Agent 업무로 분류 | 입력별 handling을 명시하고 VIA 직접 응답으로 변경. 수신자 비용은 해당 위임 경로에만 남김 |
| F09에 분모 밖 사용자 발화가 존재 | 새 외부 검토 메모로 원자료와 요청을 함께 정정. 두 사용자 입력 외의 숨은 발화가 없음을 확인 |
| A의 같은 대화 의미 호출 중첩과 EXEC의 정정 상태 과소계산 | A의 의미 호출을 직렬 연결하고 EXEC은 목표 수 대신 실행별 생존 구간으로 RAM 계산 |
| 오답 의미와 정상 완료 선언의 혼동 | 처리 종료 `AUTHORED_TERMINAL`과 `terminal_content_correct`를 분리하고 실행 제어 변경 대신 명시적인 내용 오류를 사용 |
| 직접 응답의 상세 텍스트 표시 누락 | 상세 내용 준비 뒤 공통 UI 표시 0.06초를 추가. 처음부터 전체 지식 답변인 F12는 중복 상세 모델 호출을 생략 |
| F12 오답의 첫 본문이 처리 안내에 머물렀음 | 실제 지식 답변에 잘못된 기간 제한을 적용한 본문으로 소스 수정 확인. 첫 답변이 전체 답변이라는 가정과 일치 |

독립 계산 검사는 구성별 120episode, 240입력/응답, 250지칭 판단과 180목표의 동일 분모, 비용→node 연결, DAG 부모와 시작 시각, 의미 모델 동시 실행 K≤2와 A의 단일 의미 호출, RAM의 같은 시점 항목 합산, VIA 비용 합계, `0 ≤ QA03 VIA 경로 ≤ 전체 경과시간`을 확인했다. QA02 실패가 QA07에서 성공으로 처리되지 않는 경계, 정정 전 요청의 불필요한 재위임 방지, 목표 시작 전 구간 절삭과 외부 node 시간 제외 방식도 검토했다.

**이 재감사 범위에서 최종 소스의 미해결 P1/P2는 없다.** 마지막 F12 본문 수정은 소스에서 확인했으며 최종 JSON, XLSX, HTML의 재생성 및 표시 검사는 주 작성자의 최종 산출물 검사와 구별한다. 이 문장은 실제 Architecture의 우위, 합성 오류 확률의 적정성, 제품 완료나 실제 수치의 검증을 의미하지 않는다. 사전 생산 여유, 유휴 갱신, 고정 모델 단가, 속도, 상태 크기와 작성된 오류 배치는 여전히 명시적인 가정이다.

## 최종 산출물 확인

최종 원본에서 JSON, Markdown, HTML과 Excel을 다시 생성했다. [발행 확인 기록](../../../../presentations_files/qa-common-synthetic-20261021/publication-validation.json)에 파일 해시와 확인 범위를 남겼다.

- Excel 13개 시트를 렌더링하고 상단 미리보기를 확인했다. 내보낸 파일의 수식 셀 6,231개에 오류 캐시가 없으며, 21개 QA 요약 셀의 캐시 값은 JSON 원값과 일치한다. 가상 입력 단가를 바꾸면 비용 및 요약 수식이 재계산되고 복원됨을 확인했다.
- F12의 모든 후속 입력은 첫 본문에 전체 지식 답변을 포함하며 불필요한 두 번째 상세 호출을 부과하지 않는다. 마지막 소스 수정을 실제 파생물에서 다시 확인했다.
- HTML을 로컬 브라우저에서 열어 화면을 확인했다. F06, REL, 오류만 필터는 4개 행을 표시하고, 선택한 첫 행은 해당 입력과 정답, 잘못 채택한 조건 및 원자료를 표시한다.
- 새 문서와 루트 안내의 로컬 링크 검사는 8개 파일 모두 통과했다. 전체 용어 검사와 변경 공백 검사도 통과했다.
- 저장소 전체 링크 검사는 기존 `results/architecture-evaluation/current/`의 복사본과 미발행 근거 경로에서 실패했다. 이번 작업의 링크 실패는 없으며 해당 기존 파일은 변경하지 않았다.

Excel의 자체 재계산 엔진을 직접 실행한 검증은 아니다. 계산 라이브러리의 재계산과 내보낸 xlsx의 수식 캐시, 브라우저의 HTML 동작을 확인한 범위다.
