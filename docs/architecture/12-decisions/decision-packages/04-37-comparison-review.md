> **32 최종 처리:** 주요 구조 비교 후보에서 제외하고 공통 설계 참고와 검토 이력으로 보존한다. 아래 여섯 후보 유지 및 32의 별점/완료 판단은 이 결론 이전 기록이다.

## 0. 현재 읽기 안내: 31 복원과 41 분리

31은 사용자 요청으로 `ee2fcf31`의 본문/그림으로 복원했다. 아래 여섯 비교 검토도 ReAct 반영 전 판정이며, 복원이 구조 자격의 재승인을 뜻하지 않는다. 모델 중심 ReAct와 모델 틀을 코드로 완성하는 새 비교는 [04-41](./04-41-request-resolution-control.md)에서 독립적으로 읽는다. 41의 표현 범위, 조회 제어와 최종 의미 생산 책임을 31의 지속 작업공간 설명에 소급하지 않는다.

## 1. 이번 보완의 결론

**31~36의 메인 그림에서 핵심 처리, 상태 소유와 경계를 직접 비교하도록 보완했다.** 32는 요청 안의 두 해석 경로 비교를 교체했다. 현재 A는 요청 시 원본 관측을 해석하고, B는 관측 변화로 화면 상태를 발행한 뒤 요청이 조회한다. 31은 A의 저장/보존/patch도 포함하고, 33은 공동 채택, 34는 A의 선행 읽기, 35는 A의 감사 기록, 36은 OS 강제와 같은 보안 요구를 드러냈다.

[직전 문서/그림](../../../archive/decision-comparisons-before-main-figure-review-2026-10-04/README.md)은 보존했다. 여섯 주제를 모두 유지하며 어느 안도 참조 구조에 고정하지 않는다. 수정된 문서를 만들었다는 사실과 최종 발표의 사용자 수용은 구별한다.

### 4.1 04-31 독자 질문에 따른 설명과 경로 정정

- 신규 요청/보완/혼합 입력의 경로를 31 §3.2에 추가했다. 최초 입력에서 항상 신규/보완을 확정하는 분류기가 있는 것으로 설명하지 않는다. 관계는 모델 제안과 현재 연결 검증으로 정한다.
- A의 저장소 → 생성기 직결을 제거하고 저장소 → Controller → 생성기의 실제 읽기 경로를 표시했다. 검증기의 제한 재생성과 의미/미해결/거절 반환 조건을 나눴다.
- B의 Component인 Meaning Workspace와 내부 자료 구조를 구별했다. 의미 구성용 자료 조회는 Workspace, 외부 실행 직전 검사는 Controller가 맡는다. 변경 적용기/Engine은 코드이고 말뜻 해석은 Interpreter의 공유 Omni다.
- A에도 Response Manager를 표시했다. 질문 전달은 양안 모두 Controller → Response Manager → Interaction Manager로 정리하고, 실제 게시 기록과 사용자 답변의 입력 경로를 구별했다. B의 기존 직접 게시 표현을 공통 전달 통제를 거치는 계약으로 수정했다. 의미/질문 상태의 소유는 Workspace에 남는다.
- 메인 구조도의 재시도, 저장소, 모델 및 자료/Task 조회 선을 재배치하고 요청/반환 라벨을 해당 선 가까이 옮겼다. 사건도도 같은 게시/반환/요약 조회 계약으로 수정했다. 별점이나 구조 자격 판정을 이 설명 보완만으로 올리지 않는다.

| 31 + 32 | 31은 대화 목표/조건의 구성, 32는 말과 화면의 대상 결합. 32의 참조/미해결을 31의 후보로 소비. 같은 후보 선택 이익을 두 번 계산하지 않음; 모델 역할 Context와 오류 전파를 함께 검토 |

| 31 + 34 | 잠정 fragment와 여러 입력에 걸친 의미 상태는 수명이 다름. 34의 잠정 결과 중 어떤 의미 변경을 31의 내구 상태로 채택할지 명시해야 함. 잠정 전사를 매번 확정 사건으로 저장하지 않음 |
| 31 + 35 | Workspace의 채택 상태도 current record 또는 사건 원본으로 저장할 수 있음. 지속 의미 상태가 event sourcing을 강제하지 않으며 잠정 후보 전체를 영구 보존할 필요 없음 |

| 32 + 33 | 버전 있는 화면 참조를 actor 사이에 전달. B의 화면 상태는 여러 actor가 공유하되 접근 범위를 검사하며 actor마다 화면 생산을 복제하지 않음. actor별 지시 조건이 충돌하면 공통 참조로 확인 |
| 32 + 34 | 부분 전사 수정은 32 B의 조회 조건을 무효화하며 관측 자체가 안 바뀌면 화면 상태는 유지. 화면 상태 생산과 34의 잠정 준비가 같은 모델을 경합. 반복 활용 이익 중복 합산 금지 |
| 32 + 35 | 채택된 대상 참조는 현재 record나 사건으로 저장 가능. 잠정 장면 후보를 모두 내구 이력으로 만들 필요 없음. journal에 썼다고 관측/객체가 영구 유효해지지 않음 |

| 33 + 35 | actor 상태도 현재 record 또는 사건 원본으로 저장 가능. actor 메시지를 모두 영구 domain event로 취급하지 않음 |

31/33 B를 함께 쓰면 actor별 Workspace가 미채택 변경을 생산하고 Coordinator 채택 뒤 저장/질문 게시가 이루어진다. 별도 전역 Workspace를 같은 의미의 두 번째 원본으로 만들지 않는다. 32의 파생 화면 상태/조회와 34의 잠정 작업도 같은 자료/모델을 사용하는 경우 비용을 한 번만 세며, 전체 조합의 이익을 각 문서의 독립 이익 합으로 주장하지 않는다.

## 6. 산출물과 확인 범위

현재 산출물은 31~36 본문, 메인 구조도 6개와 사건도 6개, 각각의 SVG/draw.io 원본, 공통 규범 및 이 검토 기록이다. 먼저 §1 표에서 주제를 선택해 각 문서의 첫 메인 그림을 읽고 §8의 강한 반론을 확인한다.

이전 QA 정의/측정값, 참조 구조의 기술 내용, ADR의 승인 상태는 변경하지 않았다. 새로운 구조를 구현하거나 모델/OS 동작/성능을 측정하지 않았다. 실제 검사와 렌더 확인, 게시 결과는 [작업 기록](./00-workplan.md)과 최종 보고에 연결한다.
