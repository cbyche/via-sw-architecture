## 0.5 33에서 43으로 최신 비교 이관 (2026-10-05)

사용자 승인에 따라 [43](./04-43-request-interpretation.md)을 최신 정제 후보로 만들었다. 33의 A 통합/C 기능별 판단, F1~F6, 사례, 책임과 품질 판단을 변경하지 않고 본문과 두 도식을 복사했다. 33은 이관 시점의 논의와 B 제외 이력으로 보존하며 상단에서 43으로 안내한다. 이후 본문/그림의 개선 원본은 43이다.

메인 SVG/draw.io/PNG 및 보충 SVG/draw.io의 번호·식별자·참조를 43으로 바꾸고 전용 생성기와 CI 검사를 연결했다. 기존 33 도식/생성기는 그대로 보존한다. 새 이름과 번호를 별도 구조 대안이나 기능 품질의 개선으로 세지 않는다. 31/41/42 등 다른 비교, 32 제외, 참조 Architecture와 QA/ADR에는 변경이 없다.

**이관 검수:** 번호·파일 참조 치환 외에 33/43의 §0~9 본문과 두 SVG/draw.io의 내용·좌표가 동일함을 대조했다. 메인 2560×1440 PNG를 새 SVG에서 렌더링하고 1280×720 화면 및 보충 사건도를 육안 확인했다. SVG 실제 글자 경계 검사에서 메인 53개/보충 48개 text의 화면 밖 이탈·서로 겹침은 없었다. draw.io는 XML/ID/소유/경로와 같은 scene 생성 일치를 확인했으며 편집기 내 렌더는 별도로 시험하지 않았다.

| 발견/지적 | 실제 설계와 표현의 수정 |
| --- | --- |

**그림 설계:** 한 장의 16:9 메인에서 A의 통합 Module과 C의 여섯 기능 Module 및 코드 조정자, 요청/반환, 임시 상태와 공통 채택을 읽는다. C를 여섯 단계의 고정 pipeline으로 그리지 않고 Coordinator와 각 생산자의 왕복으로 표시한다. F 번호는 동일 기능의 식별자이며 호출 수가 아니다. 보충 사건도는 같은 표 정정에서 변하는 F2/F5/F4를 확대하며 F1/F3/F6도 현재 유효성을 확인한다. Component/Module 상자 안은 이름만, 실제 동작/산출물은 화살표 라벨로 표시한다.

**04-30 §4.5 판정:** A는 전체 의미를 한 책임으로 생산, C는 부분 의미의 생산 권한과 의존/재판단을 분리한다. 공통 인터페이스와 저장 원본/모델은 유지할 수 있고 전환 시 의미 생산/충돌 해결 계약이 바뀐다. Task별 기록과 전문 보조만으로 충분하면 C의 중요한 선택 이유는 약하다. 얽힌 자유로운 요청/적은 조정은 A의 조건, 반복되는 특정 기능 오류/변경의 집중 개선은 C의 후보 조건이다. C의 추가 비용보다 큰 기능 이익이나 독립 주요 DP 자격을 이번 작성으로 확정하지 않는다.

**검증 기록:** 33 커밋 예정 내용만 별도 경로에 구성하여 활성 Markdown 146개 링크, 용어, QA 23개/ASR 4개 registry와 여덟 도식 생성기 전체 검사를 통과했다. V-01~13의 정확한 이름과 직전 ABC 문서/그림/생성 source 보존본의 byte 일치를 확인했다. 시작 시 35/36, 작업 중 42의 병행 변경이 있어 그 내용을 이번 커밋에 포함하지 않는다. 커밋 대상의 다른 비교 본문/도식, 참조 Architecture와 QA/ADR는 유지한다. 실제 작업공간의 병행 파일을 덮어쓰거나 되돌리지 않는다. 게시 commit과 CI는 Git 이력/최종 응답으로 연결한다. 구현, 모델 실행, 측정과 실제 심사위원 평가를 수행한 것은 아니다.

### 4.1 04-31 독자 질문에 따른 설명과 경로 정정

- 신규 요청/보완/혼합 입력의 경로를 31 §3.2에 추가했다. 최초 입력에서 항상 신규/보완을 확정하는 분류기가 있는 것으로 설명하지 않는다. 관계는 모델 제안과 현재 연결 검증으로 정한다.
- A의 저장소 → 생성기 직결을 제거하고 저장소 → Controller → 생성기의 실제 읽기 경로를 표시했다. 검증기의 제한 재생성과 의미/미해결/거절 반환 조건을 나눴다.
- B의 Component인 Meaning Workspace와 내부 자료 구조를 구별했다. 의미 구성용 자료 조회는 Workspace, 외부 실행 직전 검사는 Controller가 맡는다. 변경 적용기/Engine은 코드이고 말뜻 해석은 Interpreter의 공유 Omni다.
- A에도 Response Manager를 표시했다. 질문 전달은 양안 모두 Controller → Response Manager → Interaction Manager로 정리하고, 실제 게시 기록과 사용자 답변의 입력 경로를 구별했다. B의 기존 직접 게시 표현을 공통 전달 통제를 거치는 계약으로 수정했다. 의미/질문 상태의 소유는 Workspace에 남는다.
- 메인 구조도의 재시도, 저장소, 모델 및 자료/Task 조회 선을 재배치하고 요청/반환 라벨을 해당 선 가까이 옮겼다. 사건도도 같은 게시/반환/요약 조회 계약으로 수정했다. 별점이나 구조 자격 판정을 이 설명 보완만으로 올리지 않는다.
