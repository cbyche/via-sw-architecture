# 04-37. 여섯 구조 비교의 작성자 검토

> 2026-10-03 / [04-30 가이드](./04-30-comparison-guide.md)의 적용 기록 / 독립 리뷰, 구현 및 측정 없음

## 1. 사용자 지적과 이전 판단의 정정

`10f5546`에서 여섯 문서의 작성과 렌더 검토를 완료했다고 보고했지만, 사용자는 두 구조를 동일한 골격에 끼워 맞춘 문제를 지적했다. 생성기는 공통 Component와 직렬 처리 위치를 먼저 고정했다. 특히 31/34/35의 이름이 다른 상자 뒤에 실제로 어떤 관계가 달라지는지 드러내지 못했다. 이 결과를 가이드에 충실한 구조 비교라고 판단한 것은 잘못이었다.

사용자가 제공한 아홉 예시의 핵심은 목적을 달성하는 메커니즘에 따라 실제 책임, 실행, 자료/상태와 운영 방식이 달라지고 그 차이에서 품질 손익이 생긴다는 점이다. 이를 [04-30 §4](./04-30-comparison-guide.md#4-sw-구조적으로-다른-대안의-정확한-의미)에 필수 기준으로 기록했다. 이후 그림의 배치만 고치는 작업과 실제 대안 재설계를 구별했다.

## 2. 같은 중요한 목적과 실용성을 대조한 결과

각 문서 §1~2에서 사용자 실패, VIA 책임과 설계 난이도를 먼저 설명했다. 각 안을 선택하는 조건과 포기할 기능은 §5~9에 있다. 정정/철회/실패를 정상 기능 설명보다 먼저 쌓아 난이도를 과장하지 않았다.

- 04-31 B의 Workspace는 VIA의 해석 상태를 소유하며 외부 Task 상태나 업무 계획을 소유하지 않는다. 타입/규칙 밖 표현과 후보 추출 오류를 공개했다.
- 04-32 B는 이미지를 볼 수 없도록 억지 제한한 안이 아니다. source 객체를 실제 읽기/재확인/인계에 사용하는 안이며 opaque 영역의 자동 지원 손실과 혼합 가능성을 공개했다.
- 04-33 B의 actor는 외부 Agent나 process가 아니다. 자기 대화 상태의 사건 처리, 원문 구간별 제안, 경쟁/누락 판정과 교차 참조 protocol을 포함한다. 공유 모델의 물리적 병렬 성능은 주장하지 않았다.
- 04-34 B의 잠정 처리는 승인 전 외부 변경의 조기 실행이 아니다. 허용된 준비만 앞당기며, 확정 경계와 실제 전달/정정을 유지한다. 이미 들려준 말을 소급 취소하지 않는다.
- 04-35 replay는 모델 재추론, 외부 command 재전송이나 음성 재생을 수행하지 않는다. local 기록으로 외부 ACK를 복원하지 않는다.
- 04-36 B는 scope 문자열 검사만 하지 않는다. 직접 파일/DB/network 접근과 모델 port 우회를 제거해야 한다. Broker와 Model Access는 신뢰 경계에 남는다.

새 learned helper, 무한 KV, Task별 Omni 복제, 분산 DB나 cloud 규모를 전제로 사용하지 않았다. 요구한 runtime/provider 기능의 실제 지원과 품질 수치는 미확인으로 남긴다.

## 3. 여섯 선택은 서로 얼마나 독립적인가

표에서 “조합 가능”은 품질 효과가 독립이라는 뜻이 아니다. 함께 쓰면 생기는 계약과 비용을 실제 조합에서 한 번만 센다.

| 두 주제 | 독립 선택 여부와 결합 시 확인할 것 |
| --- | --- |
| 31 + 32 | 의미 생성 방식과 대상 획득은 별개. A/B 각 참조를 31의 후보/근거로 넣을 수 있어야 하며 source의 정확성을 의미 해법의 정확성으로 중복 주장하지 않음 |
| 31 + 33 | 이제 단순 독립 조합이 아님. 31 B의 의미 조건/질문 상태와 33 B의 actor 대화 상태가 겹침. actor별 Workspace로 소유를 합치거나 중앙 Workspace와 actor의 비중복 상태를 명시해야 함. 두 원본을 병행하는 조합은 미설계이며 별개 이익으로 합산 금지 |
| 31 + 34 | 잠정 fragment와 여러 입력에 걸친 의미 상태는 수명이 다름. 34의 잠정 결과 중 어떤 의미 변경을 31의 내구 상태로 채택할지 명시해야 함. 잠정 전사를 매번 확정 사건으로 저장하지 않음 |
| 31 + 35 | Workspace의 채택 상태도 current record 또는 사건 원본으로 저장할 수 있음. 지속 의미 상태가 event sourcing을 강제하지 않으며 잠정 후보 전체를 영구 보존할 필요 없음 |
| 31 + 36 | 제한 process의 후보 생성은 Broker 자료만 사용. 지속 Workspace의 원본과 최종 허용은 신뢰 영역에 남기는 배치 가능. 이름상 Workspace라고 raw/전역 권한을 자동 부여하지 않음 |
| 32 + 33 | 객체/관측 참조를 대화 단위 사이에 전달 가능. 어느 actor가 참조하든 같은 유효성/삭제 의미 유지 |
| 32 + 34 | source 변경/관측 시점이 fragment의 dependency가 됨. 늦은 제공자 결과를 과거 입력에 붙이지 않음 |
| 32 + 35 | 확정 대상 참조의 저장 방식과 source 획득은 별개. journal에 썼다고 외부 객체가 영구 유효해지지 않음 |
| 32 + 36 | Source Reference Service의 identity/수명 책임과 Broker의 권한 책임을 구별. 실제 source read는 Broker 권한 아래 두거나 함께 배치할 수 있으나 두 독립 보안 경계로 중복 계산 금지 |
| 33 + 34 | actor 협력과 부분 입력은 조합 가능하지만 proposal 버전/참가 라운드가 증가. 공동 backlog와 재처리 비용을 별도로 검토 |
| 33 + 35 | actor 상태도 현재 record 또는 사건 원본으로 저장 가능. actor 메시지를 모두 영구 domain event로 취급하지 않음 |
| 33 + 36 | actor라는 논리 경계만으로 자료 권한 격리는 생기지 않음. 별도 실제 process/권한 배치가 필요 |
| 34 + 35 | 잠정 dependency는 버려도 되는 실행 상태, event journal은 확정 상태의 원본. 연속 처리 때문에 event sourcing이 필수라는 주장은 금지 |
| 34 + 36 | 취소/철회되는 model job과 source handle을 Broker 수명에 연결. 중개 대기와 복사는 VIA 시간/자원에 포함 |
| 35 + 36 | 권위 journal/current DB는 신뢰 Core에 남길 수 있음. 제한 처리의 직접 쓰기 권한을 주지 않고 owner의 확정 계약을 사용 |

04-31~34는 같은 요청에서 상호작용하며, 이번 31 재설계로 33과 의미 상태 소유가 겹치는 부분이 생겼다. 두 B를 그대로 독립 조합할 수 있다는 이전 판단은 철회한다. 이후 전체 조합의 시간 이익을 각 문서의 독립 이익 합으로 계산하지 않는다. 04-35와 04-36은 이 기능 선택을 강제하는 선행 결정이 아니다.

## 5. 검증 범위와 사용자 리뷰 위치

여섯 본문은 각각 §1~9와 13개 품질 행, 구조/사건 도식 2쌍을 갖춘다. 자동 검사는 링크, 정식 명칭, QA registry 및 SVG/draw.io 생성물/좌표/연결을 확인한다. 렌더와 본문 대조는 사람이 읽을 수 있는지와 표기 오류를 확인한다. 이 두 검사가 구조의 효과나 모델/OS 기능을 입증하지는 않는다.

현재는 **반복 지적에 따른 후속 설계와 그 한계를 리뷰할 단계**다. 이번 수정도 그림의 차이 자체를 주요 DP 자격으로 세지 않는다. 실제 구현, 모델 실행, 측정과 최종 선택은 하지 않았다. 검사 결과와 게시 기록은 [WORKPLAN](./00-workplan.md)의 현재 절에서 확인한다.
