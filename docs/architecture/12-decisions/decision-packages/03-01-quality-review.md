## 진행 순서와 검토 범위

사용자는 02-00을 승인하고 01-00의 가운데점을 정리하여 먼저 commit/push한 뒤 3단계로 진행하도록 요청했다. 정리와 승인 기록을 `e8a01e4c19bc241bd090db78baf8b6207115b221`로 먼저 반영했으며 [해당 CI](https://github.com/cbyche/via-sw-architecture/actions/runs/36823741886)의 성공을 확인했다. 이후 03-00을 작성했다.

작성자가 승인된 02-00의 P-01~16, B-01~09, U-01~08과 품질 시나리오를 대조했다. ISO/IEC 25010:2023의 공개 원문과 저장소의 ISO 대응 근거, core ASR 및 실제 event 경계 계약을 확인했다. 이번 기록은 **작성자의 자기 검토**다. 별도 에이전트의 독립 리뷰나 사용자 승인으로 표시하지 않는다. 자동 검사는 문서 형식과 저장소 일관성을 확인하며 품질 가설이나 dependency의 실제 동작을 검증하지 않는다.

## 초안 시점의 중점 대조

| 검토 관점 | 대조 결과와 문서에서 보존한 경계 |
| --- | --- |
| 요구를 포기하는 절충 | 모호한 대상의 임의 확정, 권한 위반, 복구 가능한 업무의 포기, 입력만 유지하고 정상 처리를 무기한 미루는 방식을 제외했다. 정확성과 성능의 상대 값은 미측정이며 선언만으로 동등하다고 하지 않는다. |
| target 수단의 강제 | 시나리오의 대상은 관찰할 책임이다. 독립 ASR, DB, outbox, cache 등 현재 수단을 모든 대안의 필수 구조로 바꾸지 않았다. B-02의 공유 Omni와 입력 지속은 유지했다. |
| 16개 문제의 누락 | 모든 P에 자극과 환경, 대상과 기대 반응, 품질 충돌, 조건별 차이, 관찰과 QA, 근거와 U를 연결했다. 문제 간 공통 비용도 §3과 §6에서 별도로 표시했다. |
| 품질 분류 | 기능 정확성, 시간 특성 외에 자원, 신뢰성, 변경, 기밀성, 상호운용, 조작, 분석 및 시험을 검토했다. “로그”, “CPU”, “삭제 비용” 자체를 독립 ISO 품질속성으로 만들지 않았다. |

| 정상과 실패 | P-13의 FA-14 복구 가능한 조건을 불명 안내와 구분했다. P-07의 같은 Agent 지원 수준, P-09의 audible 전달 불명, P-11/12의 철회와 purge 한계, P-14의 미검증 runtime 한계를 보존했다. |
| 추가 품질과 범위 | QA-41은 진단 지위를 유지하면서 메모리를 ASR 검토 후보로 명시했다. 사용자 단계, 수용량, 공존성 등의 추가 질문은 지표 동결이나 제품 최대치 선언이 아니다. 외부 Agent의 내부 업무 실행이나 모델 학습을 VIA 범위에 넣지 않았다. |
| 단계 경계 | 새 대안이나 DP를 선정하지 않았다. 기존 네 비교안을 결론으로 사용하지 않았고 상대 기호도 유보했다. 미확인을 동등으로 처리하지 않는 후속 규칙을 명시했다. |

대조 범위에서 승인된 R/B를 바꾸거나 기존 QA를 재정의해야 하는 문제는 찾지 못했다. 실제 사용 빈도, 장비 자원 적합성, dependency 지원, 충돌의 크기는 미확인이다. 구조 대안이 없으므로 구조별 상대 우위와 탐색의 충분성도 아직 판단하지 않았다.

## 문서 검사

### 사용자 리뷰 후 반영 — QA 공통 계약 원칙

사용자는 03의 품질 질문에 기존 QA를 그대로 적용할 것인지 질문했다. 논의 뒤 03에서 품질의 의미와 시나리오를 정하고, 04~05에서 구조 차이와 품질 인과를 검토한 다음 실제 측정 전에 정확한 QA 정의, 지표와 방법을 고정하는 흐름에 동의했다.

이어 **같은 QA는 모든 DP와 모든 방안에서 동일한 정의, 지표, 측정 방법을 사용해야 하며 DP별로 달리 적용해서는 안 된다**고 명시했다. 이 원칙을 AGENTS.md, 작업 계획, README와 03-00 §6.1에 기록했다. 공통 원본과 version, 판정 및 모집단 적용 규칙, 개정 시 전체 영향 검토까지 명시했다. 추가 진단은 공통 QA를 대체하지 않는다.

03-00 §2의 기존 QA 연결을 관련 자산과 한계의 참조로 명료화하고, §6의 “기존 집계 보존”을 “이전 기록의 의미 보존과 새 비교에서의 재사용 여부 검토”로 수정했다. 기존 QA 원본이나 지표를 이번에 개정한 것은 아니다. 앞의 작성자 대조 기록은 초안 시점의 검사이며, 이 후속 합의가 앞으로의 QA 구체화 원칙이다. 03 전체 승인이나 04 진행 승인으로 해석하지 않는다.

### 사용자 재검토 후 반영 — 11개 관점의 일관된 추적

사용자는 참조라는 단서를 추가한 뒤에도 §4가 기존 QA 번호와 지표를 계속 중심에 두고, §5가 다시 기존 QA와 추가 QA로 나뉜다고 지적했다. §2의 11개 관점이 전체 문서와 04~05에서 일관되게 다뤄져야 한다는 지적을 반영했다. 앞선 작성자 검토는 이 구성 문제를 찾아내지 못했으며, 참조 문구만 추가한 수정으로는 충분하지 않았다.

- §2를 기존 QA 대응표에서 11개 공통 품질 질문으로 바꿨다. V-01~11은 추적 표식이며 새 QA ID나 ISO 상위 특성의 개수가 아니다.
- §3은 11개 관점 각각의 충돌과 조건을 정리했다. §4는 기존 QA 번호와 집계 제약을 제거하고 같은 관점에 연결한 관찰 질문으로 다시 썼다.
- §2에만 머물던 설치 용이성, 기능 완전성과 적절성, 사용자 조작, 분석 및 시험의 구체 조건과 관찰을 보완했다. §5에는 11개 전체의 시나리오 연결 및 04와 05의 후속 질문을 넣었다.
- 모든 문제에 11개를 억지로 적용하지 않는다. 다만 04~05에서는 각 구조에 대해 11개 전부의 영향 경로, 영향 없음의 근거 또는 미확인을 확인한다. 지금의 연결표가 비적용 판정은 아니다.
- 기존 QA는 문서 끝의 별도 참고로 두었다. QA 정의, 지표와 방법을 질문 중심으로 공통 설계한다는 §6의 원칙은 유지한다. target, 승인된 요구와 기존 QA 원본을 바꾸거나 구조 탐색에 착수하지 않았다.
