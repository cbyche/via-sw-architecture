# 1단계 독립 검토·보완 기록

> 상태: **작성·독립 재검토 완료 / 사용자 공동 검토 후 2단계 진행 승인** · 2026-10-01
> 대상: [문제 원장](./01-00-problem-coverage.md), [UC 추적](./01-01-problem-coverage-use-cases.md), [횡단 점검](./01-02-problem-coverage-crosscutting.md)
> 작성자의 문서 작성 완료와 검토자 확인, 사용자 공동 검토를 구별한다. 아래는 1단계 수행 기록이며, 이후 사용자 요청으로 [2단계](./02-00-requirements-and-choices.md)를 진행한다. 3~6단계는 미착수다.

## 검토 방법

작성자는 mission/scope에서 문제를 정리하고 요구→문제 및 문제→근거를 대조했다. 별도 검토자 두 명은 초안 완성 전에 각각 기능 범위와 운영/품질 범위를 독립 추출했다. 초안 뒤에는 세 검토자가 기능 의미·횡단 범위·문제 분해의 타당성을 재검토했다. 지적 사항 수정 후 각 검토자가 자신이 제기한 문제의 해결을 재확인했다. 검토자들이 같은 저장소 기준선을 사용하므로 외부 전문가 검증이나 사용자 승인으로 표현하지 않는다.

| 검토 | 범위 | 현재 상태 |
| --- | --- | --- |
| 기능 범위 독립 추출 | 01·03·05, 모든 UC 필수 변형·실패·경계 | 완료, 아래 보완 반영 |
| 운영·품질 독립 추출 | 06·07, QC/QA, 자원·복구·삭제·관측 | 완료, 아래 보완 반영 |
| 기능 의미 재검토 | 새 16개 문제와 UC 추적의 실제 의미 | 완료, 지적 수정·재확인 |
| 운영·변화·품질 재검토 | FA 16개·변화 29개·QC 10개 및 예외 | 완료, 지적 수정·재확인 |
| 문제 분해·중요성 반론 검토 | 과도한 분해·중복·target 수단 편향·누락 | 완료, 지적 수정·재확인 |
| 사용자 공동 검토 | 중요한 문제와 분해의 적절성 | 문제 원장·VIA 특성을 검토한 뒤 사용자가 2단계 진행 요청 |

## 문서 검사

다음은 실제 실행한 문서 검사다. ID 집합 일치는 형식 누락 점검이며 의미 검토를 대체하지 않는다.

| 검사 | 결과·한계 |
| --- | --- |
| `check_active_markdown_links.py` | PASS, active Markdown 107개 local 링크 |
| `check_active_terminology.py` | PASS, active 용어·정식 Component 이름 일관성 |
| `check_qa_catalog.py` | PASS, 23개 active QA·4개 확정 ASR 등 기존 registry 유지 |
| 원문/추적표 ID 집합 대조 | 94개 UC 변형의 누락·추가·중복 0. FA 16개·M/A/C 24개·E 5개·QC 10개와 P 원장 16개 확인 |
| 새 문서 표·참조 검사 | 표 열 수 일치, 잘못된 P ID 없음, 새 문서에 archive 규범 링크 없음 |
| `git diff --check` 및 실제 변경 검토 | PASS. 변경은 계획·문제 원장·추적·검토·navigation에 한정 |

작성자가 범위·완료 조건을 대조했고, 기능 검토자는 UC 필수 변형의 의미를 전수 확인했다. 운영/품질 검토자는 FA·변화·QC와 예외 경계를 확인했다. 세 검토자 모두 자신이 검토한 범위에서 수정 후 미해결 P1/P2가 없다고 보고했다. 이는 절대적인 무결점 인증이나 사용자 합의가 아니다.

구현·모델 실행·성능 측정·ASR 변경은 수행하지 않았다. 사용자가 1단계 공동 검토본의 commit/push와 리뷰 요청을 명시적으로 요청했다. 당시 Git 전달 자체는 문제 분해의 승인이나 2단계 착수를 뜻하지 않았다. 이후 사용자가 문제·VIA 특성 설명을 확인하고 2단계 진행과 GitHub 반영을 명시적으로 요청했다.
