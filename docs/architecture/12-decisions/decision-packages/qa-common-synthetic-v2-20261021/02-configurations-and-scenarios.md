# 구성 축과 공통 시나리오 은행

**SYNTHETIC_AUTHORED_NOT_MEASURED** / 구성 registry `COMMON-QA-CONFIG-2.0`

## 1. 서로 다른 세 질문

| 축 | 사용자 문제 | 기본 대안과 차이가 생기는 경로 |
| --- | --- | --- |
| DP2 의미 판단 실행 | 진행 중 새 정정이나 독립 질문이 오면 어느 실행에서 의미를 판단하는가 | A는 기존 대화 실행의 다음 step, B는 별도 입력 해석 실행. 대기와 기존 문맥 연결 비용이 바뀜 |
| DP3 화면과 발화의 지칭 | 말한 시점의 지시가 어느 화면 대상인지 누가 해석하는가 | A는 당시 원본을 cloud 의미 모델이 직접 해석. B는 local 시각 생산자가 후보와 근거를 만들고 cloud 의미 모델이 요청에 결합 |
| DP5 과거 사건의 관계 | 과거 표시, 평가, 정정을 현재 목적에 어떻게 사용하게 하는가 | A는 요청 때 필요한 원본 관계를 판단. B는 사전 생산한 관계를 조회하고 최신 조건 및 원본으로 보완 |

화면의 객체 후보와 과거 사용자 평가 관계는 다른 파생 상태다. 같은 원본을 공유할 수 있어도 동일한 의미나 정답으로 취급하지 않는다. 어느 축도 현재 권한, 요청 판본, 원본 보완과 이미 확정한 상태의 재사용을 제거하지 않는다.

## 2. 이번에 수치가 있는 구성

| 구성 | 층 | DP2 | DP3 | DP5 | 비교 기준 |
| --- | --- | --- | --- | --- | --- |
| T-BASE | TEXT | A | 이번 경로에서 실행하지 않음 | A | Text 기준 한 벌 |
| T-EXEC | TEXT | B | 이번 경로에서 실행하지 않음 | A | T-BASE에서 DP2만 변경 |
| T-REL | TEXT | A | 이번 경로에서 실행하지 않음 | B | T-BASE에서 DP5만 변경 |
| V-A | VOICE | 고정된 주변 처리, DP2 A/B 매핑 미확인 | A | 고정된 주변 처리, DP5 A/B 매핑 미확인 | 별도 Voice 기준 |
| V-R1 | VOICE | V-A와 같음 | B-R1 | V-A와 같음 | V-A에서 시각 생산과 필요 모델 적재 |
| V-R2 | VOICE | V-A와 같음 | B-R2 | V-A와 같음 | V-A에서 시각 생산과 모델 상주 |
| V-R3 | VOICE | V-A와 같음 | B-R3 | V-A와 같음 | V-A에서 시각 생산, 모델 상주와 worker 분리 |

DP3 원본은 주변 정책이 네 안에서 같다고 고정했지만 DP2/DP5의 A 또는 B라고 구체화하지 않았다. 따라서 V-A를 `2A3A5A`로 개명하거나 T-BASE와 같은 실행으로 참조하지 않는다. TEXT의 화면 생산을 실행하지 않았다는 사실 역시 DP3 A와 B가 전체 제품에서 동점이라는 뜻이 아니다.

DP3 B의 입력은 동일 전사와 word timestamp다. OmniParser detector와 EasyOCR의 후보/bbox, 필요한 경우 SAM2.1 Tiny의 mask와 시간간 대응을 원본 crop 및 불확실성과 함께 전달한다. 원음 재해석이나 speculative execution을 새로 붙이지 않는다. Native 선택으로 충분하면 학습 모델을 건너뛰고 box로 충분하면 SAM을 건너뛴다. A도 crop, 추가 원본 조회와 확정 상태 재사용이 가능하다.

| B의 실행 축 | R1 | R2 | R3 |
| --- | --- | --- | --- |
| Worker/runtime | 1개 유지 | 1개 유지 | UI/SAM별 분리 |
| 가중치 수명 | 필요 모델 적재, 회수와 전환 | 한 번 필요해진 모델 유지 | worker별 유지 |
| Episode 근거 보존 | 허용 | R1과 같음 | 같은 근거와 판본 |
| 주 비교 heavy 추론 | 순차 | 순차 | 동일 CPU 총량, 순차 admission |
| 독자적인 비용 | 재로딩과 전환 | 상주 RAM | private RAM과 IPC |

R1→R2는 상주 정책, R2→R3는 process/장애 경계를 분리해서 읽는다. 이 변경에 정확도 이익이나 자동 병렬 보너스를 주지 않는다. 병렬 admission과 episode 보존은 별도 축이다.

## 3. 18개 사례군과 적용 범위

시나리오 은행 `COMMON-QA-CORPUS-2.0-STRATIFIED`에서 `T-`와 `V-` 접두가 층을 구분한다. 입력, 목표와 표현도 `TEXT:`/`VOICE:`로 정규화하고 원본 ID를 따로 보존한다. 숫자 이름이나 DP별 prefix만으로 의미를 추정하지 않는다.

| 사례군 | 공통 사용자 장면 | 주요 차이 또는 반대 조건 |
| --- | --- | --- |
| T-F01 | 명시 ID와 조건 정정 | 관계 조회가 쉬운 대조 |
| T-F02 | 과거 평가의 첫 재참조 | 원본 관계 재구성과 사전 관계 조회 |
| T-F03 | 비슷한 이름의 다른 업무 자료 | 같은 이름과 다른 Task의 혼동 |
| T-F04 | 실제로 본 판본과 최신 판본 | 과거 표시와 현재 자료의 구별 |
| T-F05 | 정정된 피드백과 무효 관계 | 준비 뒤 갱신된 원본에 대한 보완 |
| T-F06 | 과거 대상 유지와 현재 목적 변경 | 대상은 맞아도 목적이 틀릴 수 있음 |
| T-F07 | 평가 측면과 선호 적용 범위 | 과거 선호의 과도한 일반화 |
| T-F08 | 공통으로 확인한 관계 재사용 | A도 확정 상태를 재사용하는 대조 |
| T-F09 | 방금 도착해 미생산인 피드백 | 사전 생산이 항상 선행하지 않음 |
| T-F10 | 형식과 내용 출처를 나눠 사용 | 한 입력의 복수 표현과 출처 역할 |
| T-F11 | 조회 반환에 의존하는 정정 | 별도 해석도 필요한 증거를 기다림 |
| T-F12 | 자료 작업 중 독립 질문 | 새 질문을 기존 목표 조건과 분리 |
| V-S1 | Native로 선택한 두 견적 | 모든 B가 UI/SAM 모델을 건너뜀 |
| V-S2 | 첫 밀집 화면의 원 안 두 카드 | cold UI 생산, SAM 불필요 |
| V-S3 | 두 시점에 가리킨 견적의 중복 제거 | 이전 별도 clip 준비, UI+SAM의 2frame 대응 |
| V-S4 | 다음 새 viewport의 두 견적 | R2/R3 모델 warm, 현재 후보는 새 생산 |
| V-S5 | 같은 장면의 확정 대상 재사용 | A도 재사용, 모든 B 모델 skip |
| V-S6 | 장기 유휴 후 새 화면 | 다시 cold, UI만 필요 |

Text 각 군은 10에피소드와 20입력이며 표현/목표 수는 각각 다를 수 있다. Voice 각 군은 20개의 신규 입력, 표현과 목표다. Voice의 20변형은 주로 이름과 번호가 다르고 시간 가정이 같으며 20회 독립 모델 반복이 아니다. Voice에 후속 정정이나 동시 사용자 목표를 실행한 행은 없다.

## 4. 한 입력에서 원인과 결과를 따라가기

### T-F06: 대상은 유지하고 목적을 변경

사용자는 먼저 과거에 좋게 평가한 자료로 발표자료를 요청하고, 다음 입력에서 “같은 자료는 쓰되 이번에는 상담팀 실무회의용으로 바꿔. 장점보다 위험과 미확인 사항을 먼저 보여줘”라고 정정한다. 대상은 그대로이고 목적과 강조 조건이 바뀌는 장면이다.

v1의 `SYN-F06-01-U02`에서 T-BASE는 새 목적을 반영한다. T-EXEC와 T-REL은 같은 자료를 식별하지만 과거 위원회용 목적과 장점 우선을 잘못 유지하도록 작성됐다. 이 행에서 QA02가 같아도 QA07은 다르다. DP3의 시각 후보가 좋아진다고 이 현재 목적 오류가 자동으로 해결되지는 않는다. 최초 오답 표시와 이후 목표 경로를 원장에 함께 남긴다.

### V-S2: 후보 생산의 정확도 이익과 cold 비용

“방금 원으로 묶은 이 두 견적을 설치비는 제외하고 비교표로 만들어줘.” 원 안은 L/R이고 Z는 밖이다. `S2-01`에서는 A가 L/Z, B가 L/R을 최초 채택하도록 작성됐다.

| 첫 표시까지의 작업 | A 초 | R2 초 |
| --- | ---: | ---: |
| 잔여 전사, 화면 필요 판단, 원본 읽기 | 1.0300 | 1.0300 |
| Runtime, UI 모델 준비, 검출/OCR | 0 | 3.9000 |
| 원본 직접 해석 또는 후보 결합 | 2.7000 | 1.9333 |
| 채택과 표시 | 0.0700 | 0.0700 |
| 합계 | 3.8000 | 6.9333 |

B는 cloud 입력량을 줄여도 local 선행 3.90초를 부담한다. 이 장면에는 SAM을 추가하지 않는다. A의 틀린 첫 내용은 3.80초 그대로이고 QA02/07에서 실패한다. `S2-10`은 모든 안이 L/R을 맞추되 설치비 제외를 놓치는 별도 의미 오류다.

### V-S3와 V-S5: 상주와 보존은 다른 축

S3의 평가 이전에는 별도 clip으로 UI/SAM을 사용한 활동이 있다. R2는 두 가중치를 유지하므로 현재 요청에서 R1의 로딩과 전환 1.90초를 피한다. 현재 clip의 정답이나 후보를 준비 단계에서 미리 제공하지 않는다. S5는 같은 장면의 근거 자체를 재사용하므로 R1도 다시 UI/SAM을 실행할 필요가 없다. 모델 회수와 episode 삭제를 동일시하지 않은 결과다.

S3의 원본은 실제 픽셀이나 WAV가 아닌 작성 명세다. 두 frame의 시각 단서가 충분한지 실제 모델로 확인하지 않았고, action 설명에는 동일 객체라는 정답 관계가 포함돼 있다. 따라서 이 자료로 “모델이 원본에서 동일성을 입증했다”고 주장할 수 없다. 현재 실패 행은 L을 Z로 잘못 선택한 것이며 같은 L을 두 번 세는 출력 오류를 실제로 작성한 것도 아니다. S3는 **시간간 지칭 대상 오류의 가상 사례**로 읽는다. 원본에 없는 식별 능력이나 중복 제거 오류 증거를 새로 주장하지 않는다.

## 5. 교차 조합에서 남는 판단

현재 비교쌍은 `T-EXEC−T-BASE`, `T-REL−T-BASE`, `V-R1/R2/R3−V-A`다. 각 변화는 해당 층과 고정 주변 구조 안에서만 유효하다. 같은 workload와 profile에서 두 축을 바꾼 결과가 있을 때에만 `interaction = Q(B,B)−Q(B,A)−Q(A,B)+Q(A,A)`를 계산할 수 있다. 현재는 그 네 셀이 없으므로 값은 **미작성**이며 0이 아니다.

| 조합 | 실제로 겹칠 수 있는 처리 | 현재 판단 |
| --- | --- | --- |
| DP2와 DP3 | 새 정정을 먼저 해석해도 미완료 시각 근거를 기다림. CPU/모델 queue와 요청 revision 공유 | 개별 시간 절감량을 더할 수 없음 |
| DP3와 DP5 | 화면 후보와 과거 피드백 관계가 같은 원본 판본과 권한에 의존. crop 및 cache 중복 가능 | 호출, 저장 및 무효화 소유자를 다시 배정해야 함 |
| DP2와 DP5 | 별도 입력 실행이 사전 관계와 현재 조건을 결합. 의미 호출 슬롯과 상태가 겹침 | T-EXEC와 T-REL의 합은 2B5B 결과가 아님 |

새 통합 제품 구성에서는 동일 모델 profile과 활동 일정을 고르고 세 축의 동일 입력 행을 다시 작성해야 한다. 이 문서는 그 미작성 값을 개별 표의 합으로 채우지 않는다. 현재 완성된 층별 비교만으로도 각 선택의 이익, 부담과 반대 조건을 판단할 수 있다.
