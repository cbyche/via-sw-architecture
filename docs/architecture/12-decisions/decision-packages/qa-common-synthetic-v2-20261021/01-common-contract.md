# 공통 의미와 층별 평가 계약

`QA-COMMON-SYN-CONTRACT-v2-STRATIFIED` / **SYNTHETIC_AUTHORED_NOT_MEASURED**

## 1. 이번 통합에서 고정한 것

[INTENT.md](../../../../../INTENT.md)의 QA 의미를 유지하고 [v1 계약](../qa-common-synthetic-20261021/01-common-contract.md)을 Voice/Screen까지 확장한다. 층은 입력, 원본, 사건, 자원 및 모델 가정을 함께 고정한 비교 단위다. **같은 층의 같은 사례에는 모든 해당 대안을 적용한다. 다른 층의 값은 같은 실험의 기준값으로 재사용하지 않는다.**

| 항목 | TEXT: 대화와 과거 문서 이력 | VOICE: 화면과 발화 지칭 |
| --- | --- | --- |
| Profile ID | `TEXT-HISTORY-SYN-1.0` | `VOICE-SCREEN-CPU-SYN-1.0` |
| 부모 dataset | `COMMON-QA-SYN-1.0` | `DP3-GROUNDING-CPU-SYN-1.0` |
| 같은 입력 | 12군 × 10에피소드, 에피소드마다 2입력 | 6군 × 20평가 음성 입력, 입력마다 새 목표 |
| QA01 / QA07 분모 | 240 / 240 | 120 / 120 |
| QA02 분모 | 250표현 | 120표현 |
| QA03 분모 | 180목표 | 120목표 |
| QA04 | 동일 C01~C06 한 벌 | 동일 C01~C06 한 벌 |
| 준비 | REL의 요청 전 관계 생산과 종료 후 갱신. 별도 사용자 입력을 추가하지 않음 | S3/S4/S5 이전의 사용자 활동 각 20개, 총 60개 |
| 모델 시간 | 0.16 + 입력/3500 + 출력/160초 | 0.20 + (text+image-equivalent)/6000 + 출력/80초 |
| 공통 로컬 기반 | 238 MB | 560 MB = core/UI 180 + ASR/audio 220 + 압축 원본 96 + 요청/이력 64 |

시나리오 은행은 총 240개의 사례 묶음을 식별하지만 **하나의 구성에 360입력, 370표현, 300목표를 모두 적용한 결과는 없다.** 7구성에 저장된 응답 1,200행도 독립 사용자나 실제 모델 실행 횟수가 아니다. Text 기준 구성 한 벌을 DP2와 DP5 표에서 참조하며 복제 표본으로 세지 않는다. Voice 준비 60개는 평가 120개의 분모에 들어가지 않는다.

## 2. QA별 같은 의미와 사건 대응

| QA | 공통 의미와 집계 | TEXT 대응 | VOICE 대응 |
| --- | --- | --- | --- |
| QA01 첫 응답 지연시간 | 입력 완료 사건부터 최초 구체적 채택 내용 표시까지, 입력별 평균 | Text 제출 → 첫 표시 | 실제 발화 종료에 대응하는 가상 사건 → 첫 표시. 종료 후 0.30초 잔여 전사 포함 |
| QA02 지칭 대상 식별 정확도 | 표현/revision의 최초 채택 집합과 정답 집합 완전 일치율 | 250표현의 source/revision/extent 집합 | 120표현의 source에 결합된 객체 집합. 표현 안의 대상 수가 분모가 아님 |
| QA03 VIA 처리시간 | 원래 목표부터 마지막 revision의 공통 완료점까지 VIA 인과 경로 평균 | 정정 전 처리와 유지되는 별도 목표 포함 | 120개 신규 목표. 첫 안내 뒤 인계, 최종 상세 결과와 전체 음성 준비 포함 |
| QA04 변경 범위 | 동일 독립 변경 과제별 예상 운영 Rust 모듈 수 평균 | 실행/관계 구조의 C01~06 | grounding 구조의 C01~06 |
| QA05 모델 사용 비용 | 준비, 갱신과 미사용 작업을 포함한 VIA 활동 묶음의 비용 합계 | USD/120에피소드와 관계 준비 및 갱신 | USD/120평가입력+60준비활동 |
| QA06 최대 로컬 RAM | 같은 시각에 생존하는 소유 상태 합계 중 최고값 | episode 시점별 전체 상태 | 준비와 평가 stage별 전체 상태 |
| QA07 요청 의미 해석 정확도 | 입력/revision의 필수 의미 전체가 최초 확정에 모두 맞는 비율 | 대상, 조건, 목표 관계, 내용 출처 등 | 대상, 업무, 제외 조건, 기존 업무 보존, 필요한 경우 동일 객체 중복 제거 |

첫 표시가 틀려도 QA01은 그 시간을 남긴다. 접수 인사는 제외하며 이후 정답 시각으로 소급 교체하지 않는다. 두 층 모두 표시 사건을 작성한 것이며 화면 계측값이 아니다. Voice의 발화 중 ASR 연산 전체를 종료 이후 시간에 다시 더하지 않는다. Text에 0.30초만 더해 Voice 결과를 만들지도 않는다.

QA02 adapter는 순서에 무관한 집합 비교를 사용한다. DP3 원본의 list 비교를 공통 규칙으로 다시 판정했으며 현재 행의 성공 수는 같았다. QA07은 항목별 정확도의 평균이 아니라 입력 하나의 전체 일치다. 같은 대상 오류 때문에 QA02와 QA07이 함께 달라질 수 있으며 두 독립 품질 효과로 더하지 않는다. 인계 이후 누락과 외부 Agent 업무의 정확성은 두 QA에서 제외한다.

Text에는 첫 부분 안내 뒤 최종 의미가 확정되는 행이 있다. 원장의 첫 표시와 전체 의미 확정 시각을 분리한다. Voice 원본은 `adopt_display` stage 안에서 채택과 표시를 함께 다루므로 정확한 채택 순간을 새로 만들어 넣지 않는다. 그 stage의 구간과 최초 확정 내용을 보존한다.

## 3. 목표 시간과 실패 처리

시간 원장의 선행 의존을 따라 `finish(node)=max(finish(parent))+duration(node)`를 계산한다. 외부 Agent 업무, 사용자 답변 대기와 순수 오디오 재생 대기는 0으로 투영하고 VIA 처리와 자원 순서는 보존한다. Text의 새 목표에서는 목표 시작 이전 작업을 잘라내고, 같은 목표의 정정은 최초 입력의 시작점을 유지한다.

Voice의 현재 단일 경로에서는 QA03이 QA01+2.5166667초가 된다. 이는 인계 0.15, 결과 연결 0.10, 상세/요약 의미 호출 1.8666667, 전체 음성 준비 0.35, UI 0.05초에서 나온 값이다. 외부 Agent 8초를 제외한다. adapter는 상수를 붙이지 않고 DAG로 다시 확인한다. 회수 stage가 인계와 겹치면 직렬로 더하지 않는다. 이 상수를 Text의 정정, 직접 답변이나 여러 목표에 적용하지 않는다.

현재 모든 행에 작성된 첫 표시와 terminal이 있다. terminal은 작성한 채택 결과대로 처리가 끝났다는 뜻이다. `terminal_content_correct`와 오류 수를 따로 보존하므로 잘못된 요청을 빠르게 처리한 행이 의미상 성공으로 바뀌지 않는다. 미관측 행이 생기면 `null`과 예정 분모를 유지하고 임의 벌점 시간을 넣거나 성공 행만 평균내지 않는다.

## 4. 비용, 변경과 메모리

공통 가상 요율은 text 입력 $1/M, 출력 $4/M, 음성 생성 $0.002/초다. Voice에는 image-equivalent 입력 $1/M와 공통 음성 처리 $0.001/초가 추가된다. 이는 provider 청구서나 실제 tokenizer가 아니다. Local ASR, UI/OCR, SAM의 연산을 cloud API 요금으로 다시 청구하지 않는다. CPU와 RAM 부담은 시간과 메모리에 나타난다. 수신 Agent 비용은 QA05 밖의 별도 열이다.

Voice의 60준비활동은 warm 상태의 원인과 비용을 드러내기 위해 포함한다. 현재 평가 clip을 미리 읽은 것으로 처리하지 않는다. 준비의 응답 정확도와 완료시간은 120평가의 대표 분모 밖에 있으며, 그 180활동 전체의 정확도나 시간 결과를 주장하지 않는다. Text 관계 생산도 준비 비용을 포함하지만 동일한 60활동으로 환산하지 않는다.

QA04의 6과제를 두 층에서 12과제로 합치지 않는다. 기존 예상 모듈 목록을 각 구성에서 다시 세고 같은 완료 조건을 연결한다. `concept::` 식별자는 설계상의 소유 경계로 실제 Rust diff가 아니다. 후보 의존 무효화와 관계 의존 무효화를 동시에 가진 새 구성에서는 공통 권한 guard와 중복 소유를 다시 판정해야 하며 현재 2.00+2.00 같은 계산은 허용하지 않는다.

QA06은 decimal MB다. stage 행이 전체 RAM snapshot이면 겹치는 행을 합하지 않는다. 각 행의 소유 성분 합과 전체 최고값을 확인한다. Text 기반 238 MB와 Voice 기반 560 MB가 같은 제품 상태라는 근거는 없으므로 서로 빼거나 더해 DP3의 순수 추가 RAM으로 쓰지 않는다. DP3 내부 A→R2의 1,782 MB 차이는 같은 Voice 기반 위의 차이라 해석할 수 있다. 512 MB 제한은 이번 Voice 탐색에서 유보했으며 저장소의 기존 요구를 변경한 것이 아니다.

## 5. 집계와 우선순위

대표값은 층과 구성을 반드시 함께 표시한다. QA01/03 산술평균, QA02/07 해당 단위의 비율, QA04 6과제 평균, QA05 전체 해당 활동 비용, QA06 최고값을 사용한다. Text/Voice 평균을 50:50으로 합하거나 다른 DP의 절대값을 성능 순위로 정렬하지 않는다. 전체 시스템 값, 교차 조합과 interaction은 이 판본에 없다.

기존 QA01→QA02→QA03→QA04→QA05→QA06 순서로 각 비교의 조건부 권고를 내린다. QA07의 우선순위, 목표와 점수는 아직 정하지 않는다. 새 원값에 COMMON-28 비용 목표나 기존 점수표를 적용하지 않는다. 합성 오류 빈도는 작성한 가정이므로 통계적 유의성이나 모델 정확도의 실증 근거로 제시하지 않는다.
