## 품질 관심사와 현재 QA의 누락 점검

근거: [품질 모델](../../08-quality-attributes/quality-model.md), [ASR 계약](../../08-quality-attributes/core-asr-contract.md), [ISO/IEC 25010:2023 대응 근거](../../08-quality-attributes/iso-25010-quality-basis.md). 아래는 **현재 관심사의 문제 연결**이다. 후보별 ASR 적용 판정이나 새 QA 선정은 아니다. ISO 품질 충돌·시나리오는 3단계에서 구체화한다.

| 관심사 | 대표 연결 문제 | 현재 QA에서 보존할 의미 |
| --- | --- | --- |
| QC-01 사용자 응답성 | P-04·07·08·09·14 | QA-01/02/03/05→QA-09; QA-04 끼어들기는 별도 회귀 |
| QC-02 요청 정확성 | P-01~12 | QA-11/12→QA-19 의미/처리 field; 인식률·검색률만으로 대체하지 않음 |
| QC-03 대화·업무 연속성 | P-06·09·10·13 | QA-13~15 회귀와 QA-31/32 fault 근거; 독립 점수로 중복 합산 금지 |
| QC-04 Agent 상호연동·대체 | P-07·15 | QA-21/29 변화 후 업무·계약 의미 보존 |
| QC-05 진화·유지보수 | P-15·16 | QA-22/23/29 실제 수정 범위; 박스 개수 아님 |
| QC-06 자원·배치 | P-14·15 | QA-41은 메모리 진단; CPU/에너지/디스크도 관심사지만 같은 QA 값으로 합치지 않음 |
| QC-07 동시성·용량 | P-05·06·09·14 | 독립 QA ID가 없어도 관련 workload 조건을 빠뜨리지 않음 |
| QC-08 신뢰성·복구 | P-07·08·13·14 | QA-14/31/32·QA-39; 영향 제한·정확한 복구·기한·중복 방지·근거 조건 |
| QC-09 정보 보호·실행 통제 | P-06·08·11·12·13·16 | QA-51과 필수 접근/Action 규칙; 모든 요청 차단은 기능 충족 아님 |
| QC-10 관측·평가 근거 | P-16·15 | QA-23/61/62. 실행 재구성과 평가 재계산은 다른 완료 조건 |

현재 QA 관리 분류를 ISO 특성명으로 바꿔 부르지 않는다. 예컨대 QA-41의 메모리는 Resource utilization의 관찰 대상이고, QA-61/62는 각각 Analysability/Testability를 지원한다. QA-51은 Confidentiality에 연결한다. 자체 safety qualification이라는 이름만으로 ISO Safety를 평가한다고 하지 않는다. 이 단계에서는 기존 4 ASR·우선순위·metric·QA-41의 진단 지위를 유지한다.

| 기억 삭제/권한 철회 + 늦은 요약·모델 결과·복구 | P-11·12·13 | 파생 맥락에서 금지/삭제한 자료가 다시 사용되지 않음 |

이 23개는 모든 사건 조합을 망라하는 시험 목록이 아니다. UC의 단일 흐름만으로 묻히는 주요 경계를 점검한 것이다. 발생 확률·workload·deadline·시험 fixture는 정의하거나 실행하지 않았다.
