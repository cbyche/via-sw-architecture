# DP52 음성 대화 기반 다중 업무 세션 관리 구조

2026-10-23 / 구현 수준 설계 탐색 v1 / 사용자 검토용 / 대안 미선택

사용자가 thread를 고르지 않고 출장과 발표자료 업무를 번갈아 말할 때, **업무 미정 입력을 보관하고 판단 당시의 상태를 검증한 뒤 올바른 업무와 실행에 한 번 적용하는 구조**를 검토한다. 의미 판단 모델이 올바른 결과를 주어도 남는 상태 소유권, 원자성, 비동기 전달과 복구가 중심이다.

DP52는 사용자가 새로 지정한 주제 번호다. 기존 DP2 또는 DP44의 번호 변경이나 승계가 아니다. 기존 모델 실행 대안은 참고하며 이번 구현의 분해와 결론을 고정하지 않는다.

## 현재 판단

한 PC에서 연결과 업무 상태를 짧은 저장 트랜잭션으로 함께 확정하는 구현을 우선 상세화할 근거가 있다. 업무별 상태 소유자에게 영속 ticket을 넘기는 구현도 실행 가능한 구조지만, 추가 전달 및 복구 비용을 상쇄할 정상 사용의 이득은 미확인이다. 후자를 불필요하게 직렬화하거나 전자를 긴 전역 lock으로 약화하지 않는다.

문제 분석, 두 구현 방식과 사건 추적을 포함한 첫 검토 묶음의 작성 범위는 완료했다. 이는 제품 설계 확정, 주요 DP로서의 차별화 입증, 사용자 채택, 코드 컴파일, 실제 구현 또는 측정 완료를 뜻하지 않는다. 코드 블록은 실행하지 않은 설계용 의사코드다. 성능 수치와 QA 점수는 없다.

## 작업 경계

- DP51에서 입력과 근거 참조를 받는다. 원음 및 화면 buffer 생산과 보관은 이 문서가 소유하지 않는다.
- DP53에는 확정된 Task, Execution, 요청 판본과 명령을 전달한다. 정정 후 외부 실행 중단의 상세 메커니즘은 여기서 선택하지 않는다.
- DP54에서 질문의 실제 제시 범위와 순서 증거를 받는다. 음성 출력 scheduling은 여기서 선택하지 않는다.
- DP55의 단계 실행은 업무 식별자와 적용 receipt를 사용할 수 있다. Agent 간 단계 계획은 이 문서의 중심이 아니다.
- 이 경계들은 DP52의 요구 인터페이스 제안이며 다른 세션과 합의한 계약이 아니다.

이번 작성은 이 폴더만 수정한다. 공용 README와 package manifest에 DP52 진입점을 추가하는 작업은 공용 문서 담당에게 남긴다. 기존 QA, 시나리오 모집단, 평가 수치, 그림, PPTX와 ADR는 변경하지 않는다. 기존 발표나 평가에 이 문서가 반영되어 있다고 해석하지 않는다.
