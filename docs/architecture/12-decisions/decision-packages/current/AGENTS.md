# 네 DP 패키지 작업 규칙

이 파일은 이 폴더와 하위 폴더에 적용한다. [저장소 AGENTS.md](../../../../../AGENTS.md)와 [INTENT.md](../../../../../INTENT.md)를 먼저 따른다. 사용자의 현재 명시적 지시가 우선한다. 이 파일은 과거 이력을 새로운 작업 승인이나 영구 요구로 바꾸지 않는다.

## 필수 읽기

1. [패키지 README](README.md)에서 현재 판본과 미반영 상태를 확인한다.
2. 해당 DP의 README와 설계, 연결된 상세 계약을 읽는다. DP2, DP3, DP5, DP44는 현재 사용자 번호다. 과거 분석 문서의 01~07 읽기 번호나 이전 발표 번호로 바꾸지 않는다.
3. QA가 관련되면 [QA 기준](qa/README.md), [시나리오](scenarios/README.md)와 사용하려는 [평가 계약](evaluation/README.md)을 함께 읽는다.
4. 그림은 [그림 지침](guidelines/diagram-guide.md), PPTX는 [제작 지침](presentation/PPTX-GUIDE.md)을 반드시 읽는다.
5. [변경 영향과 동기화](guidelines/change-and-sync.md)에 따라 수정할 자료와 보존할 기록을 정한다.

## 정본과 편집 범위

- 네 DP의 후속 편집은 이 패키지에서 한다. 이전 위치의 보존본을 동시에 수정하지 않는다.
- QA 목표, 점수와 근거도 이 패키지의 `qa/`에서 함께 검토하고 수정한다. 변경 이유, 새 판본과 적용 모집단을 기록하고 이전 판본의 결과는 유지한다.
- 현재 QA07은 QA07-REQUEST-RESPONSE-v3의 요청 해석 및 응답 적합성, QA08은 온디바이스 모델 추가 메모리다. QA07은 해석/응답 구성/실제 전달의 사례 전체 충족률 90% 이상, 32사례와 5회 반복, 응답 60초/사례 300초와 추가 관측 10초, 2%p 0~6점까지 작성자 제안으로 완성했다. 목표 미정으로 되돌리거나 사용자 승인/측정 결과로 과장하지 않는다. 이전 파싱 목표의 근거와 최초 해석 결과를 자동 승계하지 않는다. 별도 응답 QA나 DP44 설계 변경은 포함하지 않는다. 철회한 후보는 현재 목록과 설명에 포함하지 않는다. 미정 항목은 미정으로 둔다.
- 설계 예상, 합성 계산, 실제 모델 실행, 제품 관측과 사용자 채택을 구별한다. QA02와 QA07의 같은 오류를 두 개의 독립 효과로 세지 않는다.
- 2026-10-23 최신 합의는 QA01-VOICE-v2와 QA03-COMPLETION-v1이다. QA01은 사전 지정 NORMAL의 실제 첫 실질적 음성 평균 2초 이하로 채점하고 WAIT의 총 지연/차례 대기/대기 종료 후 추가 지연은 해당 DP에 별도 표시한다. QA03은 전체 필수 처리/최종 준비의 VIA 경로 평균 5초 이하로 채점한다. 우수선은 모두 1초이고 간격은 각각 0.2초/0.8초다. QA09는 독립 목록에서 제거한다.
- QA 정의 담당은 명세를 관리하고 DP-QA 담당 세션 01a15dfe-8b3c-7fe3-87ab-750cd0e2db99는 사용자 요청에 따라 사례 매핑, 원장, 계산기와 산출물을 새 판본에서 갱신한다. 확정 목표/점수는 일반 상황과 대기 상황의 분리 및 새 완료 계약을 충족한 원값에 적용한다. 과거 결과를 이름만 바꾸어 사용하지 않는다. 전달 상태는 qa/timing-measurement-contract.md를 따른다.
- 확정 데이터와 기존 PPTX, 검증 기록 및 재현 snapshot은 해당 판본 그대로 유지한다. 후속 변경은 새 판본에서 수행한다.
- `package-manifest.json`은 파일 위치와 보존 근거를 관리한다. 이관 해시가 일치한다는 사실은 최신 설계, 평가와 PPTX가 의미상 동기화되었다는 뜻이 아니다.
- 설계 변경은 본문과 편집 가능한 그림을 함께 반영한다. 발표 또는 평가에 미반영한 변경은 README와 영향표에 드러낸다.
- Reference Architecture, ADR, 다른 DP, 기존 실측 원시와 다른 작업의 파일은 이 정리 범위 밖이다.

## 2026-10-23 QA 구체화

- QA는 QA01~QA08을 유지하며 핵심 QA 개수 감소를 강제하지 않는다. QA02/QA07은 대표 비율 하나씩 별도로 유지하고 세부 유형은 qa/measurement-appendix.md에 따른다.
- QA01은 P95 없이 NORMAL 산술평균 2초와 WAIT 보조 결과를 유지한다. QA03은 전체 목표의 VIA 처리 완료 평균 5초다. 기존 시간 정의/점수 버전은 바꾸지 않는다.
- QA04-CHANGE-v4는 qa/change-scenarios.md의 Q4-C01~08에 실제 운영 모듈 기준을 적용한다. Rust/Python 등 제품 코드를 누락하지 않는다. 기존 6과제 concept 추정값을 새 값으로 재명명하지 않는다. 새 평균 3개 이하와 기존 구간은 목표 제안이며 새 관측은 없다.
- QA05는 같은 활동 묶음의 준비/폐기/재시도/후속 청구까지 포함한다. QA06은 로컬 모델 포함 전체 제품 RAM 예산이고 QA08과 더하지 않는다.
- 추가 QA 논의와 발표 개정은 이번 작업 밖이다. DP-QA 담당의 후속 문서/원장 반영 범위와 전달 상태는 qa/refinement-handoff.md에 기록한다.

## 검증과 Git

[README의 검사](README.md#완료-전-확인)를 수행하고 실제 diff를 확인한다. PPTX 수정은 native 도형, 표와 노트의 편집 가능성을 유지하고 최종 렌더를 확인한다. 링크 검사나 XML 검사를 실제 PowerPoint 렌더링으로 설명하지 않는다.

Git 운영은 상위 AGENTS의 standing instruction을 따른다. 이관 파일과 이번 작업만 stage하고 관련 검사 후 commit/push한다. 정리 요청은 모델 호출, 새 측정, 대안 채택이나 accepted ADR 변경을 승인하지 않는다.
