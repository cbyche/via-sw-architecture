# QA 공통 시나리오 통합 기록

> **보존된 COMMON-28-v1 명세:** 과거 회귀 카탈로그와 목표 도출의 모집단이다. 현재 v3의 26개 사례군으로 대체하거나 합산하지 않는다. [시나리오 진입점](../README.md)에서 두 corpus를 구별한다. 본문의 현재, 완료 상태는 원래 작성 세대의 기록이다.


> **현재 DP 비교 적용: DP-RELATED-v2 (2026-10-15).** 사용자 지시대로 [DP별 관련 사건 / 목표 / 변경 과제](../../qa/history/thought-experiment/population.md)만 A/B에 동일하게 적용한다. 아래 COMMON-28 전체 건수는 공통 입력 카탈로그와 제품 전체 회귀의 기준이다. 발표용 값은 [v2 예상값과 한 줄 이유](../../qa/history/qa-dp-thought-experiment.md)를 사용한다. QA01/03은 관련 원값의 산술평균이며 오답에 시간 벌점을 넣지 않는다. QA05는 기존 $2.55가 정의된 전체 28개 묶음 비용 단위를 유지한다.

> 2026-10-14 / COMMON-28-v1 문서 입력 작성 완료 / 실제 fixture 제작과 구현 및 측정 없음

## 1. 사용자가 지적한 문제와 완료한 수정

기존 문서는 QA01의 응답 사건 30개와 QA02의 지칭 사례 20+20개 및 QA03의 목표 12개를 각각 설계했다. QA05와 QA06에는 사용자 요청 20개와 Agent 사건 6개가 있었다. 같은 상황을 다른 QA로 관측한다는 연결이 없어 사례 수를 설명할 수 없었다. 이전 수정에서 통합 방법만 기록하고 실제 공통 목록을 작성하지 않아 두 발표 표의 측정 조건도 완성되지 않았다.

이번에는 **기능 요구에서 대표 시나리오 28개를 작성하고 각 입력과 사건 및 응답과 목표 및 정답을 식별한 뒤 수량을 산출했다.** [공통 명세](common-scenarios.md)가 읽기용 원본이고 [JSON 원장](common-scenarios.json)이 수량과 생성 표의 구조화 원본이다.

## 2. 28개를 선정한 이유

개수부터 정해 QA마다 맞춘 것이 아니다. 고정 UC의 정상 흐름과 핵심 예외에서 시작 상태 또는 입력 방식과 판단 및 완료 조건이 달라지는 에피소드를 나눴다. 직접 질의와 허용 자료 조회 2개, 화면 지칭 7개, 과거 내용 연결 6개, 업무 위임과 동시 사건 및 수명과 권한 및 선호와 실패 13개로 총 28개다.

각 S의 선정 이유와 실제 발화 및 초기 상태와 사건 시각 및 정답은 공통 명세에 있다. 고정 UC의 명명된 하위 항목 94개는 S01~S28과 기능 회귀 변형 F01~F18에 연결했다. **연결표가 있다는 사실은 실제 구현의 기능 통과를 뜻하지 않는다.** F는 별도 정량 모집단이 아니라 정해진 S의 조건을 바꿔 기능 경계를 확인하는 입력이다.

28개는 실제 이용 빈도를 대표하는 통계 표본이나 최소 필요 표본 수가 아니다. 구조 비교에 필요한 대표 에피소드 묶음이며 해당 조건의 비교 결과만 주장한다. 실행 반복은 모든 실행 QA에서 5회로 통일한다.

## 3. 전체 제품 회귀 카탈로그에서 QA별로 무엇을 세는가

| QA | 공통 입력과 적용 방식 | 관측 수량과 집계 |
| --- | --- | --- |
| QA01 첫 응답 | 전체 28개에 있는 사용자 입력 84건과 Agent 사건 36건 | 120응답 × 5회 = 600개 지연의 산술평균 |
| QA02 지칭 정확도 | 전체에서 정답 대상 집합이 지정된 표현만 관측 | 44판단 × 5회 = 220판정. 실제 모호한 입력 4건은 확인 질문 기능 검사로 유지 |
| QA03 VIA 처리시간 | 같은 입력의 사용자 목표를 묶어 완료 경로 관측 | 76목표 × 5회 = 380개 경로의 산술평균 |
| QA04 변경 범위 | 같은 공통 기능에 연결한 형식 변경 3개와 기능 추가 3개 | C01~C06의 평균 모듈 수. 관련 S 수용 검사와 전체 28개 회귀 |
| QA05 모델 비용 | 28개 전체를 한 묶음으로 수행 | 5개 묶음의 전체 비용 평균 |
| QA06 최대 RAM | QA05와 같은 실행 범위 | 5개 묶음의 모든 시점 중 동시 RAM 최고량 |
| QA07 부하 간섭 | S05/S11/S18/S19 첫 입력에 같은 Agent 사건을 겹침 | 4개 부하 조건 × 5회와 동일 입력 무부하 대조. 추가 대조 실행은 QA05/06에서 제외 |
| QA08 병행 수정 중복 | QA04의 같은 변경 집합에서 6쌍 구성 | 6개 모듈 교집합의 평균 |
| QA09 음성 전달 | 전체 응답 중 의무 음성 요약만 관측 | 109응답 × 5회 = 545개 지연의 평균. Voice OFF 4건과 중간 진행 7건 제외 |

QA별 숫자가 다른 이유는 시나리오가 다른 것이 아니라 **같은 실행에서 세는 단위와 적용 대상이 다르기 때문**이다. QA04와 QA08은 실행 속성이 아닌 개발 변경 속성이므로 변경 과제를 사용하고 수용 검사를 공통 기능에 연결한다.

## 4. 공통 실행과 대안 비교

각 S 시작은 같은 원본 이력 200턴과 완료 Task 20개 및 최대 진행 Task 5개의 snapshot으로 복원한다. 파생 결과는 무료로 제공하지 않는다. 각 S 내부의 유효 cache는 유지하며 준비와 갱신 및 폐기와 후속 비용을 포함한다. Agent 결과 시각과 사용자 후속 입력 및 음성 차례는 공통 원장의 trigger로 재생한다.

2026-10-15 사용자 정정에 따라 현재 DP 비교는 **DP-RELATED-v2의 관련 사건 / 목표 / 변경 과제**를 사용한다. 같은 DP의 A/B 입력과 반복 및 외부 조건은 같고 다른 DP 영역은 같은 주변부로 둔다. COMMON-28은 모든 기능의 공통 입력 원장과 전체 제품 회귀 기준으로 유지한다. 관련 평균을 전체 제품 평균이라고 표시하지 않으며 전체 회귀의 무관한 사례로 구조 차이를 희석하지 않는다. QA05의 총비용은 원래 $2.55 배점의 28개 묶음 단위를 유지하고 관련 의미 호출 소계도 공개한다.

첫 응답 timeout 30초, 마지막 필요 source 이후 목표 timeout 60초, 전체 source 제공 후 취소 60초와 정산 120초 규칙을 공통 명세에 기록했다. 오류 이력을 보존한다. QA01/03의 오답 시간은 그대로 평균에 포함하며 미관측에 시간 벌점을 넣지 않는다. 기능 판정과 시간 점수는 별도다.

## 5. 비용과 기존 결과 처리

입력이 바뀌었으므로 이전 $0.71을 그대로 쓰거나 요청 수로 비례 환산하지 않았다. 새 원장의 음성 입력 481초와 생성 545초 및 의미 처리 120회의 입력량을 합산해 **$2.54604 → $2.55/묶음**을 산출했다. [항목별 근거](../../qa/common-model-cost-quote.md)를 읽는다. 이것은 미실행 참조 견적이며 실제 청구가 아니다.

입력 통합 당시 남았던 QA06 목표는 이후 [사용자 지정 512 MB 시스템 요구사항](../../qa/targets-source-qa06-platform.md)으로 정했다. 계측 방법은 아직 검증하지 않았다. QA01/03 산술평균과 QA02 분모 및 QA05 비용과 QA06 최고량은 평가 입력이 바뀌었으므로 이전 결과와 직접 비교하지 않는다. 기존 문서 원본은 [archive](../../../../../../archive/qa-populations-before-common-catalog-20261014/ARCHIVE.md)에 보존했다.
