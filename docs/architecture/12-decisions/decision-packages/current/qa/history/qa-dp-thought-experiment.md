# DP-44 / 47 / 45 / 42의 QA 대응과 수치 사고 실험

> **이관한 원전 이력:** 본문의 현재·최신·실측 전·검토 완료는 원래 날짜와 대상 범위의 기록이다. 현재 네 DP의 정본 상태와 결과는 [QA 기준 안내](../README.md) 및 [공통 QA v3](../../evaluation/common-qa-v3/README.md)에서 확인한다. 이 기록을 최신 실측 또는 현재 설계 승인으로 계승하지 않는다.


> **QA-DP-THOUGHT-v2-20261015 / 작성자 사고 실험 예상치 / 미측정**
> 발표에 사용할 **4개 DP × 2개 대안 × 9개 QA의 72개 예상값과 점수**다. 각 QA 행에 구조를 보고 이해할 수 있는 **우열 이유 한 줄**을 붙였다. PoC, 모델 호출, Windows 계측은 하지 않았다. 별점은 아래 가정의 숫자를 기존 0~6점 구간에 대입한 결과다.

## 1. 이번에 바로잡은 것

**각 DP의 구조가 관여하는 사례만 평균에 넣었다.** 화면 지칭을 비교할 때 일반 질문까지 넣거나, 과거 기억을 비교할 때 공통 선호 설정까지 넣어 차이를 희석하지 않는다. 같은 DP의 A/B에는 쉬운 사례, 최초 조회, 재사용, 부분 정정과 새 관계를 똑같이 적용한다. 선택한 목표가 외부 업무와 연결되면 그 목표의 후속 처리 전체를 유지한다.

**QA01과 QA03은 산술평균이며 오답도 실제 종료 시점까지의 시간을 그대로 사용한다.** 정답 대기, timeout 대체 시간, 무한대, 실패 강제 0점은 적용하지 않는다. 내용 없는 인사와 spinner는 첫 응답에서 제외한다. 이번 점추정은 모든 평가 사건에서 내용 표시와 처리 종료가 있다는 가정이다.

**공통 시간에 몇 ms만 붙이던 계산을 처리 단계별 계산으로 바꿨다.** DP-47은 생산자 병행과 생산 완료 후 결합 및 후보 재확장, DP-45는 원본 공동 해석과 준비된 관계 조회 및 원본 변경의 갱신을 계산한다. DP-44의 짧은 비동기 배정과 DP-42의 로컬 상태 전달은 모델 추론처럼 초 단위로 늘리지 않았다. 기존 [v1과 당시 모집단 규칙](../../../../../../archive/qa-dp-thought-v1-20261015/README.md)은 보존했다.

각 비교에서 나머지 세 DP는 A로 고정한다. **DP마다 관련 모집단이 다르므로 네 A의 평균도 달라진다.** A가 선택된 구조라는 뜻이 아니며 서로 다른 DP의 숫자를 직접 순위화하거나 네 B의 개선량을 더하지 않는다.

## 4. 구조에서 숫자를 도출한 가정

- **공통 모델 계산:** 호출 고정 지연 140ms + 입력 1,000토큰당 10ms + 출력 토큰당 2ms. 일반 현재 응답의 첫 내용은 48토큰, 원본 이력의 의미 관계와 현재 요청을 함께 푸는 호출은 500토큰 뒤로 예상했다. 화면 지칭은 최종 GroundingProposal의 64~96토큰 전체를 마치고 채택한 뒤 비교 대상과 처리 범위 같은 구체적 Request 카드 내용을 표시한다. 내부 proposal 조각이나 단순 접수 인사를 먼저 보여주는 가정이 아니다. 이후 상세 설명의 공통 650토큰 호출도 QA03/05에 포함한다. 중간 후보는 전체 출력이 끝나야 다음 호출이 쓴다. 모두 작성자 시간 예산이며 실제 모델 속도 자료가 아니다.
- **공통 입력과 출력:** Voice 종료 처리 180ms, Text 15ms, Agent source 전달 20ms와 채택 / UI 70ms. S05는 원본 시나리오대로 마지막 전사가 300ms 뒤 도착한다. 화면 해석 B의 독립 화면 생산은 발화 해석과 병행하며 가능한 선행 180ms를 인정했다. 전체 요약 준비 900ms와 QA09의 첫 음성 300ms를 구별했다.
- **DP-47:** native 선택은 별도 학습 생산을 강제하지 않고, 유효한 부분 후보는 재사용한다. 복잡한 신규 입력은 말 / 화면 생산을 병행한 뒤 결합한다. 세 원본 확장 사례는 A의 bounded 재판단과 B의 producer 재생산 / 재결합을 모두 센다. 같은 최종 원본 접근 권한을 유지한다.
- **DP-45:** 명시적인 Task / 전달 관계와 유효 cache는 A도 즉시 읽는다. 원본 이력의 의미 관계가 필요한 경우 A는 현재 요청과 한 모델 호출로 공동 해석한다. B는 사전에 게시한 관계를 읽고 원본을 확인한다. S11-U03의 새 비용 / 일정 비교는 양안 모두 현재 요청에서 원본으로 판단하며 B에 임의 관계 타입 생산을 강제하지 않는다. S12의 원본 변경은 입력 2초 전에 제공되므로 B의 의미 관계 갱신을 미리 마칠 수 있다. 서로 다른 선행 조건을 같은 추가 지연으로 처리하지 않았다.
- **준비 비용:** 원본 200턴, 완료 Task 20개, 진행 Task 최대 5개를 각 S마다 복원한다. B45의 초기 2회 생산은 2.56초로 5초 준비 구간 안에 끝나는 가정이며, 28번의 초기 준비와 S12의 의미 관계 갱신을 모두 청구한다. 이 초기 2회는 200턴 중 명시 ID만으로 만들 수 없는 EXPLAINS_ITEM의 batch 생산 가정이다. Task ID와 실제 전달 receipt로 명시되는 관계는 코드로 갱신하고 별도 모델 호출을 부과하지 않는다. 반복 조회가 길어져 준비비를 나누면 비용 우열이 달라질 수 있다.
- **정확도:** native, 신규 교차 지칭, 후보 확장, 부분 정정, 명시 관계, cache, 의미 관계별로 정답 확률을 따로 예상했다. B47의 부분 정정 보존 이익도 남기며 전체 오류 수를 맞추기 위해 오답을 한 건씩 교환하지 않았다. 확률 자체는 작성자 판단이며 구조만으로 97.85% 같은 확률을 증명한 것은 아니다.
- **변경 범위:** 실제 구현이 없는 단계이므로 `DESIGN_CHANGE_REVIEW`다. C04는 전체 결과 교체에서 section별 교체로, C06은 전체 source 철회에서 일부 extent 철회로 확장하는 조건이다. 변경 전 요구에 없는 새 세분화의 payload / 상태 전이 / 보존 규칙을 고치는 모듈을 센다. 기존 코드가 이미 같은 기능을 제공하면 해당 모듈은 0개로 수정해야 한다.
- **RAM:** 공통 UI / runtime / 원본 cache는 한 번만 세고 B가 추가 소유하는 후보, 관계 저장 페이지 또는 서비스 private heap만 더한다. 원본 화면 15장을 생산자별로 복제하거나 클라우드 가중치를 PC RAM에 넣지 않는다.

[계산 원장](thought-experiment/calculation-ledger.md)은 사건과 목표별 시간, 지칭별 예상 정확도, 계획 모듈 집합과 교집합, 호출별 토큰 비용과 동시 RAM 구성을 공개한다. [가정 JSON](thought-experiment/assumptions.json)을 수정하면 [문서 계산기](../../../../../../../scripts/architecture/qa_dp_thought_experiment.py)가 [예측 JSON](thought-experiment/predictions.json)과 아래 표를 재생성한다. 목표 내부의 병렬 작업은 max 경로, 목표 간 대표값은 평균이다. 오답 여부는 시간 계산에 관여하지 않는다.

## 6. 심사에서 수치와 함께 설명할 범위

**DP-47은 생산 후 결합이라는 의존 경로, DP-45는 미리 만든 관계를 읽는 이익과 그 준비 비용을 설명한다. DP-44는 실행 연결의 변경 파급, DP-42는 서비스 간 계약의 변경 파급과 추가 메모리가 이번 수치의 주요 차이다.** 44와 42의 정상 응답시간까지 큰 차이라고 말할 근거는 아직 없다. 관련 없는 사례를 빼는 것과 구조에 없는 비용을 만들어 넣는 것은 다르다.

시간 예산이나 이력 판단량이 달라지면 점수도 변한다. 예를 들어 A45가 새 의미 관계도 48토큰 안에서 바로 해결하면 B45의 응답 이익이 줄어든다. B47의 후보가 입력 전에 충분히 준비되거나 producer 모델이 훨씬 작고 빠르면 A47의 이익이 줄어든다. native / 부분 재사용의 작은 차이는 그대로 원장에 남겼다. 두 안이 공통 모델 슬롯을 거의 경합하지 않으면 QA07 차이도 작아진다.

따라서 발표의 표제는 **“동일 관련 시나리오에 대한 구조 기반 예상값”**으로 사용한다. “실측 결과”, “검증된 정확도”, “목표 달성 실적”으로 바꾸지 않는다. 특히 QA04/08은 예정 Rust 모듈의 영향 분석이다. 전체 9 QA 중 관련 구조가 같은 항목은 같은 점수로 남겼다. [작성자 검토 기록](../reviews/thought-experiment-review-20261015.md)에 검산 범위와 한계를 기록했다.
