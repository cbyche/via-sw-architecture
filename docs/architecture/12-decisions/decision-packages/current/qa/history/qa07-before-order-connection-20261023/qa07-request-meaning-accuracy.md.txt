# QA07 요청 해석 및 응답 적합성

> **2026-10-23 사용자 합의:** QA02와 QA07을 각각 별도 QA로 유지한다. 대표값은 **요청 처리 사례별 해석/응답 전체 충족률 하나**이며 단계별 정확도 평균으로 바꾸지 않는다. 사례 종류와 실패 원인은 [부록](measurement-appendix.md#3-qa02와-qa07-별도-대표값-유지)에 둔다. 최종 통합 여부는 이후 판단하며 핵심 QA 개수 제한 때문에 합치지 않는다. 사용자의 후속 구체화 지시에 따라 목표 90% 이상, 32사례와 5회 반복, 종료 기한 및 점수표까지 아래에 완성했다. 새 숫자와 평가 구성은 작성자 제안이며 사용자 채택과 실측 결과를 뜻하지 않는다.

2026-10-23 / `QA07-REQUEST-RESPONSE-v3` / `AUTHOR_DEFINED_COMPLETE` / **목표와 평가 절차 제안 완료 / 미측정**

별도의 응답 적합성 QA를 신설하지 않고 QA07에 통합한다. 최초 요청 의미의 정확성에 더해 후속 응답이 해당 요청과 전달 시점의 상황에 맞게 구성되고 실제로 전달됐는지 평가한다. 문서 경로는 기존 링크 호환을 위해 유지한다.

## 1. 정의와 단일 지표

**시스템은 사용자 요청을 정확하게 해석하고 유효한 요청과 상황에 맞는 응답을 실제 전달하는 비율을 최대화해야 한다.**

- **목표 지표:** 요청 처리 사례 전체 충족률 90% 이상. 전체 충족률 = 모든 해석과 응답 의무를 만족한 사례 반복 수 / 전체 사례 반복 수 × 100.
- **측정 조건:** 8개 유형의 32사례를 동일 조건에서 각각 5회 실행한다. 최초 입력부터 마지막 필수 응답과 이후 10초까지 확인한다. 최초 해석, 응답 구성, 실제 전달 중 하나라도 틀리면 해당 사례 반복은 실패다.
- **목표 근거:** Park 외의 한국어 목적 지향 대화 연구가 보고한 대화 성공률 약 90%를 수치 참조로 삼아 VIA의 개발 목표를 90% 이상으로 정한다. VIA는 중간 해석 오류와 전달 오류까지 실패에 포함한다. [Sensors 2018, §6.1.2, Table 3](https://pmc.ncbi.nlm.nih.gov/articles/PMC5982658/), [TD-EVAL, SIGDIAL 2025](https://aclanthology.org/2025.sigdial-1.7/). 상세 도출과 표본 구성은 [근거 문서](research-notes/qa07-meaning-research.md)를 따른다.

## 2. 평가하는 의미와 응답 의무

### 2.1 정답에 포함할 의미

입력과 허용된 문맥에서 요구하는 항목을 실행 전에 지정한다. 모든 입력에 모든 항목이 나타나는 것은 아니다. 아래 표현은 평가에서 확인할 의미이며 특정 내부 JSON이나 새로운 Component를 강제하지 않는다.

[저장소 용어](../../../../02-terms.md)에 따라 **사용자 입력(User Turn)**은 한 번의 발화 또는 Text 전송, **사용자 요청(User Request)**은 그 입력에 담긴 질문이나 지시, **VIA Request**는 이를 처리하도록 구분한 논리 단위, **VIA Task**는 여러 요청에 걸쳐 지속적으로 추적하는 사용자 업무 목표다. 아래에서 요청한 처리를 막연히 “작업”이라 부르거나 모든 요청을 VIA Task라고 부르지 않는다.

| 사용할 명칭 | 정확히 판정할 내용 | 예와 판정 경계 |
| --- | --- | --- |
| **요청한 처리** | 각 사용자 요청이 요구하는 행위와 산출물. 설명/비교/조회/파일 작성/수정/취소/승인/거부 등을 구별 | “두 견적을 비교”는 비교 요청. 각각 요약하는 것으로 바꾸면 오류. 이를 수행할 도구나 도메인 계획은 평가 밖 |
| **처리 대상과 적용 범위** | 처리를 적용할 자료/항목의 식별자, 필요한 판본, 문서 구간/셀 범위/대상 집합과 역할 | “이 두 견적”은 Q1/Q2, “이 문단만”은 지정 문단 범위. 원본과 비교본의 역할도 보존. 사용자 입력에서 대상이 새 결과물이라면 생성할 결과물 종류/이름을 판정하며 존재하지 않는 파일 ID는 요구하지 않음 |
| **요청의 제한사항** | 사용할 자료, 계산/비교 기준, 포함/제외, 기간/금액/수량, 출력 형식과 전달 허용 범위를 제한하는 명시 내용 또는 유효한 문맥상 요구 | “설치비 제외”, “본문만 사용”, “두 장의 PDF”, “외부 전달 금지”. 실제 접근 차단/송신 성공과는 구별 |
| **실행 순서, 결과 의존과 실행 조건** | 여러 요청을 독립적으로 처리할 수 있는지, 어느 요청 뒤에 수행하는지, 앞 요청 결과가 다음 입력인지, 어떤 조건에서만 실행하는지 | “만든 뒤 이름 변경”은 선후 관계. “검색 결과로 요약 작성”은 데이터 의존. “계약서가 있으면 요약”은 조건부 실행. Agent가 스스로 세우는 도구 실행 순서가 아님 |
| **이전 요청/응답 또는 VIA Task와의 연결** | 어느 이전 요청, 실제 전달 응답이나 Task를 참조하는지 식별하고, 후속 질문/수정/상태 조회/취소/유지인지 또는 독립된 새 요청인지 구별 | “아까 설명의 두 번째 항목”은 이전 응답 참조이고 Task가 없어도 됨. “그 보고서만 취소”는 기존 보고서 Task 식별과 취소. “그 결과로 새 발표 작성”은 기존 결과를 참조하는 새 업무 |
| **정정할 내용과 유지할 내용** | 정정 발화가 앞서 확정된 요청의 어느 내용을 바꾸며 무엇을 그대로 두는지 | “납기만 다시 비교하고 설치비 제외는 유지”는 비교 항목 변경과 제외 기준 유지. 별도 업무의 취소로 확장하지 않음 |
| **사용자가 지정한 수행자와 수신자** | 사용자가 명시한 Agent 또는 결과를 받을 사람/채널의 식별과 역할 | “그 자료를 만든 Agent에게 맡겨”의 작성 Agent, “민수에게 보내”의 수신자. 지정이 없을 때의 자동 Agent 추천 우열은 평가 밖 |

“조건” 한 단어에 제한사항과 실행 조건을 섞지 않는다. **“설치비 제외”는 비교 기준의 제한사항, “계약서가 있을 때만 실행”은 실행 조건**이다. “결론을 먼저 보여줘”는 결과의 표시 형식이고 “파일을 만든 다음 발송”은 실행 순서다. 한 문장이 여러 항목을 동시에 지정할 수 있으며 이 분류를 독립 점수로 합산하지 않는다.

예를 들어 “아까 두 견적을 설치비는 제외하고 비교해줘. 보고서 작성은 계속하고.”의 정답은 다음과 같다.

- 비교 요청: 이전 대화에서 지정한 견적 Q1/Q2를 비교하고, 비교 금액에서 설치비를 제외한다.
- 유지 지시: 현재 작성 중인 보고서의 VIA Task T-report를 식별하고 그 업무를 취소하거나 변경하지 않는다.
- 두 지시의 관계: 보고서 완료를 비교의 선행조건으로 요구하지 않는다. 이 입력에는 실행 순서를 새로 지정한 내용이 없다.

따라서 “다섯 단어에 해당하는 값이 들어 있다”가 아니라 **입력이 요구한 위 의미를 전부 맞혔는가**를 판정한다.

### 2.2 응답 구성의 적합성

평가자는 사례 실행 전에 응답 의무와 허용 가능한 표현/행동을 정한다. 내부 구조나 특정 문장을 강제하지 않으며 표현의 자연스러움만으로 합격/실패를 정하지 않는다.

| 판정 항목 | 확인할 내용 | 실패 예 |
| --- | --- | --- |
| 요청과의 대응 | 어느 입력/요청/Task에 대한 설명, 질문, 진행, 결과, 취소 안내인지 정확함 | 보고서 결과를 메일 발송 결과로 설명 |
| 유효 판본과 상태 | 사용자가 바꾼 내용, 취소/거부/응답 완료, 실제 확인된 Agent 상태를 반영 | 이미 답한 질문을 새 확인 질문으로 채택 |
| 필요한 내용 | 요청한 답변 범위, 유지 조건, 필수 고지와 결과 참조를 보존 | 설치비 제외 요청을 채택했지만 포함 비교로 설명 |
| 사실과 출처의 일치 | VIA가 받은 근거/Agent 사건의 상태와 응답 주장이 일치 | Agent가 접수만 했는데 작업 완료라고 안내 |
| 전달 방식 | 유효한 채널, 수신 대상, 상세 화면/음성 요약의 역할과 허용 범위에 맞음 | 화면에만 보여 달라는 정보를 음성 응답으로 채택 |
| 취소/대체/병합 | 사전 정책상 불필요해진 질문/응답을 폐기하거나 유효 내용으로 대체 | 취소된 질문을 재개할 대상으로 구성 |

필수 의미를 보존하는 요약과 동의 표현은 허용한다. 기분, 취향, 모든 세상 지식의 정확성을 통째로 판정하지 않는다. 응답의 요청 대응과 제공 근거에 대한 충실성은 포함하되 Downstream Agent의 도메인 추론/산출물 품질 자체는 평가 밖이다. Agent가 실패했다면 확인된 실패와 허용된 후속 행동을 정확히 알리는 것이 성공 조건이 될 수 있다.

### 2.3 실제 전달의 적합성

응답 생성/채택과 실제 화면 표시/음성 출력의 증거를 구별한다. 각 필수 채널에서 대응 내용/범위, 판본과 수신 대상을 확인한다. 합의된 기능 계약상 화면과 음성 모두 필수면 둘 다 확인한다. 전송 큐에 넣었다는 기록만으로 실제 전달 성공을 인정하지 않는다.

- 채택 시 맞았지만 차례 대기 중 요청이 취소됐다면 새로 시작하는 출력은 취소 이후 상태에 맞아야 한다.
- 취소 이전에 정당하게 전달된 내용은 이후 취소를 근거로 소급 실패시키지 않는다. 이후의 재전달/재개/중복과 갱신 의무를 판정한다.
- 이미 재생 중일 때 취소가 들어온 경계는 취소 정보의 수신/가용 시각과 출력 구간을 연결한다. 현재 대표 시험은 [32사례와 사건 순서](qa07-evaluation-cases.md)의 명시적 대기/중단 경계를 사용한다. 출력 시작 뒤 취소가 들어온 경우 이미 출력된 내용은 소급 오답으로 바꾸지 않으며, 취소 이후 새로 시작하거나 재개한 무효 내용은 실패다. 중단 장치의 잔여 버퍼를 새 발화로 세지 않고 실제 재생 구간과 원인을 기록한다. 물리적 중단 지연은 별도 시간 진단이다.
- 취소/대체로 전달 의무가 사라졌다면 정상 폐기가 성공일 수 있다. 모든 필수 응답을 안 하는 방식은 성공이 아니다.
- 필수 출력 누락, 다른 채널/수신자, 잘못된 재개 위치, 중복 질문과 금지된 과거 판본 출력은 실제 전달 실패로 기록한다.

정보 기준은 판정 시점까지 공통 계약상 VIA에 제공 가능했던 사건과 유효한 권한/요청 판본이다. 아직 도착할 수 없었던 미래 사건을 정답으로 요구하지 않는다. 반대로 내부 처리가 늦었다는 이유로 이미 제공 가능했던 취소를 무시할 수 없다. 시험에서는 제어 입력 뒤 음성 차례를 10초 더 막은 후 열어 취소/정정과 새 출력의 순서를 명확히 한다. 내부 전파가 늦어 구판 응답을 새로 출력한 경우는 실패다.

## 3. 요청 처리 사례와 분모

`case_id` 하나에 시작 사용자 입력과 관련 후속 입력/Agent 사건/응답 의무를 등록한다. 사례는 [Q7-C01~32](qa07-evaluation-cases.md)로 정했다. 기존 입력 수를 새 사례 수로 그대로 쓰지 않는다.

1. 한 시작 입력에 여러 요청이 함께 있으면 한 사례로 묶고 요청들 및 관계의 필수 조건을 모두 확인한다. 후보가 VIA Request나 응답을 쪼개도 분모는 늘지 않는다.
2. 같은 요청의 정정, 명확화 답변, 승인/거부, 취소와 응답 재개는 같은 사례에 연결한다. 각 revision의 최초 해석은 개별 checkpoint로 보존하되 성공/실패는 사례당 한 번이다.
3. 독립된 새 요청은 별도 사례다. 과거 결과를 참고한다는 이유만으로 기존 사례와 합치지 않는다. 공유 문맥과 영향을 주는 사건은 링크로 연결한다.
4. Agent의 진행/질문/결과/실패/취소 사건은 관련 요청에 연결하며 그 자체로 분모를 늘리지 않는다. 기존 Task의 비동기 통지만 평가할 때는 사전 등록한 시작 요청과 그 정확한 최초 해석 증거를 연결해야 한다. 그 증거가 없으면 전달 단계 진단만 가능하고 QA07 전체 성공으로 세지 않는다.
5. 출력 chunk, 내부 호출, 검색/재시도, 모델 후보 수와 원인 태그 수는 분모가 아니다. 반복은 별도 repeat_id로 지정하되 동일 실행 증거를 다른 DP에서 재사용했다고 독립 표본을 추가하지 않는다.
6. 공동 응답의 필수 의미 구간은 `obligation_id`로 각 요청에 연결한다. 같은 의무를 여러 사례에 복제하지 않는다. 하나의 전달 사고가 여러 요청의 서로 다른 의무를 위반했다면 각 요청 사례가 실패할 수 있으나, 원인 사건은 하나로 기록하고 독립적인 여러 개선 효과로 부풀리지 않는다.

QA01의 NORMAL/WAIT는 QA07의 분모를 나누는 기준이 아니다. 요청과 응답의 정확성을 평가하는 동일한 원칙으로 둘 다 포함할 수 있으며 비중과 사례 구성을 먼저 고정한다.

## 4. 최초 확정, 후속 정정과 관찰 종료

### 4.1 최초 확정의 보존

채택 책임자가 실제 처리 기준으로 수용한 의미/응답을 관측한다. 명시 commit보다 먼저 사용자에게 확정 내용으로 보이거나 실행 경로에 사용했다면 그 사용 시각이 최초 확정이다. 내부 이름이 임시라도 실제 사용을 감추지 않는다.

확정 전 후보 수정은 오류가 아니다. 부분 확정은 부분별 최초 사용과 후속 전체 확정을 연결한다. 최초로 확정한 의미나 응답이 틀렸다면 실제 출력 전에 나중에 복구했더라도 해당 단계의 오류는 유지한다. 실제로는 채택하지 않은 폐기 후보를 구성 실패로 세지 않는다.

입력 내 자기 정정은 하나의 사용자 입력 의미로 평가하되, 정정이 끝나기 전 실제 잘못 사용한 조기 확정은 남긴다. 후속 사용자 정정은 그 시점부터 새로운 유효 revision을 만든다. 이전에 맞았던 해석은 소급 오답이 아니지만 이후 응답은 새 revision을 따라야 한다. 앞선 오답을 다음 revision의 정답으로 덮어쓰지 않는다.

### 4.2 유한한 종료 계약

관측은 첫 사용자 발화의 시작 또는 Text 제출에서 시작한다. 입력 도중의 조기 확정도 포함한다. 마지막 필수 사건 이후 모든 응답의 실제 전달 또는 정상 폐기가 끝난 뒤 **10초**를 더 관측한다. 그 사이 구판 사건을 재주입해 취소한 질문과 구판 응답이 살아나지 않는지 확인한다.

응답 의무 하나의 기능적 관측 한도는 **60초**다. 시작은 해당 의무를 발생시킨 입력의 종료/사건의 제공 가능 시각과 필수 외부 정보의 도착 및 필수 채널의 전달 허용 시각 중 가장 늦은 시각이다. 내부 해석, 모델, 큐 대기는 이 한도를 늦추지 않는다. 60초 안에 필수 내용을 모두 전달하지 못하면 누락 실패다. 사례는 최초 입력 종료 후 최대 **300초**에 응답 관측을 닫고 **10초**를 추가 관측하므로 전체 종료 상한은 310초다.

60초와 300초는 무응답을 유한하게 판정하기 위한 작성자 시험 한도다. QA01의 평균 2초나 QA03의 평균 5초를 대체하지 않는다. 짧은 고정 답변, 최대 4개 응답 차례와 고정 외부 사건으로 구성한 시험에 적용하며 실제 장기 업무 완료 기한으로 확장하지 않는다. 상세 사건 트리거, 미응답 시 진행 및 판정은 [평가 계획](qa07-evaluation-plan.md)을 따른다.

## 5. 성공/실패와 대표값

```text
N = 사전 등록한 유효 case_id × repeat_id의 수
I_c = 최초 해석 checkpoint 전체 충족
C_c = 채택한 응답의 구성 의무 전체 충족
D_c = 필수 실제 전달/정상 폐기 및 금지 전달 방지 전체 충족
S_c = 1 (모든 의무 충족 입증), 0 (하나 이상의 위반 입증), 미정 (판정 증거 부족)
Q = 100 × sum(S_c) / N  [모든 사례의 S_c가 확정된 경우]
```

모든 예정 사례를 판정할 수 있을 때 Q를 확정한다. 세 단계 비율의 평균이나 곱으로 대체하지 않는다. 항목별 부분 정답 점수도 부여하지 않는다.

| 상태 | 처리 |
| --- | --- |
| 전 구간 증거와 모든 의무 충족 | PASS, 사례 성공 1 |
| 명확한 해석/구성/전달 위반이 한 번 이상 있음 | FAIL, 사례 성공 0. 이후 복구는 최초 실패를 지우지 않음 |
| 완전한 관찰로 기능 기한 내 필수 응답 누락 확인 | FAIL, 전달 누락. 실제 무응답과 계측 누락 구별 |
| 정당한 질문/거부/대체/폐기 | 사전 oracle가 허용하고 모든 후속 의무까지 충족하면 PASS |
| 실행/계측/전달 이력 부족 또는 사건 순서를 입증할 수 없음 | UNKNOWN. 임의 성공/실패나 0점으로 바꾸지 않음 |
| 공통 시험 자료 자체 무효 | 양안에 동일 기준으로 무효 처리하고 원인/영향/대체 판본 기록 |

확정 성공 S, 실패 F, 미판정 U이면 N=S+F+U를 공개한다. U가 남아 있으면 전체 정확도와 별점을 확정하지 않는다. 필요하면 `[100S/N, 100(S+U)/N]`의 가능한 충족률 범위를 진단으로 표시하며 관측 성공만 분모로 삼지 않는다. 이미 확정된 오류가 있으면 이후 trace가 부족해도 FAIL 증거를 보존하고 계측 부족을 함께 기록한다. N=0은 비적용/미산출이다.

모호한 입력은 올바른 명확화 질문과 후속 답 연결이 oracle에 정의되면 평가할 수 있다. 정답 해석을 결정할 수 없는 자료를 후보 결과를 보고 뒤늦게 제외하지 않는다. 허용되는 여러 응답 경로가 있으면 실행 전에 가능한 의미/행동을 정한다.

## 6. 원인 구분과 QA 경계

대표값은 하나이며 실패 원인은 REQUEST_INTERPRETATION, RESPONSE_COMPOSITION, ACTUAL_DELIVERY로 기록한다. 같은 원인이 여러 단계로 전파될 수 있으므로 최초 위반과 전파 결과를 연결하고 원인별 건수를 합쳐 실패 사례 수로 사용하지 않는다.

| 사례 | QA02 | 확장 QA07 |
| --- | --- | --- |
| 다른 견적을 대상으로 최초 확정 | 대상 오류 | 해석 실패. 같은 원인 ID로 연결 |
| 대상은 맞지만 설치비 제외 조건을 최초 확정에서 누락 | 대상 판정 성공 가능 | 해석 실패 |
| 최초 해석은 맞지만 완료되지 않은 업무를 완료라고 응답 채택 | 기존 대상 판정 유지 | 구성 실패 |
| 질문은 정당하게 준비됐지만 취소를 받은 뒤 실제로 다시 질문 | 기존 대상 판정 유지 | 실제 전달 실패. 새로 채택까지 했다면 구성 오류도 기록 |
| 오답을 확정한 뒤 올바른 응답으로 복구 | 최초 대상 오류가 있었다면 실패 유지 | 최초 실패 유지, 복구는 진단 |
| 취소 전에 정당하게 질문했고 취소 후 남은 질문은 폐기 | 기존 대상 판정 유지 | 다른 의무도 충족하면 성공 |
| Agent 인계 payload만 손상, 최초 해석과 사용자 응답 의무에는 영향 없음 | 대상 판정 유지 | 인계 기능 오류는 별도. 전 구간 응답 의무까지 확인 후 QA07 판정 |

QA02는 지칭 표현/revision의 최초 대상 집합 정확도이고 QA07은 요청 처리 사례 전체다. 동일 대상 오류나 개선을 두 독립 효과로 합산하지 않는다. QA01/03은 시간, QA07은 의미/응답의 적합성을 평가한다. 느리다는 이유만으로 QA07 실패로 바꾸지 않되 사전 기능 기한을 넘겨 필수 응답이 없으면 누락으로 판정한다.

## 7. 목표와 0~6점

**목표 Q ≥ 90%, `QA07-REQUEST-RESPONSE-score-v3`.** 대화 전체 성공률의 수치 참조와 중간 오류를 놓치지 않는 판정 연구를 구별하여 적용했다. 이전 TreeDST의 최초 의미 파싱 90.8%를 새 전체 충족률의 근거로 사용하지 않는다. [근거와 이전 판본 차이](research-notes/qa07-meaning-research.md)를 참조한다.

| 점수 | 표시 | 전체 충족률 Q 구간 |
| --- | --- | --- |
| 0 | ○○○ | Q < 90% |
| 1 | ◐○○ | 90% ≤ Q < 92% |
| 2 | ●○○ | 92% ≤ Q < 94% |
| 3 | ●◐○ | 94% ≤ Q < 96% |
| 4 | ●●○ | 96% ≤ Q < 98% |
| 5 | ●●◐ | 98% ≤ Q < 100% |
| 6 | ●●● | Q = 100% |

90%부터 100%까지의 10%p를 다섯 구간으로 균등 분할하여 2%p로 정한다. 6점은 등록된 160회 전부 성공한 경우다. 반올림 전 비율로 점수를 정하고 표시는 소수 둘째 자리까지 한다. 예를 들어 143/160은 89.375%로 0점, 144/160은 90%로 1점이다. 미관측은 0점이 아니며 결과와 사용자 채택은 미확정 상태로 구별한다. 점수 구간은 작성자 설계 규칙이며 논문이 검증한 임계값이 아니다.

## 8. DP 적용과 판본

| DP | 평가 가능한 경로 |
| --- | --- |
| DP2 의미 해석 실행 | 요청별 의미와 유지/정정의 최초 확정 및 후속 응답 구성 연결 |
| DP3 화면/음성 지칭 | 대상/역할/범위 해석과 그 의미를 보존한 응답. QA02 중복 원인 연결 |
| DP5 위임용 메모리 | 과거 요청/실제 전달 내용과 현재 응답의 관계 및 유효 판본 |
| DP44 음성 실행/전달 | 준비된 질문/응답의 취소, 대체, 중단/재개와 실제 출력의 현재성. 현재 설계에서 해당 경로를 관측할 때 평가하며 새 구성 책임을 가정하지 않음 |

관련성이 곧 대안 차이나 우위를 뜻하지 않는다. 이 변경으로 DP44 설계나 대안 채택, 모델 실행/측정을 승인하지 않는다. 기존 24입력, 80후보/400판정, Delivery 제어 fixture는 새 QA07 사례 수나 정확도로 재명명하지 않는다. 현재 원장/결과는 원래 판본으로 보존하며 새 적용은 이 v3와 32사례 평가 계획에 따라 새 판본으로 작성한다. 기존 24묶음에 90%만 붙여 새 계약으로 표시하지 않는다.
