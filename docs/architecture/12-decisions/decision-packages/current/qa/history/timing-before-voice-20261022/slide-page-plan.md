## 공통 편집과 판정 규칙

- 슬라이드 오른쪽 점수표는 **6점 ●●●부터 0점 ○○○ 순서**로 배치한다. 아래 표도 같은 순서다.
- 목표 충족은 1~6점이며 0점은 목표 미달이다. 실측 표에서는 미관측을 숫자 점수로 바꾸지 않는다. 현재 사고 실험 표는 예상 원값을 숫자 구간에 대입한 예상 점수이며, 사용자 지시대로 기능 실패에 시간 벌점을 적용하지 않는다.
- 모든 수치 예시는 **설명용 가상값**이다. 점수 간격은 비교 표현 규칙이며 출처가 모든 구간을 정한 것은 아니다.
- COMMON-28-v1 전체를 5회 실행하고 QA별 관측을 추출한다. QA04/08의 개발 변경과 QA07의 무부하 대조는 연결된 별도 평가다.
- 예상 DP 손익은 발표자 노트에 둔다. 실측 우열이나 최종 A/B 선택으로 표현하지 않는다.

## QA01 첫 응답 지연시간

### 화면 본문

| 분류 | Title | Scenario |
| --- | --- | --- |
| Performance | **첫 응답 지연시간** | 시스템은 사용자 요청이나 업무 사건에 대한 **구체적인 첫 응답을 신속하게 화면에 표시해야 한다.**<br>**[평균 첫 응답 지연시간 ≤ 1초]**<br>※ 측정 조건: 공통 28개 / 응답 사건 120건 × 5회 / 실제 사건 → 첫 내용 UI 표시<br>※ 목표 근거: Nielsen(1993) 사고 흐름 유지 1초와 Microsoft Windows 응답성 지침 |

**사용자가 말을 마친 뒤 이해된 내용을 빠르게 확인하고 대화를 이어가게 한다.**

- **목표 1초:** Nielsen의 사고 흐름 유지 지침과 Windows의 응답성 유지 구간 0.5~1초를 첫 내용 표시에 적용한다.
- **평균 판정:** 600개 응답의 산술평균을 사용하며 오답도 실제 시간을 포함한다.
- **측정 경계:** 실제 발화 마지막 sample / Text 제출 / Agent source 최초 제공 → 첫 완결된 내용의 실제 UI 표시 프레임. VAD와 전사 및 polling 대기를 포함한다.

**측정 산식**

```text
L = Σ(첫 완결된 내용 UI 표시 시각 − 입력 사건 시각) / 600
대상: 지정 응답 120건 × 5회 = 600건 / 단위: 초
```

**설명용 예시:** `발화 끝 0.0 → “네” 0.1 → 구체적 수행 안내 0.8 → Agent 전송 1.3 → 음성 재생 2.5초`. 이 사건의 값은 **0.8초**다. 가상 4건이 0.8 / 0.6 / 1.0 / 0.8초라면 평균 0.8초로 **2점 ●○○**. 실제 관측은 같은 공통 입력의 600건

### 점수표

| 점수 | 표시 | 기준: L [초] |
| ---: | --- | --- |
| 6 | ●●● | `0 ≤ L ≤ 0.20` |
| 5 | ●●◐ | `0.20 < L ≤ 0.36` |
| 4 | ●●○ | `0.36 < L ≤ 0.52` |
| 3 | ●◐○ | `0.52 < L ≤ 0.68` |
| 2 | ●○○ | `0.68 < L ≤ 0.84` |
| 1 | ◐○○ | `0.84 < L ≤ 1.00` |
| 0 | ○○○ | `L > 1.00` |

**구간 도출:** 목표 1.00초와 개선 수준 0.20초 사이를 (1.00−0.20)/5 = 0.16초씩 분할한다. 0.20초는 채점용 개선 수준 제안이며 인용 연구가 보장한 VIA 성능은 아니다.

**출처 각주:** [Nielsen 1993](https://www.nngroup.com/articles/response-times-3-important-limits/) / [Microsoft Windows responsiveness](https://learn.microsoft.com/en-us/windows/apps/develop/performance/responsive). 자료 확인일 2026-10-14.

### 발표자 노트

**발표자 노트:** 위임 전에 대상과 수행 범위를 실제 채택했다면 “비교하겠습니다”도 유효하다. 사실과 다른 완료 안내도 시간은 그대로 포함하고 기능 오류를 따로 기록한다. 사용자나 기존 음성이 출력 중인 경우를 고려해 실제 음성 시작은 QA09에서 다룬다. 1초를 모든 음성 대화의 만족 임계로 일반화하지 않는다. 평균은 개별 요청의 1초 보장이 아니며 오답 벌점을 넣지 않는다.

**자료:** [정의와 점수표](qa01-first-response-latency.md) / [원문 조사와 반대 방향 연구 및 심사 답변](../../research-notes/qa01-latency-research.md). 질문 시 Miller의 추정 성격과 VR 54명 연구의 조건 및 지연을 신중함으로 해석한 2026 연구도 확인할 수 있다.

**DP 설명:** **DP-44 B는 앞 단계 완료에서 다음 처리를 직접 시작해 중앙 진행 경로를 거치는 대기를 줄일 수 있다.** 현재 차이는 약한 가설

## QA02 지칭 대상 식별 정확도

### 화면 본문

| 분류 | Title | Scenario |
| --- | --- | --- |
| Accuracy | **지칭 대상 식별 정확도** | 시스템은 사용자가 화면이나 과거 이력을 지칭할 때 **의도한 대상 집합을 누락이나 추가 없이 정확하게 식별해야 한다.**<br>**[지칭 대상 집합 일치율 ≥ 93%]**<br>※ 측정 조건: 공통 28개 중 지칭 판단 44건 × 5회 / 정답 대상 집합 전체 일치<br>※ 목표 근거: ReALM-3B 화면 지칭 93.0%의 집합 완전 일치 성능 참조 |

**사용자가 가리키거나 다시 언급한 대상을 정확히 골라 재설명과 오작업을 줄인다.**

- **목표 93%:** ReALM-3B 화면 지칭의 대상 집합 완전 일치율 93.0%를 기술 참조 목표로 채택한다.
- **판정 단위:** 원본과 범위 및 필요한 버전까지 대상 집합 전체가 같아야 성공이다. 연구와 VIA의 처리 범위 차이는 발표자 노트에 둔다.

**측정 산식**

```text
a = 100 × 전체 대상 집합이 일치한 판정 수 / 220
대상: 지칭 판단 44개 × 5회 / 실제 모호한 입력 4건은 사전 제외
```

**설명용 예시:** 정답 `{매출표 A, 비용 그래프 B}`에 `{A,B}`는 성공. `{A}`와 `{A,B,C}`는 실패 220회 중 205회 전체 집합 일치 → **약 93.18% → 1점 ◐○○**. 217~219회면 5점이며 220회면 6점

### 점수표

| 점수 | 표시 | 기준: a [%] |
| ---: | --- | --- |
| 6 | ●●● | a = 100% |
| 5 | ●●◐ | 98.6% ≤ a < 100% |
| 4 | ●●○ | 97.2% ≤ a < 98.6% |
| 3 | ●◐○ | 95.8% ≤ a < 97.2% |
| 2 | ●○○ | 94.4% ≤ a < 95.8% |
| 1 | ◐○○ | 93% ≤ a < 94.4% |
| 0 | ○○○ | 0% ≤ a < 93% |

**구간 도출:** 93%를 1점 하한으로 두고 (100−93)/5 = 1.4%p씩 나눈다. 6점은 100%일 때만 부여한다. 220개 중 205~207개 일치가 1점이며 220개가 6점이다.

**출처 각주:** [Apple ReALM, SIGDIAL 2024 §3과 Table 3](https://aclanthology.org/2024.sigdial-1.5.pdf). 자료 확인일 2026-10-14.

### 발표자 노트

**발표자 노트:** 화면과 대화의 지칭을 해석하고 전체 대상 집합이 같아야 성공이라는 공통점을 먼저 설명한다. 단 ReALM은 질의별 집합이고 VIA는 표현별 집합과 revision이므로 평가 단위와 처리 범위는 다르다. 화면 최고 성능 93.0%를 두 DP의 기술 참조 최소 목표로 선택했다. ReALM의 대화 97.9%와 평균내지 않는다. 후보 수집과 과거 원본 검색 및 범위와 버전의 처리가 VIA에서는 더 넓으므로 관련 연구의 성능을 적용한 요구이지 동일 시험의 비열등성 증거가 아니다. 마우스 연구와 근거 없는 downstream 복구율은 사용하지 않는다.

**자료:** [정의와 점수 및 DP 예상](../../qa02-referent-accuracy.md) / [연구 과제 조건과 통계 한계 및 잘못된 복구 산식](../../research-notes/qa02-accuracy-research.md).

**DP 설명:** **DP-47과 DP-45는 현재 화면과 과거 자료에서 같은 대상 집합을 고르는 문제를 다루므로 같은 성공 판정을 적용한다.** 공통 적용 자체는 양안 차이의 증거가 아님

## QA03 VIA 처리시간

### 화면 본문

| 분류 | Title | Scenario |
| --- | --- | --- |
| Performance | **VIA 처리시간** | 시스템은 사용자 목표를 완료하는 과정에서 **VIA가 담당하는 처리의 소요시간을 최소화해야 한다.**<br>**[평균 VIA 귀속 처리시간 ≤ 5초]**<br>※ 측정 조건: 공통 28개 / 완료 목표 76개 × 5회 / 외부 대기를 제외한 완료 경로<br>※ 목표 근거: Microsoft Windows Long wait 상단 5초를 VIA 자체 처리 상한으로 적용 |

**첫 안내 이후에도 VIA 자체 처리 때문에 사용자의 요청이 오래 지연되지 않게 한다.**

- **목표 5초:** Windows 지침의 Long wait 2~5초 상단을 VIA 자체 처리의 한계로 적용한다.
- **완료 경계:** 최초 요청의 실제 발화 종료 또는 Text 제출 → 최종 revision의 상태와 필요한 Agent 사실 확정 및 전체 상세 텍스트 표시와 전체 음성 요약 준비.
- **귀속 경로:** 외부 Agent 업무와 사용자 대기 및 후속 발화와 순수 청취 및 재생 차례 대기만 0으로 둔다. 실제 의존관계와 자원 경합 및 VIA 모델과 내부 대기는 유지한다.

**측정 산식**

```text
T_i = 각 목표 DAG에서 외부 업무와 사용자 대기/발화 및 순수 청취/차례 대기를 0으로 둔 최장 경로
t = (T_1 + ... + T_380) / 380
대상: 완료 목표 76개 × 5회 = 380개 / 단위: 초
```

**설명용 예시:** 실제 경로 `1.2 + max(Agent 8, VIA 3) + 0.6 = 9.8초`. 외부 작업 길이만 0으로 두면 `1.2 + max(0,3) + 0.6 = 4.8초` 가상 두 목표가 4.8초와 3.2초라면 **평균 4.0초 → 2점 ●○○**. `9.8−8=1.8초`로 계산하지 않음

### 점수표

| 점수 | 표시 | 기준: t [초] |
| ---: | --- | --- |
| 6 | ●●● | 0초 ≤ t ≤ 1초 |
| 5 | ●●◐ | 1초 < t ≤ 1.8초 |
| 4 | ●●○ | 1.8초 < t ≤ 2.6초 |
| 3 | ●◐○ | 2.6초 < t ≤ 3.4초 |
| 2 | ●○○ | 3.4초 < t ≤ 4.2초 |
| 1 | ◐○○ | 4.2초 < t ≤ 5초 |
| 0 | ○○○ | t > 5초 |

**구간 도출:** 목표 5초와 개선 수준 1초 사이를 (5−1)/5 = 0.8초씩 분할한다. 1초는 개선 수준의 채점 기준이며 실제 업무 전체를 1초에 끝낸다는 뜻이 아니다.

**출처 각주:** [Microsoft Windows responsiveness](https://learn.microsoft.com/en-us/windows/apps/develop/performance/responsive). 자료 확인일 2026-10-14.

### 발표자 노트

**발표자 노트:** 5초를 내부 단계별로 나눈 것은 원래 목표의 이유가 될 수 없다. 여기서는 외부 UI 지침의 경계를 먼저 채택한다. 외부 작업을 0으로 둔 DAG는 계약상의 귀속시간이고 VIA를 제거한 제품과 비교한 인과적 추가 지연은 아니다. 실제 경과시간도 함께 보존한다. Cloud 모델과 VIA가 사용하는 네트워크는 VIA 시간이며 음성 재생 차례 대기는 별도다. 오답도 실제 처리시간을 평균에 포함하고 실패 시간 벌점은 사용하지 않는다.

**자료:** [DAG 계산과 완료 조건 및 점수표](qa03-via-processing-time.md) / [Windows 분류와 채택 논리 및 잘못된 차감 예시](../../research-notes/qa03-duration-research.md).

**DP 설명:** **DP-42 A는 관련 로컬 상태를 함께 확정하므로 독립 서비스의 확인과 전달을 기다리는 경로가 짧다.** 실측 전 구조 가설

## 원고와 상세 명세의 관계

이 문서는 발표할 문구와 계산 예시 및 점수표를 모은 원고다. 각 QA 상세 명세는 판정 경계와 실패 처리 및 DP 가설과 최소 PoC의 기준이고 조사 기록은 출처의 조건과 적용 한계를 설명한다. 정적 검사에서 9개 페이지의 상단 표와 점수 구간이 상세 명세 및 전체 축약 표와 일치하는지 확인한다.

실제 PPT 제작과 렌더 검토 및 PoC는 수행 전이다. 원고 준비 완료를 목표 달성이나 구조 우열의 검증 완료로 해석하지 않는다.
