## 1. 제안과 기존 5초에 대한 판단

**목표별 VIA 처리 완료 경로의 평균 T를 5.0초 이하로 유지하는 안을 제안한다.** 외부 Agent 업무, 사용자 대기/발화와 순수 전달을 제외한 경로이며, 모든 필수 상태/연동/최종 응답 준비를 완료해야 한다. 5초가 사용자의 실제 업무 완료 대기나 마지막 음성을 듣는 시간이라는 뜻은 아니다.

5초의 근거는 음성 첫 응답 연구가 아니다. Windows 상호작용 지침의 긴 대기 구간을 참조하여 **VIA의 연결과 응답 준비가 자체적으로 장시간 처리를 더하지 않도록 관리하는 설계 예산**으로 제안한다. 외부 지침이 VIA의 DAG 투영시간 또는 그 산술평균에 대해 5초를 실증한 것은 아니다. 직접적인 외부 근거의 강도는 QA01의 음성 응답 연구보다 낮다.

기존 QA03도 첫 응답 이후의 전체 상태 확정과 최종 응답 준비를 다뤘고 Agent 업무를 제외한 VIA 경로를 사용했다. 새 정의는 실제 표시와 장치 재생을 처리 준비에서 분리하고, 필수 채널 및 자원 의존을 더 명확히 했다. 전체 처리 예산을 관리하는 목적은 유지되므로 5초를 버려야 할 이유는 없다. 다만 표시 지연을 제외하면 수치가 바뀔 수 있으므로 **동일한 목표 수치를 선택하는 것과 이전 결과/점수를 그대로 재사용하는 것은 다르다.** 새 계약으로 다시 계산한다.

## 2. 확인한 원자료와 적용 한계

2026-10-23 [Microsoft, Responsive interactions and Windows Application Performance](https://learn.microsoft.com/en-us/windows/apps/develop/performance/responsive)의 상호작용 분류표를 재확인했다. 페이지 갱신일은 2026-03-18이다.

| 원문 분류 | 원문의 범위와 취지 | 이번 판단 |
| --- | --- | --- |
| Wait | 1~3초. 작업량 때문에 기다리는 상호작용 | 3초는 더 엄격한 개선 목표의 후보가 될 수 있음 |
| Long wait | 2~5초. 응답성이 좋다고 느끼기 어려운 긴 대기 | 이 구간 상단을 VIA 자체 처리 예산의 상한 참조로 선택 |
| Captive | 5~10초. 불가피하게 길거나 복잡한 작업 | 외부 업무를 제외한 VIA 처리 자체에 이 정도의 예산을 기본으로 주지는 않겠다는 제품 판단 |

분류가 겹치므로 5초를 정확한 심리적 경계로 설명하지 않는다. 5초는 원문에서 좋은 경험의 기준도 아니다. 또한 원문은 관측 가능한 상호작용 경과시간을 다루고, QA03은 인과/자원 경로에서 일부 duration을 0으로 투영한 값이다. 따라서 **5초의 QA03을 충족하면 실제 사용자 대기도 5초 이하이거나 만족도가 보장된다는 결론은 성립하지 않는다.** 실제 전체 경과와 음성 전달은 별도로 보고한다.

이번 조사에서 새 QA03과 경계 및 집계가 일치하는 외부 실험으로 5초를 직접 정당화하지는 못했다. 새 수치를 더 정확한 것처럼 만드는 대신 기존 5초를 간접 지침에 근거한 제품 목표 제안으로 유지하고 적용 한계를 명확히 한다. [이전 조사](../../research-notes/qa03-duration-research.md)는 과거 경계의 근거로 보존한다.

## 3. 다른 수치와 비교한 판단

| 검토한 목표 | 판단 |
| --- | --- |
| 1초 | 첫 응답 이후에도 남는 필수 처리까지 일괄 요구하기에는 지나치게 강한 기본안. 전체 목표 완료의 직접 근거가 없으며 6점의 개선 수준으로만 사용 |
| 3초 | 더 빠른 제품 요구로 선택할 수 있지만 새 정의 때문에 반드시 이 숫자로 바꿔야 할 근거는 없음. 앞으로 대표 업무의 사용자 검증이나 명시적 제품 요구가 이를 지지하면 재검토 |
| **5초** | 전체 처리 예산이라는 의미를 유지하면서 참조 가능한 Windows 긴 대기 구간의 상단을 적용하는 현재 제안 |
| 10초 | Captive 상단을 자체 처리에 허용하는 안. VIA가 외부 업무를 제외하고도 기본적으로 10초를 쓰도록 완화할 근거를 확인하지 못함 |

이는 각 후보의 기술적 달성 가능성을 측정한 비교가 아니다. 특정 DP를 통과시키거나 점수 차이를 만들 목적으로 3초/5초/10초를 고르지 않는다. 먼저 고른 5초를 해석, 조회, 음성 생성의 임의 소요시간으로 나눠 적은 것을 목표 근거라고 부르지 않는다.

## 4. 적용 조건

등록한 목표 집합의 완료 의무, 후속 확인/정정, 외부 결과, 필수 채널과 응답 내용 범위를 후보 실행 전에 고정한다. 전체 음성 생성이 포함되므로 짧은 상태 요약과 긴 낭독의 길이를 같은 것으로 보지 않는다. 필요한 내용을 생략하거나 후보별로 필수 채널을 바꿔 목표를 맞추지 않는다. 반대로 새 QA를 만들었다는 이유로 긴 낭독을 임의로 추가하지도 않는다.

장기 업무와 여러 차례 확인을 무제한으로 포함한 모든 목표가 5초를 충족한다는 보장은 없다. 현재 공통 목표 집합의 평균 요구이며, 대표 업무 구성이 바뀌면 목표 적용의 타당성을 다시 검토한다. 모든 DP와 대안에는 동일한 목표 집합과 같은 경계를 적용한다. 불완전 trace나 빠른 의무 누락을 정상 완료로 인정하지 않는다.

QA01의 차례 대기 보조 지표 E와 QA03의 T는 다른 값이다. QA01 목표 2초와 QA03 목표 5초를 더해서 총 7초 예산으로 설명하지 않는다. 단순 목표에서는 두 지표가 비슷할 수 있으며 점수표로 차별화를 인위적으로 만들지 않는다.

## 5. 0~6점 제안

**0점은 수치 목표 미달, 1점 이상은 수치 목표 충족, 6점은 높은 개선 수준**으로 둔다. 6점 상한 1초는 처리 예산 5초의 20%를 사용하는 개선 수준으로 정한 설계 규칙이다. 음성 첫 응답의 1초 선호 연구를 QA03에 적용한 값이 아니다.

1초부터 5초까지 다섯 구간을 균등 분할하여 `(5.0−1.0)/5 = 0.8초` 간격을 사용한다. 숫자 구간은 이전과 같지만 새 완료 계약에 연결된 별도 점수 제안 판본이다. 이전 점수표를 자동 승인하거나 과거 결과를 새 점수로 전용하지 않는다.

| 점수 | 원형 | 평균 T / 초 |
| --- | --- | --- |
| 0 | ○○○ | `T > 5.00` |
| 1 | ◐○○ | `4.20 < T ≤ 5.00` |
| 2 | ●○○ | `3.40 < T ≤ 4.20` |
| 3 | ●◐○ | `2.60 < T ≤ 3.40` |
| 4 | ●●○ | `1.80 < T ≤ 2.60` |
| 5 | ●●◐ | `1.00 < T ≤ 1.80` |
| 6 | ●●● | `0 ≤ T ≤ 1.00` |

**1초의 우수선, 20% 및 0.8초의 구간 폭은 외부 문헌의 실험 임계가 아니다.** 연속 원값을 일관되게 표시하는 채점 규칙이며 1점의 차이가 동일한 사용자 효용 증가를 뜻하지 않는다. 두 안이 같은 점수이면 원값과 불확실성을 보고하고 점수 차이를 만들기 위해 구간을 바꾸지 않는다.

반올림 전 유효 평균을 채점한다. 5초는 1점, 4.2초는 2점, 1초는 6점이다. 음수/미관측/불완전 trace는 0점으로 처리하지 않는다. 오답 처리의 실제 시간과 기능 오류는 함께 보고하며 준비 시간만으로 실제 전달 성공을 선언하지 않는다. 제품 실측이 없는 분석값의 점수는 가정하의 점수일 뿐이다.

## 6. 채택과 후속 작업

정의와 측정방법은 합의됐고 이 목표/점수는 사용자 검토를 위한 제안이다. 아직 평가 계산기에 적용하지 않는다. 사용자 채택 후 동일한 목표 구성에 새 판본을 적용하고 과거 수치와 채점 조건을 보존한다. 이번 작업에서 DP별 원값, 점수나 선택 순위를 산출하지 않았다.
