## 1. 정의와 결론

**시스템은 사용자의 한 목표를 처리하는 데 필요한 VIA의 해석, 업무 연결, 상태 확정과 최종 응답 준비를 신속하게 완료해야 한다.**

| 항목 | 정의 |
| --- | --- |
| 이름 | VIA 처리시간 |
| 지표 | 외부 Agent 업무, 사용자 대기/발화와 순수 음성 재생/차례 대기를 제외한 **목표별 VIA 처리 완료 경로 시간의 산술평균 T**, 초 |
| 시작 | 등록한 목표를 시작하는 최초 사용자 발화 종료 또는 Text 제출 |
| 종료 | 목표에 필요한 VIA 상태 확정, 외부 연동 확인과 최종 응답의 필수 채널별 준비가 **모두** 끝난 시점 |
| 출력 범위 | 화면/음성 중 먼저 시작한 것을 고르지 않는다. 필요 채널의 전체 응답 준비를 완료한다. 실제 화면 표시와 음성 재생은 전달 진단/기능 검증으로 구별 |
| 좋은 방향 | 낮을수록 좋음 |
| 목표와 점수 | **TARGET_PENDING_REVIEW / SCORE_BANDS_PENDING**. 새 제안은 평균 5초 이하 유지와 1초 이하 6점. [근거와 0~6점 제안](../../research-notes/qa03-completion-target-proposal-20261023.md)은 사용자 채택 전이며 계산기에 적용하지 않음 |

**화면/음성 중 빠른 첫 응답은 권하지 않는다.** 그 방식은 채널만 바뀐 첫 응답 지표이므로 QA01과 구별이 약하다. QA01은 사용자가 응답을 듣기 시작한 시점, QA03은 전체 목표에서 VIA가 해야 할 처리를 끝낸 시점으로 구별한다. 두 값은 같은 경로 일부를 공유하므로 독립적인 두 이익으로 합산하지 않는다.

“둘 중 빠른 것”이 첫 출력이 아니라 **전체 화면 응답 준비와 전체 음성 응답 준비 중 먼저 끝난 것**을 뜻해도, 둘 다 필수인 사례에서는 남은 채널의 처리 의무를 놓친다. 한 채널만 필요한 사례라면 그 채널만 완료하면 되지만 후보가 결과를 본 뒤 빠른 채널을 선택하지 않는다. 필요한 채널은 사용자 모드와 사례 계약으로 먼저 정한다.

단순한 한 문장 답변에서는 두 지표가 비슷할 수 있다. 이를 피하려고 QA03에 불필요한 작업을 추가하지 않는다. 실제 대표 사례에서 대부분 같은 원인과 순위를 보이면 최종 QA 선정 때 하나를 제외할 수 있다. 차별화 여부는 아직 검증하지 않았다.

## 2. 목표와 완료 의무

입력, 요청과 목표를 구별한다. 하나의 목표는 추가 확인 답변이나 정정, 외부 결과를 거칠 수 있다. 첫 확인 질문이나 수행 안내만 생성한 것을 전체 목표 완료로 처리하지 않는다. Agent 알림 자체는 새 사용자 목표로 부풀리지 않고 지정된 기존 목표에 연결한다.

모든 목표에 다음 완료 의무 중 적용되는 것을 실행 전에 등록한다.

1. **상태 확정:** 처리 판본, Request/Task 연결, 요청한 제어/결과 상태와 필요한 지속 기록이 확정됐다.
2. **외부 연동:** 목표가 요구하는 Agent 접수, 결과, 취소 확인 등 필요한 사실을 받아 VIA 상태에 반영했다. 전송 성공만으로 완료를 대체하지 않는다.
3. **내용 준비:** 최종 답변/결과 안내/확인된 종료 사유와 필요한 자료 참조의 전체 내용이 채택됐다. 첫 안내 이후 처리 의무가 남아 있으면 미완료다.
4. **채널별 준비:** 필요한 출력 채널의 전체 내용과 현재 판본/권한/출력 참조가 전달 계층에 수용됐다. 양 채널이 필요하면 둘 다, 한 채널만 필요하면 그 채널을 완료한다.

| 채널 | QA03 완료를 위한 준비 | 별도로 검증할 전달 |
| --- | --- | --- |
| 화면 | 필수 상세 텍스트/결과 참조가 완성되고 표시용 최신 판본이 전달 계층에 수용됨 | 실제 렌더/표시 시각과 누락 여부 |
| 음성 | 필수 음성 요약 전체의 생성이 끝나고 유효 출력 참조가 수용됨. 스트리밍으로 이미 출력한 구간은 생성 완료로 인정 | 실제 첫 출력은 QA01, 전체 전달/중단/재개/누락은 기능 검증 |
| 모두 | 화면 준비와 음성 전체 준비가 모두 완료 | 두 전달 경로 모두 검증 |

음성 전체를 생성할 때까지 재생을 막거나 전체 PCM을 RAM에 보관하라는 요구가 아니다. 스트리밍 재생을 허용하며, 이미 전달한 구간과 남은 유효 구간을 합쳐 생성 의무를 확인한다. 화면을 실제로 표시하지 않아도 된다는 제품 정책도 아니다. **필수 화면 전달은 여전히 기능 의무이고, QA03의 처리 종료점에서 장치 전달을 분리하는 제안**이다. 화면이 선택인지 여부는 제품/사례 계약에서 정한다.

입력 의미의 정답 여부로 시간 종료를 늦추지 않는다. 잘못된 대상을 기준으로 처리 종료했다면 실제 시간을 보존하고 기능 오류를 붙인다. 필요한 처리 자체를 누락한 경우에는 관측된 조기 종료와 누락을 함께 보고하며 정상 완료나 빠른 성공으로 인정하지 않는다. 정상 목표를 자의적으로 포기한 오류 종료도 별도 표시한다.

## 3. 구체적인 목표별 끝점

| 목표 | 완료 의무 | 첫 응답과 다른 부분 |
| --- | --- | --- |
| 자료 설명 | 요청한 설명 전체의 채택, 필요한 채널의 최종 응답 준비와 상태 확정 | 첫 문장을 말한 뒤에도 나머지 설명/음성 준비가 남을 수 있음 |
| 보고서 작성 위임 | Agent의 보고서 결과 수신, 지정 Task와 결과 참조 연결, 최종 안내 준비 | “보고서를 작성하겠습니다”는 QA01 응답일 수 있지만 QA03 완료가 아님 |
| 업무 상태 조회 | 실제 조회/확인한 상태의 반영과 최종 응답 준비 | “확인하겠습니다” 이후의 조회와 상태 반영 포함 |
| 정정/취소 | 지정 판본의 정정 또는 취소 확인 상태 반영, 무효 상태 정리와 최종 응답 준비 | 제어 요청 접수 안내 뒤의 실제 연동/정리 포함 |
| 확인이 필요한 목표 | 정해진 사용자 답을 받은 뒤 원래 목표의 최종 완료 의무 이행 | 확인 질문만 생성하고 완료하지 않음. 사용자 응답 대기는 시간에서 제외 |
| 정당한 거부/보류 | 공통 계약이 허용한 종료 상태와 사유/후속 행동 준비 | 빨리 포기한 후보 오류와 구별 |

장기 업무의 무한한 미래까지 기다리지 않는다. 공통 사례에서 한 목표의 결과/종료 사건을 유한하게 정한다. “요청 제출만”을 목표로 삼은 경우와 “보고서 생성 완료”를 목표로 삼은 경우를 같은 이름으로 비교하지 않는다. 정정/취소를 독립 목표로 등록하면 기존 목표와 중복 계수하는지 원장에 명시한다.

## 4. 포함과 제외

| 포함하는 VIA 처리 | 제외하는 외부/전달 시간 |
| --- | --- |
| 발화 종료 판단, 전사 확정, 요청 해석, 근거 취득, 검색과 문맥 구성 | Downstream Agent 내부의 도메인 추론, 계획과 도구 실행 |
| VIA가 사용하는 원격/로컬 의미 모델, 음성 모델의 호출/전송/추론/할당 대기 | 사용자 답변 대기와 답변의 발화 길이 |
| 위임/제어 전송, 접수/결과의 연동 확인, 상태 저장과 관계 확정 | 이미 준비된 음성을 듣는 길이와 공통 차례 정책의 순수 발화 대기 |
| 최종 답변과 음성 전체 준비, 내부 큐/직렬화/서비스 왕복, 필요한 재검증과 복구 | 최종 준비 수용 뒤의 단순 화면 렌더/장치 재생 지연 |

원격 모델이라고 전부 외부 업무로 빼지 않는다. VIA가 호출한 의미/TTS 모델은 포함한다. Agent 업무가 밖에 있다는 이유로 VIA의 위임 전달, 결과 수신과 상태 반영까지 제외하지 않는다.

전달 완료가 이후 사용자 확인이나 다음 상태 확정의 실제 선행조건이면 그 의존 edge를 보존하되 순수 전달 duration만 0으로 투영한다. 내용 생성, 권한 확인과 전달 오류 복구처럼 VIA가 실제 수행한 처리는 포함한다. 자동 선택/스케줄링의 내부 지연을 “사용자 차례 대기”로 바꾸지 않는다. 겹치는 원인은 [공통 계약](../../timing-measurement-contract.md)의 사건/자원 원장으로 구별한다.

## 5. 병렬성을 보존한 산식

```text
각 목표 g의 실제 인과 그래프 G_g:
  node = 실제 처리 또는 대기
  edge = 데이터/상태 의존과 실제 자원 선후 관계

d'(node) = 0                 사전 정의한 외부 업무/사용자/순수 전달 시간
           실제 duration    VIA 처리와 내부 대기

finish(node) = d'(node) + max(finish(parent))
T_g = 모든 필수 완료 node를 잇는 공통 terminal의 finish
QA03 T = sum(T_g) / 목표 수
```

먼저 원래 duration의 그래프가 실제 관측 완료시각을 재구성하는지 확인한다. 그 다음 제외 duration만 0으로 바꾸며 실제 인과와 실행 순서를 유지한다. 직렬은 합, 병렬은 늦게 끝나는 경로를 사용한다. 전체 경과시간에서 외부 시간을 단순히 빼거나 모든 CPU 작업시간을 더하지 않는다. 외부 업무를 실제로 0초로 만든 제품의 예측 성능도 아니다.

- 목표 시작 이전에 끝난 준비는 초기 상태다. 시작 전에 시작해 이후까지 남은 작업은 시작 이후의 잔여 구간만 포함한다. 사전 비용과 메모리는 QA05/08 등 해당 지표에 남긴다.
- 자원 선행 작업 때문에 기다린 구간을 선행 작업 edge와 동일 길이의 대기 node로 두 번 세지 않는다. 별도의 scheduler 지연만 추가한다.
- 다른 목표가 자원을 점유해 만든 경합도 시작 이후의 관련 경로에 포함한다. 대기 원인을 알 수 없는 gap을 외부 시간으로 임의 제외하지 않는다.
- 첫 응답 시각은 QA03의 새 시작점이 아니다. 첫 음성을 일부러 늦춰 QA03을 줄이는 `완료시각 - 첫 음성시각`을 사용하지 않는다.

설명용 예: VIA 위임 준비 1.2초 뒤 Agent 업무 8초와 VIA 병행 처리 3초가 실행되고, 둘 다 끝난 후 최종 응답 준비 0.6초가 필요하다.

```text
실제 처리 완료 경과 = 1.2 + max(8, 3) + 0.6 = 9.8초
QA03 귀속시간      = 1.2 + max(0, 3) + 0.6 = 4.8초
```

`9.8 - 8 = 1.8초`는 VIA 병행 처리 3초를 잃으므로 잘못된 계산이다. 음성 첫 안내가 0.8초였다면 QA01은 0.8초이며 QA03 4.8초와 서로 다른 질문에 답한다. 모두 설명용 값이다.

## 6. 측정 절차와 실패

1. 동일 목표별 최초 입력, 완료 의무, 채널, 후속 정정/외부 사건과 정상 종료 상태를 원장에 등록한다.
2. 양안의 입력/모델 조건과 외부 사건, 공통 권한/차례 정책 및 자원 한도를 고정한다. 후보별 실제 구조와 고유한 재사용/병렬성은 보존한다.
3. 처리/대기 span의 시작/끝, owner, 원인, 부모와 자원 관계, 채널별 준비 수용과 상태 확정을 수집한다.
4. 실제 실행 그래프의 wall-clock 재현을 확인하고, 제외 노드만 0으로 투영해 목표별 T_g를 계산한다.
5. 실제 오답/오류 종료시간과 오류를 함께 보존한다. 정상 완료/오류 종료/미완료 수와 관측분 평균을 분리한다. 정답이 나올 때까지 기다린 시간으로 소급하지 않는다.
6. 모든 예정 목표의 처리 종료와 trace가 갖춰졌을 때 전체 평균을 확정한다. 누락이 있으면 `NOT_OBSERVED`/`INCOMPLETE_TRACE`와 부분 관측값을 보고한다. 임의 기한을 시간값으로 넣지 않는다.

처리 자체의 의무 누락, 거짓 완료와 음성 미전달은 낮은 T로 상쇄할 수 없다. 음성 전달 누락은 QA01/기능 검증에도 남는다. 반복 수, 원본, 목표 수와 관측창은 후속 실행 manifest에서 동결하며 이전 76×5나 현재 24목표를 자동 확정하지 않는다.

## 7. 목표와 중복 검토

기존 5초는 Windows 상호작용 지침을 VIA 전체 처리의 평균에 적용했던 작성자 제안이었다. 새 경계는 실제 화면 표시 대신 채널 준비 수용을 사용하므로 기존 점수표로 재채점하지 않는다. [이전 조사](../../research-notes/qa03-duration-research.md)는 출처 이력이고 새 경계의 실증 결과가 아니다. 2026-10-23 [새 경계의 목표와 점수 제안](../../research-notes/qa03-completion-target-proposal-20261023.md)에서는 5초를 VIA 자체 처리 예산으로 유지하는 안을 독립적으로 검토했다. 1초 우수선과 0.8초 균등 구간은 별도 설계 규칙이다. 정의는 합의됐지만 목표 수치, 0~6점과 적용할 대표 목표 구성의 채택은 별도 합의 대상이다.

중복 여부는 같은 실제 목표에서 첫 응답 이후 남은 처리의 종류, QA01/03의 차이를 만든 경로, 동점/순위가 달라지는 사례와 전체 대표성을 확인한다. 단순한 상관계수 하나나 한 개의 긴 예시만으로 독립성을 선언하지 않는다. DP2/3/5의 앞단 해석이 두 시간에 같이 작용할 수 있고 DP44의 선행 준비도 둘에 영향을 줄 수 있다. 모든 DP에 서로 다른 순위를 만들어야 하는 것은 아니다.

2026-10-23 사용자가 이 정의와 측정방법을 채택하고 지정된 담당 세션에 공통 평가 갱신을 요청하도록 승인했다. 새 목표와 점수, 최종 핵심 QA 선정 및 대안의 우열은 별도 판단이다. 실제 값과 평가 자료의 갱신은 담당 세션이 수행하며 전달 상태는 공통 측정 계약에 기록한다.
