## 1. 기존 90%를 자동 유지하지 않는 이유

이전 90% 제안은 요청 의미를 최초 확정하는 단일 입력의 전체 일치율에 대한 기술 참조였다. 현재 QA07은 요청 처리 사례의 모든 최초 해석과 응답 구성 및 실제 전달 의무를 함께 판정한다. 사례에 따라 후속 revision, 여러 Agent 사건과 응답 채널이 추가된다.

따라서 입력 의미 exact match 90.8%에서 정수 목표 90%를 제안했던 논리를 새 전체 충족률에 그대로 적용하지 않는다. 사례가 길어졌으므로 일정 비율을 임의로 더하거나 빼는 보정도 하지 않는다. 해석/구성/전달의 오류는 서로 연관될 수 있으므로 세 정확도의 곱으로 목표나 결과를 만들지 않는다.

## 2. 이전 근거의 역할

| 보존한 근거 | 새 QA07에서 사용할 범위 |
| --- | --- |
| TreeDST 및 FULLTOGRAPH의 90.8% 의미 exact match | 최초 해석 단계의 관련 기술 참조. 응답 채택 이후 취소/대체/실제 출력 전체의 충족률 근거로 사용하지 않음 |
| SMCalFlow의 문맥 참조와 수정 관계 | 요청 revision과 이전 요청/응답 연결의 의미 판정 참고 |
| 전체 의미 구조 일치와 slot별 평균의 차이 | 필수 의무 중 일부만 맞아도 성공으로 처리하지 않는 판정 원칙 |
| 이전 80후보/400판정, 현재 v4의 24입력 | 입력 출처 이력. 새 요청 처리 사례의 분모가 아님 |

TreeDST는 데이터셋 이름이고 90.8%는 이전 조사에서 확인한 별도 모델의 validation 결과다. 원문 링크, 수치와 확인 내역은 보존한 조사에 남긴다. 이번 변경에서는 새로운 외부 성능 수치를 주장하거나 논문 재현을 수행하지 않았다.

## 3. 목표와 0~6점의 결정 조건

**TARGET_PENDING_REVIEW / SCORE_BANDS_PENDING.**

1. 대표 요청 처리 사례의 길이, 후속 정정/취소와 Agent 사건, 필수 응답/채널 및 관측창을 먼저 정한다.
2. 실패의 사용자 영향과 현재 요청에 맞지 않는 실제 전달의 허용 수준을 제품 요구로 검토한다. 단순 문장 스타일의 만족도와 구별한다.
3. 같은 단위와 범위의 검증 자료 또는 명시적 제품 요구가 준비되면 새 목표를 제안한다. 최초 의미 파싱 자료만으로 전체 전달 목표를 확정하지 않는다.
4. 목표가 합의된 뒤 0~6점 구간의 우수선과 분할 원칙을 정한다. 기존 90%와 2%p 구간은 보존본에만 둔다.

목표 미정은 정의 작업이 미완료라는 뜻이 아니다. 새 지표의 범위와 평가 단위 제안은 명세에 기록했고 숫자의 정당화와 실행 동결을 별도 작업으로 남긴 상태다. 새 표본이 없는데 이전 결과를 재채점하거나 현재 DP의 원하는 순위에 맞춰 수치를 고르지 않는다.
