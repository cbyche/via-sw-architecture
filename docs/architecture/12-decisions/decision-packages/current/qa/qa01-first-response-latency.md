## 1. 정의와 대표 지표

**시스템은 음성 전달이 필요한 사용자 입력이나 업무 사건에 대해 첫 실질적 내용의 음성을 신속하게 출력해야 한다.**

| 항목 | 정의 |
| --- | --- |
| 이름 | 첫 응답 지연시간 |
| 지표 | 입력/사건부터 첫 실질적 음성의 실제 출력 시작까지 걸린 시간의 산술평균 L, 초. 낮을수록 좋음 |
| 시작 | 실제 사용자 발화 종료, 음성 응답 대상 Text 제출, 또는 알릴 의무가 있는 Agent 사건의 외부 최초 제공 가능 시각 |
| 종료 | 해당 입력/사건에 대응하는 최초 채택 내용 중 첫 실질적 발화 구간의 실제 출력 시작 |
| 포함 | 입력 종료 판단, 해석, 검색, 모델 호출, 음성 생성과 내부 큐/출력 지연. 사용자 발화와 이전 응답의 재생으로 말할 차례를 기다린 시간도 **대표값에 포함** |
| 보조 진단 | 사용자 발화로 막힌 시간, 이전 응답 재생으로 막힌 시간, 둘의 중복을 뺀 차례 대기, 나머지 시간 및 채택 후 재생 가능 구간의 추가 대기 |
| 화면 | 첫 내용 표시 시각을 별도 진단으로 기록. 음성 대신 QA01을 종료하지 않음 |
| 정확성 | 빠른 오답도 실제 시간을 보존. 정확성과 기능 오류는 별도로 평가 |
| 목표와 점수 | **TARGET_PENDING_REVIEW / SCORE_BANDS_PENDING**. 이전 화면 기준의 평균 1초와 점수 구간을 자동 적용하지 않음 |

QA01의 핵심 질문은 **언제 사용자가 응답을 듣기 시작했는가**다. 전체 답변 생성, 업무 완료나 음성 전체 재생까지 기다리는 지표가 아니다. QA03은 전체 목표에서 VIA의 처리 의무가 완료됐는지를 평가한다.

## 2. 첫 실질적 음성의 판정

구체적인 수행 의도, 질문에 대한 답변, 해결할 모호함이 특정된 확인 질문, 업무 상태 또는 결과를 인정한다. 위임을 실제 전송하기 전이라도 채택한 구체적 처리 의도를 말할 수 있다. 업무를 끝내지 않았는데 완료했다고 말한 경우는 실제 시작 시간을 남기고 사실 오류를 함께 기록한다.

- “네”, 알림음, “잠시만요”, “처리 중입니다”와 무음은 종료점이 아니다.
- “네. 두 견적에서 설치비를 제외하고 비교하겠습니다”라면 일반 인사 뒤의 구체적인 수행 안내가 시작된 sample을 사용한다.
- 첫 chunk 생성, codec packet, playback enqueue는 실제 출력과 구별한다. 장치 출력에서 어느 발화 구간이 나왔는지 확인한다.
- 문장을 다 말한 시각으로 종료하지 않는다. 실제 출력된 발화가 실질적 내용인지 사후 확인하고 그 내용 구간의 시작을 사용한다. 의미가 드러나기 전에 중단되어 식별할 수 없으면 단순 첫 소리로 인정하지 않는다.
- 잘못된 대상을 설명했어도 실질적 응답이면 지연은 그 실제 시작까지다. 나중에 고친 시각으로 소급하지 않는다. QA02/07의 해석 오류와 출력 판본/음성 전달 오류를 구별한다.

## 3. 적용 사건과 분모

입력 목록 전체에 자동 적용하지 않는다. 평가 전에 사건별로 음성 상호작용 활성화, 음성 전달 의무, 대응할 Response/revision, 시작 시각과 종료 조건을 등록한다. 음성으로 질문한 사례뿐 아니라 음성 응답을 요구한 Text 입력과 사용자에게 전달해야 하는 Agent 통지도 포함할 수 있다.

텍스트만 요구한 사례는 음성 분모에서 제외하고 화면 지연과 기능 완료를 별도로 확인한다. 후보가 음성 생성을 하지 않았다는 이유로 음성 의무 사건을 제외할 수 없다. 모든 Agent 로그를 알림으로 세지도 않는다. 병합/철회 가능한 통지는 공통 정책과 사건 목록에 먼저 명시한다.

- 여러 사건에 하나의 발화가 대응하면 각 사건의 원래 시작 시각과 대응한 내용 구간을 기록한다. 같은 파일의 재생 시작을 모든 사건의 응답 시각으로 복사하지 않는다.
- 정정/취소로 더 이상 말해서는 안 되는 내용은 공통 revision 규칙으로 의무 철회를 기록한다. 정상 철회와 모델 실패를 구별하며 불리한 사건을 사후에 버리지 않는다.
- 현재 v4의 24개 입력이 이 지표의 24건이 된다고 확정하지 않는다. 음성 의무와 Agent 사건, 정정에 따른 대응을 다시 매핑해야 한다. 이전 120×5나 109×5도 자동 계승하지 않는다.

## 4. 대표값과 차례 대기 보조 지표

```text
s_i = 입력/사건의 시작
v_i = 첫 실질적 음성의 실제 출력 시작
l_i = v_i - s_i
L = sum(l_i) / N

U_i = [s_i, v_i)에서 사용자가 말하는 구간
P_i = [s_i, v_i)에서 공통 차례 정책상 앞선 응답을 재생하는 구간
B_i = duration(U_i union P_i)
E_i = l_i - B_i
```

**L이 대표 QA01이다. B를 뺀 E로 몰래 대체하지 않는다.** 사용자 발화 시간 `duration(U)`와 이전 재생 시간 `duration(P)`, 겹친 시간 `duration(U intersection P)`, 합집합 B를 각각 남긴다. `l = B + E`로 중복 없는 분해가 된다. B의 평균과 E의 평균은 대표값과 같은 관측 사건 집합에서 산출하며 별도 QA 점수를 부여하지 않는다.

E는 차례 대기가 아니었던 경과시간이지 모델 계산량이나 VIA 전체 처리시간이 아니다. 생성이 B와 병렬로 진행될 수 있으므로 `해석시간 + 생성시간 + 사용자 발화시간 + 이전 재생시간`을 QA01로 합산하지 않는다.

내용 채택 후 진단은 다음과 같다.

```text
a_i = 첫 실질적 음성 구간에 대응하는 내용의 채택 시각
D_i = [max(s_i, a_i), v_i)에서 공통 정책상 말할 수 있었던 구간의 길이
```

D에는 아직 음성이 준비되지 않았거나 내부 큐에서 기다린 시간도 들어간다. 후보의 ready flag로 말할 수 있는 구간을 늦추지 않는다. D는 QA01 내부 진단이며 B/E와 다시 더하지 않는다. 독립 QA09, 500ms 목표와 점수는 사용하지 않는다.

출력 장치 고장/음소거/중도 모드 전환 등 다른 방해 조건은 별도 태그로 남긴다. 고정 시험 전제 위반, 정상 의무 철회, 제품 전달 실패 중 무엇인지는 공통 규칙으로 판단하며 사용자 발화 대기에 섞지 않는다.

## 5. 동일 조건과 실패 처리

모든 대안에 같은 입력, 원본, 사용자 발화 일정, 이전 응답의 내용/길이, 차례/우선순위 정책과 기능 의무를 적용한다. 먼저 말하기 위해 사용자를 끊거나 필수 내용을 생략하면 기능 오류다. 상대 대안의 선행 준비 효과를 없애도록 모델 시작 시각을 강제하지 않는다.

음성이 끝내 나오지 않은 경우는 `NO_AUDIO` 또는 `NOT_OBSERVED`, 기록이 누락된 경우는 `UNOBSERVABLE`로 남긴다. 0초나 임의 timeout 값을 평균에 넣지 않는다. 예정 N, 유효 관측 수, 전달 실패, 정상 철회와 계측 무효를 모두 보고한다. 일부 관측 평균은 전체 QA01로 확정하거나 목표 달성으로 선언하지 않는다.

관측 종료시간은 최대 차례 대기와 처리 기한을 포함하도록 시험 전에 고정한다. 30초를 무조건 계승해 정상 긴 발화를 실패 처리하지 않는다. 사건의 결과를 보고 관측창을 늘리거나 줄이지 않는다. 반복 수와 사건 종류별 비중도 공통 manifest에 고정한다.

## 6. 설명용 예와 목표 상태

사건 0초, 앞 응답 종료 5초인 사례에서 A는 2초에 준비해 5초에 출력하고 B는 5초부터 준비해 6초에 출력한다고 하자.

| 값 | A | B |
| --- | ---: | ---: |
| QA01 실제 지연 | 5초 | 6초 |
| 차례 대기 B | 5초 | 5초 |
| 나머지 E | 0초 | 1초 |

생성 시간이 A에게 없었다는 뜻이 아니다. 차례 대기와 겹쳐 있었고 사용자에게 추가 대기를 만들지 않은 것이다. 양안 모두 5초 전에 준비됐다면 QA01은 동점이다. 이 수치는 실제 측정값이 아니다.

새 목표에는 음성 첫 응답 근거와 즉시 발화/차례 대기 사건의 고정 구성에 대한 판단이 필요하다. 기존 [화면 지연 조사](research-notes/qa01-latency-research.md)의 1초를 그대로 이전하거나 새 수치를 임의 지정하지 않는다. 현재는 초 단위 원값과 보조 지표를 정의한 상태이며 점수 적용은 보류한다. [측정 담당 전달 계약](timing-measurement-contract.md)에 합의 필요 항목과 담당 범위를 기록한다.
