## 1. 정의와 대표 지표

**시스템은 음성 전달이 필요한 사용자 입력이나 업무 사건에 대해 첫 실질적 내용의 음성을 신속하게 출력해야 한다.**

| 항목 | 정의 |
| --- | --- |
| 이름 | 첫 응답 지연시간 |
| 대표 지표 | 차례 대기가 없는 일반 상황 NORMAL에서 입력/사건부터 첫 실질적 음성의 실제 출력 시작까지 평균 L, 초 |
| 목표 | **L ≤ 2.00초** |
| 시작 | 실제 사용자 발화 종료, 음성 응답 대상 Text 제출, 또는 알릴 의무가 있는 Agent 사건의 외부 최초 제공 가능 시각 |
| 종료 | 해당 입력/사건에 대응하는 최초 채택 내용 중 첫 실질적 발화 구간의 실제 출력 시작 |
| 포함 | 발화 종료 판단, 해석, 검색, 모델 호출, 음성 생성, 내부 큐와 출력 장치까지의 지연 |
| 일반 상황 | 추가 사용자 발화나 앞 응답 재생 때문에 발화 차례가 막히지 않도록 사전 지정한 공통 사례 |
| 별도 보고 | 사용자 발화 또는 앞 응답 재생으로 차례 대기가 있는 WAIT 상황. 실제 지연, 대기와 대기 종료 후 추가 지연을 해당 DP에 함께 표시 |
| 별점 | NORMAL의 L에만 0~6점 적용. WAIT 값은 일반 상황 평균과 합치지 않고 별도 점수도 부여하지 않음 |
| 화면 | 첫 내용 표시 시각은 진단용. 음성 대신 QA01을 종료하지 않음 |
| 정확성 | 빠른 오답도 실제 시간을 보존하고 오류를 별도로 보고 |

QA01은 사용자가 응답을 듣기 시작한 때, QA03은 전체 목표에서 VIA가 필요한 처리를 끝낸 때를 평가한다.

## 2. 첫 실질적 음성의 판정

구체적인 수행 의도, 질문에 대한 답변, 해결할 모호함이 특정된 확인 질문, 업무 상태 또는 결과를 인정한다. 위임을 실제 전송하기 전에도 채택한 구체적 처리 의도를 말할 수 있다.

- “네”, 알림음, “잠시만요”, “처리 중입니다”와 무음은 종료점이 아니다.
- “네. 두 견적에서 설치비를 제외하고 비교하겠습니다”에서는 구체적인 수행 안내가 시작된 sample을 사용한다.
- 첫 chunk 생성, codec packet, playback enqueue와 실제 장치 출력은 구별한다.
- 실질적 내용이 확인되는 발화 구간의 시작을 사용한다. 문장 전체를 말한 끝까지 기다리지 않는다. 식별할 수 없게 중단된 첫 소리만으로 종료하지 않는다.
- 잘못된 대상이나 완료 주장을 말했어도 실질적 응답이면 실제 시각과 오류를 남긴다. 후속 정답의 시각으로 덮어쓰지 않는다.

## 3. 일반 상황과 차례 대기 상황의 사전 구분

**NORMAL과 WAIT는 후보 실행 전에 공통 입력 일정, 앞 응답과 차례 정책으로 지정한다. 실행 결과에서 대기가 0이었던 건만 골라 별점을 매기지 않는다.** 두 대안은 같은 사례 ID와 분모를 사용한다.

| 구분 | 사전 조건 | 보고와 채점 |
| --- | --- | --- |
| NORMAL | 입력/사건 이후 응답 차례를 막는 추가 사용자 발화나 앞 응답 재생을 배치하지 않음 | 실제 첫 음성 지연 평균 L과 2초 기준 별점 |
| WAIT_USER | 응답할 사건 이후 사용자가 말해 차례를 기다리는 상황 | 총 실제 지연, 사용자 발화 대기, 대기 종료 후 추가 지연 |
| WAIT_PREVIOUS | 앞선 응답을 재생하는 동안 새 입력/Agent 사건이 발생 | 총 실제 지연, 앞 응답 대기, 선행 준비 여부와 대기 종료 후 추가 지연 |
| WAIT_BOTH | 두 차례 대기가 겹치거나 이어짐 | 두 원인의 구간과 합집합을 중복 없이 보고 |

모델 슬롯 부족, 내부 큐, 네트워크, 의미 채택과 음성 생성의 지연은 차례 대기가 아니다. NORMAL에 그대로 포함한다. 후보가 불필요하게 앞 응답을 늘려 NORMAL에서 차례 충돌을 만들면 그 실행을 WAIT로 옮기지 않는다. 원래 NORMAL 분모와 실제 지연을 유지하고 후보가 만든 충돌을 기록한다. 공통 fixture 자체의 조건이 잘못됐다면 양안에 동일한 수정 판본을 적용한다.

Voice 입력 외에 음성 응답 대상 Text와 전달 의무 Agent 통지를 포함할 수 있다. 음성 의무가 없는 사례와 정상 철회는 사전 규칙에 따라 관리한다. 미출력 때문에 음성 의무 사례를 빼지 않는다. 사건 병합/정정 시 각 사건과 실제 해당 내용 구간을 연결하며 하나의 음성 시작 시각을 모든 사건에 복사하지 않는다.

기존 24입력, 120×5, 109×5를 새 분모로 자동 계승하지 않는다. NORMAL/WAIT 각각의 사건 ID, 종류, 음성 의무, 사례 수와 반복 수를 manifest에 기록한다. WAIT가 핵심인 DP도 관련 대기 결과를 반드시 별도로 제시한다. 별점 대상이 아니라는 이유로 해당 설계 효과를 숨기지 않는다.

## 4. 산식과 별도 보고

```text
s_i = 입력/사건 시작
v_i = 첫 실질적 음성의 실제 출력 시작
l_i = v_i - s_i
L = sum(l_i for i in NORMAL) / N_NORMAL
```

WAIT에서도 l_i는 대기를 포함한 실제 경과시간으로 보존한다. 추가 진단은 다음과 같다.

```text
U_i = [s_i, v_i) 중 사용자 발화 때문에 출력이 금지된 구간
P_i = [s_i, v_i) 중 앞 응답 재생 때문에 출력이 금지된 구간
B_i = duration(U_i union P_i)
E_i = l_i - B_i
R_i = 첫 실질적 음성 직전에 마지막 차례 대기가 끝난 시각부터 v_i까지
```

U/P의 길이와 교집합, 합집합 B를 함께 기록한다. E는 대기가 아니었던 전체 구간의 합이고 R은 마지막 대기 종료 뒤 남은 지연이므로 둘이 항상 같지는 않다. 여러 대기 사이의 준비 가능 구간과 실제 생성/출력 타임라인을 보존한다. `l = B + E`이며 생성이 B와 겹칠 수 있으므로 생성시간과 차례 대기를 다시 더하지 않는다. WAIT의 E를 가상의 NORMAL 측정값으로 사용하지 않는다.

최초 내용 채택 시각 a_i 이후의 발화 가능 구간 `D_i = duration([max(s_i,a_i),v_i)에서 출력 가능한 구간)`도 진단으로 유지한다. 후보의 ready flag로 발화 가능 시각을 늦추지 않는다. D, B, E, R은 서로 더하거나 별점으로 변환하지 않는다.

DP 비교 표에는 **일반 상황 평균/별점**과 **대기 상황 총 지연/차례 대기/대기 종료 후 추가 지연**을 나란히 둔다. WAIT_USER, WAIT_PREVIOUS, WAIT_BOTH를 구별하고 비교 사례 수와 누락을 표시한다.

설명용 예: 사건 발생 뒤 앞 응답이 5초 동안 재생된다. A는 대기 중 준비하여 5초에 말하고 B는 대기 후 준비하여 6초에 말한다. WAIT 결과는 A 총 5초/B 6초, 차례 대기 각각 5초, 마지막 대기 뒤 추가 지연 A 0초/B 1초다. 두 값에 2초 기준 별점을 매기지 않는다. NORMAL의 별점은 별도의 사전 지정 일반 사례에서 계산한다.

## 5. 동일 조건과 실패 처리

입력, 원본, 사용자 발화 일정, 앞 응답의 필요한 내용과 길이, 우선순위, 기능 의무를 양안에 동일하게 준다. 각 구조의 선행 준비는 허용하며 비용과 메모리에 기록한다. 먼저 말하려고 사용자를 끊거나 필수 내용을 생략하면 기능 오류다.

미출력은 NO_AUDIO/NOT_OBSERVED, 계측 누락은 UNOBSERVABLE로 남긴다. 0초나 임의 timeout을 평균에 넣지 않는다. NORMAL과 WAIT 각각 예정 수, 유효 수, 실패와 정상 철회를 공개한다. 일부 관측 평균에는 전체 별점을 확정하지 않는다. 오답의 실제 시간은 포함하되 정확성/기능 오류를 함께 보고한다.

관측창과 반복 수는 사전에 고정한다. 정상 긴 차례 대기를 임의 timeout으로 실패 처리하거나 결과를 보고 관측창을 바꾸지 않는다. 분석값과 물리 관측 및 proxy는 구별한다.

## 6. 목표 근거

**음성 Agent 연구의 4초 참조값에서 지연시간 50% 단축을 목표로 정해 2초를 채택했다: `4.0 × (1−0.50) = 2.0초`.**

[Maslych 외, CUI 2025](https://arxiv.org/html/2507.22352v1)는 54명을 대상으로 1.5/4.0/6.5초 응답 조건을 비교했고 4초 미만을 지향하도록 권고했다. 이를 근거 자료로 삼고, 50% 단축은 VIA의 사용자 합의 개발 목표로 정했다. 50%는 해당 연구의 달성 결과를 뜻하지 않는다. [상세 근거](research-notes/qa01-voice-target-rationale.md)

1초는 음성 응답 선호 연구를 참고한 우수선으로 사용한다. 기존 화면 1초 목표는 위 새 도출 방식으로 대체한다.

## 7. 0~6점 — QA01-VOICE-score-v1

| 점수 | 원형 | 일반 상황 평균 L / 초 |
| --- | --- | --- |
| 0 | ○○○ | `L > 2.00` |
| 1 | ◐○○ | `1.80 < L ≤ 2.00` |
| 2 | ●○○ | `1.60 < L ≤ 1.80` |
| 3 | ●◐○ | `1.40 < L ≤ 1.60` |
| 4 | ●●○ | `1.20 < L ≤ 1.40` |
| 5 | ●●◐ | `1.00 < L ≤ 1.20` |
| 6 | ●●● | `0 ≤ L ≤ 1.00` |

2초가 목표 충족선, 1초가 우수선이며 사이를 `(2−1)/5 = 0.2초`씩 균등 분할한다. 반올림 전 평균으로 채점한다. 0점은 목표 미달이고 미측정은 점수를 부여하지 않는다. 중간 간격은 합의된 채점 규칙이다. 기존 혼합 모집단의 값과 점수를 새 NORMAL 점수로 재명명하지 않는다.
