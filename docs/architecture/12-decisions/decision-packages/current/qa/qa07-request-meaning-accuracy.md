# QA07 — 요청 의미 해석 정확도

[INTENT.md §4.1~4.2](../../../../../../INTENT.md)의 사용자 정의를 현재 QA 패키지에서 바로 읽고 편집할 수 있도록 정리한다. 새로운 목표나 점수표를 도입하지 않는다. [구판 QA07 부하 추가 지연](legacy/qa07-load-interference.md)은 이름과 의미 및 적용 판본이 다른 지표다.

| 항목 | 정의 |
| --- | --- |
| 이름 | 요청 의미 해석 정확도 |
| 평가 내용 | 무엇을, 어떤 대상으로, 어떤 조건에서 처리하며 기존 요청과 어떻게 연결하는가 |
| 평가 단위 | 사용자 입력 하나와 그 revision |
| 평가 시점 | VIA가 해당 입력의 필수 요청 의미를 처음 확정한 시점 |

| 제외 | 최초 의미 확정 뒤 인계 과정의 누락, Downstream Agent의 실제 업무 수행 품질 |
| 아직 합의하지 않은 것 | 핵심 QA 선정, 우선순위, 목표값, 0~6점 구간, 향후 실제 평가의 세부 실행 계약 |

## QA02와의 관계

“아까 두 견적을 설치비는 제외하고 비교해줘. 보고서 작성은 계속하고.”라는 입력에서 QA02는 견적 A와 B라는 지칭 대상 집합을 확인한다. QA07은 A와 B를 비교하고 설치비를 제외하며 기존 보고서 업무를 유지한다는 필수 의미를 모두 확인한다.

대상이 맞아도 설치비 제외를 놓쳤으면 QA02는 성공하고 QA07은 실패한다. 대상을 잘못 찾았으면 두 QA가 함께 실패할 수 있다. 같은 대상 오류와 개선을 독립적인 두 품질 효과로 부풀리지 않는다. 표현 수와 사용자 입력 수의 분모가 다를 수 있으므로 두 정확도 수치를 직접 환산하지 않는다.

여러 필수 항목을 보더라도 QA07은 **입력별 전체 충족 여부**의 단일 지표다. 의미 항목별 정답률의 평균으로 바꾸지 않는다. 누락된 항목은 원인 진단으로 따로 남긴다. 처음 올바르게 확정한 조건이 이후 인계에서 누락된 경우를 QA07 실패로 바꾸지 않는다.

## 현재 v3에서의 적용

[공통 계약 §2](../evaluation/common-qa-v3/01-common-contract.md#2-qa-의미와-관측-사건)는 집합, 순서, 대소문자, 누락/null/false/0의 비교 규칙과 최초 확정 경계를 정의한다. 해당 규칙은 현재 합성 원장의 판정 규칙이며 새로운 실제 모델 실행 계약을 동결했다는 뜻이 아니다.

Text는 240입력, Voice/Screen은 120입력, Delivery는 80입력을 각 구성의 분모로 사용한다. 이 분모들은 같은 workload의 합이 아니다. Delivery의 80/80은 올바른 의미를 공통 입력으로 공급한 제어 조건이며 DP44의 정확도 이익 근거가 아니다.

현재 값은 [v3 결과](../evaluation/common-qa-v3/03-results-and-decisions.md)와 [원장](../evaluation/common-qa-v3/artifacts/normalized-data.json)을 따른다. 모두 **가상 작성 평가**이며 실제 정확도 측정치가 아니다. 기존 QA01→QA06의 우선순위에 QA07을 임의로 삽입하거나 QA02를 대체하지 않는다.
