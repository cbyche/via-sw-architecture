## 1. 한눈에 보는 요구사항

- **정의 한 줄:** 시스템은 사용자가 요청한 업무의 선후 관계와 신규 또는 기존 업무 연결을 정확하게 판단해야 한다.
- **목표 지표:** 업무 순서와 연결의 전체 일치 정확도 **85% 이상**. 두 항목을 모두 맞힌 평가 입력 수 / 전체 평가 입력 수 × 100.
- **측정 조건:** 공통 시나리오에서 선정한 28개 업무 요청을 동일한 대화 이력과 업무 상태로 각각 5회 평가한다. 최초로 채택한 업무 순서와 신규/기존 업무 연결을 사전 정답과 비교한다.
- **목표 근거:** TaskBench의 GPT-4 2개 작업 그래프 전체 일치 정확도 **84.53%**를 정수 상향한 **85%**를 목표 수준으로 제안한다. SMCalFlow의 과거 요청 참조/수정 구조를 연결 평가 설계에 참고한다. [TaskBench, NeurIPS 2024, Table 10](https://proceedings.neurips.cc/paper_files/paper/2024/file/085185ea97db31ae6dcac7497616fd3e-Paper-Datasets_and_Benchmarks_Track.pdf), [SMCalFlow 공식 자료](https://microsoft.github.io/task_oriented_dialogue_as_dataflow_synthesis/).

**채점 항목은 두 가지다.**

| 항목 | 맞아야 하는 것 |
| --- | --- |
| 업무 순서 | 사용자가 지정한 먼저 할 업무와 나중에 할 업무. 독립적으로 요청한 업무에 불필요한 선행조건을 붙이지 않음 |
| 업무 연결 | 새 업무인지 기존 업무의 후속 요청인지. 기존 업무라면 어느 업무인지 |

업무 순서/연결을 모두 맞히면 해당 입력은 성공 1회다. 둘 중 하나가 틀리거나 필요한 연결을 빠뜨리면 실패 1회다. 항목별 점수 평균은 대표 지표로 사용하지 않는다.

## 2. 평가 범위

업무 순서는 사용자가 요구한 업무 사이의 관계다. 선행 결과로 다음 업무를 수행하라는 요청은 그 결과가 준비되어야 한다는 선후 관계를 포함한다. 이미 완료된 결과를 새 업무의 자료로 재사용할 뿐이면 이전 업무를 다시 실행해야 한다는 관계를 만들지 않는다.

업무 연결은 신규 업무와 기존 업무의 후속 요청을 구별하는 것이다. 기존 업무의 조회, 수정, 취소, 승인 답변은 해당 업무에 연결한다. 같은 Agent가 수행했거나 주제가 같다는 사실만으로 같은 업무라고 판단하지 않는다. 과거 업무 결과를 자료로 쓰더라도 별도 산출물을 새로 요청하면 신규 업무일 수 있다.

다음은 QA07 점수에 넣지 않는다.

- 기간, 금액, 출력 형식, 비교 기준 등 Downstream Agent가 해석하여 수행할 세부 업무 조건.
- Agent의 내부 계획, 도구 선택과 호출 순서, 최종 산출물의 품질과 실행 성공.
- 화면 대상 자체의 식별 정확도, 응답 문장의 정확성/자연스러움, 실제 음성 전달과 중단/재개 품질.
- 결과를 먼저 보여달라는 표시 형식과 업무 실행의 선후 관계를 혼동하지 않는다.

조건 원문을 보존해 전달하는 기능 요구는 유지한다. QA07에서 채점하지 않는다는 이유로 원문 전달 의무나 다른 QA를 제거하지 않는다. 기존 v3의 응답 구성/실제 전달 단계와 32사례 점수는 이 정의에 포함하지 않는다.

## 3. 정답과 최초 판단

평가자가 실행 전에 업무 요청의 각 절을 구분하고, 각 절에 `NEW` 또는 `EXISTING:<업무 ID>`와 필요한 선후 관계를 붙인다. 이 두 정보만 정답으로 비교한다. 특정 제품 JSON, Component, 내부 Task 개수를 강제하지 않는다. 새 업무의 임시 ID와 의미가 같은 내부 표현은 공통 adapter로 정규화한다.

- 여러 요청이 한 입력에 있으면 전부 맞아야 그 입력이 성공이다. 내부 Task/모델 호출 개수로 분모를 늘리지 않는다.
- 순서는 필요한 선후 관계의 집합으로 비교한다. A→B→C에서 A→C를 함께 쓰는 등 같은 추이 관계는 동등하다. 순환 관계, 필수 관계 누락, 반대 방향 또는 불필요한 선행조건은 실패다.
- 독립된 요청은 선후 관계 정답이 공집합이다. 자원 사정으로 실제 실행을 차례로 한 것과 의미 판단에서 선행조건을 잘못 추가한 것을 구별한다.
- 처음 실제로 채택/사용한 관계를 평가한다. 명시 commit 이전에 위임이나 상태 갱신에 사용했다면 그 사용이 최초 채택이다. 내부에서 폐기한 후보는 채점하지 않는다.
- 부분 채택을 하면 최초 사용한 부분과 이후 나머지 채택을 묶는다. 한 번 잘못 사용한 연결은 나중에 고쳐도 실패를 유지한다.
- 후속 입력이 이전 업무를 바꿀 때는 그 후속 입력의 첫 판단을 별도로 평가한다. 정정 전 올바른 연결을 정정 이후 기준으로 소급 오답 처리하지 않는다.

QA02는 사용자 지칭과 자료/화면/이력 대상의 일치, QA07은 요청의 업무 연결과 순서다. 같은 Task 지칭 오류가 두 QA에 영향을 주면 동일 원인 ID로 연결하며 두 독립 개선 효과로 합산하지 않는다.

## 4. 측정 단위와 종료

단위는 **업무 요청이 포함된 사용자 입력 하나 × 반복 하나**다. 전체 대화 수명, 출력 문장 수, Agent 사건 수는 분모가 아니다. 대표 모집단은 [정답 원장](qa07-order-link-population.json)의 28개 입력을 5회 반복한 **140회**다. **119회 이상 성공하면 85%**다.

대표 정확도 시험은 공통 사용자 원문 Text와 대화 이력 및 현재 업무 상태를 입력한다. 원전의 음성/Text 구분은 출처 필드로 보존한다. 음성 인식 결과나 화면 지칭 결과를 바꾸어 섞지 않으며 원음 기반 전체 제품 시험은 별도 진단으로 둔다. 시험은 외부 벤치마크와 마찬가지로 의미 구조 판단을 분리해 확인한다. 후보에게 정답 업무 연결을 제공하지 않는다.

시작은 해당 입력을 VIA에 제공한 시점, 종료는 그 입력의 업무 순서와 연결이 처음 채택되어 실제 처리 기준으로 사용된 시점이다. 입력 중 조기 사용이 있는 전체 제품 진단에서는 그 이력도 보존한다. 입력 제공 후 **60초**까지 판단이 없으면 누락 실패다. 60초는 무응답 판정을 위한 시험 한도이며 QA01/QA03 지연 목표가 아니다. 최종 사용자 답변이나 Agent 업무 완료까지 기다리지 않는다.

공통 선행 대화와 업무 상태를 각 반복 전 복원한다. 후보가 앞 입력을 잘못 처리한 결과 때문에 다음 입력의 출발 상태가 달라지는 연쇄 시험은 별도 진단이다. 요청 종류별/순서별 결과는 부록에 두고 전체 정확도는 하나로 제시한다.

## 5. 성공, 실패와 미관측

```text
N = 140
S = 업무 연결과 필요한 선후 관계가 모두 일치한 입력 반복 수
Q = 100 × S / N
```

| 상태 | 집계 |
| --- | --- |
| 두 항목의 최초 채택 결과 전체 일치 | PASS, 성공 1 |
| 연결/순서 오류, 누락, 근거 없는 추가 관계 | FAIL, 성공 0 |
| 완전한 관측에서 60초 동안 판단 없음 | FAIL, 성공 0 |
| 필요한 실제 채택 기록 또는 입력 제공 기록이 없음 | UNKNOWN. 성공/실패나 0점으로 추정하지 않음 |
| 공통 원본/정답 자체 결함 | 양안 공통 무효 처리 후 수정 판본으로 같은 입력 재평가. 원래 기록 보존 |

판정 불가가 남으면 전체 대표값과 별점을 확정하지 않는다. 성공 S, 실패 F, 미판정 U와 N=S+F+U를 함께 남긴다. 미판정 범위 `[100S/N, 100(S+U)/N]`는 부록 진단이며 확정 정확도가 아니다. 후보의 오답을 fixture 결함으로 제외하지 않는다.

## 6. 목표와 0~6점

목표 `Q ≥ 85%`, 점수 판본 `QA07-ORDER-LINK-score-v4`. 목표와 점수는 작성자 제안이며 사용자 최종 채택과 우선순위는 미합의다. 이름과 두 항목의 범위는 사용자 지시로 확정했다.

| 점수 | 표시 | 전체 일치 정확도 Q |
| --- | --- | --- |
| 0 | ○○○ | Q < 85% |
| 1 | ◐○○ | 85% ≤ Q < 88% |
| 2 | ●○○ | 88% ≤ Q < 91% |
| 3 | ●◐○ | 91% ≤ Q < 94% |
| 4 | ●●○ | 94% ≤ Q < 97% |
| 5 | ●●◐ | 97% ≤ Q < 100% |
| 6 | ●●● | Q = 100% |

100%는 등록한 입력 반복 전체 성공이라는 우수선이다. `(100−85)/5=3%p`로 구간을 나눈 작성자 규칙이며 논문이 검증한 합격선/점수 경계가 아니다. 반올림 전 비율로 채점한다. 이전 v3의 90%와 2%p 구간은 보존본에만 적용한다.

## 7. 근거 해석과 DP 적용

TaskBench는 도구 선택/의존 그래프, SMCalFlow는 값과 API를 포함한 대화 의미 프로그램을 평가한다. 현재 QA07과 동일한 시험은 아니다. 따라서 공개 숫자는 목표 수준을 정하는 참조이며 VIA가 같은 벤치마크에서 그 모델을 이겼다는 근거로 사용하지 않는다. 최신 최고 성능이라는 주장도 하지 않는다. 세부 비교와 harness 조건은 [조사 문서](research-notes/qa07-meaning-research.md)에 둔다.

DP2의 요청 해석과 DP5의 과거 업무 관계 복원이 직접 관련될 수 있다. DP3는 잘못된 지칭이 업무 연결로 전파되는 경로가 있을 때 관련된다. DP44는 현재 설계가 최초 순서/업무 연결 판단 자체에 영향을 주는 경우에만 적용하며, 이후 음성 큐의 취소/재개만 개선한다면 새 QA07의 차별화로 세지 않는다. 관련성이나 같은 정답 공급만으로 효과를 주장하지 않는다.

문서 경로는 기존 참조 호환을 위해 유지한다. 기존 v6/v7/v8 및 과거 v3 원장과 결과를 이 좁아진 QA의 관측으로 재명명하지 않는다. 새 적용은 `QA07-ORDER-LINK-v4`와 이 모집단을 사용한 별도 판본에서 수행한다.
