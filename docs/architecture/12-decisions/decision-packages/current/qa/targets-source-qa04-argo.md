# QA04 목표 근거: ARGO의 변경 PR 145건

> **현재 QA 자료의 이관본 (2026-10-22):** 출처, 원값, 목표 도출과 기존 검토 내용을 유지한다. 문서 안의 이전 DP, 모집단, 검토 상태는 해당 작성 세대에 한정한다. [현재 QA 기준과 적용 범위](README.md).


> 2026-10-14 사용자 제공 내부 분석 집계 / 현재 QA04의 수치 근거

## 제공된 분석과 목표

사용자가 이전 Agent 개발 과제 **ARGO**의 기능 추가와 데이터 형식 변경 PR **145건**을 분석한 평균 모듈 수정 수 **5.4개**를 목표 근거로 지정했다. 이 문서는 사용자 제공 집계와 개선 목표를 기록한다. 이 저장소에서 145개 PR 원문을 직접 열어 재분석한 결과로 표현하지 않는다.

| 항목 | 값 |
| --- | ---: |
| 분석 대상 | ARGO 기능 추가 및 데이터 형식 변경 PR 145건 |
| 기존 평균 수정 모듈 수 | 5.4개/PR |
| 개선 요구 | 기존 대비 40% 이상 감소 |
| 40% 감소 시 수치 | 5.4 × (1 − 0.40) = **3.24개** |
| VIA의 운영 목표 | **변경 과제당 평균 3개 이하** |
| 3개 달성 시 감소율 | (5.4 − 3) / 5.4 = **약 44.4%** |

3.24에서 3으로 정한 것은 평균값이 정수여야 해서가 아니다. **40% 개선 요구를 만족하는 더 엄격하고 간명한 운영 목표**로 사용자가 선택한 값이다. 숫자 40%는 논문의 발견이 아니라 이번 과제의 개선 요구다.

## 발표용 문장

**기존 Agent 개발 과제 ARGO의 기능 추가와 데이터 형식 변경 PR 145건에서 평균 5.4개 모듈을 수정했으므로 40% 이상 개선한 평균 3개 이하를 목표로 한다.**

작은 산식은 `5.4 × 60% = 3.24 → 목표 3개`로 표시한다. 3개가 정확히 40% 감소라고 말하지 않는다.

## 비교와 증거의 경계

VIA의 새 평가에서는 [QA04의 Rust 모듈 집계 규칙](qa04-change-scope.md#3-rust-모듈을-어떻게-세는가)을 사용한다. ARGO 집계의 원자료를 발표 증빙에 첨부할 때 다음을 함께 기록해야 실제 개선율을 재현할 수 있다.

- PR 목록과 분석 기간 및 기능 추가와 데이터 형식 변경의 분류
- 하나의 PR에 여러 독립 변경이 섞였는지와 하나의 변경이 여러 PR로 나뉘었는지
- 모듈의 식별 기준과 테스트 전용 및 자동 생성 코드의 처리
- PR별 수정 모듈 집합과 원시 평균. 5.4는 제공된 표시값이며 역산해 정수 총합을 만들어 넣지 않음

현재 확인 가능한 것은 사용자 제공 145건과 평균 5.4 및 40% 개선 지시다. ARGO의 모듈과 VIA의 Rust 모듈이 같은 단위인지 확인하기 전에는 **VIA가 실제로 44.4% 개선됐다는 실적**을 주장하지 않는다. 목표 설정과 개선 실적은 구분한다.

이전 [VIA Rust 수정 1개와 3개 선례](targets-source-qa04.md)는 실제 모듈을 세는 예시로 보존한다. 현재 3개 목표의 수치 근거는 ARGO 집계다.
