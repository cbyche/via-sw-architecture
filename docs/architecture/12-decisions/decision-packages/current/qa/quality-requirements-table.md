## 현재 요구사항

| ID | 요구사항명과 한 줄 정의 | 대표 지표 하나 | 목표와 상태 |
| --- | --- | --- | --- |
| [QA01](qa01-first-response-latency.md) | **첫 응답 지연시간**: 음성 전달이 필요한 입력/사건에 첫 실질적 음성을 빠르게 시작한다. | NORMAL의 첫 음성 시작까지 산술평균 초 | **2초 이하**, 목표/점수 합의. WAIT 별도 보조 결과 |
| [QA02](qa02-referent-accuracy.md) | **지칭 대상 식별 정확도**: 사용자가 가리킨 대상 집합과 범위를 정확히 찾는다. | 최초 대상 집합 완전 일치율 % | 93% 이상 제안, 기존 점수 유지 |
| [QA03](qa03-via-processing-time.md) | **VIA 처리시간**: 한 목표의 필수 상태/연동 처리와 최종 응답 준비를 빠르게 끝낸다. | 목표별 VIA 처리 경로의 산술평균 초 | **5초 이하**, 목표/점수 합의 |
| [QA04](qa04-change-scope.md) | **기능 및 연동 변경의 파급 범위**: 같은 기능/연동 변경을 적은 운영 모듈 수정으로 완료한다. | 공통 8개 변경 과제의 변경 모듈 수 평균 개 | 3개 이하 제안, 구간 유지. 새 과제 결과 미산출 |
| [QA05](qa05-model-cost.md) | **모델 사용 비용**: 동일 활동의 준비부터 후속 처리까지 청구 모델 비용을 줄인다. | 활동 묶음당 평균 총 모델 비용 USD | COMMON-28 묶음 **$2.55 이하 제안** |
| [QA06](qa06-local-memory.md) | **최대 RAM 사용량**: 로컬 모델을 포함한 VIA 전체 제품의 RAM 부담을 줄인다. | VIA 전체 실제 RAM 최고량 MB | 사용자 지정 **512 MB 이하** |
| [QA07](qa07-request-meaning-accuracy.md) | **업무 순서 및 연결 정확도**: 시스템은 사용자가 요청한 업무의 선후 관계와 신규 또는 기존 업무 연결을 정확하게 판단해야 한다. | 업무 순서와 연결의 전체 일치 정확도 % | **85% 이상 제안**, 공통 시나리오에서 선정한 28개 입력 × 5회, QA02와 별도 유지 |
| [QA08](qa08-on-device-model-memory.md) | **온디바이스 모델 추가 메모리 최소화**: 추가 로컬 모델 실행에 필요한 전체 메모리를 줄인다. | 추가 모델 경로의 동시 메모리 최고량 GB | 사용자 지정 **1 GB 미만** |

총 **8개**다. 유형별 세부 결과는 [부록](measurement-appendix.md)에 둔다. QA02/07은 전체 성공 수를 해당 전체 분모로 나눈 숫자 하나를 사용하며 유형별 비율 평균을 사용하지 않는다. QA04의 [변경 과제와 완료 조건](change-scenarios.md)은 모든 비교안에 공통 적용한다. QA07은 v4의 좁아진 사용자 지정 범위에 맞춰 TaskBench 공개 성능을 참조한 85% 목표와 평가 절차 및 점수를 제안했다. 실제 측정값은 만들지 않았다.

## QA01과 QA03의 시작과 끝

| 구분 | QA01 첫 응답 지연시간 | QA03 VIA 처리시간 |
| --- | --- | --- |
| 쉽게 말하면 | 말을 마친 뒤 첫 실질적 음성이 들리기 시작할 때까지 | 한 목표에서 VIA가 맡은 처리와 최종 응답 준비를 모두 끝낼 때까지의 VIA 처리시간 |
| 시작 | 사용자 발화 종료 / 음성 응답 대상 Text 제출 / 알릴 Agent 사건의 외부 최초 제공 가능 시각 | 목표를 시작한 최초 사용자 발화 종료 또는 Text 제출 |
| 끝 | 첫 실질적 내용의 실제 음성 출력 시작 | 필수 상태 확정, 외부 연동 확인과 최종 응답의 모든 필수 채널 준비 완료 |
| 포함/제외 | NORMAL에서 입력 판단, 해석, 모델과 내부 큐, 음성 생성과 장치 출력까지 포함. 차례 대기 사례는 WAIT 별도 | VIA 모델/내부 대기 포함. Agent 내부 업무, 사용자 응답/발화와 순수 재생/차례 대기 제외. 병행 VIA 처리는 보존 |
| 첫 안내 뒤에도 남는 의무 | 첫 음성이 시작되면 해당 사건 종료 | 결과 수신과 상태 반영, 나머지 답변/전체 음성 준비까지 이어짐 |

QA03은 단순히 전체 경과시간에서 외부 시간을 빼지 않고 실제 직렬/병렬 관계를 반영한다. 각 상세 명세의 산식과 누락 처리 규칙을 따른다.

## 발표 반영 상태

QA01/QA03의 목표와 점수는 합의됐다. 발표자료는 별도 작업이다. QA09 독립 행과 점수는 사용하지 않는다. 차례 대기는 QA01 WAIT의 별도 결과로 해당 DP에 표시하고 일반 상황 별점과 구별한다. 기존 v4 수치, 발표 v10과 예전 점수표를 새 계약으로 재명명하지 않는다.

기존 선택 순서는 QA01→QA02→QA03→QA04→QA05→QA06이며 QA07/QA08의 삽입 순위는 합의 전이다. QA01/QA03이 실제 대표 사례에서 중복되는지는 향후 같은 사례의 결과와 처리 경로로 확인한다. 사용자가 수치 담당 세션의 갱신을 요청했으며 실제 전달 상태는 [공통 계약](timing-measurement-contract.md)을 따른다.
