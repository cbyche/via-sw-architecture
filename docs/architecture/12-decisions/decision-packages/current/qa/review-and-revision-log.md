# QA 후보 패키지 검토와 보완 기록

> **이관한 원전 이력:** 본문의 현재, 최신, 실측 전, 검토 완료는 원래 날짜와 대상 범위의 기록이다. 현재 네 DP의 정본 상태와 결과는 [QA 기준 안내](README.md) 및 [공통 QA v3](../evaluation/common-qa-v3/README.md)에서 확인한다. 이 기록을 최신 실측 또는 현재 설계 승인으로 계승하지 않는다.


> 2026-10-15 / 문서 검토 기록 / 사용자 검토본 / 구현과 모델 호출 및 Windows 측정 없음
> 최신 QA06 시스템 요구사항과 아홉 페이지 원고 및 독립 검토는 §15를 따른다. 공통 시나리오 통합은 §14를 따른다. 이전 회차의 완료는 그 당시 범위에 한정한다.

## 1. 완료한 범위

- 기존 여섯 QA와 추가 세 후보에 정의, 단일 지표, 경계와 실패 처리, 구체적 목표와 도출 근거, 0~6점, 가상 예시, DP별 예상 한 문장, 최소 PoC와 발표 한 장 문안을 작성했다.
- 작성 에이전트와 별개의 **독립 검토 에이전트 세 명**이 측정, Architecture 관계, 변경, 자원, 채점의 관점으로 검토했다. 인간 전문가 심사나 외부 기관 인증을 받았다는 의미는 아니다.
- 독립 검토의 중복을 제거하면 **P2 8건**을 발견했고 모두 수정 후 재확인했다. QA07의 비선형 집계 단위도 추가로 명확히 했다. 검토 범위에서 미해결 P1/P2는 없다.
- 측정 리뷰는 3차까지, 구조와 자원 리뷰는 각각 2차까지 진행했다. QA1은 전체 재독 후 실제 관측 오차의 추가 결함을 발견해 다시 수정했다.

**완료하지 않은 것은 문서 결함과 구별한다.** 목표의 제품 승인, 모델 달성 가능성, 실제 Rust 변경 수, Windows 계측 정확성, DP별 성능 차이와 핵심 구성의 최종 선정은 후속 단계다. 문서 리뷰가 이 사실을 대신 입증하지 않는다.

## 4. 자체 검수와 정적 검사

```text
python3 scripts/architecture/check_qa_candidate_package.py
git diff --check
```

점수 검사는 9개 QA의 실제 Markdown 점수표에서 구간을 읽어 **237개 검증점**의 중복, 공백, 단조성, 원형 표시를 확인한다. 정확도는 0~100%, 다른 수치는 비음수의 유한 영역으로 제한한다. 예시의 주요 산술과 패키지의 로컬 파일 링크도 검사한다. 별도로 현재 문서의 로컬 heading anchor를 대조했다.

이 검사는 QA 구현이나 PoC가 아니다. `+∞`, 계측 실패, 기능 자격 판정은 본문과 독립 리뷰에서 확인했으며 자동 validator가 전부 실행하는 규칙인 것처럼 말하지 않는다. 외부 URL의 현재 접근성, 숫자의 제품 적합성, 실제 대안 우세나 모델 동작을 검사하지 않는다.

## 5. 리뷰로 바뀐 구성 판단

- 지칭 집합 정확도를 47, 45에 같이 적용하는 **측정 의미는 타당**하다. 강한 대안이 둘 다 정답에 도달할 수 있으면 정확도 차이는 별도 입증이 필요하다.
- 47의 B가 원본, 경쟁 후보, 확장 경로를 갖고 A도 부분 정정을 할 수 있으므로 정확도 우세를 구조 이름으로 정하지 않았다.
- 44의 단계 직접 연결이 짧은 async dispatcher보다 체감 수준으로 빠를지는 약한 가설이다. QA1과 QA3를 합산해 같은 이익을 두 번 크게 만들지 않는다.
- 42의 업무 접수 왕복은 위임 전 첫 안내 뒤에 올 수 있으므로 QA1의 자동 손해로 세지 않았다.
- 추가 07, 08, 09도 현재 네 DP의 빈칸을 메우는 확정 핵심 QA로 승격하지 않았다.

**최종 전달 상태:** QA 후보의 상세 문서와 독립 검토, 보완 완료. 목표, 점수, 모집단은 사용자 검토용 제안. QA–DP 최종 구성 조건은 아직 미충족. 구현, 실측, 최종안 선정으로 이어가기 전에 강한 대안의 실제 손익을 보강해야 한다.

## 6. 게시 검증 보완

2026-10-14 사용자가 commit/push를 요청했다. 첫 게시 CI에서 03-02 원문에 추가한 재검토 안내가 기존 원본 해시와 연결된 계산 명세, 발표자료의 검사를 실패시키는 것을 확인했다. 03-02 원문은 이전 계약의 해시를 유지하도록 보존하고 최신 검토 안내는 루트 README, decision-packages README와 03-03에서 관리한다. 기존 계산값, 발표자료, 보관 증거를 변경하지 않았으며 공통 활동, 참조 계산과 두 발표자료의 검사가 통과했다. 새 QA 후보의 문서 점수, 링크 검사도 `architecture-ci`에 추가했다.

## 7. 기본 탑재 관점의 메모리 목표와 발표 문구 보완

2026-10-14 사용자는 QA04의 추상 용어를 풀어쓰고 가운데 점을 제거하며 QA06의 임의 RAM 분할 근거를 교체하도록 요청했다. 내부 메모리 허용 기준이 없다고 답했고 제품 통합 담당자 입장에서 목표를 도출하도록 요청했다.

- QA04를 데이터 형식 변경 3건과 기능 확장 3건으로 설명하고 “기준선”을 “변경 전의 같은 코드 버전”으로 바꿨다. 평가하는 여섯 변경의 기능과 평균 3개 목표는 유지했다.
- 품질 요구사항 표와 이번에 함께 수정한 설명 문서의 가운데 점을 제거했다. 이전 독립 리뷰 원문과 보관된 세대는 당시 기록을 유지한다.
- Galaxy Book6 Ultra NP960UJH-XG3IN의 공식 사양을 다시 확인했다. 기존 4GiB 임의 배분은 [이전 기록](../../../../../archive/qa06-before-preload-budget-20261014/README.md)으로 보존했다.
- QA06의 단일 확보량 지표는 유지하며 현재 RAM 상주량과의 차이를 쉬운 설명으로 추가했다. 실제 화면 크기와 내부 보관 상한으로 1GiB 제품 목표안을 도출했다.
- 화면 입력을 2880×1800으로 바꾸고 QA05의 공통 실행 조건과 MEM-v2 점수 및 예시를 동기화했다. 과거 결과를 새 기준으로 재사용하지 않는다.
- 별도 에이전트의 조사 검토 후 수정본을 다시 검토했다. 남은 P1/P2는 보고되지 않았으며 “요구”를 “권고”로 고친 문구 보완까지 반영했다. [독립 검토 기록](reviews/preload-memory-revision.md)

문서 검사에서 9개 QA의 237개 점수 검증점과 로컬 링크 및 새 화면과 음성의 산술을 확인했다. 실제 Windows 측정이나 제품 목표 승인은 아니다.

## 8. 목표 산식 철회와 실제 RAM 지표로 개정

2026-10-14 사용자는 QA04의 형식 변경 1개와 기능 확장 5개의 이유를 물었고 QA06의 확보량 대신 동작 중 실제 RAM 최고량과 기본 탑재 제품의 허용 기준을 요구했다.

- QA04의 두 가정은 실제 Rust 수정 목록에서 도출되지 않았다. 평균 3개와 CHG-v1 점수를 철회하고 지표와 C01~C06은 유지했다. 목표 재설정 중임을 상세안과 두 요약 표 및 중심 문서에 반영했다.
- QA06의 MEM-v2 1GiB 내부 예산 합산과 점수를 철회했다. 새 지표는 VIA 전체 RAM 관측 최고량이며 512MiB를 클라우드 후보 조건의 제품 정책안으로 제안했다. 공식 앱별 할당량이나 실측 적정값이라고 표현하지 않는다.
- 16GB 삼성 제품을 기준 장비에 포함할 것을 제안하고 8GB 구성도 있음을 밝혔다. 16GB가 삼성 노트북의 최저 사양이라는 주장을 하지 않는다.
- WPR Resident Set의 단일 스냅샷과 공유 페이지 귀속 한계를 확인했다. 전체 RAM의 연속 관측과 공유 중복 및 그래픽 귀속을 미확정 상태로 기록했다. 기존 확보량 결과나 점수를 새 RAM 값으로 바꾸지 않는다.
- 이전 상세 문서를 [보관](../../../../../archive/qa04-qa06-before-ram-peak-20261014/README.md)하고 정적 검사는 7개 점수표와 2개 명시적 보류 상태를 구별하도록 변경했다. 검사 통과를 아홉 QA의 목표 완성으로 표현하지 않는다.
- 독립 검토자는 이전 검토가 산술과 문서 일치에 치우친 점을 인정했다. [재검토와 보완 기록](reviews/ram-peak-and-change-target-review.md)에 의견과 남은 작업을 보존한다.

제품 목표의 타당성이나 실제 Windows 계측 및 DP의 우열을 새로 입증한 것은 아니다. 근거가 부족한 목표와 채점을 현행 문서에서 철회하는 보완을 수행했다.

## 15. QA06의 512 MB 요구사항과 아홉 QA 페이지 원고

2026-10-15 사용자는 QA06 목표를 **512 MB**로 지정하고 PC 플랫폼 및 기술기획 측 시스템 요구사항으로 기록하도록 했다. [SR-PC-MEM-01](targets-source-qa06-platform.md)에 과제 요구의 직접 출처와 범위를 남겼다. 실제 조직의 별도 승인 문서를 확인했다고 표현하지 않는다. 512 MB는 정확히 512,000,000바이트이며 이전 512MiB와 구별한다. 목표의 절반인 256 MB를 최고 개선 등급으로 두고 51.2 MB 간격의 RAM-v3-MB 표를 작성했다.

QA06 상세와 목표 논리 및 조사 기록과 전체 두 표와 탐색 문서를 동기화했다. [아홉 QA 한 장 원고](slide-page-plan.md)에는 각 페이지의 상단 표와 목표 근거 및 산식과 예시 및 전체 0~6점 표를 직접 수록했다. 다른 파일을 조합해야 했던 내용을 페이지별로 모았다. 이전 판본은 [archive](../../../../../archive/qa06-before-platform-budget-20261015/README.md)에 보존했다.

[두 검토자의 독립 리뷰](reviews/platform-memory-and-page-manuscript-review.md)에서 QA01 경계와 QA03 완료 및 제외 항목과 QA07 실패 판정의 P2 3건을 발견해 수정했다. QA09의 전체 실패 점수도 명확히 했다. 수정 후 두 검토자는 각 담당 범위에서 미해결 P1/P2가 없다고 보고했다.

정적 검사는 9개 QA와 9개 점수표의 237개 경계 및 아홉 페이지의 상단 표와 점수 투영을 확인했다. 공통 원장과 비용 계산 및 active 링크와 용어와 QA catalog 검사도 통과했다. PPT 파일과 레이아웃 검증 및 실제 계측과 PoC는 별도다. QA06의 목표 확정을 실제 달성으로 보고하지 않으며 QA07~09는 설계 예산 제안 상태를 유지한다.

## 2026-10-22 새 QA07 요청 의미 해석 정확도 상세화
