## 1. 모집단 도출

[원전 JSON](../scenarios/common-28-v1/common-scenarios.json)의 사용자 입력 84건을 재사용 후보로 대조했다. 원전의 모호 입력 4건은 확인 기능 회귀, 나머지 80건은 정량 평가 후보로 분리한다. **기존 입력의 정답 응답 문장을 QA07 정답 object로 복사하는 작업은 아직 하지 않았다.** 응답 내용에는 실제 업무 결과까지 포함될 수 있으므로 요청 의미에 해당하는 부분을 구별해 전체 의미 oracle을 작성해야 한다.

## 2. 모호함과 실패를 나누는 기준

제외는 후보 실행 전에 제공된 근거로 필수 의미를 결정할 수 있는지에 따라 정한다. 원전의 네 사례는 다음 확인이 필요하다.

| 입력 | 불확정 내용 | 기능 회귀에서 요구할 행동 |
| --- | --- | --- |
| S06-U02 | 우연한 포인터 이동만으로 D1/D2 확정 불가 | 대상을 물으며 임의 대상을 확정하지 않음 |
| S09-U01 | 선택과 포인터 충돌, 정리의 답변/파일 형식 불명확 | 대상과 처리 형식을 확인하고 필요 없는 파일을 만들지 않음 |
| S20-U01 | 여러 Agent 질문 중 “응”의 대상 불명확 | 어느 질문에 대한 답인지 확인 |
| S26-U05 | 여러 발송 중 “응”이 승인하는 범위 불명확 | 승인 대상을 확인하며 임의 송신 허가로 채택하지 않음 |

자료 내용이 없거나 권한이 없다는 것과 사용자 요청 의미가 모호하다는 것은 다르다. S28의 F404 내용 조회는 요청 자체가 명확하므로 포함한다. 자료의 실제 내용과 업무 완료를 맞혀야 한다는 정답을 만들지 않는다. S26의 동의 요청도 사용자 의미와 실제 접근 권한을 구별한다. 의미가 명확한 실패 사례를 후보 결과를 본 뒤 제외하지 않는다.

## 3. 전체 의미 oracle 작성 규격

각 정량 입력에 다음 필드를 작성한다. JSON schema 구현이 아닌 평가 원장의 요구사항이다.

| 필드 | 기록할 내용 |
| --- | --- |
| `case_id`, `input_revision`, `repeat_id` | 원전 U-ID, 의미 판본, 반복. 내부 호출 ID와 구별 |
| `source_refs`, `context_revision` | 입력 원음/Text, 원본 화면/선택/포인터, 허용된 대화와 Task 상태 |
| `presentation_refs` | 이 입력 전에 실제 보거나 들은 내용과 범위. 생성됐지만 전달 안 된 내용과 구별 |
| `required_meaning` | 작업, 역할별 대상, 조건/제외, 순서/의존, Task 연결과 유지 조건 |
| `forbidden_additions` | 작업/대상 추가, 부정 반전, 임의 취소나 영속 선호 변경 등 의미를 바꾸는 해석 |
| `equivalence_rules` | 허용 동의 표현, 단위, 집합과 순서, 판본 동등성 |
| `eligibility`, `reason` | 정량/확인 회귀, 판정 근거와 필수 채택 여부 |
| `deadline`, `trigger` | 실제 입력 종료 기준 30초, 원전 사건과 연결한 시간 관계 |
| `adoption_refs` | 부분/전체 최초 확정, UI/전달 기록과 후속 수정 이력 |
| `outcome`, `error_tags` | 성공/실패/관측불능/무효, 오류 원인과 평가자 합의 |

후속 의미의 기준은 사용자가 실제 제공한 입력과 관측할 수 있던 문맥이다. 후보의 앞선 오답을 새로운 사용자 의도로 취급하지 않는다. 앞선 응답 차이로 후속 입력의 의미가 달라질 수 있는 사례는 실제 표시/청취 범위에 대한 동일 oracle 규칙을 먼저 정한다. 대안마다 평가자가 그때그때 다른 정답을 만들어서는 안 된다.

### 의미만 평가하는 예

`S17-U05`: “보고서는 계속 만들고 메일 보내는 건 취소하고 이 문단은 설명해줘.”

- 필수 의미: TR 업무 유지, TM 메일 발송 취소 요청, DOC-A P1 설명, 세 지시를 올바른 대상에 연결.
- 오답: TR도 취소, TM 대신 다른 메일 취소, 설명 대신 파일 수정, 일부 지시 누락.
- 점수 밖: 실제 취소 성공 여부와 문단 설명의 도메인 사실 정확성. 이 실패들은 해당 기능 계약에 별도 기록.
- 판정: 세 지시와 관계가 모두 맞아야 1. 두 지시만 맞았다는 이유로 2/3점을 주지 않음.

`S08-U02`는 보존 표를 T1/T3로 바꾸면서 P2 수정은 유지해야 한다. 새 대상만 맞추고 유지 조건을 누락하면 실패다. 실제 파일 수정이 끝났는지를 QA07 종료점으로 기다리지 않는다.

## 4. 비교와 보고 규격

전체 공통 회귀는 400판정이다. DP별 좁은 PoC는 이 목록에서 실제 의미 확정에 영향을 주는 입력을 선택하고 원전 U-ID, 포함 이유와 모든 비교안의 같은 분모를 실행 전에 고정한다. 이 문서가 각 DP에 400건을 무조건 독립 실행하도록 요구하는 것은 아니다. 같은 공통 실행을 재사용하면 `source_execution_key`를 남기고 중복 표본으로 세지 않는다.

보고 항목은 예정/유효/무효/미실행 입력 수, 성공/실패/미관측 수, 전체 일치율과 점수, 시나리오 및 복합성별 원값, 오류 유형, 같은 입력에서 A만 성공/B만 성공한 건수다. 통계 유의성 없이 작은 차이를 구조적 우위로 선언하지 않는다. 판정자 불일치 건수와 조정 결과도 남긴다.

## 5. 실행 전 남은 작업과 호환성

- 원전의 80입력 각각에 전체 의미와 금지된 추가 의미를 작성하고 두 평가자가 검토한다. 문서에 있는 필수 응답을 그대로 의미 정답으로 전용하지 않는다.
- WAV, 화면, 현재/과거 원본과 실제 전달 이력을 준비하고 권한 및 시각 관계를 확인한다. 입력 종류별 계측과 최초 채택 adapter를 검증한다.
- 원전에 완료가 필요하지 않은 중간 판본이 있는지 확인하고, 후보 실행과 무관한 사전 규칙으로 처리한다. 변경 시 모집단 판본과 이유를 기록한다.
- 장비, 모델, 예산, 반복 순서, 기한, 후보/평가자 데이터 분리와 산출물 경로를 manifest에 고정한다. 이번 문서 작성은 실제 실행 승인이 아니다.

기존 v3의 240/120/80입력 및 작성한 정확도 수치는 유지한다. 현재 제안의 80입력은 Delivery의 80입력과 다른 집합이다. 다른 작업에서 작성 중인 새 평가 corpus에도 이 400분모를 자동 적용하지 않는다. 공통 의미는 유지하되 해당 corpus의 입력 ID, 자격, 실제 최초 출력과 계약 호환성을 별도로 확인해야 한다.
