## 1. 모집단을 요청 처리 사례로 다시 구성

새 단위는 사용자 입력 개수가 아니라 **시작 요청부터 연결된 후속 입력/Agent 사건과 응답 의무까지 묶은 사례**다. 분할/병합은 실행 전에 공통 사용자 목표와 의미 관계로 정한다. 내부 Task/Request 개수에 종속시키지 않는다.

기존 공통 v4의 24입력은 최초 의미 oracle의 출처다. 원전 COMMON-28의 84입력에서 4개를 제외한 80후보와 5회 반복 제안 역시 이전 계획이다. 어느 숫자도 새 분모로 자동 적용하지 않는다. 30초 해석 기한도 새 사례 전체의 기한으로 사용하지 않는다.

1. 시작 입력을 선정하고 그 안의 요청 묶음과 최초 해석 checkpoint를 기록한다.
2. 후속 정정/명확화/승인/거부/취소/재개 입력을 같은 사례에 연결한다. 독립 새 요청은 별도 사례로 만들고 공유 맥락은 링크로 유지한다.
3. Agent 진행/질문/결과/실패/취소 사건을 발생 요청에 연결한다. source 시각, VIA 제공 가능 시각과 수신 시각을 구별한다.
4. 각 상태에서 필수/허용/금지되는 응답 의무와 채널을 작성한다. 하나의 출력이 여러 요청을 다루면 의미 구간별 obligation_id를 연결한다.
5. 마지막 필수 사건과 전달/폐기 조건 및 늦은 재전달 확인 구간까지 유한한 관측창을 지정한다.
6. 입력 수, 해석 checkpoint 수, 응답 의무 수와 최종 사례 수를 각각 공개하고 모든 후보에 같은 manifest를 적용한다.

## 2. 필수 원장

| 필드 묶음 | 내용 |
| --- | --- |
| 식별 | case_id, source_case_id, root_input_id, repeat_id, source_execution_key, 공통 계약/fixture 판본 |
| 원본과 문맥 | 원음/Text, 화면/선택/포인터와 원본 판본, 실제 전달 이력, 시작 시점 Task/요청/권한 상태 |
| 관계 | request_id, revision_id, corrects/clarifies/cancels/resumes/independent_of, Agent event와 response/obligation 연결 |
| 시간 | source 발생, 계약상 제공 가능, 로컬 수신, 최초 부분/전체 확정, 응답 채택, 각 실제 출력 구간 |
| 최초 해석 | checkpoint별 필수 의미, 금지된 추가 해석, 근거 범위와 허용 동등성 |
| 응답 구성 | obligation_id, 대상 요청/판본, 필요한 의미/근거/상태, 가능한 질문/요약/거부/대체/병합 경로 |
| 실제 전달 | 필수 채널/수신자, 내용 구간과 출력 증거, 중단/재개 위치, 완료/폐기, 중복/금지 전달 |
| 관측 종료 | 마지막 필수 source 사건, 의무별 기능 기한, 후속 금지 전달 점검 구간, 시험 종료조건 |
| 경합 | 취소/정정/완료와 출력의 순서, clock 오차, 공통 중단/전파 허용 정책과 미정 여부 |
| 판정 | PASS/FAIL/UNKNOWN/INVALID, 최초 위반, 원인 범주, 전파 관계, evaluator 판단과 증거 참조 |

특정 JSON 구조나 새로운 제품 Component는 강제하지 않는다. adapter는 후보 표현을 공통 의미로 옮기되 oracle에서 빠진 내용을 채워 주지 않는다. 전 단계가 정답으로 주어진 fixture라면 그 사실을 기록하고 해석 능력을 평가했다고 설명하지 않는다.

## 3. 전달 시점의 정답

유효 상태는 후보가 응답을 생성한 시점과 실제 전달한 시점 각각에 판단한다. 사전 정의한 사건 순서와 제공 가능 범위, 요청/권한 판본에 따라 정답을 갱신한다. 동일 규칙이 두 후보에 적용되며 늦은 후보에게 유리하도록 최신 입력을 감추지 않는다.

| 흐름 | 구성 판정 | 전달 판정 |
| --- | --- | --- |
| 필요한 확인 질문을 채택 → 사용자가 요청 취소 → 대기 후 질문 출력 | 최초 채택 당시 구성은 적합할 수 있음 | 취소 후 새로 질문한 출력은 부적합 |
| 필요한 질문을 채택 → 취소 → 질문 폐기와 필요한 취소 안내 전달 | 적합 | 의무가 모두 충족되면 적합 |
| 질문 전달 → 사용자 답변 → 동일 질문 재출력 | 첫 구성은 적합할 수 있음 | 답변 반영 의무를 위반한 중복 질문 |
| 결과 안내를 준비 → 사용자가 대상/형식 변경 → 이전 판본 출력 | 이전 채택은 당시 유효할 수 있음 | 현재 요청과 불일치 |
| Agent 실패 → VIA가 확인된 실패와 다음 행동을 정확히 전달 | 적합 | 적합. 외부 업무 실패 자체로 QA07 실패가 아님 |
| 최초 조건 누락 → 자체 정정 → 올바른 결과 전달 | 최초 해석 오류 유지 | 이후 출력이 적합해도 사례는 실패 |

이미 재생 중인 내용을 취소하는 경합은 음성 구간, 입력/이벤트 가용 시각과 허용 중단 정책을 함께 관측한다. 이 정책이 없는 경합 사례는 전체 판정을 확정하지 않는다. 취소가 출력 전에 충분히 제공된 명확한 재전달 오류와 미정 경합을 섞지 않는다.

## 4. 반드시 포함해 검토할 사례군

- 단일 직접 답변: 해석한 질문과 실제 답변의 대상/범위/형식 일치.
- 복합 요청: 처리/제한/순서/의존/유지 사항과 최종 안내의 일치.
- 모호한 입력: 필요한 확인 질문, 사용자의 답 연결, 이후 응답 의무.
- 요청 정정: 이전에는 유효했던 응답의 교체, 새 조건과 유지 조건 반영.
- 취소/거부: 질문/음성의 정상 폐기와 잘못된 재전달 방지.
- Agent 질문/결과 교차: 서로 다른 Task와 사용자 요청에 올바르게 연결.
- 차례 대기와 재개: 준비 후 상황 변경, 중단 위치/이미 전달한 내용/남은 유효 내용 구별.
- 실제 채널 차이: 화면 상세와 음성 요약, 화면 전용/음성 의무/수신 범위.

사례 수, 각 비중, 반복 수는 미정이다. DP별로 다른 정확성 의미를 만들지 않는다. 지칭 오류와 응답 오류가 많은 사례를 특정 대안에 맞춰 넣거나 빼지 않는다. 공통 실행 증거를 재사용할 때 source_execution_key로 중복 계수를 막는다.

## 5. 판정과 보고

두 평가자가 후보 이름을 가린 채 oracle와 trace를 확인하고 표현 차이, 정당한 대체/폐기, 오류 및 미관측의 이견을 조정한다. 자동 판정은 ID/판본/기한/의무 충족처럼 명시한 규칙에 한정한다. 자유문장 유사도 하나를 정답으로 사용하지 않는다.

보고는 다음을 한 묶음으로 제공한다.

1. QA07 계약 판본, 사례 목록과 관측창, 예정/실행/무효/미판정 수.
2. 확정 성공 S, 실패 F, 미판정 U와 N=S+F+U. U=0일 때 전체 충족률, 그 외에는 가능한 범위와 미판정 사유.
3. 요청 해석/응답 구성/실제 전달 원인과 최초 위반, 전파 결과. 단계별 건수를 전체 실패 수처럼 합하지 않음.
4. 각 사례의 A만 성공/B만 성공/공통 실패, 공유 오류 ID와 증거 종류.
5. QA02와 동일 대상 오류의 연결, QA01/03의 별도 시간 결과, 모델 비용과 메모리.

목표와 점수는 미정이므로 90% 합격선이나 기존 0~6점을 표시하지 않는다. 계획 문서의 정합성 검사는 실제 모델/제품 정확도 검증이 아니다.

## 6. 실행 전 결정할 항목

- 요청 처리 사례 묶음의 사용자 검토와 최종 사례 ID/분모.
- 응답/전달 oracle, 정상 폐기/허용 중복/명확화 정책과 근거.
- 최종 이벤트, 기능 기한, 재전달 확인 구간과 취소/중단 경합 정책.
- 실제 해석/구성/전달 관측 수단과 clock 오차, adapter 검증.
- 목표 수치, 0~6점 및 우선순위. 기존 단계별 성능을 곱하거나 목표를 사후 조정하지 않음.

이번 문서 변경은 모델 실행/측정이나 DP44 설계 변경, 대안 선택을 승인하지 않는다. 기존 공통 v3/v4 및 병행 작성 중인 후속 판본은 그 계약을 먼저 확인하고 새 QA07로 자동 재명명하지 않는다.
