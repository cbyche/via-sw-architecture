# QA01 음성 종료점 전환에 대한 판단

> **후속 상태:** 사용자 지시로 QA01 음성 종료점 변경과 QA09 제거를 반영했다. QA03은 [구체안](../qa03-via-processing-time.md)으로 확장했다. 아래는 그 전 판단 기록이며 현재 상태는 [측정 계약](../timing-measurement-contract.md)을 따른다.

2026-10-22 / 작성자 검토와 권고 / **QA 정의 변경 미적용 / 미측정**

사용자는 QA01을 실제 음성 시작까지의 지연으로 바꾸는 의견을 제시하고 독립적인 판단 및 QA09의 필요성을 물었다. 이 문서는 그 판단을 기록하며 승인된 정의나 새 목표가 아니다.

## 1. 결론과 현재 기준

**음성 전달이 필요한 VIA 상호작용의 QA01은 첫 실질적 음성의 실제 출력 시작까지 측정하는 방향을 권고한다. QA09는 별도 QA와 점수에서 제외하고 그 관측값을 QA01의 원인 진단으로 통합할 수 있다.** 화면의 첫 응답도 별도 진단으로 남긴다. 음성을 요구하지 않는 Text 전용 사례는 음성 지표의 분모에 넣지 않으며 해당 기능과 화면 지연 확인을 생략하지 않는다.

현재 [QA01 명세](../qa01-first-response-latency.md)와 [공통 v4 계약](../../evaluation/common-qa-v4/01-common-contract.md)은 화면 표시 종료점이다. 화면/음성 중 빠른 값을 고르는 기준으로 이미 변경됐다는 사실은 이번 저장소에서 확인하지 못했다. 다른 세션의 설명과 현재 정본을 구별한다.

이 권고의 이유는 음성 상호작용에서 사용자가 실제로 듣기 시작하는 대기를 직접 평가하기 위해서다. 화면이 먼저 뜨면 음성 전달이 늦어도 빠른 것으로 평가되는 `min(화면, 음성)`은 이 사용자 가치를 충분히 드러내지 못한다. 반대로 음성을 끈 모든 PC 사용 장면에 음성 지표를 강제하는 것도 부적절하다. 음성 모드를 주요 평가 범위로 명시한다.

## 2. 권고하는 경계

| 항목 | 권고 |
| --- | --- |
| 이름 | 첫 응답 지연시간 |
| 시작: 사용자 | 실제 발화 종료. 음성 응답을 요청한 Text 입력도 평가한다면 제출 시각을 사용. VAD 판단이나 전사 완료로 늦추지 않음 |
| 시작: Agent 사건 | 사용자에게 알릴 의무가 있는 사건이 외부 source에서 최초 소비 가능해진 시각. 내부 업무가 시작된 시각이나 VIA가 늦게 수신한 시각으로 바꾸지 않음 |
| 종료 | 해당 입력/사건에 대응해 채택한 첫 실질적 내용의 음성이 실제 출력 장치에서 시작된 시각 |
| 인정하는 내용 | 구체적 처리 의도, 직접 답변, 필요한 확인 질문, 업무 상태/결과. 답변 전체나 실제 업무 완료까지 기다릴 필요는 없음 |
| 제외 | 알림음, 인사, 일반 접수 멘트와 무음. 생성된 첫 audio chunk나 재생 큐 등록만으로 종료하지 않음 |
| 스트리밍 | 의미 있는 발화 구간에 해당하는 첫 실제 음성 sample로 판정. 앞에 붙인 “네”로 종료하지 않으며 문장 전체를 끝까지 들은 시각도 아님. 전체 발화와 내용 대응으로 사후 확인 |
| 오답 | 첫 실질적 응답이 틀렸어도 실제 시간은 보존. 최초 해석 오류는 QA02/07, 상태 사실 오류나 발음/전달 오류 등은 해당 기능 진단에 기록. 모든 오류를 QA07로 넘기지 않음 |
| 적용 | 공통 정책상 음성 상호작용이 활성화되고 음성 전달 의무가 있는 사건. 모든 Agent 로그를 알림 분모에 넣지 않음 |
| 집계 | 사전 등록한 적용 사건의 산술평균과 건수. 사용자 입력/Agent 통지, 즉시 발화/차례 대기별 분포도 공개. 관측분 평균을 전체 완료 평균으로 표현하지 않음 |

텍스트만 필요한 사례에 0초를 넣지 않는다. 기대한 음성이 끝내 나오지 않은 사례는 전달 실패와 미관측으로 남기고 성공 사례만으로 전체 목표 달성을 선언하지 않는다. 정정으로 의무가 철회되거나 여러 알림을 묶는 조건도 공통 정책에 미리 정해, 불리한 사건만 사후에 제외하지 못하게 한다.

## 3. 사용자 발화와 이전 재생을 기다린 시간

**대표 QA01에는 실제 경과시간을 포함하되, 그 전부를 VIA의 처리 지연이라고 설명하지 않는 것이 적절하다.** 사건이 생겼지만 사용자가 계속 말하는 동안의 시간도 출력까지의 경과시간이다. 사용자가 사건 자체를 모를 수 있으므로 Agent 사건 지연을 모두 사용자가 인지한 대기라고 단정하지 않는다.

평가자가 사용자 발화 일정, 기존 응답의 내용/길이와 대화 차례 규칙을 공통으로 고정한다. 상대의 발화를 끊거나 필요한 설명을 짧게 누락해 빠른 결과를 얻을 수 없게 한다. 입력/사건의 종류와 발생 시점도 대안 간 같게 유지한다. 즉시 답할 수 있는 사례와 차례 대기가 있는 사례의 비중을 결과에 맞춰 바꾸지 않는다.

해석, 음성 생성과 차례 대기는 병렬로 진행될 수 있다. 따라서 각 단계 소요시간을 더해 전체 지연으로 표시하지 않는다. 원시 타임라인에 음성 전달이 허용되지 않은 구간의 합집합과 그 밖의 대기를 구별하고, 그 위에 해석/생성/장치 출력 구간을 표시한다. 사용자 발화와 기존 응답의 구간도 서로 겹치면 중복 계산하지 않는다. 상태 채택 전의 처리 대기와 채택 후의 생성/전달 대기를 분리해 볼 수 있다.

설명용 예: 사건은 0초, 기존 응답은 5초에 끝난다. A가 2초에 새 음성을 준비하고 5초에 출력하면 QA01은 5초다. B가 5초부터 생성을 시작해 6초에 출력하면 6초다. A의 선행 준비 이익은 1초이며, 기존 응답을 기다린 5초 자체가 없어지는 것은 아니다. A/B 모두 5초 전에 준비되면 QA01은 동점이다. DP44의 이익을 드러내려고 대기 조건을 선택하지 않는다.

## 4. QA09의 처리

[현재 QA09](../history/timing-before-voice-20261022/qa09-audio-delivery-lag.md)는 채택 이후 음성을 전달할 수 있었던 구간만 누적한 지연이다. 새 QA01은 입력/사건부터 실제 출력까지이므로 같은 산식은 아니다. 그러나 음성을 실제로 전달해야 한다는 사용자 품질 목적을 새 QA01이 직접 평가하므로 **독립 QA와 500ms 목표 및 별도 점수는 없애도 된다**는 판단이다.

음성 채택, 첫 재생 가능 시각, 첫 chunk 준비와 실제 출력 시각은 진단 로그로 유지한다. 음성 출력 누락, 정정 전 내용의 출력, 중단과 재개, 끝까지 전달하는 기능 검증도 남긴다. 첫 소리만 빨리 내고 나머지를 누락한 구현을 정상 완료로 보지 않는다. 같은 개선을 QA01과 QA09의 독립적인 두 장점으로 세지 않는다.

## 5. 목표와 QA03에 미치는 영향

**기존 1초와 점수 구간을 그대로 이전하지 않는다.** 종료점 외에도 음성이 필요한 사건의 분모와 차례 대기 포함 여부가 달라진다. 음성 상호작용 근거, 공통 사건 구성과 실제 첫 음성 관측을 바탕으로 목표를 다시 정해야 한다. 지금 임의의 새 수치를 정하지 않는다.

QA03은 첫 응답 이후 필요한 처리도 끝났는지를 보는 지표다. 화면이 실제로 선택 기능이라는 제품 계약이 확정된다면, 화면을 요구하지 않는 사례에 실제 화면 표시를 완료 조건으로 강제할 이유는 없다. 요청된 결과와 상태 확정, 필요한 음성 요약 전체의 준비 등 사례별 의무를 완료 조건으로 삼고, 화면 출력이 필요한 사례에는 표시 조건을 유지하는 방향이 맞다.

다만 **QA01의 종료점을 음성으로 바꾸는 결정만으로 화면 기능 자체가 선택 사항이 되지는 않는다.** 현재 QA03은 상세 텍스트 표시와 전체 음성 준비를 명시한다. 화면 정책을 바꾸려면 그 기능 계약을 함께 명시해야 한다. UI 표시의 선택 여부와 내부 Task 상태/전달 이력 보존 의무도 구별한다.

QA01은 첫 음성의 실제 출력까지의 경과시간, QA03은 목표 완료까지 VIA에 귀속되는 처리시간으로 역할을 나눈다. QA03에 순수 재생 길이와 사용자 대기를 다시 포함하거나 전체 음성 생성 완료 뒤에만 재생하도록 강제할 필요는 없다.

## 6. 채택 시 후속 변경 범위

QA01의 정의/음성 의무 사건/측정 경계/목표와 점수, QA09의 독립 목록과 점수, QA03의 채널별 완료 조건, 공통 평가 계약과 산출물, DP44의 예상 효과 및 선택 근거를 같은 판본에서 정리한다. 현재 결과는 기존 정의로 보존한다. v4의 첫 음성 계산을 이름만 바꿔 새 QA01의 실측이나 확정 결과로 사용하지 않는다. 이번 검토에서는 정의 변경이나 QA09 삭제를 실행하지 않았다.
