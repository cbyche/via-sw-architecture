## 수행한 정적 확인

- `check_active_markdown_links.py`: active 문서 로컬 링크 통과.
- `check_active_terminology.py`: active 용어와 Component 이름 검사 통과.
- `check_qa_candidate_package.py`: 공통 카탈로그와 비용 참조, 9개 배점 구간 및 두 요구사항 표와 9개 발표 원고의 배점 투영 검사 통과.
- `qa_dp_thought_experiment.py --check`: 72개 예상값, 관련 모집단, 단계별 DAG, 목표 전체 경로, 변경 집합 / 교집합, 비용 / RAM / 부하 원장과 표 재현성 통과.
- 계산기 추가 불변식: 같은 A 구조의 공통 사건과 전체 비용 및 같은 변경 과제의 모듈 집합 일치, 지칭 확률 0~100%, 구조별 사건 분류 중복 없음, 우열 문구와 원값 방향 일치.
- `git diff --check`: 공백 오류 없음.

계산기가 증명하는 것은 입력한 가정과 산식 및 문서의 일치다. 모델의 예상 속도, 정확도나 변경 모듈 수 자체를 실험으로 검증한 것은 아니다.

## 발표에 남기는 한계

QA01/03은 평균이며 오답 시간도 그대로 센다. 5회 동일 기대값은 실제 실행 표본이 아니다. 모델 고정 지연과 토큰 처리 예산, 의미 관계를 풀기 전에 필요한 출력량, 최종 정답 확률, 상주 RAM, Rust 모듈 영향은 모두 작성자 예상이다. 특히 의미 정확도는 구조에서 연역되는 숫자가 아니다.

DP44/42는 관련 사례로 좁혀도 첫 응답과 전체 처리시간 차이가 작다. 기존 강한 A의 비동기 작업을 없애거나 B에 없는 모델 호출을 추가하지 않았기 때문이다. 해당 DP는 변경 파급과 상태 / 메모리 차이를 주요 예상 근거로 제시하며 정상 사용에서 B의 큰 성능 이익까지 검증됐다고 말하지 않는다. QA09처럼 경로가 같은 항목은 동점으로 남긴다.

C04/C06의 요구를 기존 generic 계약이 이미 완전히 제공하면 계획 모듈 수를 줄여야 한다. 실제 Rust 구현과 diff는 없으며 `DESIGN_CHANGE_REVIEW`다. 최종 대안 선택, 제품 달성, 양성과정의 모든 DP 커버리지 충족을 확정하지 않는다.
