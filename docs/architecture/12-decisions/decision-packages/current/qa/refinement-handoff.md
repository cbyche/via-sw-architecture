# 기존 QA01~QA08 구체화의 후속 반영 계약

2026-10-23 / `QA-REFINEMENT-v1` / 정의 문서 반영 / `READY_TO_SEND`

수신 담당 세션: `01a15dfe-8b3c-7fe3-87ab-750cd0e2db99`. 사용자가 합의한 QA 변경을 해당 DP-QA 담당에게 전달하도록 한 기존 지시에 따라 준비했다. 발송은 후속 갱신 완료를 뜻하지 않는다.

## 전달할 확정 방향

1. [대표값과 부록](measurement-appendix.md): QA01~08 각각 대표 숫자 하나. 세부 유형은 부록. QA01 WAIT는 해당 DP 대표 비교 옆의 보조 결과도 유지한다.
2. QA01: 평균 2초, NORMAL/WAIT, 실제 음성 시작 경계와 점수 유지. P95 사용하지 않는다. 요청 종류별 평균/건수는 부록.
3. QA02: 최초 지칭 집합의 전체 완전 일치율 하나. 선택/과거 화면/스크롤/다중 대상/정정은 태그로 분해하되 전체 분모에 중복 가산하지 않는다.
4. QA03: 최초 목표 입력부터 전체 필수 상태/연동/최종 응답 준비까지 VIA 처리 경로의 평균 5초. 첫 응답 또는 먼저 준비된 채널로 종료하지 않는다. 기존 DAG 포함/제외 및 점수는 유지.
5. QA04: [QA04-CHANGE-v4](qa04-change-scope.md)와 [Q4-C01~08](change-scenarios.md). 8개 공통 변경의 실제 운영 모듈 수 평균이며 Python 등 제품 코드를 포함한다. 기존 C01~06/CHG-v3 추정값을 새 결과로 복사하거나 신규 과제의 예상 숫자를 임의 생성하지 않는다.
6. QA05: 동일 묶음당 전체 청구 모델 비용, 준비/미사용 생산/취소/재시도/후속 처리 포함. $2.55는 COMMON-28에 한정한다.
7. QA06: 전체 VIA 제품 RAM 예산 512 MB, 로컬 모델 포함. QA08과 합산하지 않는다. DP3 탐색의 기존 상한 적용 유보는 제품 예산 변경이 아니다.
8. QA07: QA02와 별도 유지, 요청 처리 사례 전체 충족률 하나. 단계별 실패 원인은 부록. 현재 목표/점수와 세부 분모/종료 동결 상태는 미정으로 유지.
9. QA08: 추가 모델의 엔진/버퍼/worker까지 동일 시각 최고량. 1 GB 미만과 귀속/공유 중복 제거 유지.

## 담당 세션의 후속 범위

기존 v6와 이전 평가 산출물은 보존한다. 새 판본에서 문서, 사례/변경 과제 매핑, 원장 필드와 출력 설명을 갱신하고 기준 변경을 명시한다. QA04는 새 8개 과제의 ID/변경 전후/완료 조건과 등록 모듈 목록을 준비하되 실제 패치 근거가 없으면 `NOT_MEASURED`로 둔다. 이전 추정은 이전 계약의 참고 열로만 유지한다. 정의 담당이 이번에 모델 실행, 구현 실험, 숫자 추정이나 PPTX 변경을 요청하는 것은 아니다.

기존 QA01/03 값은 새 수치 생성 없이 경계 적합성을 확인한다. QA02/07은 관측이 없으므로 미산출 상태를 유지한다. 단일 대표값과 부록 표시를 반영하되 합의 전 목표/점수를 만들지 않는다. 실제 재생성 범위와 실행한 검사, 미완료 항목을 담당 세션에 기록한다.

## 전달 상태

문서 반영과 정적 검사 후 전달한다. 현재 READY_TO_SEND이며 평가 담당의 완료는 확인하지 않았다.
