## 1. 찾으려는 근거

QA07은 한 입력에서 요청한 처리, 처리 대상과 적용 범위, 요청의 제한사항, 실행 순서와 의존 관계, 이전 요청/응답 또는 VIA Task와의 연결을 처음 확정할 때 모두 맞는지를 본다. 정정할 내용과 유지할 내용, 사용자가 지정한 수행자와 수신자도 해당 입력이 요구하면 포함한다. [항목별 정의와 예](../qa07-request-meaning-accuracy.md#21-정답에-포함할-의미)를 기준으로 intent 이름 하나의 분류 정확도, slot별 F1, 지칭 대상 집합 정확도, Agent 최종 업무 성공률과 구별되는 **전체 의미 구조 일치**를 조사했다. 논문 발표 연도는 논문 본문을 기준으로 썼으며 검색 엔진의 최근 수집 시각을 발표일로 사용하지 않았다.

VIA와 동일한 한국어 음성/화면/여러 Task 환경의 사용자 허용 오류율이나 제품 출시 임계값은 확보하지 못했다. 아래 자료는 관련 과제의 기술 참조와 평가 원칙을 제공한다. 최신 최고 성능 순위의 포괄적 조사는 아니다.

논문 표의 수치는 웹에서 제공하는 본문과 표 추출 텍스트 및 공식 구현 설명으로 확인했다. 외부 모델이나 논문 코드를 실행하지 않았다.

### TreeDST가 평가하는 것

대화가 이어질 때마다 사용자가 현재 무엇을 요청하는지 문맥을 포함해 트리 구조로 표현한다. 예를 들어 일정 생성 요청 뒤 시간만 고치면, 시간을 바꾸고 다른 지정 내용은 유지해야 한다. 여기서 트리는 요청 행위, 대상과 속성, 연산 관계를 계층적으로 기록하는 표현이다. TreeDST는 이를 학습하고 평가할 입력과 정답을 제공하는 데이터셋이며 모델 이름이 아니다.

자료는 컴퓨터가 만든 대화 흐름을 사람이 자연스럽게 표현하는 방식으로 구성되었으며 실제 Siri 사용 로그가 아니다. QA07에서 인용한 **90.8%는 별도의 2022년 연구가 FULLTOGRAPH 모델을 TreeDST의 validation 데이터에 평가한 결과**다. VIA의 한국어 음성/화면 평가나 사용자 허용 오류율을 뜻하지 않는다.

## 3. 왜 이 수치를 목표의 참조로 택했는가

요청을 의미 구조 전체로 옮긴 뒤 전체 일치로 판정하는 과제는 QA07의 사용자 정의와 연결된다. 여러 턴의 참조와 수정이 중요한 VIA에는 문맥 기반 semantic parsing이 단일 intent 분류보다 가까운 참조다. 다만 같은 논문에서도 두 데이터셋 값이 다르므로 90.8%를 보편적 달성 수준이나 사용자 만족 기준으로 주장하지 않는다.

이번 목표 선정은 다음 두 부분으로 나뉜다.

1. **외부 사실:** 관련 과제에서 전체 일치율 90.8%라는 공개 결과가 있다.
2. **작성자 판단:** 그 약 90% 수준을 VIA 대표 시험의 초기 개발 목표로 삼고 정수 백분율로 내림하여 **90% 이상**을 제안한다.

`90.8 → 90`의 0.8%p 완화는 외부 연구로 입증된 허용 오류가 아니다. 자료 취득, 한국어, 여러 Task와 장기 이력이 추가되는 VIA 범위를 수학적으로 보정한 값도 아니다. 90.8%를 그대로 도입하는 것 역시 다른 모집단의 소수점 정밀도를 그대로 요구하는 판단이다. 이번에는 요구의 근거 수준에 맞게 정수 목표로 제안한다. 이 선택은 사용자 검토 대상이며 미리 승인된 요구사항으로 기록하지 않는다.

95%나 99%는 더 강한 요구로 제안할 수 있지만 이번에 확인한 자료만으로 반드시 그 수치여야 한다고 도출할 수 없다. 반대로 SMCalFlow의 낮은 값에 맞춰 요구를 낮추거나, 합성 원장의 결과에 맞춰 목표를 조정하지 않는다. 실패한 조건의 사용자 영향과 대표성이 확인되면 목표와 모집단의 재검토 사유를 기록한다.

## 4. 연구와 VIA가 다른 부분

| 구분 | 관련 연구에서 확인한 범위 | VIA 평가에서 별도로 확인할 부분 |
| --- | --- | --- |
| 출력 | 프로그램/의미 frame의 exact match | 구현 표현을 정규화한 필수 의미의 동등성, 불필요한 추가 해석 |
| 근거 | 지정한 Text 발화와 문맥 | 원음, 전사, 화면/선택/포인터, 실제 전달 이력과 원본 조회 |
| 상태 | 연구 데이터셋의 대화 상태 | 여러 Task, 현재/과거 판본, 수정 범위와 유지 조건 |
| 시점 | 평가 모델의 예측 결과 | 잠정 결과와 최초 실제 확정을 구별하고 후속 복구로 오답을 지우지 않음 |
| 목표 해석 | 데이터셋의 관측 성능 | 자체 시험의 개발 목표. 제품 만족도/출시 허가와 구별 |

이 차이는 외부 수치를 직접 비교할 수 없다는 한계다. 연구와 다른 점이 있다는 이유로 QA07을 모호한 주관 점수로 바꾸지는 않는다. 자체 입력, 정답, 최초 확정과 동등성 규칙을 먼저 고정한다.

## 5. 다른 지표를 가져오지 않는 이유

| --- | --- |

| intent accuracy | 행위 종류가 맞아도 대상과 제외 조건이 틀릴 수 있음 |

| confidence estimator F1 | 옳은 해석을 알아보는 판별 성능이며 해석 자체의 성공률이 아님 |
| Agent benchmark 업무 성공률 | 해석 이후 도구, 환경과 업무 계획이 함께 작용하며 최초 의미의 정답률이 아님 |
| 항목별 정확도 곱 | 오류 독립성 가정이 없고 입력별 필수 항목 수가 다름 |
| v3 Delivery 80/80 | 정답 의미를 고정 공급한 제어 조건이며 모델 해석 성능이 아님 |

## 6. 점수와 모집단 수의 근거

**점수 구간:** `(100−90)/5 = 2%p`. 목표부터 완전 성공 직전까지 다섯 균등 구간을 만들고 100%에 6점을 부여한다. QA02와 같은 표현 원리를 쓰되 93% 목표나 1.4%p 간격을 계승하지 않는다. 2%p의 사용성 임계값을 연구에서 찾았다고 말하지 않는다.

**이전 원전에서 도출한 분모 제안:** COMMON-28-v1의 사용자 입력 84건 중 사전 모호 입력 4건을 별도 회귀로 두어 나머지 80건을 평가 후보로 제안했다. 작성자가 이번 QA07 상세화에서 계산한 수이며 다른 QA의 공통 분모나 TreeDST에서 가져온 숫자가 아니다. 나머지 80건의 전체 의미가 명확한지 아직 확인하지 않았으므로 “명확한 입력 80건”으로 표현하지 않는다. 모두 평가 가능하다고 확인된다면 기존 계획의 반복 규격 5회를 빌려 400판정으로 구성한다. 통계적 최소 표본 수로 도출한 숫자가 아니다.

**현재 공통 평가와의 구별:** [v4 공통 계약](../../evaluation/common-qa-v4/01-common-contract.md)은 24개 입력과 QA07 정답을 준비했다. 후보 출력은 없으며 QA07은 미산출이다. 이전 80개 후보와 400판정 제안을 현재 v4의 분모나 실제 반복 횟수로 사용하지 않는다. [평가 계획](../qa07-evaluation-plan.md)에 이전 QA별 관측 단위와 수량을 비교했다.

**판정 예:** 360/400은 90%와 1점, 392/400은 98%와 5점, 400/400은 해당 표본에서 오류 없음과 6점이다. 실제 결과가 아닌 산식 예시다. 처음부터 맞힌 입력과 나중에 복구한 입력을 섞지 않는다.

## 7. 확인 한계와 후속 근거

이번 작업에서 한 것은 출처 확인, 정의 상세화, 수치 제안과 정적 검증이다. 독립 평가자 리뷰나 원문 연구 재현, 모델 호출, 실제 VIA 정확도 평가를 수행하지 않았다. 제품 사용자가 10% 오류를 허용한다는 근거는 없다.

후속 증거는 입력별 전체 의미 oracle과 근거 범위, 실제 최초 채택 출력/시각, 실패와 수정 이력, 판정자 불일치 기록, 같은 입력의 대안 간 차이다. 사용자가 목표를 채택한 사실과 시험에서 달성한 사실은 각각 별도 기록한다. 기존 우선순위, QA02와 과거 결과를 변경하지 않는다.
