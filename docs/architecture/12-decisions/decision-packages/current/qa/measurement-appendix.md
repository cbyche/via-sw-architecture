# QA 대표값과 부록 작성 계약

[현재 목록](README.md) / [요구사항 요약](quality-requirements-table.md) / [변경 과제](change-scenarios.md)

## 1. 본문에 보여줄 숫자

각 QA에는 대표값 하나를 둔다. 분모, 단위, 근거 종류와 미관측/실패 수는 대표값을 해석하는 필수 정보이며 생략하지 않는다. 점수가 확정된 QA만 해당 점수를 붙인다. 부록의 세부 수치를 평균내어 별도의 종합 점수를 만들지 않는다.

| QA | 대표 숫자 하나 | 부록에 넣을 상세 |
| --- | --- | --- |
| QA01 | 사전 지정 NORMAL 사건의 첫 실질적 음성 시작까지 **산술평균 초** | 요청 종류별 평균과 건수, WAIT 원인별 타임라인과 값 |
| QA02 | 전체 지칭 표현/revision의 **최초 대상 집합 완전 일치율 %** | 선택, 과거 화면, 스크롤 전후, 다중 대상, 정정별 결과 |
| QA03 | 목표 전체의 필수 처리/최종 응답 준비까지 **VIA 처리 경로의 산술평균 초** | 목표별 완료 의무, 처리/대기 구간, 직렬/병렬 경로와 외부 제외 원장 |
| QA04 | 공통 8개 변경 과제의 **변경 운영 모듈 수 산술평균 개** | 변경 전후, 실제 diff, 추가/수정/삭제 모듈과 검증 결과 |
| QA05 | 동일 활동 묶음을 반복했을 때의 **묶음당 평균 총 모델 비용 USD** | 준비/실행/재시도/취소/미사용 생산/후속 처리와 모델별 청구 항목 |
| QA06 | 관측 범위의 **VIA 전체 실제 RAM 최고량 MB** | 같은 시각의 프로세스/버퍼/공유 메모리 귀속과 단계별 값 |
| QA07 | 요청 처리 사례의 **해석/응답 전체 충족률 %** | 사례 유형, 최초 해석/응답 구성/실제 전달의 실패 원인과 전파 |
| QA08 | 추가 로컬 모델 경로의 **동시 메모리 합계 최고량 GB** | 가중치/엔진/추론 상태/버퍼/worker와 호스트/전용 가속기 구성 |

QA01은 평균으로 평가하며 P95를 대표값이나 추가 평가 지표로 사용하지 않는다. QA06/08은 평균이 아니라 최고량이다. QA05의 $2.55는 COMMON-28 한 묶음의 목표로 유지한다. 다른 묶음의 비용이나 요청당 비용에 자동 적용하지 않는다.

## 2. QA01 일반 상황과 대기 상황

일반 상황의 설명은 **“말을 마친 뒤 첫 실질적 음성이 들리기 시작할 때까지 평균 몇 초인가”**다. 음성 응답 대상 Text는 제출 시각, Agent 사건은 외부에서 처음 제공 가능한 시각을 시작으로 삼는다. 앱의 수신/해석/출력 큐에서 기다린 시간도 포함한다. 첫 token이나 음성 생성 시작이 종료점이 아니다.

대표 비교에는 NORMAL 평균과 2초 기준 점수를 쓴다. 차례 대기가 중요한 DP에는 **WAIT 총 실제 지연, 차례 대기, 마지막 대기 종료 후 추가 지연**을 같은 비교 자료에 보조 결과로 함께 표시한다. 이 결과를 부록에만 숨기거나 NORMAL 평균에 섞지 않는다. 상세 사건표와 원인별 분석은 부록에 둔다.

- NORMAL/WAIT는 사용자 발화 일정과 이전 응답 조건을 기준으로 실행 전에 정한다. 결과를 보고 후보마다 분모를 바꾸지 않는다.
- WAIT_USER, WAIT_PREVIOUS, WAIT_BOTH를 구별한다. 사용자와 앞 응답 대기가 겹치는 시간은 한 번만 센다.
- WAIT에서 대기를 뺀 값을 NORMAL 관측값으로 바꾸지 않는다. 대기 중 생성은 총 실제 지연에 이미 반영된다.
- 요청 종류별 부록은 음성 입력/Text/Agent 사건을 먼저 구분하고, 안내/확인 질문/상태/결과 등 사전에 정한 주유형별 평균과 건수를 제시한다. 전체 합계와 맞추는 표는 사건마다 주유형 하나를 사용한다. 겹치는 분석 태그는 중복 가능하다고 표시한다.
- 일반 상황에서 출력 누락이 있으면 전체 평균/점수를 확정하지 않는다. 부분 관측 평균과 누락 수를 함께 남긴다.

정확한 B/E/R 정의와 실제 출력 판정은 [QA01](qa01-first-response-latency.md)과 [시간 계약](timing-measurement-contract.md)을 따른다.

## 3. QA02와 QA07: 별도 대표값 유지

**QA02는 “무엇을 가리켰는가”, QA07은 “그 대상에 무엇을 하라는 요청인지 이해하고 이후 상황에 맞게 응답했는가”를 구별해 유지한다.** QA02를 QA07의 부록 항목으로 축소하지 않는다. 핵심 QA 개수를 줄이기 위해 두 지표를 합치지 않으며 최종 통합 여부는 나중에 검토한다.

### QA02

`대표값 = 100 × 최초 대상 집합이 완전히 맞은 지칭 수 / 전체 평가 지칭 수`다. 표현 하나가 여러 대상을 가리켜도 집합 전체를 한 번 판정한다. 같은 표현/revision/반복의 결과가 선택·과거 화면·정정 태그에 동시에 포함되어도 대표 분모에서는 한 번이다. 유형별 비율의 단순평균을 대표값으로 쓰지 않는다.

유형별 표에는 분자/분모와 비율을 함께 넣는다. 모호함은 후보 결과를 보기 전에 정답 작성자가 판단한다. 명확한 지칭을 못 찾은 실패를 사후 제외하지 않는다. 실제로 근거가 부족한 지칭의 확인 동작은 기능 검증과 QA07의 해당 응답 의무로 관리하며 가짜 대상 ID로 QA02에 합치지 않는다.

### QA07

`대표값 = 100 × 모든 필수 해석과 응답 의무를 충족한 사례 수 / 전체 평가 사례 수`다. 사례 하나에서 해석과 전달이 모두 틀려도 실패는 한 건이다. 한 번의 잘못된 최초 해석은 후속 수정으로 지우지 않는다. 모든 필수 해석은 맞더라도 철회된 질문을 다시 전달하면 실패다.

부록에는 요청 종류/연결 복잡도와 최초 해석, 응답 구성, 실제 전달의 원인 태그를 넣는다. 원인 태그는 겹칠 수 있으므로 합계를 전체 실패 건수라고 표시하지 않는다. 사례가 길다는 이유로 해석 항목 수를 분모로 바꾸거나 단계별 비율을 평균내지 않는다. [v3의 32사례](qa07-evaluation-cases.md)를 각각 5회 반복하여 160회를 판정한다. 시작/종료와 사건 순서는 [평가 계획](qa07-evaluation-plan.md)에 정했다. 미판정 사례가 남으면 성공 사례만으로 전체 충족률을 확정하지 않는다. 목표는 전체 충족률 90% 이상이며 144/160 이상 성공해야 한다. 100% 우수선과 2%p 균등 구간의 0~6점을 작성자 제안으로 구체화했다.

공통 지칭 오류는 두 QA에서 같은 원인 ID로 연결한다. 예를 들어 대상을 맞혔지만 “비교”를 “각각 요약”으로 이해했다면 QA02는 성공, QA07은 실패다. 지칭을 틀리게 확정해 후속 요청/응답까지 틀리면 양쪽 실패이지만 독립적인 두 개선 효과로 합산하지 않는다.

## 4. QA03의 시작과 끝을 설명하는 방법

**“한 목표를 시작하는 입력부터, VIA의 상태 반영과 최종 응답 준비가 전부 끝날 때까지 VIA가 맡은 처리가 얼마나 걸렸는가”**다. 첫 안내만 끝낸 것은 완료가 아니다. 사용자 확인이나 Agent 결과가 필요하면 그 결과를 반영한 최종 준비까지 확인한다.

- 시작: 목표의 최초 사용자 발화 종료 또는 Text 제출.
- 끝: 필수 상태 확정, Agent 접수/결과/취소 등 해당 연동 확인, 최종 응답의 필수 채널 준비가 모두 끝난 시점.
- 포함: VIA의 해석, 원격/로컬 모델 호출, 내부 큐, 검색, 전송/수신 반영, 전체 음성 생성과 필요한 상태 저장.
- 제외: 외부 Agent 내부 업무, 사용자 답변/발화, 이미 생성된 음성을 듣는 시간과 순수 차례 대기.

시작/끝은 전체 처리 범위를 정한다. 대표 시간은 그 안의 VIA 처리 경로로 계산한다. 실제 작업 순서를 보존하며 연속 처리는 합하고 병렬 처리는 늦게 끝나는 경로를 사용한다. 외부 업무와 겹쳐 수행한 VIA 작업을 빼버리지 않는다. 식, 원장과 예는 [QA03](qa03-via-processing-time.md)에 둔다. QA01은 첫 음성 시작, QA03은 최종 준비 완료이므로 첫 응답 이후 남은 처리도 설명할 수 있다.

## 5. QA04~QA08의 보조 증거

QA04는 [8개 변경 과제](change-scenarios.md)를 동일 출발 코드에서 각각 독립 적용한다. 언어별 모듈 등록부, 실제 diff와 완료 검증을 부록에 둔다. 구조상 차이가 없으면 같은 수를 유지한다. 변경 실패/미구현을 0개로 기록하지 않는다. 기존 6개 과제의 추정값은 새 평균의 근거가 아니다.

QA05는 사전 준비부터 활동 유래 후속 청구 종료까지 모두 포함한다. 실제 사용하지 않은 생성, 재시도와 취소 직전/이후 청구분도 남긴다. 로컬 모델의 전력·장비 비용을 임의 환율로 합산하지 않으며 해당 모델의 자원은 QA06/08로 확인한다.

QA06은 전체 제품 예산이다. UI, 요청/Task 상태, 캐시, 버퍼, 보조 프로세스와 로컬 모델을 포함한다. QA08은 그중 추가 모델에 귀속되는 자원이며 전용 GPU/NPU 메모리를 별도 포함한다. 시스템 RAM을 공유하는 가속기 메모리는 중복 합산하지 않는다. 구성요소별 서로 다른 시점의 최고값을 더하지 않고 같은 시점의 합계에서 최고값을 구한다. 두 QA의 호스트 RAM은 겹치므로 전체 예산을 512 MB + 1 GB로 만들지 않는다.

현재 정의 구체화는 새 QA 추가, 새로운 DP 수치 생성이나 기존 PPTX 수정이 아니다. 신규 QA 후보는 이번 정리 이후 사용자와 별도로 논의한다.
