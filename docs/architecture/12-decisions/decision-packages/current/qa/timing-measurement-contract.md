## 2. 필요한 원장

아래는 평가 구현에 넘길 필수 의미 규격이며 특정 JSON schema나 제품 구현을 강제하지 않는다. 모든 시각은 공통 단조 시계로 연결하고 원격 시각 변환과 오차를 남긴다.

| 원장 | 필수 내용 |

| 사건 | `event_id`, 종류(Voice/Text/Agent), 원래 source 시각, VIA 수신 시각, 음성 전달 의무, 공통 정책 판본, 연결 목표/Request |

| 응답 | `response_id`, revision, 대응 사건/목표, 채택한 의미와 시각, 문장/음성 구간 ID, 현재성/권한, superseded/cancelled 상태 |

완료 이벤트 하나에만 의존하지 않고 필요한 상태/자료/채널 준비 증거와 대조한다. 후보가 `done`이나 `ready`를 빨리 기록했다고 기능 의무가 사라지지 않는다. 반대로 결과가 틀렸다는 이유로 이미 관측한 종료 시각을 후속 정답 시각으로 바꾸지도 않는다.

## 3. QA01 계산 순서

1. 후보 실행 전에 동일 사건 중 음성 전달 의무가 있는 집합을 정한다. Voice 입력, 음성 응답 대상 Text, Agent 통지의 수와 비중을 공개한다.
2. 사건/revision과 실제 출력 내용을 연결해 첫 실질적 음성 구간을 확인한다. 물리 출력 계측이 없으면 proxy 또는 분석값으로 표시한다.
3. `l = 첫 실질적 음성 시작 - 입력/사건 시작`을 계산한다. 음수이면 잘못된 사건 연결/시계 또는 기능 위반을 확인하고 0초로 보정하지 않는다.
4. 같은 구간에서 사용자 발화 U와 앞 응답 재생 P를 공통 차례 정책으로 구해 `B = |U ∪ P|`, `E = l-B`를 계산한다. U와 P의 합에서 교집합을 한 번 뺀 값과 B가 일치해야 한다.
5. 채택 이후 말할 수 있었던 구간의 길이 D와 생성/출력 단계의 타임라인을 진단으로 남긴다. D와 생성 시간, B를 다시 더하지 않는다.
6. 원값과 전체 평균, 차례 대기 진단, 사건 유형별 분포와 누락을 보고한다. 미출력/정상 철회/계측 무효를 별도 계수하며 부분 평균에는 관측 범위를 명시한다.

사용자 발화, 앞 응답 내용/길이와 공통 우선순위 정책을 대안에 동일하게 적용한다. 현재성을 잃은 응답은 공통 규칙대로 취소한다. 후보가 응답을 불필요하게 늘려 이후 사건의 차례 대기를 만드는 경우도 공개하며 이를 외부 환경 차이로 숨기지 않는다. 대화 차례를 기다리면서 가능한 선행 준비는 허용하고 실제 자원/비용에 기록한다.

## 4. QA03 계산 순서

1. 공통 목표의 시작, 적용 채널, 필수 상태/연동 확인과 최종 준비 의무를 고정한다. 일부 후보만 첫 안내로 목표를 종료할 수 없게 한다.
2. 실제 처리와 대기의 span, 상태/데이터와 자원 의존으로 목표별 DAG를 구성한다. 목표 시작 전 완료된 작업은 초기 상태, 시작 이후 남은 경합은 잔여 구간으로 반영한다.
3. 원래 duration으로 계산한 terminal이 관측된 준비/상태 완료시각을 재현하는지 검사한다. 다르면 미복원 trace로 남긴다.
4. 사전에 분류한 Agent 내부 업무, 사용자 대기/발화, 순수 음성/화면 전달과 차례 대기만 0으로 투영한다. VIA의 모델 호출, 네트워크 연동, 상태 확정, 출력 준비와 내부 자원 대기는 보존한다.
5. 실제 인과/자원 순서를 유지하고 모든 필수 완료 node를 잇는 terminal까지의 가장 긴 경로를 구한다. 자원 선행 작업과 그로 인한 대기 시간을 중복 합산하지 않는다.
6. 목표별 값과 전체 평균, 실제 wall-clock, 제외 노드 및 오류/미완료를 보고한다. DAG 값과 wall-clock을 같은 측정값으로 부르지 않는다.

차례 대기 중 이미 생성이 진행되었다면 그 생성 span은 VIA 처리로 남는다. 다음 발화를 선택할 수 없어 순수하게 기다린 구간만 전달 대기로 분류한다. 모델 슬롯 부족, 후보의 스케줄링 지연이나 아직 내용이 채택되지 않은 상태를 차례 대기로 위장해 제외하지 않는다.

## 5. 완료 경계 확인용 사례

| 사례 | QA01 | QA03 |
| --- | --- | --- |
| 한 문장 직접 답변 | 그 문장의 실질적 음성 시작 | 전체 내용/필수 음성 준비와 상태 완료. 두 값의 차이가 작을 수 있음 |
| 첫 안내 후 자료 조사/결과 정리 | 구체적 수행 안내의 실제 시작 | 필요한 결과 취득/관계 확정/최종 준비까지. Agent 업무 시간은 제외 |
| 앞 응답을 듣는 중 새 Agent 결과 도착 | 앞 응답 대기를 포함한 새 내용의 실제 시작 | 결과 연결과 최종 준비의 VIA 경로. 순수 차례 대기는 제외 |
| 먼저 말하고 나머지를 생성하는 streaming | 첫 내용 시작 | 뒤에 남은 필수 응답 전체 생성/준비까지 |
| 빠른 잘못된 답변 | 관측된 첫 음성 시간과 오류 | 관측된 처리 종료 경로와 오류. 후속 정답으로 시간 덮어쓰기 금지 |
| 출력이 누락됨 | 전달 실패/미관측. 0초 아님 | 준비까지 끝났는지와 의무 누락을 분리. 준비값만으로 제품 성공 선언 금지 |

QA01과 QA03은 시간의 일부를 공유한다. 최종 중복 검토에는 같은 목표에서 첫 응답 뒤 남은 처리와 서로 다른 병목의 유무, 대표 사례의 비중을 제시한다. QA 간 수치를 단순히 빼거나 더해 새로운 시간값을 만들지 않는다. 차이를 만들려고 긴 답변, 다단계 업무나 대기 사례의 비중을 사후 변경하지 않는다.

## 6. 승인된 담당 작업 범위

사용자는 2026-10-23 정의와 측정방법을 채택하고 담당 세션에 모든 관련 평가 자료의 갱신을 요청하도록 지시했다. 새 목표/점수는 아직 없으므로 원값과 진단, 분석 근거를 갱신하고 목표/점수에는 미정 상태를 유지한다. 목표 재검토를 이유로 전체 갱신을 중단하지 않는다.

> 합의된 QA01-VOICE 및 QA03-COMPLETION 계약 판본을 기준으로 DP2/3/5/44 공통 평가를 새 판본에서 갱신해 주세요. QA01은 첫 실질적 음성의 실제 시작까지이며 차례 대기를 대표값에 포함하고 별도 진단으로 분해합니다. QA03은 목표별 필수 상태/연동/최종 채널 준비 완료까지의 VIA 귀속 DAG 시간입니다. QA09는 독립 지표와 점수에서 제거합니다. 기존 결과를 덮어쓰거나 첫 음성 열을 이름만 바꿔 전용하지 말고, 사건과 목표 의무, 채널, 지연 원인과 실제 관측 수준을 먼저 확인해 주세요. 분석값/실측을 구별하고 적용 건수, 오류/미관측, 원값과 목표 적용 여부를 공개해 주세요. 같은 사례에서 첫 응답 이후 남은 처리와 두 지표의 중복 여부도 함께 확인해 주세요.

담당 세션은 공통 계약, 사례별 사건/목표 의무와 trace, 계산기, JSON, Excel/HTML, 비교표, 해설, 검사와 현재 진입점을 새 판본으로 갱신한다. 기존 v4의 계약/원장/결과와 재현 경로는 보존하고 새 정의로 이름만 바꾸지 않는다. QA08 온디바이스 모델 추가 메모리도 현재 명세와 연결하되 귀속 근거가 없으면 미산출로 표시한다. QA02/QA07 후보 출력이 없으면 정확도를 만들지 않는다. QA01/03 목표와 점수 제안은 정의 담당과 별도 검토하며 그 전에는 점수나 새 순위를 확정하지 않는다. QA02/04~08의 정의와 우선순위를 임의 변경하지 않는다. 제품 실측이 없는 분석 모델은 분석값으로 표시한다. 발표자료는 현재 우선순위 밖이며 기존 발표 v10의 미반영 상태를 유지한다. 정의 담당은 별도의 DP-QA 수치를 생성하지 않는다.
