# 현재 네 DP의 설계 그림 작성 지침

이 패키지에서 그림을 고칠 때 적용하는 안내다. 공통 표기 원전은 [설계 대안 그림 작성 기준](../../diagram-design-guide.md), 과제 판단 원전은 [INTENT.md](../../../../../../INTENT.md)다. 원전의 과거 S 번호, 당시 색 범례와 미측정 상태를 현재 네 DP의 요구로 자동 계승하지 않는다.

## 표현할 계약

- 그림 전에 공통 입력과 출력, 각 대안의 책임, 상태 소유자와 수명, 실행 의존, 확정과 복구 조건을 문서로 정한다.
- 상자에는 구성요소의 이름을, 화살표에는 데이터, 동작, 조건과 순서를 쓴다. Component와 Module, 데이터, 저장소, 모델 의존성과 실제 process 경계를 구별한다.
- Component 이름은 해당 DP의 현재 설계 계약에 정의한 정식 이름을 사용한다. 참조 Architecture의 Component를 실제로 재사용하는 경우에는 그 정식 이름을 유지한다. 대안의 새로운 책임은 해당 DP 계약에 이름과 역할을 명시한다. 줄임말을 만들기보다 배치를 조정한다. Module과 내부 실행 ID를 별도 모델이나 process로 오해하게 하지 않는다.
- 조회와 결과 반환, 보완 요청과 재허가, 모델 호출과 완료, 실패와 정정 경로를 실제 endpoint에 잇는다. process 테두리에서 호출선이 끝나지 않게 한다.
- 동일한 정상, 정정과 실패 사건으로 대안별 흐름을 따라갈 수 있어야 한다. 실제 구조에 없는 대기, 중앙 처리나 장벽을 만들어 대안을 약화하지 않는다.
- 자료는 능동 처리자로 그리지 않는다. 상태의 물리 저장 위치와 의미상 소유권을 구별한다. 공유 상태와 개별 상태, 불변 참조와 가변 상태를 분리한다.
- 기본 구조, 공통 필수 검사와 별도 tactic을 구별한다. A2가 A1을 포함한다는 뜻으로 표시하지 않는다. 조합은 A1+A2처럼 명시한다.

## 파일과 시각 확인

현재 그림은 각 DP 또는 [공통 설계 보정](../design-review/README.md)의 `diagrams/`에서 관리한다. draw.io 편집 원본과 SVG를 함께 유지하고 본문에 SVG를 삽입한다. PNG와 PPTX가 있으면 같은 수정 작업에서 반영한다. 이전 판본의 그림은 history 역할을 표시한다.

PPTX의 이름은 해당 도형 자체의 text body에 넣는다. 그림 전체를 하나의 PNG로 바꾸어 편집 가능성을 잃지 않는다. 설명과 흐름 주석은 이름과 구별한다. 실제 범례를 그림마다 제공하고 색이 곧 우위나 채택을 뜻하지 않게 한다.

검증은 XML/ID/연결 참조와 canvas, 소유 관계, 선 경로를 확인한 뒤 실제 렌더에서 수행한다. 글자 넘침, 중첩, 잘림, 모호한 분기와 반환 경로를 확인한다. 구조적 타당성, 수치 근거, XML 유효성과 시각 품질은 각각 확인한다. 과거 구조나 QA를 현재 조건으로 다시 채택하는 작업은 그림 보정에 포함하지 않는다.

발표의 폰트, 언어, 크기와 새 판본 검증은 [PPTX 제작 지침](../presentation/PPTX-GUIDE.md)을 따른다. 중간점 문장부호는 새 본문과 그림 label에 사용하지 않는다.
