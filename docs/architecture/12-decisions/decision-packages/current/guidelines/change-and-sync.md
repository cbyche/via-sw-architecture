# 변경 영향과 동기화

> **2026-10-23 QA07 v4 반영:** 현재 QA07은 **업무 순서 및 연결 정확도**다. 사용자 지정 선후 관계와 NEW/EXISTING 및 기존 업무 ID의 최초 판단을 평가한다. 이름과 범위는 사용자 확정, **85%·28입력 × 5회(140회)·3%p 점수는 작성자 제안**이다. 공통 v9에 별도 매핑과 관측 전 평가표를 두었다. 실제 실행 0회, 결과 미산출이며 기존 v7/v8은 보존한다. v8의 응답 구성·전달 범위와 90%·160회는 이전 제안이다.

> **2026-10-23 QA 구체화:** [대표값/부록 계약](../qa/measurement-appendix.md)과 [QA04의 8개 변경 과제](../qa/change-scenarios.md)를 적용한다. QA01은 P95 없이 평균 2초와 NORMAL/WAIT 분리, QA02/QA07은 각각 단일 비율로 별도 유지한다. QA06은 전체 제품 예산이다. QA04-CHANGE-v4는 Rust/Python 등 실제 운영 모듈을 세며 v6에 보존된 기존 6과제의 추정값과 호환되지 않는다. 새 QA04 값은 미산출이며 기존 평가 파일과 PPTX는 보존한다. 후속 담당 작업은 [구체화 전달 계약](../qa/refinement-handoff.md)을 따른다.

> **2026-10-23 최신 시간 계약:** QA01-VOICE-v2, QA03-COMPLETION-v1과 [측정/전달 계약 v2](../qa/timing-measurement-contract.md)를 따른다. QA01 NORMAL 평균 2초와 WAIT 별도 표시, QA03 평균 5초 및 0~6점이 합의됐다. 계약, 원장, 계산기, JSON/Excel/HTML과 해설을 새 판본으로 갱신하고 기존 결과와 PPTX는 보존한다.

## 자료별 변경 순서

| 바뀐 내용 | 먼저 수정할 정본 | 함께 확인할 자료 |
| --- | --- | --- |
| 대안의 책임, 호출, 상태와 수명 | 해당 DP 설계와 상세 계약 | SVG/draw.io/PNG, QA 인과, 적용 시나리오, 발표 구조와 노트 |
| QA 정의 또는 관측 경계 | `qa/`의 해당 정의와 변경 기록 | 시나리오 관측 단위와 정답, 평가 계약, 기존 결과 호환성, 발표 용어 |
| 목표와 0~6점 구간 | 해당 QA 문서와 목표 근거 | 구간의 중복과 공백, 양안 공통 적용, 수치표와 발표. 원값은 유지 |
| 사례, 분모 또는 완료 조건 | 해당 시나리오 원장과 판본 | 모든 비교안의 적용 범위, 평가 계약, 대표값. 이전 모집단과 단순 합산 금지 |
| 평가 원장 또는 산식 | 새 dataset과 출력 판본 | Excel, HTML, CSV, 설명, 검증과 발표의 근거 표기 |
| 발표 표현과 배치 | 새 PPTX 판본과 작성 원본 | 편집 가능한 그림, 슬라이드별 근거, 미리보기와 제작 검사 |

동기화할 자료를 한 작업에서 갱신할 수 없으면 [패키지 README](../README.md)의 미반영 상태에 원본 판본, 영향받는 DP와 페이지, 남은 작업을 적는다. 완료되지 않은 자료를 최신 기준이라고 표시하지 않는다. 변경 중인 초안, 검토를 마친 문서와 사용자가 채택한 대안은 별개다.

## 판본과 근거

`package-manifest.json`의 이관 원본과 commit은 출처다. `EDITABLE_SOURCE`인 현재 설계, QA와 그림은 같은 경로에서 편집한다. 이관 당시 byte 동일성이 후속 편집을 금지하지 않는다. `IMMUTABLE_SNAPSHOT`인 기존 PPTX와 평가 산출물은 해시로 보존을 확인한다. 이 산출물의 변경본은 새 이름으로 만들고 README의 현재 링크와 원장을 함께 갱신한다. 이전 산출물과 검증 보고서를 새 파일의 성공 증거로 재사용하지 않는다.

공통 QA v3는 Text 이력, Voice/Screen, Voice Delivery의 서로 다른 profile을 관리한다. 실제 모델 캠페인의 수치를 이 합성 평가에 붙이거나 서로 다른 profile의 이익을 더하지 않는다. COMMON-28은 QA 목표와 점수 도출의 기존 모집단이고 v3의 26개 사례군과 같은 집합이 아니다.

## 현재 미반영 상태

새 [QA08-LOCAL-MEM-v1](../qa/qa08-on-device-model-memory.md)은 사용자 지정 1 GB 미만 목표와 DP 공통 계측 설계다. v3/v4, Excel/HTML과 발표 v10에는 새 QA08을 반영하지 않았다. 적용 대상은 추가 모델을 쓰는 모든 DP이며 DP3은 구체적인 설명 예다. 새 v5는 추가 자원의 귀속과 동시 피크를 분석 원장에 반영했다. 실제 장치·지원 최대 부하 검증은 미수행이다. QA06 전체 RAM에서 모델 메모리를 임의로 제외하지 않는다.

최신 공통 비교는 [공통 QA v9](../evaluation/common-qa-v9/README.md)다. QA07 v4의 최초 업무 순서/연결만 다루는 28입력 × 5회 계획과 85%/3%p 점수 제안을 반영했다. 실제0·980 UNKNOWN이며 실행 fixture는 미준비다. v7/v8 원장과 snapshot 및 기존 평가 파일은 보존한다. 다른 QA의 24입력 시간/비용/자원 분석은 그대로이며 새 28입력의 결과로 옮기지 않는다. QA04는 실제8과제 근거가 없어 미측정이고 QA06/QA08의 범위·단위는 유지한다. v10 발표와 설계 그림도 보존하며 최신 평가 계약은 발표에 미반영이다.

2026-10-22 이관에서는 사용자 확인 v10 PPTX와 QA v3 원장 및 산출물의 bytes를 보존했다. v10에는 DP2의 기존 PoC, DP3와 DP44의 합성 예시, DP5의 미평가 상태가 남아 있다. QA v3에는 네 DP의 조건부 개별 권고가 있다. 이 차이를 숨기지 않으며 이번 자료 정리로 발표 내용까지 재평가한 것으로 표시하지 않는다.

QA07의 이전 확장 범위는 v2에서 도입됐고 v3에서 32사례 × 5회, 90% 목표와 점수 제안으로 구체화됐다. 이번 사용자 범위 재확정에 따라 이 제안은 보존한다. 새 업무 순서 및 연결 정확도에 이름만 바꾸거나 기존 점수/분모를 전용하지 않는다. 반영 완료와 보존 범위는 [정합성 이슈](../evaluation/qa07-scope-transition-20261023.md)를 따른다. DP44 설계 변경이나 별도 QA 신설을 포함하지 않으며 QA06/QA08의 범위와 요구는 유지한다.
