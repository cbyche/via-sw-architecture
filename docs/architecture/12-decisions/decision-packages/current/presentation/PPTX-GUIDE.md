## 발표 내용과 비교 구성

각 DP는 사용자의 문제와 설계 질문을 설명하고, 기본안의 실제 구조와 QA 손익을 비교한 뒤 선택 조건과 보완을 제시한다. 배경, 비교, 선택 및 보완, 상세라는 흐름은 유지하되 과거의 DP당 네 쪽이나 총 16쪽을 고정 분량으로 강제하지 않는다. 현재 사용자가 요청한 분량과 기존 파일의 보존 범위가 우선한다.

- 비교 장과 선택 장은 대안 이름 및 순서, 공통 QA 행 순서와 대응하는 표의 위치를 맞춘다. 선택 후에도 다른 대안과 기본안의 단점을 남긴다.
- 선택한 열의 외곽선과 체크, 추가한 보완 경로 및 설명을 연결한다. 미선택, 조건부 권고, 미평가 보완을 각각 표시하고 근거 없이 선택 표시를 추가하지 않는다.
- 기본안과 보완은 별도다. A2가 A1을 자동 포함하지 않는다. 같은 조건의 기본안과 보완안만 전후 비교하며 추가 비용과 남은 실패를 보인다.
- 구조적 동점, 우열 미확정, 비적용과 미측정을 구별한다. 다른 계약과 모집단, 부분 실행과 완주 결과, 실측과 가상 평가를 하나의 수치나 개선 효과로 묶지 않는다.
- 발표에 쓴 수치는 같은 패키지의 QA 정의, 목표와 점수 판본, 시나리오 및 평가 원장으로 연결한다. 발표 편집 과정에서 QA의 의미나 결과를 바꾸지 않는다.

## 편집 가능한 그림과 서체

납품 대상은 Windows의 Microsoft PowerPoint다. 모든 선언 서체는 **Calibri**로 한다. Latin, East Asian, complex-script, 표, 노트, master, layout과 theme을 포함한다. 글자 크기는 실제 PowerPoint point 단위의 정수이며 자동 축소로 소수 크기를 만들지 않는다. 문서 언어와 기존 텍스트 및 새 텍스트 기본값은 `ko-KR`로 한다.

본문 글자는 검정이고 다른 글자색은 강조에 사용한다. 통합 발표의 시각 참고는 [presentation_kjh](../../../../../presentations_files/reference_presentaion/presentation_kjh/)다. 참고 PNG를 슬라이드 전체 이미지로 붙여 편집 가능한 구조도나 표를 대신하지 않는다. 도형의 라벨은 해당 도형 자체의 text body에 넣고, 독립 텍스트 상자를 겹쳐 라벨을 흉내 내지 않는다.

Component와 Module의 상자에는 이름을 쓰고 동작, 조건과 송수신 자료는 선에 표시한다. Module은 소유 Component 내부에 두며 논리 Component, 실제 process와 모델 인스턴스를 구별한다. 요청과 반환, 의미 제안과 채택, 전송 허가와 실제 전달을 다른 사건으로 그린다. 자세한 표기와 검수는 [현재 그림 지침](../guidelines/diagram-guide.md)과 그 원전을 따른다.

비교 그림의 A/B 색과 선택 또는 tactic 강조색은 용도가 다르므로 그림마다 범례를 표시한다. 같은 색을 품질 우위의 증거로 사용하지 않는다. 화면 지칭이 중심인 DP3에서는 해당 장면을 충분히 설명하되 다른 DP의 주제까지 화면 지칭으로 바꾸지 않는다.

## 수정의 시작점과 원본 소유

1. [현재 판본 목록](current-deck.json)의 파일과 SHA, 발표별 근거 상태를 확인한다. `final`, `latest`라는 과거 파일명이나 가장 큰 버전 숫자로 시작본을 고르지 않는다.
2. 현재 v10 PPTX 사본에서 새 번호로 작업한다. 기존 슬라이드, 표, 노트, media와 관계 중 변경 허용 대상을 먼저 기록하고 비대상 자료는 보존한다.
3. 구조가 달라지면 같은 패키지의 해당 DP 본문, 계약, scene, SVG와 draw.io를 먼저 일치시킨다. 현재 정본은 [설계 보정 폴더](../design-review/README.md)와 DP별 폴더다. 발표용 복사본만 고쳐 두지 않는다.
4. PPTX를 직접 편집한 내용은 생성기와 draw.io에 자동 반영되지 않는다. 편집 내용을 현재 scene과 생성 코드에 되돌린 다음 파생 자료를 갱신한다. SVG만 단독 수정하지 않는다.
5. [sources의 v10 스냅샷](sources/README.md)은 고정 재현 자료다. 차기 편집에 필요한 코드를 새 `sources/v11/` 등의 revision으로 가져와 현재 설계 원본을 입력으로 연결한다. 이전 `scripts/presentations/`와 새 원본을 양쪽에서 동시에 유지하지 않는다. 새 revision의 manifest에 단일 작성 원본과 의존 자료를 기록한다.
6. 슬라이드 선택은 의미가 있는 key, DP 번호와 페이지 종류 및 실제 presentation relationship으로 확인한다. `slideN.xml`의 N만 믿고 다른 페이지를 교체하지 않는다. 변경 범위만 생성하고 package 보존 검사를 수행한다.

v10 생성기는 v9의 특정 그림 영역과 라벨을 바꾸는 변환이다. v10을 v9 입력처럼 다시 넣으면 안전한 일반 편집기가 되지 않는다. 전체 재생성 또는 다른 판본을 재병합하여 현재 내용을 덮어쓰지 않는다. 역사적 v9에서 v10 재현과 최신 v10에서 v11 편집은 별도 작업이다.

## 검증과 발행

아래 명령은 저장소 루트에서 신규 PPTX 경로를 넣어 실행한다.

```sh
.venv/bin/python scripts/presentations/presentation_windows_policy.py check NEW.pptx
```

서체와 언어 검사 외에 package 무결성, 슬라이드 수와 순서, native 표와 도형, 노트, 이미지 및 관계와 비대상 part 보존을 확인한다. 최종 PPTX를 다시 읽어 변경한 모든 페이지를 렌더하고 겹침과 잘림, 선의 출발과 도착 및 구조 의미를 눈으로 검토한다. 전체 순서나 theme을 바꿨으면 영향받는 모든 페이지가 검토 대상이다.

Windows 검증을 사용할 수 있으면 [.github/workflows/presentation-windows-check.yml](../../../../../../.github/workflows/presentation-windows-check.yml)에 실제 새 파일 경로를 지정하여 Open XML SDK 검사와 해당 SHA를 기록한다. PowerPoint 앱을 설치하여 실행했는지 별도로 밝힌다. SDK 성공이나 다른 판본의 성공을 native PowerPoint 렌더링 및 GIF 재생의 확인으로 바꾸지 않는다.

새 파일과 렌더, 검증 결과를 같은 revision으로 저장하고 [현재 판본 목록](current-deck.json)에 작성 원본, 설계 및 QA 판본, 근거 상태와 반영한 변경을 기록한다. README의 현재 링크와 전체 미리보기도 함께 갱신한다. 이전 PPTX와 그 평가 원값 및 실패는 보존한다.

이번 이관처럼 원본 전체 바이트가 같고 내용 편집이 없는 경우에는 SHA와 package 동일성 및 기존 렌더의 출처를 확인할 수 있다. 이것을 새로운 렌더 검사나 새로운 설계 및 성능 검증이라고 기록하지 않는다.
