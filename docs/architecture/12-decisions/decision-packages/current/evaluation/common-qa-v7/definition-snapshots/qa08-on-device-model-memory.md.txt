## 2. 무엇을 추가 메모리로 세는가

**추가 모델이 없으면 필요하지 않은 메모리**를 센다. 비교 실행 전에 모든 대안이 공유하는 기본 기능과 기본 모델, 추가 모델 및 그 의존성을 목록으로 고정한다. 특정 대안의 추가 모델을 기본 모델로 옮겨 한도를 피하지 않는다.

| 자원 | 포함 규칙 |
| --- | --- |
| 모델 가중치 | 로딩한 모든 추가 모델과 보조 모델의 실제 상주 가중치. 변환/압축 해제/모델 교체 중 겹치는 복사본도 포함 |
| 실행 엔진 | 추가 모델 때문에 필요한 라이브러리, 세션, 그래프 최적화 상태, 스레드 및 allocator의 상주 공간. 전용 worker의 실행 비용도 포함 |
| 추론 임시 공간 | 입력 tensor, 중간 activation, attention/KV cache, workspace와 출력 tensor 등 실제 사용하는 상태 |
| 모델 전용 상태 | embedding, 화면 프레임/객체/추적 상태, 재사용 캐시, 전후처리와 IPC 복사본 중 추가 모델 경로 때문에 필요한 부분 |
| 공유 기본 모델/엔진의 증가분 | 기본 상태는 제외하되 추가 기능 때문에 늘어난 세션, KV, 캐시, 버퍼와 복제 가중치는 포함. 공유 엔진 전체를 0으로 처리하지 않음 |
| 기본 VIA 자원 | 모든 대안에 필요한 UI, 일반 요청 상태, 기존 음성 입력 등은 QA06 범위. 추가 모델 경로가 늘린 사본이나 상태는 QA08에도 포함 |
| 제외 | 디스크상의 모델 파일 크기, 아직 실메모리를 쓰지 않는 주소 공간 예약, 원격 모델 서버의 메모리, Downstream Agent 내부 메모리 |

호스트 RAM과 GPU/NPU가 사용하는 메모리를 자원별로 기록한다. **시스템 RAM과 별도의 전용 가속기 메모리를 합산하되, GPU/NPU가 시스템 RAM을 공유하면 같은 물리 메모리를 한 번만 센다.** CPU에서 GPU로 옮겼다는 이유로 메모리 사용량이 사라지지 않는다. 이 합산 범위는 실행 장치가 다른 DP에도 같은 뜻으로 적용하기 위한 측정 제안이다.

여러 프로세스가 가중치나 실행 엔진 페이지를 실제로 공유하면 한 번만 센다. 별도의 실제 복사본은 각각 포함한다. 모델별 최고값이나 프로세스별 최고값을 더하지 않는다.

### QA06과의 관계

QA06은 **VIA 전체의 실제 RAM 최고량**, QA08은 **추가 모델 실행에 귀속되는 메모리 최고량**이다. QA08의 호스트 RAM 부분은 QA06에도 포함되므로 두 값을 더해 전체 메모리를 만들지 않는다. 가속기 전용 메모리는 QA08에서 별도 구성값으로 공개한다.

QA06의 기존 512 MB 요구와 DP3 탐색의 상한 적용 유보는 그 문서의 범위를 유지한다. QA08 추가로 QA06에서 모델을 빼거나 전체 허용량을 512 MB + 1 GB로 늘리지 않는다. 두 요구가 모두 적용되는 구성에서는 둘 다 만족해야 한다. 같은 호스트 RAM 범위라면 전체 512 MB 요구가 더 엄격하므로 QA08 충족만으로 전체 제품 적합성을 선언하지 않는다.

## 3. 대표값과 판정

```text
H_r(t) = 시각 t의 추가 모델 경로에 귀속되는 호스트 실제 RAM
D_r(t) = 같은 시각의 별도 전용 GPU/NPU 실제 메모리
R_r(t) = H_r(t) + D_r(t)   (공유 물리 메모리는 H에서 한 번만)
M_bytes = max_r max_t R_r(t)
M = M_bytes / 1,000,000,000  [GB]
목표 충족: M_bytes < 1,000,000,000
```

기본안 대비 전체 VIA의 피크 차이 `peak(추가안) − peak(기본안)`을 QA08로 사용하지 않는다. 두 피크는 발생 시점과 처리 단계가 다르며, 다른 자원의 감소가 모델 비용을 가릴 수 있다. 전체 프로세스의 실행 전후 단순 차이도 보조 진단이다. 귀속이 확인된 자원 원장과 동일 시각의 실제 관측으로 주지표를 만든다.

추가 모델이 없는 대안은 경로와 의존성을 확인한 뒤 **0 MB(추가 모델 없음)**로 표시할 수 있다. 모델을 구현하지 않았거나 호출을 건너뛴 대안을 0 MB로 처리하지 않는다. 측정 누락, 공유 중복 미해결과 장치 귀속 불명은 `INCOMPLETE_MEMORY`이며 목표 충족이나 0점으로 확정하지 않는다.

## 4. 모든 DP에 적용하는 측정 조건

| 조건 | 공통 규칙 |
| --- | --- |
| 장치 | 대상 Galaxy Book의 SKU, RAM, CPU/GPU/NPU, Windows 빌드, 드라이버와 전원 모드를 고정. 지원 SKU별 별도 보고 |

| 입력 | 같은 원본, 화면 해상도/프레임 수, 음성 길이, 문맥 길이, 요청 도착과 정정/취소 시각 적용. 필요한 결과와 품질 조건도 동일 |

| 지원 한계 | 제품이 허용할 최대 입력 크기, 문맥/프레임 보존량, 동시 요청과 모델 세션 수를 실행 전에 고정하고 그 경계 부하를 추가. 모든 대안에 같은 사용자 부하 적용 |
| 초기 실행 | 앱/worker 시작 전부터 관측. 추가 모델이 미로딩인 상태의 최초 로딩과 첫 추론 포함. OS 파일 캐시 상태도 기록하며 프로세스 재시작을 디스크 cold 상태와 혼동하지 않음 |
| 반복 실행 | 같은 세션에서 반복 요청과 여러 업무를 이어 처리하여 캐시, arena와 누적 상태를 관측. 요청마다 재시작해 지속 상태를 없애지 않음 |
| 동시 실행 | 허용한 최대 사용자 부하에서 실제 설계의 실행/대기 정책 적용. 실행 중 모델, 대기 입력, 보존 상태와 로딩 중 새 모델이 겹치는 구간 포함 |
| 교체와 종료 | 모델 전환, 취소, 후속 정리, 유휴 유지와 회수까지 관측. 유휴 회수 정책의 시한 이후 해제 완료 또는 정책상 유지 상태까지 확인. 실패/복구 경로는 별도 표시하고 피크 보존 |
| 반복 횟수 | 위 묶음을 초기 상태에서 **5회** 실행하는 제안. 한 묶음 내부에는 초기 실행과 반복 사용을 모두 포함. 5회는 기존 메모리 평가와 맞춘 운영 규격이며 통계적 보장 수가 아님 |
| 집계 | 지원 환경과 활동별 원값 및 전체 5회의 최고값. 평균으로 일시적인 상한 초과를 숨기지 않음 |

기본 탑재 앱과 일정한 업무 앱 부하를 유지한다. 인위적인 working-set 비우기나 과도한 외부 메모리 압박으로 상주량을 낮춘 결과를 인정하지 않는다. 메모리 절감으로 로딩 지연, page fault 또는 처리 누락이 늘었는지는 QA01/03과 QA02/07 및 기능 완료 기록으로 함께 확인한다.

현재 v4는 실제 실행 자료가 완성된 계측 시험이 아니라 분석 모델이다. 새 QA08 실행에는 실제 모델과 입력 자료, 자원 귀속 및 계측 검증이 필요하며 이번 요구사항 작성으로 모델 실행을 시작하지 않는다.

## 5. 계측 절차와 근거

1. **자원 원장 작성:** 기본 기능/모델, 추가 모델, process/session ID, 공유 메모리, tensor/버퍼의 소유와 수명을 등록한다. 모델을 본체에 넣든 별도 worker에 넣든 같은 범위를 센다.
2. **실제 메모리 관측:** Windows의 프로세스 메모리 관측과 페이지 조사, runtime 할당 이력 및 GPU/NPU 도구를 연결한다. working set만으로 빠지는 잠금/대형 페이지와 장치 버퍼를 확인한다. `commit`, 파일 크기와 runtime의 활성 tensor 크기를 실제 사용량으로 대체하지 않는다.
3. **시간축 연결:** 모든 프로세스, 장치와 모델 수명 사건을 공통 시각으로 기록한다. 고정 주기 표본에 로딩/추론/해제 사건 추적을 보완한다. 예비 검증에서 짧은 피크의 누락과 계측 부하를 확인한 뒤 수집 주기와 허용 오차를 고정한다. 표본 최고값을 연속 시간의 절대 최고값이라고 주장하지 않는다.
4. **귀속과 중복 검증:** 공유 매핑의 정체성과 상주 여부를 확인한다. `QueryWorkingSetEx`의 공유 표시만으로 서로 다른 프로세스 페이지의 동일성을 증명했다고 보지 않는다. 엔진이 보유한 재사용 메모리는 tensor가 해제됐어도 실제 상주하면 포함한다.
5. **반복과 판정:** 동일 활동을 5회 수행하고 원시 바이트, 피크 시각/사건, 모델별 구성, 기능 완료와 오류를 보존한다. 상한 초과가 한 번이라도 관측되면 미충족이다. 누락/귀속 오류 또는 경계 부근에서 측정 오차로 판정이 바뀔 수 있으면 미확정으로 남긴다.

계측의 기술 근거는 다음 공식 자료다. 이 자료가 삼성의 1 GB 상한을 정하는 것은 아니다.

- [Microsoft Working Set](https://learn.microsoft.com/en-us/windows/win32/memory/working-set): 실제 RAM에 상주한 페이지와 working set에 포함되지 않는 일부 할당을 구별한다.
- [Microsoft QueryWorkingSetEx](https://learn.microsoft.com/en-us/windows/win32/api/psapi/nf-psapi-queryworkingsetex): 지정 주소의 페이지 상태 조사에 사용하며 AWE와 large page 조사도 지원한다.
- [Microsoft GPU 메모리 설명](https://devblogs.microsoft.com/directx/gpus-in-the-task-manager/): 전용 장치 메모리와 시스템 공유 메모리 및 프로세스 간 공유를 구별한다. 장치/드라이버별 실제 귀속 방법은 확인해야 한다.
- [ONNX Runtime 메모리 관리](https://onnxruntime.ai/docs/performance/tune-performance/memory.html): 여러 세션의 arena 공유 등 실행 엔진의 메모리 관리가 전체 비용에 영향을 준다. 특정 runtime 사용을 강제하지 않는다.

| 대안 | 같은 기준으로 관측할 부분 |
| --- | --- |
| DP3 A | 추가 시각 모델이 없음을 확인하면 해당 모델 비용은 0. 원본 화면 버퍼와 기본 VIA RAM은 QA06에 남음 |
| DP3 B-R1 | 필요 모델 교체 시의 가중치, 로딩/변환용 복사본, 추론 공간, 보존 화면 상태와 이전 모델 회수 지연. 번갈아 실행한다고 두 모델의 겹침을 무조건 0으로 두지 않음 |
| DP3 B-R2 | 유지되는 모든 모델 가중치와 공유 엔진, 활성 추론 공간, 대기 입력과 캐시의 동시 합계 |
| DP3 B-R3 | 각 worker의 모델과 실행 엔진, 전용 공간, IPC를 합산하되 실제 공유 페이지는 한 번만 계산 |
| 다른 DP | 로컬 검색/embedding, 의미 해석, 음성 등 새 모델을 넣으면 같은 원장과 관측 구간 적용. 모델 종류로 범위를 바꾸지 않음 |

제품 구성에 여러 DP의 추가 모델을 함께 넣으면 **통합 구성의 같은 시각 합계**로 1 GB 미만을 확인한다. DP별로 각각 0.7 GB였다는 사실만으로 두 DP를 결합한 구성이 합격하지 않는다. 공유와 실행 시점이 다르므로 개별 피크 합도 실제 결합 피크로 단정하지 않는다.

설명용 예: 같은 시각 가중치 420 MB, 실행 엔진 120 MB, 추론 공간 180 MB, 모델 전용 캐시/버퍼 80 MB이면 총 **800 MB**다. 같은 실행의 모델 교체 중 총량이 **1,020 MB**가 되었다면 QA08은 **1.02 GB로 미충족**이다. 실제 DP3 측정값이 아니다.

## 7. 0~6점 제안

`QA08-LOCAL-MEM-score-v1`은 기존 QA들과 비교할 때 쓸 **작성자 제안**이다. 사용자가 지정한 요구는 1 GB 미만이며 중간 점수 경계는 삼성 요구사항이 아니다. 500 MB 이하를 6점, 그 위부터 1,000 MB 직전까지를 100 MB 간격으로 나눈다. 예산의 절반을 남기는 수준을 최고 개선 등급으로 삼은 규칙이다.

| 점수 | 표시 | 관측 최고량 M [MB] |
| ---: | --- | --- |
| 0 | ○○○ | M ≥ 1000 |
| 1 | ◐○○ | 900 < M < 1000 |
| 2 | ●○○ | 800 < M ≤ 900 |
| 3 | ●◐○ | 700 < M ≤ 800 |
| 4 | ●●○ | 600 < M ≤ 700 |
| 5 | ●●◐ | 500 < M ≤ 600 |
| 6 | ●●● | 0 ≤ M ≤ 500 |

반올림 전 바이트로 판단한다. 미측정/관측 불완전에는 점수를 주지 않는다. 기능 미완료는 낮은 메모리와 분리해 보고하며 제품 적합성을 인정하지 않는다. 실제 결과가 없으므로 현재 대안 점수나 우승안을 지정하지 않는다.

## 8. 보고할 자료와 호환성

환경/모델/입력 manifest, 기본과 추가 자원 원장, 시각별 호스트/가속기 메모리, 공유 중복 제거 근거, 피크 사건, 5회별 원값, 기능 완료와 오류, 계측 누락, 목표 충족 여부와 점수 제안의 적용 여부를 남긴다. 대기 상주량, 모델 파일 크기와 commit은 별도 진단이다.

기존 QA06 결과에서 임의 고정량을 빼 QA08 실측을 만들지 않는다. v3/v4 계산값을 재사용하려면 자원별 귀속과 중복, 시간축 및 판본을 별도로 검토해 새 분석 결과로 기록해야 한다. 이번 추가는 요구사항과 측정 설계이며 모델 평가, 기존 결과 재채점과 발표 개정은 수행하지 않았다.
