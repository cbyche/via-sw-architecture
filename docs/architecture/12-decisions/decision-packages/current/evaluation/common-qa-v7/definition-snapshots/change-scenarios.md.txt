# QA04 변경 과제와 완료 조건

## 공통 규칙

평가 질문은 **같은 변경 요구를 완료하는 데 운영 모듈을 몇 개 수정하는가**다. 아래 여덟 과제를 모든 구성에 동일하게 적용한다. 특정 DP를 유리하게 만들기 위해 요구 기능이나 필요한 증거를 바꾸지 않는다. 두 형식 변경과 여섯 기능/정책 변경을 같은 비중으로 집계한다. 이 비중은 공통 비교 계약이며 실제 릴리즈 빈도라고 주장하지 않는다.

- 표의 변경 전은 시험할 기준 동작이다. 실제 후보가 이를 제공하는지 먼저 확인한다. 이미 변경 후 기능까지 제공하면 0개 변경을 수용 시험으로 증명한다.
- 변경 전 필수 기능이 고장 난 경우 그 수리는 baseline 수정으로 구별한다. 결함이 있는 약한 안을 변경 비용 비교에 그대로 넣지 않는다.
- 각 과제는 독립 실행한다. 다른 과제의 새 기능을 전제로 하지 않는다.
- 시간 t1/t2, 자료·문장 ID 등은 시험용 식별자이며 제품 정책 수치가 아니다. 구체 원본과 source 판본, 의미 정답, 경합 순서는 양안 실행 전에 동결한다.
- 새 기능의 사용자 흐름과 결과는 공통이다. A를 B 구조로 전환하라는 구현 요구를 넣지 않는다. 특정 저장소, Component, 모델 호출 횟수나 모듈 수를 강제하지 않는다.

## Q4-C01 모델 데이터 형식 변경

**쉽게 말하면:** 모델이 주고받는 데이터의 모양이 바뀌어도 같은 요청을 처리한다.

- 변경 전: 제품의 기존 모델 요청·응답·사용량 형식을 사용한다.
- 변경 후: 요청 본문, 응답 내용, 취소 상태와 사용량의 필드 이름/중첩 위치가 바뀐 동등한 형식을 사용한다. 예를 들어 사용량의 `input_tokens`가 `usage.input.total`로 이동한다. 정확한 전후 schema와 예제는 adapter 시험 자료로 고정한다.
- 완료 조건: 같은 요청 내용과 응답/취소 결과를 얻고 입력·출력·cache 등 청구 항목이 빠지거나 중복되지 않는다. 기존 오류 응답도 동일한 의미로 처리한다.
- 제외: 새로운 모델의 추론 능력 개선, streaming 기능 신규 도입, 학습/양자화. 기능은 같은 형식 변경이다.
- 관련 경로: 공통 Model Access와 실제 소비자. 어댑터만 수정되면 그대로 기록한다.

## Q4-C02 Agent 데이터 형식 변경

**쉽게 말하면:** Agent의 요청·취소·접수 메시지 모양이 바뀌어도 같은 업무 상태를 추적한다.

- 변경 전: 기존 작업 요청, 취소 요청, 접수 확인/거절 형식을 사용한다.
- 변경 후: 같은 의미의 필드를 새 이름/중첩 구조로 수신·전송한다. 전후 메시지의 업무 ID, 요청 판본, 접수 상태를 일대일로 대응한다.
- 완료 조건: 한 업무가 한 번 접수되고, 전송 성공과 실제 접수가 구별되며, 취소 요청과 확인된 종료가 뒤섞이지 않는다. 늦은 확인도 원래 업무에 연결한다.
- 제외: Agent 내부 업무 알고리즘 변경, 새 업무 기능, 재시도 정책 신규 설계.
- 관련 경로: Agent adapter와 실제 상태 소비자. 작은 변경으로 끝나는 대조 과제로 유지한다.

## Q4-C03 화면의 범례와 그래프 계열 연결

**쉽게 말하면:** “이 범례의 항목에 해당하는 그래프를 설명해줘”를 처리하도록 지칭 관계를 확장한다.

- 변경 전: 표·버튼·문단·그래프 자체의 지정 대상을 식별하는 기존 동작을 유지한다.
- 변경 후: 한 화면의 차트 범례 항목과 그 항목에 대응하는 데이터 계열/그래프 범위를 연결한다. 선택한 범례 L1에서 계열 S1을 식별하고 다른 계열 S2를 섞지 않는다.
- 시험 자료: 범례와 두 계열이 화면에 관측되는 동일 차트 및 실제 제공 가능한 native 정보. 후보 한쪽에만 정답 관계나 객체 ID를 주지 않는다. 모호한 자료는 기능 확인 사례로 별도 구분한다.
- 완료 조건: 범례 선택→해당 계열, 지칭 정정 L1→L2→계열 S2 연결이 맞고, 기존 표/버튼/문단 사례도 유지된다. 데이터의 도메인 통계 분석은 요구하지 않는다.
- 제외: 시각 모델 자체의 재학습, 모델 내부 구현. 제품 adapter·근거 표현·prompt·결합 코드의 변경은 포함한다.
- 관련 경로: DP3 직접 지칭 해석 또는 대상 생산/결합. 기존 일반 관계 표현으로 이미 가능하면 그 동작을 검증한다.

## Q4-C04 요청별 임시 자료 보관 규칙

**쉽게 말하면:** 어떤 요청의 자료는 끝나면 버리고, 다른 요청의 자료는 정해진 기간까지 다시 쓸 수 있게 한다.

- 변경 전: 해석용 임시 자료에 공통 보관 규칙을 적용한다.
- 변경 후: 요청에 `종료 시 폐기` 또는 `정해진 만료 시각까지 재사용`을 지정한다. 영구 원본 문서를 지우는 기능이 아니라 요청 해석용 임시 복사본·문맥의 보관 규칙이다.
- 시험 자료: 동시에 존재하는 R1/R2와 각각만 사용하는 자료, 양쪽이 적법하게 공유하는 자료. R1 종료와 R2의 만료 시각을 고정한다.
- 완료 조건: R1 종료 후 R1 전용 임시 내용이 재사용되지 않고 소유 참조가 정리된다. R2의 유효 자료는 유지하고 기한이 지나면 회수한다. 공유 자료는 다른 유효 소유자가 있으면 유지하되 R1의 만료된 접근으로 다시 사용하지 않는다.
- 유지: 업무 ID·현재 판본·실제 전달 사실 등 최소 필수 기록. 민감 원문을 필수 기록이라는 이유로 다시 복사하지 않는다. 실제 사용자가 받은 내용의 기록 정책은 그대로 유지한다.
- 제외: 원본 파일 삭제, 영구 사용자 기억 정책 변경, process 재시작 복구 신규 도입.
- 관련 경로: DP2의 공유 문맥/실행별 상태, 공통 근거 소유와 회수. 논리 실행이 분리됐다는 사실만으로 수정 0개를 부여하지 않는다.

## Q4-C05 기억한 선호의 적용 기한

**쉽게 말하면:** “이번 달까지만 이 형식을 써줘”처럼 선호를 기한까지만 적용한다.

- 변경 전: 명시적으로 저장한 선호는 수정/삭제 또는 기존 유효성 조건에 따라 적용된다.
- 변경 후: 사용자가 지정한 만료 시각을 선호에 붙이고, 만료 이후 새 요청에는 그 선호를 자동 적용하지 않는다. 기한 없는 선호는 종전대로 동작한다.
- 시험 자료: 같은 자료와 같은 요청을 만료 전/후에 제공한다. 만료 경계를 걸쳐 만들어진 조회/파생 결과를 함께 확인한다.
- 완료 조건: 만료 전 적용, 만료 후 미적용, 기한 없는 선호 유지가 확인된다. 만료된 선호를 파생 관계/캐시에서 다시 가져와 적용하지 않는다. 오래된 저장 기록을 읽을 때 기한 없음의 의미를 보존한다.
- 제외: 선호를 삭제하라는 요청과 만료를 동일시하지 않음. 새로운 추천 알고리즘이나 자동 Agent 선택 우열을 평가하지 않음.
- 관련 경로: DP5 원본 관계 해석 또는 사전 생산/조회/무효화. 상태 이관이 실제 필요할 때만 해당 코드 변경을 센다.

## Q4-C06 응답의 지정 문단만 수정

**쉽게 말하면:** 답변의 두 번째 문단만 바꾸고 나머지 내용과 음성은 유지한다.

- 변경 전: 응답 전체를 새 판본으로 교체할 수 있다.
- 변경 후: `response_id + section_id`로 지정한 문단을 수정하고, 대응하는 아직 전달하지 않은 음성을 갱신한다.
- 시험 자료: 세 문단 P1/P2/P3 중 P1은 전달됐고 P2/P3은 대기 중인 상황에서 P2를 교체한다.
- 완료 조건: 화면 P2와 대기 음성 P2는 새 내용이며 P1의 실제 전달 사실과 P3의 내용/의무는 보존된다. 늦게 도착한 P2 구판 출력은 사용하지 않는다. 다른 Task는 그대로 유지한다.
- 제외: 이미 들은 내용을 소급 삭제, 음성 모델의 내부 편집 알고리즘 강제.
- 관련 경로: 응답 판본, DP44 준비/발화 상태, 화면과 실제 전달 이력. 양안의 부분 범위 계약이 이미 지원하면 0개 가능.

## Q4-C07 선택 문장 다시 읽기와 원래 위치 복귀

**쉽게 말하면:** 이미 나온 답변에서 한 문장만 다시 듣고, 듣던 설명을 계속 듣는다.

- 변경 전: 응답 단위 읽기와 중단 지점 이후 계속 읽기를 지원한다.
- 변경 후: 사용자가 유효한 응답의 문장 하나를 선택하면 그 문장만 다시 읽고 기존 진행 위치로 복귀한다.
- 시험 자료: R0를 읽다가 문장 S1을 선택한다. S1은 현재 위치와 다른 문장이며 같은 요청 판본에서 유효하다. 선택/복귀 직전 정정 또는 권한 철회도 공통 순서로 시험한다.
- 완료 조건: S1만 재생하고 나머지를 불필요하게 처음부터 읽지 않는다. R0의 실제 중단 위치를 유지해 남은 내용으로 복귀한다. 선택 재생도 실제 전달 이력으로 남으며 구판/철회된 문장은 재생하지 않는다.
- 제외: 새로운 문안 요약/생성, 선택 음성의 사전 준비 강제. 유효 audio 재사용과 필요한 재생성 모두 허용한다.
- 관련 경로: DP44의 준비 구간 조회 또는 현재 발화 전환/복귀 및 공통 UI/전달 이력.

## Q4-C08 자료의 지정 구간만 사용 철회

**쉽게 말하면:** 문서 전체를 막지 않고 특정 문단만 앞으로 사용하지 못하게 한다.

- 변경 전: `source_id`로 자료 전체의 사용 허용을 철회한다.
- 변경 후: `source_id + revision + extent`로 지정한 구간만 철회한다. 원본 파일을 삭제하라는 요구는 아니다.
- 시험 자료: 같은 문서의 E1/E2 중 E1을 철회한다. E1을 사용한 파생 관계·준비 응답, E2만 사용한 결과와 다른 문서 결과를 함께 둔다.
- 완료 조건: E1을 새로운 해석/조회/출력에 사용하지 않는다. E1에 의존하는 파생 관계와 미전달 응답을 차단하거나 유효 내용으로 재구성한다. E2 및 무관한 자료는 계속 사용할 수 있다. 늦은 구판 결과도 재사용하지 않는다.
- 제외: 전체 문서 차단으로 부분 철회를 대체, 이전 적법 전달을 소급 실패 처리, 새로운 접근권한 체계 도입.
- 관련 경로: 공통 권한/근거 계약, DP3 대상 근거, DP5 파생 관계, DP44 준비 응답. 기존 정책으로 충족되면 검증된 변경 수를 그대로 사용한다.

## 실행 전 점검과 보고

각 과제에 기준 commit, 전후 동작 확인, 공통 수용 자료, 모듈/자산 registry, 독립 patch, 수정 이유와 회귀 결과를 연결한다. 구체 구현을 아직 하지 않았으므로 모듈 개수를 이 문서에서 예상 배정하지 않는다. 실제 사용 빈도로 가중하려면 빈도 근거와 새 판본을 합의하고 양안에 동일 적용해야 한다.

이전 C01~C06 원전과 결과는 보존한다. Q4-C01/02는 기존 C01/02의 동등 형식 변경을 구체화했고 Q4-C06/08은 기존 C04/06의 확장 요구를 계승한다. Q4-C03/04/05/07은 새로 명시한 변경 요구다. 종전 C03 좌표/시각 형식과 C05 원본 표시 과제의 결과를 새 ID로 바꾸지 않는다.
