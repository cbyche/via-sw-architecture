## 2. 필요한 원장

아래는 평가 구현에 넘길 필수 의미 규격이며 특정 JSON schema나 제품 구현을 강제하지 않는다. 모든 시각은 공통 단조 시계로 연결하고 원격 시각 변환과 오차를 남긴다.

| 원장 | 필수 내용 |
| --- | --- |
| 사건 | `event_id`, 종류(Voice/Text/Agent), 원래 source 시각, VIA 수신 시각, 사전 NORMAL/WAIT 구분과 사유, 음성 전달 의무, 공통 정책 판본, 연결 목표/Request |
| 목표 | `goal_id`, 최초 입력/revision, 필수 종료 상태, 필요한 외부 확인, 채널별 출력 의무, 후속 정정과 정상 철회 규칙 |
| 응답 | `response_id`, revision, 대응 사건/목표, 채택한 의미와 시각, 문장/음성 구간 ID, 현재성/권한, superseded/cancelled 상태 |
| 출력 시각 | 첫/전체 음성 생성 완료, 채널별 전체 준비 수용, 첫 실질적 음성의 실제 출력, 마지막 유효 음성 전달, 첫/전체 화면 표시 |
| 차례 | 사용자 발화 시작/끝, 기존 응답 재생 시작/끝과 우선순위, 공통 정책이 금지한 출력 구간, 이유와 대상 |
| 처리 span | span ID, 실제 시작/끝, owner(VIA/Agent/사용자/전달), 작업/대기 구분, 원인, 부모 ID, 자원 ID와 실제 선후 관계 |

완료 이벤트 하나에만 의존하지 않고 필요한 상태/자료/채널 준비 증거와 대조한다. 후보가 `done`이나 `ready`를 빨리 기록했다고 기능 의무가 사라지지 않는다. 반대로 결과가 틀렸다는 이유로 이미 관측한 종료 시각을 후속 정답 시각으로 바꾸지도 않는다.

## 3. QA01 계산 순서

1. 음성 의무 사건을 등록하고 공통 일정/차례 정책에 따라 NORMAL, WAIT_USER, WAIT_PREVIOUS, WAIT_BOTH를 실행 전에 지정한다. 관측된 대기가 0인 건만 추리지 않는다.
2. 입력/사건과 실제 첫 실질적 음성 구간을 연결하고 `l = 음성 시작 - 사건 시작`을 계산한다. 일반 인사/화면 표시/생성 완료로 종료하지 않는다.
3. NORMAL 사건의 유효 평균 L에 목표 2초와 QA01-VOICE-score-v1을 적용한다. 내부 큐, 모델과 장치 출력 지연은 포함한다. 후보가 유발한 차례 충돌도 NORMAL에서 빼지 않는다.
4. WAIT는 대기 포함 실제 지연, 사용자 발화 U, 앞 응답 P, 겹침과 `B = |U ∪ P|`, 나머지 `E = l-B`, 마지막 대기 종료 후 추가 지연 R을 별도로 기록한다. E와 R은 다를 수 있으며 타임라인을 함께 남긴다.
5. 내용 채택 후 발화 가능 구간 D와 선행 준비를 진단으로 유지한다. D/B/E/R을 더하거나 WAIT의 E를 NORMAL 별점으로 바꾸지 않는다.
6. DP 표에는 NORMAL 평균/별점과 WAIT 유형별 총 지연/대기/추가 지연을 함께 표시한다. 각각의 예정 수, 관측 수, 철회/실패/계측 누락을 공개한다. 불완전 관측을 전체 별점으로 확정하지 않는다.

두 대안에 동일한 사건 ID, 일정, 앞 응답의 필요한 내용/길이와 차례 정책을 적용한다. 대기 중 선행 준비는 허용하며 실제 자원/비용을 기록한다. 실행 결과를 보고 NORMAL/WAIT 소속을 바꾸지 않는다. 차례 대기와 내부 자원 대기를 구별한다.

## 4. QA03 계산 순서

1. 공통 목표의 시작, 적용 채널, 필수 상태/연동 확인과 최종 준비 의무를 고정한다. 일부 후보만 첫 안내로 목표를 종료할 수 없게 한다.
2. 실제 처리와 대기의 span, 상태/데이터와 자원 의존으로 목표별 DAG를 구성한다. 목표 시작 전 완료된 작업은 초기 상태, 시작 이후 남은 경합은 잔여 구간으로 반영한다.
3. 원래 duration으로 계산한 terminal이 관측된 준비/상태 완료시각을 재현하는지 검사한다. 다르면 미복원 trace로 남긴다.
4. 사전에 분류한 Agent 내부 업무, 사용자 대기/발화, 순수 음성/화면 전달과 차례 대기만 0으로 투영한다. VIA의 모델 호출, 네트워크 연동, 상태 확정, 출력 준비와 내부 자원 대기는 보존한다.
5. 실제 인과/자원 순서를 유지하고 모든 필수 완료 node를 잇는 terminal까지의 가장 긴 경로를 구한다. 자원 선행 작업과 그로 인한 대기 시간을 중복 합산하지 않는다.
6. 목표별 값과 전체 평균, 실제 wall-clock, 제외 노드 및 오류/미완료를 보고한다. DAG 값과 wall-clock을 같은 측정값으로 부르지 않는다.

차례 대기 중 이미 생성이 진행되었다면 그 생성 span은 VIA 처리로 남는다. 다음 발화를 선택할 수 없어 순수하게 기다린 구간만 전달 대기로 분류한다. 모델 슬롯 부족, 후보의 스케줄링 지연이나 아직 내용이 채택되지 않은 상태를 차례 대기로 위장해 제외하지 않는다.

## 5. 완료 경계 확인용 사례

| 사례 | QA01 | QA03 |
| --- | --- | --- |
| 한 문장 직접 답변 | 그 문장의 실질적 음성 시작 | 전체 내용/필수 음성 준비와 상태 완료. 두 값의 차이가 작을 수 있음 |
| 첫 안내 후 자료 조사/결과 정리 | 구체적 수행 안내의 실제 시작 | 필요한 결과 취득/관계 확정/최종 준비까지. Agent 업무 시간은 제외 |
| 앞 응답을 듣는 중 새 Agent 결과 도착 | WAIT 별도 결과: 총 실제 지연, 앞 응답 대기와 대기 종료 후 추가 지연 | 결과 연결과 최종 준비의 VIA 경로. 순수 차례 대기는 제외 |
| 먼저 말하고 나머지를 생성하는 streaming | 첫 내용 시작 | 뒤에 남은 필수 응답 전체 생성/준비까지 |
| 빠른 잘못된 답변 | 관측된 첫 음성 시간과 오류 | 관측된 처리 종료 경로와 오류. 후속 정답으로 시간 덮어쓰기 금지 |
| 출력이 누락됨 | 전달 실패/미관측. 0초 아님 | 준비까지 끝났는지와 의무 누락을 분리. 준비값만으로 제품 성공 선언 금지 |

QA01과 QA03은 시간의 일부를 공유한다. 최종 중복 검토에는 같은 목표에서 첫 응답 뒤 남은 처리와 서로 다른 병목의 유무, 대표 사례의 비중을 제시한다. QA 간 수치를 단순히 빼거나 더해 새로운 시간값을 만들지 않는다. 차이를 만들려고 긴 답변, 다단계 업무나 대기 사례의 비중을 사후 변경하지 않는다.

## 6. 승인된 담당 작업 범위

사용자는 정의와 측정방법에 이어 QA01의 일반/대기 상황 분리, 4초 대비 50% 단축한 일반 상황 평균 2초 목표, QA03 평균 5초 목표와 양쪽 우수선/균등 점수 구간을 채택했다. 담당 세션은 이 계약 v2를 기준으로 공통 평가의 새 판본을 갱신한다.

1. QA01 NORMAL/WAIT 사례를 사전에 매핑하고 NORMAL만 2초 기준으로 채점한다. 해당 DP의 WAIT 총 지연, 차례 대기와 대기 종료 후 추가 지연을 별도 표기한다.
2. QA03의 모든 필수 상태/연동/최종 채널 준비 완료 경로를 복원하고 평균 5초 기준으로 채점한다. QA01의 NORMAL만으로 QA03 목표 집합을 자동 축소하지 않는다.
3. 공통 계약, 원장/계산기, JSON/Excel/HTML, 비교표/해설과 검사를 모두 새 판본에 맞춘다. 0점과 미산출을 구별하고 물리 관측, proxy 및 분석값의 증거 종류를 유지한다.
4. QA09는 독립 목록/점수에서 제거한다. QA08은 현재 추가 모델 메모리 정의를 따른다. QA02/QA07 후보 출력이 없으면 정확도를 만들지 않는다. 다른 QA의 정의와 우선순위는 변경하지 않는다.
5. 이전 평가/발표와 이력은 원래 계약으로 보존한다. 기존 화면 또는 혼합 평균 열을 NORMAL QA01로 재명명하지 않는다. 발표자료는 현재 우선순위 밖이다.

새 점수와 원값의 업데이트는 지정된 DP-QA 담당 세션이 수행한다. 이 정의 담당 세션은 별도의 DP 평가 수치나 순위를 생성하지 않는다.
