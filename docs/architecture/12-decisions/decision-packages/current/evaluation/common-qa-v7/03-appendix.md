# QA별 부록 읽기

[전체 비교](README.md) / [부록 JSON](artifacts/appendices.json)

Excel `QA상세부록`과 HTML 세부 유형은 같은 JSON에서 만든다. 유형 태그는 작성한 분석 분류이며 실제 관측이나 새 모집단 동결이 아니다. 표의 작성 건수와 실제 관측 수를 구분한다.

| QA | 세부 내역 | 계산으로 연결되는 자료 |
| --- | --- | --- |
| QA01 | VOICE/TEXT/AGENT, 직접 응답/위임 의도/복합 의도/전달 제어/결과/확인 질문/철회 안내별 NORMAL/WAIT 건수와 평균 | qa01_event_labels, qa01_types, Excel `사건계산`. 사건마다 주유형 하나, 합계 구성당 42예정. NORMAL 36, WAIT 6 중 철회 1은 실제 출력 지연 없음 |
| QA02 | 선택/과거 화면/스크롤 전후/다중 대상/정정 태그의 계획 지칭 수, 관측 수와 정확도 | qa02_expressions의 고유 표현키와 qa02_tags. 태그는 중복 가능하며 합계를 33개 전체 분모로 사용하지 않음. `지칭판정`은 실제 출력 미입력 |
| QA03 | 24목표별 필수 상태/외부 연동/필수 채널과 직렬/병렬 경로, 외부 제외 | `목표계산`, `처리단계`, cases[].nodes 및 timing_overlap |
| QA04 | 변경 전후, 완료 조건과 운영 모듈/실제 patch 증거 | [8개 과제](02-qa04-changes.md), `QA04변경`, [등록부](qa04-change-manifest.json). 새 기록 56개는 모두 미측정 |
| QA05 | 준비/요청/선행 목표/입력/배경/취소·미사용 생산과 모델 과금 종류별 비용 | qa05_buckets, qa05_coverage, `비용원장`. 각 청구 항목은 한 번만 집계. 재시도/후속 청구 관측 공백을 0으로 바꾸지 않음 |
| QA06 | 전체 제품 최고량이 발생한 입력과 같은 시점 구성 자원 | memory_peaks의 qa06, `메모리상태`, cases[].memory_peak |
| QA07 | VIA_LOCAL/DELEGATED/MIXED 사례 묶음과 해석/구성/실제 전달 실패 원인 | qa07_types, `QA07사례`/`QA07의무`. 실제 관측 없음. 한 사례의 여러 원인 합을 전체 실패 건수로 표시하지 않음 |
| QA08 | 추가 모델 최고량이 발생한 입력, 가중치/엔진/추론 상태/버퍼/worker와 호스트/전용 자원 | memory_peaks의 qa08, cases[].qa08_peak. 상세 원장의 MB와 대표 표 GB를 1000으로 환산 |

세부 실패율은 관측값이 있을 때만 제시한다. QA02/QA07의 빈 비율은 0%가 아니다. QA02와 QA07이 같은 지칭 오류로 실패하면 공통 원인 ID를 연결한다. 현재 발생한 오류가 있다는 주장은 하지 않는다.
