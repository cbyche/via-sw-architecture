# QA04 공통 8개 변경 과제

[계약](01-contract-and-scope.md) / [정본](../../qa/change-scenarios.md) / [운영 모듈 등록과 증거](qa04-change-manifest.json)

7구성 모두 같은 8개 변경을 동일 기준 코드에서 각각 독립 적용한다. 현재 56개 기록은 전부 NOT_MEASURED다. 기준 commit, 운영 모듈 registry, 실제 diff와 수용/회귀 증거가 없으며 변경 개수는 null이다. 0개나 구형 concept 추정값으로 채우지 않는다.

| 과제 | 변경 전 | 변경 후 | 완료 조건 | 이전 과제와 관계 |
| --- | --- | --- | --- | --- |
| Q4-C01 모델 데이터 형식 변경 | 제품의 기존 모델 요청·응답·사용량 형식을 사용한다. | 요청 본문, 응답 내용, 취소 상태와 사용량의 필드 이름/중첩 위치가 바뀐 동등한 형식을 사용한다. 예를 들어 사용량의 `input_tokens`가 `usage.input.total`로 이동한다. 정확한 전후 schema와 예제는 adapter 시험 자료로 고정한다. | 같은 요청 내용과 응답/취소 결과를 얻고 입력·출력·cache 등 청구 항목이 빠지거나 중복되지 않는다. 기존 오류 응답도 동일한 의미로 처리한다. | C01 요구 계보만 연결, 수치 재사용 금지 |
| Q4-C02 Agent 데이터 형식 변경 | 기존 작업 요청, 취소 요청, 접수 확인/거절 형식을 사용한다. | 같은 의미의 필드를 새 이름/중첩 구조로 수신·전송한다. 전후 메시지의 업무 ID, 요청 판본, 접수 상태를 일대일로 대응한다. | 한 업무가 한 번 접수되고, 전송 성공과 실제 접수가 구별되며, 취소 요청과 확인된 종료가 뒤섞이지 않는다. 늦은 확인도 원래 업무에 연결한다. | C02 요구 계보만 연결, 수치 재사용 금지 |
| Q4-C03 화면의 범례와 그래프 계열 연결 | 표·버튼·문단·그래프 자체의 지정 대상을 식별하는 기존 동작을 유지한다. | 한 화면의 차트 범례 항목과 그 항목에 대응하는 데이터 계열/그래프 범위를 연결한다. 선택한 범례 L1에서 계열 S1을 식별하고 다른 계열 S2를 섞지 않는다. | 범례 선택→해당 계열, 지칭 정정 L1→L2→계열 S2 연결이 맞고, 기존 표/버튼/문단 사례도 유지된다. 데이터의 도메인 통계 분석은 요구하지 않는다. | 새 요구 |
| Q4-C04 요청별 임시 자료 보관 규칙 | 해석용 임시 자료에 공통 보관 규칙을 적용한다. | 요청에 `종료 시 폐기` 또는 `정해진 만료 시각까지 재사용`을 지정한다. 영구 원본 문서를 지우는 기능이 아니라 요청 해석용 임시 복사본·문맥의 보관 규칙이다. | R1 종료 후 R1 전용 임시 내용이 재사용되지 않고 소유 참조가 정리된다. R2의 유효 자료는 유지하고 기한이 지나면 회수한다. 공유 자료는 다른 유효 소유자가 있으면 유지하되 R1의 만료된 접근으로 다시 사용하지 않는다. | 새 요구 |
| Q4-C05 기억한 선호의 적용 기한 | 명시적으로 저장한 선호는 수정/삭제 또는 기존 유효성 조건에 따라 적용된다. | 사용자가 지정한 만료 시각을 선호에 붙이고, 만료 이후 새 요청에는 그 선호를 자동 적용하지 않는다. 기한 없는 선호는 종전대로 동작한다. | 만료 전 적용, 만료 후 미적용, 기한 없는 선호 유지가 확인된다. 만료된 선호를 파생 관계/캐시에서 다시 가져와 적용하지 않는다. 오래된 저장 기록을 읽을 때 기한 없음의 의미를 보존한다. | 새 요구 |
| Q4-C06 응답의 지정 문단만 수정 | 응답 전체를 새 판본으로 교체할 수 있다. | `response_id + section_id`로 지정한 문단을 수정하고, 대응하는 아직 전달하지 않은 음성을 갱신한다. | 화면 P2와 대기 음성 P2는 새 내용이며 P1의 실제 전달 사실과 P3의 내용/의무는 보존된다. 늦게 도착한 P2 구판 출력은 사용하지 않는다. 다른 Task는 그대로 유지한다. | C04 요구 계보만 연결, 수치 재사용 금지 |
| Q4-C07 선택 문장 다시 읽기와 원래 위치 복귀 | 응답 단위 읽기와 중단 지점 이후 계속 읽기를 지원한다. | 사용자가 유효한 응답의 문장 하나를 선택하면 그 문장만 다시 읽고 기존 진행 위치로 복귀한다. | S1만 재생하고 나머지를 불필요하게 처음부터 읽지 않는다. R0의 실제 중단 위치를 유지해 남은 내용으로 복귀한다. 선택 재생도 실제 전달 이력으로 남으며 구판/철회된 문장은 재생하지 않는다. | 새 요구 |
| Q4-C08 자료의 지정 구간만 사용 철회 | `source_id`로 자료 전체의 사용 허용을 철회한다. | `source_id + revision + extent`로 지정한 구간만 철회한다. 원본 파일을 삭제하라는 요구는 아니다. | E1을 새로운 해석/조회/출력에 사용하지 않는다. E1에 의존하는 파생 관계와 미전달 응답을 차단하거나 유효 내용으로 재구성한다. E2 및 무관한 자료는 계속 사용할 수 있다. 늦은 구판 결과도 재사용하지 않는다. | C06 요구 계보만 연결, 수치 재사용 금지 |

등록부는 Rust/Python 및 제품 코드와 소유 prompt/schema/config, build/이관 모듈을 포함한다. 사전 등록한 모듈 ID, 소스, 공개 경계, 상태와 자산 소유를 실제 patch에 연결한다. 목록이 비어 있다는 것은 아직 등록하지 않았다는 뜻이며 수정 모듈 0개를 뜻하지 않는다.

신규/수정/삭제 모듈을 고유 ID로 센다. 단순 이동은 전후 경로를 같은 ID로 연결한다. 테스트/주석/포맷만 바뀐 것은 운영 개수에 포함하지 않는다. 이미 변경 후 기능을 제공하는 경우도 baseline 확인과 수용/회귀 증거로 0개를 입증해야 한다. 여덟 과제 중 하나라도 미완료면 전체 평균과 점수는 미산출이다.

기존 C03 좌표/시각 형식과 C05 원본 표시 과제는 새 ID로 재명명하지 않는다. 기존 6개 과제와 추정값은 v6와 Excel의 보존 변경과제 표에만 남긴다.
