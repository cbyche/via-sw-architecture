# v5 공통 평가 계약

[시작](README.md) / [현재 QA 계약](../../qa/timing-measurement-contract.md)

## 같은 입력과 근거 수준

DP2/DP3/DP5/DP44의 7구성은 같은 24입력, 24목표, 33지칭 표현과 6변경 과제를 사용한다. 각 사례는 한 번 계산하는 설계 커버리지이며 통계 반복이나 실사용 빈도 표집이 아니다. 사례별 VIA 자체 응답, 외부 위임, 혼합 책임은 [명세](specification.json)에 고정했다. 추가 모델, 전송, 음성 처리와 자원 제한을 후보에 맞춰 누락하지 않는다.

모델 내용과 실제 출력 sample은 없다. 구조상 정상 내용을 생성한다는 조건부 분석이며, 내용 오류와 목표 성공 여부는 UNKNOWN이다. 분석상 출력 시각과 비용을 실제 측정으로 표현하지 않는다. 실패율0이나 정확도100%를 만들지 않는다. 기존 v4를 새 정의로 재명명하지 않는다.

## QA01 음성 사건

`QA01-VOICE-v2`와 `QA01-VOICE-score-v1`을 적용한다. 사용자24, Agent 결과12, 질문5, 철회 안내1을 합쳐 42예정 사건을 등록했다. 각 사건에 source 시각, VIA 수신, 내용 채택, Response revision, 실제 실질 발화 구간에 대응하는 분석 출력 시각을 연결한다. 같은 질문 읽기가 사용자와 Agent 사건을 함께 충족하더라도 사건 시작은 별개다.

사전 분류는 NORMAL36, WAIT_USER5, WAIT_PREVIOUS1, WAIT_BOTH0이다. WAIT_USER의 U18 안내1은 첫 음성 전에 철회된다. 정상 철회는 0초가 아니며 별도 상태다. NORMAL 평균에 WAIT나 WAIT의 E를 넣지 않는다. 후보가 NORMAL에서 차례 충돌을 만들면 분모를 유지하고 회귀 표시한다. 내부 큐·모델·네트워크 지연은 NORMAL에서 제외하지 않는다.

L은 source→첫 실질 음성 경과다. U는 사용자 발화, P는 앞 응답 재생이며 B는 두 구간의 합집합이다. E=L−B, R은 마지막 차례 대기 종료→첫 음성, D는 내용 채택 후 발화 가능 시간이다. U/P 교집합과 생성이 대기와 겹치는 시간도 남긴다. 여러 가능한 발화 구간이 있으면 E와 R은 달라질 수 있다. 구간을 겹쳐 더하지 않는다.

NORMAL 평균 ≤2초가 목표다. 4초 참조 대비50% 단축은 사용자 합의 목표이며 연구의 달성 성과가 아니다. 1초 우수선과 0.2초 간격의 합의 구간으로 반올림 전 평균에 0~6점을 계산한다. 여기의 점수는 분석 가정에만 조건부로 적용한다. 실제 관측이 없는 상태에서 실측 별점을 확정하지 않는다.

NO_AUDIO/UNOBSERVABLE/NOT_OBSERVED는 예정 분모에 남기고 전체 점수를 확정하지 않는다. 잘못된 실질 응답은 원래 시각과 오류를 함께 보존한다. 현재 분석에는 물리/proxy 관측이 없고 오류 여부는 미확인이다.

## QA03 전체 처리 완료

`QA03-COMPLETION-v1`과 `QA03-COMPLETION-score-v1`을 적용한다. QA01의 NORMAL/WAIT와 무관하게 24목표 전체를 사용한다. U08/16/24는 최초 -6초 원점을 유지한다. VIA 최초 해석2초는 공개 토큰 예산600/136으로 모델링하며 모델 슬롯·비용·client RAM에도 포함한다.

종료는 필수 상태 확정, 외부 접수와 결과 확인, 최종 상세 화면과 전체 필수 음성의 전달계층 수용을 모두 만족하는 시점이다. 첫 표시·첫 음성·위임 전송만으로 끝내지 않는다. 전체 음성은 streaming 전송으로 수용할 수 있으며 전체 PCM의 동시 상주를 요구하지 않는다. 실제 표시/재생의 순수 장치 시간은 완료 조건이 아니다.

명시적 처리 DAG의 원래 duration으로 완료 wall time을 먼저 재현한다. 이후 외부 Agent 업무, 사용자 대기와 순수 전달/재생 duration만0으로 투영한다. VIA 원격 호출, 전송, 상태 처리, 음성 준비와 자원 경합은 포함한다. 자원 선행 작업 edge와 같은 대기 시간을 중복 추가하지 않는다. 고정 source 도착과 정정 대기는 이유가 있는 별도 gap node다. 원인 불명 gap을 임의로 제외하지 않는다.

QA03은 VIA 자체 처리 평균5초 예산이다. Windows Long wait 상단5초를 채택했고, 우수선1초까지0.8초 균등 구간을 적용한다. [목표 근거](../../qa/research-notes/qa03-completion-target-rationale.md). 첫 음성 후 남은 VIA 경로는 [진단 표](03-results-and-ranges.md)에 별도 표시하며 QA03−QA01로 계산하거나 새 점수로 만들지 않는다.

## QA02와 QA04~QA08

QA02와 QA07은 후보 출력이 없어 null이다. 작업 중 확장된 `QA07-REQUEST-RESPONSE-v2`의 응답 구성/실제 전달 평가는 이 판본에 미반영이다. 기존 입력 의미 정답과 Excel 판정란은 부분 진단으로만 보존하며 이를 채워도 QA07 대표값을 산출하지 않는다. 다른 QA에 산출값이 있다는 이유로 정확도 성공을 가정하지 않는다. QA04는 동일6변경 과제의 개념 모듈 집합 크기 평균이며 실제 Rust diff가 아니다.

QA05는 요청 전 준비·미사용·취소·후속 생성까지24사례의 VIA 비용 합이다. Agent 내부 비용과 전체 시스템 비용은 null이다. 이전 COMMON-28 비용 목표를 다른 묶음에 그대로 적용하지 않는다.

QA06은 기본560MB와 요청/모델 client/로컬 시각/음성 상태의 같은 시각 전체 RAM 최고량이다. QA08은 그중 추가 로컬 모델 경로의 weights, shared/private runtime, workspace·tensor, 임시 적재, IPC와 보존 프레임/추적 상태를 귀속시킨 별도 최고량이다. 기본 공유 ASR과 UI는 모든 구성 동일하며 의미·음성 생성은 원격이라는 명세다. 추가 상태32MB는 QA06/08 양쪽에 포함하지만 두 QA를 합산하지 않는다.

QA08은 decimal MB이며 엄격히 <1000MB 요구다. 공유 물리 페이지는 한 번, 전용 CPU 호스트 자원은 각 소유자별 한 번 센다. 전용 가속기 메모리는0이다. 모델별 피크 합이나 전체 피크 차감이 아니다. 24사례의 분석 범위이며 최대 지원 부하·5회 장치 실행·제품 적합성은 미검증이다. QA08 점수는 미부여다.

## 이전 판본과 변경 기록

v4 입력과 속도·가격·메모리 가정 대부분을 유지한다. 새 완료 경계의 network0.04초, receipt/state0.03초, channel accept0.02초, screen prepare0.04초를 공개 계수로 추가했다. v4에 빠졌던 모델 전용 보존 상태32MB도 명시했다. U19 생성 시각은 -2→-4초로 양안 동일하게 수정해 -3초 사용자 중단보다 앞서게 했다. U23 자동 질문 알림과 새 Text 입력 안내는 서로 다른 구간이다. U23의 보존 R0 잔여 buffer는 공통12초 초기 상태로 명시해 RAM에 포함했다. 정의 변경과 누락 보완을 성능 개선으로 주장하지 않는다.

v4 전체25파일은 [보존 해시](preserved-v4-sha256.json)로 검사한다. 이전 점수와 원값, 발표 v10, 설계 그림과 accepted ADR는 수정하지 않는다.
