Sensors 2018의 한국어 목적 지향 대화 성공률 약 90%는 목표 수준의 참조이며 VIA 검증 결과가 아니다. TD-EVAL 2025는 마지막 성공만으로 중간 오류를 지우지 않는 판정 방법의 근거다. 표본·반복·기한과 점수 구간은 작성자 시험 설계다. 두 연구의 역할과 적용 한계는 위 근거 문서에 있다.

## 사례와 근거

32개 사례의 입력, 제공 자료, 사건 트리거, 허용 응답과 금지 사항을 원문 그대로 manifest.source_contract와 snapshot에 보존한다. 원장에는 반복마다 세 단계의 판정 슬롯을 둔다. 각 슬롯은 해당 단계의 모든 최초 채택, revision과 필수 의무를 확인하는 체크리스트의 판정이다. 단계 슬롯 수 3,360을 정확도 분모로 사용하지 않는다.

실제 trace를 연결할 때 최초 채택 이력, 전체 입력/사건/권한/채널 조건, 전달 완료 또는 정상 폐기와 후속 관측 종료를 모두 확인한다. 각 단계에 두 평가자의 별도 판정/참조와 실제 출력 근거를 요구하며, 불일치는 조정 참조가 있어야 확정한다. 두 평가자 참조는 서로 달라야 한다. Excel의 `과거 입증 실패 참조`에는 조정된 이전 FAIL의 근거를 남겨 최신 정답으로 지우지 않는다. JSON은 전체 판정 이력의 입증 FAIL을 보존한다.

현재 Excel의 노란 칸은 관측 입력이다. `fixture 완비`와 `실행 동결`은 manifest 검증 후 새 실행 판본에서만 바꾼다. 문장 정답과 빈 원장을 만든 것은 fixture 제작/실행이 아니다. 실제 기록 없이 PASS를 채우거나 정확도를 추정하지 않는다.

## 집계와 부록

같은 구성에서 case_id × repeat_id 160키와 실행 증거 키를 중복 없이 확인한다. 입증 오류가 있으면 FAIL을 유지한다. UNKNOWN이 남으면 전체 Q와 점수를 내지 않는다. 공통 fixture 결함은 모든 구성에 같은 사례 단위로 적용하며 원래 기록을 보존하고 수정/재실행한다. INVALID를 분모에서 빼서 160회 목표를 쉽게 만들지 않는다. 동결이 안 됐거나 중복/공통 무효가 있으면 확정 N도 미산출이다.

8유형의 반복 수는 각각 20회이며 세부 표는 Excel `QA07v3명세` H:O에 둔다. 해석/구성/전달의 실패 원인과 QA02 공통 원인을 함께 기록하되 원인 수의 합을 실패 사례 수로 표시하지 않는다. QA02의 33지칭과 QA07의 160사례 반복은 다른 분모다. 이전 24입력의 시간·비용·RAM 계산에 새 32사례의 정확도 계약을 같은 실험인 것처럼 합치지 않는다.

## 보존과 재생성

v7의 모든 파일은 [해시 원장](preserved-v7-sha256.json)으로 보존한다. 기존 Excel 15시트 중 QA07 연결과 보존 표기만 바꾸고 새 `QA07v3명세`, `QA07v3사례`, `QA07v3의무`를 추가했다. QA04의 실제 변경 증거와 기존 시간/자원 가정은 그대로 유지한다. JSON의 legacy_qa07과 Excel의 구형 QA07 두 시트는 이전 24묶음이다.

실행 명령은 `scripts/architecture/build_common_qa_v8.py`, `scripts/presentations/render_common_qa_v8.mjs`다. 생성기는 snapshot을 우선 사용하여 나중 정의 편집이 기존 판본을 바꾸지 않게 한다. 실제 제품 평가 runner는 아니다.
