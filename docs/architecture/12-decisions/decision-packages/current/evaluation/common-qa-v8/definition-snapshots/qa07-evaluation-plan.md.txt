# QA07 요청 해석 및 응답 적합성 평가 계획

2026-10-23 / `QA07-REQUEST-RESPONSE-POP-v3` / `AUTHOR_DEFINED_COMPLETE` / 32사례, 각 5회 / 미측정

[정의와 점수](qa07-request-meaning-accuracy.md) / [32개 입력과 정답](qa07-evaluation-cases.md) / [목표 근거](research-notes/qa07-meaning-research.md)

## 1. 측정 대상과 단위

시스템에 실제 사용자 입력과 문맥 및 Agent 사건을 제공하고, 최초 채택 해석부터 응답 구성과 실제 화면/음성 전달까지 확인한다. 사례 하나에 최초 요청과 연결된 정정/명확화/승인/거부/취소/재개를 묶는다. 내부 Request, 모델 호출, 출력 chunk 수를 분모로 쓰지 않는다.

대표 모집단은 `QA07-CASES-v3`의 Q7-C01~32다. 8개 유형마다 서로 다른 실패 경로 4개, 각각 5회 반복하므로 분모는 **160회**다. 대표값은 `100 × 전체 성공 횟수 / 160`이며 **144회 이상 성공**이 목표다. 유형별 성공률 평균과 해석/구성/전달의 단계별 평균 또는 곱으로 바꾸지 않는다. 최초 해석이 틀렸다면 최종 답변을 복구해도 해당 반복은 실패다.

대표값을 비교할 후보는 동일한 32사례와 5회 조건을 모두 지원해야 한다. DP별 적용 경로만 평가하는 부분 시험은 부분 진단으로 표시하고 160회 대표값 및 그 별점으로 표기하지 않는다. 공통 기능은 동일한 주변 구조로 연결하고 비교 구조만 바꾼다. 실제 전체 경로가 준비되지 않았다면 관측 결과는 미산출로 기록하며 작성한 정답을 실제 해석 출력으로 대신 넣지 않는다.

## 2. 동일 조건과 실행 순서

1. [사례 문서](qa07-evaluation-cases.md)의 입력, 화면/문서 판본, Task 상태, 실제 전달 이력, 채널 상태와 외부 사건을 공통 자료로 만든다. 후보 출력 확인 전에 파일/스크립트 해시와 아래 oracle를 고정한다. 새 사례를 설계할 필요 없이 지정된 32개를 구현한다.
2. 후보별 모델 판본, 실행 옵션, 기기/OS, 음성 장치와 로그 clock을 기록한다. 정답은 판정 측에만 둔다. 동일 원음/Text와 화면을 사용하며 테스트 전용 정답 의미를 후보에 공급하지 않는다. 각 반복은 세션/상태를 초기화한다.
3. 원음의 시작부터 입력 종료, 부분/전체 최초 해석 채택, 응답 채택과 실제 화면/음성 출력까지 관측한다. 명시적 commit 이전에 실행이나 전달에 썼다면 그 최초 사용을 채택으로 기록한다. 사용되지 않은 내부 후보는 채점하지 않는다.
4. 사례의 후속 사용자 답/제어와 Agent 사건은 사전 지정한 인과 트리거에 따라 제공한다. 응답 지연 때문에 사건 순서가 뒤집히지 않게 하되 내부 처리 대기를 숨기지는 않는다. 잘못된 응답/무응답이 있어도 가능한 후속 경로를 계속 기록하며 이미 발생한 실패는 유지한다.
5. 각 응답 의무의 기능 한도 60초, 사례 한도 300초와 마지막 10초 관측을 적용한다. 취소/정정 행의 구판 재전송/큐 재검사까지 확인한다. 자세한 경계는 다음 절과 사례 문서가 정본이다.
6. 두 평가자가 후보 이름을 가린 전체 trace를 독립 판정한다. 불일치는 입력/정답과 실제 출력 근거로 조정하고 이유를 기록한다. 단순 문자열 일치나 문장 유사도만으로 의미를 판정하지 않는다. 표현 차이와 의무 위반을 구분한다.

다섯 반복은 모델 출력 변동을 관찰하기 위한 공통 실행 규칙이다. 별도의 통계 검정력 산정이나 대표 사용자 160명의 무작위 표본으로 설명하지 않는다. 모델 결과를 보고 반복 수나 사례 비중을 늘리거나 줄이지 않는다.

## 3. 시작, 끝과 무응답 판정

| 항목 | 고정 규칙 |
| --- | --- |
| 사례 관측 시작 | 첫 사용자 발화 시작 또는 Text 제출. 음성 입력 중 조기 채택도 확인 |
| 응답 의무 발생 | 사용자 입력 종료 또는 해당 Agent 사건이 VIA에 제공 가능해진 시각 |
| 응답 기한의 시작 | 의무 발생, 필수 외부 정보 도착, 필수 채널 전달 허용 중 가장 늦은 시각. 내부 해석/큐 지연은 제외 조건이 아님 |
| 응답 기한 | 시작부터 60초 안에 필수 내용의 실제 전달 완료. 단순 “네”나 첫 토큰만으로 종료하지 않음 |
| 차례 대기/취소 | 응답 준비 후 제어 입력 제공. 제어 입력 종료 후 10초에 음성 차례 개방. 이후 구판 응답 새 출력 금지 |
| 후속 입력 | 지정 질문/응답 실제 전달 뒤 1초에 제공. 해당 응답이 60초 내 없으면 누락 실패 기록 후 예정 후속 입력을 제공 |
| 사례의 전체 한도 | 최초 입력 종료 후 300초. 미완료 필수 의무는 누락 실패. 시험이 강제 중단돼 증거 자체가 없으면 UNKNOWN |
| 정상 관측 종료 | 마지막 예정 사건 이후 모든 필수 전달/정상 폐기가 끝난 시점부터 10초 후 |
| 한도 도달 시 종료 | 300초 한도 뒤 10초 관측. 최초 입력 종료 후 최대 310초 |
| 후속 10초의 5초 시점 | 해당 사례의 구판 event 재전송 또는 기존 response 큐 재검사. 중복/무효 출력이 발생하면 FAIL |

60초는 이 시험의 짧은 응답 의무를 무한정 기다리지 않기 위한 충분히 긴 관측 한도다. 최대 4개 응답 차례에 60초씩을 배정한 240초에 제어/사건/채널 전환 여유 60초를 더해 전체 한도를 300초로 정했다. 추가 10초는 등록한 재전송/큐 재검사 뒤 5초를 확인하기 위한 것이다. 모두 작성자 시험 설계이며 연구가 검증한 사용자 수용 지연시간이 아니다. QA01의 2초와 QA03의 5초는 그대로 별도로 측정한다.

본 대표 시험은 취소와 새 출력 사이에 명시적 차례 대기를 두거나 정지 경계를 사용하여 의미/전달의 유효성을 판정한다. 실제 장치의 중단 반응속도와 초근접 동시 사건의 순서는 별도 시간/경합 진단이다. 동일 타임스탬프의 사건은 fixture 순번과 실제 인과 trace로 판정하고, 증거가 부족하면 임의로 유리한 순서를 부여하지 않는다. 취소 이전의 합법적 전달을 소급 실패시키지 않는다.

## 4. 성공 조건과 원장

사례의 각 revision에서 최초로 채택한 의미가 모두 맞고, 채택한 응답 내용과 실제 전달이 그 시점의 유효 요청/상태/채널에 맞으며, 모든 필수 의무가 끝나고 금지된 출력이 없을 때만 PASS다. 하나라도 틀리면 FAIL 한 번이다. 적절한 확인 질문, 근거 없는 질문에 대한 정보 부족 안내, 취소 뒤 정상 폐기도 표의 정답에 맞으면 성공이다.

| 필드 묶음 | 기록할 내용 |
| --- | --- |
| 식별/반복 | case_id, repeat_id, candidate_id, source_execution_key, 정의/표본/점수 판본 |
| 입력과 초기 상태 | 원음/Text/화면 해시, 선택/문서 판본, Task/권한/실제 전달 이력, 모델/기기 조건 |
| 의미 | revision_id, 최초 부분/전체 채택 내용과 시각, 올바른 요청 처리/대상/제한/의존/이전 요청 연결/정정 범위/수행자/수신자 |
| 응답 의무 | obligation_id, 요청/Task/revision, 필수 의미와 출처, 허용 채널/수신자, 허용 질문/거부/폐기 |
| 시간과 출력 | 사건 제공 가능/수신 시각, 최초 사용/채택, 화면 표시와 실제 음성 구간, 중단/재개/큐 폐기, 기능 기한/종료 |
| 판정과 원인 | PASS/FAIL/UNKNOWN/INVALID, 최초 위반 근거, REQUEST_INTERPRETATION/RESPONSE_COMPOSITION/ACTUAL_DELIVERY, 공통 원인 ID |
| 검토 | 평가자 두 명의 판정, 불일치 해결 근거, 누락 증거와 공통 fixture 결함 |

실제 장치 출력 없이 큐/생성 로그만 있다면 실제 전달까지 관측한 대표값을 만들지 않는다. 신뢰할 수 있는 해석 채택 증거 없이 최종 발화만 맞았다고 최초 해석 성공을 추정하지 않는다. 반대로 완전한 관측 중 필수 응답이 없었다면 누락 실패이며 계측 미완료로 바꾸지 않는다.

## 5. 집계와 기존 평가 이관

- 모든 160회가 판정됐을 때 Q와 0~6점을 산출한다. 성공 S, 실패 F, 미판정 U를 항상 보고하며 N=S+F+U=160이다. U가 남으면 점수를 확정하지 않고 가능한 비율 범위만 진단한다.
- 동일 fixture 결함으로 무효인 경우 양안에 같은 원인/판본을 적용하여 수정한 동일 사례를 다시 실행한다. 원래 실패와 원장은 보존한다. 후보의 모델 오답, timeout, 구현 오류는 fixture 무효 사유가 아니다.
- 해석/구성/전달 단계별 실패와 8개 유형별 결과는 부록이다. 같은 원인의 전파를 별도 실패로 합하지 않는다. QA02와 공동 대상 오류는 같은 원인 ID로 연결한다.
- v6의 24묶음과 이전 입력 단위 결과는 보존한다. 새 32사례 원장으로 매핑 가능한 근거만 연결하고 누락한 최초 해석/실제 전달을 추정해 채우지 않는다. 기존 결과에 목표 90%만 붙여 v3 성능으로 만들지 않는다.
- 담당 세션은 이 계약과 32사례에 맞는 원장/출력 구조를 작성한다. 실제 측정은 해당 세션의 실행 승인 범위에 따르며 이 정의 문서 작성은 모델 실행이나 DP44 설계 변경을 뜻하지 않는다.
