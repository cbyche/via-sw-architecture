# QA07 v6 검토와 검증

## 변경 범위

QA07-REQUEST-RESPONSE-v2의 사례 묶음, 최초 해석, 응답 구성과 실제 전달 의무를 U01~U24에 연결했다. Excel과 HTML, JSON 원장은 7구성에 같은 명세를 적용한다. 사례당 한 번 판정하며 의무별 원인 수를 실패 사례 수로 더하지 않는다. 24묶음과 168행은 검토/작성 단위이며 실제 반복이나 동결 분모가 아니다.

## 독립 검토

독립 검토자가 사례 매핑과 Python/Excel 판정기를 읽었다. 세 P2 발견에 다음과 같이 대응했다.

| 항목 | 발견 | 수정 |
| --- | --- | --- |
| R01 | 후보별 무효 문자열로 FAIL을 제외할 수 있었음 | 공통 case manifest와 Excel 공통 레지스트리로 이동. 모든 구성에 동일 근거를 적용하고 위반 의무와 원시 증거는 보존 |
| R02 | 과거 UNKNOWN이 해소되지 않거나 과거 PASS가 최신 미입증 판정을 가릴 수 있었음 | 입증 FAIL은 모든 이력에서 보존. 나머지는 각 의무의 최종 조정 판정과 증거로 집계 |
| R03 | JSON 집계에 중복 실행키 차단이 없었음 | record 기반 집계에서 중복 검출. 해당 PASS와 전체 분모/비율 산출 차단 |

수정 후 독립 재검토에서 R01~R03을 모두 확인했고 열린 P1/P2는 없었다. 실제 모델 내용의 타당성을 두 평가자가 판정한 것은 아니다.

## 수행한 검증과 한계

- [정적 검증](artifacts/validation.json): 24사례와 구성당162의무, 168작성 슬롯, 미측정/미동결 상태, 이전 원장 동일성, 재생성 일치, 판정 경계 테스트.
- [Excel 검증](artifacts/artifact-validation.json): 기존 시트의 값/수식/표/서식/고정창 보존, 새 사례/의무와 빈 관측 입력, 수식 오류와 전체비교 연결.
- [HTML 검증](artifacts/html-validation.json): 내장 JSON 일치, 기존144비교와 QA07의24사례 전환, 로컬 링크 확인.
- [렌더/재계산](artifacts/outputs/01a15dfe-v6/render-verification.json): 변경 영역 렌더와 판정/증거 누락/실패/완료/중복/공통 무효의 가역 입력 테스트. 임시 테스트 값은 모두 제거한다.

실제 Excel 앱과 제품 화면/음성 계측은 수행하지 않았다. HTML의 최소 DOM 검사는 실제 브라우저 배치 검증이 아니다. 관측이 없는 정확도와 점수를 성공률 또는 0점으로 만들지 않는다.

## 보존 검사 중 발견한 이전 재현 문제

직전 v5 commit 직전의 파일 끝 빈 줄 정리가 생성기 SHA256과 저장된 원장의 SHA256을 다르게 만들었다. v5 산출물의 숫자와 bytes는 수정하지 않고 생성기 끝의 원래 줄바꿈을 복원해 당시 해시와 재생성 검사를 회복했다. 이 한 파일의 EOF 빈 줄은 재현용 원본 bytes를 보존하기 위한 예외다. Git whitespace 검사는 이 EOF 예외를 구별한다.

v5 원장, Excel, HTML과 그림의 bytes는 [보존 해시](preserved-v5-sha256.json)로 검증한다. 이전 PPTX, 다른 DP 설계와 QA 정의 원전은 이번 평가 갱신에서 수정하지 않았다.
