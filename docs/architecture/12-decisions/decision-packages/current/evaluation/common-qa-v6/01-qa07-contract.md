# QA07 공통 적용 계약

[현재 정의](../../qa/qa07-request-meaning-accuracy.md)와 [평가 계획](../../qa/qa07-evaluation-plan.md)의 상세 검토안을 U01~U24에 연결한다. 정의 자체의 목표와 점수, 우선순위를 확정하지 않는다.

## 동일한 판정 단위

모든 DP2/DP3/DP5/DP44 방안은 같은 사례 명세와 의무를 사용한다. 모델 호출, 응답 chunk, Agent 사건과 내부 Request 개수를 분모로 세지 않는다. 네 A행은 하나의 BASE 재표시이며 독립 표본이 아니다. 정상/대기 분류도 QA07 사례를 제외하는 기준이 아니다.

입력에 여러 요청이 있으면 그 관계와 유지 지시까지 한 묶음으로 확인한다. 같은 요청의 정정/취소/재개는 원래 요청과 연결하고 최초 해석 checkpoint를 보존한다. 원래 요청을 찾을 수 없는 경우 새 입력의 해석만으로 전체 성공을 주장하지 않는다. 기존 24입력의 ID 순서가 하나의 대화 순서라는 가정도 하지 않는다.

## 세 단계와 하나의 결과

| 단계 | 필요한 증거 |
| --- | --- |
| REQUEST_INTERPRETATION | 원본 입력/문맥과 최초로 실제 사용한 의미. 조기 부분 확정과 정정 이력 포함 |
| RESPONSE_COMPOSITION | 실제 채택한 응답 내용, 연결 요청/판본, 당시 제공 가능했던 사실과 의무 |
| ACTUAL_DELIVERY | 실제 화면과 가청 출력 내용/구간, 수신자, 유효 판본, 재개 위치, 정상 폐기와 후속 금지 전달 관측 |

PASS는 모든 의무가 증명되고 계약과 유한한 관측 종료까지 확인됐을 때만 가능하다. 한 의무라도 증거가 있는 위반이면 FAIL이며 이후 복구와 미관측이 이를 지우지 않는다. 증거 없는 판정 문자열이나 정확한 oracle는 관측 증거가 아니다. 의무별 원인을 합산해 사례 실패 수를 늘리지 않는다. 공통 자료 무효는 양안에 같은 근거로 적용한다. 후보 실패를 INVALID로 제외하지 않는다.

등록한 유효 사례/반복의 수를 N, 성공/실패/미판정을 S/F/U로 두면 N=S+F+U다. U=0이고 N>0일 때 Q=100S/N이다. U가 있으면 Q는 미산출이며 [100S/N, 100(S+U)/N]만 진단으로 보고할 수 있다. 현재는 모집단 자체가 미동결이므로 N과 이 범위도 미산출이다. 작성 슬롯의 UNKNOWN 24개를 실제 24회 실행으로 바꾸지 않는다. 반복 ID와 source_execution_key가 없는 기록은 전체 성공이 될 수 없다.

## 남은 사전 조건

명세의 contract_ready=false는 미승인 계약 상태를 나타낸다. 관측을 입력했다는 이유로 바꾸지 않는다. 사례 묶음, 원래 요청, 정확한 응답 내용/허용 경로, 마지막 source 사건, 기능 기한, 후속 관측 길이, clock 오차와 취소 전파/중단 정책을 사전 검토한 새 manifest 판본에서 바꾼다. Excel의 준비 표시는 manifest를 읽어 표시하는 고정 값이며 사용자 관측 입력란이 아니다.

U18은 보고서 업무의 취소가 아니라 보고서 음성 안내의 철회다. U19/U20은 유효 내용 재개이며 이미 정당하게 재생한 내용은 소급 오답이 아니다. U23의 질문은 새 입력 전에 시작할 수 있으므로 새 요청의 최초 응답과 질문 전달을 같은 시각으로 복사하지 않는다. 구형 타이밍 원장의 계산 결과는 이 동작을 실제 관측했다는 증거가 아니다.

## 입력란과 증거 추적

`QA07의무`의 판정은 PASS/FAIL/UNKNOWN 중 하나로 입력하며 증거 참조와 평가자/조정 기록 참조가 있어야 PASS/FAIL로 집계한다. 자유문장 판단은 후보 이름을 가린 두 평가자의 조정 결과를 기록한다. 공통 무효 근거는 사례 단위에서 양안에 적용한다. 원인/QA02 공유 ID는 동일 지칭 오류의 전파를 추적한다. JSON judgments는 같은 의무의 여러 판정을 보존하며 한 번 입증된 FAIL은 이후 PASS로 지워지지 않는다. Excel은 이 원시 이력의 최종 조정 판정을 옮기는 표다.

## 보존과 범위

v5 통합 원장의 시간 DAG, 입력, 비용, 메모리와 변경 모듈 수는 바꾸지 않았다. QA02도 기존 지칭 정확도 그대로다. 새 manifest는 평가자 전용이며 모델 입력으로 전달하면 안 된다. 별도 응답 QA와 DP44의 새로운 설계 책임을 만들지 않았다. 새 모델 실행, 제품 관측과 PPTX 개정은 수행하지 않았다.
