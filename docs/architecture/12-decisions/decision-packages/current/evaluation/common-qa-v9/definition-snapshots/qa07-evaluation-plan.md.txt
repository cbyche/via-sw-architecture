# QA07 업무 순서 및 연결 정확도 평가 계획

2026-10-23 / `QA07-ORDER-LINK-POP-v4` / 작성자 제안 완료 / 미측정

[정의](qa07-request-meaning-accuracy.md) / [입력과 정답](qa07-evaluation-cases.md) / [기계 판독 원장](qa07-order-link-population.json) / [벤치마크 조사](research-notes/qa07-meaning-research.md)

## 1. 모집단과 다른 QA의 관계

원전은 기존 [COMMON-28 JSON](../scenarios/common-28-v1/common-scenarios.json)이다. 28개 에피소드에 있는 84개 사용자 입력 중 지속 업무의 생성 또는 기존 업무 후속 요청을 다루는 28개를 선정했다. 28개 에피소드와 28개 선정 입력은 다른 단위다. 포함 ID와 제외한 56개 입력의 이유를 원장에 전부 남겼다. 기존 QA07 전용 32사례는 사용하지 않는다.

**현재 시간/비용 분석의 U01~U24와 같은 평가 집합이라는 뜻은 아니다.** 이 계획은 기존 공통 원전에서 업무 관계를 추출한 QA07 평가 제안이다. 같은 사용자 원전을 사용한다는 사실과 실제 실행 조건/분모가 같다는 사실을 구분한다. 후속 DP 공통 평가에서는 이 입력과 문맥의 판본을 재사용하고 적용 가능한 다른 QA도 같은 실행에서 관측한다. 기존 U01~U24의 시간/비용 숫자를 28입력의 새 결과로 복사하지 않는다.

S17-U03은 원문의 “메일 검색 결과”가 이전 완료 검색인지 새 검색인지 모호할 수 있다. 이를 숨기지 않고 **해당 검색 TS17은 진행 중이고 결과가 아직 없다는 공통 문맥을 보완한 파생 fixture**로 지정했다. 보완 문맥과 `context_adapted=true`를 원장에 남겼다. 원전은 변경하지 않는다. 이 사례를 다른 QA에 적용할 때도 같은 보완 문맥을 사용하고 원전의 새 search ingress 일정은 가져오지 않는다.

순서 요구가 없는 입력도 신규/기존 연결은 판정한다. 선후 관계 공집합과 명시적 독립 요청의 정답을 구분해 태그로 남긴다. 복잡한 다단계 업무 전체를 대표하는 통계 표본이라고 주장하지 않는다. 선후 관계의 양성 사례가 적으므로 그 건수/원값도 부록에 반드시 표시하며 전체 정확도만으로 모든 순서 유형이 검증됐다고 설명하지 않는다. 평가 후 원하는 승패에 맞춰 표본을 늘리거나 줄이지 않는다.

## 2. 입력과 정답

평가 입력은 원문 Text, 이전 사용자/Agent/응답 이력, 기존 업무 ID와 상태다. 원전의 실제 전달 여부와 현재 판본을 유지한다. 정답에는 각 사용자 요청 절의 NEW/EXISTING 및 기존 업무 ID와 필요한 선후 관계만 둔다. 기간/금액/자료 내용/응답 문장을 QA07 정답 필드로 추가하지 않는다.

업무 이름은 입력의 어느 절을 비교하는지 정렬하는 표식이다. 동의 표현을 허용하며 내부 Task ID와 업무 alias를 연결하는 adapter를 사전에 확인한다. 하나의 Task 안에 복수 요청이 있는 설계와 복수 Task 설계가 같은 사용자 업무 관계를 표현하면 동등하게 본다. 사용자 지정 관계를 adapter가 추론하여 정답으로 보정하면 안 된다.

신규/기존 판정의 기준은 이 입력이 시작되기 전 업무 상태다. 같은 입력에서 새로 요청된 후속 단계도 NEW로 표시할 수 있으며 선후 관계로 연결한다. 이미 완료된 이전 결과를 새 산출물의 자료로 쓴다는 이유만으로 기존 업무 수정으로 표시하지 않는다. 기존 업무의 후속 조회/수정/취소/승인은 해당 업무 ID에 연결한다.

## 3. 실행과 관측

1. 동일 입력/이력/업무 상태 및 허용 원본을 모든 후보에 제공한다. 최초 판정에 필요한 자료가 원래 후보 입력 경로로 접근 가능해야 하며 평가자 정답 연결은 제공하지 않는다.
2. 각 입력을 독립 초기 상태에서 5회 실행한다. 모델/프롬프트/설정/기기와 자료 해시를 기록한다. 반복마다 대화와 캐시 상태를 공통 규칙으로 초기화하고, 과거 반복의 정답을 이어받지 않는다.
3. 최초 채택/실제 사용한 업무 연결과 순서 관계를 관측한다. 내부 후보 수정은 허용하며 실제 처리에 쓰인 최초 오류는 이후 복구해도 유지한다. 부분 채택은 최초 부분과 나머지를 연결한다.
4. 입력 제공부터 60초 안에 판정이 없고 관측이 완전하면 누락 실패다. 사용자 응답/음성 재생/Agent 작업 완료와 v3의 300초+10초 종료를 기다리지 않는다.
5. 구조 비교는 업무 ID 정렬과 선후 관계의 추이 폐쇄 후 수행한다. 필요한 업무 절/연결/관계의 누락, 추가, 반전 또는 순환은 실패다. 실제 실행 스케줄이 순차였다는 이유로 독립 관계 해석을 실패시키지 않는다.
6. 자유 표현의 정규화는 후보를 가린 두 평가자가 원문과 채택 증거로 검토한다. 허용 동등 표현을 사전에 등록하고 불일치 이유를 남긴다. 문장 유사도나 응답 자연스러움은 채점 기준이 아니다.

원음 기반 시험은 의미 정확도와 음성 인식의 영향을 함께 보여주는 별도 진단이다. 대표 140회에 정답 Text 실행과 원음 실행을 섞지 않는다. 모델 응답을 요청하는 PoC 실행은 이 정의 작업에 포함하지 않았다.

## 4. 원장과 집계

필수 필드는 contract_version, source_event_id, repeat_id, candidate_id, input/context hash, 최초 채택 시각/증거, 정규화된 업무 절/연결/선후 관계, PASS/FAIL/UNKNOWN, 실패 원인, 평가자 기록이다. 출력 문장이나 오디오 의무를 새 대표값의 분모로 추가하지 않는다.

- 28입력 × 5회 = 140회. 모든 기록이 판정되었을 때 전체 성공 수 / 140 × 100을 계산한다.
- 119회 이상 성공이면 85% 목표에 도달한다. 점수 구간은 정의 문서의 `QA07-ORDER-LINK-score-v4`다.
- 같은 입력의 순서와 연결이 둘 다 틀려도 실패 한 번이다. 순서 오류/신규 판정 오류/기존 업무 ID 오류는 원인 태그이며 세 비율의 평균을 대표값으로 쓰지 않는다.
- 판정에 필요한 기록이 없으면 UNKNOWN이다. 완전한 관측 중 무응답/구조 오류는 FAIL이다. 미판정이 남으면 전체 정확도와 별점은 확정하지 않는다.
- source_execution_key가 같은 실행을 다른 DP 비교에서 재사용해도 새 독립 표본으로 더하지 않는다. QA02와 같은 원인에 의한 업무 ID 오류는 공동 cause ID를 사용한다.

## 5. 공개 벤치마크와의 비교

TaskBench Table 10과 SMCalFlow 공식 리더보드의 숫자는 해당 논문/평가셋의 보고값이다. 현재 140회는 VIA 전용 투영이므로 단순히 두 숫자를 빼서 모델 개선량으로 표시하지 않는다. 정확한 우열을 주장하려면 같은 입력/정답/채점기로 기준 모델 또는 기준 harness와 VIA 후보를 비교해야 한다.

후속 실제 비교의 기준은 동일 모델을 동일 원문/대화/업무 상태로 호출하여 업무 연결과 순서만 예측하는 단일 호출 reference harness로 둔다. 두 예시를 동일하게 제공하되 평가 28입력과 겹치지 않게 하고 모델 판본과 예시/출력 schema 해시를 실행 전에 기록한다. 이것은 별도 제품 대안이나 측정된 기준값이 아니다. 아직 실행하지 않은 reference 결과를 84.53% 또는 73.751%로 채우지 않는다. 이 기준의 비교 증거는 기존 DP-QA 담당의 승인된 후속 측정 범위에서 만든다.

## 6. 이관과 보존

과거 32사례/160회와 응답 전체 충족률 90% 원장은 보존한다. 새 정의는 최초 업무 관계 판정에서 끝나므로 과거 응답 성공/실패를 새 QA07로 재채점하지 않는다. DP44의 음성 전달 개선이 새 범위의 관계 판단까지 영향을 주는지 별도로 확인한다. 이름이 같다는 이유로 QA coverage를 자동 승계하지 않는다.
