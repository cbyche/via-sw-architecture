기존 COMMON-28의 사용자 입력을 재사용한다. 아래 이름은 사용자 요청 절을 정렬하는 표식이며 모델이 같은 문구를 출력해야 한다는 뜻이 아니다. NEW는 이 입력에서 새로 요청한 업무, EXISTING은 기존 어느 업무에 대한 후속 요청인지 나타낸다. 선후 관계가 없으면 사용자 요구상 선행조건을 추가하지 않는 것이 정답이다. 실제 자원 스케줄의 순차 실행은 관계 오류가 아니다.

T08은 S08-U01의 수정 업무, T24는 S24-U01의 보고서 업무다. 다른 Task ID는 원전 상태를 따른다. S17-U03에만 진행 중 메일 검색 TS17의 문맥을 보완했다. 이 파생 조건은 아래 주석과 원장에 명시하고 원전 source 이벤트 일정을 그대로 적용하지 않는다.

## 판정 경계 주석

- **S08-U02**: T08은 S08-U01에서 시작한 문단 수정 업무다.
- **S15-U03**: 이전 문단 설명은 자료 참조다. 그 설명을 다시 이어가는 요청이 아니라 새로운 파일 생성 업무다.
- **S16-U01**: 조사와 비교의 내부 도구 순서는 채점하지 않는다.
- **S16-U03**: 사전 승인은 제공된 권한이다. 진행 중인 발송 Task가 없는 초기 상태다.
- **S17-U01**: 두 업무는 독립적이다. 원문에 별도로라고 명시됐다.
- **S17-U02**: 이름 변경을 이미 존재하는 무관한 파일 업무에 연결하지 않는다. 내부 Task 개수는 강제하지 않는다.
- **S17-U03**: QA07 문맥 보완: 이 입력이 참조하는 메일 검색 TS17은 진행 중이고 결과는 아직 없다. 이전 S17-G01의 검색 결과는 다른 대상이다. 원전의 새 search ingress 일정은 이 파생 fixture에 재사용하지 않는다.
- **S17-U05**: 문단 설명은 직접 응답으로 QA07 업무 연결 채점 밖이다. TR/TM에는 새 선후 관계가 없다.
- **S18-U03**: TA의 수정본을 자료로 재사용해도 별도 발표자료를 만드는 새 업무다. 완료된 TA를 다시 실행해야 한다는 선후 관계는 없다.
- **S20-U02**: 파일 형식 값이나 수신자 값 자체는 QA07 점수가 아니다. 각 절을 올바른 업무에 연결하는지만 확인한다.
- **S22-U04**: 실제 취소 가능 여부나 성공 안내는 별도 기능 평가다.
- **S22-U05**: 실제 취소 가능 여부나 성공 안내는 별도 기능 평가다.
- **S23-U01**: Agent 사건의 도착 순서를 사용자 지정 업무 순서로 만들지 않는다.
- **S24-U02**: T24는 S24-U01에서 시작한 보고서 업무다.
- **S24-U03**: 표를 먼저 보여달라는 말은 결과 표시 형식이다. 별도 업무의 실행 순서로 채점하지 않는다.
- **S26-U03**: 앞선 요약은 자료 참조다. 이번 파일 생성은 새 업무다.
- **S28-U03**: Agent 미접속 자체는 업무 연결 판단의 오류가 아니다.

## 포함과 제외

원전의 84개 사용자 입력 중 업무 생성/후속 요청의 연결을 비교하는 28개를 선정했다. 직접 질의, 자료/화면 지칭만의 요청, 음성 제어, 접근 동의와 선호 설정은 이 모집단에서 제외했다. 조건부 실행이 중심인 S17-U04와 업무 대상이 모호한 짧은 답변은 별도 기능 회귀로 남겼다. 제외 56건의 ID와 사유는 JSON에 모두 기록했다. 시험 뒤 모델 오답을 보고 제외한 것이 아니다.

선후 관계가 필요한 입력은 S17-U02와 보완한 S17-U03이다. 독립 업무 S17-U01 및 다중 기존 업무 연결은 불필요한 선행조건을 붙이는 오류도 확인한다. 전체 값과 함께 이 입력들의 건수/원값을 부록에 보존한다. 현재 구성은 긴 복합 업무의 정확도를 대표하지 않는다.

다섯 반복은 같은 입력의 출력 변동 확인을 위한 작성자 실행 규칙이다. 140개의 서로 다른 사용자 요청 또는 실제 사용 빈도의 통계 표본으로 설명하지 않는다. 현재 U01~U24 분석 숫자와 이 모집단은 다르다. 후속 공통 실행에서는 같은 입력 판본과 상태를 다른 적용 QA에도 제공한다.
