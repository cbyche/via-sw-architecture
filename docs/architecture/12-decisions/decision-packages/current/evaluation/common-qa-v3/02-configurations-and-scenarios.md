# 구성 축과 26개 사례군

**SYNTHETIC_AUTHORED_NOT_MEASURED** / 구성 registry `COMMON-QA-CONFIG-3.0`

## 1. 서로 다른 네 질문

| 축 | 사용자 문제 | 기본 구조와 차이가 생기는 경로 |
| --- | --- | --- |
| DP2 의미 판단 실행 | 진행 중 정정이나 독립 질문이 오면 어느 실행에서 의미를 판단하는가 | A는 기존 대화 실행의 다음 step, B는 별도 입력 해석 실행. 대기와 문맥 연결 비용이 바뀜 |
| DP3 화면과 발화 지칭 | 말한 시점의 지시가 어느 화면 대상인지 누가 해석하는가 | A는 당시 원본을 cloud 의미 모델이 직접 해석, B는 local 시각 생산자가 후보와 근거를 만들고 cloud 의미 모델이 요청에 결합 |
| DP5 과거 사건의 관계 | 과거 표시, 평가와 정정을 현재 목적에 어떻게 쓰게 하는가 | A는 요청 시 원본 관계를 판단, B는 사전 생산한 관계를 조회하고 최신 조건과 원본으로 보완 |
| DP44 여러 응답의 전달 | 어떤 응답의 음성을 언제 준비하고 중단 뒤 무엇을 재사용하는가 | A는 응답별 생성 실행과 오디오를 독립 유지, B는 현재 발화에 생성 실행을 연결. 선행 준비와 미사용 생성의 비용이 바뀜 |

화면 객체 후보, 과거 평가 관계와 준비된 오디오는 서로 다른 파생 상태다. 같은 원본이나 모델 자원을 공유할 수 있어도 하나의 상태로 취급하지 않는다. 어느 대안도 현재 권한, 요청 판본, 중복 실행 방지와 유효한 확정 상태의 재사용을 제거하지 않는다.

## 2. 이번에 수치가 있는 9개 구성

| 구성 | 층 | DP2 | DP3 | DP5 | DP44 | 비교 기준 |
| --- | --- | --- | --- | --- | --- | --- |
| T-BASE | TEXT | A | 이 경로에서 실행하지 않음 | A | `FIXED_UNMAPPED` | Text 기준 한 벌 |
| T-EXEC | TEXT | B | 이 경로에서 실행하지 않음 | A | `FIXED_UNMAPPED` | T-BASE에서 DP2만 변경 |
| T-REL | TEXT | A | 이 경로에서 실행하지 않음 | B | `FIXED_UNMAPPED` | T-BASE에서 DP5만 변경 |
| V-A | VOICE | `FIXED_UNMAPPED` | A | `FIXED_UNMAPPED` | `FIXED_UNMAPPED` | Voice/Screen 기준 |
| V-R1 | VOICE | `FIXED_UNMAPPED` | B-R1 | `FIXED_UNMAPPED` | `FIXED_UNMAPPED` | V-A에서 시각 생산과 필요 모델 적재 |
| V-R2 | VOICE | `FIXED_UNMAPPED` | B-R2 | `FIXED_UNMAPPED` | `FIXED_UNMAPPED` | V-A에서 시각 생산과 모델 상주 |
| V-R3 | VOICE | `FIXED_UNMAPPED` | B-R3 | `FIXED_UNMAPPED` | `FIXED_UNMAPPED` | V-A에서 시각 생산, 모델 상주와 worker 분리 |
| D-A | DELIVERY | `FIXED_UNMAPPED` | `FIXED_UNMAPPED` | `FIXED_UNMAPPED` | A | 독립 응답별 준비 |
| D-B | DELIVERY | `FIXED_UNMAPPED` | `FIXED_UNMAPPED` | `FIXED_UNMAPPED` | B | D-A에서 현재 발화별 준비로 변경 |

`FIXED_UNMAPPED`는 해당 비교에서 주변 처리를 동일하게 두었지만 기존 DP의 A/B 중 어느 구조인지는 확정하지 않았다는 뜻이다. 비적용, 0 또는 전체 제품의 구조적 동점이 아니다. T-BASE를 V-A 또는 D-A와 같은 기준 실행으로 참조하지 않는다. TEXT에서 화면 생산을 실행하지 않은 사실도 DP3의 제품 전체 동점을 뜻하지 않는다.

DP3의 B는 같은 전사와 word timestamp를 받는다. OmniParser detector와 EasyOCR의 후보/bbox, 필요한 경우 SAM2.1 Tiny의 mask와 시간간 대응을 원본 crop 및 불확실성과 함께 제공한다. Native 선택으로 충분하면 학습 모델을 건너뛰고 box로 충분하면 SAM을 건너뛴다. R1은 필요 모델을 적재 및 회수하고, R2는 한 번 필요한 모델을 유지하며, R3는 UI/SAM worker를 분리한다. 동일 CPU 총량에서 heavy 추론은 순차 admission이다. 상주와 process 분리를 정확도나 자동 병렬 이익으로 바꾸지 않는다.

DP44의 D-A는 Response Registry가 받은 유효 응답마다 Speech Preparation Coordinator가 S2S 출력을 준비하고 Prepared Audio Store에 보관한다. Speech Playback Coordinator는 실제 차례에 준비된 음성을 읽는다. D-B는 Speech Turn Controller가 선택한 발화에 생성 실행을 붙이고 대기 응답은 텍스트 상태로 보관한다. **D-B도 생성한 유효 잔여 음성을 보존한다.**

DP44의 실제 문안은 Downstream Agent가 만든다. 별도 문안 생성 LLM을 추가하지 않는다. 입력과 의미 채택, 판본과 권한 검사, 독립적인 UI 게시, 발화 감지와 로컬 80ms 재생 중단은 양안 공통이다. D-A의 선행 준비는 이미 유효한 응답을 대상으로 하며 새 사용자 요청의 의미를 미리 안다는 뜻이 아니다.

## 3. 시나리오 은행과 분모

시나리오 은행 `COMMON-QA-CORPUS-3.0-STRATIFIED`는 T, V, D 사례군을 분리한다. 입력, 목표와 지칭 표현은 각각 TEXT, VOICE, DELIVERY namespace로 연결하고 부모 ID를 따로 보존한다. 표시 이름만으로 서로 다른 부모 행을 동일 사례로 합치지 않는다.

| D-S07 | 일정, 메일, 보고서 순서로 읽기 | 여러 Agent 결과의 순서 지정 |
| D-S08 | 도착하는 메일 질문을 바로 읽기 | 선행 준비 여유 50ms |

TEXT 각 군은 10에피소드와 20입력이다. VOICE 각 군은 20개의 신규 입력, 표현과 목표다. DELIVERY 각 군은 10평가 입력으로 총 80입력, 120표현, 90목표다. D-S03에는 원래 보고서 목표 10개와 새 전달 목표 10개가 있으므로 다른 군과 목표 분모가 다르다.

VOICE 준비 60개와 DELIVERY 준비 80개의 비용과 메모리는 포함하지만 준비의 정확도를 평가 분모에 더하지 않는다. VOICE 현재 평가에는 후속 정정이나 동시 사용자 목표 행이 없다. DELIVERY의 정정 장면은 같은 올바른 의미 결과를 고정하므로 DP2 해석 정확도나 겹침 효과의 새 평가가 아니다.

## 4. 같은 입력에서 원인과 결과를 따라가기

### T-F06과 V-S3의 이전 한계를 보존한다

T-F06의 `SYN-F06-01-U02`는 같은 자료를 유지하면서 상담팀 실무회의용으로 목적과 강조점을 바꾸는 입력이다. T-BASE는 새 목적을 반영하고 T-EXEC와 T-REL은 과거 목적을 잘못 유지하도록 작성됐다. QA02가 같아도 QA07은 달라질 수 있다는 사례이며 DP3 시각 후보나 DP44 음성 준비로 이 오류가 자동 해결되지 않는다.

V-S3의 원본은 실제 픽셀이나 WAV가 아닌 작성 명세다. Action 설명에 동일 객체라는 정답 관계가 있고 현재 실패 행은 L을 Z로 바꾼 것이다. 이 자료로 모델이 원본에서 동일성을 식별했거나 중복 출력 오류를 실증했다고 주장하지 않는다. v3 추가가 이 한계를 해소하지 않는다.

### D-S03: 원래 보고서와 새 질문 읽기의 목표를 나눈다

원본 `S03-05`에서 보고서 요청은 -6초에 시작했고 현재 발화는 -4.4~0초다. 메일 질문은 -1.4초, 5월 보고서는 -1초에 도착한다. 양안은 UI에 독립 표시하고 사용자의 발화와 정정 판단 중 음성은 보류한다.

| 사건, 평가 입력 종료 기준 초 | D-A | D-B |
| --- | ---: | ---: |
| 정정 의미 채택 | 0.867 | 0.867 |
| 판본과 순서 반영 | 0.907 | 0.907 |
| 새 입력의 수행 의도 화면 표시 | 0.947 | 0.947 |
| 메일 질문 첫 음성 준비 | -0.999 | 1.308 |
| 메일 질문 첫 음성 출력에 대응하는 사건 | 0.947 | 1.348 |
| 6월 보고서 도착 | 3.427 | 3.427 |
| 6월 보고서 화면 표시 | 3.467 | 3.467 |
| 6월 보고서 전체 음성 준비 | 5.784 | 6.499 |

첫 화면은 보고서를 6월 기준으로 다시 요청하고 메일 질문부터 읽겠다는 구체적 수행 의도다. 첫 음성은 실제 요청한 메일 질문이다. 질문을 읽었다고 메일 업무 완료나 보고서 수정 완료를 주장하지 않는다. 표의 모든 시각은 부모가 작성한 값이며 실제 출력 로그가 아니다.

D-A는 메일 질문을 미리 준비한 이익과 5월 보고서의 무효 음성 생성 비용을 함께 갖는다. 새 보고서 생성과 UI 게시를 음성 준비가 막지는 않는다. 원래 보고서 목표 시작을 현재 정정 입력 시각으로 옮기면 그동안의 VIA 처리가 사라지므로 -6초를 유지한다.

### D-S05와 D-S06: B의 재사용을 빼지 않는다

D-S05는 생성과 재생 중인 긴 설명을 중단하고 메일 질문을 읽은 뒤 돌아오는 사례다. 양안은 사용자 발화 시작 후 80ms까지 재생을 멈춘다. 의미 채택 후 실제로 질문으로 전환할 때 D-A는 이전 생성 실행을 유지하고 D-B는 종료한다. 복귀 시 D-B도 기존 buffer를 먼저 재생하며 미생성 후반만 요청한다. 추가 재개 문맥 비용은 남기되 전체 설명을 처음부터 생성하는 불리한 B를 만들지 않는다.

D-S06은 이미 생성이 끝난 유효 오디오를 다시 사용하는 사례다. 양안 모두 새 생성 호출을 하지 않는다. 실제로 출력한 구간과 아직 준비만 한 구간은 전달 이력에서 분리한다.

### D-S08: 물리 시간과 투영 QA03을 구별한다

D-S08은 새 질문 도착과 발화 차례 사이에 50ms만 선행 여유가 있다. 첫 음성의 작성된 실제 경과시간 이익은 50ms다. 외부 도착 대기를 0으로 투영한 QA03에서는 A의 병행과 B의 직렬 의존 차이가 더 크게 남는다. 두 값은 서로 다른 관측 의미이므로 QA03 차이를 사용자가 실제로 덜 기다리는 시간이라고 바꿔 말하지 않는다.

## 5. 기본안, 민감도와 tactic

DP44 기본 표에는 다음 응답 한 개만 준비하는 A1을 적용하지 않는다. A1은 폐기될 생성 비용을 줄일 수 있지만 다른 응답이 선택되면 선행 이익을 잃는 보완 설계다. B의 동일 생성 상태 pause/resume도 미구현 capability와 유지 상태 비용을 별도로 확인해야 하며 현재 B에 무상으로 부여하지 않는다.

QA04에서 A의 C04와 C06 추가 변경이 공통 section/extent 인터페이스로 흡수되면 A도 B와 같은 2.000이 될 수 있다. 이 조건은 예상 모듈 경계의 민감도로 남기며 실제 변경 실험이나 tactic 성과로 표시하지 않는다. 기본 표의 다른 QA값을 이 민감도에 맞춰 임의 조정하지 않는다.

## 6. 아직 없는 교차 조합

현재 비교쌍은 `T-EXEC−T-BASE`, `T-REL−T-BASE`, `V-R1/R2/R3−V-A`, `D-B−D-A`다. 각 차이는 해당 층과 고정 주변 처리 안에서만 해석한다. 같은 workload와 profile에서 두 축의 네 교차 구성을 작성했을 때만 `interaction = Q(B,B)−Q(B,A)−Q(A,B)+Q(A,A)`를 계산한다. 현재 그 값은 미작성이며 0이 아니다.
