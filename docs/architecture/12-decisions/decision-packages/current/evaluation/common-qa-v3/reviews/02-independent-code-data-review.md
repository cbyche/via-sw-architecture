# v3 통합 생성기와 원장의 독립 검토

2026-10-22 / **SYNTHETIC_AUTHORED_NOT_MEASURED**

## 검토 범위와 방법

통합 생성기를 작성하지 않은 별도 에이전트가 [원장 생성기](../../../../../../../../scripts/presentations/build_common_qa_delivery_v3.py), [정규화 원장](../artifacts/normalized-data.json), [집계](../artifacts/summary.json), 고정한 v2와 DP44 부모 사본을 읽었다. 생성기를 import하거나 재실행하지 않고 별도 Python 표준 라이브러리 계산으로 저장된 행을 대조했다. 같은 에이전트가 v3 공통 문서 초안을 작성했으므로 이 기록을 그 문서의 독립 검토로 세지 않는다.

주요 확인 대상은 화면과 음성 QA01의 분리, DP44 정확도의 고정 제어 조건, 미모델링 수신 비용, 준비와 평가의 분모, 원래 목표 시작점, QA03의 인과 경로, 전체 사용량, 동시 메모리와 부모 값 보존이다. Renderer의 Excel 및 HTML 검사는 다른 검토 기록의 범위다.

## 발견과 수정 후 확인

| ID | 심각도 | 발견 | 수정과 재검토 |
| --- | --- | --- | --- |
| DATA-01 | P2 | DELIVERY 시나리오의 `source_ids`는 원본 `S01-01:status` 형식인데, 정규화된 source 원장의 `source_id`는 `DELIVERY:S01-01:status`였다. 80시나리오의 140개 참조가 source 원장에 직접 연결되지 않았다. 화면이 case/config 필터로 자료를 찾더라도 정규화 원장의 명시적 참조는 불완전했다. | 데이터 작성자가 `source_ids`에 namespace를 적용하고 원본은 `parent_source_ids`로 보존했다. 생성기에 scenario에서 각 구성의 source 및 source/display stage까지 연결하는 검사를 추가했다. 별도 재검토에서 140참조 × D-A/D-B의 280연결이 같은 case, config와 profile로 이어짐을 확인했다. 대표값은 바뀌지 않았다. **해결 확인.** |

Renderer의 QA07 순서 비교, 단계 선행 참조와 source의 구성 필터 관련 발견은 통합 담당 및 표시 검토 담당의 기록에서 관리한다. DATA-01은 시나리오 원본 참조의 정규화 문제이며 그 표시 문제와 별개다.

| DP44 의미 제어 | 양안의 최초 expected와 adopted가 입력별로 같고 `FIXED_CORRECT_SEMANTIC_FIXTURE` 표시 유지. QA02와 QA07 100%를 새 모델 정확도로 해석할 근거 없음 |
| 비용 누락 | 부모 usage 910행의 양수 사용량을 정규화한 1,500 bucket 모두 대응하며 사용량과 비용 합 일치. 준비, 폐기와 재개 행도 보존 |
| 수신 비용 | D-A와 D-B의 receiver 및 total은 `null`, 상태는 `NOT_MODELED`. 0이나 VIA 비용으로 대체하지 않음 |
| Source 전달 진단 | 부모 280행의 source 시각, 표시, 첫 음성, 지연 및 상태 보존. 사용자 입력 QA01과 분리 |
| 메모리 snapshot | DP44의 5,340개 상태를 job 생성량, 실제 작성 재생 구간의 소비량 및 metadata에서 별도 재구성해 일치 |
| 메모리 최고값 | 160개 case/option 조합에서 생성 시작, 첫 chunk, 생성 종료, 오디오 포화, 재생 시작/종료와 release 경계 및 양옆 시각의 상태를 확인. D-A 561.659272 MB, D-B 561.506936 MB로 일치 |
| QA04 민감도 | 구성당 C01~C06의 고유 concept 모듈 수를 평균. 공통 인터페이스 가정에서 A와 B 모두 2.000이라는 민감도 필드 유지 |
| S08 시간 해석 | 첫 음성 B−A는 0.050000초, 투영 QA03 B−A는 0.883333초. 같은 wall-clock 이익으로 치환할 수 없는 별도 값임을 확인 |

별도 DAG 계산은 원장에 있는 목표별 terminal 목록 전체를 사용했다. 목표마다 선행 node의 투영 완료값 중 최대값에, 목표 시작 이후의 포함 duration만 더했다. 원래 보고서 목표를 현재 입력 0초로 잘라내거나 사례군 평균을 다시 평균하지 않았다.

## 판정과 한계

**검토한 통합 생성기와 JSON 원장 범위에서 미해결 P1/P2는 없다.** 이는 가상 자료의 계산, 연결과 의미 경계를 확인한 결과다. 실제 모델, 대상 장치, 마이크와 스피커, 제품 경로를 실행하지 않았다. 예상 시간, 정확도 빈도, 모델 capability 및 실제 메모리 사용의 현실성을 검증한 것이 아니다.

이 검토는 native Windows Excel이나 HTML 브라우저 시각 확인을 수행하지 않았고, 전체 저장소 링크 또는 원격 CI 상태도 판정하지 않았다. 그런 상태는 [통합 검토 기록](../04-migration-and-review.md)과 산출물의 발행 검증에서 별도로 관리한다. 이전 DP44 전체 링크 PASS에 포함된 다른 세션의 검사기 변경을 이 검토의 성과로 계승하지 않는다.
