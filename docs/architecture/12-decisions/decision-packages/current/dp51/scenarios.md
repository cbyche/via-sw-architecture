# DP51 상황과 같은 사건 추적

[진입점](README.md) / [구현 설계](design.md) / [검토 결과](review.md)

## 1. 사용자 목표와 관측 범위

사용자가 PDF의 표 일부를 선택하고 “이 수치하고…”라고 말하며 스크롤한다. 다른 창의 그래프를 클릭 없이 가리키고 “이걸 비교해줘”라고 말한다. 발화 후 포인터는 다른 곳으로 이동한다. ASR 부분 결과와 최종 결과는 늦게 도착하고 앞 단어의 내용과 구간을 수정할 수 있다.

성공은 뒤늦은 해석이 당시의 두 근거를 실제로 읽고 다른 시점의 화면과 섞지 않는 것이다. 마지막 화면만 읽거나 현재 포인터를 과거 발화에 붙이는 것은 성공이 아니다. 수집 실패를 정직하게 알리는 것은 올바른 실패 처리지만 원래 비교 요청의 정상 성공으로 세지 않는다.

수집 계층은 의미상 비교 대상을 확정하지 않는다. 어느 시점에 어떤 픽셀, 선택 값과 경로가 관측되었는지 제공한다. 의미 모델의 판단 능력과 Agent의 비교 업무 능력은 이 계층의 구조적 우열 근거가 아니다.

## 2. 대표 사건의 순서

아래 E 번호는 설명용 사건 식별자다. 시간 간격과 프레임 수를 측정 조건으로 지정한 것이 아니다.

| 사건 | 시간순 입력 또는 외부 사건 | 내부 처리와 남는 상태 | 사용자에게 보이는 결과 |
| --- | --- | --- | --- |
| E01 | 화면 interaction 수집 활성화 | 허용된 display 집합, geometry, capture epoch 및 시계 매핑 생성. 초기 선택 읽기는 현재 관측으로 기록 | 수집 범위는 기존 제품 설정을 따름 |
| E02 | 발화 전 PDF 표 일부 선택 | 선택 변경 사건 저장. 별도 worker가 선택 값을 읽고 당시 화면 후보를 보존 | 아직 업무 실행이나 의미 확정 없음 |
| E03 | “이 수치하고…” 발화 | 원음 block 저장. 발화 시작이 감지되면 원음 시각으로 직전 이력과 기존 선택 hold 생성 | 자연스러운 음성 입력 지속 |
| E04 | 빠른 스크롤 | wheel/drag 사건과 실제 도착한 화면을 별도로 저장. 누락 중간 구간 표시 | 입력을 받는 동안 분석 때문에 화면 수집이 멈추지 않음 |
| E05 | 다른 창의 그래프를 클릭 없이 지시 | 포인터 경로, display 및 창 관측, 당시 픽셀 저장 | 클릭을 필수로 요구하지 않음 |
| E06 | “이걸 비교해줘” 후 발화 종료 | 종료 샘플 위치 기록. 이후 포인터 이동도 새 사건으로 기록 | 종료 후 포인터 이동이 앞 지칭을 덮어쓰지 않음 |
| E07 | 늦은 ASR 부분 결과 r1 | 원음 sample 범위로 evidence view 발급. r1 해석 작업 생성 가능 | 임시 자료와 확정 결과는 상위 계약에서 구별 |
| E08 | 최종 전사 r2가 단어와 시각 수정 | 최신 판본 교체. r1 게시 무효화 및 취소 요청. r2 범위로 이력 재조회 | 오래된 결과를 최신 요청 결과로 게시하지 않음 |
| E09 | 이미 시작한 화면 복사 완료 또는 선택 조회 늦게 도착 | 실제 source 시각/조회 구간으로 추가. 관련 evidence view 판본 변경 통지 | 중요한 근거 변화가 있으면 상위가 재검토 |
| E10 | r2 해석 완료 | 입력 및 evidence 판본 확인 후 근거 포함 결과 전달. 작업 사용권 해제 | 당시 두 자료에 근거한 처리 의도를 확인 가능 |
| E11 | 요청에서 raw 이력 사용 종료 | 필요한 대상 참조와 최소 근거를 별도 기억 계약으로 인계한 뒤 hold 해제 | 대화가 길어져도 raw 이력이 무제한 누적되지 않음 |

E07~E09의 수신 순서는 바뀔 수 있다. 처리 task의 수신 순서와 실제 source 사건의 시간순은 같다고 가정하지 않는다.

## 3. 가정과 확인 필요 조건

| 항목 | 이번 설계의 가정 | 확인 필요 또는 지원 한계 |
| --- | --- | --- |
| 제품 OS | Windows 데스크톱의 구체 API를 사용해 설계 | 최소 Windows 빌드, driver, HDR와 다중 GPU는 미확인 |
| 수집 시작 | E02 전부터 허용된 화면 수집이 활성 | 수집 전 사라진 화면은 복구 보장 불가 |
| 수집 대상 | 허용된 display를 미리 구독하는 경로를 기준으로 설명 | 전경 창만 구독하면 창 전환 직후의 첫 화면을 놓칠 수 있음. 이 기능 차이를 비용 절감으로 숨기지 않음 |
| 다중 display | 허용 및 자원 admission된 display만 수집 | 구독하지 않은 display로 포인터가 이동하면 CoverageUnknown/NotCaptured |
| PDF 선택 | 실제 제공되는 text/range/rect만 사용 | 앱별 UI Automation 제공 여부 및 snapshot 일관성 미확인 |
| 객체 없는 이미지 | 픽셀과 좌표만으로도 근거를 표현 | 객체 ID, 문서 좌표, 과거 selector를 만들어 내지 않음 |
| ASR | 입력 sample 범위에 대응하는 출력 계약 요구 | 단어 시각 미지원이면 발화 구간 및 불확실성 유지 |
| 전사 지연 | 유한한 보관 및 작업 예산 안에서 처리 | 무제한 지연이나 무제한 발화에 대한 완전 보존 약속 없음 |
| 지칭 판정 | 같은 의미 해석 의존성을 사용 | 저장 형식만으로 의미 판단 정확도가 상승한다고 가정하지 않음 |

## 4. 두 보관 구조에 같은 사건 적용

독립 이미지와 기준/변경분의 세부 코드는 [설계](design.md)에 있다. 여기서는 같은 사건에서 동작이 달라지는 부분을 추적한다.

| 사건 유형 | 공통 정확성 조건 | 독립 이미지 보관 | 기준 이미지와 변경분 보관 |
| --- | --- | --- | --- |
| 발화 전 선택 후 오래 대기 | 선택 anchor의 내용, 시각 및 만료를 보존. 현재 선택으로 갱신한 척하지 않음 | 해당 이미지 또는 독립 crop 보존 | 의존 묶음 보존 또는 당시 픽셀을 독립 이미지로 추출. 추출 비용 포함 |
| 정적 화면에서 두 지시 | 포인터와 화면 시각을 분리 | 같은 이미지 ID를 여러 사건에서 참조 가능 | 화면 갱신 없는 경우 변경분 생성 불필요 |
| 빠른 스크롤 | wheel 입력 시각을 화면 변경 시각으로 대체하지 않음 | 확보한 프레임마다 전체 복사 비용 | move/dirty metadata가 유효하면 활용. 큰 dirty 영역이면 절감 감소 |
| 창 전환과 동일 좌표 | 당시 display와 geometry, 창 관측의 시각 확인 | 독립 frame마다 확인 | 동일 display의 화면 변화는 delta 가능. capture/geometry 변경은 새 기준 필요 |
| 원형 포인터 경로 | 여러 sample과 손실 여부를 유지 | frame의 표현과 무관하게 경로 저장 | 동일 |
| ASR 내용 및 단어 경계 정정 | 원음 sample 매핑을 통해 과거 view 재조회 | 대상 frame 직접 읽기 | 목표마다 복원 의존성과 scratch 필요 |
| 캡처 완료가 늦음 | source 시각과 완료 시각을 따로 기록 | 완료된 이미지 공개 | 선행 기준/변경분 commit 확인 후 공개 |
| 화면 보관 실패 | 손실 구간 공개, 현재 화면으로 보완한 척하지 않음 | 다른 이미지 읽기는 독립 | 기준 불일치면 이후 delta 금지, 새 full로 재개 |
| 오래 실행 중인 분석 | 작업이 실제 사용 종료하기 전 메모리를 재사용하지 않음 | 읽는 이미지가 pin됨 | 기준과 변경분 또는 복원 이미지가 pin됨 |
| 장치 재시작/크기 변경 | 새 epoch와 geometry 생성. 옛 자료는 옛 변환 유지 | 옛 frame을 독립적으로 읽을 수 있음 | 옛 묶음은 유지, 새 묶음부터 full |
| 권한 철회 | 신규 use 차단 후 실행 중 사용 취소 및 정리 | 동일한 fence 적용 | dependency와 복원 cache에도 fence 적용 |

## 5. 반드시 구분할 실패

1. **E02 선택 사건의 수신이 늦고 조회 전에 선택이 바뀜:** 조회 결과는 조회 구간의 관측이다. E02 당시의 선택이라고 표시하지 않는다. 별도 화면 이력에 선택 표시가 남아 있는지 확인할 수 있지만 의미 복구를 보장하지 않는다.
2. **E04 중 여러 화면 갱신이 하나로 누적됨:** 최종 화면을 정확히 보관한 것과 중간 화면을 보관한 것은 다르다. 중간 지칭은 근거 부족일 수 있다.
3. **E05 포인터 이동만 있고 클릭/선택 이벤트 없음:** 선택 이벤트 기반 캡처만으로는 충족되지 않는다. 경로 수집과 시각 근거가 필요하다.
4. **같은 native window handle이 재사용됨:** process instance 및 incarnation과 함께 식별한다. 핸들 숫자만으로 역사 창을 연결하지 않는다.
5. **좌표 변환 조회가 화면 갱신과 경쟁함:** 동일 시점 보장이 없으면 변환 오차 및 unknown을 남긴다. 현재 DPI나 창 위치로 옛 좌표를 변환하지 않는다.
6. **r1 취소 후에도 모델이 결과를 반환함:** r1 게시를 거절한다. 취소 신호만으로 source 사용권을 강제로 해제하지 않는다.
7. **ASR r2가 이미 만료된 구간을 요구함:** Expired/Gap 반환. 현재 화면을 대신 주지 않으며 상위가 재지칭 또는 한계 안내를 결정한다.
8. **UI Automation native 호출이 멈춤:** 화면 및 음성 수집을 유지한다. in-process timeout이 native 실행 종료를 보장하지 않음을 기록한다.
9. **GPU 복사 중 timeout/취소:** source와 destination을 읽는 GPU 작업 종료 또는 device teardown 확인 전에는 해당 자원을 재사용하지 않는다.
10. **발화가 계속되고 모든 예산이 pin됨:** 기존 자료를 몰래 덮어쓰지 않고 신규 보관 실패와 coverage 악화를 알린다. 무제한 hold 확대를 허용하지 않는다.

## 6. 후속 검증용 관찰표

아래는 실제 실행이나 measurement freeze가 아닌 검토 항목이다. 양 구조에는 같은 source 입력, 픽셀 형식, 해상도, 채택 프레임과 완료 조건을 적용한다.

| 확인할 성질 | 필요한 관찰 | 실패로 남길 조건 |
| --- | --- | --- |
| 시각 정합 | audio sample 위치, OS source timestamp, 수신/복사 완료 시각, clock epoch | 수신 시각이나 현재 화면을 과거 source 시각으로 사용 |
| 픽셀 재현 | 같은 보관 frame을 독립 이미지와 delta 복원으로 읽어 픽셀 비교 | move 겹침, 기준 누락, geometry 변경 후 오복원 |
| 수명 | 할당, pin, 작업 종료, 실제 해제와 GPU 완료 기록 | 사용 중 buffer 재사용, 해제 전 quota 반환 |
| bounded 자원 | bytes 및 항목 상한, in-flight, scratch, lease, queue occupancy | timeout 작업이 쌓이면서 상한 우회 |
| 누락 공개 | queue overflow, source 누적 갱신, permission/device 오류 | 빈 근거를 정상 COMPLETE로 반환 |
| 정정 | r1/r2와 evidence view 판본, 늦은 결과 게시 시도 | 무효화된 판본의 결과 채택 |
| 비용 | 캡처, 복사, metadata, 복원, readback 및 폐기 비용 | 모델 시간만 측정하거나 발화 중 비용을 전체 비용에서 삭제 |

포인터 손실, UIA 지연 및 실제 display 출력은 현재 fixture가 대신 보장하지 않는다. 실제 앱과 장치에서 관측하기 전에는 성공률과 처리시간을 산출하지 않는다.
