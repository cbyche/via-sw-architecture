# DP-47 대표 장면 — 선택, 지칭과 페이지 이동이 이어지는 비교 요청

## 1. 사용자의 목적과 시작 화면

사용자는 올해 매출 자료와 작년 보고서의 실적 및 관련 그래프를 비교하려고 한다. 스프레드시트 창과 PDF viewer가 나란히 보이며 메일 앱도 열려 있다. 앱이 열려 있다는 사실, foreground와 focus, pointer 위치와 문서 대상은 서로 구별한다.

사용자는 앞서 스프레드시트의 매출 cell 범위를 선택해 둔 다음 PDF viewer를 활성화했다. 처음 지정한 범위를 다시 가리키는 순간에도 PDF viewer가 foreground다. 현재 선택이 남아 있는지와 그 정보를 VIA가 읽을 수 있는지는 실제 관측으로 확인한다. 사전 동작의 전체 경로를 기록했다고 가정하지 않는다.

PDF의 8페이지에는 작년 실적 표가 있고 9페이지에는 위아래 두 그래프가 있다. 9페이지는 scanned appendix라 화면에서 그래프를 볼 수 있어도 개별 graph와 수치가 UIA 요소로 노출되지 않는 조건을 검토한다. 특정 Acrobat Reader 버전의 실제 노출 범위를 확인한 결과가 아니다. 페이지와 app 표시는 사람이 상황을 이해하기 위한 설명이며 후보의 입력 정답으로 주지 않는다.

## 2. 말과 행동의 연속

| 순서 | 사용자의 말과 행동 | 확보할 수 있는 관측 자료 | 해석에서 보존해야 할 관계 |
| --- | --- | --- | --- |
| 1 | PDF viewer가 foreground인 채 옆 spreadsheet의 선택 범위 위로 pointer를 옮겨 “이 매출 범위를…”라고 말한다. 클릭하지 않는다 | 원음, 당시 frame, pointer 관측, foreground/focus와 지원될 경우 선택 상태 | 첫 대상은 실제로 지정한 매출 범위다. foreground PDF로 자동 대체하지 않는다 |
| 2 | PDF 8페이지의 표에 pointer를 올리고 “여기 작년 실적하고 비교해줘. 그리고…”라고 이어간다 | 후속 원음, PDF frame과 pointer, 이용 가능한 UIA 자료 | 새 지칭은 PDF의 작년 실적 표다. spreadsheet 대상은 유지한다 |
| 3 | PDF의 scrollbar thumb을 드래그해 9페이지로 이동한다. 드래그 도중 pointer는 여러 객체 위치를 지난다 | button down/move/up, scrollbar 또는 앱 상태가 제공된다면 그 변화, 이동 전/중/후 frame | 이 조작은 탐색 동작이다. 경로에서 지나간 객체를 모두 비교 대상으로 추가하지 않는다 |
| 4 | 버튼을 놓은 뒤에도 잠깐 page rendering이 이어지고 두 그래프가 나타난다 | up 이후 frame과 이용 가능한 앱 변화 통지 | button up과 유효한 후속 화면을 구별한다. 화면이 아직 불명확하면 대상 해석의 불확실성을 남긴다 |
| 5 | 버튼을 누르지 않고 두 그래프 주위로 원형 pointer 경로를 만들며 “이 두 그래프도 같이 비교해줘”라고 한다 | 원음, 포인터 경로와 당시 frame. 앱의 실제 selection은 생기지 않을 수 있음 | 두 그래프의 집합 지정이다. 원의 가운데 좌표 한 점이나 앱 selection 유무만으로 대상 집합을 확정하지 않는다 |
| 6 | 아래 그래프에 pointer를 두며 “아니, 그래프는 아래 것만. 처음 매출 범위와 작년 실적 표는 그대로”라고 정정한다 | 추가 원음과 전사 revision, 아래 graph의 당시 frame/pointer | graph 집합만 아래 graph로 교체한다. 첫 매출 범위와 8페이지 표의 관계는 유지한다 |
| 7 | 발화를 끝내고 메일 앱을 활성화해 다른 내용을 확인한다. 전체 전사의 마지막 부분 또는 완료 이벤트는 그 뒤 도착한다 | foreground/focus 전환, 마지막 전사와 로컬 원음 구간 대응 | 요청의 지칭 대상은 유지한다. 결과 수신 시점의 메일 화면을 과거 지칭 근거로 사용하지 않는다 |

이 순서는 가능한 정상 사용 장면을 구체화한 것이다. 특정 지연 ms, sampling rate나 provider 반환 순서를 고정하거나 실제 발생을 측정한 것이 아니다. 스크롤, render와 전사 시간이 다른 변형도 동일 목적 아래 검토할 수 있다.

## 3. 올바른 결과와 VIA의 책임

사람이 설명하기 위해 첫 매출 범위를 A, PDF 8페이지 표를 B, 9페이지 위 graph를 C, 아래 graph를 D라고 부르면 최종 대상은 **A, B, D**다. C는 정정으로 제외된다. 이 기호는 검토용 정답 설명이며 후보에게 미리 주는 binding이 아니다.

VIA는 실제 확보한 근거에서 대상과 필요한 범위를 연결하고 graph 집합의 교체만 반영해야 한다. 위임한다면 이 대상과 정정 결과를 필요한 근거와 함께 Downstream Agent에 전달한다. 실제 비교 내용의 domain reasoning이나 작업 계획은 외부 Agent 책임이라는 기존 경계를 유지한다. 허용된 bounded direct response 여부도 기존 범위를 따른다.

자료가 명확할 때 자연스러운 짧은 확인은 “선택한 매출 범위와 작년 실적 표, 마지막 페이지의 아래 그래프를 비교할게요”와 같은 형태다. 모든 요청에 필수 확인을 추가하는 정책을 선정한 것은 아니다.

특정 대상이 관측되지 않았거나 본질적으로 모호하면 부족한 지칭에 맞게 확인해야 한다. 존재하지 않는 UIA 항목을 만들어내거나 전체 요청을 근거 없이 성공 처리하지 않는다. 확인 질문 수가 많은 것으로 품질 문제를 모두 회피하는 구조도 자동 우세로 보지 않는다.

## 4. 한 장면에서 드러나는 SW 설계의 어려움

| 어려움 | VIA가 다뤄야 하는 실제 구별 |
| --- | --- |
| 서로 다른 정보원 | native selection이 있을 수 있는 범위, click 없는 pointing, 실제 selection이 없는 원형 지정 |
| 지칭과 앱의 관계 | 실행 중인 앱, foreground/focus, pointer 아래 window와 사용자가 말한 대상 |
| 시간 대응 | 원음 시점, 단어 span의 제공 또는 추정, frame 시점, input event와 전사 도착 시점 |
| 화면 이동 | 동일 좌표의 의미 변화, 과거 frame의 필요성, navigation path와 대상 지정 path |
| 완료 판단 | button up, app의 상태 변화와 화면 rendering을 별도 관측으로 이해 |
| 불완전한 구조 자료 | PDF를 볼 수 있다는 사실과 각 표/graph/selection을 UIA로 읽을 수 있다는 사실 |
| 일부 정정 | graph 집합만 교체하며 먼저 지정한 비교 자료 유지 |
| 자원과 비용 | 확보할 frame과 pointer 자료의 범위, 모델에 제공할 원음/이미지 양과 재판단 비용 |

이 장면은 모든 정보를 얻는 하나의 API나 최종 화면 한 장을 전제할 수 없다는 문제를 보여준다. 무엇을 기록하고 어떤 자료를 어떤 단위로 해석하며 어느 관계를 정정할지에 따라 정확성, 기다림, 모델 비용과 메모리가 달라진다. 현재는 이 차이를 만들 실제 구조를 탐색하기 위한 입력 현실과 성공 조건을 정리한 상태다.

## 5. 발표에서 사용할 짧은 배경 문장

사용자는 선택해 둔 매출 범위를 가리키며 말하다가 PDF의 표를 지정하고, 페이지를 넘겨 여러 그래프를 가리킨 뒤 일부만 남기도록 고친다. 그 사이 화면과 앱이 바뀌고 전사는 늦게 도착할 수 있다. **VIA는 말과 화면 조작이 함께 만든 대상을 당시 근거에 연결하고, 바뀐 지정만 고쳐 같은 요청을 이어가야 한다.**

짧은 발표에서는 선택한 대상에서 시작해 page drag와 후속 pointing/정정을 핵심 흐름으로 사용한다. UIA 지원 차이, 원형 집합 지정과 foreground 변화는 확대 설명으로 보완할 수 있다. 쉬운 설명을 위해 필수 지원 행동을 제거하거나 정상 동작을 구조의 측정 이익으로 표현하지 않는다. 이 문서 작성만으로 그림/PPTX 동기화가 완료된 것은 아니다.
