## 1. 이번에 바꾸는 접근

목적은 **중요한 VIA 품질을 달성하기 위한 구조 선택의 이유를 찾는 것**이다. 먼저 기존 T/A를 쉽게 수용할 수 있는 공통 구조를 찾고, 그 구조가 비용을 발생시키는 원리를 바꾸는 대안을 검토했다. 전환 비용을 키우거나 여섯 개의 새 C를 만드는 것이 목적은 아니다.

결론은 세 가지다.

1. S-01~06의 기존 설명은 주요 구조 결정의 자격을 입증하지 못한다. 아래의 국소 전환 반론을 먼저 해소해야 한다.
2. 상위 품질과 직접 연결되는 새 방향으로 **대화 사건마다 다음 처리를 판단하는 모델 실행 구조**를 구체화했다. 기존의 요청별 해석, 코드 상태기계와 비교한다. 구조 차이를 제시했지만 싼 호환 구현으로도 같은 이익을 얻는지 추가 검토가 남는다.
3. **독립 상태 확정과 메시지 조정 구조**도 구체화했다. 공유 transaction을 실제로 없애면 구조가 달라진다. 그러나 즉시 보류와 권한 철회 계약을 보전하는 데 필요한 조정이 독립성의 이익을 줄인다. 현재는 주요 후보로 승격하지 않는다.

새 두 방향의 실행과 상태는 [04-11](./04-11-mechanism-family-proposals.md), 전환 반론과 13개 품질, 판정은 [04-12](./04-12-mechanism-family-review.md)에 있다. 구조의 차이와 VIA에서 선택할 가치의 입증은 별개다.

## 2. S-01~06의 가장 쉬운 조합부터 검토

`T+A`는 검토용 가상 확장이다. 실제 target이 두 기능을 이미 가진다는 뜻이 아니다. 기능 지원의 모순까지 합친 가상의 완전한 안을 만들지 않는다.

| 기존 질문 | 공유하는 핵심 구조 | 가장 싼 전환 또는 조합 | 남는 비용과 이번 판정 |
| --- | --- | --- | --- |
| [S-01 추가 자료 확인](./04-01-semantic-execution.md) | Request Interpreter의 후보를 Request Controller가 검증하고 확정한다. Context Manager가 허용 조회를 수행한다. | 모델 호출 중 read 요청을 받는 실행 adapter와, 반환 후 다시 부르는 adapter를 Request Interpreter 뒤에 둔다. 공통 read 예산과 최종 제안 형식을 유지한다. | 세션 유지, 중단, timeout 구현은 필요하다. 그러나 Request와 Task의 의미 확정 및 재개 원리가 바뀐다는 근거가 없다. **계열 내부 선택**. C-대화처럼 전체 후속 결정권까지 옮기는 것과 구별한다. |
| [S-02 화면 정보](./04-02-screen-evidence.md) | 같은 관측과 입력 시간 근거를 Request Interpreter에 제공한다. A의 객체와 관계는 같은 관측에서 만든 해석이다. | Context Manager의 준비 자료에 파생 화면 해석을 선택적으로 붙이고, 원래 화면 경로를 유지한다. | 생성, stale 처리와 자원 비용은 실제 비용이다. 독립 정보원이나 새로운 확정 권위로 바뀌지는 않는다. **계열 내부 선택**. 기존 A 보강 미정 상태를 강한 대안 확정으로 바꾸지 않는다. |
| [S-03 자료 찾기](./04-03-semantic-retrieval.md) | Context Manager가 후보를 모으고 실제 source와 권한을 확인한다. | 검색 port 뒤에 의미 색인을 추가하고 metadata/keyword 조회와 함께 후보를 낸다. 실패 시 기존 조회를 유지한다. | 색인 구축과 삭제 전파의 개발비는 있지만 요청과 실행의 권위를 바꾸지 않는다. **계열 내부 선택**. 검색의 중요성과 주요 DP 자격은 구분한다. |
| [S-04 대기와 재개](./04-04-request-continuation.md) | T와 A 모두 명시적 요청 관계, 질문, 전송 검증을 내구적으로 이어간다. A도 공유 저장 transaction을 유지한다. | Request Controller의 외부 계약을 유지하며 continuation 실행을 내부 runtime으로 바꾼다. B의 세션 한정 지원은 선택 기능으로 둘 수 있으나 복구 지원을 동시에 주장할 수 없다. | 진행 중 continuation 변환은 비용이다. 작업을 종료하고 전환하면 줄어드는 비용과, 그래도 남는 전체 제어 설계 교체를 구별해야 한다. 현재 문서에는 후자의 입증이 부족하다. **주요 자격 보류**. |
| [S-05 응답 생성](./04-05-response-path.md) | 최종 게시 권위, Text/Voice 전달 기록과 사용자 발화 중 출력 금지는 같다. | 좁은 직접 S2S 경로를 선택적으로 활성화하고, 나머지는 Core의 승인된 Text를 음성화한다. | 직접 기능을 끄면 해당 기능 손실을 기록해야 한다. 경로 제어와 생성 비용 변화만으로 핵심 구조의 되돌림 비용을 설명하지 못한다. **계열 내부 선택**. |
| [S-06 음성 근거](./04-06-speech-evidence.md) | 정규화된 SpeechEvidence를 소비하고 입력 revision을 검증하는 경로는 같다. | 생산자 adapter를 독립 ASR 또는 Omni native evidence에 연결한다. 동시에 양쪽을 쓰려면 기준 전사와 불일치 처리도 정해야 한다. | runtime 지원, 스케줄링과 장애 결합 비용은 남는다. 생산자 교체 이상의 전체 구조 재설계가 필요하다는 근거는 미확인이다. **주요 자격 보류**. 모델 capability 부족을 구조 전환의 어려움과 혼동하지 않는다. |

이 판정은 여섯 기능이 중요하지 않거나 구현이 무료라는 뜻이 아니다. 해당 기능의 설계와 평가 자료는 남긴다. “Component가 생긴다”, “예전 데이터를 새 형태로 만들 수 없다”만으로 주요 구조 결정이라고 주장하지 않는다.

## 4. 공통 골격의 무엇을 바꾸는가

| 구체 대안 | 같은 목적 | 실제 T의 원리 | 바꾸는 원리 | T+A의 기능 확장과 다른 점 |
| --- | --- | --- | --- | --- |
| C-대화 | 불완전한 대화와 후속 사건을 정확한 응답, 질문 및 업무 연결로 이어가기 | Request Interpreter는 해석 후보를 반환한다. Request Controller의 요청 관계와 상태기계가 다음 처리 및 재개를 구동한다. | 새 Conversation Agent가 사건과 실행 receipt를 읽고 다음 VIA 처리를 반복 제안한다. 코드가 권한, identity, 전송과 게시의 불변 조건을 강제한다. | 모델은 추가 read 한 번을 수행하는 내부 함수에 머물지 않는다. 후속 결과, 질문 답변과 정정 이후의 의미상 진행도 같은 실행 루프가 결정한다. **다만 기존 요청 계약의 확장으로 그 이익을 얻을 수 있다면 주요 자격에서 내려야 한다.** |
| C-독립 | 정정, Agent 사건과 장애가 교차해도 각 요청의 처리와 확인 가능한 상태를 유지하기 | 여러 owner의 변경과 전송 검사를 하나의 State Store transaction으로 확정한다. | 대화, Task/전송, 정보 사용의 owner가 각자 내구 확정하고 메시지 및 barrier로 관계를 조정한다. | 메시지 전달 API의 유무가 아니라 공유 확정 시점의 부재가 다르다. 독립 저장을 단순 분할하는 것만으로 성립하지 않는다. **공통 제어를 되살리면 독립성 이익이 줄어든다.** |

이 둘은 S 번호의 대체 목록이나 선정된 DP가 아니다. 서로 조합할 수도 있는 서로 다른 질문이며, 조합하면 비용과 상호작용을 다시 검토해야 한다. 이번에는 실제 T와 각각 따로 대조한다.

## 5. 이번 선별과 재개 조건

- **C-대화: 다른 계열 가능성 검토 중.** 상위 품질에 대한 원리와 구조를 사용자에게 제시한다. 순서 선택의 유연성이 실제로 부족한 질문이나 재설명을 줄이는지, 싼 기존 계약 확장으로 그 이익이 재현되는지가 관건이다. 강한 대안 확정은 아니다.
- **C-독립: 보류.** 구조 차이는 설명할 수 있지만 단일 사용자 PC에서 조정 비용을 감수할 이유와 엄격한 hold/철회 동작의 양립이 충분히 뒷받침되지 않는다. 일부 owner 장애의 독립 진행이 실제 상위 품질 문제를 크게 줄이는 상황이 확인되면 재검토한다.
- **기존 S-01~06: 주요 후보 자격 미입증.** 원래 기능 설명과 장단점은 참고로 유지한다. 새 C를 붙였다는 사실만으로 이들을 다시 주요 후보로 선언하지 않는다.

이번 결과는 “강한 대안 두 개 확보”가 아니다. 하나의 우선 검토 방향과 하나의 구체적 보류 사례를 얻었다. 상위 품질의 이익과 구조 전환 근거가 모두 충족되는 주요 DP 후보는 아직 확정하지 않았다. 다음 검토에서 C-대화도 싼 전환 반론을 넘지 못하면 보류하고 문제 원장에서 다른 원리를 찾는다.
