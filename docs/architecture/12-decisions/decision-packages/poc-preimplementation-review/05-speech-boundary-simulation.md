# 전사 입력과 음성 경계 모사의 PoC 축소안

> **METHOD_PROPOSAL / NOT_IMPLEMENTED / NOT_RUN — 2026-10-12.**
> 사용자가 반복 WAV 전사 대신 전사 fixture와 소수 보정 관측/지연 모형을 제안했다.
> 이 문서는 그 방법을 권고하는 설계안이다. API 호출, 보정 측정과 QA 원문 개정은 수행하지 않았다.

## 1. 입력 음성 API는 DP41 비교의 필수 구현이 아님

DP41은 같은 전사와 근거를 어떻게 해석/조회/결합하는지 비교한다. 전사 서비스 자체는
A/B 교체 대상이 아니므로 매 실행마다 WAV를 만들어 전사 API에 보낼 필요가 없다.
전사 원문, 입력/revision, 지칭 span의 시각과 원천 observation은 동일 fixture로 공급한다.
원문에서 final 전사 시각을 지정한 사례는 그 사건 시각을 유지한다. 미지정 값은 명시한
공통 profile로 정하고 새로운 profile 결과를 기존 실행과 섞지 않는다.

VIA의 제어는 final 전사 이전에도 동작한다. InputStarted에 따른 hold/출력 중단,
발화 중 source 사건과 화면 근거, SpeechEnded와 TranscriptFinalReceived를 별도 사건으로
제공한다. 후속 사용자 답변과 질문 철회/재연결도 같은 사건 port를 사용한다.
전사 완료 이벤트만으로 onset, 발화 종료와 단어 시각을 대신하지 않는다.

실제 의미 LLM의 A 반복/조회 결과 재입력과 B frame/부분 호출/코드 결합은 유지한다.
원천 조회/채택/인계/continuation/전달 제어도 후보가 실제 수행한다. 음성 stub은 후보가
생산한 출력과 release/stop을 소비하며 올바른 내용/순서를 정답으로 보정하지 않는다.

## 2. 공통 지연을 정하는 방법

지연 모형은 결과 전에 version/입력 변수/규칙/seed를 정하고 양안에 동일하게 적용한다.
소수 실제 API 보정은 선택 사항이다. 실행하지 않으면 평균을 실측값으로 부르지 않는다.
보정할 때는 발화 길이/환경과 표본별 원값을 보존한다. 적은 표본의 평균으로 제품의
분포나95% 보호 조건을 검증했다고 주장하지 않는다.

- canonical 원천 시각에 따른 전사 입력의 실행을 우선 보존한다.
- 추가 민감도는 빠른/기준/느린 공통 profile로 분리한다. 상수 평균을 써도 그 가정과
  적용 범위를 명시하며 A/B별로 임의 값을 가감하지 않는다.
- 변동 profile을 쓸 때 동일 case/repeat/logical utterance의 지연은 짝지어 고정한다.
  global 호출 순번으로 배정해 추가 질문 이후 두 안의 공통 입력 지연이 달라지게 하지 않는다.
- 지연은 TranscriptFinalReceived의 실제 주입 시각에 반영한다. 측정 종료값에 나중에
  일괄 더하면 늦은 반환/동시 사건의 경합을 재현하지 못한다.
- 후보가 실제 추가한 질문/사용자 답변/음성 안내는 횟수, 실제 텍스트, 길이와 queue를
  기록하고 같은 모형을 다시 적용한다. 모든 Request에 음성 비용/지연 한 번을 붙여
  후보별 추가 상호작용을 지우지 않는다.

예를 들어 발화 종료가2초이고 옛 반환이2.1초일 때, 전사 도착2.05초와2.3초는
사건 순서가 다르다. 이는 설명용 값이며 보정 관측이 아니다. 평균 지연을 쓸 수는
있지만 같은 실행 순서의 결과에 단순 덧셈만으로 이 두 경합을 재현할 수는 없다.

## 3. 출력과 QA 보고의 구별

출력 음성도 제어 비교에서는 실제 후보 Text를 소비하는 device/provider stub을 쓸 수 있다.
첫 핵심 segment, 준비/재생 queue, release, 실제로 모사한 전달 범위와 stop receipt를
기록한다. 문장 길이, 안내 횟수와 순차 재생 차례를 반영하며 특정 A/B에 유리한 상수를 넣지 않는다.
실제 cloud 음성 생성/물리 재생 endpoint가 필요한 검증은 별도 소수 실험으로 추가할 수 있다.

| 결과 | 증거 수준 |
| --- | --- |
| 같은 전사에서 의미 LLM 출력/조회/채택/인계/효과, Text 정확성과 로컬 실행 | 실제 후보/모델 실행의 관측. 입력 전사의 정확성이 주어진 조건에서의 결과 |
| 음성 stub의 전달/중단/queue 처리 | 실제 제어 코드가 모사 장치와 수행한 구조 검증. 실제 speaker onset/청취와 구별 |
| 지연 profile을 포함한 QA02/03 | 공통 음성 조건을 가정한 수치와 민감도. 실제 음성 endpoint의 실측으로 표시하지 않음 |
| 의미 모델 usage/비용 | 실제 usage와 검증한 단가로 집계. 음성 입력/출력과 평가 judge는 별도 분리 |
| 음성 비용 | 실제 발생한 발화/출력 기록과 공통 가격/사용량 모형에서 계산한 추정. 음성 API 미호출을 제품 비용0으로 처리하지 않음 |
| QA05와 Mac 메모리 | 실제 patch/회귀와 prototype process의 OS 값. 생략한 음성 runtime/buffer 범위를 공개하고 전체 음성 제품 메모리로 확장하지 않음 |

모든 표에 실제 관측, 모사 실행과 계산 추정을 구분한다. C6의 Text 사실/제어는 평가할 수
있으나 모사만으로 음성 모델의 내용 변환, 실제 재생과 local stop 보호 조건을 실측 검증하지 않는다.
현재 QA의 Voice ON endpoint와 음성 청구를 생략한 값을 기존 전체 QA 점수로 직접 치환하지 않는다.
음성 profile의 비교 조건과 적용할 등급 의미는 측정 전에 실행 계약에 기록한다.

## 4. 권고

DP41의 주 실행은 **전사 fixture + 실제 의미 LLM/후보 코드**로 축소하고 음성은
공통 사건/device profile로 모사한다. 음성 API 보정은 필요한 공통 변수만 대상으로 하는
선택 실험이다. 입력 전사 오류, 실제 음성 변환/장치 지연과 전체 음성 runtime 자원의
검증을 목적으로 할 때만 그 구간을 실제 연결한다. 차이를 만드는 후보 경로를 대체하지
않고 반복 음성 호출을 줄이는 방법이다.
