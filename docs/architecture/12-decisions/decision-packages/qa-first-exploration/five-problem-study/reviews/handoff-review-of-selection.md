## 1. 현재 판정

발견한 P2 한 건은 원 작성자가 수정했고 고정 소스 및 수정 문장을 재대조했다. 현재 확인 범위에서 미해소 P1/P2는 없다. 이 판정은 선택 정확도의 실제 우위나 모든 외부 Agent의 지원 기능을 검증한 결과가 아니다.

문제 5는 결합 판단과 별도 선택 실행을 구별하면서도 강한 A의 후보 축소, cache와 선택 부분 재판단을 허용한다. B의 정상 사용 이익이 이 보완을 넘는지 미확인이라고 남긴 점이 타당하다. 선택 기능의 중요성과 주요 DP 자격을 구별하며, 두 안을 확보했다는 사실로 3개 이상의 QA trade-off가 검증됐다고 주장하지 않는다.

## 3. 공통 QA 정의 확인

- **N-S 선택 정확도:** 현재 채택한 Agent 또는 보류가 사전 허용 집합에 속하는지 같은 지점에서 판단한다. 복수 정답, 적합 후보 없음, 정당한 보류와 불필요한 보류를 구별한다. 기능 선언과 실제 업무 품질 근거도 구별한다. 선택 이유를 선택기가 생성했다는 사실을 독립 oracle로 사용하지 않는다.
- **N-H 업무 인계 정확도:** 외부 실행을 허가하며 확정한 계약을 같은 tuple과 경계로 판단한다. 중간 요약 / 해석 입력으로 관찰 지점을 바꾸지 않는다. source 본문을 전부 push할 필요는 없지만 유효한 자료 참조와 접근 계약이 있어야 한다. 외부 Agent가 자료를 읽지 않거나 업무를 잘못 수행한 결과는 VIA의 인계 오류와 구별한다.
- **N-R 요청 관계 연결 정확도:** 최초로 채택한 관계 집합을 대상으로 한다. QA02의 대상 집합과 구별하며, 나중의 정정으로 최초 오류를 지우지 않는다. 같은 오류가 N-H에도 남는 경우 독립 이득으로 합산하지 않는다.
- **QA01/03:** 선택 확정 전에 구체적 처리 의도를 표시할 수 있으면 첫 응답 차이가 작아질 수 있음을 인정한다. QA03의 전체 처리 경로와 QA01의 겹치는 시간을 독립 이득으로 합산하지 않는다.
- **QA02/04/06:** 후보 정보의 문맥 간섭을 QA02의 확정 우위로 취급하지 않는다. 실제 Rust 수정 없이 QA04 모듈 수를 추정하지 않으며, cloud 선택 문맥을 local RAM으로 계산하지 않는다.
- **QA05:** 별도 selector 호출, 계약 보완, 재선택과 준비 비용을 포함한다. 후보 축소와 cache를 양안 모두에 허용한다.
- **coverage:** N-S의 중요성이 높아도 현재 두 DP에서 실제 차이가 확보된 것은 아니라고 명시한다. 문제 4에서 선택 이후에만 인계가 달라지면 N-S에 영향이 없다는 설명이 타당하다.

새 지표의 수치 목표, deadline, 모집단과 판정 도구가 아직 정해지지 않았다는 한계도 명시돼 있다. 이번 문서 리뷰가 지표 freeze나 평가 수행을 의미하지 않는다.

## 4. 종합 README의 문제 4/5 대조

문제 4의 H-A/B는 가공 시점이고 H-C는 수신자 읽기라는 별도 축으로 요약돼 있으며, 1과4가 동일 producer를 비교한다면 통합해야 한다는 조건도 남아 있다. native session 재사용을 이종 Agent의 private 상태 이전으로 설명하지 않는다. 수신자 pull의 비용 이동도 전체 업무 비용 절감으로 과장하지 않는다.

문제 5는 비교안은 확보했지만 주요 DP 승격은 보류한다고 요약한다. 필터와 worker handoff 제안은 공통 보완으로 두며, 후보 card의 기능 선언을 업무별 최고 성능의 근거로 쓰지 않는다. ‘추가 핵심 후보’라는 문제 4 권고와 ‘최종 DP / core QA 미선정’ 상태도 구별돼 있다. 이 범위에서 본문이나 확인한 source 사실을 과장한 추가 요약 오류는 발견하지 못했다.
