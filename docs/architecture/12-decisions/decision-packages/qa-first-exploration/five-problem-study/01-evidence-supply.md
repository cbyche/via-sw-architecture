# 문제 1. 현재 요청을 이해하는 데 필요한 근거 공급

2026-10-17 / §10에 기본 A 작성자 권고와 PoC 판정 기준 추가 / 사용자 선정과 측정 전

**현재 권고:** 문제 1을 독립 DP로 유지하고 기본 A인 대화 작업 문맥 유지를 추천한다. 근거와 반증 조건은 [§10](#10-2026-10-17-설계-권고)에 있다. §1~9의 미선정 표시는 이전 비교 단계 기록이며, 아래 권고가 사용자 선정이나 측정 결과를 뜻하지는 않는다.

## 1. 사용 장면과 기본 A/B/C

사용자는 비용 비교 설명을 들은 뒤 다른 이야기를 하다가 “아까 들려준 부분과 일정 설명을 연결해줘”라고 말한다. VIA는 화면에 적었던 전체 설명과 실제 음성으로 전달한 부분을 구별하고, 서로 다른 시점의 결과를 찾아 현재 요청을 판단해야 한다. 관련 UC는 01~07, 10~11, 14~15, 17~18이다.

**설계 질문은 필요한 근거를 언제 모으고, 다음 요청을 위해 어떤 상태로 남기는가다.** 기본안은 각각 그 자체로 이 기능을 수행한다. 선택 뒤 약한 QA를 개선하는 추가 기법은 §7의 보완책(tactic)으로 분리한다.

| 기본안 | 핵심 상태와 처리 | 선택할 이유 | 기본 비용 |
| --- | --- | --- | --- |
| **A. 대화 작업 문맥 유지** | 모델이 읽는 대화별 작업 문맥을 유지하고 다음 요청에서도 사용 | 같은 주제의 후속 질문에서 이미 읽은 근거를 곧바로 재사용 | 문맥 유지와 축약, 관련 없는 내용의 반복 입력 |
| **B. 요청별 원본 구성** | 최근 대화와 채택 상태에서 시작해 필요한 원본을 읽고 요청별 문맥을 만듦 | 주제가 바뀌거나 자료의 좁은 일부만 필요한 요청 | 요청마다 필요한 근거를 찾는 조회와 재판단 |
| **C. 기억 게시와 회상** | 원본에서 출처 있는 기억을 생산해 저장하고 여러 요청에서 조회 | 긴 이력에서 같은 사실과 결과 관계를 반복 사용 | 쓰지 않을 기억의 생산, 수정 반영과 출처 관리 |

A의 유지 문맥 재사용과 C의 게시 기억 재사용은 기본 구조다. 이를 선택적 cache로 빼지 않는다. B의 별도 조회 결과 cache, 입력 prefix cache, 병렬 읽기와 부분 재생산은 기본 비교에 넣지 않는다. 각 기본안이 기능을 수행하는 데 필요한 원본 읽기, 현재 유효성 확인과 오류 복구는 유지한다.

## 2. 모든 기본안의 공통 완료 조건

같은 원본, 권한, 모델과 자원 예산을 사용한다. 최근 사용자 원문, 현재 선택, 채택한 대상과 조건은 공통으로 보존한다. 따라서 “방금 두 번째 방식”처럼 최근 대화만으로 해결되는 요청에 조회를 강제하지 않는다.

| 정보 | 공통 소유와 규칙 |
| --- | --- |
| 사용자 입력과 시점별 화면 관측 | Interaction Manager가 관측한 범위와 누락을 남김. 마지막 화면을 과거 관측으로 대신하지 않음 |
| 현재 요청과 업무 조건 | Request Controller가 채택한 revision(변경 판본) 및 Task Manager의 확인된 상태 사용 |
| 실제 사용자 전달 | Response Manager의 텍스트 표시와 실제 음성 전달 범위 사용. 생성만 한 음성을 들려준 것으로 취급하지 않음 |
| 원본 결과와 첨부 | Agent Gateway가 관측한 결과와 접근 가능한 자료 사용. 외부 revision이 없으면 로컬 보존 복사본 식별자로 구별 |
| 작업 문맥, 기억과 검색 색인 | Context Manager의 파생 상태. 원본 및 현재 채택 조건의 권위를 대체하지 않음 |
| User Memory | 사용자가 허용한 지속 선호와 사실. 현재 업무의 임시 조건 및 Agent 주장과 구별 |

공통 처리 순서는 `원본 기록 → 근거 공급 → Request Interpreter의 의미 제안 → 현재 revision 채택 → 실제 표시`다. Task 연관성은 판단 결과이며 정답 Task를 미리 제공하지 않는다.

부족한 필수 원본의 보완, 철회된 자료의 사용 차단과 낡은 결과의 채택 거절은 기본 기능이다. 모호하면 확인하고, 충분한 근거가 있는데 불필요하게 묻는 것은 성공으로 세지 않는다. 구체적인 처리 의도를 채택했다면 상세 자료 읽기 전에 표시할 수 있다.

## 3. 기본 구조와 reference 근거

### A. 대화별 작업 문맥을 유지한다

작업 문맥(view)은 다음 모델 판단에 사용할 대화 내용과 근거를 모은 파생 상태다.

1. Context Manager가 새 원문, 채택 조건과 실제 전달 기록을 대화 작업 문맥에 반영한다.
2. Request Interpreter가 작업 문맥과 현재 관측을 함께 읽는다. 충분하면 곧바로 의미를 제안한다.
3. 부족한 근거는 원본에서 읽어 판단하고 작업 문맥에 반영한다. 다음 요청에서도 이 문맥을 사용한다.
4. 입력 한도를 넘으면 오래된 부분을 출처 있는 요약과 참조로 축약한다. 필요한 상세 원본은 별도로 남긴다.

문맥은 대화 수명 동안 유지한다. 정정된 조건은 사용을 차단하고 유효한 문맥을 다시 구성한다. 기본 비교에는 영향 구절만 재생산하는 별도 최적화를 넣지 않는다. 이때 문맥을 다시 만들더라도 사용자에게 전체 요청을 다시 말하도록 요구하지 않으며, 바뀌지 않은 채택 조건은 그대로 유지한다.

**근거:** OpenHands의 rolling view와 조건부 condensation(문맥 축약), [R01](../../../../../references/five-problem-study/evidence-and-handoff.md#r01-원본-사건과-대화별-모델-입력-view의-분리). VIA의 전달 범위와 화면 시점 추적은 추가 설계다. 축약이 실패하면 유효한 제한 문맥과 원본 읽기로 진행하며 낡은 요약을 최신 사실로 쓰지 않는다.

### B. 현재 요청에서 필요한 원본을 읽는다

1. 최근 대화, 현재 선택과 채택 상태를 읽고 이번 요청에 필요한 근거를 판단한다.
2. Context Manager가 필요한 원본의 권한과 revision을 확인해 제한된 범위를 반환한다. 기본 비교에서는 여러 읽기를 순서대로 수행한다.
3. Request Interpreter가 원본을 요청별 문맥에 결합해 판단한다. 부족하면 정해진 범위와 예산 안에서 다시 읽는다.
4. 채택 결과와 원본 기록은 보존하고, 탐색 중간 문맥은 해당 요청이 끝나면 종료한다. 다음 요청에서 이를 자동 재사용하는 조회 cache는 두지 않는다.

최근 답변 자체가 다음 질문에 필요한 내용을 이미 포함하면 그 답변을 사용한다. 기본 B에서 cache를 제외한다는 이유로 기록한 답변을 지우거나 원본을 불필요하게 다시 읽지는 않는다. 이전 탐색에서만 읽고 답변이나 채택 상태에 남기지 않은 상세 근거가 다시 필요하면 원본을 재조회한다.

**근거:** Deep Agents의 큰 자료 분리 저장(offload)과 범위별 원본 읽기, [R02](../../../../../references/five-problem-study/evidence-and-handoff.md#r02-큰-자료를-원본-저장소에-두고-필요한-범위-재조회). Deep Agents 전체가 이 기본 B만 사용한다는 뜻은 아니다. 요청별 문맥 수명은 실제 메커니즘을 VIA에 적용한 설계다.

### C. 출처 있는 기억을 생산하고 게시한다

1. Context Manager의 기억 생산 역할이 허용된 업무 결과, 실제 전달 기록과 사용자 수정에서 재사용할 기억을 만든다.
2. 원본과 revision을 연결하고 현재 유효성을 확인한 뒤 저장소에 게시한다. 게시란 이후 요청에서 조회할 수 있는 상태로 확정하는 것이다.
3. 현재 요청은 최근 대화와 함께 관련 기억을 읽어 판단한다. 기억에 없는 필수 세부는 원본에서 보완한다.
4. 원본이나 조건이 바뀌면 영향을 받는 기억의 사용을 차단하고 새 판본을 생산한다. 기본 비교는 각 대상 사건의 생산과 갱신을 수행하며, 선택적 생산이나 여러 변경의 묶음 처리는 추가하지 않는다.

기억은 하나의 대화를 넘어 재사용하는 파생 상태다. 업무 기억을 허용 User Memory로 자동 승격하지 않는다. 생산 작업이 늦게 끝나면 source revision과 사용 허용 판본을 다시 검사한다. 실패하거나 준비되지 않은 기억 대신 원본에서 필요한 근거를 읽는다.

**근거:** OpenClaw의 출처 검사, 기억 통합과 변경 계획 검증, CrewAI의 기억 저장 및 조회 전 미완료 쓰기 대기, [R03~04](../../../../../references/five-problem-study/evidence-and-handoff.md#r03-먼저-생산한-기억과-조건부-별도-recall), [R09](../../../../../references/five-problem-study/evidence-and-handoff.md#r09-명시-task-출력-조합과-추출-기억). 별도 회상 처리자는 가능한 보완 구현이며 기본 C에 추가 모델 왕복을 항상 강제하지 않는다.

| **EX02 명시 선택:** 선택한 문단의 실제 판본 사용 | 현재 선택을 문맥에 반영 | 명시된 원본 범위 읽기 | 현재 선택 사용. 관련 없는 기억 조회 생략 |

| **EX04 과거 결과와 반복:** 비용 비교 재조회, 반복, 이어 일정과 연결 | 첫 읽기로 문맥에 반영한 근거를 다음 요청에도 사용 | 최근 답변에 필요한 내용이 있으면 사용. 남지 않은 상세 근거는 다시 읽고 일정도 필요한 범위 조회 | 게시된 비용 / 일정 기억 재사용. 원본 세부가 없으면 보완 |
| **EX08 이동 지칭:** 발화 중 차트 A, B를 가리킨 뒤 빈 곳 이동 | 발화 구간 관측을 문맥에 넣어 판단 | 같은 구간 관측을 요청별 근거로 읽어 판단 | 최근 관측을 사용. 기억 게시가 끝날 때까지 기다리지 않음 |
| **EX09 부분 정정:** 표 T2를 T3로 바꾸고 문단 P2 조건은 유지 | 기존 문맥의 옛 조건을 차단하고 유효 문맥 재구성 | 현재 조건과 새 관측으로 요청별 문맥 구성 | 관련 기억 사용 차단 및 갱신. 준비 전에는 원본 보완 |
| **EX10 모호 / 관측 누락** | 부족한 근거 보완 또는 질문 | 원본 탐색 확대 또는 질문 | 기억의 불확실성을 유지하고 원본 보완 또는 질문 |
| **EX16 철회** | 관련 작업 문맥 사용 차단 후 재구성 | 현재 원본 접근을 차단. 없는 자료와 철회를 구별 | 출처 관계로 해당 기억 사용 차단 후 재생산 |
| **EX17 재접속과 변경** | 저장한 문맥의 원본 판본 확인 | 필요한 원본을 현재 상태에서 읽음 | 게시 기억의 판본과 원본 변경 확인 |

EX17에 별도 조회 cache가 남는 변형은 tactic을 적용한 §8에서 다룬다. 기본 A의 작업 문맥과 기본 C의 게시 기억이 남는 것은 각 구조의 핵심 상태다.

EX03에서 실제 들려준 A를 채택하면 “앞서 들려드린 첫 부분을 다시 보여드릴게요”라는 구체적 의도를 먼저 표시할 수 있다. 이후 상세 재구성은 첫 응답에 포함하지 않는다. 기본안의 조회가 있다고 해서 항상 QA01이 늘어나는 것은 아니다.

## 5. 기본안의 QA trade-off

| QA | 기본 A | 기본 B | 기본 C |
| --- | --- | --- | --- |
| **QA01 첫 응답** | 필요한 근거가 문맥에 있으면 조회 왕복 절약. 문맥 읽기 / 축약은 부담 | 작은 최근 입력으로 시작. 필수 근거가 없으면 조회와 재판단 대기 | 기억이 준비돼 있으면 작은 근거로 시작. 미완료 갱신이나 원본 보완은 부담 |
| **QA02 지칭 정확도** | 대화 관계를 보존하지만 축약에서 전달 범위가 빠질 수 있음 | 원본 세부를 확인하지만 검색 대상을 잘못 잡을 수 있음 | 과거 관계를 준비하지만 기억의 누락과 잘못된 통합이 가능 |
| **QA03 VIA 처리시간** | 문맥 구성과 조건부 축약, 상세 원본 읽기 | 요청별 조회와 재판단 | 기억 회상, 필요한 생산 대기와 원본 확장 |
| **QA04 변경 범위** | 전달 범위나 철회 변화가 문맥 구성 및 출처 계약에 영향 | 조회 / 범위 필터에 영향 | 기억 생산, 출처 관계와 갱신 계약에 영향 |
| **QA05 모델 비용** | 문맥 반복 입력과 축약. 유지 근거의 재사용 이익 | 현재 요청의 질의와 재판단. 필요한 범위만 읽는 이익 | 미사용 생산과 갱신도 비용. 반복 회상에서 의미 조합 절약 가능 |
| **QA06 최대 RAM** | 활성 문맥과 재구성 버퍼 | 요청별 읽기와 임시 문맥 | 기억 색인, 생산 대기열과 갱신 버퍼 |
| **N-H 업무 인계 정확도** | 문맥의 누락 / 옛 조건이 최종 인계에 남는 경로 | 원본 검색 누락이 최종 인계에 남는 경로 | 기억의 누락 / 잘못된 판본이 최종 인계에 남는 경로 |

QA01/03은 정해진 관찰 경계를 유지하고 겹치는 시간을 합산하지 않는다. QA03에는 실제 trial의 인과 경로만 포함한다. QA05는 전체 COMMON-28의 준비, 미사용 생산과 폐기를 포함하며 외부 Agent 내부 비용은 별도다. QA06은 로컬 최대 RAM으로 공통 512 MB 요구를 유지한다. 실제 Rust 모듈 수나 RAM 수치, 정확도 우열은 아직 없다.

N-H는 [외부 실행을 허가하며 확정한 계약](./06-qa-candidates-and-coverage.md#3-신규-후보-n-h-업무-인계-정확도)을 같은 oracle로 평가한다. 직접 응답과 모델 중간 입력의 충실도로 경계를 바꾸지 않는다. 채택 전에 필요한 원본을 보완하여 최초 채택 대상이 같다면 QA02는 동점이다. 최초로 잘못 채택한 대상을 후속 수정으로 고쳐도 그 오류는 지우지 않는다. N-H도 해당 인계 revision의 확정 계약에서 판정하며, 이후 수정 계약으로 이전 실패를 없애지 않는다.

## 6. 선정에 사용할 근거와 현재 판단

| 우선 사용 조건 | 기본안의 선택 이유 | 그 선택으로 남는 약점 |
| --- | --- | --- |
| 같은 주제가 길게 이어지고 방금 읽은 자료를 계속 사용 | **A:** 근거와 관계가 대화 문맥에 남음 | 반복 입력 비용, 정정 후 문맥 재구성 |
| 주제가 자주 바뀌고 실제 필요한 원본 범위가 작음 | **B:** 아직 쓰지 않을 의미 자료를 만들지 않음 | 반복 상세 조회와 여러 원본의 대기 |
| 여러 대화에서 과거 결과와 관계를 자주 회상 | **C:** 공통 기억 생산을 반복 사용 | 낮은 재사용률에서 미사용 생산, 변경이 잦을 때 갱신 비용 |

**현재는 A/B/C 모두 미선정이다.** 이 표의 사용 비중과 실제 QA 차이를 확인해야 선택할 수 있다. 보완책으로 약점을 줄일 수 있다는 사실만으로 기본 구조 비교를 무효화하지 않는다. 먼저 기본안의 선택 이유를 정하고 해당 안에 필요한 보완책을 선택한다.

A의 문맥 유지 비용이 조회 절약을 넘는 경우, B의 반복 탐색이 입력 절약을 넘는 경우, C의 기억 재사용이 낮아 생산 비용을 회수하지 못하는 경우는 각각의 선정 근거가 약해지는 조건이다. 중요한 DP인지 판단할 때도 정상 사용에서의 실질 차이와 여러 QA의 충돌을 확인한다.

## 7. 선택한 기본안의 부족한 QA를 보완하는 tactic

[공통 규칙](./07-basic-designs-and-tactics.md)에 따라 A1은 기본 A에 첫 보완책을 적용한 구성이고 A2는 기본 A에 둘째 보완책을 적용한 구성이다. 자동 누적하지 않으며 함께 쓰면 `A1+A2`로 명시한다. B1, C1도 같은 규칙이다. 각각의 개선과 비용을 기본 부모 안에 대비해 기록한다. 아래 기능은 §4~5의 기본 비교에 이미 들어 있지 않다.

| 부모 안 / tactic | 보완하려는 약점과 실제 추가 | 기대 개선 | 추가 비용과 적용 범위 |
| --- | --- | --- | --- |
| **A1 입력 prefix cache** | 반복되는 모델 입력 앞부분을 provider cache로 재사용 | 지원 조건에서 QA05와 QA03 개선 가능 | cache 수명, 변경과 provider 조건 관리. 수정으로 prefix가 바뀌면 이익 감소 |
| **A2 변경 조각만 갱신** | 문맥을 source별 조각으로 관리해 정정이 영향을 준 부분만 재생산 | 정정 시 QA03/05와 임시 RAM 감소 가능 | 조각 dependency와 무효화 검사. 변경되지 않은 의미가 실제로 독립적일 때 |
| **B1 조회 결과 cache** | 원본 판본 / 범위 / 권한으로 조회 결과를 보관해 요청 간 재사용 | 반복 상세 조회의 QA03, 첫 채택에 필요하면 QA01 개선 가능. 모델 조회 / 재판단 호출까지 줄 때만 QA05 이익 | 저장과 메모리, 만료 / 철회 검사. 최근 답변만으로 충분한 장면에서는 추가 이익 작음 |
| **B2 독립 근거 병렬 읽기** | 서로 의존하지 않는 여러 읽기를 동시에 수행 | 여러 원본이 필요한 요청의 QA01/03 개선 가능 | 동시 버퍼, 취소와 부분 실패 조정. 읽기 대상이 먼저 정해져야 함 |
| **C1 선택적 기억 생산** | 재사용 가능성이 있는 허용 사건만 의미 기억으로 생산 | 미사용 생산의 QA05와 대기열 RAM 감소 가능 | 생산 대상 판단 비용과 잘못 건너뛴 기억의 조회 지연. 누락 시 기본 원본 보완 유지 |
| **C2 변경 묶음 갱신** | 짧은 기간의 여러 정정을 모아 해당 기억을 한 번 갱신 | 잦은 정정의 QA05와 생산 부하 감소 가능 | 최신 기억이 늦게 준비됨. 옛 판본은 즉시 사용 차단하고 그동안 원본 보완 |

## 8. 반복과 변경 장면에서 기본안과 보완 후를 구별

| 장면 | 보완 없는 기본 동작 | tactic을 적용한 뒤 확인할 것 |
| --- | --- | --- |
| EX04 반복 질문에서 앞선 탐색의 상세 원본이 다시 필요 | A는 유지 문맥, C는 게시 기억을 재사용. B는 답변에 남지 않은 상세 근거를 재조회 | **B1:** 그 재조회가 줄었는지와 cache 유지 비용. **A1:** 문맥을 다시 입력하는 비용이 줄었는지 |
| 비용 원본과 일정 원본을 모두 읽어야 함 | 기본 B는 필요한 읽기를 순서대로 수행 | **B2:** 읽기를 병렬화한 실제 임계 경로와 추가 RAM. 답을 해석하는 모델 시간을 병렬 이득으로 세지 않음 |
| EX09 정정이 연속 도착 | 기본 A는 유효 문맥을 재구성. 기본 C는 대상 사건마다 갱신 | **A2:** 영향 조각만 재생산. **C2:** 원본 보완으로 기능을 유지하면서 여러 갱신을 합친 비용 |
| EX17 재접속 시 오래된 추가 cache가 남음 | A의 문맥 / C의 기억은 기본 유효성 검사. 기본 B에는 별도 조회 cache 없음 | **B1:** 판본 / 철회 검사 실패 시 cache를 쓰지 않고 원본 조회. cache 도입으로 늘어난 복구 책임 기록 |

A를 선택한 뒤 긴 과거 회상을 보완하려고 게시 기억을 추가하거나, B를 선택한 뒤 일부 업무의 기억 생산을 추가할 수도 있다. 이는 별도의 혼합 설계이며 두 기본 구조의 유지 비용이 함께 생긴다. 이번 A1~C2를 적용한 것으로 간주하지 않는다.

## 9. 문제 4 및 기존 DP와의 관계

문제 1의 출력은 VIA가 현재 발화를 이해하는 근거다. 문제 4의 출력은 외부 Agent가 업무를 수행할 인계 계약이다. 예를 들어 **문제 1 A + 문제 4 A**, **문제 1 B + 문제 4 B**를 독립적으로 구성할 수 있다.

문제 1 C의 기억 생산과 기존 DP-45는 직접 연결되므로 새 DP 번호로 중복 등록하지 않는다. 문제 4 B와 같은 생산 상태를 사용한다면 공통 생산 비용을 두 DP의 이익으로 중복 계산하지 않는다. 반면 수신 주체와 계약이 다르면 각각의 기본 구조를 비교할 수 있다.

이번 수정은 기본안과 선택 후 tactic의 비교 순서를 정리한 것이다. reference 구현 사실은 유지하며 구현, 모델 호출, 측정이나 우열 선정을 수행하지 않았다.

## 10. 2026-10-17 설계 권고

### 10.1 결론: 독립 DP로 유지하고 기본 A를 권고한다

**DP 질문은 ‘VIA가 현재 발화를 이해할 근거를 대화 문맥으로 유지할지, 요청마다 원본에서 구성할지, 재사용 기억으로 미리 생산할지’다. 기본 A를 추천한다.** 이는 작성자 권고이며 사용자 선정, QA 점수나 실측 결과가 아니다. 기존 DP-45와의 연결은 유지하며 이 문서에 새 DP 번호를 붙이지 않는다.

VIA의 정상 사용에는 현재 화면과 방금 설명한 내용을 이어 묻고, 들은 범위를 다시 지정하며, 같은 요청의 일부를 정정하는 과정이 포함된다. A는 이때 이미 읽은 근거와 대화 관계를 다음 판단에 남기는 구조다. 매 요청의 원본 탐색이 선행해야 하는 B보다 이 연속 사용을 직접 지원하고, 여러 대화를 위한 기억 생산을 추가하는 C보다 준비 범위가 좁다. **주제가 이어지는 대화가 중요한 사용 형태라는 요구를 선택 근거로 삼는다. 그 비중이 실측으로 높다고 주장하지는 않는다.**

감수하는 비용은 유지 문맥의 반복 입력, 한도 초과 시 축약, 정정 후 유효 문맥 재구성이다. A의 문맥은 원본을 대체하지 않으므로 긴 과거의 세부와 실제 전달 범위가 빠지면 원본을 보완해야 한다. 이 비용을 감수하고 현재 대화의 응답 준비를 우선하는 판단이다. 단순히 ‘history를 기억한다’는 가치만으로 C를 필수로 만들지는 않는다.

### 10.2 문제 4와 분리하는 이유와 공통 비용

| 실제 변경 경계 | 문제 1 | 문제 4 |
| --- | --- | --- |
| 소비자와 출력 | Request Interpreter가 읽을 현재 발화 해석 근거 | Downstream Agent에게 확정할 목적 / 조건 / 자료 접근 계약 |
| 준비를 시작하는 사건 | 사용자 입력 및 관련 관측, 대화 문맥 갱신 | 위임 확정 또는 공통 업무 기록 갱신 |
| 독립적으로 바꿀 수 있는 상태 | 대화 view, 요청별 임시 근거, 게시 기억 | 인계 묶음, 업무 기록, 명세와 읽기 권한 |
| 같은 입력에서 독립 변경 예 | 인계기를 A로 고정한 채 근거 공급 A/B/C 교체 | 해석기와 채택 결과를 고정한 채 인계 A/B/C 교체 |

**두 문제는 별도 DP로 유지한다.** 예를 들어 문제 1의 A로 후속 발화를 이해하면서 문제 4의 A로 위임 때만 묶음을 만들 수 있다. 반복 위임이 늘면 문제 1의 A를 그대로 두고 문제 4만 B로 바꿀 수도 있다. 한 DP의 선택이 다른 DP의 상태 수명과 자료 선택 책임을 결정하지 않는다.

공통 원본 보존, 현재 조건, 실제 전달 기록과 권한 검사는 한 번 구현하고 한 번 비용에 넣는다. 문제 1의 C와 문제 4의 B가 **동일한 생산물**을 공유하면 생산 / 갱신 비용을 한 번 기록하고 두 소비 경로를 표시한다. 두 DP의 비용 절감량을 더해 전체 절감량으로 제시하지 않는다. 반대로 같은 기록을 서로 다른 모델 호출에 두 번 입력했다면 실제 두 입력 비용은 모두 남는다. 결합 구성의 비용은 별도 실행 이력으로 판단한다.

### 10.3 기본안 선택에 사용할 네 QA의 손익

| QA | A를 권고하는 경로 | 반대편 이익과 상쇄 | 현재 근거 수준 |
| --- | --- | --- | --- |
| **QA01 첫 응답 지연시간** | 다음 발화의 필수 근거가 유지 문맥에 있으면 원본 탐색 왕복 없이 최초 채택 가능 | B는 주제가 달라지면 작은 입력으로 시작. C는 긴 이력의 관련 기억이 준비돼 있으면 탐색 단축. A의 긴 입력 / 축약은 이익을 상쇄 | 구조 가설. 최근 대화만으로 모두 판단하거나 구체적 의도를 먼저 표시하면 동점 |
| **QA02 지칭 대상 집합 일치율** | 발화와 실제 전달 범위의 관계를 함께 남길 수 있음 | A의 축약 누락, B의 검색 누락, C의 잘못된 통합은 서로 다른 오류 경로. 필수 원본 보완 뒤 최초 채택이 같으면 동점 | 정확도 우열 미확인. A의 속도 이익을 정확도 이익으로 바꾸지 않음 |
| **QA03 VIA 처리시간** | 같은 근거의 반복 읽기와 관계 재구성을 줄일 수 있음 | 주제가 자주 바뀌면 B의 좁은 조회가 유리. 장기 반복이면 C의 게시 기억이 유리. A의 문맥 재구성 / 축약은 직접 비용 | 정해진 trial 인과 경로에서만 비교. QA01과 겹치는 시간을 별도 이익으로 합산하지 않음 |
| **QA05 VIA 모델 비용** | 이미 구성한 근거를 재사용하여 탐색 / 재판단을 줄일 수 있음 | B는 불필요한 과거 입력과 미사용 생산을 줄임. C는 반복 조합을 상각하지만 생산 / 갱신 비용도 냄. A는 매번 읽는 긴 문맥 비용을 감수 | 전체 COMMON-28 비용으로 판단. A의 view 재사용 자체가 무료 입력이라는 뜻은 아님 |

주된 기본 trade-off는 **후속 판단의 조회 대기 절약 대 유지 문맥의 반복 입력 / 축약 비용**이다. QA02는 중요한 제약이면서 구조별 오류 경로가 다른 비교 축이지만 차별화가 확보된 축은 아니다. QA04와 QA06은 변경 파급과 로컬 최대 RAM 회귀를 확인하고, 숫자를 추정해 네 번째 이득을 만들지 않는다.

### 10.4 반대안을 선택할 구체적인 조건

| 대안 | A 대신 선택할 조건 | 왜 기본 구조 변경이 필요한가 |
| --- | --- | --- |
| **B** | 독립된 주제가 연속되고 각 요청이 긴 원본의 작은 부분만 쓰며, 앞선 탐색 상세를 다시 쓰는 일이 적음 | 대화 전체의 유지 / 재입력보다 현재 요청의 좁은 읽기가 주 비용을 줄임. 최근 답변만으로 되는 후속 질문은 B도 즉시 처리 가능 |
| **C** | 대화를 넘어 같은 결과와 관계를 여러 번 회상하고, 기억 생산 뒤 수정이 적으며, 게시 기억만으로 해결되는 요청이 많음 | 같은 의미 조합을 여러 소비자가 재사용해 선행 생산 / 갱신 비용을 회수. A의 현재 대화 범위보다 긴 수명이 필요 |

반복 횟수만으로 C의 이익을 단정하지 않는다. 이전 답변만으로 해결되는 반복에는 추가 기억 생산의 이득이 작다. 실제로 반복되는 것은 답변 밖의 근거 조합인지 확인해야 한다. 이 조건이 우세하면 B 또는 C가 더 나은 권고가 될 수 있다.

### 10.5 선택 후 추천 tactic: A1, A2

| 추천 구성 | 먼저 개선할 약점 | 추가 처리와 비용 | 적용 / 보류 기준 |
| --- | --- | --- | --- |
| **A1 입력 prefix cache** | 같은 문맥을 반복 입력하는 QA05 비용 | provider가 지원하는 안정된 입력 prefix를 재사용. 지원 형식, 유효기간과 적중 기록 관리 | 같은 유효 입력에 실제 cache 적중이 확인될 때 우선 적용. 캐시 할인이나 지연 감소를 적용 전에 성과로 기록하지 않음 |
| **A2 변경 조각만 갱신** | 일부 정정에도 문맥을 다시 만드는 QA03/05 비용 | source별 조각과 의존 관계를 관리하고 영향 조각만 재생산. 무효화 누락 위험과 관리 상태 증가 | 부분 정정의 재구성 비용이 확인된 경우 적용. 영향 범위를 확정할 수 없으면 기본 A의 유효 문맥 재구성 사용 |

기본 A 대 A1, 기본 A 대 A2를 각각 확인한 뒤 필요하면 A1+A2를 별도 비교한다. A2가 prefix 배치를 바꾸면 A1 적중이 감소할 수 있으므로 두 효과를 합산하지 않는다. A의 rolling view 재사용과 필수 원본 보완은 이 tactic 이전부터 존재한다.

### 10.6 같은 입력 PoC와 판정 규칙

아래는 **향후 별도 실행 승인 후 사용할 설계**다. 이번에 runner, 모델 호출이나 제품 실행을 수행하지 않는다. 작은 기전 검증을 전체 COMMON-28의 공식 QA 결과로 바꾸지 않는다.

| 입력 묶음 | 모든 안에 같은 원본과 사건 순서로 주는 내용 | 드러내려는 차이 |
| --- | --- | --- |
| P1-1 최근 연속 대화 | EX01 뒤 같은 대상을 다시 묻기. 정답 대상과 정답 Task는 미리 주지 않음 | 세 안 모두 최근 대화로 해결하는 동점 대조군 |
| P1-2 상세 근거 반복 / 목적 변경 | EX04 비용 원본의 답변 밖 상세를 다시 요청한 뒤 일정 원본과 결합. 이후 독립 주제로 전환 | A의 유지, B의 재조회, C의 생산 / 회상 비용과 주제 전환 손익 |
| P1-3 실제 전달 차이 | EX03 텍스트 A/B/C와 음성 A만 전달한 기록, 중간에 다른 주제 삽입 | 전달 범위 압축 / 검색 / 기억 오류와 최초 QA02 채택 |
| P1-4 정정과 철회 | EX09 표 T2→T3, 문단 P2 조건 유지. EX16 일부 source 철회. 옛 생산 결과는 나중 도착 | 정정 후 유효성, 기본 재구성 비용, 낡은 파생물 재사용 금지 |
| P1-5 대화 밖 회상 / 누락 | EX17 재접속 후 과거 결과와 새 v3 연결, 필요한 원본 일부는 없음 | C의 긴 수명 이익, A/B의 추가 조회, 정당한 보류와 실패 보존 |

공통 원본, 사건 시간, 모델 / provider, 입력 한도, 읽기 권한과 판정 oracle을 고정한다. 준비부터 시작하여 C의 기억 생산을 무료 준비물로 주지 않고 A의 문맥도 동일 사건에서 형성한다. 공통 최근 대화 / 채택 상태는 어느 안에서도 빼지 않는다. 기본 A/B/C의 결과를 먼저 남기고 tactic 결과는 따로 수집한다.

**완료 및 반증 판정은 다음과 같다.**

1. 최초 채택, 실제 표시, 상세 표시 / 음성 요약 준비, 모델 사용 내역을 같은 경계로 남긴다. 누락, 잘못된 최초 채택, timeout과 재시도를 보존한다. 나중 정정 성공으로 최초 오류를 지우지 않는다.
2. A의 권고는 P1-2/3에서 유지 근거가 실제 조회 / 재판단 대기를 줄이고, 그 이익을 얻으면서 현재 정확도 요구와 비용 요구를 만족한다는 가정에 기초한다. B와 최초 채택이 같고 속도 차이가 없는데 A의 비용만 높으면 이 권고의 핵심 근거가 반증된다. 축약 때문에 최초 오채택이 늘면 속도만으로 A를 정당화하지 않는다.
3. B가 같은 기능 / 정확도에서 주된 장면의 QA01/03을 악화시키지 않고 QA05를 낮추면 B로 권고를 바꾼다. C가 긴 회상뿐 아니라 동일한 준비 / 갱신을 포함한 비교에서 이익을 보이고 주된 연속 대화에도 요구 위반이 없으면 C로 바꾸는 근거가 된다. 특정 장면의 이득을 얻기 위해 입력 비중을 사후 조정하지 않는다.
4. QA05의 공식 판정은 COMMON-28 전체를 동일하게 실행할 때 한다. 위 묶음의 비용은 기전 진단으로만 보고한다. 기존 수치 목표, 점수, 모집단을 여기서 새로 확정하지 않으며, 시간 차이가 반복 변동과 구별되지 않으면 차이 확인으로 세지 않는다.
5. QA01/03이 함께 줄어도 독립된 두 이득을 더하지 않는다. QA02가 동점이면 이 DP의 정확도 coverage는 0이다. 그 경우에도 상태 수명과 준비 비용의 선택은 의미 있지만, 과정의 ‘3~4개 실제 차이’ 충족은 별도로 보고한다.

현재 결론은 ‘추가 조사를 기다리자’가 아니라 **문제 1의 A를 기본 설계로 권고하고, 그 비용을 A1/A2로 선택적으로 보완한다**는 것이다. PoC는 이 권고를 지지하거나 뒤집을 수 있도록 위 조건으로 제한한다.
