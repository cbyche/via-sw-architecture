2026-10-16 / 기능별 문제 지도와 첫 비교안 / 사용자 검토용

**첫 심화 문제는 ‘현재 요청을 이해하는 데 필요한 근거를 어떻게 공급할 것인가’다.** 대화를 이어 가며 이미 유지한 문맥을 읽을지, 요청마다 필요한 근거를 모아 해석할지 비교한다. 이 선택은 첫 응답 전에 필요한 모델 입력과 조회 왕복, 반복 입력 비용을 직접 바꾼다. 별도 근거 처리자를 두는 선택도 조사했지만, 앞의 두 방식에 조합할 수 있으므로 별도 설계 축으로 정리했다.

이 문서는 QA01~05에서 VIA 기능을 먼저 검토한 결과다. [첫 A/B 비교와 C 검토](./01-response-evidence-supply.md), [고정 소스 근거](../../../../references/qa-first-evidence-supply-20261016.md), [현재 QA 논의](../03-03-qa-dp-evaluation-plan.md)를 연결한다. 새 DP 번호나 기존 DP의 교체를 결정하지 않는다.

## 1. QA가 요구하는 설계 작업

여기서 QA01~05는 [현재 후보 패키지](../qa-candidate-package/README.md)의 번호다. 과거 범주형 QA-01~05와 구별한다.

| QA | 사용자에게 필요한 결과 | VIA가 설계해야 할 기능 경로 | 구조 비교에서 확인할 것 |
| --- | --- | --- | --- |
| QA01 첫 응답 지연시간 | 말하거나 사건이 발생한 뒤 해당 내용의 응답이 빨리 표시됨 | 입력 수신 → 근거 취득 → 의미 판단 → 대응 채택 → Request/Task UI 표시 | 첫 내용 응답에 꼭 필요한 단계, 그 단계의 대기와 추가 왕복. 단독 접수 신호는 제외 |
| QA02 지칭 대상 식별 정확도 | 말과 화면 또는 과거 맥락으로 가리킨 대상 집합을 올바르게 채택 | 관측 보존 → 필요한 근거 선택 → 지칭 해석 → 정정 반영 → 대상 집합 채택 | 어떤 정보가 해석 전에 없어지거나 늦게 도착하는지. 업무 상태 일관성을 이 지표로 대신 평가하지 않음 |
| QA03 VIA 처리시간 | 첫 안내 뒤의 상세 내용과 음성 준비도 오래 끌지 않음 | VIA의 조회, 모델 호출, 조정, 상세 표시와 전체 음성 요약 준비 | 외부 업무 시간과 사용자 대기를 제거한 실제 인과 경로. QA01과 겹치는 시간을 두 이익으로 합산하지 않음 |
| QA04 변경 범위 | 외부 형식과 기능이 바뀔 때 수정 영역이 과도하게 퍼지지 않음 | 모델 / Agent / 자료 연결, 응답 부분 교체, 전달 근거 조회, 구간 허용 철회 | 같은 C01~C06 변경을 완료하는 실제 Rust 모듈의 차이. 그림의 상자 수로 예측하지 않음 |
| QA05 모델 사용 비용 | 지속적인 사용에서 준비와 폐기까지 포함한 모델 비용이 감당 가능함 | 음성 처리, 해석, 문맥 유지, 근거 탐색, 응답 생성, 정정 재처리 | COMMON-28 전체의 사용량과 가격. 쓰지 않은 사전 생산, 재시도, embedding과 cache 요금을 함께 계산 |

QA01/03의 오답은 실제 소요 시간을 보존한다. 정확성 부족은 QA02와 해당 기능 검증에서 드러낸다. 빠른 오답을 느린 정답 시간으로 바꾸거나, 응답이 없는 경우 가상의 시간을 넣지 않는다. 숫자 목표와 점수 구간은 변경하지 않았다.

## 2. VIA 기능에서 찾은 어려운 설계 지점

아래 항목은 **DP 후보 목록의 확정본이 아니라 기능별 설계 문제 지도**다. 기능 경로가 겹치므로 행마다 DP를 만들지 않는다. QA 표기는 차이가 생길 수 있는 경로이며, trade-off 커버리지의 확정 수가 아니다.

| 기능과 어려운 문제 | VIA에서 중요한 이유와 실패 장면 | 선택에 따라 바뀔 메커니즘 | QA 충돌 또는 검토 축 | 이번 판단 |
| --- | --- | --- | --- | --- |
| **현재 요청에 근거 공급**: 지금 무엇을 알아야 하는가? | ‘방금 두 번째’, ‘아까 들려준 것’, ‘저 표 말고 이 표’가 대화, 실제 출력과 화면을 가로지름. 첫 응답 전에 범위를 정해야 함 | 대화별 유지 문맥의 갱신과 원본 재조회 vs 요청별 근거 취득과 임시 문맥 구성 | 01/03의 조회 대기와 입력 처리량, 02의 필요한 근거 확보, 05의 반복 입력과 사전 가공 비용. 04는 별도 확인 | **첫 심화 비교** |
| **동시 입력과 업무 사건 처리**: 새 입력이 기존 처리를 언제 바꾸는가? | 사용자가 정정하는 동안 다른 Task의 질문과 완료가 도착. 음성 중단만 빨라도 의미 처리가 줄에 갇히면 대화가 늦어짐 | 같은 대화 실행에 반영할 경계, 독립 해석 실행, 실행 중단과 채택 제어, 결과 재연결 | 01/03의 대기 감소 vs 05의 중복 추론과 폐기. 02는 해당 입력이 실제 지칭을 포함할 때만 관련 | **다음 심화 우선순위 2**. Task 수명 분리를 답으로 미리 정하지 않음 |
| **음성 중 화면 근거 보존과 결합**: 말과 화면 변화의 관계를 무엇으로 남기는가? | 포인터가 두 차트를 거친 뒤 빈 공간으로 이동. 마지막 화면 한 장으로는 사용자가 가리킨 두 대상을 복구할 수 없음 | 원본 관측 묶음과 해석 시 결합, 관측 단계의 대상 후보 생산과 이후 결합, 원본 확장 경로 | 02의 대상 누락 vs 01/03의 해석 대기와 05의 선행 생산 / 재판단 비용 | **심화 우선순위 3**. 첫 비교에서는 관측 품질을 공통으로 고정 |
| **부분 정정과 결과 재사용**: 무엇이 무효가 되고 무엇이 남는가? | 보존할 표만 바꿨는데 문단 수정 지시까지 사라지거나, 늦은 결과가 예전 조건을 되살림 | 요청 전체 교체, 근거와 해석의 의존 관계에 따른 부분 재판단, 결과의 조건별 재사용 | 01/03의 재처리 범위, 02의 수정된 대상 집합, 05의 폐기 / 재사용, 04의 부분 기능 확장 | **공통 어려움으로 추적**. 모든 안의 부분 수정 허용 후 독립 DP 여부 판단 |
| **요청의 의미와 업무 연결**: 확인 질문, 직접 답변, 위임을 어떻게 정하는가? | 불완전한 요청과 여러 업무가 섞인 발화. Task를 미리 정답으로 지정하면 실제 어려움이 사라짐 | 한 의미 판단에서 산출, 기능별 의미 생산과 교환, 필요한 근거에 따른 반복 판단 | 01/03의 판단 단계와 05의 호출, 02는 지칭 출력에 한정. ‘일반 요청 정확도’를 새로 넣지 않음 | **기능 요구로 유지**. 근거 공급과 동시 처리 이후 중복을 제거하고 검토 |
| **상세 응답과 음성 전달 연결**: 무엇을 사용자가 실제 접했는가? | 화면에는 A/B/C가 있으나 음성은 A만 전달. ‘들려준 것’과 ‘적어둔 두 번째’의 근거가 다름 | 응답 생성, 부분 채택과 표시, 음성 요약 준비, 실제 전달 범위 기록, 수정 전파 | 01의 첫 표시와 03의 전체 준비, 02의 과거 지칭, 04의 C04/C05, 05의 중복 생성 | **별도 중요 지점**. 현재 비교에는 공통 전달 원장을 제공 |
| **외부 연결과 허용 범위 변경**: 변화가 어디까지 퍼지는가? | 모델 / Agent 형식 변경, 자료 좌표 변경, 문서 일부의 사용 허용 철회 | adapter와 내부 자료 계약, 출처 및 범위 추적, 파생 자료 무효화 책임 | 04가 주축. 01/03/05의 정상 사용 차이는 구체적인 자료 경로를 찾아야 성립 | **모든 후보의 변경 검토에 적용**. 추상적 계층화만으로 DP를 만들지 않음 |
| **보류, 재접속과 실패 복구**: 대화가 끊겨도 무엇을 이어 가는가? | 업무는 계속되는데 대화 연결이 바뀜. 재실행과 결과 복원 시 중복과 오래된 답을 막아야 함 | 기록과 실행 수명, 복구 단위, 원격 사실 확인, 채택의 현재성 검사 | 01/03의 해당 복구 경로와 05의 재실행. QA02와 혼동하지 않을 별도 신뢰성 조건 | **필수 기능으로 유지**. 현재 01~05에서 큰 정상 사용 차이가 있는지 별도로 입증해야 주요 DP로 승격 |

**첫 순서의 이유:** 근거 공급은 QA01의 첫 내용 응답 이전에 직접 위치하고, QA02가 요구하는 대상 판단의 입력을 결정하며, QA05의 반복 비용에도 영향을 준다. 화면 처리만이나 과거 기억만으로 범위를 좁히지 않고 동일 기능을 여러 장면에서 비교할 수 있다. 어려운 장면에서도 허용된 자료의 제한된 읽기와 이해에 머물러 VIA 경계를 지킨다.

두 번째 문제는 첫 번째와 구별된다. 근거가 이미 충분해도 다른 실행 때문에 현재 입력이 기다릴 수 있다. 세 번째는 필요한 자료를 찾아도 그 자료에 발화 중 관측이 남아 있지 않으면 풀 수 없다. 이 구별을 유지해야 문맥, 실행 조정, 관측 생산을 한 DP에 모두 묶는 일을 피할 수 있다.

## 4. 첫 심화 결과와 DP 자격 판단

| 항목 | 현재 결론 |
| --- | --- |
| 문제 | 첫 응답에 필요한 현재 화면, 최근 대화, 과거 전달 내용과 업무 사실을 어떻게 가져올 것인가 |
| A | **대화별 유지 문맥 우선**. 기록으로부터 유지한 모델 입력 view에 최신 관측과 요청을 결합하고, 빠진 근거를 추가 조회 |
| B | **요청별 근거 구성 우선**. 공통 최소 문맥에서 시작해 현재 요청에 필요한 근거를 해석기가 읽고 임시 view를 구성 |
| C 검토 | **별도 근거 처리자**. 분리된 문맥에서 검색하고 근거 묶음을 반환. A/B에 조합 가능한 두 번째 축으로 분리 |
| 실제 구현 근거 | OpenHands의 rolling view, Deep Agents의 원본 offload와 도구 재조회, OpenClaw의 조건부 Active Memory, CrewAI의 별도 RecallFlow. Magentic-One은 현재 관측 묶음을 모델에 제공하는 보조 근거 |
| 가장 직접적인 손익 | A는 이미 필요한 근거가 있는 연속 대화에서 조회 왕복을 피할 수 있음. B는 주제가 바뀌거나 일부 자료만 필요한 요청에서 반복 모델 입력과 유지 비용을 줄일 수 있음 |
| 정확도 | A의 요약 탈락과 B의 조회 누락을 비교할 실제 경로는 있음. 양안의 원본 재조회와 cache를 허용한 뒤에도 유의미한 차이가 남을지는 미확인 |
| 변경 범위 | 공통 adapter와 provenance 계약을 강하게 두면 동점일 수 있음. 변경 모듈 수 우위를 주장하지 않음 |
| 판정 | **설계 비교로 구체화할 가치는 있다. 주요 DP 승격은 보류한다.** 현재 강한 경로는 01/03/05이며 01과03의 중복이 크다. 02의 차별화와 A/B가 저비용 혼합으로 수렴하는지 확인해야 함 |

‘VIA에서 중요하다’와 ‘양성과정의 주요 DP로 좋은 비교가 된다’를 구별한다. 근거 공급은 반드시 설계해야 하는 중요한 지점이다. 그러나 강한 혼합안으로 양쪽 손실이 작아진다면 독립 DP로 고집할 이유가 없다. 이 첫 검토의 기여는 근거가 있는 대안과 유리한 조건을 구체화하고, 주요 DP로 승격하기 전에 남은 반증 가능성을 드러낸 것이다.

## 5. 다음 탐색의 순서와 중단 기준

1. **동시 입력과 업무 사건 처리**를 같은 방식으로 심화한다. 정정, 독립 질문, Agent 질문과 완료의 경쟁에서 의미 실행을 계속할지, 분기할지, 취소 후 다시 할지 조사한다. 이미 필요한 입력 저장이나 단순 ID 검사만 다른 안은 제외한다.
2. **음성 중 화면 근거 보존과 결합**을 심화한다. speech와 관측의 실제 입력을 고정하고, 원본 관측과 producer 해석의 역할을 찾는다. 외부 harness가 다루지 않는 VIA 시간 지칭 부분은 별도 설계 추론으로 표시한다.
3. 각 문제의 강한 대안과 혼합안을 놓고 QA01~05의 차이와 동점을 기록한다. 그 뒤 기존 44/45/47/42와 겹치는 책임을 정리한다. 기존 번호를 먼저 배정하지 않는다.
4. **저비용 보완 뒤 차이가 사라지면 상세 설계로 낮춘다.** 3~4개 지표를 채우기 위해 accuracy나 modifiability의 뜻을 넓히지 않는다. 서로 같은 상태와 모델 호출을 바꾸는 비교를 독립 DP 두 개로 세지 않는다.

이 순서는 후속 조사 제안이다. 이번 산출물은 기능 지도와 첫 비교안이며 구현, 측정, 기존 DP 변경과 최종 선정은 포함하지 않는다.
