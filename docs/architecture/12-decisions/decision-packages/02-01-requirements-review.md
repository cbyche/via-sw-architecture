## 검토 범위와 방법

작성자는 1단계 문제 원장과 active mission/scope/UC·품질 계약·target 본문 및 상세 계약을 대조했다. P-01~16마다 필수 결과·예외·명시 합의·현재 수단·설계 자유도·미확인 지원 조건을 작성했다. 이전 네 비교안의 대안을 먼저 확정하고 역으로 요구를 만든 작업이 아니다.

별도 두 검토 에이전트가 초안 전에 위험한 분류 지점을 독립 추출하고, 초안 작성 후 문서 전체를 다시 읽었다. 한 검토자는 사용자 합의·현재 소유권·target 충실성, 다른 검토자는 요구 약화·평가 조건·미검증 지원·기존 QA 상태를 중점 확인했다. 수정 후 두 검토자가 자신이 지적한 사항의 해결과 수정 구간의 회귀를 재확인했다. 각 검토 범위에서 미해결 P1/P2가 없다고 보고했다. 같은 저장소를 읽는 에이전트 리뷰이며 외부 전문가 또는 사람 심사위원의 인증은 아니다.

| 발견사항 | 영향 | 보완 | 확인 상태 |
| --- | --- | --- | --- |

| P-13의 UNKNOWN을 외부 상태 소실/조회 불가에만 허용 | P2. 로컬 저장 손상·migration 실패·전달 receipt 불명 같은 확인 한계를 누락 | 근거가 부족한 범위의 불명은 보존. 저장소 정상·외부 조회 가능이라는 FA-14 기본 조건의 실제 복구는 여전히 필수 | 수정·독립 재확인 완료 |
| 06/07의 잘못된 파일명, E 변경의 직접 출처 누락 | P2. 사용자가 분류 근거를 확인할 수 없음 | active `06-fixed-assumptions.md`, `07-intentional-variables.md`로 수정. E-01~05는 QA-23 근거 원장 §5로 직접 연결 | 수정·독립 재확인 완료 |
| U 목록의 target-specific 계약을 모든 대안의 필수 형식으로 읽을 가능성 | 명료화. 공통 capability와 현재 schema/DB 수단을 혼동할 수 있음 | VoiceProposal·파일/DB 계약은 대안의 동등 계약으로 치환 가능하다고 §5에 명시 | 수정·독립 재확인 완료 |

두 검토자가 지적한 중복 발견사항은 한 건으로 기록했다. 이후 요구·경계의 분류가 바뀌면 이 문서와 해당 P/B 근거를 함께 수정한다.

## 특히 보존한 구분

| 구분 | 확인한 내용 |
| --- | --- |
| 제품 범위와 사용자 합의 | 일반 bounded 위임 허용과 target의 직접 설명 기본 방향·명시 예외를 함께 보존. 좁은 S2S·동일 대화 미전송 보류·발화 중 알림 금지는 단순 구현 정책으로 풀지 않음 |

| 정상과 예외 | FA-14의 복구 가능한 업무는 실제 재연결. 미지원/UNKNOWN 안내를 정상 기능 성공으로 대체하지 않음 |
| 상태와 전달 | Task 없는 clarification, 서로 다른 Task/Execution, Text 표시·Voice audible 범위·전달 불명, 대화 삭제·업무 취소를 구별 |

| 평가와 제품 | 장비·Task 수·지연값은 제품 최대/보장이나 새로운 workload 동결이 아님. 외부 상태/정답을 대안에 공짜로 제공하지 않음 |
| 단계 경계 | 구조 대안·DP 선발·품질 기호 비교는 아직 수행하지 않음. 기존 QA 의미·QA-41 diagnostic 지위·target·ADR·archive 유지 |
