# 공통 의미와 세 층의 평가 계약

`QA-COMMON-SYN-CONTRACT-v3-STRATIFIED` / **SYNTHETIC_AUTHORED_NOT_MEASURED**

## 1. 통합 범위와 층별 조건

[INTENT.md](../../../../../INTENT.md)의 QA02 지칭 대상과 새 QA07 요청 의미의 경계를 유지한다. [v2 계약](../qa-common-synthetic-v2-20261021/01-common-contract.md)의 Text와 Voice/Screen 조건을 보존하고, [DP44 인계](../seven-problem-review/dp44-local-voice-execution-20261021/synthetic-comparison-20261022/handoff.md)를 별도 DELIVERY 층으로 연결한다. 층은 원본, 입력, 사건, 자원 및 모델 가정을 함께 고정한 비교 단위다.

**같은 층에서는 모든 해당 대안에 같은 사례, 정답, 완료 조건과 분모를 적용한다. 다른 층의 기준 구성을 동일 제품으로 취급하지 않는다.** 이 통합은 같은 QA 의미의 층별 비교이며 모든 구성을 모든 workload에 실행한 결합 평가가 아니다.

| --- | --- | --- | --- |

26개 사례군을 묶었다고 각 구성의 분모가 모든 층의 합으로 바뀌지 않는다. Text 기준 구성은 DP2와 DP5 비교에서 같은 출처로 재사용한다. Voice 준비 60개와 Delivery 준비 80개는 비용 및 RAM에 포함하지만 평가 입력, 지칭 정확도와 요청 의미 정확도의 분모에는 더하지 않는다. 작성 변형의 수는 실제 모델 반복 횟수나 통계적 독립 표본 수가 아니다.

VOICE와 DELIVERY가 같은 560 MB 기반과 일부 요율을 사용해도 같은 workload나 같은 실행 구성이라는 근거는 없다. VOICE의 DP2와 DP5 및 기존 두 층의 DP44는 `FIXED_UNMAPPED`다. DELIVERY의 DP2, DP3와 DP5도 고정 주변 기능이며 기존 A/B에 매핑하지 않는다.

## 2. QA 의미와 관측 사건

| QA | 공통 의미와 대표 집계 | DELIVERY에서 유지할 경계 |
| --- | --- | --- |
| QA01 첫 응답 지연시간 | 사용자 입력 완료부터 첫 구체적 채택 내용의 화면 표시까지, 입력별 산술평균 | 80개 새 입력의 수행 의도 표시. 기존 Agent 질문의 선행 표시를 새 입력 응답으로 재사용하지 않음 |
| QA02 지칭 대상 식별 정확도 | 표현/revision의 최초 채택 집합과 정답 집합의 순서 무관 완전 일치율 | 같은 올바른 DP2 결과를 고정한 120/120 fixture. DP44 정확도 향상을 검증한 값이 아님 |
| QA03 VIA 처리시간 | 원래 목표부터 최종 revision의 공통 완료점까지, 외부 duration을 제거한 인과 경로의 목표별 산술평균 | 원래 보고서 목표 10개와 새 전달 목표 80개를 구분. 장치 준비는 포함하고 순수 재생 대기는 제외 |

| QA07 요청 의미 해석 정확도 | 입력/revision의 최초 확정에서 필수 의미 전체가 맞는 비율 | 같은 올바른 의미를 고정한 80/80 fixture. 항목별 정확도 평균이나 전달 성공률로 바꾸지 않음 |

TEXT는 Text 제출, VOICE와 DELIVERY는 실제 발화 종료에 대응하도록 작성한 가상 사건을 입력 완료로 사용한다. 음성 입력의 종료 후 0.30초 잔여 전사는 포함하며 발화 중 수행한 처리를 다시 더하지 않는다. Text 값에 0.30초만 붙여 음성 값을 만들지 않는다.

v2와 마찬가지로 첫 표시가 틀린 행은 그 시각과 오류를 함께 남기고 이후 정답 시각으로 소급 교체하지 않는다. 단순 접수 인사는 제외한다. 현재 자료의 표시 시각은 작성값이며 실제 UI 계측이 아니다. 최초 표시와 전체 의미 확정을 구별하고, VOICE의 `adopt_display` stage처럼 원본이 둘을 한 구간으로 작성했다면 정밀한 채택 순간을 추가로 만들어 넣지 않는다.

QA02의 한 표현은 여러 대상을 가리킬 수 있다. 대상 개수를 분모로 세지 않는다. QA07은 필수 의미 전체가 맞아야 하는 입력 단위 판정이며, 최초 오류를 뒤의 정정으로 성공 처리하지 않는다. 같은 대상 오류가 두 QA에 동시에 나타날 수 있으므로 독립 효과 두 개로 합산하지 않는다. 첫 의미 확정 이후의 전달 누락과 Downstream Agent 업무 정확성은 두 QA의 정의 밖이다.

### 화면, 음성과 Agent source 진단의 분리

공통 대표값 `qa01`은 화면 종료점이다. DP44 부모의 `qa01_display_s`를 여기에 연결하고, `qa01_voice_s`는 별도 음성 진단으로 보존한다. 음성은 같은 입력 종료부터 장치 출력에 대응하는 가상 사건까지이며 생성 callback이나 enqueue 시각이 아니다. 실제 장치를 관측한 사실도 아니다.

화면 QA01을 포함한 공통 QA01~07의 63개 대표값과 DP44 음성 2개 값을 섞어 평균내거나 서로 대체하지 않는다. 음성 종료점을 공통 QA01로 바꾸려면 별도 계약 판본에서 기존 DP에도 같은 정의를 적용해야 한다. Agent source 발생부터 전달까지의 `deliveries`는 출발 사건과 모집단이 다르므로 사용자 입력 80개의 QA01에 편입하지 않는다.

DELIVERY의 QA02와 QA07 100%는 의미 해석을 공통 제어 조건으로 고정했다는 뜻이다. 모델 정확도, DP44 정확도 우위, 다른 층보다 높은 성능 또는 과정의 정확도 차별화 coverage를 뜻하지 않는다. 구판 미재생과 실제 전달 이력 검사는 필요한 전달 계약 검사로 별도 보고한다.

## 3. 목표 DAG와 원래 시작점

처리 단계의 선행 관계에 따라 `finish(node)=max(finish(parent))+duration(node)`를 계산한다. VIA 처리와 자원 의존은 남기고 외부 Agent 업무, 사용자 답변 대기와 순수 재생 대기의 duration을 0으로 투영한다. 겹치는 외부 구간을 단순 차감하거나 병렬 작업을 직렬 합산하지 않는다.

같은 목표의 정정은 최초 목표 시작을 유지하고, 새 독립 목표에서는 그 목표 시작 이전의 완료 작업을 초기 상태로 둔다. 초기 상태를 만드는 비용과 메모리는 각 층의 전체 활동 원장에 남긴다.

DELIVERY에서 원래 보고서 목표 10개는 시작 -6초를 보존한다. 현재 정정 입력의 0초로 시작을 옮기지 않는다. 새 전달 목표 80개는 읽기, 순서 변경, 재개 또는 음성 철회라는 별도 완료 조건을 갖는다. 메일 질문을 읽는 것을 메일 발송 업무의 완료로 세지 않는다. 전체 QA03은 90목표의 평균이며, 목표 수가 다른 8개 사례군 평균을 다시 균등 평균하지 않는다.

VOICE 원본의 현재 직렬 경로에서 QA03이 QA01+2.5166667초가 되는 관계는 해당 DAG의 결과다. 이 상수를 TEXT나 DELIVERY에 재사용하지 않는다. DELIVERY S08은 외부 도착 전 선행 여유가 50ms인 사례다. **작성된 실제 경과시간의 첫 음성 이익은 50ms**이고, 외부 대기를 0으로 투영한 QA03에서는 A의 생성과 의미 채택이 병행되고 B의 직렬 의존이 남아 차이가 더 커진다. 투영 QA03 차이를 물리 wall-clock 단축량으로 표현하지 않는다.

현재 부모 자료에 작성된 terminal은 채택 결과에 따라 처리가 끝났다는 뜻이다. 내용 오류와 terminal의 의미상 정확성을 별도로 보존한다. 이후 terminal이 없는 행을 추가하면 `null`과 예정 분모를 남기고 임의 벌점 시간을 만들거나 성공 행만 평균내지 않는다.

## 4. 비용과 미모델링 값

공통 가상 요율은 text 입력 1 USD/M, 출력 4 USD/M, 음성 생성 0.002 USD/초다. 음성 층은 공통 음성 처리 0.001 USD/초를 사용하고 VOICE는 image-equivalent 입력 1 USD/M를 추가한다. 이 값은 공급자 청구서나 실제 tokenizer 결과가 아니다. Local ASR, UI/OCR와 SAM의 CPU 처리를 cloud 호출 비용으로 다시 청구하지 않는다.

DELIVERY는 최대 4개 출력 생성 실행, 16 MB의 audio 한도, 0.38+text token/6000초의 첫 음성 준비, 첫 0.20초 chunk와 이후 wall 1초당 audio 4초의 생산, 취소 후 최대 0.10초 생성 tail을 부모 가정으로 보존한다. 이는 모델 capability를 확인한 결과가 아니다. 유효한 기존 오디오는 A와 B 모두 재사용한다. B의 S05 재개는 미생성 후반만 요청하며 전체 설명을 다시 생성하지 않는다.

QA05의 비교값은 VIA 비용이다. TEXT와 VOICE의 수신 Agent 비용은 별도 열로 남긴다. DELIVERY에는 수신 Agent 내부 사용량과 비용 모델이 없으므로 `receiver_cost=null`, `total_cost=null`로 유지하고 표시에는 **미모델링**을 쓴다. 비어 있는 값을 0으로 계산하거나 VIA 비용을 시스템 전체 비용으로 이름만 바꾸지 않는다. 비용의 층별 활동 분모가 다르므로 비용 합계의 DP 간 순위도 만들지 않는다.

## 5. 변경 범위와 동시 메모리

QA04는 각 구성에 동일 C01~C06 한 벌을 적용한다. 세 층을 더해 18종 과제로 보거나 9구성의 변경 행 수를 새로운 요구 수로 세지 않는다. 예상 모듈 목록은 설계의 소유 경계이며 실제 Rust diff, AI 개발 시간이나 병렬 개발 충돌의 실측이 아니다.

DELIVERY의 기본 목록은 A `[1,1,1,5,2,4]`, B `[1,1,1,4,2,3]`으로 평균 2.333과 2.000이다. B의 Turn Execution과 Turn Audio Buffer도 별도 모듈로 센다. 공통 section/extent 인터페이스가 A의 준비와 보관에도 충분히 일반화되어 있으면 C04와 C06의 추가 변경 각 1개가 사라져 A도 2.000으로 동점이 된다. 이 민감도는 기본 목록을 덮어쓰지 않으며 0.333모듈 차이를 구조의 필연적 비용으로 주장하지 않는다.

QA06은 decimal MB다. 같은 시점의 상태 성분을 합하고 사례별 최고값에서 구성의 최고값을 구한다. 서로 다른 시각의 audio peak와 metadata peak를 더하지 않는다. 전체 snapshot 행은 겹쳐 있다고 다시 합산하지 않는다. DELIVERY의 audio는 PCM 24 kHz, 16 bit, mono의 48,000 byte/초와 job metadata 4096 byte/개 가정이다. 원격 모델 가중치와 KV를 로컬 상태에 넣지 않는다.

TEXT의 238 MB, VOICE와 DELIVERY의 560 MB를 합산하거나 한 층의 peak를 다른 층의 순수 추가 비용으로 빼지 않는다. 공통 원본, 사용량, 메모리 소유와 현재성 guard가 실제로 합쳐지는 제품 구성은 별도로 작성해야 한다. 현재 계수로 목표 장치의 512 MB 요구 충족을 주장하지 않는다.

## 6. 집계와 판단 규칙

QA01/03은 해당 입력/목표의 산술평균, QA02/07은 해당 평가 단위의 비율, QA04는 6과제 평균, QA05는 해당 VIA 활동 묶음 전체 비용, QA06은 동시 상태의 최고값을 쓴다. 결과에는 층과 구성을 함께 표시한다. 다른 층 사이 평균, 가중 총점과 결합 제품 점수는 만들지 않는다.

QA01→QA02→QA03→QA04→QA05→QA06의 기존 순서로 조건부 개별 권고를 설명한다. 새 QA07 요청 의미 해석 정확도의 우선순위, 목표와 점수는 별도 합의 전까지 추가하지 않는다. 이전 QA07 부하 추가 지연의 순위와 점수를 계승하지 않는다. COMMON-28의 비용 목표와 점수표도 이 묶음에 적용하지 않는다.

관련성, 고정 fixture의 동점, 수치가 있다는 사실은 차별화 coverage가 아니다. 합성 오류 빈도와 처리 시간은 작성 가정이며 모델 정확도, 통계적 유의성, 실제 장치 성능이나 측정된 승리의 근거로 바꾸지 않는다.
