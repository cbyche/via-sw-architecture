# 수치 범위와 해석 재검토

2026-10-22 / `COMMON-QA-SYN-3.0-REVIEW-2` / **SYNTHETIC_AUTHORED_NOT_MEASURED**

공통 v3를 다시 검토한 결과, **63개 공통 QA 값과 별도 첫 음성 2개 원값은 유지한다.** 음수 지연, 범위 밖 정확도, 누락된 완료점을 0으로 채운 값이나 합산 오류는 없었다. 보완한 부분은 비교 규칙, 관측 경계의 추적, 표시 정밀도와 자원 초과의 해석이다. 현재 범위는 작성한 사례와 계수 안에서 수학적으로 유효하며 실제 제품 성능의 적정 범위를 입증한 것은 아니다.

원자료는 [범위 원장](../../../../presentations_files/qa-common-synthetic-v3-20261022/range-review.json), 대표값은 [03 수치와 판단](03-results-and-decisions.md), 집계 정의는 [01 계약](01-common-contract.md)에 둔다. 최초 v3는 Git `8b2f555`와 [당시 검증 기록](../../../../presentations_files/qa-common-synthetic-v3-20261022/validation-history/8b2f555/README.md)으로 보존한다. 부모 v2와 DP44 자료는 수정하지 않는다.

## 1. 표시와 판정에 사용하는 수치

| 종류 | 저장 및 계산 | 문서, Excel과 HTML 표시 |
| --- | --- | --- |
| 시간, QA04 평균, RAM | 반올림 전 원값 | 소수 3자리 |
| 정확도 QA02/07 | 0~1 비율 | 분자/분모와 소수 2자리 백분율 |
| 정확도 차이 | 비율 차이 × 100 | 소수 2자리 `%p` |
| 비용 등의 상대 변화 | 원값 차이 / 기준 원값 × 100 | 소수 2자리 `%`, 기준 구성 명시 |
| 비용 | 준비 및 갱신을 포함한 사용량 × 가상 요율 | USD 소수 6자리 |
| 사례, 표현, 목표, 변경 모듈 개수 | 정수 | 정수 |

표시 자리수는 계산 재현을 위한 것이다. 모델의 예측 신뢰도나 계측 정밀도가 아니다. 십진수 half-up 반올림을 적용하여 1.1675는 1.168로 표시한다. 최소/최대는 작성 사례의 양끝이며 신뢰구간, 실측 최악값 또는 보장 상한이 아니다. JSON과 CSV의 원값을 반올림하여 저장하지 않는다.

TEXT의 입력/목표/비용 사례 수는 구성당 240/180/120, VOICE는 120/120/120, DELIVERY는 80/90/80이다. QA04는 구성당 같은 6과제다. 사례별 비용은 그 사례에 속한 준비와 갱신까지 포함한다. **QA05 대표값은 이 비용들의 합계**이며 표의 범위를 평균 내어 대체하지 않는다. 전체 비용이 사례별 최대보다 큰 것은 오류가 아니다.

첫 음성 지연은 DELIVERY에만 작성됐다. 두 안 모두 개별 범위는 0.890~1.364초지만 평균은 A 1.069초, B 1.276초다. 범위가 같아도 사례별 분포와 평균은 다를 수 있다. TEXT/VOICE의 첫 음성은 미작성이며 0초가 아니다. 이 진단은 입력 종료 기준이므로 채택 이후 청취 가능 시간을 세는 QA09로 재명명하지 않는다.

QA03은 구성별 **원래 목표 분모**로 평균한다. 예를 들어 D-A의 90목표 평균은 1.965초지만 8개 사례군 평균을 다시 평균하면 1.909초가 된다. T-BASE도 180목표 평균 6.650초와 12개 사례군 평균의 평균 7.004초가 다르다. 목표 수가 다른 사례군에 같은 가중치를 다시 주지 않는다. 다른 층의 시간이나 비용을 합쳐 평균내지 않는다.

지연과 처리 duration은 모두 0 이상이며 각 목표의 QA03은 해당 목표의 경과시간을 넘지 않는다. 준비 활동과 원래 목표 시작의 음수 timestamp는 입력 종료 0초보다 이전이라는 뜻이다. 음수 처리시간으로 잘못 판정하거나 0으로 잘라 준비 작업을 지우지 않는다. DELIVERY의 준비비는 0초 전 시작한 활동 전체의 분류다. A의 폐기비 0.263333 USD는 준비비의 부분집합으로 총액에 다시 더하지 않는다.

## 3. 정확도와 응답 경계

QA02의 분모는 지칭 표현/revision이고 QA07의 분모는 입력/revision이다. [03의 분자/분모](03-results-and-decisions.md)를 함께 표시한다. 판정은 행당 0 또는 1, 집계는 0~1이다. 100%가 되도록 분모나 오류를 바꾸지 않았다. DELIVERY의 120/120과 80/80은 올바른 해석을 공급한 고정 fixture이므로 정확도 성능이나 차별화 coverage가 아니다. VOICE에서 QA02와 QA07의 순개선 8입력은 같은 대상 오류 개선이며 독립 효과 두 개로 더하지 않는다.

세 층의 QA07 비교 규칙을 통일했다. `targets`, 배열형 `conditions`, `exclusions`는 순서와 중복을 무시하는 집합이다. `conditions.order`는 순서를 보존한다. JSON object key 순서는 무관하고 문자열은 대소문자를 구별한다. 누락, `null`, `false`, 숫자 0은 서로 구별하며 JSON number의 1과 1.0은 같다. 미등록 배열은 임의 처리하지 않는다. Excel도 같은 정규화 후 `EXACT`로 비교한다. 이 교정으로 기존 1,360응답의 판정이 달라지지는 않았다.

Excel 의미 셀은 미리 정규화된 JSON 문자열이다. 수동 편집한 문자열을 수식이 다시 파싱하거나 집합 정렬하지는 않으므로 같은 정규화 형태로 입력해야 한다. 원자료를 바꾸는 전체 재평가는 생성기를 통하며 단순 문자열 편집을 범용 의미 판정기로 해석하지 않는다.

T-EXEC의 70입력은 구체적인 부분 수행 의도를 먼저 표시하고 이후 전체 의미를 확정한다. 첫 표시 내용과 노드, 전체 확정 object와 노드를 별도 연결했다. 예를 들어 `TEXT:SYN-F02-01-U02`는 입력 종료 2.552초, 첫 부분 표시 5.081초, 전체 의미 확정 5.666초다. QA01은 2.528초이며 전체 확정까지의 시간으로 바꾸지 않는다. VOICE 원본이 채택과 표시를 한 구간으로 작성한 경우에는 그 구간을 보존하고 정밀한 채택 시각을 만들어 넣지 않는다.

현재 [QA01](../qa-candidate-package/qa01-first-response-latency.md)과 [QA03](../qa-candidate-package/qa03-via-processing-time.md)은 오류가 있는 표시와 완료점도 시간과 오류를 함께 보존한다. 따라서 오답 행을 제외하거나 정답 시각으로 소급 교체하지 않았다. 전체 의미 오류 수는 TEXT 16/27/23, VOICE 18/10/10/10, DELIVERY 0/0이며 terminal 내용 오류 수와 같다는 가정도 하지 않는다. 모든 현행 행에는 표시와 완료점이 있으므로 누락값을 0으로 채운 사례는 없다.

범위는 사례별로 **같은 시각의 소유 상태 합계**를 구한 뒤 그 최고값들을 모은 것이다. 구성의 대표값은 그중 최대다. D-A의 최고값은 S05-10의 4.639초, D-B는 S05-08의 8.269초에 발생한다. 두 최고값의 차이 0.152 MB는 서로 같은 시점의 차이가 아니다. 다른 시점의 성분 최고값을 더하거나 서로 다른 층의 RAM을 합산하지 않는다.

## 5. 이번 검토로 확정한 범위

문서, JSON, Excel과 HTML은 같은 의미, 분모, 표시 정밀도와 미모델링 상태를 사용한다. Excel의 범위검토 시트는 원장 기준 범위의 사본이다. 단가를 바꾸면 비용 계산표와 요약 수식은 재계산되지만 사례별 범위 전체를 다시 생성하지는 않는다. 새 비용 범위가 필요하면 변경한 가정을 별도 원장 판본으로 생성한다.

이번 검토는 상한이나 점수에 맞추어 수치를 조정한 작업이 아니다. 작성한 사례의 산술적 유효성, 기존 원값 보존, 의미 판정과 관측 경계 및 산출물 일치를 확인했다. 실제 오류 빈도, 모델 처리속도, 가상 요율의 시장 적합성, 실제 RAM과 통계적 유의성은 확인하지 않았다. 상세 발견과 독립 재확인 범위는 [재검토 기록](reviews/03-consistency-and-range-review.md)에 남긴다.
