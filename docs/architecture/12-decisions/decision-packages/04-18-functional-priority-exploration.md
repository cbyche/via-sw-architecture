# VIA 핵심 기능의 추가 설계 문제 — 화면 지칭, 업무 대화, 음성 처리

> 2026-10-03 / Stage 4 추가 탐색 / 주제와 두 방안의 사용자 검토용
> [현재 계획](./00-workplan.md), [선발 원칙](./selection-principles.md), [공통 품질 관점](./03-00-quality-scenarios.md#2-어떤-품질을-보고-있는가)

## 1. 이번 결론

**M-2 요청 해석과 함께 먼저 다룰 기능 주제 세 개를 추가한다.** 모두 VIA를 평상시에 사용하는 장면의 문제다. 장애 복구나 범용 보안 구조에서 후보 수를 채우지 않았다.

| 새 주제 | 사용자가 겪는 핵심 문제 | 방안 A | 방안 B | 주요 기능 품질의 손익 |
| --- | --- | --- | --- | --- |
| F-01 [말과 손짓의 대상 연결](./04-19-temporal-grounding.md) | 창과 포인터가 바뀌는 동안 말한 “이것과 저것”을 각각 맞는 대상에 연결 | 발화 주변의 관측을 모아 요청 시점에 지칭을 해석 | 관측 때부터 객체의 동일성과 지시 관계를 추적하고 그 대상 모델에서 해석 | A는 새로운 모양과 표현을 원자료로 판단하기 좋지만 시점 정합과 반복 분석 부담. B는 반복 지칭과 이동 추적에 유리할 수 있지만 잘못 연결한 객체와 표현 누락이 계속 전파 |
| F-02 [여러 업무의 후속 대화 연결](./04-20-task-dialogue.md) | 질문 여러 개가 도착했을 때 “응”, “그건 취소해”를 다른 업무에 적용하지 않기 | Conversation 전체의 관련 근거에서 이번 발화와 질문/Task를 함께 연결 | 업무별 대화 상태를 유지하고 발화를 해당 대화 범위로 보낸 뒤 해석 | A는 자유로운 주제 이동과 업무 간 지칭에 유리. B는 해당 업무의 긴 문맥을 보존하고 혼입을 줄이기 좋지만 잘못 고른 범위와 잦은 전환에서 불리 |
| F-03 [음성 이해와 응답 연결](./04-21-voice-processing.md) | 부정과 정정을 정확히 이해하고, 끊어 들은 답을 다음 질문에 맞게 연결 | 원음과 음성 응답의 연결을 중심으로 음성 대화 처리 | 확정 전사와 답변 Text를 중심으로 이해와 음성화를 분리 | A는 전사가 놓친 음성 단서를 사용할 수 있지만 의미/출력 근거 통제가 복잡. B는 Text/Voice의 공통 의미를 다루기 쉽지만 전사 오류와 음성 단서 손실이 병목 |

표는 우위의 측정 결과가 아니다. **두 방안이 잘하는 상황과 어려운 상황을 함께 만들 수 있다는 설계 판단**이다. F는 탐색 표식이며 최종 DP 번호나 새 QA ID가 아니다.

## 2. 이번에는 무엇을 바꿨는가

사용자는 기존 target을 기능 전반을 한 번 지원해 본 reference architecture라고 명확히 했다. 이번 두 안은 어느 쪽도 참조 구조일 필요가 없다. 참조 구조의 실제 기능을 허술하게 만들지는 않지만, 그 안의 분해/확정/호출 정책을 모든 대안에 강제하지 않는다.

- **요구 기준:** [고정 범위](../../03-fixed-architecture-scope.md), [UC](../../05-representative-use-cases.md), [02 요구/수단 구분](./02-00-requirements-and-choices.md). VIA가 상호작용과 위임을 맡고 실제 업무 계획/실행은 Agent가 맡는다.
- **공유 조건:** 같은 입력, source/Agent 지원과 현재 권한, 단일 on-device Omni weights, 발화 수신/인식의 지속, 실제 전달 기록을 유지한다. 역할과 Context를 무조건 한 세션으로 합치지 않는다.
- **바꿀 수단:** 언제 어떤 중간 표현을 만들지, 대화 상태를 어떤 단위로 관리할지, 원음과 전사 중 어느 것을 주 의미 입력으로 삼을지, 후속 발화가 거치는 경로를 비교한다.
- **부분 지원:** 없는 모델 capability나 추적 실패를 지원으로 세지 않는다. 질문/재지칭으로 진행을 보완할 수 있지만, 원래 목표를 바로 처리한 것과 같다고 하지 않는다.

## 3. M-2 및 이전 탐색과의 관계

| 자료 | 이번 위치 |
| --- | --- |
| 04-14 M-2 | 사용자가 좋아한 것은 요청 해석 **주제**다. 통합 해석과 단계별 결합이라는 두 안의 실용성은 계속 다듬을 대상이며 승인된 답이 아니다. 이번 F-01/02의 출력이 M-2의 입력이 될 수 있음 |
| 04-15, 04-16 | 복구/권한은 상대적으로 낮은 우선순위의 조건부 후보로 유지. 의미 있는 구조 차이와 QA 손익이 있으면 보고서에 포함할 수 있음 |
| S-02, D-1 | 원래 안은 파생 화면 정보를 기존 최종 해석에 추가하는 구조. F-01 B는 **요청의 대상 연결을 담당하는 경로 자체를 지속 객체 모델로 옮김**. 최종 단계가 항상 전체 원화면을 다시 해석하면 기존 추가형으로 돌아감 |
| 기존 W-1/2 및 C-대화 | 요청 workflow 표현이나 모델 재호출의 일반성은 별도 큰 결정으로 입증되지 않았음. F-02는 **업무별 사용자 대화 상태와 질문 연결 책임**을 비교하며 Agent 내부 workflow나 단순 재호출 횟수를 비교하지 않음 |
| S-05/06, R-2 | 음성 fast path, 인식 helper, chunk 크기의 유무만으로 선발하지 않음. F-03은 **원음 중심의 이해/응답 기록과 Text 중심의 공통 의미 경로**를 비교. ASR 추가/제거 자체는 주요 근거가 아님 |

전형적인 대안이라는 이유로 제외하지 않는다. 반대로 기능 주제가 중요하다는 이유로 모든 두 안의 구조 차이가 충분하다고 확정하지도 않는다. 각 문서 §6에서 작은 확장으로 축소되는 반론과 판정을 남긴다. 이전 제외안 전체를 자동 복권하지 않았다.

## 4. 깊게 다룰 순서와 서로의 의존성

**작성자 제안: M-2와 F-01을 먼저, F-02를 다음, F-03을 그다음으로 구체화한다.** 별도의 QA 순위를 만든 것이 아니라 VIA 특화 기능의 직접성, 기존 주제와의 중복 및 capability 부담에 따른 작업 순서다.

- M-2는 얻은 근거로 목표/대상/업무 관계를 어떻게 해석하는가다. F-01은 그 이전에 **무엇을 화면 대상의 근거로 만들고 유지하는가**다. 단순 전처리로 끝나면 둘을 통합한다.
- F-02는 의미 해석 알고리즘 자체보다 **누가 어떤 업무의 대화 이력과 질문 상태를 가지고 해석에 참여하는가**다. F-01의 객체 ID와 직접 응답의 결과 참조도 업무 대화 사이에 옮겨야 한다.
- F-03은 의미 해석의 주 입력과 응답의 연결 형태를 정한다. 원음 중심 안과 M-2의 발화 분해 단계를 함께 쓰면 음성 단서를 담는 중간 표현이 필요하다. Text만 남기는 단계에 연결한 뒤 원음의 이익을 그대로 주장할 수 없다.

F-03의 원음 입력과 Text 선확정 출력은 함께 사용할 수도 있다. 두 대표 조합의 품질 차이를 각각의 선택과 혼합안으로 분해해야 한다.

이 네 주제가 그대로 네 DP가 된다는 뜻은 아니다. 최종 보고서에서는 겹치는 구조/비용을 합치고, 하나의 기능 이익을 서로 독립적인 근거처럼 중복 계산하지 않아야 한다.

## 5. 어디까지 판단했는가

세 주제의 **정상 기능 중요성, 실제 두 처리안, 주요 장단점과 선택 조건**을 작성했다. 같은 사용자 사건, 정정/권한/장애와 복구, 13개 관점 및 가장 싼 전환 반론을 포함한다. [04-22](./04-22-functional-priority-review.md)에 검토 결과와 구현 가능성의 한계를 모았다.

F-01과 F-02는 VIA에 특화된 다음 심화 주제로 권한다. F-03도 음성 제품의 중요한 전형적 비교로 남기되, 기존 S-05/06과 차별화되는 전체 계약 및 실제 runtime 지원을 가장 엄격히 확인할 후보로 둔다. 세 주제 모두 완성된 제품 설계나 측정된 승자가 아니다. 지금 읽고 있는 [04-13](./04-13-broad-mechanism-discovery.md)과 [04-17](./04-17-broad-mechanism-review.md)의 기존 분석은 보존한다.
