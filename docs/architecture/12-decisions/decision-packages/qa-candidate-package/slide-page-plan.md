# QA별 한 장 설명 페이지 구성안

> **후속 평가 구성 정정:** QA별로 따로 정한 사례 수는 [공통 시나리오 구성 방안](./common-evaluation-population-plan.md)에 따라 통합할 초안이다. 20요청과 Agent 사건 6건은 독립 시나리오 26개가 아니다. 공통 N과 QA별 관측 건수 확정 전이며 기존 $0.71 견적은 이전 20요청 활동에만 적용된다.

> 2026-10-14 / 발표 제작에 넘길 Markdown 원고와 자료 위치 / 슬라이드 파일 미제작
> 목표와 점수 및 DP 우열은 사용자 검토용 제안이다. 예시 수치는 가상값이며 PoC 결과가 아니다. 현재 후보 명세를 반영한다. QA06은 목표와 점수 근거가 미완료이므로 확정 발표 페이지가 아니다.

[조사 상세 기록](./research-notes/README.md)에 출처별 사실과 적용 판단 및 채택하지 않은 근거를 보존했다. 이 문서는 그 자료에서 **한 장에 보여줄 내용과 발표자 노트에 남길 내용**을 골라 놓은 구성안이다. 전체 QA를 한눈에 비교하는 [품질 요구사항 표](./quality-requirements-table.md#presentation-table)와 구별해 사용한다.

## 공통 구성

| 영역 | 한 장에 넣을 내용 | 원고 편집 규칙 |
| --- | --- | --- |
| 상단 | QA 이름과 사용자 또는 제품이 얻는 가치 한 문장 | 이름만으로 모호한 경계는 정의에서 즉시 명시 |
| 왼쪽 위 | 정의와 단일 지표 및 목표 숫자 | 평균과 최대 및 분모와 단위 생략 금지 |
| 오른쪽 위 | 왜 그 숫자인지 짧은 도출 논리와 1~2개 주요 출처 | 문헌의 원값과 VIA의 제품 판단을 구별 |
| 가운데 | 측정 시작과 종료 또는 집계 방식을 보여주는 예시 | 실제 측정 전에는 반드시 ‘설명용 예시’ 표기 |
| 하단 | 0~6점 원형 구간과 대표 DP의 한 문장 설명 | 현재 상세안의 점수표 사용. 예상 우열을 실측으로 표시하지 않음 |
| 각주 | 출처와 확인일 및 핵심 적용 조건 | 긴 연구 조건과 반대 자료 및 예상 질문은 발표자 노트로 이동 |

원형 표시는 `0 ○○○ / 1 ◐○○ / 2 ●○○ / 3 ●◐○ / 4 ●●○ / 5 ●●◐ / 6 ●●●`이다. 합격 목표와 점수표의 중간 경계는 별개다. 외부 연구가 모든 점수 간격을 정한 것처럼 표현하지 않는다. 미측정은 0점이 아니며 필수 기능 실패와 관측 누락은 각 QA의 실패 규칙을 따른다.

QA01~06은 최근 목표 근거를 다시 조사한 핵심 후보이고 QA07~09는 기존 추가 후보와 회귀 검증이다. 후자의 목표는 설계 예산 제안이므로 외부 수치 검증이 끝난 것처럼 통일하지 않는다. 실제 핵심 QA 채택 수는 별도 결정한다.

## QA01 첫 응답 지연시간

| 페이지 요소 | 넣을 문안과 자료 |
| --- | --- |
| 가치 한 문장 | **사용자가 말을 마친 뒤 이해된 내용을 빠르게 확인하고 대화를 이어가게 한다.** |
| 정의 | 입력 사건부터 해당 Request/Task UI에 요청을 반영한 첫 완결된 정답 내용이 실제 표시될 때까지의 시간 |
| 단일 지표와 목표 | **고정 시험의 최대 첫 응답 지연시간 ≤ 1초** |
| 목표 근거 | Nielsen의 사고 흐름 유지 약 1초와 Microsoft의 Windows 응답성 유지 구간 0.5~1초를 적용 |
| 측정 조건 | 30개 사건 × 3회. 실제 발화 종료 / 텍스트 제출 / Agent source 사건부터 실제 내용 표시까지. 인사와 spinner 및 첫 토큰 제외 |
| 설명 그림 | `발화 끝 0.0 → “네” 0.1 → 구체적 수행 안내 0.8 → Agent 전송 1.3 → 음성 재생 2.5초`. 이 사건의 값은 **0.8초** |
| 채점 예시 | 가상 4건이 0.8 / 0.6 / 1.0 / 0.8초라면 최대 1.0초로 **1점 ◐○○**. 실제 모집단은 90건 |
| DP 한 문장 | **DP-44 B는 앞 단계 완료에서 다음 처리를 직접 시작해 중앙 진행 경로를 거치는 대기를 줄일 수 있다.** 현재 차이는 약한 가설 |
| 주요 각주 | Nielsen 1993 / Microsoft Windows responsiveness. UI 지침을 VIA 첫 내용 표시에 적용한 목표 제안 |

**발표자 노트:** 위임 전에 대상과 수행 범위를 실제 채택했다면 “비교하겠습니다”도 유효하다. 완료하지 않은 동작을 완료했다고 안내하면 인정하지 않는다. 사용자나 기존 음성이 출력 중인 경우를 고려해 실제 음성 시작은 QA09에서 다룬다. 1초를 모든 음성 대화의 만족 임계로 일반화하지 않는다. 최대값은 고정 시험의 최댓값이며 모든 미래 요청의 최악 시간 보장이 아니다.

**자료:** [정의와 점수표](./qa01-first-response-latency.md) / [원문 조사와 반대 방향 연구 및 심사 답변](./research-notes/qa01-latency-research.md). 질문 시 Miller의 추정 성격과 VR 54명 연구의 조건 및 지연을 신중함으로 해석한 2026 연구도 확인할 수 있다.

## QA02 지칭 대상 식별 정확도

| 페이지 요소 | 넣을 문안과 자료 |
| --- | --- |
| 가치 한 문장 | **사용자가 가리키거나 다시 언급한 대상을 정확히 골라 재설명과 오작업을 줄인다.** |
| 정의 | 사용자가 지칭한 대상의 원본과 범위 및 필요한 revision을 빠짐과 추가 없이 올바르게 지정하는 정도 |
| 단일 지표와 목표 | **지칭 대상 집합 일치율 ≥ 93%** |
| 목표 근거 | Apple ReALM-3B의 화면 지칭 집합 완전 일치율 93.0%를 관련 기술 참조로 채택 |
| 측정 조건 | DP별 20개 사례 × 5회. 정답 대상 집합 전체가 같아야 성공. 부분 정답과 추가 대상 및 잘못된 revision은 실패 |
| 설명 그림 | 정답 `{매출표 A, 비용 그래프 B}`에 `{A,B}`는 성공. `{A}`와 `{A,B,C}`는 실패 |
| 채점 예시 | 100회 중 93회 전체 집합 일치 → **93% → 1점 ◐○○**. 99회면 5점이며 100회면 6점 |
| DP 한 문장 | **DP-47과 DP-45는 현재 화면과 과거 자료에서 같은 대상 집합을 고르는 문제를 다루므로 같은 성공 판정을 적용한다.** 공통 적용 자체는 양안 차이의 증거가 아님 |
| 주요 각주 | ReALM, SIGDIAL 2024 §3 및 Table 3. 후보 항목이 주어지는 연구이며 VIA의 증거 수집과 포인터 및 정정까지 검증한 것은 아님 |

**발표자 노트:** 화면과 대화의 지칭을 해석하고 전체 대상 집합이 같아야 성공이라는 공통점을 먼저 설명한다. 단 ReALM은 질의별 집합이고 VIA는 표현별 집합과 revision이므로 평가 단위와 처리 범위는 다르다. 화면 최고 성능 93.0%를 두 DP의 기술 참조 최소 목표로 선택했다. ReALM의 대화 97.9%와 평균내지 않는다. 후보 수집과 과거 원본 검색 및 범위와 버전의 처리가 VIA에서는 더 넓으므로 관련 연구의 성능을 적용한 요구이지 동일 시험의 비열등성 증거가 아니다. 마우스 연구와 근거 없는 downstream 복구율은 사용하지 않는다.

**자료:** [정의와 점수 및 DP 예상](./qa02-referent-accuracy.md) / [연구 과제 조건과 통계 한계 및 잘못된 복구 산식](./research-notes/qa02-accuracy-research.md).

## QA03 VIA 처리시간

| 페이지 요소 | 넣을 문안과 자료 |
| --- | --- |
| 가치 한 문장 | **첫 안내 이후에도 VIA 자체 처리 때문에 사용자의 요청이 오래 지연되지 않게 한다.** |
| 정의 | 고정된 사용자 목표의 완료 경로에서 외부 Agent 업무와 사용자 대기를 제외하고 VIA에 귀속하는 시간 |
| 단일 지표와 목표 | **고정 시험의 최대 VIA 귀속 처리시간 ≤ 5초** |
| 목표 근거 | Microsoft Windows의 Long wait 상단 5초를 VIA 자체 처리의 제품 상한으로 채택 |
| 측정 조건 | 12개 목표 × 5회. 상태와 필수 텍스트 및 전체 음성 요약 데이터 준비까지. 실행 의존관계와 자원 경합을 보존한 DAG로 귀속시간 계산 |
| 설명 그림 | 실제 경로 `1.2 + max(Agent 8, VIA 3) + 0.6 = 9.8초`. 외부 작업 길이만 0으로 두면 `1.2 + max(0,3) + 0.6 = 4.8초` |
| 채점 예시 | 위 사건이 고정 시험의 최대값이라면 **4.8초 → 1점 ◐○○**. `9.8−8=1.8초`로 계산하지 않음 |
| DP 한 문장 | **DP-42 A는 관련 로컬 상태를 함께 확정하므로 독립 서비스의 확인과 전달을 기다리는 경로가 짧다.** 실측 전 구조 가설 |
| 주요 각주 | Microsoft Windows responsiveness. 5초는 VIA 자체 처리에 적용한 요구이며 Agent 업무 전체 완료의 보장 시간이 아님 |

**발표자 노트:** 5초를 내부 단계별로 나눈 것은 원래 목표의 이유가 될 수 없다. 여기서는 외부 UI 지침의 경계를 먼저 채택한다. 외부 작업을 0으로 둔 DAG는 계약상의 귀속시간이고 VIA를 제거한 제품과 비교한 인과적 추가 지연은 아니다. 실제 경과시간도 함께 보존한다. Cloud 모델과 VIA가 사용하는 네트워크는 VIA 시간이며 음성 재생 차례 대기는 별도다.

**자료:** [DAG 계산과 완료 조건 및 점수표](./qa03-via-processing-time.md) / [Windows 분류와 채택 논리 및 잘못된 차감 예시](./research-notes/qa03-duration-research.md).

## QA04 변경 범위

| 페이지 요소 | 넣을 문안과 자료 |
| --- | --- |
| 가치 한 문장 | **기능을 바꿀 때 여러 개발자의 코드와 담당 영역까지 수정이 퍼지는 부담을 줄인다.** |
| 정의 | 같은 변경 과제를 완료하기 위해 실제로 수정하는 운영 Rust 모듈의 범위 |
| 단일 지표와 목표 | **변경 과제당 평균 변경 운영 Rust 모듈 수 ≤ 3개** |
| 목표 근거 | ARGO 기능 추가와 형식 변경 PR 145건의 평균 5.4개 × 60% = 3.24개에서 3개로 강화 |
| 측정 조건 | 독립 변경 C01~06을 같은 기준 코드에서 각각 수행. `package / crate target / fully qualified mod path`의 고유 수 집계 |
| 설명 그림 | 기능 책임 상자 대신 실제 `mod` 트리에서 수정된 노드를 표시. inline 모듈과 외부 파일 모듈 모두 동일 기준 |
| 채점 예시 | 6과제의 변경 수 `2,2,3,4,3,4` → 18/6 = **3개 → 1점 ◐○○** |
| DP 한 문장 | **DP-45 A는 필요한 과거 관계를 조회할 때 구성하므로 새 관계를 추가할 때 생산과 저장 및 재게시 계약까지 바꿀 필요가 적다.** 실제 diff 확인 전 가설 |
| 주요 각주 | 사용자 제공 ARGO 내부 집계. 40% 개선은 사용자 요구이며 3개 달성 시 제시된 평균 대비 약 44.4% 감소. 원본 PR 감사 전 |

**발표자 노트:** 파일 수와 module 수는 다르다. prompt와 schema 및 설정 변경도 담당 운영 모듈에 귀속하고 테스트 전용 변경은 제외한다. 부모 모듈은 실제 수정됐을 때만 센다. AI 코딩 병행 수정의 부담은 사용자 경험에서 나온 요구이고 모듈 수는 변경 파급의 구조 지표다. 이 값만으로 전체 개발시간이나 충돌 건수를 증명하지 않는다. “형식 변경은 1개와 기능 확장은 5개”라는 이전 가정은 사용하지 않는다.

## QA05 모델 사용 비용

| 페이지 요소 | 넣을 문안과 자료 |
| --- | --- |
| 가치 한 문장 | **같은 사용자 활동을 범용 API 구성보다 큰 모델 원가 없이 제공한다.** |
| 정의 | 정의한 20요청 활동을 처리하는 동안 VIA의 음성과 의미 모델에 청구되는 총금액 |
| 단일 지표와 목표 | **20요청 활동당 평균 총 모델 비용 ≤ $0.71** |
| 목표 근거 | gpt-realtime 음성 처리와 Luna 화면 및 문맥 처리의 참조 견적 $0.7067을 센트 단위로 올림 |
| 측정 조건 | COST-20-v3 동일 활동 5회. 초기 준비와 재사용 및 갱신과 폐기 및 마지막 청구까지 포함 |
| 설명 그림 | Realtime $0.4936 + Luna $0.2131 = **$0.7067 → 목표 $0.71** |
| 채점 예시 | 각 활동의 준비 $0.02 + 요청 $0.12 + 음성 $0.32 + 갱신과 재시도 $0.04 = $0.50. 5회 모두 같으면 **평균 $0.50 → 3점 ●◐○** |
| DP 한 문장 | **DP-47 A는 필요한 원본을 한 판단 경로에서 처리하므로 후보별 생산과 결합의 추가 모델 사용을 줄일 수 있다.** code producer와 cache를 허용한 상태에서 확인 |
| 주요 각주 | 2026-10-14 gpt-realtime과 GPT-5.6 Luna 공개 요금. 미실행 참조 견적이며 기능 동등성 확인 전 |

**발표자 노트:** 월 $20와 20근무일 및 하루 40요청 가정은 폐기했다. 20요청은 비교용 활동 단위이고 20,000입력과 500총 청구 출력은 견적 규격이다. 실제 후보의 호출 수와 출력량을 강제하지 않는다. 추론과 음성 및 cache의 실제 청구 bucket을 사용한다. 가격은 확보했지만 필요한 정보를 담은 payload와 기능 달성을 검증하지 않았다.

**발표자 추가 노트:** Realtime 46개 Response는 매번 명시적 입력을 지정한다. 원본 맥락은 Luna에 제공한다. 음성은 120초 입력과 130초 출력으로 견적을 냈고 음성과 함께 생성되는 텍스트도 포함한다. 음성 토큰 환산은 근사치이며 실제 청구는 provider usage로 확인한다.

## QA08 병행 수정 중복

| 페이지 요소 | 넣을 문안과 자료 |

| 지위와 가치 | **추가 후보. 개발자들이 독립 변경을 수행할 때 겹쳐 수정하는 영역을 줄인다.** |

| 목표 근거 상태 | 공통 조정 영역을 한 곳 이내로 관리하려는 기존 협업 예산. 실제 팀 합의나 업계 표준 수치 아님 |

## QA09 음성 전달 지연

| 페이지 요소 | 넣을 문안과 자료 |
| --- | --- |
| 지위와 가치 | **필수 회귀 검증. 첫 텍스트가 보인 뒤 사용자가 들을 수 있는 요약 음성을 오래 미루지 않게 한다.** |
| 정의와 단일 지표 | 응답 내용 채택 후 재생 가능한 구간에서 실제 요약 음성이 시작될 때까지의 누적 시간 평균 |
| 목표 제안 | **평균 음성 전달 지연 ≤ 500ms** |
| 목표 근거 상태 | 요약 200ms + 첫 음성 준비 200ms + 출력 100ms의 기존 설계 예산. 자연스러운 대화의 보편적 임계값 아님 |
| 측정 조건 | 6사례 × 20회. 사용자나 앞선 음성 때문에 말할 수 없는 구간 제외. 생성과 출력 경로에서 발생한 대기는 포함 |
| 설명 그림 | `내용 채택 0.7 → 텍스트 0.8 → 사용자 발화 종료 2.0 → 음성 시작 2.3초`. 0.7~2.0이 차단됐다면 재생 가능 대기는 **300ms** |
| 채점 예시 | 모든 사례의 평균 재생 가능 대기가 300ms라면 **3점 ●◐○**. 사건이 0초였다면 실제 전체 청취 대기 2.3초도 보존 |
| DP 한 문장 | **현재 DP의 양안은 같은 음성 출력 경계를 사용할 수 있으므로 필수 검증으로 유지하고 차이 축을 억지로 만들지 않는다.** |
| 주요 각주 | Microsoft 저지연 오디오와 loopback 문서 / 저장소의 실제 사건 경계 계약 |

**발표자 노트:** 첫 음성 데이터 준비와 실제 장치 출력은 다르다. WASAPI loopback만 관측하면 software proxy이고 실제 audible endpoint에는 보정한 acoustic 또는 analog 관측이 필요하다. 재생 가능한 누적 5초까지 필수 음성이 없으면 실패 판정을 남긴다. 실패를 분모에서 빼거나 빠른 사례와 평균내 숨기지 않는다.

**자료:** [재생 가능 시간의 정의와 점수 및 실제 출력 관측](./qa09-audio-delivery-lag.md). 음성 전달 예산의 외부 수치 보강은 이번 핵심 여섯 QA 조사 범위에 포함되지 않았다.

## 실제 발표 제작 때 가져올 파일

1. **이 문서:** 각 페이지의 문안과 설명 그림 구도 및 발표자 노트.
2. **각 QA 상세안:** 최신 정의와 점수 구간 및 실패 규칙. 목표를 바꾸면 먼저 이 기준을 개정한다.
3. **[조사 상세 기록](./research-notes/README.md):** 출처와 원문 조건 및 채택 논리와 반대 자료.
4. **[QA와 DP 대응표](./README.md#4-qadp-대응과-예상-우열):** 최신 예상 우열. 개별 카드의 한 문장이 전체 커버리지 표를 대체하지 않는다.
5. **[검토와 보완 기록](./review-and-revision-log.md):** 실제 반영한 리뷰와 아직 확인하지 않은 실행 범위.

발표의 짧은 본문과 상세 근거를 연결하되 원문 조건을 지워 더 강한 주장으로 바꾸지 않는다. 현재 수치의 제안 상태와 실측 부재도 유지한다.
