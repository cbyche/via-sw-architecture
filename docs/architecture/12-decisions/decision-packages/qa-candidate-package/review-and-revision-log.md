# QA 후보 패키지 검토와 보완 기록

> 2026-10-14 / 문서 검토 완료 / 사용자 검토본 / 구현·모델 호출·Windows 측정 없음

## 1. 완료한 범위

- 기존 여섯 QA와 추가 세 후보에 정의, 단일 지표, 경계와 실패 처리, 구체적 목표와 도출 근거, 0~6점, 가상 예시, DP별 예상 한 문장, 최소 PoC와 발표 한 장 문안을 작성했다.
- 작성 에이전트와 별개의 **독립 검토 에이전트 세 명**이 측정, Architecture 관계, 변경·자원·채점의 관점으로 검토했다. 인간 전문가 심사나 외부 기관 인증을 받았다는 의미는 아니다.
- 독립 검토의 중복을 제거하면 **P2 8건**을 발견했고 모두 수정 후 재확인했다. QA07의 비선형 집계 단위도 추가로 명확히 했다. 검토 범위에서 미해결 P1/P2는 없다.
- 측정 리뷰는 3차까지, 구조와 자원 리뷰는 각각 2차까지 진행했다. QA1은 전체 재독 후 실제 관측 오차의 추가 결함을 발견해 다시 수정했다.

**완료하지 않은 것은 문서 결함과 구별한다.** 목표의 제품 승인, 모델 달성 가능성, 실제 Rust 변경 수, Windows 계측 정확성, DP별 성능 차이와 핵심 구성의 최종 선정은 후속 단계다. 문서 리뷰가 이 사실을 대신 입증하지 않는다.

추가 보완: QA07은 **4사례×3겹침 시점의 12개 cell**, 각 cell의 조건별20회 평균 차이, 0 하한 적용, 12개 균등 평균 순서로 고정했다. 이는 비선형 집계 순서에 따라 값이 달라지는 해석을 막는다. 자원 2차에서 확인했다.

최종 편집에서 QA03에 원래 DAG의 실제 완료 시각 재구성 검사와 streaming 재생 허용을 명시하고 “실제 대기에 더한 인과 효과”와 처리 경로 시간을 구별했다. QA05 예시의 $0.21을 “첫 응답 전 비용” 대신 “20요청의 의미 처리 비용”으로 고쳤다. 이 두 명료화는 통합 작성자가 검토했으며 별도 제품 시험 결과가 아니다.

## 4. 자체 검수와 정적 검사

```text
python3 scripts/architecture/check_qa_candidate_package.py
git diff --check
```

점수 검사는 9개 QA의 실제 Markdown 점수표에서 구간을 읽어 **237개 검증점**의 중복·공백·단조성·원형 표시를 확인한다. 정확도는 0~100%, 다른 수치는 비음수의 유한 영역으로 제한한다. 예시의 주요 산술과 패키지의 로컬 파일 링크도 검사한다. 별도로 현재 문서의 로컬 heading anchor를 대조했다.

이 검사는 QA 구현이나 PoC가 아니다. `+∞`·계측 실패·기능 자격 판정은 본문과 독립 리뷰에서 확인했으며 자동 validator가 전부 실행하는 규칙인 것처럼 말하지 않는다. 외부 URL의 현재 접근성, 숫자의 제품 적합성, 실제 대안 우세나 모델 동작을 검사하지 않는다.

## 5. 리뷰로 바뀐 구성 판단

- 지칭 집합 정확도를 47·45에 같이 적용하는 **측정 의미는 타당**하다. 강한 대안이 둘 다 정답에 도달할 수 있으면 정확도 차이는 별도 입증이 필요하다.
- 47의 B가 원본·경쟁 후보·확장 경로를 갖고 A도 부분 정정을 할 수 있으므로 정확도 우세를 구조 이름으로 정하지 않았다.
- 44의 단계 직접 연결이 짧은 async dispatcher보다 체감 수준으로 빠를지는 약한 가설이다. QA1과 QA3를 합산해 같은 이익을 두 번 크게 만들지 않는다.
- 42의 업무 접수 왕복은 위임 전 첫 안내 뒤에 올 수 있으므로 QA1의 자동 손해로 세지 않았다.
- 추가 07·08·09도 현재 네 DP의 빈칸을 메우는 확정 핵심 QA로 승격하지 않았다.

**최종 전달 상태:** QA 후보의 상세 문서와 독립 검토·보완 완료. 목표·점수·모집단은 사용자 검토용 제안. QA–DP 최종 구성 조건은 아직 미충족. 구현·실측·최종안 선정으로 이어가기 전에 강한 대안의 실제 손익을 보강해야 한다.
