# DP-44 / 47 / 45 / 42의 QA 대응과 수치 사고 실험

> **QA-DP-THOUGHT-v1-20261015 / AUTHOR_THOUGHT_EXPERIMENT_NOT_MEASURED**
> 발표자료의 설계와 trade-off 원천 자료다. **4개 DP × 2개 대안 × 9개 QA = 72개 숫자와 72개 점수**를 만든다. PoC, 모델 호출, Windows 실험, 제품 성능 측정은 수행하지 않았다. 숫자는 작성자가 정한 하나의 예상값이며 실제 관측이나 대안 선정 결과가 아니다.

## 1. 읽는 순서와 사용 규칙

1. 이 문서: 비교 구조, 전체 값과 점수, 각 QA에서 예상한 우열과 이유.
2. [계산 원장](./thought-experiment/calculation-ledger.md): 28개 시나리오별 시간, 예상 오답, 변경 모듈 집합과 교집합, 비용 / RAM / 부하 구성.
3. [가정 JSON](./thought-experiment/assumptions.json): 수정 가능한 단일 수치 가정. [예측 JSON](./thought-experiment/predictions.json): 120개 사건과 76개 목표의 경로 계산 및 72개 결과. 발표 차트는 이 JSON의 summary를 사용한다.
4. [공통 입력](./common-scenarios.md)과 [QA 상세 목록](./README.md): 모집단과 배점의 기준. [계산기](../../../../../scripts/architecture/qa_dp_thought_experiment.py)는 문서 산술 검산 도구이며 실행기나 PoC가 아니다.

**사용자 정정:** QA01 첫 응답과 QA03 VIA 처리시간은 산술평균이다. **오답이어도 실제 표시 / 처리 종료까지의 시간을 그대로 사용**한다. 정답을 기다리는 시간, 무한대, timeout 대체 시간, 실패 강제 0점은 사용하지 않는다. 정확도는 QA02에 별도로 기록한다. 다른 QA에서도 이 사고 실험은 원값을 해당 수치 구간에만 대입하며 기능 실패 벌점으로 수치를 조작하지 않는다. 실제 종료점이 없는 경우 시간을 꾸며낼 수는 없으므로 미관측으로 남겨야 하나 이번 점추정은 전 사건의 표시와 처리 종료가 있다고 가정한다.

내용 없는 인사와 spinner는 첫 응답에서 제외한다. 목표 1초 / 5초와 기존 숫자 배점은 유지하고 집계 의미를 QA-C01/C03-v3로 개정했다. [직전 최대값 제안](../../../../archive/qa-timing-before-mean-correction-20261015/README.md)은 보존했다. QA09도 채택 이후 실제 음성 전달의 원값을 예상하며 잘못된 내용의 전달에 시간 벌점을 넣지 않는다. 기존 음성 기능 검증의 통과를 의미하지 않는다.

각 비교에서 **다른 세 DP는 A로 고정**한다. 따라서 네 A 열이 같다. 이는 분석의 통제 조건이며 A가 선택됐거나 모든 A의 조합이 기존 참조 Architecture라는 뜻이 아니다. B 네 개의 개선량을 더해 전체 B 제품 값을 만들 수 없다. 메모리와 호출 및 경합의 상호작용은 별도 검토가 필요하다.

## 3. 같은 입력을 두 구조에 통과시키는 가정

**입력과 준비.** COMMON-28-v1의 120개 응답 사건, 76개 목표, 44개 지칭, 109개 음성 요약을 각각 5회 반복한 기대값이다. 같은 사건의 기대값을 5회 적용하며 난수나 가짜 실행 로그를 만들지 않는다. 각 S는 원본 200턴, 완료 Task 20개, 최대 진행 Task 5개로 시작한다. 초기 준비부터 계상하고 5초에 첫 입력을 시작한다. B의 파생 결과를 무료로 주지 않는다. 원본은 모두 동일하고 채택 이전 내부 재판단 비용도 포함한다.

**시간 예산.** 입력 종료 판단과 전사는 Voice 180ms, Text 15ms, Agent source 전달 20ms로 가정한다. 원본 읽기 30~180ms, 첫 내용까지 의미 모델 경로 350~820ms는 profile별 단일 상수다. 공통 scheduler 20ms, 연결 처리 20ms, 채택 30ms, UI 실제 표시 40ms를 더한다. 과거 자료의 유효 cache 8건은 170ms를 줄이고 어려운 6건의 bounded 재판단은 450ms를 추가한다. 의미 모델 동시 세션 한도 4개와 음성 한도 2개를 양안에 똑같이 둔다. 이 상수들은 문헌이나 실측에서 가져온 제품 성능이 아니라 현재 구조를 설명하기 위한 예산 가정이다. 입력량과 모델 속도가 달라지면 그대로 유지할 수 없다.

**전체 처리시간.** 첫 내용 뒤 상세 Text 완성 tail과 streaming 음성 전체 준비의 늦은 쪽을 사용한다. 요약은 채택한 짧은 내용을 바탕으로 상세 출력과 병행 생성하므로 첫 음성 300ms와 전체 음성 준비 900ms를 구별한다. 같은 목표의 사용자 후속 입력은 앞 처리와 직렬, 독립 Agent 결과는 병렬, 결과를 쓰는 다음 명령은 의존 edge를 둔다. Agent 도메인 업무와 사용자 발화 / 기다림 / 준비된 음성 재생만 0으로 둔다. 로컬 연동 100ms는 남긴다. 실제 trace 대신 **예상 의존 그래프**를 JSON에 기록한 것이므로 향후 구현의 자원 edge와 검증해야 한다.

S17-G01의 독립 두 업무는 max 경로이고 G02~04는 결과 의존을 따라 누적한다. S08 정정 전 응답은 첫 내용 이후 460ms 시점에 중단되는 가정으로 미생성 나머지를 요구하지 않는다. S24-G01에는 중간 상태 질문 U02의 실제 의존도 넣는다. 다른 목표라고 그 사이 발생한 처리 원인을 제거하지 않는다. 각 목표 내부에서는 가장 긴 경로를 쓰지만 **QA03 대표값은 380개 목표의 평균**이다.

**정확도.** 220개 중 공통 5개 오답을 가정한다. 47B는 개선되는 오류와 새로 생기는 후보 결합 오류를 하나씩 교환해 동점, 45B는 게시 관계 의미 오류 한 건을 추가한다. 내부에서 거절한 후보는 채택 오류로 세지 않으며 앞선 오답을 정정했다고 QA02에서 없애지 않는다. 정밀 확률 모델이 아니므로 예상 오류 위치를 공개한 정수 근사다.

**모델 원가.** 가격은 저장소의 2026-10-14 snapshot이다. Realtime 음성 입력 481초 / 생성 545초 / 190호출은 공통 견적과 같다. 의미 모델의 기대 출력은 참조 예산의 1/4로 가정한다. 참조 예산은 실제 출력량이 아니며 reasoning을 빼는 방법으로 비용을 낮추지 않는다. A에도 여섯 bounded 재판단 호출을 넣는다. B47은 native / 재사용 producer가 모델을 호출하지 않는 경우, 작은 binding, 원본 후보 확장을 각각 센다. B45는 S마다 14,000입력 + 200출력의 두 초기 호출과 8회 갱신을 센다. 원본 24,000토큰 수준을 두 구간으로 읽고 게시하는 초기 처리 경로는 5초 안에 끝난다고 가정한다. 입력 이후 새 의미 관계 생산은 지연에도 남긴다. 그 준비가 5초를 넘으면 B45 시간 이익은 줄어든다.

**RAM.** UI와 공용 runtime 및 Core/DB, audio/network, 화면 / 이력 cache를 같은 순간에 더한다. 화면 buffer는 15장의 전체 RGBA를 무조건 상주시킨 값이 아니라 해독 frame과 압축 cache 및 crop을 제한해 둔 가정이다. 양안 모두 shared reference와 disk를 허용한다. B마다 새로 소유하는 자료나 process의 동시 resident 부분만 가산하며 클라우드 가중치는 넣지 않는다. 최고점은 S08이다. 512 MB 요구를 만족하는 추정이지 실제 메모리 달성 증거는 아니다.

**변경과 협업.** 실제 Rust 구현이 없는 단계이므로 QA04/08은 DESIGN_CHANGE_REVIEW다. 공통 package / crate / module 기준을 고정하고 C01~C06의 변경 집합에서 QA08의 여섯 교집합을 산출한다. 결과가 좋아지도록 과제마다 모듈 경계를 바꾸지 않는다. 이미 있는 source IDs, revisions, bounded query, 부분 정정은 유지한다. 평가 변경은 새 public 표시와 부분 허용 범위의 처리 확장이다. 실제 구조가 그 기능을 이미 완전히 제공하면 해당 변경 수는 0으로 다시 계산해야 한다.

## 6. 발표에서 주장할 수 있는 범위

이 원장은 **조건을 공개한 수치 가설**이다. 수치상 빠르다는 판단, 배점 차이, 실용적으로 중요한 차이, 실제 측정으로 확인한 차이는 구별한다. 이번에는 마지막 단계의 증거가 없다. QA01의 기존 실용 구분 제안 100ms와 QA03의 0.5초를 전체 평균에 대입하면 네 비교 모두 시간 차이가 작다. 특히 47의 QA01 점수 차이만으로 중요한 latency 이익을 주장할 수 없다.

현재 가정에서 45는 B의 시간 단축 방향과 A의 생산비 / RAM / 변경 범위 이점이 드러난다. 44는 아주 작은 연결 지연 감소와 join 변경 비용, 47은 단계 의존과 후보 재사용의 상쇄, 42는 독립 상태 운영 비용이 핵심 설명이다. **네 DP가 각각 3~4개의 큰 정상 사용 QA 차이를 갖는다는 과정 선정 요건을 이 숫자만으로 충족했다고 할 수 없다.** 동점 항목이나 약한 예측을 승리로 세지 않았다. 배점을 바꾸어 행렬을 채우지 않는다.

본 표의 점수는 모두 예상 점수다. 예측이 틀릴 조건을 함께 제시하고 실제 결과가 생기면 새 판본으로 병기한다. 현재 수치나 과거 측정 기록을 덮어써 맞춘 결과로 바꾸지 않는다.

## 7. 재계산과 검산

저장소 루트에서 .venv/bin/python scripts/architecture/qa_dp_thought_experiment.py --check 및 .venv/bin/python scripts/architecture/check_qa_candidate_package.py를 실행한다. 이 작업은 문서 산술 검사다.

가정을 바꾸면 assumptions.json에 이유와 판본을 기록하고 --write로 계산 원장과 이 문서의 표를 함께 갱신한다. DP별 문안 원본은 rationale.json이며 숫자를 직접 인용한 본문 문장도 재확인한다. 입력 / QA 문서의 SHA-256을 JSON에 넣어 배점과 정의를 추적한다. 계산기는 72개 원값과 점수, 공통 건수, 모듈 교집합, 토큰 비용, 동시 RAM, 부하 짝만 검산한다. 모델 성능, 시간 상수의 타당성, 실제 모듈 수정 수, Windows 측정 정확도나 독립 검토 완료를 입증하지 않는다.
