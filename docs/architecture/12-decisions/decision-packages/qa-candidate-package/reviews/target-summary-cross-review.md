## 2. 최초 판정

**P1 없음. P2 1건.** 숫자 자체와 대표 통계는 문서 간에 일치한다. 비용 견적 요약에서 추론 토큰의 청구 범위가 생략된 부분은 보완해야 한다.

### SUM-01 — P2: 비용 견적 요약에도 추론을 포함한 총 청구 출력 500토큰 조건을 표시

- **위치:** `target-rationale.md` §6의 참조 견적 규격 문장과 견적표의 `텍스트 출력` 행. 검토 당시 85행과 91행.
- **현재 표현:** 회당 `출력 500토큰`과 `텍스트 출력 26 × 500토큰 × $1.20/100만 토큰`.
- **문제:** QA05 상세안은 500토큰을 추론 토큰까지 포함한 전체 청구 출력량으로 정의한다. 그러나 독립적으로 읽는 목표 근거 요약은 사용자에게 보이는 텍스트 500토큰으로 해석될 수 있다. 그 해석에서 별도의 추론이 발생하면 $0.0156과 총 $0.4631은 해당 구성의 총비용이 아니다. 사용자에게 보여줄 상세 텍스트 500토큰을 보장하는 것과 총 청구 출력 500토큰의 견적은 다른 조건이다.
- **최소 수정:** 규격을 `추론을 포함한 총 청구 출력 500토큰`으로 적고 표 행을 `총 청구 출력(추론 포함)`으로 바꾼다. 500토큰 안에서 필요한 결과를 제공할 수 있는지 실측 전이라는 기존 제한도 유지한다. QA05 상세안의 규격 표에도 같은 표현을 사용하면 표만 따로 읽을 때의 모호함이 줄어든다.
- **영향:** 견적 금액을 바꾸라는 요구가 아니다. $0.47의 성립 조건을 요약에서도 정확히 전달하려는 수정이다. 단순 오탈자보다 중요하지만 모델 호출이나 새 구현이 필요하지 않은 문서 수정이다.
- **최초 상태:** 작성자에게 전달함. 수정 후 재검토 전.

## 4. 비용 수치와 공개 자료 확인

2026-10-14에 [GPT-Live 1](https://developers.openai.com/api/docs/models/gpt-live-1), [GPT-5.6 Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna), [이미지 토큰 계산](https://developers.openai.com/api/docs/guides/images-vision)을 별도로 조회했다.

- 음성 세션 $0.05/분과 백엔드 별도 청구를 확인했다.
- 텍스트 입력 $0.20/100만 토큰과 출력 $1.20/100만 토큰 및 cache-write 1.25배를 확인했다.
- 해당 모델의 `high` 이미지 2,500패치 상한과 배율 1.2를 확인했다.
- 산식 `0.2500 + 0.1300 + 0.0156 + 0.0675 = 0.4631`을 독립 계산했다.

모든 입력에 높은 쓰기 단가를 적용한 참조 견적이며 사용량을 중복 청구하는 식은 아니다. 후보 구조의 실제 호출 수를 26회로 제한하거나 5분이 지나면 원장을 닫지 않는다는 규칙도 확인했다. payload와 WAV 및 필요한 출력의 실현 가능성은 아직 검증 전이며 이번 검토가 이를 검증한 것은 아니다.

## 5. RAM 참조의 해석 확인

[PowerToys PR #40551](https://github.com/microsoft/PowerToys/pull/40551)에서 시작 피크 5개 원값과 최고 171.0MB를 확인했다. [Vosk 공식 모델 안내](https://alphacephei.com/vosk/models)의 소형 모델 실행 메모리 약 300Mb를 확인했다. 원문은 `Mb`를 사용하며 엄밀한 단위가 확인되지 않았다는 상세안의 제한을 유지해야 한다. [Orca 벤치마크](https://picovoice.ai/docs/benchmark/tts/)는 합성 중 최고 41MB와 Ryzen 7 5700X 및 RAM 64GB 조건을 제공한다.

QA06과 목표 근거 문서는 세 값의 환경과 범위 및 카운터가 다르다고 명시하고 동일 시점의 합산 실측으로 제시하지 않는다. 약 0.5GB 규모의 기능 참조에서 **제품 상한 512MiB를 선택한 판단**으로 적는다. Windows나 삼성의 앱별 공식 할당량, VIA가 실제 달성한 값 또는 다른 앱에 영향이 없다는 증거로 바꾸지 않는다.

실제 VIA의 연속 최고량 계측과 공유 페이지 및 그래픽 귀속은 검증 전으로 남아 있다. 이 제한은 결함을 발견하지 못했다는 문서 검토 결과와 별개다. 이번 검토로 계측 구현이나 제품 공존 검증이 완료된 것은 아니다.

## 6. 검증 한계

공개 자료와 문서의 의미 및 산식을 검토했다. 실제 VIA 모델 호출, tokenizer 검증, Windows RAM 측정, 고객 사용 조사와 제품 담당자 합의는 수행하지 않았다. 목표의 근거를 추적할 수 있다는 판정이 각 목표의 달성 가능성이나 시장 적합성까지 입증하는 것은 아니다. 목표와 점수는 사용자 검토용 제안 상태를 유지한다.

## 7. 수정 후 재검토

2026-10-14 작성자의 수정 후 해당 문장을 다시 읽었다.

- **SUM-01 해결:** 목표 근거 §6의 규격 문장은 `추론을 포함한 총 청구 출력 500토큰`으로 바뀌었고 견적표의 행은 `총 청구 출력 / 추론 포함`으로 바뀌었다. QA05 상세안의 500토큰 전체 청구 조건과 일치한다. $0.0156과 $0.4631의 성립 조건이 요약에서도 드러난다.
- **RAM 표현 추가 보완 확인:** 다른 독립 검토의 지적에 따라 통합 기능군의 규모를 약 0.5GB라고 부르던 문장이 삭제됐다. QA06과 목표 근거 및 두 표와 README는 `명령 UI 171MB와 소형 음성 기능 41~300MB의 개별 사례`와 `작성자가 선택한 0.5GiB = 512MiB 제품 상한`을 분리한다. 최초 검토에서 합산 실측 부인 문구를 확인했던 것보다 더 명확한 표현이다. 이전 §5의 최초 검토 기록은 당시 판정을 보존하기 위해 남긴다.

**이 검토에서 제기한 P1/P2의 미해결 항목은 0건이다.** 제품 목표의 실제 달성 가능성, QA05 견적 payload의 충족 여부 및 QA06 계측과 제품 공존 검증은 여전히 실행 전이다. 이 재검토는 그 남은 검증을 완료했다는 판정이 아니다.
