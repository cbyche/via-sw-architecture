# 공통 평가 시나리오 독립 리뷰와 보완

> 2026-10-14 / COMMON-28-v1 문서 검토 / 실제 PoC와 모델 및 Windows 실행 없음

## 1. 검토 범위와 역할

사용자 요청에 따라 QA01~09에 서로 다른 시나리오 수를 만들던 방식을 폐기하고 공통 시나리오를 작성했다. 독립 검토자는 주 작성자의 설계를 참조하되 직접 파일을 수정하지 않고 문제와 계산을 보고했다.

| 검토자 | 검토 범위 | 방식 |
| --- | --- | --- |
| review_measurement | 공통 사건과 목표 및 정답과 UC 연결, QA01~09 경계와 분모, 두 발표 표 | 문서와 JSON 참조 대조 및 수량과 산식 독립 검산 |
| targets_cost_memory_research | 비용 청구 항목과 공통 RAM 범위 및 두 표와 목표 요약 | 생성기의 계산 함수를 재사용하지 않은 유리수 계산과 28개별 금액 대조 |

## 2. 지적과 수정

| 지적 | 수정 |
| --- | --- |
| S01의 두 번째 설명이 무엇인지 원본에서 고정되지 않음 | 첫 요청에 TCP 먼저와 UDP 다음 순서를 명시 |
| S17 복합 요청의 다음 Agent ingress를 기다리면 독립 작업이 막힐 수 있음 | 논리 동작별 명세와 선행 결과에 따라 source 시각을 결정. 독립 결과는 다른 작업을 기다리지 않음 |
| S22 미래 취소 ingress에서 거꾸로 100ms를 계산하는 조건 | 취소 발화 종료 +100ms로 외부 완료 source 고정 |
| S22 각 목표에 다른 Task의 완료 사실까지 요구 | 각 목표를 해당 Task의 실제 취소 또는 완료 사실에 한정 |
| 서로 다른 Agent의 역순 결과와 채택 후 부분 대상 정정이 약함 | S23의 시작/완료 순서를 지정하고 S08의 두 번째 정정 추가. F16 같은 Agent 변형과 F17 선행 실패 회귀 추가 |
| S21 미청취 구간의 정답이 후보의 실제 전달과 달라질 수 있음 | 실제 들린 sample을 기준으로 남은 구간 oracle을 정하고 처음 중단한 설명 ID를 명시 |
| BG 진행 직후 완료가 오면 올바른 최신 표시도 앞 진행 미응답으로 실패 | 같은 Task 최신 완료 카드가 진행 응답도 충족. source 시작은 사건별 유지하고 실제 카드 표시를 공통 종료점으로 사용 |
| S08 음성 전 정정으로 구버전 전달 의무와 stale 재생 금지가 충돌 | 정량 S08은 첫 UI와 첫 내용 음성 중 늦은 시각 +200ms에 정정. 음성 전 정정은 출력 barrier를 둔 기능 회귀 F18로 분리 |
| 정정된 구버전의 미생성 음성 나머지까지 준비해야 하는 해석 | 최종 revision의 준비를 완료 조건으로 두고 이미 수행한 구버전 처리와 폐기 비용은 보존 |
| 확인 답변 전에 듣는 음성의 재생 시간이 QA03에 포함될 수 있음 | 순수 청취와 차례 대기는 0초 node. 요약과 TTS 생성 및 내부 출력 준비는 포함 |
| QA06에 이전 20요청과 Agent 6건 및 단독 자원 한도가 남음 | 상세안과 조사 기록 및 요약을 전체 28개로 통일. QA06 독자 호출/Task/버퍼 한도 제거 |
| QA03가 유형별 같은 수를 별도 요구 | 양안에 동일 공통 목록과 동일 사건을 적용하도록 수정 |
| F18이 빠른 후보에서 음성 전에 도착할 수 없는 조건 | 공통 시험 출력 barrier로 첫 음성 보류 후 UI+200ms에 정정하고 barrier 해제 |

같은 지적을 두 검토자가 보고한 경우 한 항목으로 합쳤다. 첫 검토 이후 추가된 지적도 수정 후 다시 검토한다.

## 4. 최종 재검토

두 검토자 모두 최종 파일을 다시 읽고 **기존 지적 종결 및 검토 범위의 미해결 P1/P2 없음**을 보고했다.

- review_measurement: QA06 범위와 QA03 대기 구간 및 동일 사건 적용, S08/F18 절차와 분모 및 두 표의 5회 수량 일치를 확인했다.
- targets_cost_memory_research: QA06 범위와 S08 수정 및 F18 분리, 마지막 발표 원고의 20요청 잔존 문구까지 수정 확인했다. 새 합계는 독립 재계산과 일치한다.

최종 정적 검사에서 공통 원장의 참조와 94개 UC 연결 및 생성 표와 견적을 확인했다. QA 후보 검사는 두 요구사항 표의 숫자 투영과 8개 점수표의 210개 경계 검증점 및 로컬 링크를 확인했다. 활성 문서 링크와 용어 및 기존 QA catalog 검사와 `git diff --check`도 통과했다. 이는 문서 검증이며 실제 기능 통과나 PoC 결과의 증명이 아니다.

## 5. 검증 한계

- 시나리오는 문서 입력 명세다. 실제 WAV와 화면 및 정답 asset과 hash를 제작하지 않았다.
- 비용은 기존 공식 단가 snapshot과 입력 규격의 참조 견적이다. tokenizer 검증과 provider usage가 아니다.
- QA06 절대 목표와 전체 RAM 계측 방법 미완료는 이번 범위에서 해결됐다고 주장하지 않는다.
- 기능 연결과 사건 경계의 문서 검토다. Windows 실행과 API 동등성 및 DP 우열을 실측하지 않았다.
- 정적 검사 통과는 입력 목록과 표 및 산식의 일치성을 확인한다. 28개의 통계적 대표성이나 현장 품질 보증을 뜻하지 않는다.
