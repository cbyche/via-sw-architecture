## 1. 범위와 판본

검토 대상은 이 패키지의 README, QA01~09와 `additional-candidates.md`다. 부모 작성자와 동시에 작업하므로 최초 발견과 재확인 상태를 구분한다. 판단에는 현재 QA 논의 `03-03`, 작업 계획의 2026-10-14 선정 계약, 시스템 경계·고정 범위·대표 UC 및 측정 사건 경계의 해당 정의를 사용했다. 이전 QA 정의를 새 후보에 강제로 적용하지 않았다.

구조 대조에서 직접 확인한 주요 범위는 다음과 같다.

- DP-44 §3.1~3.4 및 `dp44-implementation-structure.md` §1~2, §6: 중앙의 짧은 비동기 Dispatcher와 Stage별 활성화, 공통 상태 권한·게시·수용량.
- DP-47 §7~8.4, §10~12: 원본 공동 해석, 후보의 생산자 소유·확장·재판단, 원본 보존, 강한 A의 crop/cache/patch, 현재성 및 품질 가설.
- DP-45 §3.2~3.3, §10.1~10.7: 요청별 원본 조합과 공통 파생 관계 게시, A의 유효 cache, B의 backfill과 미지원 관계·혼합 경계.
- DP-42 §3.1~3.4, §5~6: 공동 확정 대 독립 서비스 접수·receipt, 강한 통합 Core와 제한된 독립 운영 이익.

도면의 픽셀 검수, 전체 구현 검수, 모든 외부 링크·논문의 정확성 검증을 수행했다는 의미는 아니다.

## 3. 구조와 커버리지 판단

| 검토 질문 | 판정 |
| --- | --- |
| QA 하나가 여러 DP에서 같은 뜻인가 | QA02는 47의 화면 대상과 45의 과거 자료를 모두 최종 지칭 집합으로 평가한다. 45의 중간 근거 정확도로 바꾸지 않는다. 나머지 지표도 각 문서의 경계를 유지한다. |
| 강한 대안을 임의로 약화했는가 | A의 async/cache/부분 patch와 B의 원본 보존·후보 확장·생산 재사용을 명시적으로 허용한다. 실제 구현 전이므로 우열 자체는 아직 확인할 수 없다. |
| DP-47 B의 이익 부족을 과장해 결론내렸는가 | 현재 여섯 QA와 지정 대표 범위에서는 B의 고유 정확도 이익이 보장되지 않는다는 진단이 타당하다. 47 원문은 후보 재사용·오류 추적·변경 국소화의 조건부 이익을 가설로 남긴다. 패키지도 ‘B가 무가치하거나 A가 확정 승자’라고 바꾸지 않는다. |
| DP-42의 정상 사용 이익 공백 진단이 타당한가 | A도 background Core와 모듈화·worker를 지원한다. 재시작 때 업무 추적 유지라는 B의 조건부 이익을 정상 첫 응답의 자동 이익으로 붙이지 않았다. 드문 재시작을 주요 선택 논리로 쓰지 말라는 사용자 방향을 지킨 결과로 해석할 수 있다. |
| QA1과 QA3가 같은 시간을 두 번 가중하는가 | 첫 내용 표시와 목표 전체 완료라는 경계를 구분하고 합산·가중 총점을 금지한다. 44에서 두 지표가 같은 중앙 회수 비용을 공유할 수 있다는 사실은 남으므로 두 독립적인 구조 이익을 증명했다고 표현해서는 안 된다. 현재 문서는 두 시간 축의 차이가 모두 약하다고 적는다. |
| QA1의 3~4 DP 조건을 확보했는가 | 아직 아니다. 44는 약한 가설, 47·45는 방향 가설, 42는 동점 예상이다. README는 이를 확보한 커버리지로 세지 않는다. |
| 4~6 QA와 DP별 3~4 차이를 완성한 것처럼 보이는가 | 아니며 선정 조건 미충족을 명시한다. 특히 QA02의 두 연결, QA06의 차이 크기, 42의 세 번째 축과 B의 이익을 미해결로 남긴다. 이는 숨겨야 할 결함이 아니라 현재 구조 검토의 결과다. |
| 추가 후보가 빈칸을 억지로 채우는가 | QA07은 부하가 더한 지연, QA08은 수정 집합의 교집합, QA09는 재생 가능한 구간의 음성 추가 대기로 각각 뜻이 분리돼 있다. 07·09는 회귀/진단, 08은 예비로 남겨 가짜 커버리지에 사용하지 않는다. |

예측 한 문장은 실제 의존·중간 상태·확정 경로에서 나온다. 그러나 방향 가설만으로 차이가 실용 기준을 넘는다고 보장할 수는 없다. 특히 44의 중앙 회수 제거와 42의 서비스 왕복 차이는 실제 짧은 코드 비용일 수 있으므로 해당 문서가 정한 실용 차이 기준을 넘지 못하면 동점으로 내려야 한다. 현재 문서는 이 반증 가능성을 유지한다.

## 4. 다음 단계에 남기는 조건

1. 핵심 QA 후보의 정의 검토와 핵심 QA·DP 선정 완료를 구별한다. 현 패키지의 빈칸을 충족한 것으로 발표하지 않는다.
2. 독립 PoC에서는 한 DP만 바꾸고 다른 비교 구조와 외부 조건을 고정한다. 실제 호출·queue·후보 저장 비용을 우승자에 맞춘 상수로 모사하지 않는다.
3. 47의 재판단/작은 입력 이익과 45의 반복 조회 이익이 강한 A와 비교해 남는지 확인한다. B의 후보 확장이나 backfill을 금지해 차이를 만들지 않는다.
4. 42의 첫 수행 안내는 업무 서비스 접수 전에 가능하다. 그 뒤의 왕복을 QA1에 더하지 않는다.
5. 구현에서 반대 결과가 나오면 원값과 실패를 유지한다. 모듈 수, 비용, 메모리의 목표 예산 승인과 경험적 차이 확인은 별개다.
