# QA05 조사 기록: 모델 사용 비용

> 조사 확인일: 2026-10-14 / 발표 설명 페이지를 위한 근거 보존 / 가격과 견적은 해당 확인일 기준
> 현재 판본: `COST-20-v3` / `COST-BUDGET-v3` / `COST-v3`. 정의와 실제 비용 집계의 기준은 [QA05 상세안](../qa05-model-cost.md)이다. 이 부록은 공급자 선정이나 API 호출 및 비용 측정을 수행하지 않는다. [조사 목록](./README.md)

## 1. 이번 조사에서 답하려던 질문

사용자는 월 구독료 $20과 월 20일 및 하루 40요청으로 요청당 비용을 나누는 방식을 거부했다. 소비자가 낼 금액과 실제 이용량이 확인되지 않았고 원하는 상한을 정한 다음 나누는 방식으로 제품 원가의 적정성을 설명할 수 없었기 때문이다.

이번 요구안은 **같은 음성 대화와 화면 및 문맥 처리를 기성 API로 구성하는 공개 견적보다 VIA의 모델 원가가 커지지 않아야 한다**는 비교다. CTO/담당임원과 과제 책임자 관점에서 구성한 제품 요구안이며 승인된 예산이나 실제 발언은 아니다. 모델 원가 경쟁력의 참조점이고 출시 서비스 전체의 손익분기점은 아니다.

사용자는 GPT-Live가 너무 최근 모델이라는 이유로 참조에서 제외하고 **정확히 `gpt-realtime`을 사용하라고 요청했다.** 따라서 음성 참조를 바꾸고 토큰 과금에 맞춰 전체 견적을 다시 계산했다. 의미 처리 백엔드인 GPT-5.6 Luna는 이번 요청에서 교체하지 않는다. 이전 GPT-Live 견적과 $0.47 목표는 [보존 문서](../../../../../archive/qa-targets-before-task-aligned-revision-20261014/research-notes/qa05-cost-research.md)에 남긴다.

현재 `gpt-realtime` 문서의 모델 상태와 가격은 공개 견적의 출처다. 실제 계정에서의 사용 가능성이나 제품 공급 계약을 확인한 것은 아니다. 향후 실행에서는 provider와 모델 버전 및 지역과 서비스 등급 및 확인일을 같은 단가 manifest에 고정한다. 과거 결과를 새 단가의 실측 결과로 이름만 바꾸지 않는다.

## 3. 이력을 유지하면서 음성 견적을 계산하는 구성

### 3.1 참조 구성의 역할과 흐름

기존 의미 처리 백엔드를 유지하면서 `gpt-realtime`을 음성의 입구와 출구에 배치한다. 아래는 **공개 견적을 계산하기 위한 한 가지 구성**이며 DP의 A/B 구현 구조를 강제하지 않는다.

```text
사용자 음성 20건
  → Realtime 발화 전달 Response 20회
  → 원 발화와 식별정보를 VIA에 전달
  → Luna 의미 처리 26회 ← Agent 사건 6건
  → 채택한 상세 텍스트를 Request/Task UI에 표시
  → Realtime 음성 생성 Response 26회
  → 사용자가 들을 수 있을 때 요약 음성 전달
```

- **발화 전달:** 현재 음성을 받아 원 발화와 식별정보를 function 인자로 출력한다. 지칭 표현이나 정정을 임의로 확정하지 않는다. 이 출력의 텍스트 요금도 포함한다.
- **의미 판단:** 화면과 원본 이력 및 Task와 현재 요청을 기존 Luna 입력에 제공한다. 이전 발화와 정정의 의미를 해석할 책임은 여기에 유지한다. 원본 이력을 무료로 만든 요약으로 대체하지 않는다.
- **상세 텍스트와 음성:** VIA가 채택한 상세 결과는 UI로 전달한다. 음성용 Response에는 채택한 내용과 발화 지시를 제공하며 임의로 업무를 다시 수행하거나 대상을 바꾸도록 하지 않는다.
- **통계적 의미:** 20회와 26회는 참조 견적의 호출 수다. 실제 후보의 추가 해석과 후보 확장 및 재시도 호출 수를 제한하지 않는다.

### 3.2 이력 재입력 비용이 없는 조건

**46개 Response 모두에 `conversation: none`과 명시적인 `input`을 함께 사용한다.** 발화 전달에는 현재 음성만 넣고 음성 생성에는 채택한 내용만 넣는다. 각 호출의 지시문과 제어 데이터는 별도로 입력 비용에 포함한다. 자동 Response 생성은 꺼서 계산하지 않은 응답이 발생하지 않도록 한다.

`conversation: none`은 출력의 기본 대화 저장을 막는 설정이다. 이것만으로 입력 이력이 없어졌다고 계산하면 안 된다. 이전 음성이나 텍스트를 다시 참조하는 `input`을 보내면 그 입력도 청구한다. 이 견적은 이전 음성을 Realtime에 다시 주지 않는 구성이고 과거 의미 판단을 위한 원본 텍스트와 화면 비용은 Luna 쪽에 포함한다.

별도 입력 전사 옵션은 사용하지 않는다. 발화의 텍스트 전달을 위한 Realtime 호출을 이미 20회 계산했으므로 별도 전사 모델을 무료로 가정하지 않는다. 별도 전사를 켜거나 다시 듣기가 필요하면 해당 모델 사용량을 추가한다. 음성과 함께 생성되는 응답 텍스트는 별도의 전사 API 호출이 아니라 Realtime의 청구 텍스트 출력으로 센다.

이 구성의 입력 분리와 호출 방식은 공식 API가 지원하지만 **같은 정확도와 응답성을 달성했다는 실측 증거는 없다.** 발화 전달이 원문의 정정과 지칭 및 불확실성을 보존하는지와 채택한 결과를 정확하게 음성화하는지는 검증해야 한다. 필요한 정보를 잘라 이 견적에 맞추지 않는다.

## 4. 정의한 20요청 활동과 참조 사용량

대표 활동은 `COST-20-v3`이고 실제 요청과 사건은 [20요청 활동 명세](../user-activity-20.md)를 따른다. 아래 숫자는 고객의 하루 이용량이 아닌 **미실행 견적 규격**이다.

| 조건 | 참조 규격과 의미 |
| --- | --- |
| 사용자 요청 | 20건. 원래 요청과 정정을 같은 활동에서 처리 |
| Agent 사건 | 질문 2와 진행 2 및 결과 2. 사용자 요청 수와 별개 |
| 원본 이력 | 200턴과 완료 Task 20개 및 진행 Task 5개. 후보의 파생 상태 생산 비용은 별도로 집계 |
| 원본 변경 | 2건. 후보의 갱신과 무효화 비용을 실제 원장에 포함 |
| 활동 길이 | 5분 입력 창. 사용자 음성 120초와 응답 음성 130초의 견적 조건이며 재생은 창 밖으로 이어질 수 있음 |
| 사용자 음성 | 20건 × 6초. 공식 환산율로 약 1,200 음성 입력 토큰 |
| 응답 음성 | 26건 × 5초. 공식 환산율로 약 2,600 음성 출력 토큰 |
| Realtime 호출 | 발화 전달 20회와 음성 생성 26회. 합계 46회 |
| Realtime 제어 입력 | 매 Response 1,000 텍스트 토큰. 지시문과 도구 스키마 및 해당 요청의 식별정보와 메시지 특수 토큰을 포함할 총 청구량 가정 |
| Realtime 채택 내용 입력 | 음성 생성마다 500 텍스트 토큰. 채택 결과와 직렬화에 필요한 토큰을 포함할 총 청구량 가정 |
| Realtime 발화 전달 출력 | 사용자 요청마다 100 텍스트 토큰. 원 발화와 function 인자 및 청구 특수 토큰을 포함할 총량 가정 |
| Realtime 음성의 텍스트 출력 | 음성 응답마다 50 텍스트 토큰. 청구 특수 토큰을 포함할 총량 가정 |
| Luna 의미 처리 | 26회. 매회 텍스트 입력 20,000토큰과 추론을 포함한 총 청구 출력 500토큰 |
| 화면 | 화면 요청 6건에 각 15장. Luna에 제공할 참조 입력 90장 |
| 반복 | 동일 초기 원본에서 5회 활동. 반복 내부의 후보 cache 재사용은 허용 |

**1,000/500/100/50 및 20,000토큰을 확인한 직렬화 payload와 표준 WAV는 아직 없다.** 총 청구 토큰 가정이므로 내용만 센 뒤 wrapper와 특수 토큰을 무료로 더할 수 없다. 음성의 10/20 tokens/s도 공식 가이드에 따른 예상 환산이며 실제 usage에는 차이가 날 수 있다. 아직 준비하지 않은 자료를 확인한 것으로 기록하지 않는다.

Luna의 총 출력 500토큰에는 청구 추론을 포함한다. Realtime에 제공할 500토큰은 별도의 **채택 내용 입력 견적**이며 숨겨진 추론을 음성 모델에 전달한다는 뜻이 아니다. 실제 보이는 결과에 필요한 제어 정보를 더한 입력을 만들고 그 총량을 확인해야 한다. 두 500은 서로 다른 청구 항목이다.

실행 전에 실제 자료에 필요한 원문과 상세 응답 및 요약을 담을 수 있는지 확인한다. 규격을 넘으면 후보 결과를 보기 전에 활동과 참조 견적을 함께 개정한다. 사용자와 모델이 5분간 실제로 성공적인 상호작용을 수행한 관측값은 아니다.

## 5. 공개 견적과 목표값의 산출

### 5.1 Realtime 음성 부분

캐시 재사용 할인은 선반영하지 않는다. 지시문 입력이 반복되더라도 46회 모두 일반 입력 단가로 계산한다. 명시적 입력에 과거 음성이 없으므로 이 참조에서는 음성 이력 재입력량이 0이다. 실제 후보가 누적 이력을 사용하면 그 비용도 원장에 포함한다.

| 항목 | 산출 과정 | 금액 |
| --- | --- | ---: |
| 제어 텍스트 입력 | 46 × 1,000 × $4 / 1,000,000 | $0.1840 |
| 채택 내용 입력 | 26 × 500 × $4 / 1,000,000 | $0.0520 |
| 사용자 음성 입력 | 20 × 6초 × 10 tokens/s × $32 / 1,000,000 | $0.0384 |
| 발화 전달 텍스트 출력 | 20 × 100 × $16 / 1,000,000 | $0.0320 |
| 음성 응답의 텍스트 출력 | 26 × 50 × $16 / 1,000,000 | $0.0208 |
| 응답 음성 출력 | 26 × 5초 × 20 tokens/s × $64 / 1,000,000 | $0.1664 |
| **Realtime 소계** | **위 여섯 항목의 합** | **$0.4936** |

5분에 분당 요금을 곱하지 않는다. Realtime의 Response 입력과 출력이 과금 단위다. 이 구성에서는 무음과 백엔드 대기 시간 자체에 별도의 분당 음성 요금을 붙이지 않는다.

### 5.2 기존 의미 처리 백엔드

| 항목 | 산출 과정 | 금액 |
| --- | --- | ---: |
| 텍스트 입력 | 26 × 20,000 × $0.25 / 1,000,000 | $0.1300 |
| 총 청구 출력 / 추론 포함 | 26 × 500 × $1.20 / 1,000,000 | $0.0156 |
| 화면 입력 | 6 × 15 × 3,000 × $0.25 / 1,000,000 | $0.0675 |
| **Luna 소계** | **위 세 항목의 합** | **$0.2131** |

기존의 입력 $0.20에 cache write 1.25배를 적용해 $0.25로 계산한다. 이는 참조 입력에 높은 단가를 적용한 것이며 실제 원장에서는 input과 cache write 및 cache hit를 구분해 한 번씩만 센다. 요청당 텍스트 20,000과 이미지 최대 45,000토큰의 합은 272,000토큰 미만이므로 해당 긴 입력 할증을 적용하지 않는다.

### 5.3 제품 목표 제안

```text
참조 견적 = Realtime $0.4936 + Luna $0.2131 = $0.7067
COST-BUDGET-v3 목표 = 센트 단위 올림 = $0.71 / COST-20 활동
QA05 대표값 = 동일 활동 5회의 실제 총비용 산술평균
```

이는 **미실행 `REFERENCE_QUOTE`를 바탕으로 한 제품 상한 제안**이다. 실제 청구액과 기능 동등성의 증거도 삼성의 승인 예산도 아니다. 세금과 지역 추가 요금 및 무료 크레딧과 프로모션은 반영하지 않는다. 참조 구성에 별도 유료 검색이나 전사 또는 외부 도구 호출은 없으며 이를 추가하면 견적에도 추가해야 한다.

## 6. 실제 비용에서 빠뜨리기 쉬운 부분

1. **준비 비용:** 파생 이력과 후보 및 cache를 미리 만드는 시점부터 원장을 연다. B에 완성된 파생 상태를 무료로 주지 않는다.
2. **재사용:** A의 cache를 매 요청 삭제하지 않는다. B에 모든 가능한 관계의 생산을 강제하지 않는다.
3. **폐기와 실패:** 재시도와 취소 전 생성 및 사용되지 않은 준비도 청구되면 포함한다. 참조의 46회와 26회로 실제 호출을 제한하지 않는다.
4. **이력과 제어 입력:** 이전 음성과 텍스트를 다시 넣는 비용 및 지시문과 도구 스키마와 function 인자를 포함한다. 현재 참조의 명시적 입력 정책을 다른 후보의 원장에 강제로 적용하지 않는다.
5. **출력과 추론:** 음성과 함께 생성되는 텍스트 및 실제 청구 추론을 포함한다. UI에 표시한 텍스트 길이만 세지 않는다.
6. **중복:** cached input이 총 input에 포함됐다면 두 번 더하지 않는다. 이미지와 음성의 별도 bucket도 provider 정의를 따른다.
7. **활동 이후 처리:** 5분 뒤 생긴 해당 활동의 청구도 포함한다. R20 발화 종료를 기준으로 +30~40초의 완료 확인과 +40초 취소 및 +120초 미완료 판정을 적용한다. 늦은 최종 청구도 추가한다. [활동 종료 규칙](../user-activity-20.md#4-응답과-관측-범위)을 따른다.
8. **기능 실패:** 필요한 응답을 생략한 실행은 저비용 성공으로 채점하지 않는다. usage 누락은 $0가 아니라 `INCOMPLETE_COST`다.

직렬화 payload와 tokenizer로 계산한 값은 `ESTIMATED_COST`이고 공시 요금의 참조 견적은 `REFERENCE_QUOTE`다. 실제 provider usage와 재시도 및 음성 청구가 있어야 실측이라고 부른다. 현재 조사에는 모델 실행과 비용 실측이 없다.

## 7. 현재 점수와 설명용 예시

`COST-v3`는 목표 $0.71과 절반 $0.355 사이를 $0.071 간격으로 나눈 점수 표현 규칙이다. 각 경계가 외부 연구의 임계값이라는 뜻은 아니다. 결과를 보기 전에 양안에 동일하게 적용하고 반올림 전 평균 비용으로 채점한다.

| 점수 | 표시 | 평균 총 모델 비용 C (USD/COST-20) |
| --- | --- | --- |
| 6 | ●●● | 0 ≤ C ≤ 0.355 |
| 5 | ●●◐ | 0.355 < C ≤ 0.426 |
| 4 | ●●○ | 0.426 < C ≤ 0.497 |
| 3 | ●◐○ | 0.497 < C ≤ 0.568 |
| 2 | ●○○ | 0.568 < C ≤ 0.639 |
| 1 | ◐○○ | 0.639 < C ≤ 0.710 |
| 0 | ○○○ | C > 0.710 |

**설명용 가상 예시:** 한 활동에서 준비 $0.03와 의미 처리 $0.12 및 음성 $0.32와 갱신 및 재시도 $0.03이 발생하면 합계는 $0.50이다. 가상으로 5회 활동 모두 같은 합계라면 평균도 $0.50이며 `COST-v3`에서 **3점**이다. 단일 활동의 합계만으로 전체 QA05를 채점하지 않는다.

이전 $0.47 목표와 점수표는 [보존 문서](../../../../../archive/qa-targets-before-task-aligned-revision-20261014/qa05-model-cost.md)에 있다. 이번 변경은 사용자가 지정한 음성 참조 모델의 교체와 청구 방식 반영에 따른 것이며 A/B 측정값을 보고 조정한 것이 아니다.

## 8. 채택하지 않은 근거와 이유

| 검토했던 방식 | 채택하지 않은 이유 |
| --- | --- |
| 월 $20 ÷ 20일 ÷ 40요청 | 구독료와 업무일 및 사용량이 확인되지 않았고 일반 소비자 이용을 설명하지 못함 |
| GPT-Live의 분당 요금을 유지 | 사용자가 해당 모델을 제외하고 `gpt-realtime`을 지정함 |
| Realtime을 5분 × 고정 분당 요금으로 계산 | 해당 모델은 Response별 입력과 출력 토큰 과금 |
| 음성 입력 120초와 출력 130초만 합산 | 제어 입력과 발화 전달 출력 및 채택 응답 입력과 음성의 텍스트 출력이 빠짐 |
| 기본 세션에 모든 이력을 남기면서 최초 음성만 계산 | 이전 입력과 출력의 반복 입력 요금이 빠짐 |
| `conversation: none`만 사용해 이력 요금 0이라고 주장 | 출력 저장 제어와 입력 문맥 선택은 별개. `input`도 명시해야 함 |
| Realtime 26회만 계산하면서 별도 전사를 무료로 가정 | Luna에 사용자 발화를 전달하는 모델 작업이 빠짐 |
| 호출 1회 대 3회 | 입력 길이와 출력 및 단가와 cache에 따라 실제 비용의 대소가 달라짐 |
| 참조 API가 같은 기능을 성공한다고 전제 | 가격과 API 지원 문서는 정확도와 품질 달성을 증명하지 않음 |
| 5분에 원장 강제 종료 | 늦게 실행된 응답과 취소 및 청구가 빠져 느린 후보에 유리함 |

## 9. 발표 페이지와 예상 질문에 사용할 내용

- **핵심 문장:** “같은 20요청 활동의 공개 API 견적 $0.7067을 기준으로 VIA의 모델 비용 상한을 $0.71로 제안했습니다.”
- **작은 도식:** Realtime 음성 전달과 음성화 $0.4936 + Luna 의미 처리 $0.2131 → $0.7067 → $0.71.
- **측정 조건 한 줄:** 동일 20요청과 Agent 사건 6개를 5회 반복해 준비부터 마지막 청구까지 집계.
- **목표 근거 한 줄:** 명시적 입력의 `gpt-realtime`과 Luna 참조 견적 $0.7067을 센트 단위로 올림.
- **예시 한 줄:** 5회 활동이 각각 $0.50이면 평균 $0.50으로 3점.
- **각주:** 2026-10-14 공개 단가와 `COST-20-v3`. 호출 수와 토큰 수는 견적 가정이며 실제 청구와 품질 달성 확인은 별도.

| 심사 질문 | 답변의 핵심 |
| --- | --- |
| 왜 하필 $0.71인가 | 같은 활동을 범용 음성과 의미 API로 구성하는 견적 $0.7067의 센트 단위 상한이다 |
| 이전 $0.47은 왜 바뀌었나 | 사용자가 음성 참조를 `gpt-realtime`으로 바꾸도록 요청했다. 그 모델의 입력과 출력 과금을 전체 항목에 반영했다 |
| 이력 비용을 빼서 낮춘 것 아닌가 | 원본 문맥은 Luna 입력에 포함한다. Realtime은 현재 발화와 채택 내용만 처리하는 참조 구성이며 실제 후보의 이력 재입력은 전부 센다 |
| 46회는 어디서 나왔나 | 사용자 발화 전달 20회와 사용자 요청 및 Agent 사건에 대한 음성 생성 26회의 합이다 |
| 1000토큰과 음성 5초는 실측인가 | 아니다. 필요한 내용을 담을 참조 규격이다. payload와 WAV를 만들어 확인하기 전에는 기능을 달성한 청구액으로 주장하지 않는다 |
| 500토큰에 추론을 숨겼나 | Luna의 500은 청구 추론을 포함한 총 출력이다. Realtime 입력의 500은 채택 내용과 제어 정보를 담는 별도 입력 가정이다 |
| 참조 API와 성능이 같은가 | 아직 확인하지 않았다. 가격 기반 제품 원가 요구안이며 후보는 정확성과 응답성도 함께 만족해야 한다 |
| 6점의 절반 비용은 근거가 있는가 | 같은 예산으로 두 배의 활동을 처리한다는 원가 의미를 가진 점수 규칙이다. 외부 연구의 임계값은 아니다 |

DP 예상과 반증 조건은 [QA05 상세안](../qa05-model-cost.md)을 따른다. 발표 편집 시 [아홉 QA 페이지 구성안](../slide-page-plan.md)을 함께 사용한다.
