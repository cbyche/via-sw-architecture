# QA05 조사 기록: 모델 사용 비용

> 출처 조사 확인일: 2026-10-14 / 가격 snapshot 보존 / COMMON-28-v1 통합 반영 / REFERENCE_QUOTE / 미실행
> 정의와 실제 비용 집계는 [QA05 상세안](../qa05-model-cost.md), 시나리오별 산식은 [공통 견적](../common-model-cost-quote.md)을 따른다. 이전 20요청 활동의 상세 조사와 산식은 [통합 이전 원본](../../../../../archive/qa-populations-before-common-catalog-20261014/research-notes/qa05-cost-research.md)에 그대로 보존했다.

## 1. 이번 조사에서 답하려던 질문

사용자는 월 구독료 $20과 월 20일 및 하루 40요청으로 요청당 비용을 나누는 방식을 거부했다. 소비자가 낼 금액과 실제 이용량이 확인되지 않았고 원하는 상한을 정한 다음 나누는 방식으로 제품 원가의 적정성을 설명할 수 없었기 때문이다.

이번 요구안은 **같은 음성 대화와 화면 및 문맥 처리를 기성 API로 구성하는 공개 견적보다 VIA의 모델 원가가 커지지 않아야 한다**는 비교다. CTO/담당임원과 과제 책임자 관점에서 구성한 제품 요구안이며 승인된 예산이나 실제 발언은 아니다. 모델 원가 경쟁력의 참조점이고 출시 서비스 전체의 손익분기점은 아니다.

사용자는 GPT-Live가 너무 최근 모델이라는 이유로 참조에서 제외하고 **정확히 `gpt-realtime`을 사용하라고 요청했다.** 따라서 음성 참조를 바꾸고 토큰 과금에 맞춰 전체 견적을 다시 계산했다. 의미 처리 백엔드인 GPT-5.6 Luna는 이번 요청에서 교체하지 않는다. 이전 GPT-Live 견적과 $0.47 목표는 [보존 문서](../../../../../archive/qa-targets-before-task-aligned-revision-20261014/research-notes/qa05-cost-research.md)에 남긴다.

## 2. 출처별 확인 내용과 적용 범위

| 출처 | 확인한 사실 | VIA에 적용하는 부분 | 적용하지 않는 주장 |
| --- | --- | --- | --- |
| [GPT-Realtime 공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-realtime) | 100만 토큰당 텍스트 입력 $4와 출력 $16. 음성 입력 $32와 출력 $64. Function calling 지원 | 명시된 `gpt-realtime`의 입력과 출력을 각각 계산 | 다른 Realtime 모델의 단가를 대신 사용하거나 분당 고정 요금으로 계산 |
| [Realtime 비용 공식 가이드](https://developers.openai.com/api/docs/guides/voice-latency-cost?voice-api=realtime) | Response마다 입력과 출력 과금. 기본 대화에서는 이전 출력도 다음 입력에 포함. 사용자 음성은 약 10 tokens/s이고 응답 음성은 약 20 tokens/s | 음성 길이의 예상 토큰 환산과 이력 재입력 여부 확인. 음성과 함께 생성되는 텍스트 출력도 포함 | 세션 5분 전체를 발화 시간으로 계산하거나 누적 대화 이력을 무료로 처리 |
| [Realtime 대화 관리 가이드](https://developers.openai.com/api/docs/guides/realtime-conversations)와 [Response API 항목](https://developers.openai.com/api/reference/resources/realtime/client-events#response.create) | `conversation: none`으로 기본 대화에 출력을 추가하지 않는 Response를 만들 수 있음. `input`으로 사용할 입력을 명시할 수 있음. 자동 Response 생성 제어 지원 | 각 호출의 입력을 정한 음성 전달 및 음성화 참조 구성 | `conversation: none`만 지정하면 이전 입력까지 자동 제외된다는 주장 |
| [GPT-5.6 Luna 공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-5.6-luna) | 100만 토큰당 입력 $0.20와 출력 $1.20. Cache write는 입력의 1.25배 | 참조 입력에는 높은 쓰기 단가 $0.25를 적용 | 모든 실제 API 입력이 반드시 쓰기 단가로 청구된다는 주장 |
| [이미지 입력 공식 가이드](https://developers.openai.com/api/docs/guides/images-vision) | 해당 모델의 high 입력은 최대 2,500패치와 1.2배 배율 | 화면 한 장의 입력 견적을 최대 3,000토큰으로 계산 | 해당 화면의 실제 tokenizer 결과가 정확히 3,000이라는 주장 |
| [Groq 모델 표](https://console.groq.com/docs/models)와 [청구 FAQ](https://console.groq.com/docs/billing-faqs) | 모델과 입력 및 출력과 음성에 따라 요금 단위가 다름 | 모든 모델 사용을 통화 단위로 합치는 원장 필요 | 모델 호출 수만으로 비용 우열을 결정 |

현재 `gpt-realtime` 문서의 모델 상태와 가격은 공개 견적의 출처다. 실제 계정에서의 사용 가능성이나 제품 공급 계약을 확인한 것은 아니다. 향후 실행에서는 provider와 모델 버전 및 지역과 서비스 등급 및 확인일을 같은 단가 manifest에 고정한다. 과거 결과를 새 단가의 실측 결과로 이름만 바꾸지 않는다.

## 3. 공통 시나리오로 바뀐 평가 단위

모든 실행 QA가 [공통 28개 대표 시나리오](../common-scenarios.md)를 사용한다. 사용자 입력 84건 가운데 Voice 81건과 Text 3건이 있고 Agent 사건은 36건이다. 지정 응답 120건 가운데 Voice OFF 4건과 진행 UI 7건을 제외한 109건에 음성 요약을 요구한다. 이 수량은 고객의 하루 이용량이나 통계적 이용 빈도가 아니다.

```text
Voice 입력 81건 → Realtime 발화 전달 81회
Text 입력 3건과 Agent 사건 36건을 함께 수신
→ Luna 의미 해석과 내용 생성 120회
→ 상세 Text 표시 120건
→ 의무 음성 요약 109건을 Realtime으로 생성
```

실제 후보가 진행과 완료를 합쳐 처리하거나 후보 확장과 재시도를 추가할 수 있다. 위 호출 수는 참조 견적의 구성이고 A/B 구현을 강제하는 호출 상한이 아니다. 공통 기능과 각 응답의 의미 조건을 만족해야 한다.

## 4. 누적 이력과 빠뜨리기 쉬운 청구

- **명시적 입력:** 190개 Realtime Response 모두 `conversation: none`과 현재 `input`을 함께 사용한다. 출력 저장만 막는 설정으로 과거 입력도 무료라고 주장하지 않는다.
- **원본 맥락:** 이전 대화와 Task 및 화면은 Luna 입력에 포함한다. 유료 모델로 만든 요약을 무료 초기 상태로 제공하지 않는다. 참조의 원본 복원은 코드 작업이며 실제 후보의 모델 준비는 전부 추가한다.
- **발화 전달:** 별도 입력 전사를 무료로 가정하지 않는다. Realtime 전달 출력의 Text 비용을 이미 포함한다. 별도 전사 모델을 사용하면 그 청구도 추가한다.
- **전체 입력:** 지시문과 schema 및 직렬화 wrapper와 현재 발화 및 해당 자료까지 모든 청구 입력을 포함하는 견적 가정이다.
- **전체 출력:** Luna는 추론 포함 총 청구 출력을 센다. Realtime은 생성 음성과 동반 Text 출력을 각각 센다. UI에 보이는 글자 수만으로 출력량을 계산하지 않는다.
- **준비와 폐기:** 초기 파생 생산과 갱신 및 실패와 재시도 및 중단된 음성 생성도 포함한다. S21/S23 이전 고정 클립은 초기 fixture여서 새 생성 비용은 없지만 RAM과 재생 점유는 포함한다.
- **후속 청구:** 모든 입력과 의무 외부 사건이 제공된 `t_final_source` 이후 60초에 미완료를 기록하고 취소를 요청하며 120초까지 종료와 정산을 수집한다. 선행 입력이 막힌 경우의 실패 fallback도 공통 목록을 따른다. 늦은 청구 누락은 $0가 아니라 `INCOMPLETE_COST`다.
- **중복 방지:** input에 cached bucket이 포함됐는지 공급자 정의를 확인해 한 번만 센다. 실제 청구에 참조의 보수적 쓰기 단가를 다시 곱하지 않는다.

## 5. 새 참조 견적과 근거 상태

| 부분 | 원장에서 산출한 참조량 | 견적 |
| --- | --- | ---: |
| Realtime | 전달 81회 + 생성 109회. 입력 음성 481초와 생성 음성 545초. 제어와 채택 입력 및 발화 전달과 동반 Text 포함 | $2.04632 |
| Luna | 의미 처리 120회. Text 입력 1,144,000토큰과 이미지 입력 36회. 추론 포함 총 출력 155,600토큰 | $0.49972 |
| **전체** | 개별 S 반올림 없이 합산 | **$2.54604** |
| **목표 제안** | 센트 단위 올림 | **$2.55 / 28개 묶음** |

각 토큰 bucket의 산식과 28개 S별 원장은 [공통 견적 §2~4](../common-model-cost-quote.md#2-입력량의-정의와-한계)에 모두 공개했다. 공식 출처의 단가는 이전 조사 snapshot이며 이번 통합에서 새 가격을 조회한 것은 아니다.

**입력량은 아직 payload와 tokenizer로 확인한 값이 아니다.** simple/screen/history/task/lookup별 입력 예산과 출력 예산을 등록했으며 현재 참조의 최대 입력은 기존 272,000토큰 경계 이하다. 이미지마다 high 최대 3,000토큰을 적용한다. 실제 원문과 의미 정보가 해당 규격에 담기는지는 자료 제작 단계에서 확인한다.

**음성 길이도 미실행 규격이다.** 입력은 사건별 길이를 합산하며 출력 요약은 각각 5초 생성으로 견적했다. 입력 약 10 tokens/s와 출력 약 20 tokens/s는 공식 가이드의 근사 환산이다. 필요 내용을 담을 수 없으면 결과를 보기 전에 공통 원장과 참조 견적을 함께 바꾼다. 5초를 맞추려고 내용을 버리거나 무음으로 입력량을 늘리지 않는다.

같은 기능의 범용 API 참조 구성보다 원가가 커지지 않도록 요구하는 제품 제안이다. 실제 API가 모든 기능과 품질 목표를 달성했다는 증거도 삼성의 승인 예산도 아니다. 구독료와 세금 및 외부 도구 사용료를 포함한 전체 사업 원가로 확대하지 않는다.

## 6. 점수와 설명용 예시

`COST-COMMON-v4`는 $2.55 목표의 50% / 60% / 70% / 80% / 90% / 100%를 각각 6~1점의 상한으로 사용한다. 실제 구간은 [QA05 §6](../qa05-model-cost.md#cost-scores)의 표를 따른다. 경계는 표현 규칙이며 외부 연구의 사용성 임계값이 아니다.

준비 $0.08 + 의미 $0.45 + 음성 $1.12 + 갱신과 재시도 $0.15 = **$1.80**이다. 설명용으로 5개 묶음이 모두 같다면 평균 $1.80은 **3점**이다. 실제 측정값이 아니다. 비교 최소 차이 제안은 예산의 5%인 $0.1275다.

## 7. 제외한 근거와 예상 질문

| 질문 또는 이전 방식 | 답변과 판단 |
| --- | --- |
| 왜 이전 $0.71이 바뀌었나 | 20요청 활동을 폐기하고 모든 실행 QA의 같은 28개 시나리오를 사용한다. 새 입력과 응답 및 화면량을 항목별로 다시 계산했다 |
| 월 $20를 하루와 요청 수로 나누면 되지 않나 | 구독료와 이용량이 확인되지 않았고 일반 소비자의 제품 원가 목표를 설명하지 못한다 |
| 왜 gpt-realtime인가 | 사용자가 정확히 이 모델을 지정했다. 다른 Realtime 모델이나 GPT-Live 단가로 대체하지 않는다 |
| 190회는 어디서 나왔나 | 실제 목록의 Voice 입력 81건과 의무 음성 응답 109건의 합이다 |
| 음성 길이만 계산하면 되나 | 제어와 채택 내용 입력 및 발화 전달과 동반 Text 출력도 각각 청구되므로 포함해야 한다 |
| Realtime을 분당 고정 과금하면 되나 | 해당 참조는 Response별 입력과 출력 토큰 과금이다. 무음과 백엔드 대기 자체에 임의 분당 비용을 붙이지 않는다 |
| 준비 비용을 빼면 싸지는 것 아닌가 | 앱 시작 전부터 원장을 열고 실제 후보의 모든 모델 준비와 갱신 및 폐기를 포함한다 |
| 참조 API와 성능이 같은가 | 미검증이다. 실제 후보는 정확성과 응답성도 만족해야 하며 입력 자료의 충분성 검증이 필요하다 |
| 왜 5회인가 | 공통 시나리오에서 반복 일관성을 확인하는 PoC 규격이다. 실사용 비용의 통계적 보증이 아니다 |

발표에는 “공통 28개 묶음의 공개 API 참조 견적 $2.54604를 센트 단위로 올려 $2.55를 제안했다”로 요약한다. 실제 호출과 실측 비용은 별도로 제시한다.
