# VIA 품질 요구사항 표와 발표용 요약

> 2026-10-14 / QA01~QA09 검토안 / 목표 수치와 중요도 / 난이도는 제안 / 미측정

사용자가 제공한 품질 요구사항 레퍼런스의 `ID / 분류 / Title / Scenario / 중요도 / 난이도` 형식으로 정리한다. [대화에서 제공한 상세 표](#detailed-table)를 바탕으로 같은 파일에 [발표용 축약 표](#presentation-table)를 제공한다. 중요도 / 난이도에는 10점 척도를 적용하고 중요도 판단 근거에 관련 stakeholder의 요구를 연결했다. QA04는 실제 변경 예시로 풀어썼으며 QA06은 삼성 기본 탑재 관점의 1GiB 제품 목표안으로 개정했다. 이전 4GiB 근거는 사용하지 않는다.

QA01~QA09는 [QA 후보 패키지](./README.md)의 식별자다. 기존 ASR 번호를 변경하지 않는다. 각 QA의 측정 경계 / 예외 / 점수 / DP 관계는 연결된 상세 명세를 따른다.

## 1. 대화에서 제공한 상세 표

첨부 표의 **ID / 분류 / Title / Scenario / 중요도 / 난이도** 구성을 따랐습니다. Scenario에는 **요구사항 문장 → 정량 목표 → 측정 조건 → 목표 근거**를 넣었습니다.

목표 수치는 기존 문서의 **검토용 제안값**입니다. 중요도 / 난이도는 **1~10점의 사전 판단**이며 **1~4점=L / 5~7점=M / 8~10점=H**로 표시합니다. 예를 들어 `H(10) / H(9)`는 중요도 10점과 난이도 9점입니다.

### 1.2 중요도와 난이도 판단 근거

**중요도는 사용자 가치와 사업 / 개발 영향을 고려한 이 과제의 QA 평가 우선도**다. 기존 QA 순서에 맞춰 핵심 여섯 개를 먼저 두고 이미 다루는 품질을 보완하는 후보는 뒤에 둔다. **난이도는 각 목표를 달성하는 데 필요한 구조적 조정의 복잡성**이며 중요도와 독립적으로 판단한다. 두 점수를 합산하지 않는다.

- **중요도 기준:** 10점은 최우선 대화 경험, 9점은 핵심 기능의 신뢰, 8점은 전체 처리와 지속 개발의 핵심, 7점은 운영 비용, 6점은 PC 자원 공존, 5점은 핵심 QA를 보완하거나 공통으로 검증할 품질이다. 이 점수는 현재 VIA 과제에 대한 판단이며 범용 공식이 아니다.
- **난이도 기준:** 10점은 여러 종류의 불확실한 근거를 함께 판정하는 문제, 9점은 여러 처리 단계와 대기를 함께 줄이는 문제, 8점은 상태 / 계약 / 동시 처리 경계를 조정하는 문제, 7점은 품질을 유지하면서 생산량과 비용을 줄이는 문제, 6점은 자원 수명이나 모듈 경계를 제한하는 문제에 부여했다. 현재 측정 범위와 목표를 전제로 한 구현 전 판단이다.
- **동점 처리:** QA03 / QA04는 중요도 8점이며 사용자의 완료 경험을 먼저 다루는 기존 순서를 유지한다. 추가 후보 QA07~QA09는 모두 5점이며 기존 후보 순서를 유지한다.
- **이전 등급의 수정:** QA09는 제품 필수성을 이유로 H였으나 이번에는 평가 우선도와 행 순서를 일치시키기 위해 **M(5)**로 조정했다. **음성 전달은 여전히 필수 검증 항목**이며 낮은 평가 순위가 생략을 허용하지 않는다.

**Stakeholder 연결의 근거:** 사용자 / CTO/담당임원의 요구와 AI 코딩 병행 개발 부담은 대화에서 확인했다. 아래는 이를 QA 목적과 연결한 **요구 연계안**이며 역할별 세부 발언이 확인되지 않은 연결은 해당 역할의 관점에서 제안했다. 인용문이나 stakeholder별 합의 점수로 해석하지 않는다. 개발자가 VIA에 바라는 연동 / 협업 조건을 적으며 그 개발자의 구현 업무를 요구사항으로 바꾸지 않는다.

### 1.3 표를 해석할 때 유지할 조건

- **평균 목표와 개별 사례 보장은 다릅니다.** 실패나 느린 사례를 숨기지 않고 원값과 함께 확인합니다.
- QA05 / QA06의 공통 활동은 **이력 200턴 / 완료 업무 20개 / 진행 업무 5개**에서 시작하며 원본 변경 2건과 Agent 사건 6건을 포함합니다. 초기 준비부터 후속 작업까지 관측합니다.
- **QA01~QA06은 핵심 검토 대상**입니다. QA07은 QA01의 부하 진단이며 QA08은 QA04의 협업 보조 지표입니다. QA09는 필수 음성 검증 항목입니다. **평가 우선도 점수는 DP의 두 방안에 성능 차이가 있다는 증거가 아닙니다.**
- 여기의 **H/M/L과 괄호 안 1~10점은 중요도 / 난이도 평가**입니다. 이후 PoC 결과에 부여할 **0~6점 성능 점수와는 별개**입니다.

- 중요도 / 난이도는 1~10점 제안값이며 1~4=L / 5~7=M / 8~10=H다. 목표 달성 성능은 PoC의 별도 0~6점으로 평가한다.
- QA01~QA06은 핵심 검토 대상이며 QA07과 QA08은 보조 지표이고 QA09는 필수 음성 검증 항목이다. QA06의 1GiB는 클라우드 모델 조건의 제품 설계 목표안이다.

측정 상세와 실패 처리, 목표 산식의 가정, 0~6점 구간, 예시와 QA–DP 관계는 각 QA 상세 명세와 [패키지 대응표](./README.md#4-qadp-대응과-예상-우열)로 연결한다.
