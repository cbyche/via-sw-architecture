## 1. 발표에 사용할 핵심 설명

**사용자가 말로 지정한 대상을 빠짐없이 정확하게 찾는지를 평가한다.**

| 항목 | 제안 |
| --- | --- |
| QA 이름 | **지칭 대상 식별 정확도** |
| 한 문장 정의 | 사용자의 지칭 표현을 그 표현이 가리키는 대상 집합에 정확하게 연결하는 능력 |
| 단일 지표 | **지칭 대상 집합 일치율(%)** |
| 목표 제안 | **99% 이상** |
| 목표 근거 | 수동 선택 실험의 마우스 성공률 **98.7%**를 참조하여 정수 단위로 상향한 **대상 지정 신뢰도 목표** |
| 주된 비교 DP | **DP-47과 DP-45** |
| 비교할 결과물 | 두 DP 모두 현재 요청에 **채택된 최종 지칭 대상 집합** |

DP-47에서는 화면의 대상, DP-45에서는 과거 대화나 자료의 항목을 찾는다. 출처는 달라도 질문은 같다. **“이 표현이 가리키는 대상 집합을 맞게 찾았는가?”** DP-45의 중간 검색 결과나 반환 근거의 정확도를 대신 채점하지 않는다.

## 2. 왜 집합 전체의 일치율인가

“이 표와 아래 그래프를 비교해 줘”에서 표만 맞고 그래프가 틀리면 사용자는 요청을 바로 실행할 수 없다. 대상별 정답을 평균하면 이 사례가 절반 성공으로 보이지만, 해당 지칭은 실패다.

평가 단위는 **사전에 지정한 지칭 표현 하나와 그 입력 revision**이다. 표현 하나가 여러 대상을 가리키면 집합 전체를 한 번에 평가한다. 서로 다른 표현의 대상을 모두 합쳐 채점하지 않는다. 예를 들어 “이 표를 저 표와 비교”에서 두 표의 역할이 바뀌면 각 표현의 binding이 틀린 것이므로 실패다.

```text
G_i = 지칭 표현 i가 의도한 대상 집합
P_i = 동일 표현과 입력 revision에 대해 VIA가 채택한 대상 집합

I_i = 1  (P_i와 G_i가 완전히 같음)
      0  (누락 / 추가 / 다른 대상 / 다른 범위 / 의도와 다른 버전 또는 판단 없음)

지칭 대상 집합 일치율 = 100 × Σ I_i / N
```

최종 채택 전에 내부 후보를 수정하는 것은 오답 횟수를 늘리지 않는다. 반면 오답을 채택해 사용자에게 확정 내용으로 표시하거나 업무에 전달한 뒤 정답으로 고쳤다면 첫 채택의 실패를 지우지 않는다. 사용자의 새로운 정정 발화는 미리 지정한 다음 revision의 별도 판단이다. 후보가 자의적으로 요청을 쪼개거나 재시도해 분모를 늘릴 수 없다.

### 동일 대상을 판정하는 방법

- 원본 식별자와 의도한 항목 / 범위 및 필요한 버전을 평가용 정답 원장에 기록한다. 이 원장은 후보에 제공하지 않는다.
- 셀 범위와 원본 항목 ID가 실제로 존재하면 이를 정규화한다. 이미지의 영역만 존재하면 원본 frame과 지칭 영역을 평가자가 연결한다. 화면에 없는 native ID나 stable selector를 후보 입력에 만들어 주지 않는다.
- 표현 차이와 구현별 후보 ID의 차이는 정답 차이가 아니다. 같은 원본의 같은 의미 범위를 가리키면 동등하다.
- 시각 영역의 허용 경계와 버전 구분 필요성은 자료 작성 시 정한다. 결과를 본 뒤 정답 영역을 넓히거나 특정 후보 ID에 맞추지 않는다. 자동 정규화가 불가능한 항목은 익명화한 결과를 두 평가자가 원본과 대조한다.
- 버전이 달라도 사용자의 의도에 영향을 주지 않는 장면에서는 버전 문자열 자체로 오답 처리하지 않는다. “아까 들은 설명”처럼 과거 내용이 대상인 장면에서는 실제 전달 버전을 구별한다.

이 과정은 서로 다른 표현을 같은 정답 대상에 대응시키는 절차다. 화면에서는 IoU를 점수로 쓰고 과거 이력에서는 문장 사실 수를 점수로 쓰는 식으로 **대표 지표를 바꾸지 않는다.**

### 모호한 요청의 처리

이 지표의 분모에는 **양안에 제공한 근거만으로 정답 집합을 결정할 수 있는 지칭**을 넣는다. 명확한 요청에 불필요한 확인 질문만 하거나 제한 시간 안에 채택하지 못하면 0이다.

실제로 근거가 부족한 지칭은 별도의 공통 기능 검증에 넣는다. 여기서는 특정 대상을 단정하지 않고 필요한 정보를 확인해야 한다. 이 사례를 `확인 필요`라는 가짜 대상 ID로 바꿔 집합 일치율에 합치지 않는다. 분모 제외는 정답 작성자가 실행 전에 판단하며, 후보의 실패를 본 뒤 “원래 모호했다”고 제외할 수 없다.

## 3. 대표 평가 집합 제안

**각 DP에 20개 지칭 판단 × 5회 = 100개 판정**을 제안한다. 아래 표는 20개 판단의 배분이며 제품의 실제 발생 비율을 추정한 것은 아니다. 각 유형은 서로 다른 자료 / 문장 / 대상 배치로 만들고 A/B에 같은 입력을 재생한다.

| 유형 | 판단 수 | DP-47의 실제 입력 | DP-45의 실제 입력 | 공통 채점 질문 |
| --- | ---: | --- | --- | --- |
| 단일 대상 | 4 | 선택한 표 또는 pointer로 가리킨 항목 | 이전 응답의 특정 설명 항목 | 하나의 의도한 대상을 찾았는가 |
| 복수 대상 | 4 | 원으로 가리킨 두 그래프 | 앞서 설명한 두 기준 또는 두 결과 자료 | 대상의 누락 / 추가 없이 집합을 찾았는가 |
| 부분 정정 | 4 | “아래 그래프만”으로 집합 축소 | “그중 두 번째 기준은 빼고” | 변경된 집합과 유지할 대상이 맞는가 |
| 시점 / 버전 구분 | 4 | 화면 전환 전 지칭과 늦은 전사 | 실제 들려준 설명과 미전달 생성문 또는 수정 전후 자료 | 표현이 뜻한 시점의 대상을 찾았는가 |
| 유사 후보 구별 | 4 | 같은 모양의 표 / 그래프와 page 이동 | 비슷한 설명이 있는 다른 대화 / Task | 잘못된 이웃 후보와 구별했는가 |
| **합계** | **20** | | | |

추가로 각 DP에 **근거 부족 사례 4개**를 두어 잘못된 단정을 검사한다. 이 4개는 위 20개와 분모 / 점수에 섞지 않고 기능 검증 결과로 함께 공개한다. 부분 정정의 유지 항목도 oracle에 포함한다. 두 DP의 문제 난이도와 입력 종류가 다르므로 `47A 99%`와 `45B 98%`를 대조해 어느 DP가 더 정확하다고 말하지 않는다. **같은 DP의 A/B 차이를 같은 의미의 지표로 비교**한다.

## 4. 측정 방법과 실패 처리

1. 원본 화면 / 동작 / 음성 또는 실제 전달 이력을 준비하고 정답 집합과 제외 이유를 먼저 작성한다.
2. 양안에 같은 원본, 접근 권한, 모델 capability와 budget을 제공한다. 47의 후보 정답과 45의 완성된 이력 관계를 입력에 미리 넣지 않는다.
3. 실제 관측 / 조회 / 생산 / 결합 경로를 실행한다. 45의 과거 이력 생성 / 갱신 / 정정도 준비 단계에서 양안의 실제 경로를 거친다.
4. Request Controller가 채택한 지칭 결과와 근거 revision을 수집한다. 45에서는 근거 공급 뒤 공통 후속 해석 경로까지 실행해야 한다.
5. 후보 이름을 가리고 대상 집합을 정규화한 뒤 정답과 대조한다. 판정이 갈리는 항목은 근거와 함께 재검토하되 실행 후 정답 변경은 별도 판본으로 보존한다.
6. A/B 순서를 교차하고 5회 결과를 모두 남긴다. 평균 일치율뿐 아니라 유형별 원값 / 오답 원인 / 같은 사례에서의 A/B 차이를 보존한다.

**실패도 분모에 남는다.** 누락, 과다 선택, 잘못된 범위, 의도와 다른 버전, 무응답과 해석 오류로 인한 불필요한 확인은 0이다. 구조 때문에 모델 호출이 실패한 경우도 실패다. 시험 장치 자체가 원본을 전달하지 못한 공통 사고는 양안 모두 같은 쌍을 무효 처리하고 사유와 재실행을 남긴다.

완료 상한은 **입력 종료 이후 30초**로 제안한다. 이는 정답률을 시간제한 없이 높이는 것을 막는 평가 실행 한도이며 사용자 반응 목표가 아니다. 정답이 늦게 도착해도 QA 1의 지연값은 별도로 불리하게 남는다. 30초 뒤의 정답을 소급해 본 판정에 넣지 않는다.

## 5. 목표 99%의 도출과 근거 수준

**사용자와 PC 플랫폼 및 제품 통합 담당자의 관점에서 대상 지정의 편의성을 높이면서 기존 수동 선택 수준의 신뢰도를 유지하도록 요구한다.** CTO/담당임원이 기대하는 주된 PC 인터페이스로 발전하려면 대상 선택 오류를 후속 Agent가 알아서 복원한다고 가정해서는 안 된다. 이는 해당 stakeholder의 관점에서 도출한 요구 제안이며 실제 인터뷰나 합의가 완료됐다는 뜻은 아니다.

### 5.1 수치의 참조점

| 원문과 위치 | 관측한 수치 | 시험 조건과 이 문서의 사용 범위 |
| --- | --- | --- |
| [Sasangohar, MacKenzie & Scott, HFES 2009, Error Rates](https://www.yorku.ca/mack/hfes2009) | 마우스 오류율 2.1%, 즉 성공률 **97.9%** | 12명, tabletop의 반복 표적 선택, 표적 크기와 거리 16조건. 기존 수동 선택의 참조 사례이며 VIA의 의미 판단 실험이 아님 |
| [Rajanna & Hammond, 2022, Table 2](https://arxiv.org/html/2208.01248) | 마우스 오류율 1.3%, 즉 성공률 **98.7%** | 12명, desktop 환경, 입력 방식별 2,496회, ISO 9241-9 과제. 표적 폭 230/330px의 실험 결과이며 일반 PC 사용 전체의 평균이 아님 |

두 연구는 표적을 마우스로 고르는 실제 실험이다. 문헌의 높은 참조값인 98.7%를 제품 목표의 출발점으로 삼고 정수 단위로 상향한다.

```text
참조 수동 선택 성공률 = 100% − 1.3% = 98.7%
VIA의 대상 지정 신뢰도 목표 = ceil(98.7%) = 99%
```

**99%는 수동 선택 실험을 참조해 설정한 제품 목표다.** 같은 과제의 비열등성을 실측했다거나 논문이 VIA의 99% 사용자 만족을 보장했다는 뜻은 아니다. 여러 대상이 포함된 경우에도 전체 지칭 집합을 한 번에 평가하므로 개별 대상의 부분 정답을 평균하여 목표를 완화하지 않는다. DP-45에서도 과거 항목을 사용자가 직접 찾아 선택하는 수고를 줄인다는 같은 제품 요구를 적용한다.

2009 연구는 tabletop 환경과 마우스 emulator의 한계를 보고한다. 2022 연구는 큰 표적을 사용했다. 두 값이 모든 수동 선택 과제의 범위를 대표하지 않는다. 이 문서에서는 **지정 대상을 잘못 고르는 일을 기존 입력 수단의 참조 사례보다 늘리지 않겠다는 목표 설정**에 사용한다. 삼성 PC에서 동일한 대상과 자료로 직접 수동 선택과 비교한 결과는 아직 없다.

### 5.2 목표와 검증 수준의 구분

| 출처 | 확인한 내용 | 이 문서에서 사용하는 범위 |
| --- | --- | --- |
| [ReCLIP, ACL 2022](https://aclanthology.org/2022.acl-long.357/) | 자연어 지칭을 영상의 대상에 연결하는 문제와 시각적 공간 추론 오류를 다룸 | 평가 대상의 연구적 맥락. VIA의 99% 목표나 B의 우세를 직접 입증하지 않음 |
| [NIST TN 2045](https://www.nist.gov/publications/confirming-performance-threshold-binary-experimental-response) | 이진 성공과 실패의 성능 기준을 확인하려면 표본 크기와 수용 기준을 먼저 정해야 함 | 제품 목표와 통계적 입증을 구별하는 근거 |
| [NIST 이항비율 신뢰구간](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm) | 작은 표본과 적은 실패에서는 정확 이항 구간을 사용할 수 있음 | 작은 PoC 표본의 정답률을 전체 제품의 보장으로 확대하지 않는 근거 |

출처 확인일은 2026-10-14다. PoC 100개 판정에서는 오류가 1개 이하여야 표본 목표를 만족한다. 20개 원본의 5회 반복은 모델 변동을 확인하지만 독립적인 100개 사용 상황은 아니다. 결과명은 `대표 20개 지칭의 5회 반복 일치율`로 쓴다. 독립 표본 100개에서 전부 정답이어도 일측 95% 정확 이항 하한은 약 97.05%이므로 99% 모집단 보장을 입증하지 못한다. 반복 원본은 이 계산의 독립성 가정도 충족하지 않는다. 제품 보장에는 독립 사례와 별도의 수용 계획이 필요하다.

### 5.3 심사 질문과 답변

| 질문 | 답변 |
| --- | --- |
| 마우스 선택과 의미 해석이 다른데 왜 그 수치를 쓰는가 | 사용자에게 대상 지정 수단을 바꾸어도 유지할 신뢰도 수준을 요구하기 위한 참조값이다. VIA의 의미 해석은 실제 화면과 과거 이력의 정답 집합으로 따로 평가한다. |
| 98%나 95%로 정해도 되지 않는가 | 참조한 desktop 마우스 실험은 98.7%다. 그 값을 낮춰 잡지 않고 정수 단위로 상향한 99%를 채택한다. 소수점 정밀도가 과도하므로 98.7% 자체를 제품 목표로 쓰지 않는다. |
| 99%면 사용자 만족과 업무 성공을 보장하는가 | 이 목표는 대상 지정의 정확도다. 사용자 만족이나 업무 전체 성공률은 별개의 결과이며 99%라는 숫자만으로 보장하지 않는다. |
| Agent가 오류를 복구할 수 있으니 목표를 낮춰도 되는가 | 잘못 지정한 대상을 받은 조건에서의 복구율을 측정한 근거가 없다. 일반 Agent benchmark 성공률을 그 복구율로 대체하거나 목표에 미리 반영하지 않는다. |
| 100회면 99%를 입증할 수 있는가 | 그 표본의 합격 여부는 판단할 수 있지만 모집단의 99%를 보장하는 검증은 아니다. PoC와 제품 수용 시험을 구별한다. |

종전의 오류 50건당 1건 예산과 98% 목표는 [개정 전 원문](../../../../archive/qa-targets-before-evidence-rebuild-20261014/qa02-referent-accuracy.md)에 보존한다. 외부 참조 성능과 제품 요구를 연결하기 위해 목표를 바꿨으며 A/B 결과에 맞춘 변경이 아니다.

## 6. 0~6점 구간 — `QA-C02-score-v2`

목표 99%에서 오류 없는 표본 100%까지를 0.2%p 간격으로 나눈다. **99%는 수동 선택 참조값에서 도출한 제품 목표이고 중간 구간은 비교 표시 규칙이다.** 인간의 인지 차이가 0.2%p마다 발생한다는 주장이 아니다. 반올림 전 원값으로 채점한다.

| 점수 | 원형 표시 | 일치율 a의 범위 | 의미 |
| ---: | --- | --- | --- |
| 0 | ○○○ | 0% ≤ a < 99% | 목표 미달 |
| 1 | ◐○○ | 99% ≤ a < 99.2% | 목표 충족 |
| 2 | ●○○ | 99.2% ≤ a < 99.4% | 오류 감소 |
| 3 | ●◐○ | 99.4% ≤ a < 99.6% | 오류 감소 |
| 4 | ●●○ | 99.6% ≤ a < 99.8% | 오류 감소 |
| 5 | ●●◐ | 99.8% ≤ a < 100% | 오류 감소 |
| 6 | ●●● | a = 100% | 평가 표본에서 오류 없음 |

미측정은 0점이 아니라 **미측정**이다. 범위 밖 값은 입력 오류다. 100개 판정의 해상도는 1%p이므로 이 PoC에서 가능한 합격 점수는 **99%의 1점과 100%의 6점**이다. 2~5점은 나오지 않을 수 있다. 빈 등급을 채우려 표본을 반복 복제하거나 분모를 바꾸지 않는다. 0.2%p 차이를 판단할 필요가 있을 때 새로운 독립 자료를 확장하고 기존 결과도 보존한다.

## 7. DP별 예상 결론과 한 문장 이유

아래 결론은 §3의 주요 사례를 대상으로 한 **PoC 전 설계 예측**이다. 점수나 실측 우열이 아니다.

| DP | 예상 결론 | 발표용 한 문장 구조 설명 | 커버리지 판단 |
| --- | --- | --- | --- |
| **47** | **실용적인 동점 예상** | **양안 모두 원본 재조회와 부분 정정을 지원하므로 후보 분리만으로 최종 지칭 정확도가 높아진다고 볼 근거가 없다.** | 동일 지표로 평가 가능하나 현재 핵심 차이 커버리지로 세지 않음 |
| **45** | **A 우세 방향의 약한 가설** | **A는 현재 지칭 표현에 맞춰 과거 원본을 조합하므로 미리 만든 관계에서 빠진 항목과 조건을 찾을 직접 경로가 있다.** | 동일 지표로 평가 가능하나 정확도 차이의 강한 사전 근거는 부족 |
| 44 | 유의미한 차이를 예상하지 않음 | 실행 연결 방식만 달라지고 같은 지칭 해석과 원본을 사용한다. | 핵심 차이 축으로 세지 않음 |
| 42 | 유의미한 차이를 예상하지 않음 | 서비스 경계의 분리 자체는 지칭 대상을 더 정확하게 판단할 근거를 추가하지 않는다. | 핵심 차이 축으로 세지 않음 |

### 예측이 의존하는 사실과 검증점

47B는 원본을 버리는 구조가 아니다. 후보 확장과 양방향 재판단을 지원한다. 첫 초안의 A 우세 예측은 중간 후보 누락을 추가 오류 경로로 보았으나 **B의 실제 보완 계약을 고려하면 누락은 회수할 수 있다.** 그 추가 비용이 시간과 모델 비용에서 드러나는 것과 최종 정확도 차이는 별개다. B가 후보별 근거 / revision을 유지한다는 이유만으로 정정 정확도 우세를 주장할 수도 없다. 강한 A 역시 dependency와 부분 patch를 갖는다. 따라서 현재 구조만으로는 정확도에서 결정적인 방향을 설정하지 않고 실용 동점을 예상한다. 이는 실제 측정도 같을 것이라는 보장이 아니라 **명확한 정확도 우위 주장을 채택하지 않는 판단**이다.

45B도 원본 출처와 coverage를 보존하고 부족한 관계를 다시 생산한다. A는 검색 누락을 일으킬 수 있고 B의 안정된 관계가 반복 해석의 흔들림을 줄일 수 있다. **새 지칭과 정정 / 버전 구별을 포함하는 정상 업무 집합**에서 원본을 현재 요청에 맞추는 경로가 더 정확할 수 있다는 방향은 있으나 확신이 낮다. B가 보완 생산으로 같은 근거를 확보하면 시간 차이만 남을 수 있다. 새 표현만 과대표집하거나 B의 보완 경로를 막아 정확도 차이를 만들지 않는다.

따라서 두 DP에서 같은 지표를 쓰는 것은 타당하다. 다만 **같은 지표의 적용 가능성과 성능 차이의 존재는 다르다. 이 후보는 현재 “최소 2개 DP에서 뚜렷한 차이” 조건을 확보하지 못했다.** 정확도 차이가 실제로 관측되면 어떤 구조적 오류 경로에서 발생했는지 확인한 뒤 커버리지를 갱신한다. 비교 의미가 정확하다는 이유만으로 기존 대응표의 47 / 45 두 칸을 확정된 trade-off로 채우지 않는다.

## 8. 최소 PoC와 필요한 증거

| 항목 | 범위 |
| --- | --- |
| 구현할 구조 | 47의 공동 해석과 후보 생산 / 교환 / 재판단, 45의 요청 시 원본 조합과 사전 관계 게시 / 조회 |
| 공통 경로 | 동일 원본 취득 / 권한 / 모델 capability / 후속 최종 지칭 채택 |
| 모사 가능한 주변부 | 외부 Agent의 실제 문서 작성과 앱 조작, 고정된 UI fixture의 재생 |
| 모사하면 정확도 증거가 되지 않는 것 | 정답 후보를 미리 주는 생산자, 정답을 돌려주는 모델 stub, 정답에 맞춘 검색 / 이력 관계 |
| 남길 원자료 | 원본 hash, 입력 순서, 현재 revision, 후보/조회/원본 근거, 채택 집합, 정답 원장 version, 판정과 이견 |
| 이번 문서 작업 상태 | **구현 / 모델 호출 / PoC 측정 없음** |

같은 사례에서 A만 맞은 건수와 B만 맞은 건수를 함께 제시한다. 총 정답률 차이뿐 아니라 최소 두 가지 독립 사례에서 같은 구조적 오류 경로가 반복되는지 확인해 한 번의 모델 흔들림을 설계 우세로 확대하지 않는다. 통계적 우월성을 주장할 단계에서는 반복 구조를 고려한 별도 분석을 추가한다. 원형 점수 차이만으로 통계적 차이를 입증했다고 하지 않는다.

## 9. 이해 예시와 발표 한 장 원고

**가상 예시:** 사용자가 표 A와 그래프 D를 가리키며 “이 두 개를 비교해줘”라고 요청했다. 평가할 지칭 표현은 **“이 두 개” 하나**다.

```text
“이 두 개”의 정답 지칭 집합: {표 A, 그래프 D}

VIA 결과 {표 A, 그래프 D} → 일치 1
VIA 결과 {표 A, 그래프 C} → 일치 0
VIA 결과 {표 A, 그래프 C, 그래프 D} → 일치 0

100개 판정 중 99개 일치 → 99% → 1점 ◐○○
```

과거 이력의 “아까 설명한 두 기준 중 첫 번째만”에도 동일하게 적용한다. 비교 대상은 저장소가 돌려준 문장 수가 아니라 **현재 지칭의 채택 대상**이다. 위 수치는 설명용 가상값이다.

### 슬라이드에 바로 사용할 문구

- **정의:** 사용자가 말로 지정한 대상 집합을 정확하게 찾는 능력
- **지표:** 정답 집합과 완전히 일치한 판단 수 ÷ 전체 평가 판단 수 × 100
- **목표:** 99% 이상
- **목표 근거:** 마우스 선택 성공률 98.7%를 참조한 대상 지정 신뢰도 목표 [Rajanna & Hammond, 2022]
- **측정:** 화면 지칭과 과거 이력 지칭에서 채택한 대상 집합을 같은 방식으로 대조
- **예시:** `{표 A, 그래프 D}`를 `{표 A, 그래프 C}`로 찾으면 0점 판정
- **연결:** DP-47 원본 공동 해석과 후보 결합 / DP-45 현재 요청별 원본 조합과 사전 관계 조회
- **각주:** 사용자 검토용 목표와 PoC 전 우열 예측. 표본 정확도를 전체 제품 정확도로 일반화하지 않음.

## 10. 문서 검수 기록

- 기존 요청 처리 정확성의 의도 / 상태 / 전달 품질을 이 지표에 합치지 않았다.
- DP-47과 DP-45 모두 최종 지칭 집합을 채점하도록 경계를 맞췄다.
- 모호한 지칭의 안전한 확인과 지칭 집합 정답률을 분리했다.
- 마우스 선택 실험의 98.7%와 VIA의 제품 목표 99%를 구별하고 과제 차이와 표본 해상도 및 통계 보장 한계를 적었다.
- 두 안의 cache / 후보 확대 / 원본 재조회 / 부분 정정을 유지했다.
- 작성 중 강한 B의 누락 회수 경로와 강한 A의 부분 정정을 다시 대조해 47의 최초 A 우세 제안을 실용 동점 예상으로 수정했다. 45의 A 방향도 약한 가설로 낮췄다.
- 제3자 검토 결과와 보완 이력은 패키지의 통합 검토 문서에 연결한다. 이 절은 작성자 검수이며 독립 검토를 완료했다는 뜻이 아니다.
