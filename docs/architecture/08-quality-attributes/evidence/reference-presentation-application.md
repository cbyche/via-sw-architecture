# 참조 발표자료에서 적용할 방식

> 참조: 사용자가 제공한 NEO-Operation Reference Guide, Slide Catalog 및 Google Drive의 SW Architect 폴더 내 ZIP.
> 원본 사진·문서·민감한 업무 자료는 GitHub에 복제하지 않는다. 이 문서는 발표 구조를 자체 언어로 정리한 적용 메모이다.

## 검토한 자료와 범위

52장 사진으로 구성된 pack의 README·manifest·Word 가이드·Excel catalog를 확인하고, 핵심 원본 페이지 9·18·32·40의 화면 구성을 직접 확인했다. 페이지 번호는 pack의 파일 순서이며 원래 발표의 인쇄 슬라이드 번호와 다를 수 있다. 모든 사진을 정밀 판독한 것으로 주장하지 않는다.

## 최종 VIA 발표의 근거 연결

| 참조 위치 | 표현 방식 | VIA 적용 |
| --- | --- | --- |
| p7~10 | 문제/요구 → 품질과 측정 기준 | 01~08의 도출 근거, 고정 metric/target/scoring을 요약 |
| p11~13 | context와 설계 질문 위치 | 03·04 책임 그림에 실제 선정 DP 위치 표시 |
| p14~26, 특히 p18 | 후보 구조를 나란히 보여주고 같은 QA 값으로 비교 | 12에서 3~4개 Primary ASR의 동일 측정 계약 사용 |
| p16·20·26 | 선택안의 약점과 제한된 보완책 | base 대안과 tactic을 구분하고 같은 시험으로 재평가 |
| p27~28 | 요구 coverage와 최종 구조 | 09 trace와 10 요소 원장을 최종 구조에 연결 |
| p32 | 처음 정한 목표 ↔ 최종 검증값 | 근거 있는 실측·모의시험·설계 추정을 구분하여 닫기 |
| p40~49 | 목표 산식·전제·실험 근거를 부록으로 | Qwen source/profile, token ledger, call graph, raw pass/fail, change ledger를 부록으로 |

본문에는 “문제 → 비교 구조 → 같은 기준의 수치 → 선택 → 남은 약점”을, 부록에는 계산/원자료/제약을 둔다. 현재 Measurement Contract Definition은 그 부록 증거를 미리 준비하는 단계다. 아직 후보 선택이나 성능 결과는 없다.

## 가져오지 않는 것

참조의 처리시간·MM·메모리·보안 control 점수와 VIA의 지표는 다른 제품 요구다. 숫자·가중치·허용 기준을 복사하지 않는다. 참조 p9의 선정은 H/H만의 규칙과도 같지 않으므로 현재 VIA의 1~10점/H-H 선정 체계를 바꾸는 근거로 쓰지 않는다.

가이드의 과거 VIA DP-00 등 적용 아이디어는 현재 승인 Scope가 아니다. ASR을 다시 늘리거나 이미 제외한 최상위 책임 대안을 되살리지 않는다. 보안 control 점수를 VIA 위반 기회 기반 평가로 임의 치환하지도 않는다.

## 이번 작성에 반영한 점

1. ASR별 측정 카드와 공통 원장으로 후보마다 다른 metric을 고르는 것을 막는다.
2. 숫자마다 공개 관측·계산 가정·산식 검산·실제 VIA 결과를 분리한다.
3. 목표와 점수 구간은 Measurement Contract Definition에서 제품 근거를 붙여 확정한다.
4. 선택안 보완 tactic도 동일 입력으로 재측정하며 “구현했으니 좋다”로 끝내지 않는다.
