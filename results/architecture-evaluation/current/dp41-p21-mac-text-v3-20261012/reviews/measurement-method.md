# DP41 P21 측정 방법과 결과 해석

이 문서는 [고정 manifest](../manifest.json)에 기록된 `DP41-P21-MAC-TEXT-v3`의 측정 방법이다. 완료 여부와 실제 수치는 [최종 완료 검수](../final/completion.json)와 [결과 보고서](../final/report.md)에서 확인한다. 원본 후보·측정 코드 49개 파일의 digest는 `f521d6bea196342dab6c0f66268134e9c33f25dfa86a0aac874afc160cb6a20a`다.

## 실행과 판정의 분리

A는 41A+44A+45A+42A, B는 41B+44A+45A+42A다. 각 구성에 동일 P21 활동을 독립 초기화해 5회 실행한다. 순서는 A/B, B/A, A/B, B/A, A/B이며 시간·메모리 worker는 동시에 실행하지 않는다. 각 활동 안의 Request와 비동기 작업은 실제로 겹칠 수 있다. Cloud 의미 모델의 실제 왕복·재시도·부분 판단·대기·폐기를 기록한다.

정답은 후보 및 Agent stub과 분리한다. source는 예약된 실제 도착 사건 이후에만 조회할 수 있다. 추가 질문에 대한 답변도 실제 질문 전달 이후에만 주며, 예정된 미래 사건을 후보 Context에 제공하지 않는다. Agent stub은 수신 payload와 실제 source를 소비한다. 잘못된 목표·조건·참조를 평가 정답으로 고치지 않는다.

OpenAI 판정과 변경 실험은 10개 측정 worker가 끝난 뒤 실행한다. 시간 관측에 judge의 대기나 변경 실험의 CPU 부하를 섞지 않는다. 판정은 16개 보정 사례, 두 블라인드 prompt pass, 불일치 시 세 번째 trace audit를 사용한다. 실제 금지 효과와 의미/전달 사실을 구분하고, 실제 출력에 없는 인용이나 증거 ID는 자동 거절한다. 추가 증거 검토가 판정을 수정하면 원래 판정과 변경 사유를 모두 보존한다.

QA02의 오답 첫 반응은 이후 정정되더라도 5초로 계산한다. 정답만 평균에서 그 첫 오답은 제외하고, 오답 포함 실제 평균에는 관측된 첫 오답 시각을 사용한다. 실제 시각이 없는 반응에는 실측값을 만들지 않는다. 유효한 5초 초과 반응은 실제 시간을 유지한다.

QA03의 유효 완료가 30초를 넘으면 주 지표에서 30초를 적용하고, 완료만 평균에는 실제 늦은 완료 시간을 유지한다. 관측 종료까지 유효 완료가 없으면 완료만 평균에서 제외한다. 두 평균의 분모를 함께 읽는다.

VIA 귀속 시간은 실제 인과 DAG에서 외부 Agent 작업·사용자 대기·사용자 발화의 duration만 0으로 재계산한다. 병렬 경로는 join을 유지하고, VIA 모델·조회·queue·출력 시간은 남긴다. 실제 wall-clock과 재계산 경로는 별도로 보존한다. 인사나 filler onset으로 핵심 반응을 대신하지 않는다.

## 실제 사용과 공통 모형

실제 Qwen API가 Request 의미/Frame과 필요한 부분 판단을 생산하고, 실제 OpenAI API가 자유문과 증거를 판정한다. 후보 제어 코드·owner 조회/cache·로컬 상태·비동기 위임/수신·출력 제어·OS 메모리 관측은 실행된다. Downstream Agent의 보고서/메일 작업과 음성 입력·출력은 공통 모형이다. 메일은 실제 발송하지 않는다.

입력은 전사이며, 공통 음성 출력은 onset 0.25초·초당 6문자·중단 제어 지연 0.005초의 명시된 profile이다. 실제 추가 질문 수와 문장 길이, 출력 queue·중단·부분 전달을 그 profile에서 실행한다. 후보별 임의 시간 가감으로 차이를 만들지 않는다. 실제 음성 API 요금은 0이다. 이 측정의 시간은 그 profile에서 실제 관측한 VIA 경로와 Qwen 지연을 포함한다.

메모리의 공통 부하는 실제 20MiB 원문·2,000turn·200 완료 Task·30 source 슬롯·서로 다른 RGBA 버퍼 15개를 포함한다. Cloud 모델의 원격 weight를 로컬 메모리에 더하지 않는다. 하나의 worker 안의 공유 객체는 한 번 귀속되고, 실제 JSON snapshot·Context 등의 복사본은 OS 관측에 포함된다. Mac의 phys_footprint와 RSS를 Windows commit으로 환산하지 않는다.

공통 owner의 query-only 조회는 유한한 lexical 검색이다. 명시적인 Task/source/publication locator 조회와 구분한다. 검색 관련성이 낮은 반환, 모델의 locator 미사용과 지원 언어의 한계는 원인 분석에서 구분한다. 이 범위는 두 후보에 동일하다.

## 비교 결론의 기준

0–6점과 보호 조건은 동결된 ASR-QA-v6 경계를 적용한다. 같은 점수여도 원지표와 실패 분포를 함께 비교한다. 실용 차이 기준과 다섯 쌍의 방향 일관성은 사전 계약대로 계산하며 통계적 유의성으로 표현하지 않는다. 가중 총점이나 전체 VIA의 최종 A/B 선택은 만들지 않는다.

이 캠페인의 결론은 고정된 두 구현, 실제 사용한 모델·가격, P21·변경 과제, Mac·음성 profile에서 발생한 QA tradeoff다. 모델의 잘못된 선택, 표현 가능한 의미의 구현 결함과 유한 계약이 표현하지 못하는 요구를 별도로 분류한다. 개별 실패만으로 구조 전체가 불가능하다고 결론 내리지 않는다. 다른 DP의 B 교체, 실제 음성 품질, Windows 자원 회계와 Downstream Agent의 domain 결과 품질은 이 캠페인의 측정 대상과 다르다.
