## Scope

Presentation DP1/2/3/4 map to repository DP01/02/04/05. The ten basic variants are ABC/AB/AB/ABC. The new directories hold separate source freezes, raw calls, failures, costs and reports. QA04 independent source-change exercises and QA06 native diagnostics remain separate from actual model trials.

The primary plan is DP01 45, DP02 72, and DP05 54 trajectories. Before any DP05 formal outcome, a sixth condition was added: repeated consumption of a prepared record without prior common raw acquisition, retaining the original five conditions and strong A reuse. See shared contract section 7. DP04 adds six authored screen cases and dedicated parser dependency validation; its final configuration and execution count will be fixed before formal calls. The shared management budget is $4, including unknown-usage reservations, allocated $1.60 to DP01+DP05, $0.80 to DP02, $1.40 to DP04 and $0.20 unallocated. This is a fixed comparison-price ledger, not an invoice.

All cases are authored finite tests. Repeated executions are not independent user scenarios. Timings are the accepted callback and host-completion proxy; content correctness diagnostics and missing outcomes are retained. This is not a full Windows product, real voice, or on-device Omni measurement.

## Preservation

Prior raw results are not overwritten. A failed or interrupted phase stays in its original directory. A new source, oracle, policy or interpretation contract receives a separate freeze. Analysis corrections must preserve the prior analyzer and state their reason. Local downloaded weights and caches are runtime dependencies, not repository evidence; version and hash manifests identify them.

Independent model timing windows are serialized. The first DP02 trial began just before confirmation that a DP04 parser probe had stopped; it is retained with a possible-interference note and separately requested exclusion sensitivity. No outcome is silently replaced.

The common evaluation redesign must connect one input, source/rights, Request/Task/revision and response lifecycle. Every configuration receives the same scenario and oracle set; only the evaluated DP changes. Existing standalone runners cannot be chained and called a common evaluation because they each own adoption and completion. The original COMMON-28 and later DP-RELATED-v2 historical scopes remain intact; the new request's common representative population will be frozen separately. Prepared QA04 patches have not passed new acceptance runs and are not reported as measured module counts.
