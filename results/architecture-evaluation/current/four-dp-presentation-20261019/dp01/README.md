# DP01 발표용 추가 확인

이 디렉터리는 기존 BASIC의 수치·실패·판정을 변경하지 않는 별도 실험이다. `plan.json`, `freeze.json`을 먼저 읽는다.

## 선택의 경계

A/B의 첫 안내 호출 위치는 같지만 A의 유지 view와 B의 최소 입력은 같지 않다. 기존 각 안의 VIA 첫 semantic 호출 **36개 합계** 입력 토큰은 A 39,182/B 34,603/C 127,180, 출력 합계는 11,713/11,045/23,189였다. 호출당 평균은 입력 약 1,088/961/3,533, 출력 약 325/307/644토큰이며 단일 prompt가 127,180토큰이었다는 뜻이 아니다. 원값 6.609/6.267/11.995초를 보존하며 A/B의 작은 차이는 **우열 미확정**, C에는 게시 근거 입력량과 완성 본문 동시 반환의 영향이 있다고 설명한다. C의 관계 사전 생산 33호출·$0.0729348은 입력 이전 준비이며 QA05에 포함되고, 요청의 QA01에 소급 합산하지 않는다.

A의 선택은 엄격한 QA01 승자 확정이 아니라 지칭 36/36, 호스트 계약상 상세 종료 36/36(별도 수동 본문 충족 30/36·누락 6건)와 실제 재사용에 근거한 조건부 선택이다. 출력정책 민감도는 같은 E3의 ABC에 공통 adoption-only 첫 반환을 추가한다. 이는 정책 변경이므로 순수 기본 구조 효과나 전체 BASIC 승자를 확정하지 않는다.

## 자원 교환

기존 A는 이미 14,000바이트 view 예산이 있으나 마지막 단일 passage는 초과해도 남기는 예외가 있었다. 이 예외의 hard-cap 수정은 **필수 기본 계약 수정**이며 tactic 성과로 세지 않는다. 선택적 A3는 수정된 14KB 기본과 비교해 8KiB로 보존 예산을 줄이고 원본 locator를 남긴다. 원문은 필요할 때 현재 판본·권한으로 다시 읽는다.

`native/`는 기존 합성 보고서의 범위·가격·납기 1–48행을 고정한 실제 native 프로세스 자원 진단이다. 모델 호출·새 정확도·서비스 지연이 아니다. 보존 상태 직렬화 바이트와 전체 프로세스 RSS를 혼동하지 않는다. raw의 `query_text_sha_input_unchanged`는 명칭과 달리 코드상 길이 비교이며 SHA 동일성 증거가 아니다. 원본 파일 SHA는 별도로 기록되어 있다. `reread_bytes`는 선택 범위 반환 바이트이며, full-file `read_to_string` 요청량과 물리 디스크 I/O는 별개다. A3 12회는 선택 반환 100,776바이트, 추가 전체 파일 읽기 174,828바이트다.

`replay/`는 기존 A의 실제 모델 응답을 같은 stage 순서로 재생한다. 초기 기본안의 짧은 view에서 A3가 발동하지 않으면 변화 없음으로 남긴다. 재생 시간·0 API 비용을 새 Qwen 지연·비용 개선으로 쓰지 않는다.

## 실행과 보존

- fresh: E3 × ABC × ORIGINAL/ADOPTION_ONLY × 3 = 18 episode. 추가 호출과 실패를 모두 포함한다.
- replay: 12개 기존 A episode × basic/A3 = 24. 실제 이전 응답의 식별자를 연결한다.
- native: 같은 자연 보고서의 선택 범위 × 기본/A3 × 12 = 24와 전체 80행 hard-cap 회귀.
- `freeze-v1-preflight-error`는 API 호출 전 driver 경로 충돌이 검출된 이력이다. `freeze-v2-before-evaluator-pin`은 평가자·원문 pin 보완 전 동결본이다. 최종 `freeze.json`을 유효 실행에 사용한다.
