## 실패를 세 범주로 구별

1. **공급자 JSON 생성 오류**: A page r2의 첫 판단은 point/bbox 모순. 복구 호출이 provider HTTP400 response_format 생성 중단으로 끝났다. usage없음은0원이 아니며 예약상한$0.0729404를 유지한다. 이 실패행을 재실행하지 않고 미실행 항목만 계속했다.
2. **기하 gate 거절 후 복구 소진**: A dense r2, A 정정r2 최초판본, B 정정r3 최종판본, B4 정정r3 최종판본. B의 최종 선택 C1/C3 자체가 맞아도 screen과 확장이 같은 bottom794를 반환해 높이650을 넘었다. 단위 혼동 가능성과 시각 추정 오차를 분리하지 못했으며 구조 분리의 정확성 보장으로 쓰지 않는다.
3. **모델 미해결/불필요한 추가근거 요구**: B4 정정r1 최초판본. 화면에 좌/중/우 후보와 유효 bbox가 있었는데 발화·결합 모델이 left/middle에는 pointer가 필요하다고 판단했고 한 번의 확장 뒤에도 미해결이었다. 이 경우는 단순 normalized 좌표 어댑터로 해결된다고 할 수 없다.

B4의 first13/15와 final11/12가 다른 이유: r1 최초판본은 실패했으나 최신정정이 완료됐다. r3는 최초판본에 응답했으나 최신정정이 실패했다. 두 미응답과 한 최종미완료를 분리한다. 부분정정의 옛 proposal 재주입은 실제 provider 지연 실험이 아닌 제어 replay다.
