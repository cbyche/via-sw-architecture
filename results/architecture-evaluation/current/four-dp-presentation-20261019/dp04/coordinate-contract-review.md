## 공식 구현과 현재 후보의 차이

QwenLM의 공개 grounding 도구는 기본 모델을 qwen3.7-plus로 설명하고, bbox_2d를 0..1000 정규화 좌표로 요구한 뒤 원본 이미지 크기로 변환한다. [grounding.py L85–147](https://github.com/QwenLM/Qwen-MM-Plugins/blob/main/src/capabilities/api/qwen_mm_plugins_api/vl/grounding.py). 변환은 각 축을 1000으로 나누어 원본 폭·높이를 곱하고 반올림한다. [shared/image.py L29–37](https://github.com/QwenLM/Qwen-MM-Plugins/blob/main/src/shared/image.py). 이는 조회한 main의 공식 도구 구현이며, 특정 날짜 모델의 모든 자유 JSON 응답이 반드시 그 단위를 쓴다는 API 보증과는 다르다.

이번 고정 후보는 A joint와 B screen 모두 원본 pixel 좌표와 W/H를 명시했고, 공통 gate가 그 단위로 검증했다. 따라서 prompt 내부 단위가 미정의였던 것은 아니다. 다만 vendor grounding 관례를 수용하는 명시적 normalized-output 어댑터 없이 모델에게 직접 pixel을 생성하도록 한 통합 선택이었다. 역할·소유권과 공통 모델 좌표 관례의 영향을 현재 결과에서 분리하지 못했다.

## 관측과 가설을 구별

- 새 BASIC B 정정r3의 revision2에서 화면 생산자가 C1/C2/C3 bbox의 아래쪽을 모두794로 반환했다. 원본 높이는650이다. 화면 확장도 같은 값을 반복했고 binder가 C1/C3를 맞게 선택해도 gate가 거절했다.
- 만약794가 0..1000 기준이었다면 y=516.1pixel이다. 저작 원본 카드의 하단530과 가까운 것은 정규화 혼동 가설과 양립한다. **그 단위를 실제로 썼다고 확정하지 않는다.** 다른 값의 시각 추정 오차까지 이 계산으로 해소되지 않는다.
- B4 정정r1은 다른 문제다. 유효한 세 카드의 좌우 위치 후보가 있었는데 발화·결합 모델이 ‘왼쪽/가운데’를 해결하려면 pointer가 더 필요하다고 잘못 미해결로 남겼다. 좌표 단위 어댑터만으로 이 의미 판단 실패를 해결한다고 예측할 수 없다.
- A2+A5는24/24로 통과했지만 보조 눈금·crop, 국소 patch, 실제 모델 반환 변동이 결합된 관측이다. 소유권이나 좌표표현 중 하나의 단독 효과가 입증된 것은 아니다.

## 다음 검증을 한다면: 공통 모델 어댑터로 분류

이 보완은 A만의 tactic으로 세지 않는다. A joint와 B screen의 output wire를 동일하게 normalized 0..1000으로 명시하고, source/frame에 결속된 공통 어댑터가 pixel로 변환한 뒤 기존 gate에 전달하는 **새 A/B 공통 baseline**이다. raw 포인터·path와 평가 oracle는 원본 pixel 그대로 유지한다. 단위를 overflow 여부로 추측하거나 기존 응답에 사후 적용하지 않는다. crop/grid·A2 patch·B4 병행을 baseline에 무료로 넣지 않는다.

API 전에는 축별 변환, 범위·유한값·frame/source revision 불일치, rounding 경계, 알 수 없는 단위와 기존 stale input/source gate를 offline로 검증한다. 원본 fixture는 모두 접근 허용 상태이며 이 좌표 어댑터에 새로운 철회 기능을 추가하거나 검증했다고 하지 않는다. live는 승인 시 네 사례×3반복×A/B의24 episode 공통표현 비교로 한다($0.08–0.10 예상, 별도 $0.20 상한 제안). 모든 사례와 반복을 포함하며 알려진 실패만 골라 고치지 않는다. 기존48의 보수 합계 $0.2387928에 새 상한을 더하면 $0.4387928로 승인된 DP04 전체 $0.55 안에 있다. 새24도 원시 실패·미관측·미확정 사용량을 전부 보존한다. 현재 이 추가 API는 미승인·미실행이다.

## 현재 선택 결론

새 BASIC A/B는 모두 필수 endpoint를 일부 놓쳤으므로 확정 기본 승자를 만들 수 없다. 새 네 구성 중 A2+A5만 예정15 first/12 goals와24 exact-set을 모두 충족했다. 따라서 **현재 finite 사례의 조건부 실행 구성**으로 제시할 수 있지만, ‘BASIC A가 QA01 전체 승자였고 A2+A5가 그 속도를 유지했다’는 서사는 성립하지 않는다. A가 응답한 같은12입력은9.268→10.875초로 약17.3% 느려졌다. 실패를 없애기 위해 그 비용을 지불한 결과다.
