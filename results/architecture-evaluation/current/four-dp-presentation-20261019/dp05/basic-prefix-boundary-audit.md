# 기본 DP05 첫 응답의 공통 경계와 입력 차이

기존 최종 `basic-dp05-reuse-union-corrected-v2`의 첫 정상 의미 해석 요청을 읽기만 했다. 새 API·후보 수정·지연 재채점은 없다. [JSON](basic-prefix-boundary-audit.json)에 63개 실제 request 파일·값 SHA·token과 21개 목표별 대응을 보존한다. 별도 해석 repair/producer/receiver 호출은 아래 합계에 포함하지 않았다.

| 안 | 첫 정상 의미 호출 | 전체 입력 token | 전체 출력 token |
| --- | ---: | ---: | ---: |
| A | 21 | 15,318 | 3,720 |
| B | 21 | 41,002 | 3,828 |
| C | 21 | 13,722 | 3,690 |

이는 21호출 합계이며 단일 prompt 크기가 아니다. 같은 episode·반복·목표의 실제 전체 request 값은 A/C 15/21쌍만 같았다. A/B와 B/C는 0/21이다. B는 실제 생산 때 취득한 supporting raw passages를 임시 prefix view로 제공한다. A는 앞선 VIA_COMPOSER가 실제 취득한 원문을 다음 목적의 prefix에 제공한다. C의 외부 receiver 읽기는 VIA 원문 취득으로 자동 승격되지 않는다. 원문 재사용을 공정하게 복구한 교정의 실제 효과이며 그것을 제거해 문맥을 같게 만드는 기본안은 실행하지 않았다.

E3 r1의 실제 user message 길이는 A 첫1431→후속2029/2032문자, B2905/2910/2913문자, C1431/1436/1439문자였다. 공통 함수·출력 계약·호출 위치가 같다는 사실은 해당 입력량 경로의 영향이 없다는 뜻이 아니다. 따라서 기존 QA01 4.307/4.421/4.321초와 20/21·21/21·21/21 관측을 보존하면서 **구조적 동점 대신 우열 미확정**으로 정정한다.

QA02 비적용과 QA03의 C 이익은 그대로다. 다만 최고 우선순위가 미확정인 상태에서 C는 공개된 조건부 설계 권고이며, 엄격한 우선순위 전체 승자를 확정했다고 말하지 않는다. 실행 전 계약의 공통 prefix 동점 예상은 당시 예상 이력으로 남기고 결과에서 이 정정을 연결한다.
